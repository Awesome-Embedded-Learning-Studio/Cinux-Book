# 换世界

堆开张了,上一卷许的三件活还剩最后一件:地址空间。咱们把要造的东西说成人话:一个 AddressSpace,就是一个世界——它自己的一套页表,自己的用户半边,想进就 load 它的根,想走了就换回来。造它是为了谁?为了进程。下一卷的进程,每个都要有自己的世界,跑在进程甲的世界里,看不见进程乙的半张地图。可进程眼下还来不了,咱们现在造它,是把地基里最难搬的几块赶早搬了:世界怎么造、怎么进去、怎么活着出来。这三件事办成了,进程来了只是拎包入住。

造世界的代码咱们整个看一遍:

```cpp
bool AddressSpace::init() {
    base::PhysAddr const kFrame = Pmm::self().allocate_page();
    if (kFrame == base::PhysAddr{}) {
        return false;
    }
    auto* const kFresh = cinux::base::PtrAt<Entry>(DirectMapVirt(kFrame.raw));
    cinux::base::SetBytes(kFresh, 0, cinux::arch::page::kSize);
    auto* const kKernel = cinux::base::PtrAt<Entry>(DirectMapVirt(KernelPageRoot()));
    cinux::base::CopyBytes(kFresh + kKernelHalfSlots, kKernel + kKernelHalfSlots,
                           kKernelHalfSlots * kSlotBytes);
    root_ = kFrame.raw;
    return true;
}
```

四步的头一步是名册取一页,这页就是新世界的 PML4。清零是页表的出厂纪律,走查一节立下的道理,咱们这里一道工序都不省。然后是全场最要紧的一抄:从内核根上,把 256 到 511 项原样地镜像过来。为什么抄的是这半边、抄的为什么恰好够?咱们想一件事:切换世界的那一拍,正在跑的代码是谁?是内核。它脚下的路、手里的栈、串口的驱动、屏幕的字库——全在内核半边的门牌里。新世界要是只有用户的地,load 进去的那一拍,取指的路当场就断,机器连报丧的机会都没有。所以每个世界生下来,内核的半边必须整副都在——直接映射、堆、设备窗、镜像窗,256 项一项也少不了。这一抄还有个静悄悄的妙处咱们点一句:抄的是 PML4 这一层,底下的 PDPT、PD、PT 一张没抄,各个世界共享的还是那几张表,多花的内存一分没有,内核在每个世界里却都是完整的。为什么任何世界都看得见内核?这句话的谜底就是这个镜像。

用户的那半边,新世界是从纯零开始的。地怎么画?走查伺候:map 一个门牌挂一页,translate 问一句咱们就走一趟,根是入参——您注意设计在这一步结出的果子:给不在场的世界画图完全不用惊动机器,CR3 稳稳地一动没动,咱们坐在内核的桌前,拿走查往新世界的表里添砖。这就是当初把走查降成纯函数时埋的伏笔,此刻兑了现。

然后咱们入场。activate 的身子是一行 LoadCr3(root_),外带着一道守卫的,root 还是零的空间进不了场。这一行咱们细看,里头全是本卷攒下的家当。LoadCr3 把根装进了 CR3,CPU 从下一条指令起就在新世界取指了——为什么敢装?内核半边镜像,装完的那一拍代码还有路。装完顺手发生什么?CR3 一换,作废的就是整个 TLB,新世界的第一趟访问就要走真表。换世界从来不是白来的,代价就是速查记忆的全部清空,“大换血的那一档”在 unmap 的一节里说过,说的就是这一拍。出去的路呢?LoadCr3(KernelPageRoot())。这里头有个身份的变迁咱们得交代:接管落成那天咱们把 CR3 存进了 KernelRoot,当时它就是内核的根。可从 activate 存在的这刻起,CR3 变成了“当前在跑的世界”的根,算是个变量了,而 KernelRoot 存的是定格,回家路用的是定格,而不是变量。KernelPageRoot() 读的,就是 KernelRoot 存下来的定格。还有一条纪律:切换期间的中断必须关着。道理跟切换本身同源:中断的桩、桩后面的服务全住在内核半边,这倒是镜像保的。真正的风险是切到一半来一个中断,它把世界又切走了。测试里的 mm 阶梯本来就没开总闸,天然地成立,将来调度器真用上了它,纪律得写成铁的。

验收的台子上,aspace 的一台三案里,第三案是本卷实弹的压轴,咱们把它当剧本读:

```cpp
space.activate();
// NOLINTNEXTLINE(clang-analyzer-core.FixedAddressDereference)
*cinux::base::PtrAt<unsigned long>(kSpot) = 0x114514UL;
// NOLINTNEXTLINE(clang-analyzer-core.FixedAddressDereference)
ASSERT_EQ(*cinux::base::PtrAt<unsigned long>(kSpot), 0x114514UL);
ASSERT_EQ(cinux::arch::ReadCr3(), space.root());
cinux::arch::LoadCr3(cinux::mm::KernelPageRoot());
ASSERT_EQ(cinux::arch::ReadCr3(), cinux::mm::KernelPageRoot());
```

四拍的头一拍是入场。在新世界的用户半边,咱们写一个 0x114514,读回来还是它——这个门牌在内核的世界里根本没映射,偏偏写读能成,走的一定是新表。咱们回读 CR3,对上空间的根——机器现在真住在那个世界里。末了回家,咱们再读一遍 CR3 复核。那两行 NOLINT 是给静态分析器的豁免:内核往写死的高位门牌上写字,这场面分析器是真的没见过,在它的眼里那永远是野指针,咱们给它挂个说明再干活。案名咱们也抄来:aspace: activation switches the machine and comes home,说的就是这件事。一台机器、两个世界、一个来回的戏,全在这几十个字节的里面。

有一件刻意没造的东西,咱们得把话说在明处:销毁。世界用完了,用户半边的表要一层一层拆下去还回去,只要漏了一层,那几页物理内存就永远挂在一张没人用的表上——名册上它们还是空闲的,邻居们是头一个遭殃的。当年的实现连递归回收都写了,这一遍咱们把它砍掉了。砍它的依据,和会听那一卷给心跳立脸时说的是同一条家法,那卷的原话是“要求等真消费者出现的那天再加——不提前备货”,紧跟着的还有“可扩展、不等于完备”。递归销毁的法子,得跟进程的生老病死一起立才有意义:进程来了,一张表的归属、哪天拆,到那时都有了着落。单独地写,写完了没人用,对错也就无从验起了。图纸咱们画到这儿,就等进程来落笔了。

收尾之前咱们还有一笔欠的得跟会疼那一卷结清。那一卷讲异常转储的时候留过话:缺页这样现场可修的故障,将来的处理程序有机会把路修好再回去,那是虚拟内存当家的卷的事。现在内存当家的卷到了,咱们把机制讲清楚,代码却稳稳地一步不挪。机制是这样的:#PF 进来,肇事地址躺在 CR2 里。处理程序看的是错误码,确认的答案是页不在,而不是权限错。然后咱们从名册取一页,走查挂到肇事的门牌上,iret 回去了,咱们让肇事指令再执行一遍,这次有路了。这就是按需调页的机制。一副骨架的模样,咱们这一卷把每一块骨头都备齐了:异常的现场报告、名册、走查,差的只是把处理程序接上。为什么不现在接?因为眼下内核里没有一处访问是“该缺页的”——所有该有的映射,咱们都提前铺好了,处理程序接上了也无事可做,要防的就是它把真错误也当场盖掉,盖掉了一个野指针,就少了一具验尸报告。第一个真用户在用户态那一卷:进程的用户页,生下来就该是缺的,用到的那天才给。等到了那天再接,接上了就有活干,机制的每一行都验在实处。会疼那一卷的这句话,咱们今天把它兑现成了一张图纸,图纸的事归图纸,工期排在用户态的那一卷。

至此上一卷许的三件活齐了。下一节咱们对数、验货、翻考古箱。
