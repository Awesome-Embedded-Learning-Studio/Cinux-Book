# 页表还没有主人

上一卷收工的时候留过话:门的故事开的是一扇粗门,内存当家是下一卷的事,虚拟内存的管理会用 4KiB 的页来精修,堆和地址空间的活都在后头排着队。这一卷就是当家的这一卷。三件承诺咱们一件一件兑:头一件,给内核的虚拟世界画一张正式的地图,随后在地图上开一个能找零钱的堆,末了把地址空间做成能造、能换的物件。可咱们动工之前还得把产权盘一遍,产权盘清楚了,本卷头一件该干什么,顺势也就明了。

头一件盘门的产权。咱们回想内核出生那一卷的布置:三张表起头当的是过桥的桥,后来接了交接门的差事,PML4 的第 0 项和第 511 项指着同一张 PDPT,PDPT 的第 0 项和第 510 项又指着同一张 PD——一张表挂两个门牌,高半的别名恒等于物理地址。到了上一卷画自己的脸,同一张 PDPT 里又添了第三扇门:帧缓冲的 1GiB 巨页,装在低窗的 PDPT 槽上,内核从此能把物理地址当门牌用,咱们写字,直接往屏幕上写就是了。这三扇门替咱们办成过很多大事,可您翻遍工程,得到的说法只有一种:门是 boot 画的。BuildHandoffDoors 这个名字就是它自己的自白,建造的人是它,产权从头到尾攥在 boot 的手里。内核的日子,是天天踩着这些门过的,改过的页表项却一个也没有。

接着盘一个更要紧的事实:内核根本不知道页表在哪。您要是不信,咱们拿事实说话。交接单咱们在内核出生那一卷誊过一遍,里头 magic、版本、E820 图谱、画布参数、内核自己的四个数都全,唯独没有页表的字段。boot 造完门就跳走了,递门牌的事压根没发生过。咱们也把内核树整个搜过一遍:kernel/ 底下,提到过 CR3 的文件一个也没有。CPU 走的每一条指令背后都是一趟四级查表,而住在这套表上的内核,对这套表的位置一无所知。您听着可能觉得荒诞,可它正是现状:名册那一卷咱们给物理内存立了册,能分的页、有主的页,PMM 都替咱们记得清清楚楚,但名册记的是物理页的身世,不是虚拟到物理的路怎么走。虚拟这半边的管理,咱们到上一卷收工为止一天都没开过张。

那么第一个问题就自己站出来了:谁告诉内核页表在哪?路子看着有两条:头一条是请 boot 在交接单上添一个页表的字段,把 PML4 的物理地址誊给内核。而另一条更直接,咱们当面去问 CPU。走表的起点从来就是 CR3,过桥那一卷咱们亲手把它装进去的时候就知道,它存的就是 PML4 的位置。boot 转交的是一份转述,CPU 里的才是现场——机器此刻真正在用的页表根就在那个寄存器里躺着,咱们一行 movq 就能读出来。咱们选了直读。理由说穿了不值钱:真相在硬件寄存器里,又何必让 boot 再转一道手?往后交接单上没写的事,内核就一定不知道么?只要这事实是 CPU 自己认得的,咱们就当面去问它。

咱们顺着这个答案再往下想一层,您会发现欠的不只是位置,章法也欠了一份。boot 的门是静态的:门数按内核的尾巴算,盖住镜像和单子就算交了差,再往上一页的地界都不盖。可这一卷要办的活,件件都要门会生长——堆要一页一页地往上扩,地址空间要造了又拆,用户的那一半将来要从零画出整座城。静态的门伺候不了动态的日子,本卷真正的活因此换了性质:内核接管页表,把根拿到手、走查、补页的活,全归了它自己。往后的日子,门归了内核管。

产权盘完了,咱们把现状里躺着的三件事也摆到桌面上,它们是接管那天要一起清的。头一件要清的屏幕就住在低半边:帧缓冲的门开在 PML4[0] 的低位窗里,内核往 0xFD000000 写的每一个字,走的都是低半边的路。第二件要清的栈也住在低半边:entry 里硬编码着一条 movabs,把栈顶直接安在 0x90000 的低位物理上。第三件要清的交接单,本身还躺在 boot 留下的低处信箱里,内核读它的每一行,读的都是低半边的门牌。这三件事清完的那一天,低半边就可以整个拆掉了——到那时,内核的每一件事,咱们把取指、压栈、说话、画脸一件件数过去,走的全都是自己地图上的路。

地图怎么画,咱们下一节动手,头一步的活就是把它挂上墙。
