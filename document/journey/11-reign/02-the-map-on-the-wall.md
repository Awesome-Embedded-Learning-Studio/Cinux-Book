# 挂在墙上的地图

咱们动工之前把图画画好,这是从最早立断言那天就守着的习惯:数值不该在两处各写一遍,写了一处,另一处的数就该由它推出来。这一卷要画的图不小,要画的是内核的整个虚拟世界,所以它配得上一个正式的家:kernel/mm/ 里,新立了一份公告头 layout.hpp,把往后内存子系统发出去的每一个地址的出处都写在里面。咱们把它当地图挂上墙,一处一处地看谁住在哪。

地图的基本刻度,是 PML4 的一项。一项管多宽?过桥那一卷咱们掂过层级:一项 PML4 盖 512GiB。所以地图按项分家,一家分到一整块 512GiB 的地,谁也不跟谁借地:

```text
PML4[256]  0xFFFF800000000000  RAM 直接映射窗
PML4[257]  0xFFFF808000000000  内核堆窗口
PML4[258]  0xFFFF810000000000  vmalloc 与内核线程栈(预留)
PML4[259]  0xFFFF818000000000  ioremap 与设备 MMIO
PML4[511]  0xFFFFFFFF80000000  内核镜像窗(镜像仍从 +2MiB 起)
```

头一家的名字叫直接映射窗,它是头一个住进来的,也是本卷的主角。它给的承诺一句话就说得完:物理内存里的每一个字节,在这扇窗里都有一个固定的虚拟门牌,换算的公式,咱们写出来就是一行加法:direct_va = base + phys。您拿物理 0x200000 来对:窗基是 0xFFFF800000000000,您往上一加,得出来的门牌就是 0xFFFF8000200000。咱们反着走也行,减回基址就还原成物理地址。承诺值多少钱?咱们掂一掂:名册那一卷立起来的 PMM,发给咱们的页是一枚物理地址,可内核的代码认的是虚拟门牌——中间没有这扇窗,咱们每拿一页都得手动挂上一次映射才碰得着。有了它,PMM 发的每一页,到手即是可用的指针,这扇窗等于给整本名册配了一副随时能戴的眼镜。当年第一遍的内核把这扇窗起在同一个门牌上,只是没人解释为什么是这个数。这一遍咱们把话说全:0xFFFF800000000000 就是 PML4[256] 的项底,咱们把项号左移 39 位,高 16 位的空缺由符号扩展补上,出来的结果一个字节都不多。

后三家咱们过一遍就够。堆窗口排在直接映射的下一项,按 4KiB 一页一页地向上长,项内的 512GiB 是它的硬上限——够不够用,咱们拿数字说话:内核如今的全部家当折算成页,一百四十来页就打住了。第三家给 vmalloc 和内核线程栈留了门牌,常量立了,分配器不立的缘故是消费者还没来,咱们不替它置办家具。第四家给设备留:帧缓冲这样的 MMIO 区,不该混进 RAM 的直接映射里跟内存条挤,它们有自己的窗。这一卷它接的是份临时工,图纸上给它起了名字,叫相位一:登记设备的正经差事还没轮到,拿物理偏移照搬的镜像顶着用。咱们后面拆旧城的时候会看到它怎么顶上。

第 511 项的老住户是内核镜像窗,门还是 boot 开的那扇,咱们照住。项内的 PDPT 也分了家:第 510 槽是镜像自己,第 511 槽是给将来内核模块留的模块窗,基址咱们定在 0xFFFFFFFFC0000000。为什么模块偏偏住在最顶上?不是咱们随手挑的:内核的代码模型把它按在地址空间最末 2GiB 里,链接器认的只是这个射程,地图就顺着它画。老门翻了新,挂的还是原来的门牌,只是产权和章法从此归地图管。

地图的下半边是用户的世界,这一卷咱们只画界碑,盖房子的事一概不碰。咱们把五条约定摆出来。用户半边的顶在 0x0000800000000000,这是 48 位规范地址的中线,用户的地界从中线以下起。最低的 64KiB 永不映射,给空指针留一个炸得整齐的地方。brk 区和 mmap 区的分界线,定在中线再往下的一半。咱们让 mmap 区从分界线一路往上长,长到栈区脚下一个专门的顶为止。栈顶贴着用户半边的顶,咱们再往上一页留空,越界踩空的那一脚换来的就是缺页。您注意咱们只立了常量,PML4 的 0 到 255 项,在运行期保持的是全零。约定立给将来的进程,眼下咱们在这半边不立一页映射。

最后咱们说说互锁。地图最怕的病是基址和项号各改各的:有人改了常量忘了改项号,或者反过来改了项号忘了改常量,两张地图就悄悄分了家,真查起来是要人命的。所以 layout.hpp 的尾巴上立了十二条 static_assert,把每一家焊在它自己的项号上。咱们摆两条,您感受一下它的脾气:

```cpp
static_assert(kDirectMapBase == (0xFFFF000000000000UL | (kDirectMapPml4 << 39)),
              "direct map sits exactly at its PML4 slot");
static_assert(kKernelImageBase ==
                  (0xFFFF000000000000UL | (kKernelPml4 << 39) | (kKernelImagePdpt << 30)),
              "image window sits exactly at its PDPT slot");
```

写的时候咱们还真被它抓过一回。直接映射的互锁,首版就写对了:项号左移出来的是个 48 位的无符号数,高 16 位上放的是零,而 0xFFFF800000000000 的高 16 位全是 1,两边的数天生对不上,得拿 0xFFFF000000000000 把符号扩展的底子铺上,而后再或进去。可写到镜像窗和模块窗的互锁,这道工序漏了——左移、或、一比,编译器当场把不等说了出来,两条 static_assert 一起红了。您看这就是互锁的意义:写的人刚刚犯的错,咱们开机都不用等,更不用说等黑屏了,编译那一秒它自己指认了自己。十二条互锁往后就长在了墙上,谁想改地图,编译这一关是逃不过的。

长凳那头照例配了测,mm_layout 一件六案:四家的有序互斥、直接映射换算往返,半边归类、ioremap 相位一的镜像换算,镜像窗与模块窗的位置、用户半边五约定。全是纯常量的对数,一件件把地图对实。地图挂好了,下一节咱们拿着它去接管真实的页表——从问 CPU 要根开始。
