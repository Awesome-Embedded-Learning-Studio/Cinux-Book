# unmap 欠的那一下

上一节咱们把下楼学会了,本节咱们补上另外两个动词,头一个拆的就是映射。UnmapPage 的实现是三句话:FindSlot 走到槽前,抄下的旧项就是收据,槽清成了零项交差。另有半句得补在后头:unmap 只认 4KiB 的槽,FindSlot 要是停在了大叶上,unmap 就空手而归,抱回去的是一项零——拆大叶的活跟 map 那边同宗,都是调用方的策略,轮不到 unmap 接的。收据的讲究值得说一句:拆完之后调用方往往要还页给 Pmm,还得把缓存也刷了,而缺了旧项它就是两眼一抹黑——走查把原来这儿挂的是谁如实报出来,收尾的活才接得上。

可真正的正主不在函数里,在函数后面欠着的那一下。咱们得把一件 CPU 的脾气摆到桌面上:页表项改了,CPU 自己是决不会自动知道的。每一条翻译它都往一个小本本里记了下来(TLB,翻译的速查缓存),同一个地址走第二遍,它把查表这道工序省了,只翻自己的小本本。这本来是天大的好事,缺了它,每条指令都得老老实实地四级下楼,机器就慢得没法用了。可它有一面阴着:咱们把表里的项清了,小本本里那一页记着的还是旧条目。于是天下最玄学的症状出台了:明明 unmap 了,访问偏偏还不缺页,明明 map 了,访问偏偏还报缺页,咱们再等一等,别的操作顺手把那页缓存挤掉了,它又突然好了。时好时坏、看运气吃饭的病,十有八九是小本本忘了撕的。所以义务咱们写进了纪律:unmap 清完槽,调用方必须补的一件事就是作废,少了这一补,这一次的解除就等于没有解除。作废的路子有两条,registers.hpp 里的两张脸对应着两档:

```cpp
inline void ReloadCr3() {
    asm volatile("movq %%cr3, %%rax\n\tmovq %%rax, %%cr3" : : : "rax", "memory");
}

inline void InvalidatePage(unsigned long virtual_address) {
    asm volatile("invlpg (%0)" : : "r"(virtual_address) : "memory");
}
```

invlpg 走的是手术刀的路子,精确废掉一页的翻译。ReloadCr3 是重装 CR3 的原值,咱们拆旧城那天用它换过一次血——它一响,整个地址空间的翻译全部作废,大换血的一档,单页的活犯不上动用它。您可能要问:走查既然懂这么多,为什么不在 UnmapPage 里顺手把作废办了?因为作废指令废的是“当前正在跑的这套表”的缓存,而走查天生不管哪套表在跑——根是入参,改的可以是不在场的任何一套。哪套表活着?谁在用它?说得上来底细的只有调用方,义务也就归了调用方。作废的活它接不住,其实也不该由它来接。

第二个要说的动词是翻译。TranslatePage 跟 MapPage 走的是同一副楼梯,连 FindSlot 都相同——差别只有一处:缺表怎么办。map 遇到空槽就补了页接着走,翻译遇到空槽就收了手回家报零。仅此而已,再没有分别了。可大页让翻译多了一层活:FindSlot 在半路上遇见带 Large 位的项,就停下来了:1GiB 的叶停在 PDPT 层,2MiB 的叶停在 PD 层。停在了哪一层,就用哪一层的位段把物理基址抠出来,再用本档档位以下的低位拼上页内偏移。这里有个漂亮的自洽:本档 IndexRange 的 low,恰好就是叶内偏移的宽度——1GiB 的叶底下是 30 位,2MiB 的叶底下是 21 位,通吃的只是一个公式。咱们顺带把 FindSlot 对大页的态度也交代了:它是只读的走法,看见大叶只报告停在这层了,而不评判。拒绝大叶的是 EnsureLeafTable,那边的理由上一节说过:把 2MiB 拆成 4KiB 是调用方的策略问题,替人做主的活不归走查。

本节咱们自己埋过两个雷,都值得咱们记一记。头一颗在翻译的叶档移位上:1GiB 的叶,物理基址该用本档的 30 位去抠,头一版手滑写成了下一档的 21 位。写的人浑然不觉,长凳当场红脸——host 的六案里专门有一案摆好了 2MiB 叶和 1GiB 叶各带偏移的对数,期望值一笔一笔算死了,移位错了它就抓。咱们要是把这错漏进内核,症状是 1GiB 之内的翻译全偏,查起来就够咱们喝一壶。第二颗雷的来历更有意思,它埋进了测试里,而不在代码里:拒绝拆分那一案,咱们断言“对大叶 map 会被拒绝”,首版却只摆了 2MiB 的门,拿 1GiB 说事的断言,测的其实是没装上的叶。走查倒是老老实实按没到叶处理,断言绿了,可它测的东西根本不存在。后来把 1GiB 的门也装上,断言才算测到了它声称要测的东西。测试自己写错了还能一路绿灯,病得比代码错更阴:绿灯全是假的,信心倒是真的。咱们记下的判法是:断言的期望值,要能指出它盯着的是表里的哪一项——指不出来,断言就成了许愿。

内核那头的验收是三案,案名咱们原样抄来:头一案 vmm: the user half of the live root is dead,第二案的 vmm: the live root translates image and direct map,第三案的 vmm: a page lives in the heap window only while mapped,考的全是活根。第一案是低半边的死亡证明,案底咱们在拆城一节立过。第二案拿活根真翻译:镜像窗加 2MiB 的门牌翻回物理 2MiB,直接映射里的同一个数也对得上,而还没人映射过的堆窗口基址,翻出来的必须是零。第三案走的是全生命周期:从 Pmm 领一页交给 MapPage 挂进堆窗口,写了 0x114514、读回、翻译对页号,然后 UnmapPage 拆掉、invlpg 补上该补的那一枪,翻出来的必须是零,咱们再把页还回名册。您注意第三案里 invlpg 出现的位置:清槽的下一行就是它,拆完了立刻补,而顺序本身就是义务。

走查三件套齐了,页表从此是一副能自己生长的骨架。可咱们手里还只有骨架,肉是缺的:页表最小管到 4KiB,可内核要的东西经常只有几十个字节。下一节咱们开堆——把整页拆成零钱的铺子。
