# 种子柜

地图挂好了,咱们去接管。接管的第一件事,头一节已经答了:读 CR3。arch 家里为此新立了一份薄得就剩一行内联汇编的 registers.hpp:

```cpp
inline unsigned long ReadCr3() {
    // NOLINTNEXTLINE(misc-const-correctness)
    unsigned long value = 0;
    asm volatile("movq %%cr3, %0" : "=r"(value));
    return value;
}
```

读出来的就是 boot 留下的 PML4 的物理地址,作保的是 CPU 本人,一个字都假不了。可咱们顺着这个答案往下走,马上会碰上第二道题:接管是要建新表的,直接映射的 PDPT、各家的 PD,咱们每造一张都得搭进去一页物理内存,这些新表页从哪儿来?最顺手的答案是问 PMM 要:Pmm::allocate_page 嘛,名册现成的。咱们第一版就是这么写的,写完了还挺得意,结果这一版被一句问话打回了原形:这套写法,换了个映射策略,是不是就炸了?

咱们把这道题摆开算。Pmm 的名册咱们记得,那咱们得分两句说:头一句,咱们把低 1MiB 整块圈起、一刀划成保留。咱们再把内核登记在册:它住在 2MiB,吃进多少地界,咱们就记多少页。能分的页,从这两笔之外的空当里起发。可眼下内核脚下踩着的映射是什么?boot 的门只盖到内核镜像的尾巴,咱们按 2MiB 把它向上取整,本机盖到的顶也就 4MiB 上下。1GiB 是另一个数:名册那一卷把检查的顶收到了 1GiB,单张 PD 撑到的容量也就是它,不是眼下真盖着的范围。这么一算,名册里头一批发出来的页,大多落在门的外面——PMM 说这页给您,咱们拿着物理地址却连碰都碰不着:没有映射。第一版为什么居然能跑?因为 Pmm 分配的顺序是从低往高扫位图,头几页总落在 1MiB 之上、门盖到的顶之下,恰好还在门内的地界。这靠的是运气,而拿运气当地基的工程,换一天就塌:哪天映射改了章程,或者分配顺序调了个个儿,取回来的页当场就是野指针。硬闸倒是可以加(取页时检查物理地址必须在门内,不在就响亮地报错),可响亮地失败依然还是失败,闸门是不生产表页的。

咱们的正解是把依赖整个掐断。门内有没有一块地方,是 boot 交接之后确定没人用、又不受任何策略摆布的?有,咱们翻低内存的地图就找得到:0x20000 到 0x40000,摆渡窗之上、内核镜像(住在 2MiB)之下的 128KiB,一整片低位空地。装载流水线的步骤里从来轮不到这儿,九判的脚印也踩不到它。咱们把它圈出来,立了一个正式的名字:种子柜,柜里的存粮按最坏的情况备——直接映射一整张 PDPT,外加上限 16GiB 之内的每个 1GiB 窗一张 PD,再加帧缓冲那头的一对,咱们满打满算还有富余。咱们在 vmm_config.hpp 里就写了这一行:

```cpp
inline constexpr base::memory::MemoryRegion kSeedTablesSpan{0x20000, 0x40000};
```

柜子的用法是取种:bump 一个游标,取出来的每一页,都清成了全零才交出去。为什么强调零,咱们下下节讲走查的时候细说,这里把纪律立着:凡是要当页表用的页,出厂必须是干干净净的全零。发页的事记在一个小类里,名字就叫 SeedPantry——取种的柜子。它跟 PMM 一页都不打交道:接管路上用的每一张表全部出自柜中。Pmm 从引导路径上完全退了场,直接映射从押注的赌桌变成纯粹的运行时设施,谁来验收都不用再问一句分配顺序是什么。

还有一件搬家的活得赶在动工前办:交接单。头一节咱们盘过,单子躺在 boot 留下的低处信箱里,走的是低半边的门牌。可接管的终点是把低半边整个拆掉,咱们不把单子搬走,拆到一半它就跟着旧城一起没了。所以接管函数的头一行就是归档:对齐存好整份 BootInfo,抄进内核自己的 .bss 里,往后内核读的单子,全是自家院子的副本。这一抄还带出了一段题外话,咱们照实记下。抄送用的字节循环头一版是手搓的,一个字节一个字节往前挪——被当场点了一句,这不就是 memcpy 嘛。咱们认了,它就是 memcpy 的形状,那就该有 memcpy 的名字。头一拐咱们把它塞进了 boot 的公共面,被喝了回来:boot 的公共面凭什么替内核收行李,方向整个是反的。第二拐咱们把它挪进 kernel/lib,又被问了一句:base 不行嘛。一句话把咱们点醒了。与操作系统无关的通用件,头一个落点咱们就定在 base——三个编译世界谁都能用,而且 header-inline 让每个世界不花一分钱就各得一份实例。终态是 base/include/cinux/memory.hpp 里立起的 CopyBytes,清一色的 SetBytes 随后跟上。这一对轮子立起来的当天,咱们把全仓搜刮了一遍,五处手搓的字节循环陆续收编:摆渡的活是拷贝,归了 CopyBytes。entry 的清零、boot 三张表的清零、种子柜的清零、走查测试的池子清零,剩下的四处干的是填充,归了 SetBytes。这段弯路咱们记成一句话:通用件的家,头一个想的是 base,第二个想的是 kernel,boot 就永远别想了。

粮备齐了,单子也归了档,真正的动工在下一节:新城的街一段一段接上旧根,旧城咱们再一片一片地拆。咱们有一句话得搁在前头:拆城那天,顺序错了一步,QEMU 当场黑屏给您看。
