# 疼要喊得出名字

真正说话的是报告。咱们头一个看名字从哪儿来。三十二个向量的名册,一格一个名字:kExceptionNames 从 0 号的 Division Error 排到 19 号的 SIMD Floating-Point Exception,20 号记的是 Virtualization,21 号记的是 Control Protection,而 22 号往后到 31,老老实实写的都是 Reserved。Reserved 可不是没用的占位,它的意思是架构把号占下了、用途还没派定,上一节错误码表里新认的 29、30 就是活例子:虚拟化和安全的新用场找上了门,名字的栏位里还写着 Reserved。查名字的 name_of 有个本分:越界去问,它宁可跟您说个不知道、也不编一个名目。

咱们把报告的本体请出来:两行 Println 打完,机器就进了 Halt。

```cpp
cinux::print::Println("[kern] exception #%u %s", vector,
                      name_of(static_cast<unsigned>(vector)));
cinux::print::Println("[kern]  rip=%X cs=%X rflags=%X rsp=%X err=%X", frame.rip, frame.cs,
                      frame.rflags, frame.rsp, error_code);
```

第一行是名字带向量号的,第二行排的是五个数。六件的现场,咱们一件一件地过,说清每件为什么值这一行。名字说的是出了什么事:#6 Invalid Opcode 和 #14 Page Fault 是两种完全不同的疼法,一个的事主在代码里,一个的事主在页表里,名字一报了出来,方向就分了。rip 说的是在哪儿出的,这里有个要紧的细节:对 #UD 这样的故障,压栈的 rip 指的是肇事指令本身,而不是下一条。这个细节直接决定您该去哪个地址找事主,故障的意思是“指令没办成”,所以 rip 停在它身上,陷阱类的才是“办完了往下走”。cs 说的是当时在哪个段世界里,而本卷之后,它还多了一重用处,验收那天您会亲眼看到。rflags 是 CPU 当时的状态字,里头眼下最值得认的是第九位的 IF:中断开没开,一位就见了分晓。rsp 是栈当时的落点,栈要是被谁写花了,这个数是最早露馅的。err 说的是错误码,带码的异常它是事故详情,不带码的它是桩递的零。

位级的全谱,rflags 每一粒位的含义、错误码的位段,手册里有整章的明细,咱们只记眼下用得上的。您只要认下一件事就够了:这六件每一件都在替您省一次 GDB。真要您自己捞这几个数,断点、单步、查寄存器的三板斧,一样都免不了。如今它们自己走到了面板上来,机器临睡前把口袋翻给您看。

有两个名字咱们得提前打个照面,它们是拴在一起的一对。咱们头一个照面打给 #NM,7 号的 Device Not Available,它是浮点设备不在场的门,那类指令要是没了着落,就轮到它喊疼了。咱们把第二个照面打给 #XM,19 号的 SIMD 浮点异常,向量指令算出来的事故,归它来报的。两个名字眼下都还睡着的,因为咱们内核的旗子上一直挂着 -mgeneral-regs-only:不许编译器碰向量寄存器,那类指令根本不会出现在咱们的二进制里。下一节咱们就把这杆旗的事整个讲一遍,为什么撤、撤之前地基怎么打。撤完了之后,#XM 就从死向量变活了异常。

您可能会想:桩的末尾不是 iretq 吗,报告完为什么偏偏 Halt,不回去接着跑?您把两件事摆在一起就明白了:故障类的 rip 指着肇事指令本身,咱们 iret 回去,CPU 会从 rip 接着取指的,取回来的还是肇事的指令本身——于是又执行了一遍,又炸了一遍,又进了一回桩。这么回去,等于把同一出戏又演了一遍。对缺页这样现场可修的故障,将来的处理程序有机会把路修好再回去,那是虚拟内存当家的卷的事。对眼下的这些疼,回去就是再来一遍的事。所以现阶段的正主,是把现场说全、把机器停稳——报告当的是遗言,急诊的活它眼下还接不了。能活着回来的那一课,得等内核有了自测的家伙什再上,那是下一卷的活。眼下这一步的分量在别处:从这一卷起,疼了,名字喊得出来了,六件现场也报得出来了。咱们在黑屏和名字里,选了名字。
