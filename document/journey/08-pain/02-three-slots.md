# 三槽的算盘

立表之前的那点功夫,咱们得打一遍算盘:内核到底需要几格槽?这得问长模式把段式寻址废到了什么地步。您回想保护模式的那一卷,段的 base 和 limit 还是寻址的正主,进了长模式之后,CPU 对数据段的 base 和 limit 整个不看,代码段也只认其中的几粒位。可表又不能没有:CPU 每取一条指令的时候,CS 里都得指着一个在场的、L 位亮着的代码段描述符。所以最小形态数得出来:第 0 格必须是 null,这是硬件那边的要求,第二格是内核的代码,第三格是内核的数据。三格就齐了,第四格都是多余的。

这样的抠法,是有意的。咱们去考古箱里对照一下:当年大内核立表,一次铺了七格——用户代码、用户数据、任务段,任务段在长模式下占的可是两格,外带一条 ltr 把任务寄存器也装了上去。那会儿这些格的消费者一个都没有:用户态还不存在,任务段的用处更是没有,装上了也是摆设。第一遍的教程后来挨了读者一句“太陡峭、跟不上”,这样一口气铺满的做派就是病灶之一。咱们这一遍把纪律立在了前头:格子等得起,消费者来了再添。用户段和任务段的进表,等的是用户态真有了动机,零消费者的东西,咱们一样都不抄。

描述符的身量是八个字节,解剖学在保护模式的那一卷做全了:limit 分的是两截,base 分的是三截,access 独占的是一字节,flags 半字节则带着 limit 的高半字节。这一卷新做的是词汇。咱们把 access 字节的位和 flags 半字节的位,分成了两个 scoped enum:

```cpp
enum class SegmentAccess : unsigned char {
    kPresent    = 1U << 7,
    kRing0      = 0U << 5,
    kCodeData   = 1U << 4,
    kExecutable = 1U << 3,
    kReadWrite  = 1U << 1,
};

enum class SegmentFlags : unsigned char {
    kGranularity4K = 1U << 3,
    kLongMode      = 1U << 1,
};
```

为什么分两个,不合成一个?这两套位连住的地方都不挨着:SegmentAccess 独占的是 access 那个字节,SegmentFlags 住的是下一个字节的高半边,跟它同住一个字节的,是 limit 的高半字节。一个说的是这段的身份,一个说的是这段的尺码,要是两边能随意地混或,或出来的数谁也不认得。咱们给各配了一个 operator|,同族之内的合并是自由的,跨族要是或了一下,编译期就拦下了。代码段的 access 组出来是 0x9A,数据段的则是 0x92,一位一位全来自上面看得见的词汇,没有一粒来路不明的位。

咱们再看 flags 的半字节,代码段用的是粒度加 L 位。L=1 而且必须配上 D=0,是长模式代码段的硬配对,一位都错不得:它俩说的都是默认操作数宽度,L 亮而 D 不亮才是 64 位,D 也亮就退回了 32 位的旧语法。MakeFlagsLimitHigh 干的就是搬运:把 flags 的半字节挪进高四位,低四位垫满了 1——limit 全开的老写法。两座 constexpr 工厂 MakeLongCodeDescriptor 和 MakeLongDataDescriptor 出的货,一个的标准答案落在 0x00AF9A000000FFFF,另一个的标准答案落在 0x008F92000000FFFF。哨兵对数的时候认的就是它们,咱们把这样的标准答案叫作金位。

数据段的条目,咱们得专门交代一句,不然您会觉得它多余:长模式既然不看数据段的 base 和 limit,它存在的意义是什么?是选择子算术的均匀。ds、es、ss 换新的时候有格可指、不用特判,表里三格都是一样的八字节。CPU 忽略的是它大部分的字段,咱们照常把它摆正,省的是自己脑子里的例外。

表排好了:KernelGdt 三格,kTemplate 拿的是 constexpr,整张表编译期就排定了,开机的时候就在了。咱们把选择子也定下来:`0x08` 是代码段的,`0x10` 是数据段的,紧跟在 null 的后面。选择子的算术就是格偏移乘八,跟 boot 的表一样,只是这一回算的是自家的地界。

换表的动作在 LoadOwnedGdt,咱们分两口气看。头一句 lgdt 干的活,只有一件:把表的地址和身长,装进 CPU 的表寄存器。您注意,它一个段寄存器都没碰——CS 里跑着的还是 `0x18`,ds、es、ss 还是 boot 的旧值,换掉的只是“表在哪儿”的登记。CS 是不能直接写的,得靠一次远跳:把新的代码选择子压栈,把回来要执行的地址压栈,一句 lretq 打了下去之后,CPU 从栈上取回了段和偏移,CS 就落到了 `0x08`。剩下的数据段能写,咱们一条条地换:ds、es、ss 装上了 `0x10`,fs 和 gs 干脆清成零——咱们眼下没有它们的活儿,空着就明明白白地空着。这全套动作有个一直在吃红利的前提:中断从头到尾关着,保护模式那一卷立的 cli 到今天没松过,所以这一串换装,是不跟任何人赛跑的。

末了咱们记一处汇编约束的别扭,您自己写的时候多半也会遇上:选择子要是拿 16 位的类型进 `r` 约束,编译器就只肯配 16 位的寄存器,后头的 pushq 那句,汇编器当场就报错了。咱们的写法是选择子用 64 位整数进约束,movw 那头拿 %w 修饰符取它的 16 位视图。表本体 g_own_gdt 住 .cpp 的匿名空间,值取的是 kTemplate。内核是纯 64 位的单模式世界,私有进 .cpp 的章程在这儿成立,boot 为什么不能这么干,上一卷交过底了:三个模式挤一张镜像的世界,符号各归各的日子才过得下去。

段表立好了,地契到手。下一张要办的,是只有五桩在岗的半空异常表——这一回,咱们把它铺满。
