# 表是借来的

上一卷的结尾咱们说好了,这一卷的正主是中断的表。动工之前的那点儿功夫,咱们照例把现状盘一遍。盘着盘着您就看见了:要办的事其实是两张表,而眼下的局面,一张是借的,另一张是半空的。分工咱们得说在前头,免得后面的活儿串了线:GDT 管的是段世界长什么样,是 CPU 眼里代码段、数据段的户口本。IDT 管的是被打断的时候往哪儿跑,是异常和中断用的门牌簿。两张表伺候的是 CPU 的两套机关,谁也替不了谁。

咱们头一张盘段表。您还记得它的来历:保护模式的那一卷,boot 给自己立的是张三项的表——null 打的底,32 位的代码跟上,32 位的数据收尾,没有多余的一项。后来过桥进长模式的那一卷,远跳要带的 64 位代码段得在表里有格,boot 就把表加到了五项,`0x18` 记的是 64 位代码,`0x20` 记的是 64 位数据。内核出生的那一卷,咱们踩着人家的 `0x18` 进的门,门里挂桩的时候,选择子写的也是 `0x18`。这些在前面的卷里都交代过了,那时这么过日子倒是红利:表是现成的,咱们白用了一场。

可内核如今当了家,这笔欠的分量就不一样了。表住在 boot 的镜像里,是引导链上的家当。内核哪天想动它的一个字节,就得跨过编译世界的边界去够——跨世界的下场,上一卷 console 分家的时候咱们亲眼见过:静默的死,连一句遗言都是没有的。而这还只是够不着。更要紧的是,boot 哪天为了自家三个世界的讲究动了表,内核是连知情权都没有的。而住得再久,房子也不是自己的:段世界的每一天,都从 CS 指着的表开始,而表的产权,押在别人的手里。

咱们再盘异常表。三十二个架构异常的号,挂了桩的是五个:除零、无效指令、双重故障、一般保护、缺页,都是出生那一卷手搓的汇编前哨。前哨长什么样,咱们把当年的原文请出来看一眼,挑的就是无效指令那一桩:

```cpp
asm(".section .text.exc,\"ax\"\n"
    ".global ExcUd\n"
    "ExcUd:\n  pushq $0\n  pushq $6\n  jmp ExceptionCommon\n"
```

这三步咱们念一遍:垫零、压向量号、跳公共入口,除零和双重故障跟 ExcUd 是一个模子刻的。另外的两桩是一般保护和缺页,它们走的是另一个模子:CPU 进门之前,是会自己多压一个错误码的,桩也就不垫零了,只压自家的向量号、跳进公共入口。桩的活要分两种形状这件事,从出生那一卷起就定下了。报告的那头,老函数 ReportException 交得出的只有两笔:一个向量号、一个 rip,然后机器就睡了。您要是觉得这够用了,咱们就把剩下的二十七个号挨个想一遍:真踩中了,头一个赶到的是 #GP——它自己的桩是挂着的,所以面板上还能出一行字。可您看着 exc #13,是不知道当初惹事的到底是哪一号的:错误码没打,#GP 顶的是别人的名。等于哨所只建了五个,警报只报得出有事的动静,报不出是什么情况。

异常处理的路要是自己又出了事,这就成了双重故障。双重故障要是再出了事,CPU 就不再找任何人的麻烦了,它就直接复位了。机器黑了屏、重新启动,一句遗言都是不给的——这就是三重故障。它的哑,咱们不是头一回领教:过桥进长模式的那一卷就交代过,次序走错了一步,机器的回应就是它。前两卷咱们夸过口,说出事的早上喊一声 rip,而那句话是有前提的:哨还在,而且喊得动。而表要是空着,能喊的窗口就比咱们以为的窄得多。

考古箱里的一段旧事,跟段表、异常表都有直接的关系。当年走第一遍的时候,这套东西写了两遍,boot 自家立的表是不算在内的:停摆二十三天之后复健,小内核写了一套表和异常,上一卷翻日历的时候咱们见过那段日子。第二天大内核进了场,又把整套东西推倒重写了一遍。接力搬家的老病,咱们在装载那一卷下过判词:病根其实不在懒——没有人愿意把串口写三遍,病根在接力的结构。这一遍没有接力的负担,一张表一次就长全了。

卷内的次序,卷首已经排过了,咱们这儿只记头一件:立自己的 GDT、把地契拿回来。头一步的算盘,咱们从槽位打起。
