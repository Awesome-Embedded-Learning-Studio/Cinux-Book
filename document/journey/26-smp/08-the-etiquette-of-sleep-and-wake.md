# 睡前与叫醒的口径

睡眠的事,咱们单核时代其实一直带着一处含糊。含糊在三拍的次序里:等的人把自己挂进等待队列,把锁放了,然后才真正地切栈让出处理器。三拍之间有一条敞着的窗口,叫醒的人恰好趁窗口开着跑了一遍,把状态改成了就绪,塞进了就绪队列,自顾自走了。然后等的人不紧不慢走到切栈那一步,切栈的代码不管三七二十一把状态按回阻塞,人躺下了,而唯一会叫他的人已经走了。这一觉没有下一幕了。单核时代的窗口窄到踩不着,因为叫醒的人要与等的人共用一颗核,中间还隔着一次实打实的调度,几百万次的运行里没有一次交错。到了双核,叫醒跑到了另一颗核上,与等的人真并发,窗口天天敞得大大的。这一章的活,是把全内核所有睡的地方按同一个口径过一遍。

咱们立的口径有三句话。第一句管的是把入队与置阻塞收进同一把锁:等的人在持着等待锁的临界区里,查条件、挂队列、把状态标成阻塞的三件事,一口气办完了才放锁。第二句管的是真正切栈放在放锁之后:持着别人的锁睡觉是不许的,轮流当家那一卷立下的就是它,卡口到今天还守在原来的地方。第三句管的是叫醒幂等:叫醒的人也进同一把锁,看见的要么是还没入睡的,条件已经变了,要么是已经标了阻塞的,叫醒了他,把状态置成了就绪,塞进了就绪队列。叫了两声也只醒一次,因为第二声看到的已经是就绪,幂等保证了多余的叫不产生多余的队列项。

咱们把这三句合起来,窗口在结构上就没了。咱们拿互斥锁当代表,看修完的形状:

```cpp
void Mutex::lock() {
    const cinux::arch::IrqGuard kParkGuard;
    Task* const kSelf = Scheduler::self().current();
    {
        const SpinGuard kGuard(spin_);
        if (owner_ == nullptr) {
            owner_ = kSelf;
            return;
        }
        waiters_.push_back(*kSelf);
        Scheduler::self().prepare_to_wait();
    }
    Scheduler::self().schedule_blocked();
}
```

条件、入队、置阻塞一口气在自旋锁的临界区里办完,prepare 那一句就是口径的第一句。临界区这么一放,才调真正切栈的函数。这里头还藏着一个妙的机关,咱们慢慢看:如果叫醒恰好发生在放锁之后、切栈之前,那个被叫醒的人此刻状态已是就绪,人已进了就绪队列,而他自己还站在自己的栈上。切栈的函数会去挑下一个任务,挑选的条件里本核握着的任务可取,他偏偏挑得中自己。挑中了自己,函数发现下一个恰好是当前的自己,直接返回了事,一次切换的功夫都不用,他就这么接着跑了。窗口里的叫醒不但不丢,还省了一趟切换。

全查的名单咱们如实报:互斥锁、信号量、完成件、词上的等待,四家用的是同一个形状,挨个改齐了。词上的等待说的是 futex,睡的人守在共享内存的一枚整数字上,谁改了字,叫醒人的事就落在谁的身上。第五家管的是等孩子退场,它的形状略不同:扫描名册、挑僵尸、入等待册、置阻塞,这几步都在共享的调度锁里办完,真正的切栈在锁外,同口径严丝合缝地对齐。完成件这一路其实有前科:开门迎客那一卷,盘的完成件修过一回同族病,当年修的是入睡那一侧,入队与泊车之间的窗口。这一回轮到的是唤醒那一侧,同族的病果然复发,这一次是把它连根按进统一的口径里,不再一处疼了修一处。

测试这边咱们同步立了两件。宿主的长凳上,那件测试守卫正式立形:守卫穿在身上的时候,睡眠只标状态而不切栈,长凳世界自己踩自己的地板,宿主案子能演真实的睡眠语义而不需要真的调度器。配套的状态机案把守卫内、守卫外、嵌套守卫、内层退出外层还在,四种情形的每一步状态变化逐拍断言,嵌套的情形尤其要紧,内层守卫析构了不等于解除,最外层退干净了才恢复真切换。机内的案更狠一桩:prepare 之后、切栈之前,另一颗逻辑核动真格的去叫醒,断言这一叫丢不了、不重复、不多切。窗口案是从审查的单子上下来的,单子上点出的毛病是,那桩案只验了最后凑起来的总数,没有验过窗口里交错的那一瞬本身,于是咱们补了一桩真在交错瞬间叫醒的案子。

考古的一笔。当年这族病是在四处同时发作的:互斥锁、信号量、词上的等待、等孩子,四个地方写的都是入队放锁切栈的老三拍,单核上全数过了关,双核一开四家一齐犯了病。四家的病根一模一样,修法的路子也一模一样,当年把它们一并收进了同一个口径。这一遍咱们多走了一步,把口径收成了调度器上的一对函数:睡的人调前一半,醒的世界看着后一半,谁想睡都得从同一处的入口进。下一章咱们去清锁家族另一批单核时代欠下的旧债。
