# 一张变长的户口本

咱们把上一卷撂下的话捡起来:机器里其实一直躺着第二颗核,只是咱们还没去叫醒它。不过真要叫醒它,有三个问题得答在头里:咱们的机器到底有几颗核?从外面进来的中断,该送到谁的门口?老总线上的那些引脚,固件有没有偷偷改过道?这些问题的答案都不在咱们手里,而攥在固件手里,它开机时就把答案写成了一张表摆在内存里,这一章咱们就来认它。

表的名字叫 MADT,它的全称是 Multiple APIC Description Table,中文的叫法是多 APIC 描述表。APIC 是 x86 机器上管中断的那一类硬件的名号,下一章咱们细讲,眼下只需记一件事:MADT 就是固件写下的中断户口本,谁家有几口人、各家门牌多少、老门牌改成了什么新门牌,全写在它的每一栏里。它长在 ACPI 的表家族里。认字那一卷咱们已经扫过表根:把 RSDP,规范名的根系统描述指针,从 EBDA 和高端的那一段揪出来,顺着它按签名一张一张地查表,关机的 FADT、细一档时钟的 HPET 都是这么请出来的。所以查表的家底全在,MADT 只差一件新事:认它的内容。

内容是这个样子的。开头是四十四个字节的表头,签名、长度这些老亲戚都还是原来的样子,新添的亲戚有两个:偏移三十六处摆着一个三十二位字,是本地中断控制器的物理地址,全机的核共用同一个门牌。表头后面跟着一串变长的条目,没有哪一节是定长的,每个条目开头的两个字节,一个报的是类型,一个报的是长度,条目的长短、下一条的起点,全凭头两个字节的交代。这跟咱们之前认过的表都不一样,之前的表字段位置固定,MADT 的条目像一列货车,每节车厢的长度都不同,得读了一节再数一节。

咱们挑三种车厢认。第一种是类型零的处理器条目,只用了八个字节,报一个处理器:谁家的核、它的中断身份号是多少、一个三十二位的旗标字,旗标的第一位说它能不能用,第二位说的是它虽然现在没上线、热插上就能用。咱们两条都收,能不能用与上没上线是两件不同的事,这一章咱们把人记上册,上线的事后面再说。第二种是类型一的 IOAPIC 条目,用了十二个字节,报一片外部中断芯片:它的物理地址,还有它管的引脚从全局几号开始编号。第三种是类型二的中断源改写条目,用了十个字节,这是户口本里最值钱的一栏:老总线的某个引脚,实际上被路由到了全局几号。全局号的专名是 GSI,它的全称是全局系统中断号,把全机所有中断引脚不管谁家的,统一排成一条队发的号码。

读它的代码咱们写得保守。条目里的多字节字段不做对齐假设,统一走 base 的读词原语,按字节搬进本地值再读,坏对齐的表也读不炸。每条已知条目进了门就验长度,报的长度短于它类型的身架,整张表一并拒收了。整条链也要验完整:表长不得小于四十四字节的表头,不得大过手上实际有的字节,不得大过六十四 KiB 防的是坏表把扫描拖穿内存。条目长度不得小于自己的两字节头,条目的结尾不得越过表长。任何一环不过,咱们就拒收整张表,返回一份空的拓扑,开机序列看到空拓扑就响亮地停下。为什么这么狠,你想,户口本错了一个字,中断路由就错了一条线,带着错路由跑起来的机器,病都病得没了头绪,所以干脆拒绝开机。未知类型的条目倒是宽容,按自己报的长度跨过去,规范本来就允许固件塞咱们不认识的车厢。

收敛出来的形态是一份小而硬的结构:本地控制器地址、第一片 IOAPIC 的地址与全局号基址、至多八颗处理器的身份号、至多十六条改写记录,再加一位旗标说这机器兼不兼容老的 PC/AT 中断模式。容量的数字独居一个小配置头,这是配置类常量的家法,能上公告面的只有类型与函数。有两条边界咱们当场挂明处:IOAPIC 只认第一片,固件要是把全局号摊给了多片芯片,超出第一片范围的路由咱们拒绝,不冒充支持多片的平台。改写条目只收老总线来的,总线的代号不是零的一律不理。

测试在宿主的长凳上打头阵。解析逻辑独占了一个源文件,硬件查找留在了另一边,宿主案子链接的是不带真表根的纯解析。畸形表咱们挨个喂:截断的、签名错的、条目越界的、长度为零的,一个也过不了。拓扑的正例里八颗核的上限、首片为准、改写收录一样样断言。

实机上的收据开机就打,咱们把串口那行抄来:

```text
[apic] 2 processor(s), local id 0, IOAPIC fec00000, overrides 5
```

表里点齐了两颗处理器,第一片 IOAPIC 的住址是 0xFEC00000,改写记录收了五条。机内的地址空间案子也跟着长厚:真实 MADT 进来对一遍,身份号、物理地址、与处理器手册里那个基址寄存器的读数互相核对。此刻 MADT 只是读了出来、映射了本地控制器,中断还走的老门房,咱们只是知道了两颗核的存在。可户口本里的五条改写记录,藏着这一卷最值钱的一处金矿,下一章咱们来挖。
