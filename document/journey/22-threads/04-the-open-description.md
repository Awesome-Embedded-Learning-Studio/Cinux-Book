# 打开的那份描述,立了户

搬家的动工之前,咱们把一笔旧约请出来。生与收那一卷教 fork 抄家当的时候说到文件表,咱们当时交过底:父亲读到的偏移,孩子原样抄了一份,抄完之后父子各读各的,两边的游标互不牵动。可 Unix 的真义里,fork 出的父子递到的是同一份打开,游标只有一支:读的人推着它往前走。当年咱们把话撂在了明处:共享偏移的那一等,Linux 家 dup 的语义,得等打开文件描述的那一层立起来才有,咱们留给讲线程的这一卷。这一卷到了,咱们今天兑约。线程共用一张文件表:共用的是描述,连描述带游标都得有个立得住的住法,本节咱们把它立起来。

从前的住法,咱们看一眼就能看出毛病。描述住在 FileSlot 的格子里,一格四样:后端的一对面孔、节点的号、读到的偏移,描述和格子是一体的,格子又是长在任务身上的。想共享的 fork 只能重开一格、把偏移抄一份,因为描述没有自己的户口,它是随格子活的。这次咱们给它上户口:OpenFile 立户,生在了堆上,带着自家的引用计数,生下来就攥着一个节点的引用,死的时候归还。跟着户口走的是后端对、节点、游标。表里的格子从此轻了,格子里存的只是一张持有票,base 家的 Shared,它跟管独占的 Own 是一对,生与收那一卷进的门:哪格指着哪份描述,清清楚楚地写在票上。FileSlot 这个名字就此退了场,表的实现也从头文件里搬了出去,住进自己的编译件,头里只剩公告的脸面。

家搬完了,fork 的手续跟着换了,换的那一笔正是旧约的内容。从前的办法是逐槽重开再抄偏移,如今是逐槽认领:父亲 3 号指着的描述,孩子的 3 号直接认领同一份,票加了一张,号还是原来的号,游标走的还是同一支。读的人推一步,接的人读到的就是下一截。您拿验收的实弹对着看最直观:演示程序里,一条流读了开机问候的头八个字节,接着读的是主线程,读上来的是 ys hello,两处接力走的都是同一支游标。偏移终于一起走了,这句当年欠下的话,今天咱们原样交割。

这里有一层分寸值得咱们单独说清:表只管表的事,描述只管描述的事,两层各有各的共用。fork 的孩子各有一张表,表里认领的是同一份描述,所以游标一起走,可谁关谁的门各是各的,孩子 close 掉自己的 3 号,父亲的 3 号安好,只是描述少了一张票。往后讲 clone 的那一篇还有另一层:连表都共用,全家看的是同一张表,一个成员 close 了 3 号,全家再看的都是空格子。两层共用各配各的开关,语义的差距是一整个身位,名册上咱们一开始就把它分开记。

票的生命线,咱们也有几句话要交代。开一份新的描述:造户、领票、票进格子,表要是满了,票当场就废了,户也当场注销了,节点的引用一个都不多拿。close 做的是销票,格子清了空,票也少了一张,最后一个持有者放下票的那一刻,描述才算死了,死时把攥了一辈子的节点引用归还。一方销了票,另一方还好好地活着,您别把这当漏洞,这正是描述立户的用意,宿主的案子里专门有一条考它:两张表认领同一份,一方 free 了之后,另一方的读照常工作。顺着这套票的章程,Task 身上的文件表也从值改成了持有:每个任务生来自带一张空表,这是出生的默认,想改指别家的表,咱们还是留给 clone 说。

这次搬家还带着两笔顺手的整修,咱们报个数。头一笔落在 base 的 Shared 上,它长了一层本事:数票走引用基类的脸,注销走收养那一刻记下的函数,所以持有者只要一个前向声明,不必看见类型的全身,任务的册里揣着地址空间和登记册的票,头文件里却不必把它们的身子全展开。家底长了本事,咱们让它回流 base。走法是双向的:通用的新件,咱们给它把第一落点直接落在 base。base 的旧件,咱们让它跟着新消费者升格,咱们管这个叫双向流动。第二笔的整修落在地址空间和登记册上,持法从独占改成了带计数的共有:fork 还是老手艺,克隆世界的老路照走,写时复制的老法照用,可世界从此有了好几个主人,最后一个离开的人负责拆。为什么现在就要改?因为下一节的 clone 有一面旗叫共用世界,组里的成员们指着同一个世界活,收尾的活落在最后走的人身上,没了计数,咱们就说不出这句话。exec 换世界的手续也随票据换了笔法:旧的世界搬去一旁,新的世界挂上身,页表也切了过去,旧的到这一趟走完才散,拆的世界不能在脚下还被页表走着的时候就散架。

测试的家底,宿主的文件表件添了两条共享案,认领之后两张表的游标一起动,一方销了票,另一方还活得好好的。机内 fork 的老案子里加了一条断言:孩子的 3 号和父亲的 3 号,指的是同一个描述对象,两边握的是同一个指针,认领是真的认领,不是抄像了。描述立了户,共用的家当有了住处,分家的清单可以拿上台面了。下一节咱们请 clone 进门。
