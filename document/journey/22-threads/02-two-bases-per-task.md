# 两枚基址,记进家册

动 TLS 之前咱们把一句挂了很久的旧话请出来,生与收那一卷的原话,咱们逐字念回来:咱们两个 GS base 至今同值,swapgs 换的是相等量,配对怎么乱都乱不了——这是结构上的免疫,不是修好的病。哪天用户态真用自己的 GS 基址了,简化也免不了连着改,那天的事那天办。听得懂喊声那一卷关银行的时候又把它点了一遍,说帧的事与它无关,那句话咱们接着挂。今天就是那天了。线程的 TLS 靠的是 FS,可那句远话说的是两枚 base 的简化:要作废就得连着 GS 一起改,基址从今天起是各任务的家当,咱们把它记进家册。

家册指的就是 CpuContext,切换器搬的就是它。咱们给它添两格新槽,排在浮点影像的后面:五百七十六住的是 fs_base,五百八十四住的是 gs_base,整个身子从五百七十六字节长到了五百九十二。布局锁照家法逐条上齐了,咱们把三条断言抄在下面。头一条是新的,管的是 fs_base 的座次。第二条也是新的,管的是 gs_base 的座次。第三条是旧的总数断言改了数改了词。咱们把原文翻过来念:fs_base 骑在影像的后面,gs_base 给整个上下文收的尾,成分是八个槽、一幅五百一十二字节的影像、两个基址字,咱们加出来正好五百九十二:

```cpp
static_assert(offsetof(CpuContext, fs_base) == 576, "fs_base rides behind the image");
static_assert(offsetof(CpuContext, gs_base) == 584, "gs_base closes the context");
static_assert(sizeof(CpuContext) == 592, "8 slots, one 512-byte image, two base words");
```

搬家的活咱们交给了 C++ 这一侧,切换的汇编一行没动。切换器的三个来路:请人上 CPU、从主流程进场、回到主流程,如今都在动手切上下文以前多走了一步,头一步把旧任务的两枚基址从 MSR 读走,存进它的册,第二步把新任务的册装回 MSR。您要是问这一步为什么敢放在汇编外头,答案是它本来就该在 C++ 里:家册是 C++ 的字段,搬进搬出对的是字段,汇编管的只是寄存器和栈。

真正动脑子的是 GS 那一半,咱们把新章程从头说。x86-64 给 GS 备了两枚 MSR,一枚活着的,管的是当下在跑的任务,另一枚影子里的,swapgs 响了一声,两个对调了身份。从前的章程里两枚都指着 per-CPU 块,对调换的是相等量:入口汇编进内核换一次、回用户换一次,生成的孩子再换一次。新章程把家分开了:活的那枚从此常驻 per-CPU 块,谁来了都不换,入口汇编凭 gs:0 直取块上的内核栈,连对调都省了。任务自己的 GS 值住进影子槽,当的是摆渡的船:任务上 CPU,切换器把它的值装进影子槽,任务下来的时候,再从影子槽读回它的值,存进它的册。三处 swapgs 就此退了场,柜台那一卷当年告诉咱们这一拍省不得,因为两个世界的分界线要靠对调来画。今天的分界线画在两枚 MSR 的分工上,一枚是常驻当值的,一枚是随任务摆渡的,当年省不得的那一拍,今天真的省了。

FS 的那一半比 GS 简单,咱们看它从头到尾只有一枚 MSR,分界线也就省得画了。它是全活的:内核自己的寻址,从柜台那一卷起走的就是 GS,咱们翻遍内核的代码,FS 的活一次都没派过,所以它随时可以换装。谁想改自己的 FS,咱们照 Linux 给它开门,走 arch_prctl 的一百五十八号。SET_FS 把值写进任务的册,顺手写进的是活 MSR,调用的人正拿着 CPU,两处动的是同一拍,自己的下一次访存就走新基址。这层承载的等式咱们用一句白话说:基址装的是哪一格,fs:0 取的就是哪一格。演示程序里读 TLS 的那行内联汇编,写的正是 movq %%fs:0,验收实弹里两条线程各自读回的数,认的就是上面那句等式。GET_FS 从册上读回它的值,经用户指针交还给调用的人,写之前过的是一道可写检查。SET_GS 与 GET_GS 走的是同一对操作,只是写进的是影子槽,读回的也是册上的话。门口还立了一道检查:值必须规范,高十七位的每一位都得一样。您问为什么这么严,因为不规范的值递给 wrmsr,CPU 当场就报了一次 #GP,临了连一句 errno 都没留。咱们在门口就拒,答的是 EINVAL,门里不给 CPU 发这个脾气的机会。判定函数与两条界一起进了家册,用户半区的顶、内核半区的底,中间那段谁也不认的天洞,正好从用户界的门槛上开始。

诚实的话也要说在明处:GS 的这一半,咱们立的是册,活路还留了一条。ring3 真拿 gs 去寻址的话,寻到的还是常驻的 per-CPU 块,任务自己的 GS 值今天活在册上、活在 GET_GS 的回话里,还没有一条换上真 MSR 去跑的路。为什么这样也够了?因为库在咱们的机器上 TLS 走的是 FS,GS 的真消费者还没来,咱们把册立对,路等有人的那天再修。基址是各抱各的那一半,这话本节开头就说了。

号册的双重身份,咱们顺手立在这里。gettid 一百八十六号开了门,答的是任务自家的号牌,一个进程里的每条流都有自己的那一枚。getpid 的答法改了:从今天起它答线程组的组长,同组的成员人人报的都是组长号。线程组这个词咱们头一回说全:它跟听得懂喊声那一卷喊一片的进程组不是一家,进程组是一伙进程共挂的门牌,线程组是同住一个身子的几条执行流自己的家,家里共的是名号。组长是谁?调度器收孩子入册、发号的动作,咱们叫坐席,坐了席的任务起头都是自己的组长,要入伙的流,得等 clone 的入组旗,那是后面几篇的事。咱们还请 set_tid_address 从二百一十八号进门。咱们的号表从前界在二百一十八,二百一十七是最高的住户,这一号进来了,界挪到了二百一十九,给二百一十八让出了座——挪界这件事咱们干过,按的是老章程,号照的是 Linux 的原样,界跟的是住户。它办的事说来简单:记下一个用户地址,说好了将来我退场的那天,把我记的这个词清成零。可这个词为什么值得一个专门的号,咱们卖个关子,留到讲送行的字的那一篇,戏在那里等着咱们。

基址记进家册了,身份也分好了。可挤在同一个世界里的几条流,总得有个说好的章程——大家在一个词上碰头,暗号是一个说定的数,等的睡,改的叫。下一节咱们立 futex。
