# 一扇自己找地方的窗

验收的四条配置线,咱们按惯例一条一条跑,数据竞争线头一个跑就红了。红的名目蹊跷得很:挂的是信号那一卷的老测试,改的更没有——那套假栈窗口的代码,信号那一卷立下之后咱们一行没动过,当年验收的时候四条线一次全过。咱们手里的代码还是同一份,换一条线跑就稳定地崩。同类的案子咱们见过族亲:普通构建绿得安静,咱们一开插桩,毒药铺上去当场现了形。可这一回连插桩都算自己的,真正的凶手另有其人。

咱们把窗是什么说清楚。信号投递要把改写的现场摆到用户的栈上,宿主的长凳没有真的用户栈,就造一扇假窗:拿 mmap 在内核真栈顶的下方开出两页,伪栈顶落了进去,引擎的地址算术对着内核真用的常数跑。开的办法用的是 MAP_FIXED,地址是算死的,窗就定在了那个位置。这套手艺本身是没有错的,错的是它挑的地方,而它挑地方的时候,咱们也没告诉它脚下可能有人。

有人落了脚,而且就在数据竞争线里。数据竞争的插桩一开,宿主进程自己的运行时大了一号,咱们实测,插桩把栈的落点挤到了栈顶近旁,咱们量下来,离内核真栈顶只剩了八千零六十四个字节,咱们再一算,两页差了一小截,而那扇窗,咱们定在了内核真栈顶下两页。别的构建线里,栈的落点是地址随机化撒开的,插桩的落点不由它做主。这么一说,测试自己站的那块栈,恰好被自己开的窗换掉了。MAP_FIXED 这个旗子的脾气咱们都背得出:它不问住户,地址给定,原来映着什么直接掀掉。于是窗铺下去的那一刻,脚下原本是测试自己的栈帧,铺完变成了干干净净的零页。测试还在一层一层地调用,返回的那一拍从零页里取地址,CPU 落进了零页,程序计数器归了零。当年普通线和地址排查线也都绿了一回又一回,咱们现在回头看,其实纯是运气。您看普通线,插桩是没带的,落点全凭地址随机化做主,恰好落在了别处。地址排查线的绿,咱们查下来靠的也是同一份运气,窗偏偏谁的脚下都没压着。绿过的案子挡不住这个,因为看那块内存的眼睛,咱们当年一只都没有。

修法咱们起的名字是让窗口学会自己找地方。窗不再定死一个地址,改成从栈窗的底部起步,一格的大小是六十四 KiB,拿 MAP_FIXED_NOREPLACE 往上试:格子空着的话,窗就落了进去,伪栈顶跟着搬了家。格子有了住户,NOREPLACE 不掀人家的页,答一声此地已占,咱们换下一格再试。栈顶的近处留出一整截不碰,那是别人家的院子。试满十五格还没有空地,响亮地失败,退出码定的是三,把话喊了出来——绝不静默跳过,静默跳过的测试比红掉的测试坏得多,它红的时候咱们还知道它病了。修完了之后,数据竞争线连跑了二十回,普通线和地址排查线各连跑了五回,回回都是干净的。

这一案连同长凳上的死链、虚析构那一案,算的是三家同门,咱们把同门的家训再说一遍,每说一遍它就更结实了一点:测试自己也是代码,它跑在自己的进程里,动的是自己脚下的内存。MAP_FIXED 与 MAP_FIXED_NOREPLACE 差的是一个词,差的却是拆谁的家。绿过的测试不是免检的,换了一条构建线,等于换了一双看内存的眼睛,眼睛换了,咱们再看一眼,图的是审慎。窗的事完了,下一篇咱们正式验收,让几条执行流上了台,唱一整出的戏。
