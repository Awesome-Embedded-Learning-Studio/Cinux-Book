# 三十八从哪里来

clone 落地的那一批,咱们顺手把线程的演示程序造了出来,想让它上机好好地走一圈。谁知它还没走到线程的戏,头一站就在门口演了一出怪戏:shell 里 run 下去,孩子的世界里冒出一个三十八,不是咱们让它打的,报错的文案反而没了,再往后 shell 自己的主循环都乱了。一个来历不明的数字,一句消失的台词,这案子咱们查了两天,查出来的东西值得单独开一节,因为它教的是编译器这一侧的课。

咱们走错的排查路也摆出来看。孩子的世界、fork 的克隆、盘上的文件系统,咱们挨个疑了一遍,可疑的地方翻了个底朝天,什么也没翻出来。为什么一开头疑的是这些?因为症状出在孩子里,孩子是 fork 造的,它肚子里出了乱子,头两个嫌疑人当然是造它的和喂它的。这个直觉害咱们耗掉了大半天。真凶住在咱们最不疑的地方:用户侧那个小小的包装函数。

病分成了两层,咱们从表层说起。咱们在 shell 里敲的是 run 加裸的程序名,可程序住在盘上的 /bin 里,裸名折出来的路是 /hello 这样的一级路径,盘上没有这样的路。exec 找不到要找的文件,答了一句拒绝,这个拒绝是正确的答案,内核一个字的错都没有。所以案子的真相是:程序确实该拒,拒也确实拒了,可拒的回话,您一句都没听见,听见的是三十八。这就要说深层了。

Execve 的包装函数,从早些的版本起带着一个属性:不许返回,函数的末尾还立着一句 __builtin_unreachable,白纸黑字地告诉编译器,控制流到不了这里。咱们当年写它的时候想得也简单:exec 成功了,旧世界整个被换掉了,这个函数自然没有回来的那一天。可咱们漏算了一半:exec 被拒绝的时候,函数是要回来的,而且回来之后还有活干,打印一句 run 的报错,带着退出码退了场。问题就在这:属性许出去的话,编译器是当真的。咱们许的是不许返回,那么返回之后的每一行代码,在编译器的眼里都是死代码,开了 -O2 之后,报错的那两句连同退出码,干干净净地删了。删完之后控制流落在哪?落在调用点后面随机的内联残骸里。冒出来的那个三十八,就是残骸里滚出来的一个数,它不是谁写的,它是垃圾被当成代码跑出来的口供。

破案的功夫也交代两句,这才是本节真正的货。头一步咱们做预处理,把翻译单元原样地倒出来看,字符串还在原地,源码是全的,这排除了没编进去的嫌疑。第二步看的是反汇编,拒绝的路在机器码里整个没了,动手的是中端,机器码当面作的证。这一趟给咱们立的次序是:反汇编看在前,语义的疑问在后。手写错的代码,顺着源码的线索总能审出来,编译器按许下的话删掉的代码,源码里的一个字都不缺,你盯着源码看一万遍也看不出它少了什么。编译器删的,比写错的,难查得多:这一句咱们原样记进名册。

修法反而最简单。包装的属性摘了,函数改成了可返回,exec 成功的时候不回来,拒绝答一个负的 errno,调用点把文案老老实实地打出来,退出码交的是一。这里头的道理一句话:不许返回是许给编译器的话,兑现不了的话,咱们一开始就别许。写下去的属性就是许诺,许诺管着优化器的每一刀。往后咱们再给函数挂属性,问自己一句:这话我兑现得起吗。

三十八的案破了,演示程序终于能走到它的正戏。下一节咱们把正戏的最后一块立起来:线程怎么退场,等它的人怎么知道。
