# 嗓子是借来的

上一卷收工的时候,内核当了家。打三行字、扫自己的院子、出事的早上喊一声 rip,它都学会了,听上去已经有模有样了。可您要是冷静下来追问一句:这些话,是从哪儿说出去的?答案有点尴尬:每一句话,都是从 QEMU 的后门递出去的。

后门就是 0xE9 上的一个端口。当年咱们在最荒凉的引导阶段认识它:QEMU 给虚拟机装了一个“调试控制台”,您往 0xE9 写一个字节,它就原样送到您的终端上。它没有初始化的讲究,没有握手的礼数,也不碰任何真实硬件的状态——机器醒来的那一刻到断气,通道全程都是开着的。它救过咱们的命——从 MBR 的第一句话,到上一卷内核的第三行字,这一路所有的话,全是它在替咱们传。您回头翻翻面板就会发现,起居序列里没有一个字不是从它这儿出去的。

麻烦的是,后门是 QEMU 家的家具。真正的开发板上没有 debugcon,也没有 0xE9——您往那儿写一个字节,就是往一个没有人应答的端口里扔了一个字节。咱们这套代码搬到真正的机器上,内核还活得好好的,手里的活一样也没耽误,出事的早上照样喊一声 rip,只是再也没有一个字能到您眼前。内核成了哑巴,说什么“体面地停住”都是空话:它停了,您也不知道它停了。从咱们用 0xE9 的第一天起,这件事咱们就一直欠着。那会儿咱们欠得起,引导期嘛,能往外说上一个字已经是天大的奢侈。如今内核当了家,该还了。

还的方向,得问真正的机器有什么。QEMU 专属的外设指望不上,能指望的是几十年不变的最低共识:串口。PC 从最早的年代起就带着 UART,COM1 的那颗芯片从 8250 一路传到 16550,寄存器的排布到今天还认得。BIOS 不在了,图形模式切走了,连操作系统都没有的日子,它也照样活了下来。这事不用想得多深:串口就是真正的开发板上咱们最敢指望的一张嘴。咱们把它喂饱,内核的话才能说得出去——不光在 QEMU 里,换到哪台真刀真枪的机器上都一样。

所以本卷,咱们就上两道菜,不再多了。头一道是把话说在真正的串口上:boot 和内核整条链改走 COM1,寄存器咱们一颗一颗地亲手编程,QEMU 的参数跟着换班,再请 debugcon 退了役。第二道是把内存记在自己的名册上:上一卷誊进单子的 E820 图谱,boot 侧在九判里帮咱们问过一回,内核侧却只是数了数条数、打了一行字,连图谱本身其实都还没花过一个子儿。上一卷收尾时咱们说好,下一卷从内存的家底起头。真到排次序的时候,却是嗓子的活更急:名册的数再准,报数靠的也是嗓子,所以家底排在第二道。本卷咱们给内核配一本一页一个 bit 的位图名册,机器的内存谁住着哪页,记得清清楚楚的。两道菜其实是同一件事的两面:内核接管,接的就是它自己的输出和它自己的内存,咱们这一卷,就是把这两样递到它的手里。

收工的时候,您会在面板的尾巴上看到这样几行:

```text
[kern] 64-bit C++ world alive
[kern] bootinfo: 8 e820 entries, fb 1024*768*32
[kern] kernel at 200000 size 810C0 entry 200296
[kern] pmm: 32350 pages free (probe 100000 ok)
```

您要是眼尖,就能看出两处新的动静。一处是末尾多出来的那行 pmm:空闲的有 32350 页,还顺手分了一页、验了货、又还了回去——机器的家底,头一回由住在里面的住户自己报出来。另一处是 size:上一卷内核的地界才 C40,这一卷涨到了 810C0,五百多 KB 的块头。您别慌,不是内核发了疯在长肉,涨出来的部分几乎全是一本还没出场的名册——整本躺在 .bss 里,而盘上一个字节都没为它花。讲到名册的时候,咱们把这数慢慢对清楚。

面板的头部也变了样,咱们把话放在前面:以前 MBR 会说的那两句话——`Ready to call bios` 和 `Jump to Stage 2`——从本卷起没了,起居序列的第一行改由 stage2 打。东西其实没丢,这是一笔算清楚了才做的取舍,它的代价与所得,咱们讲到 console 分家的时候正面交代。
