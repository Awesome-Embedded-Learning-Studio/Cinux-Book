# 真串口,七写开嗓

咱们去认识 COM1。基址 0x3F8——这个数您八成在别处见过:Linux 下的 /dev/ttyS0,Windows 里的 COM1,说的都是这颗从 0x3F8 起家的 UART。芯片的家谱从 8250 一路传到 16550,寄存器的排布几十年没挪过窝,所以咱们今天写的每一笔,既对 QEMU 里的那颗成立,也对插在真正开发板上的那颗成立。到哪儿都认——凭的正是它一身的资历,咱们才挑它当嗓子。

它跟 debugcon 的脾气完全不同。debugcon 是个后门:您往里写一个字节,它就把字节送到您的终端上——中间连一道关卡都不设,上一节数过的讲究它一样都没有。16550 是一台真设备:它有自己的脾气和家当,您不喂它一套初始化,它是死活不肯开口的。可编程好了,它还能回您的话。咱们跟它打交道,靠的是一组寄存器——都在端口空间里,从基址 0x3F8 一个偏移一个偏移地排过去。咱们这一路用到的也就这几颗:

```cpp
constexpr uint16_t kCom1Base = 0x3F8;

constexpr uint8_t kRegData = 0x0;
constexpr uint8_t kRegIer  = 0x1;
constexpr uint8_t kRegFcr  = 0x2;
constexpr uint8_t kRegLcr  = 0x3;
constexpr uint8_t kRegMcr  = 0x4;
constexpr uint8_t kRegLsr  = 0x5;
```

Data 是递字节的门,Ier 管的是中断,Fcr 管的是 FIFO 队列,Lcr 定的是数据格式,Mcr 管的是握手线,Lsr 则是它回话的嘴。每个偏移的背后都还有一整套故事,寄存器全谱和那些模式寄存器的细目,数据手册里自有整章的明细,本卷不铺开——咱们只认亲手写进去的那几颗。

咱们得在开嗓之前递它七张条子,每张只写一个端口的值,次序是乱不得的:

```text
0x3F9 ← 0x00   Ier:把中断关死
0x3FB ← 0x80   Lcr:DLAB 开门
0x3F8 ← 0x01   除数,低字节 = 1
0x3F9 ← 0x00   除数,高字节 = 0
0x3FB ← 0x03   Lcr:DLAB 关门,8N1
0x3FA ← 0xC7   Fcr:FIFO 开,收发两队各清一遍
0x3FC ← 0x0B   Mcr:DTR、RTS 拉起,外带 OUT2
```

咱们一张张看。头一张把 Ier 清零:咱们眼下不请串口打断自己,话怎么递,咱们上门问,就不劳它喊了。这跟开不开中断的旧纪律是一路的——中断要一张全量的表,眼下在岗的五桩只管得了出事的早上,设备的敲门声还进不来,急什么。

第二张和第五张是同一扇门的开与关,这里藏着 16550 的一个小机关:DLAB。Lcr 的最高位一置位,0 号和 1 号偏移就换了脸——不再是 Data 和 Ier,而是除数锁存器的低半和高半。您记一下这个换脸:同一对端口的两副面孔,靠 Lcr 里的一根开关切换。所以七张条子里,Lcr 只出场了两回:第二张开的门,第五张关的门。换脸不算 Lcr 的第三笔写(它压根没有第三笔),换脸是 DLAB 顺手的杰作。夹在中间的第三、四张,就是在那副换过的面孔下,把除数写成了 1。这笔除数的来历,拿的是芯片内部 1.8432MHz 的钟——十六分频、再除以除数,咱们把除数取 1,出来的波特率就是 115200。为什么偏偏是那个钟、为什么十六分频,数据手册的开篇有整笔的推导,咱们不在这儿算,本卷认的只是结果:115200,一个用了几十年的老波特率,QEMU 里那颗和真正的串口线都认。

第五张把 DLAB 关上的同时,顺手把数据格式定了:0x03,8 个数据位、无校验、1 个停止位的格式——行话叫 8N1,串口世界的普通话。第六张 0xC7 打开的是 FIFO,收发两个队列也各清了一遍,别让上电时门口排的旧货混进来。第七张 0x0B 拉起的是 DTR 和 RTS 两根握手线,再外带一根 OUT2——那是 PC 平台上几十年传下来的老定式。咱们不做流控的戏法,照经典序列写:数据手册给的就是这套,咱们不发明。

条子递完了,嗓子也开了,该说话了。您可能以为接下来就是往 Data 里写字节——差一步。串口送一个字节是要花时间的,您把字节递到门口,而它得进发送保持寄存器排着队,咱们得等它把前一个交出去了再递下一个。它肯收吗?咱们从 Lsr 里读答案:

```cpp
void SerialPutChar(char character) {
    WaitBitsSet(kCom1Base + kRegLsr, kLsrThre);
    OutB({.port = kCom1Base + kRegData, .value = static_cast<uint8_t>(character)});
}
```

`kLsrThre` 的值就是 0x20,Lsr 的第 5 位,THRE——说的就是发送保持寄存器空了。WaitBitsSet 干的是轮询:THRE 还没置位的时候,咱们就原地等,置位了才放行,然后咱们再往 Data 里写一个字节。咱们每送一个字节,干的都是一问一递的活儿。您品一品上面两行:咱们读一下 Lsr,是咱们头一回在驱动里问设备一句话,而设备真的会答。debugcon 从来没给过咱们这个礼数——它只管收,连表态都省了。

咱们也把轮询的事儿说在明处:它是眼下最贵的写法,CPU 是全程陪着等的。可中断的路要一张全量的表,那是下一卷的活。咱们现在的话又少,起居序列的那几行,一个字节一个字节地问着递,人眼是看不出停顿的。等哪天有了表,这段等待可以升级成中断驱动的——但那是后话,今天的轮询,其实一点不丢人。
