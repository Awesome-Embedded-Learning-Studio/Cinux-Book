# 三案连破

到了通电这一步,咱们等的戏来了:shell 添上 run 命令,真的 fork、真的 execve、真的 wait。头一晚三桩案子就排着队上了门,一桩赛一桩地怪,咱们挨个破。

头一案的病征荒唐得跟闹了鬼一样:run 一敲,父进程居然以为自己是孩子:fork 的返回值,父进程读到的是 0。它兴冲冲地跑去 execve,把自己换成了 hello,shell 没了,机器上跑着一个来历不明的 hello,连锁灾难一桩接一桩地来。病根在返回值的走法:头一版的入口汇编,call InvokeSyscall 之后把 rax 存进 gs:16 的中转格,等弹帧回家了再取出来。可 call 和取货的间隙,sti 是开着的——这中间父亲会被抢占,孩子上了 CPU,孩子跑完自己的 execve,把 gs:16 覆写成它自己的返回值 0,父亲醒来取到的,是孩子留下的 0。中转格是 per-CPU 的,进程却是排队来去的,窗口就这么开着,早晚有人替你留言。咱们修得干净利落: C ABI 本来就承诺了返回值住 rax 里,call 一回来它就到了位,弹帧序列一个字都不碰 rax——那咱们根本不用中转,gs:16 退了役,返回值全程待在 rax 的怀里跟着走。fork 本体那篇末尾补的 cli,收窄的是同一扇窗。

第二案说的是一个神秘数字。修好了头一案再跑,屏幕上打出了一个 5246548。hello 的问候呢?没有。这个数哪来的?咱们顺着 gdb 一层层剥:execve 装好了新世界,字段都填了,可它忘了 activate——CR3 没切,程序还在旧的世界里跑。hello 的入口 0x401000,旧世界里这个地址住着谁?shell 的代码。同一个地址,两套世界各住各的客,于是机器在 shell 的世界里,跳进了 shell 自己的 0x401000,跑的是 shell 的函数,打印程序拿到的 rdi 当十进制打出来。打出来的 5246548,是旧世界栈上躺着的一个指针值,被打印函数当成了正经数字。修法咱们只动一行:设好了 user_root 之后 activate。这一案也把咱们的调试家底往前推了一把:异常转储添了第七件,页故障专档——cr2 和错误码都解码成了人话,当前 CR3 的四级页表逐级走查,断在哪一级、缺了哪个位,咱们一眼见底。破了这一案,它立的是头功。

第三案的根最深,咱们从里头赚的也最多。症状是 wait 回了个 ECHILD,shell 明明 fork 出了孩子,系统却说它的孩子不存在。咱们翻遍 fork 的代码没有毛病,最后咱们在两条链上找见真凶:shell 这个任务,同时挂在两条侵入式链上——它是 init 的孩子,在调度器的孩子名册 offspring_ 里。它在等自己的孩子,又占着等待表 waiters_ 里的位子。而 Task 身上那枚 SelfNode 基类节点,只配了一个 next 指针。两条链挤的是一枚节点——等 shell 进了等待表,入链写 next 的那一拍,顺手把名册上的链拆了。孩子名册从此扫不到 shell 的孩子,ECHILD 就是这么来的。

这一案的教训,咱们当金矿收。侵入式链表的家规:一条链要有自己的一枚节点。对象要同时进两条链的话,两枚节点是少不了的,各链各的。更扎心的是测试为什么没抓住:机内测试全过,56 件的测试一件不差——可测试世界里,找不出一个同时进两条链的任务。单链的测试各自全过,双链的组合必炸,组合一旦多了,全排列是谁也测不全的。修法落在了 base:SelfList 添成员节点模板参数,SelfList<Task, &Task::child_link> 的形态,offspring_ 改骑 Task 里那枚专用的 child_link,waiters_ 留在了基类节点上,默认的形态向后兼容,全仓的迁移量是零。base 里补了一案回归:同一个对象的两条链,互不腐蚀地共存。调度器那一卷埋下的这颗种子,到这儿才算真正爆出来——咱们把它记进家规,往后的每一枚节点,过链之前都问一句:它还有别的链吗。

咱们也把遗留如实记下:同步三件(信号量、互斥锁)的等待表,骑的还是基类节点,和调度器的等待表同一枚——任务一边等锁、一边等孩子的组合,理论上仍有踩上的可能,眼下没有实弹的路径,分链的活留给按需分页那一卷,到那边等待的形态要大改,咱们一并动。

三案都破了,run 的全链才算真的通了。咱们剩下的收尾:内核里的裸指针要收进伞里,咱们要让 shell 搬去盘上。下一节咱们收官。
