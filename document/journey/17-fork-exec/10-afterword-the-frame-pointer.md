# 后日谈:帧指针三部曲

这一卷的 fork,孩子的内核栈上只有一帧,rip 指向返回尾——这个形状咱们说是直取终态。终态是怎么来的,值一页的后日谈。当年这一块的事,前后修了三回,一回比一回地深,咱们按幕讲——这三幕是本节的私房分法,跟卷首说的第一幕不是一回事。

头一幕讲的是帧指针不可信。当年孩子起跑的地方和咱们不一样:fork 把父进程内核栈上用着的整段拷给孩子,孩子的 rip 落在 fork 的调用链中间,从被中断的那一行续跑。想这么做,得找到用到了多深——顺着 rbp 链一帧一帧往下走,是当年的量法。可内核是 -O2 编译的,编译器默认把帧指针省了个干净,rbp 被拿去当了普通寄存器,链是根本不存在的。炸出来的现场也配得上这样的糊涂:三重故障,报了个 #DF,机器连报丧的力气都没有,转储里 rsp 是一个用户态地址——栈指针指去了另一个世界,谁看了不迷糊。当年的修法是凑合修:fork 相关的函数挂上 no-omit-frame-pointer 和 noinline 的属性,保住 rbp 的链,量到的是深度,拷出的是栈。这么修能用,可咱们谁也知道这是绕,不是治的法子。

第二幕讲的是 376 字节的窗口。凑合修跑了一阵,一个间歇性的三重故障来了:百回里炸那么几回,回回的现场一致,execve 的页表遍历深处,栈写穿了。咱们把链摊开:孩子拷了父亲整条用着的栈,在同一条深链上接着跑它的 execve,execve 要拆的是旧世界,四级页表逐层地遍历,一路的栈帧越叠越深——四页、十六 KiB 的内核栈预算,被整条链写穿了底。写穿本身已经是致命的,更糟的是页故障的处理器跑在同一块栈上,又叠了一层,又故障了一回,机器就直接三重故障躺平了。可为什么间歇?为什么大多数时候不炸?窗口在切换那一拍:调度器恢复中断之后、孩子入口之前的极短间隙里,时钟中断恰好落进来的话,中断自己的帧也压在这块栈上,多占约 376 字节——预算本来只剩几百字节的富余,这 376 一压就穿了,不压就侥幸过了关。间歇性的本质,是离悬崖只差 376 字节的距离,风大了一点才掉。

到了第三幕,该到终局了。病根明确了之后,当年起初把矛头对准了编译器,两个猜想接连上了台,验证了,皆错——编译器是无辜的。末了抬头看 Linux,人家早就把答案给过了:ret_from_fork。Linux 的新进程不从被中断的地方续跑,它从一个专门的小入口起跑,那入口只做一件事:把寄存器的现场摆好,顺着中断返回的路回用户态。内核调用链?不需要。孩子的内核栈上只需要一张返回用的帧,不需要父亲的深链。栈的预算从根上不再是问题,帧指针也不再需要信——每张帧都是自己合成的,偏移在编译期就定进了断言里。咱们这一卷的 ForkChildEntry,正是这个范式的小号实现:合成帧、弹帧、sysretq、rax 清零。当年是三幕血泪换来的公认定式,咱们靠着后见之明,一步站到了第三幕的终点。

为什么 Linux 用 ret_from_fork,现在您可以自己答了:fork 要的不是复制父进程的内核执行,是让孩子作为一个崭新的执行流回用户态去。内核里的中转站,用过了就扔,谁也不该背着别人的行李上路。孩子的行李,薄薄的一张帧,九十六字节的个头,足够用了。

栈的预算这个话题,后头还有戏:栈底魔数只是事后报案的哨兵,真正的栈守卫页,得等页故障的裁决更成熟、大页拆分这些配套齐了才能立,那是往后讲线程栈的那一卷的活。咱们这一卷的后日谈到这儿收,该上秤了。
