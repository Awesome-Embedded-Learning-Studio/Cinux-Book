# 复制什么,不复制什么

fork 这个词在 Unix 那儿的老比喻是叉子分岔:一次调用,回来的却是两次,父进程怀里是孩子的 pid,孩子怀里揣的是 0,剩下的部分,两边应该是彼此的镜像——至少从用户态的椅子上看出去是这样。要造出这样的一面镜像,咱们得把每个家当逐件过堂:哪些抄?哪些不抄?哪些只挂个名?咱们列一张单子,然后逐件地讲:

```text
抄          用户半区每一页的映射、寄存器现场、fd 表逐槽、cwd、名字
不抄        pid、内核栈(新的四页)、parent、就绪状态
天然共享    内核高半区(根表上半 256 格,指向同一批内核页表)
```

头一件是用户半区的映射。孩子的世界里,父进程每一个映射过的页,都得在同一个地址上映射——至于映射指向的物理帧抄不抄,咱们留给下一个问题。第二件是寄存器现场:切换器搬的那副寄存器图像,孩子拿到的是一份拷贝,改几个字:返回地址、栈、rip,这些字咱们留到后面讲 fork 本体时细说。第三件是 fd 表的逐槽继承:从 3 号起,父进程开着的每一个文件,孩子都开一个自己的新格子,拿到的是同一个后端、同一个节点,父亲读到的偏移,在 fork 那一刻原样抄一份——抄完之后父子各读各的,你挪你的游标,我挪我的,各自的游标互不牵动。父表的活槽连着排号的时候,孩子手里的描述符跟父亲同号,排号断了,号就各是各的。至于共享偏移的那一等,Linux 家 dup 的语义,得等打开文件描述的那一层立起来才有,咱们留给讲线程的那一卷。实现上咱们一分新词汇都不用造:文件册那一卷立过的 slot 插入路径本来就带 retain,咱们重放一遍插入,继承就办成了。第四件是 cwd 和名字:咱们把字节原样抄走,连一个字母的改动都没有。

不抄的清单短,不过件件有道理,咱们也逐件数。pid 指的是身份,身份是不能复制的,否则孩子的 getpid 报的是父亲的号。内核栈必须新领四页——孩子的内核故事和父亲不一样,所以不能踩同一块栈。parent 指的是父亲,这是链的方向,单向的。咱们把状态置成 kReady,它生下来就进了队列。

最值得看的是第三行:内核高半区,咱们根本不抄。咱们回顾一下地址空间出生的手艺:每张新根表的上半 256 格,从内核根表原样抄来——抄的是表项,表项指向的还是那批内核页表。所以任何两个用户世界的高半区天生共享同一套内核映射。fork 的克隆只走低 256 格,分界就立在根表的正中间,咱们一刀切齐。当年返工的时候,这里出过一桩真毛病:克隆的递归不认边界,内核的恒等映射连着大页被整个复制进孩子的世界,内存白白翻了一份。咱们这一遍,版式本身就把边界画好了,克隆的循环只碰用户半区,用户半区里冒出大页的话,响亮停机——咱们自己映射用户内存的路径从来不造大页,遇上了就是错了,咱们宁可喊出来也不闷着。

现在回到那个悬着的问题:映射指向的物理帧,抄不抄?两条路,咱们把取舍摆上桌。急拷:fork 的那一拍,孩子的每一页都领新帧,字节整个搬了过去。省了心,父子即刻分了家,不过代价摆在那儿——父进程占多少内存,fork 一声就翻了一倍,哪怕孩子接下来的第一件事就是 execve,把整个世界又扔掉了。写时复制:咱们把映射指去同一批帧,两边都标成了只读加一个软件位,哪边动了手,哪边的那一页才分家,各拿各的。省了内存,也符合 execve 型 fork 的真实用法,可它要一个兜底:写的那一拍会缺页,得有人坐在缺页的门口,裁决、复制、放行——而这意味着,机器得有自己的缺页处理器。

当年头一遍在没有缺页处理器的日子里就把写时复制做了,而且漏了一样东西:引用计数。一帧映射进了几个世界,咱们也没数着。父进程退了场,teardown 把帧还了池子,孩子还在读的,是已经被人领走的页。谁退谁留的事,全凭一时的运气。这一遍咱们拍过板,一次性做对:写时复制咱们要做,引用计数咱们也不落下,物理内存的每帧一个计数,多了一个世界来映射,它加的是一,拆掉了一个世界,它减的也是一,减到零了,帧才回了池子。计数安在哪儿?下一节咱们连着引擎一起讲。当年那版没计数的走法,咱们留在这几行字里当反面教材,不再留给运气了。

单子过完了。您回头看会发现,fork 的本体几乎是纯搬运——真正的新学问只有两块:一块是下一节的写时复制引擎,一块是再下一节的返回现场。咱们这就去造引擎。
