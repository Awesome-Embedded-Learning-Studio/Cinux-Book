# 机器还跑不成程序

上一卷收卷的时候,note.txt 留在了盘上,字也落进了真盘里,咱们看着 ACPI 拉了电闸。可您回头想想机器的家底,有一样东西一直没变过:它会跑的程序,就是 shell——下楼开张那一卷请下来的第一位常客,到今天还睡在内核镜像的怀里。构建的时候 objcopy 把它抽成一段纯二进制,链接进了内核,开机的时候 kernel_init 把它扶下楼。咱们在盘上认得出 hello.txt,认不出任何一份能跑的程序。这一卷咱们把这件事办了:让机器从盘上请程序进来跑。

拦路的头一件东西,是那个装载器——咱们把它现在的样子端出来给您看:

```cpp
constexpr unsigned long kUserCodeBase  = 0x400000;
auto const kShellPhys =
    reinterpret_cast<unsigned long>(&g_user_shell_start) - mm::kKernelImageBase;
base::safety::Check(shell_space.map_user(kUserCodeBase, kShellPhys), "shell code page failed");
```

一页到头了。装载器会的全部手艺,就是把镜像里的那段字节映射到 0x400000 这一页上。咱们量过 shell.bin 的个头:3657 字节,一页的大小是 4096。菜单已经排到十三样了,3657 贴着 4096 的顶,再添一件手艺就顶穿了。更麻烦的是这段格式什么都没说:哪些字节是指令、哪些是数据、程序想在内存里占几页、哪一段该清零,装载器其实一概不知,咱们只能赌它恰好装得下一页。赌不是咱们认的工程。

要跑别人的程序,光换装载器其实还不够。您在 shell 里敲下 run,背后得有一整套生老病死的手续:得能造一个新进程(fork),得能把新进程替换成盘上的程序(execve),父进程得能等子进程退场并收下它的退出码(wait),退场的进程得留一具能被收走的身子(Zombie)。这一卷的活就是这四件,外加把 pid、ppid 这套称呼立成正经词汇——上一卷交底的时候说过,PID 0 和 PID 1 都是借来的称呼,这一卷咱们把借贷还清。

走的路数,咱们照旧交底:活分两拍。头一拍咱们让 fork 在测试里成立,家族的词汇、写时复制的引擎、fork 的本体,全部在机内测试的世界里立起来、跑绿,这时的 ring3 还一点都不知道有 fork 这回事。第二拍咱们通电:shell 添一个 run 命令,真的 fork、真的 execve、真的 wait,毛病一个接一个地冒头,咱们一桩一桩破。当年头一遍也是这么走的:一天之内 fork、execve、wait 全部落地,近四千行改动里测试占了一半还多,通电之后毛病才一个一个地见着真身。咱们这一卷就照这个节奏走。

还有一句卷首的话。这套教程从零起步走到了今天,这个阶段咱们一直没给它起过名,现在把名字补上了,咱们叫它第一幕,涵盖的范围从引导、内存、调度,一路走到了文件和盘。这一卷收卷的时候,第一幕就收束了:机器会引导、会管内存、会调度、会应答中断,有了文件、有了盘、有了名字,再加上这一卷的生、换、等、收,一个内核该自己扛的事,就都扛得动了。往后的卷,咱们要带着这套家底去干更大的活。现在咱们从家族的地基起。
