# 裁决者的另一半

本节把这一卷的正主请上台,咱们收一笔生与收那一卷的旧话。缺页的错误码,生与收那一卷给第一位立过的词有两个:它是零,说的就是整页没映。而它是一,页是活的,错的只是权限。当时的裁决者,坐进异常报告员门前的单座,受理的只有写时复制一类案子,权限那一半的写路。读缺页、整页没映的,它说得清楚:不归我管,那是按需分页的案子。幕间又补了一句,那是下一卷的新业务。业务现在开张了。有个顺序上的旧事咱们顺口收了:当年工程线画这一段图纸的时候,落笔的头一笔其实是没映这一半,按需补页当的是主角,写权限是配套的那一半。咱们这一遍反着走,权限那一半在生与收那一卷造好了,没映的这一半留到今天。咱们不挑谁前谁后,两条腿都齐了,机器自然走起来了。

裁决者本人的判定链,现在的样子是两段。头一段还是写时复制的老脸,写路打头试:是写、页在、只读、带着共享标记的,走分家或者复权的路,照办的是老业务。老业务说不受理的,新业务接了手,咱们把新半边的问案顺序摆出来:

```cpp
if ((error_code & kFaultFromUser) == 0 ||
    (error_code & kFaultProtection) != 0 || address >= kUserTop) {
    return false;
}
const VmaRegion* const kRegion = ranges.find(address);
if (kRegion == nullptr) {
    return false;
}
const unsigned long kPage = AlignDown(address, kSize);
if (kRegion->kind == VmaKind::kStack && kPage == kRegion->start) {
    return false;
}
```

第一问:来自用户吗。错误码第三位是环三的印记(就是前文一路写的 ring3),内核自己的缺页,这一路是不接的,走的是老章程。地址出界的,天空以上册子就管不着了。第二问:保护性的错吗。第一位是一的,那是权限的事,写路试过了,是不接的,剩下的就是册和表都说不行,婉拒了,死法是转储里的一行判词。第三问:册上有这段吗。查册查了个空,就是真的越界。第四问是栈的守卫:栈区间的头一页是永不映的,谁碰了它就响,守卫页说的就是它,咱们等下单独说。第五问:页真没映吗。这一问看着是多余的,咱们就是在这问上交了学费,值得咱们单独开一段。

这笔学费是这样交的。判定已映未映:咱们手里有一件现成的家什,查页表的走查件,走到叶表给你一个指针。首版的判断写的是指针非空即已映,机内测试的头一轮,十案跑出了七绿三红。咱们把三处红的一查,红的根子得分层说。头一处的红在走查件的语义:走查件走到叶表,哪怕碰到的是零叶槽、没映过的页,它交回来的指针也是非空的,因为叶表本身在了,它给你的是槽位的地址。同一张叶表里的第二页,头一回缺页进了门,槽位记的是零,交回的指针非空,判成了已映,拒错了,程序白白死给咱们看。咱们要判已映,必须查槽里那一项的现在位,位真的在,页才真的在。家什交回来的东西是什么语义,要读它的说明书,别干望文生义的事。第二处的红在这个根子上又叠了一层:堆的用例种下堆之后没挪过断点,册上的堆区间长度还是零,任何地址自然查不中,挪了断点再 fault 才是完整的戏。第三处的红红得冤:栈的用例期望写错了一处地址,对齐进页之后的落点恰好是守卫页,被拒是正确的行为,错的是测试的期望,实现是没错的。三红各自改对了,十案全过了。

过了五问,补页本体的三步,咱们跟着一页走一遍。头一步咱们从物理内存的池子里领一帧。第二步把整页清了零,别问为什么,匿名页的出身就是零,文件页的短读尾巴也是零,bss 的答案提前写好。第三步按背后三态分岔:匿名的,到这就完了,零页上了表。文件的,把这一页对应的文件字节,经登记册上记的后端面读进这一帧,读进来的字节有多少算多少,文件尾巴短的,剩下的字节保持零,正好是内存大于文件的那一截该有的样子。页表项的组装,这一批也换了脸:上表的件收一个现成的叶项,谁调的谁组装,表指针上给不给写位是供给的细节,而叶上给不给写位,定的就是这一页的法。册子说这段是许写的,叶项才带上了写位,栈段记的是许写,补出来的栈页就带着写位。段权限的旧债,顺手在这清了:装载器从前把用户页一律映成可写,ELF 段自己声明的旗标没人理。如今段头里的读、写、执行三位,装载时翻进了册子,写位翻进了页表,数据段是数据段的法,代码段是代码段的法。执行位有个如实的交代:它这一卷记在册上,页表那边的执行限制要动 EFER 里的开关,那是另外的一件事,留给往后讲安全的那一卷,咱们不在这卷里越界。

守卫页是值得单独说的,因为它是栈的故事里最提气的一笔。exec 的时候,栈照旧真铺的只有一页,顶上的那一页,可册子上记的是一整段:从栈顶往下整整一兆字节,再往下多记了一页当守卫。这一页站在整段的最低处,也就是区间记下的起址:栈是往下长的,长满了一兆字节,踩到它的才是最后一步,而它是永不映的。判定链里的那句 kPage == kRegion->start,拦的就是这一步。程序的递归一层层往下压,压过真铺的那页,缺页进了门,咱们查册,栈区间内的,往下补的永远是一页,压了再补,补了再压。压到一兆字节的底,再往下的那一步,接它的是守卫页,缺页进了门,拦它的是第四问,响亮地死,串口上的一行判词,死因是清清楚楚的。您对照着看:从前栈底那句魔数,是死透了验尸才看得出的哨兵,守卫页是当场就响的警铃,踩到的那一拍就拦。魔数那句哨兵咱们留着,它守的是内核栈,那是另外的一个栈,按幕间的约定,它的守卫页归往后讲线程栈的那一卷。用户栈的守卫页,这一卷立起来了,验收的时候咱们拿两百五十六层的深递归实弹压它。

还有一笔生与收那一卷的旧约定,到这到期了。kCow 的旧语义,咱们把它唤回来:它是生与收那一卷立在页表项上的写时复制记号,fork 出的页父子合用一份帧,谁写了谁挨缺页,裁决者见着了它才接案,走的才是分家或复权的路。引擎当年把 kCow 位留在分了家的页上不摘,凭的是可写与可共享并存,碍不了事。这个约定到 mprotect 补齐的那一拍到期了:咱们改页表要判断这页跟不跟人共享,共享的页写位不能上,而页表里唯一的共享记号就是 kCow。私页要是还留着这个位的话,就会被当成共享的,写位就收错了。所以这一批把分家后的私页摘干净:kCow 只标真共享的页,册子、页表、计数三本记录说同一个口径的话。加上 mprotect 的另一半,页表逐页跟着册子的新词改,四个号那一篇欠下的言行一致,这里还上:改词收全了,册改完了,表跟上了,共享页保的是只读,私页按的是新词,下一回缺页来了再办事,照的还是新词。

到了这,懒章程的两拍全通了:登记当的是许诺,exec 种册、mmap 添行、brk 挪了断点。缺页当的是兑现,过了五问的堂,补了一页,指令回头重跑了。两拍全通了,机器这才伺候得起真正的程序。可内存的家务事还剩两件零碎,一件是锁的名册,一件是生与收那一卷记在明处的遗留,咱们下一节给锁添上名字。
