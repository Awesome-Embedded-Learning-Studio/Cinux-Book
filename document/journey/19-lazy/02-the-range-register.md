# 登记册

册子长什么样,咱们把一条条目端出来看。一段用户地址,三个问题记全了:从哪到哪,用的是含头不含末的半开区间,这样的边界两段挨着也不打架。许做什么,读、写、执行的三问各占一个布尔。背后站着的是谁,咱们从三态里挑一:匿名的就是一张白纸,补页补的全是零。文件的,记下了文件节点和页偏移,咱们补页时照着去读字节。栈的脾气是往下长,别的态没这脾气,所以单独算一态。条目就是一个普通的结构体,塞进了任务里,咱们一个任务发一本册:

```cpp
struct VmaRegion : base::container::SelfNode<VmaRegion> {
    unsigned long    start{};
    unsigned long    end{};
    VmaKind          kind{};
    bool             readable{};
    bool             writable{};
    bool             executable{};
    fs::FsNode       backing{};
    const fs::FsOps* file_ops{};
    void*            file_self{};
    unsigned long long file_offset{};
};
```

条目里那三件文件侧的家当,咱们多说两句分工。backing 记的是文件的身份,身份是按值整个抄进来的,册子是从来不拿它去解引用的。为什么不肯存指针?这是当年的亏换来的:工程线的页缓存拿指针当过键,对象腾挪了之后,新对象恰好住进了旧地址,缓存里的旧记录还认这个门牌,新对象一查就吃到了别人的字节。所以这一遍的身份一律按值抄,条目认的还是从前的它,哪怕背后的对象换了住址。把身份变成字节的事,靠的是旁边那两件:后端的脸和后端的实例。裁决者那一篇补页时说的后端面,说的就是这一对。

册子的形状,咱们拍得不花哨:按到达序排的单链。您要是在别处见过红黑树版的同类件,别嫌咱们的朴素,那是有意的。一个任务的区间,咱们数来数去也就几十条,线性扫一遍就是诚实的代价,换来的是没有排序要维护、没有再平衡要教,find 里连一页堆的分配也不领。真到了区间成千上万的年月,树有树的卷,咱们到时候再翻。

咱们把两条家法立在登记的门上。头一条是重叠的拒收,不沾合并的边。exec 铺出来的段,段与段是天然不搭界的。mmap 发出来的地段,发出去的互不重叠。所以谁要是拿着一段跟册上重叠的地来登记,重叠算不上能合并的邻居:它报的是调用方出了 bug,咱们把错原样报上去,而不悄悄替他圆。第二条管的是空区间和倒区间,起点压过终点的,咱们连门都不让它进。册子干净了,后面的查册才敢把话说满:册上查不到,就是真的没有。

册跟任务的缘分,咱们两头都要交代。exec 的那一头,新册在活册的旁边另造:装载器往新册里报段,报成了,exec 才把新册换进了任务,旧世界连册带页一起拆了,报不成的话,一切都退了回去,活着的程序毫发无伤。fork 那头是深拷:孩子把父亲的册整本抄走,一条也漏不了,抄到一半抄不动的,已经抄进去的全退,两手空空地回去,咱们要的是全有或全无。fork 出的孩子跟父亲写同一页地址会分家,这一幕您在生与收那一卷见过,分家靠的是页表那一层,而册的这一层,父子各揣了一本,各管各的。

册立起来了,咱们马上给它接一件真活:替缺页断案当证人。缺页的裁决者坐在异常报告员的门口,这您在生与收那一卷见过,当时它受理的只有写时复制。这一卷它的新业务还没开张,可证人已经到位:裁决者看完说不受理的地址,报告员在转储之前替咱们多问册子一句,这一地址落在谁家。册子的回答就三种,咱们把判词的格式从代码里抄出来:

```cpp
print::Println("[kern]  vma: addr=%X in [%X,%X) kind=%s access=%s rights r=%s w=%s x=%s",
               address, kHit->start, kHit->end, kind_name(kHit->kind),
               access_name(error_code), granted(kHit->readable),
               granted(kHit->writable), granted(kHit->executable));
```

落在册上的,判词把那一段的底细全亮出来:起止在哪、三态是谁、访问是读是写,三问权限各开各的关,您一行看完。落在册外的,咱们换第二句,整行带前缀的原样抄在下面:

```text
[kern]  vma: addr=%X sits in no registered range; a true segfault
```

判词说它真越界:程序自己的错。册子本身连任务都没有的,第三句报的是:这任务的地址世界没立册。您看,光办了登记,咱们还没发过一个页,就已经把真越界和程序说好的地界区分开了,以后真有程序写飞了指针,串口上的这一行就是第一份口供。

这里有一句当年的原话,咱们化过来当家规:登记的活当批就要办成,咱们别让册子沦为死数据。当年工程线立登记册的那一批,同一个批次里就把缺页的诊断接上了,笔记里写得直白:不带诊断的登记册就是死数据,没人查的册子,错了都没人知道。咱们照办:册子立起来和册子能作证是同一批的活,咱们谁也不等谁。测试也做成了一式两份,头一批宿主和机内各上了十三案:查册、拒重叠、克隆分离,连同往后要用的找空档、改权限的家底,一把全立了起来。册子会作证了,可咱们还没教它发页。发页之前咱们得给程序开几个口子,让它们有地方递申请。下一节咱们开四个号。
