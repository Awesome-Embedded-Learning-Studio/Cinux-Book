# 作坊:三层货与一本进料册

把后半场交给解释器那一卷收卷的时候,欠单上压了一条不太光彩的:busybox 与 musl 的源树,落在了开发机本地。这句话的分量,咱们这一卷走到今天算是全领教了。烤盘的脚本认的是开发机上的私藏:busybox 的源树躺在用户主目录的 `.local` 下面,血是当场从宿主编译器的行囊里舀的,客人程序是现编的。盘离了开发机,烤不出来:代码原样搬到了另一台机器,那边的抽屉是空的,照样是抓瞎的。所以这一章咱们开一间作坊,把这件事一口气了结。

作坊的章法,咱们从当年考古考来。当年第一遍走到这一段的时候,笔者请的是真 Buildroot,路数叫的是三层分离。骨架这一层是 Buildroot 产的,目录树、busybox、musl 的货都从这一层出。专有件的那一层,行话叫的是 overlay,Cinux 自家的当班表、测试脚本、冒烟用的源码,盖在骨架的上头。第三层是工具链的闭包,干的是把 GCC 全家从开发机里整箱抽出来随行这件事。三层货备齐了,拼进一间过渡的装配间,末了 mkfs 一次性烤成盘。构建系统拿到的是成品,挂上去就开了机,盘是怎么来的,它是一概不问的。这套章法笔者当年用得顺。重走的这一遍,范式是收下的,工具不请:真 Buildroot 不进咱们的树,三层货由自家的脚本一条龙装出来。

作坊安的家,落在了 user/rootfs 这个院落,busybox 占的是院里一间屋,构建的脚本、配置、说明清单,还有点验家当用的探针,都住的是这间屋。三层货咱们照样分三层码。头一层码的是骨架与户口:目录树,加上户口本、当班表、fstab 这些 /etc 一家的种子,都归在了这一层。第二层是血的一整套闭包:从宿主编译器的行囊里照着单子取件,解释器进了 /lib64,libc、libm、libresolv 进了 /lib,盘上 glibc 一家的血,本尊就是这一层进的货。第三层是自家的客人:busybox 一具身子,加上 hello 这样的自编程序,一一都入了座。末了烤盘,debugfs 一件一件把三层货写进 ext2 的镜像。当年走的是装配间加 mkfs 的路子,咱们是 debugfs 逐件写,路数是同源的,家什换了。

咱们给进料立三道章程。头一道管的是料有正身:BusyBox 认的是 1.38.0 的官方归档,从 busybox.net 下来的,不认开发机抽屉里来路说不清的源树。第二道把校验定死:归档的 SHA-256 校验值写死在脚本里。SHA-256 咱们不陌生,把一份文件的内容压成一段定长的十六进制,内容变了一个字节,它就整个变了样。第三道是指纹的缓存:进过一回的料记一笔总册,册页没变的话,就不重出工了。头两道落在脚本开头的这几行:

```bash
    version=1.38.0
    checksum=34f9ea6ff8636f2c9241153b9114eefa9e65674a45318ae1ef95bb5f31c53bb2
    cache="${CINUX_ROOTFS_CACHE:-$(cd "${here}/.." && pwd)/.cache/rootfs}"
    archive="${cache}/busybox-${version}.tar.bz2"
    mkdir -p "$cache"
    if [ ! -f "$archive" ]; then
        curl -fL --retry 3 --output "${archive}.part" \
            "https://busybox.net/downloads/busybox-${version}.tar.bz2"
        mv "${archive}.part" "$archive"
    fi
    printf '%s  %s\n' "$checksum" "$archive" | sha256sum -c -
```

这几行把头两道章程走全了。缓存里没有归档的话,才去 busybox.net 下载一份新的,半成品落成的是 `.part` 文件,正名是随后挪的,随后拿写死的校验值过 `sha256sum`,一个字节对不上的话,当场就报错退出了,带病是绝不进炉的。校验过了才解包,源树这就位了。您留意 checksum 那一行:校验值是跟脚本一起进版本库的,咱们谁来验,验到的都是同一个值。料的身份从此不靠哪个网站说了算,靠这段写死的十六进制。

第三道章程是这间作坊的心脏,咱们把算法单独摆出来看:

```bash
fingerprint="$({ sha256sum "${here}/../user/rootfs/busybox/busybox.config" "$script_abs";
                 printf '%s\n' "$source_fingerprint";
                 sha256sum "$(gcc -print-file-name=libc.so.6)";
                 gcc --version; gcc -dumpmachine; } | sha256sum | cut -d ' ' -f 1)"
if [ -f "$out" ] && [ -f "${out}.inputs" ] && \
   [ "$(cat "${out}.inputs")" = "$fingerprint" ]; then
    echo "[build-busybox-glibc] cache hit, keeping ${out}"
    exit 0
fi
```

而一笔指纹,五样东西收进的是同一册,咱们一笔一笔数。头一样是 busybox 的配置,就是 /lib 里只剩一家那一章翻过三个开关的同一份。第二样是脚本的本尊。第三样压的是源码树,会参与编译的文件,从 `.c`、`.h` 这样的文件到 `Makefile`,名字连内容逐个过了一遍哈希。第四样是宿主编译器配的 libc。第五样是 gcc 的版本与目标机描述,两行合成的是一样。五样凑齐了,整包再过一次总的哈希,落进产物旁边的 `.inputs` 文件,这就是进料册的本体。下一次开工的时候,新算的册页跟旧页对上了,报的就是一行 `cache hit`,作坊收了工,料是一动不动的。对不上的话,说明五样里有一样变了,重活是得从头再干的,新的一页盖过旧页。

五样里最容易被当成外人的是 gcc 与 libc 这两样。可咱们这一卷干的就是换血的活:盘上 glibc 一家的血,本尊取自宿主的编译器,同一份 busybox 的源码,换一套 libc 编出来的,血就换了。在别的工程里,编译器多半算的是工具,到了这间作坊里,它认下的身份是料。料入了册,是理所应当的。换一台机器的话,gcc 与 libc 变了,指纹跟着变了,旧册是绝不冒充新货的。

作坊开的出口有三个,咱们一条命令挑:

```sh
bash user/rootfs/busybox/build.sh           # 默认 run:装盘开机
bash user/rootfs/busybox/build.sh build     # 只组装镜像,不开机
bash user/rootfs/busybox/build.sh verify    # 非交互验收
```

咱们挨个看。run 是默认的出口,咱们敲下去,镜像备齐了,直接开机进了 KVM,要的是一块可写的 `/dev/kvm`。build 干的只是组装:内核、客人、busybox、盘,备齐了就收摊,机器是不开的。verify 是非交互的验收:机器自己起来,把这一卷攒下的家当逐件点过,当家的坐在一号座上,十四位客人逐个交了退出码,glibc 的 hello 出问候,fstab 与临时隔间的案子,共家的储物间跨 fork,门内的传话带着 poll,判据到齐了,亮的是绿灯,哪一条不齐的话,作坊不替咱们圆场。

配置不另立一份专门的文件,是一张环境变量的清单,立在了 user/rootfs/busybox/README.md 里,一行一个地排,旁边写的是默认值。`CINUX_BUILD_DIR` 管的是构建目录往哪儿出,`CINUX_ROOTFS_CACHE` 管的是进料缓存住在哪,`CINUX_BUSYBOX_SOURCE` 开的是一扇侧门,咱们设了它,就用自家的源树,跳过了下载,`CINUX_GLIBC_LDSO` 与 `CINUX_GLIBC_LIBC` 管血的本尊从宿主的哪里取。开发机的家什也得点齐,gcc 与 g++ 要的是 14 往上,cmake、qemu、e2fsprogs 之类的家什,完整的清单 README 里写着,缺了哪样,作坊会在对应的那一步大声喊停。可复现说的是料有正身,大家都领得到,空机器白手起家的那回事,它可是没许诺的。

咱们还有一处口径要翻正。/lib 里只剩一家那一章留过话:两种造盘模式是并存的,musl 的旧路照旧能走,默认是暂不翻的,等的是作坊立起来统一。如今作坊立起来了,默认翻过来了,造盘脚本里管这件事的是一行:

```bash
libc_flavor="${CINUX_LIBC:-glibc}"
```

环境变量没有设的时候,这一行取的就是冒号后头的 glibc,咱们空手跑一遍造盘,出来的直接是 glibc 一家的 64 MiB 盘。musl 的模式退居二线,只作旧路判据回归的入口。两种模式并存的过渡期到此翻篇,往后谁也不用再记哪种盘该传哪个变量了。

成色的事得换个地皮验。咱们把 `CINUX_BUILD_DIR` 指向一个空目录,再把 `CINUX_ROOTFS_CACHE` 指向了另一个空目录,缓存里是一粒料都没有的,构建目录里是一砖一瓦也没有的,然后咱们从正门走进去,您看着作坊从头走一遍:下载、校验、解包这些起步的活,编 busybox、编内核、烤盘这些重头的活,一路走到了 verify,绿灯照样是亮的。这就是换一台机器重开张的预演。作坊的料不再是开发机抽屉里的私藏,是官方归档加指纹的配方,什么样的机器都领得到,什么人都领得到,验是验得出的,重是重得出同一张盘的。把后半场交给解释器那一卷挂下的源树旧债,到这里还清了。

作坊能出盘了,但是开张还差一步,差的那一步不在作坊身上,是在构建图的身上。构建图是 cmake 手里的依赖图,谁依赖的是谁,谁变了的话,重跑的就是谁,这些都记在图上了,眼下它还不知道作坊的存在,咱们烤盘,还得记着去敲作坊的门。作坊长进了构建图里,一条命令从干净的树直达开张的机器,那一章的事才算数。
