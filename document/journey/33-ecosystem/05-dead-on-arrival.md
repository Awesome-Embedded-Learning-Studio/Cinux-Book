# 起动即死:rip 指着对齐

咱们在机器的壳里敲下 hello-glibc,回车,屏幕上什么都没有。

一句问候没有,一个字符也没有。有时候像挂起,机器坐在那儿不动。有时候悄没声地就死了,被 signal 11 击杀,壳死了又被拉起来,拉起来再死,循环往复。咱们把 musl 的客人挨个请出来试,静态的 ash 照常当班,动态的 hello-dyn 照常开口。同一个门口,唯独 glibc 动态,起动即死。差在哪儿,那会儿咱们还不知道。

值钱的证据来得很意外。调试那场盯完咱们撤场,串口的尾巴定格在了一次确定性很高的现场上。环 3,十三号异常,一般性保护。rip 是 0x100227E3,rsp 是 0x7FFFFFDC4158。印着的任务还是壳,user_shell,四号。登记册里数得出十个区。

咱们拿 rip 头一个开刀。解释器的家是把后半场交给解释器那一卷定下的,256MiB,十六进制 0x10000000。定格的 rip 减掉家的地址,余 0x227E3,落在解释器自己的映像里。再配上登记册里的十个区,两笔对上:exec 已经办完,解释器装进了家,入口也跳过去了,内核的装载活交割得干干净净,死的是解释器自己的执行。

旁证咱们也点一遍。盘上三件,一件不缺,hello-glibc 本身在,/lib64 里的解释器在,/lib 里的 libc 也在,musl 的动态客人照旧健康,装载路径没坏。串口上没有 glibc 的告状字,连它嫌内核老时会打的 FATAL 都没见着一行,更像执行流自己炸了。

现场摆在眼前,咱们不急着押宝,把嫌疑排成一张单子,按查起来的划算程度从前往后排。

排头的是解释器装库的那套序列:起手圈地,逐段塞段,末了收权。替换语义刚立,堆里砌护墙那一章的教训还热着,新消费者会拿真实调用序列考它,头一位考官就是解释器。查法也现成,断点守在门里,咱们把起动到死之间的 mmap 与 mprotect 记下来,对着两份段表核落点与权限。

再往下是收权整段连坐。RELRO 那道收尾保险,咱们在把后半场交给解释器那一卷领教过,要是它把含惰性绑定跳转表的那段整段改只读,后面绑定一写就死。占址重建那一章把观察项撂在明处,就是等它来对号。

环 3 的机制也排得上:SYSRET 落到非规范地址,或在不可执行的页上取指,咱们拿当时的页表把 rip 所在页的权限位走一遍。客人起手的那串系统调用也在单子上,rseq、clone3、set_robust_list、madvise 这类没接的号位,答 ENOSYS 是正常回退,要盯的是回退之外有没有副作用。压尾的是情报桌上新添的两味,拿 auxv 的对子跟真 Linux 逐对抄下来比。

单子立好,咱们把话说在前头,立下一条纪律:打勾之前,五条一律当假设。

破门的一步来得意外。单子还没顺着查完,咱们回头把定格现场里 rip 指着的四个字节读了出来。解释器的文件不神秘,盘上 /lib64 里躺的就是开发机拷过去的同一个文件,咱们机上的是 glibc 2.44。四个字节写的是什么?反汇编对着 0x227E3 看:

```text
227e0:  83 e1 20              and    $0x20,%ecx
227e3:  0f 29 45 90           movaps %xmm0,-0x70(%rbp)
227e7:  0f 29 45 b0           movaps %xmm0,-0x50(%rbp)
```

movaps,SSE 里的对齐存取,一次搬十六个字节,地址必须落在十六的整格上,差一个字节都当场翻脸,翻出来的正是一般性保护。咱们再数定格现场里 rsp 的尾巴:0x158,除十六,余八。栈,从进门那一刻起,就歪在八上。

歪八从哪儿来?咱们把入口的栈画像搬出来。客人的入口 rsp,落在页底往上抬一个偏移的位置,偏移就是画像头上那个常量,0x208。页底是整格,偏移的尾巴就是 rsp 的尾巴:0x208,除十六,余八。两头一对,进门的 rsp 余八,死时的 rsp 余八,中间炸在一条要整格的指令上。

入口栈错位,案子咱们给它定了。

余八,原是自家客人的形态。自家程序当年把 C++ 函数直接顶到入口位,编译器给函数体生成的代码,认的是“被 call 叫进来”那一刻的栈形,余八,内核把余八喂到门口,自家的孩子刚好合身。musl 的客人不挑,余八的门口进进出出,一直健康。glibc 的解释器认的是另一头:x86-64 的 ABI 白纸黑字,进程进门一刻,栈要落在整格上。咱们自己在把后半场交给解释器那一卷,还算过一笔“为什么是 0x208 不是 0x200”,那番道理站在自家程序直进 C++ 的形态上,一个字没算错,只是门外的新客人,不认这一套。

咱们修的活分两件,配套着来。一件在内核,画像的偏移从 0x208 改到 0x200:

```cpp
/// ELF process entry requires a sixteen-byte-aligned stack;
/// freestanding programs enter C++ through their assembly startup stub.
inline constexpr unsigned long kUserEntryStackOffset = 0x200;
```

另一件跟着注释后半句来:自家程序不能再把 C++ 函数直接顶到门口,咱们给它垫一小段汇编。user/start.S,全文就这几行:

```asm
.section .text.start,"ax"
.global _start
.type _start, @function
_start:
    xorq %rbp, %rbp
    call UserMain
    movq $60, %rax
    xorq %rdi, %rdi
    syscall
    ud2
.size _start, .-_start
.section .note.GNU-stack,"",@progbits
```

这几行咱们从头走。进门头一件事,把 rbp 清零,最外层的帧从零开始。跟着 call UserMain:call 压下返回地址,UserMain 接手时拿到的,正是它认的余八,自家的旧期待一寸没动。UserMain 干完回来,60 号系统调用,退出码零。ud2 立在后面,谁也不该走到那儿。尾巴上的 note.GNU-stack 把自家栈的执行位自报成无,章法是情报桌添两味那一章立的。构建那头,每一具自家程序都捎上垫子,偏移从此只剩一个数,测试跟生产守同一个常量,不再另备一套。

对齐修完,死法跟着换地方,死得更远,正说明路通了一截,跟出来的两案咱们同场结掉。一案在找库的路:hello-glibc 在开发机上链的,开发机的解释器找库只认 /usr/lib 一带,客人进门要找的 libc 却住在盘上的 /lib,地址簿上没记这一户。修法不在内核,在链接那一行,-Wl,-rpath,/lib 把产物的 RUNPATH 拍死到 /lib,进门照单找,一找一个准。另一案在 mmap 的门:可写、私有、背后是文件的映射被错拒了。解释器装库,数据段要的就是它:字节从文件来,写留在自己进程里。门放行,登记照旧。

三修凑齐,再开机,咱们在壳里敲下 hello-glibc,串口上那声问候落下来,`Hello from dynamic glibc on Cinux!`,跟 musl 那年的问候只差一个词。

对齐这门课,家里四代人都交过学费。头一代在懒到家那一卷:execve 的进场栈顶差八,自家 mapper 里一条被向量化的 movaps 当场炸了,收完学费,立下进场栈顶除十六余八的家法。第二代在假文件与真终端那一卷丢了又找回来的八字节那一篇:开门迎客那一卷给画像立新常量,栈顶的偏移按整页的整数重新立过,老的那八字节丢了,常量从 0x100 改回 0x108。第三代在 UDP 与 socket 那一卷表攥住座,栈守住承诺那一篇:退出栈上的 movdqa,蹦床用 jmp 飘进退出钩子,没人压返回地址,ABI 对栈的承诺空挂多年。第四代就是眼下,歪的还是进门那一步,较真的换成了门外的解释器。您翻回那三卷,案卷都还在。

办案路上,咱们还赔过一场自伤,顺手立成纪律。内核重编译一次,符号地址就全量漂移,拿旧地址去断新内核,断点会敲进不相干的代码里。这一案里真出过一回,报告说环 3 一般性保护,rip 落在自家断点的邻域,看着像案犯,其实是咱们自己插的桩,两轮就这么赔了进去。纪律立在明处:断点地址现查符号表,一次一查,查完再用。

三修进门,hello 活了,咱们把案卷合上。换血的整具身子,busybox,该上桌了。
