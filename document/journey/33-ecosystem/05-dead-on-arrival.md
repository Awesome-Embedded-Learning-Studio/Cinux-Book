# 起动即死:rip 指着对齐

咱们在机器的壳里敲下 hello-glibc,敲了个回车,屏幕上什么都没有。

问候是一句都没有的,连一个字符的影子都没有。有时候像是挂起了,机器坐在那儿一动不动地待着。有时候悄没声地就死了,是被 signal 11 击杀的,壳死了又被拉起来,拉起来了再死,循环往复地闹。咱们把 musl 的客人挨个请出来试,静态的 ash 照常当班,动态的 hello-dyn 照常开口。门口还是一样的门口,唯独 glibc 的动态,一起动就死了。那会儿的咱们还不知道差在哪儿。

值钱的证据来得很意外。调试那场盯完咱们撤场,串口的尾巴定格在了一次确定性很高的现场上。十三号异常报的是环 3 的一般性保护。定格里的 rip 是 0x100227E3,rsp 走到了 0x7FFFFFDC4158。印着的任务还是壳,名字写的是 user_shell,座次排的是四号。登记册里数得出的区是十个。

咱们拿 rip 头一个开刀。解释器的家是把后半场交给解释器那一卷定下的,家安的是 256MiB,写成十六进制的话是 0x10000000。定格的 rip 减掉家的地址,余下来的是 0x227E3,落点在解释器自己的映像里。再配上登记册里的十个区,两笔就这么对上了:exec 已经办完,解释器装进了家,入口也跳过去了,内核的装载活交割得干干净净,死的是解释器自己的执行。

旁证咱们也点一遍。盘上该在的是三件,咱们一件一件点过去,缺是没有缺的,hello-glibc 本身是在的,/lib64 里的解释器在,/lib 里的 libc 也在,musl 的动态客人照旧健康,装载路径是没坏的。串口上没有 glibc 的告状字,连它嫌内核老时会打的 FATAL 都没见着一行,更像执行流自己炸了。

现场是摆在眼前的,咱们不急着押宝,把嫌疑排成了一张单子,按查起来的划算程度从前往后排。

排头的是解释器装库的那套序列:起手圈的是地,然后一段一段地塞,末了再收它的权。替换语义是刚立的,堆里砌护墙那一章的教训还热着,新消费者是要拿真实调用序列来考它的,排头一位的考官就是解释器。查法也是现成的,断点是守在门里的,咱们把起动到死之间的 mmap 与 mprotect 记下来,对着两份段表核它的落点与权限。

再往下的一个是收权整段连坐。RELRO 那道收尾的保险,咱们在把后半场交给解释器那一卷领教过,要是它把含惰性绑定跳转表的那段整段改只读,后面的绑定一写就死。占址重建那一章把观察项撂在了明处,等的就是它来对号。

环 3 的机制也排得上:SYSRET 落到非规范地址,或在不可执行的页上取指,咱们拿当时的页表把 rip 所在页的权限位走一遍。客人起手的那串系统调用也在单子上,rseq、clone3、set_robust_list、madvise 这类没接的号位,答的是 ENOSYS,回退是正常的,要盯的是回退之外有没有副作用。压尾的是情报桌上新添的两味,拿 auxv 的对子跟真 Linux 逐对抄下来比。

单子立好了,咱们把话说在前头,立下了一条纪律:打勾之前,五条是一律当假设的。

破门的一步来得意外。单子还没顺着查完的时候,咱们回头把定格现场里 rip 指着的四个字节读了出来。解释器的文件不神秘,盘上 /lib64 里躺的就是开发机拷过去的同一个文件,咱们机上的是 glibc 2.44。四个字节写的是什么?反汇编对着 0x227E3 看:

```text
227e0:  83 e1 20              and    $0x20,%ecx
227e3:  0f 29 45 90           movaps %xmm0,-0x70(%rbp)
227e7:  0f 29 45 b0           movaps %xmm0,-0x50(%rbp)
```

四个字节说的是 movaps,SSE 里的对齐存取,一次搬的是十六个字节,地址必须落在十六的整格上,差了一个字节都当场翻脸,翻出来的正是一般性保护。咱们再数定格现场里 rsp 的尾巴:0x158,除十六的话,余的是八。进门的那一刻起,栈就歪在八上了。

歪八从哪儿来?咱们把入口的栈画像搬出来。客人的入口 rsp,落在页底往上抬一个偏移的位置,偏移就是画像头上立的那个常量 0x208。页底是整格的,偏移的尾巴就是 rsp 的尾巴:0x208,除十六的话,余的是八。两头一对的功夫,进门的 rsp 余八,死时的 rsp 余八,中间炸在一条要整格的指令上。

入口的栈错位,案子咱们给它定了。

余八原是自家客人的形态。自家的程序当年把 C++ 函数直接顶到入口位,编译器给函数体生成的代码,认的是“被 call 叫进来”那一刻的栈形,进门的是余八,内核把余八喂到了门口,自家的孩子刚好合身。musl 的客人不挑,余八的门口进进出出,一直是健康的。glibc 的解释器认的是另一头:x86-64 的 ABI 白纸黑字,进程进门的一刻,栈要落在整格上的。咱们自己在把后半场交给解释器那一卷还算过一笔“为什么是 0x208 不是 0x200”,那番道理站在自家程序直进 C++ 的形态上,一个字的错都没有,只是门外的新客人,是不认这一套的。

咱们修的活分两件,是配套着来的。一件的落点在内核,画像的偏移从 0x208 改到 0x200:

```cpp
/// ELF process entry requires a sixteen-byte-aligned stack;
/// freestanding programs enter C++ through their assembly startup stub.
inline constexpr unsigned long kUserEntryStackOffset = 0x200;
```

另一件跟着注释的后半句来:自家程序不能再把 C++ 函数直接顶到门口,咱们给它垫一小段汇编,住在 user/start.S 里的就这么几行:

```asm
.section .text.start,"ax"
.global _start
.type _start, @function
_start:
    xorq %rbp, %rbp
    call UserMain
    movq $60, %rax
    xorq %rdi, %rdi
    syscall
    ud2
.size _start, .-_start
.section .note.GNU-stack,"",@progbits
```

这几行咱们从头走。进门的第一件事,咱们把 rbp 清零,最外层的帧从零开始。跟着 call UserMain:call 压下返回地址,UserMain 接手时拿到的,正是它认的余八,自家的旧期待一寸没动。UserMain 干完了活回来,接的是 60 号系统调用,退出码给的是零。ud2 立在它的后面,谁也不该走到那儿去的。尾巴上的 note.GNU-stack 把自家栈的执行位自报成无,章法是情报桌添两味那一章立的。构建的那头,每一具自家程序都捎上了垫子,偏移从此就只剩一个数了,测试跟生产守的是同一个常量,不再另备一套了。

对齐修完了,死法跟着换地方,死得更远了,正说明路通了一截,跟出来的两案咱们同场结掉。一案在找库的路:hello-glibc 在开发机上链的,开发机的解释器找库只认 /usr/lib 一带,客人进门要找的 libc 却住在盘上的 /lib,地址簿上没记这一户。修法是不在内核的,落点在链接的那一行,链接命令里的 -rpath 选项把产物的 RUNPATH 拍死到 /lib,进门照单找它的库,一找一个准的。另一案在 mmap 的门:可写、私有、背后是文件的映射被错拒了。解释器装库的时候,数据段要的就是它:字节从文件来,写留在自己的进程里。这一回门放行了,登记照旧就是了。

三修凑齐了,再开机的时候,咱们在壳里敲下 hello-glibc,串口上那声问候出来了,`Hello from dynamic glibc on Cinux!`,跟 musl 那年的问候只差一个词。

对齐的这一门课,咱们家里四代人都交过学费。头一代在懒到家那一卷:execve 的进场栈顶差八,自家 mapper 里一条被向量化的 movaps 当场炸了,学费收完了,立下进场栈顶除十六余八的家法。第二代在假文件与真终端那一卷丢了又找回来的八字节那一篇:开门迎客那一卷给画像立新常量,栈顶的偏移按整页的整数重新立过,老的那八字节丢了,常量从 0x100 改回了 0x108。第三代在 UDP 与 socket 那一卷表攥住座的那一篇:退出栈上的 movdqa,蹦床用 jmp 飘进了退出钩子,返回地址是没人压的,ABI 对栈的承诺空挂多年。第四代说的就是眼下,歪的还是进门那一步,较真的换成了门外的解释器。您翻回那三卷,案卷都还在的。

办案的路上,咱们还赔过一场自伤,顺手把它立成了纪律。内核重编译一次的话,符号地址就全量漂移,拿旧地址去断新内核,断点会敲进不相干的代码里。这一案里是真出过一回的,报告说的是环 3 一般性保护,rip 落在自家断点的邻域,看着像案犯的样子,其实是咱们自己插的桩,两轮就这么赔了进去。纪律立在明处:断点地址现查符号表,一次一查的章程,查完了再用。

三修进了门,hello 活了,咱们把案卷合上。换血的整具身子,说的就是 busybox,该上桌了。
