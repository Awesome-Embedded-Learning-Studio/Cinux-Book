# 收环与哨兵

卡搬货的家什是描述符环,legacy 的形,一枚十六字节的个头。收形的排法:头八字节是缓冲的地址,DMA 靠的正是它,再两字节是收到的长度,再两字节是硬件校验的残值,咱们不读,末了的状态、错误与 VLAN 各占一个字节。环深取了三十二,一格描述符配一张两 KB 的收缓冲,三十二格对的是三十二张,这是它最本分的工作面。

内存怎么来,咱们一件一件地报:描述符环有两张,收的三十二格加发的八格,合了六百四十字节,一页物理页就装下了,两张环住的是同一页:前半是收环的,后半是发环的。缓冲的事另算,收的三十二张,发的八张,每张领的是收发都一样的整页四 KB,全从物理分配器的手里要,要了就不还,机器的一生里归卡用。咱们把收缓冲按两 KB 用,档位是收控制寄存器复位默认给的,驱动倒是没动它,页里空着的另一半就空着。描述符里写的地址是物理地址,DMA 说的是物理的语言。咱们自己要看这些缓冲,走的是直接映射,同一块内存的两副眼镜,卡看它的物理,咱们看咱们的虚拟,谁也不碍谁的事。

环在内存里的位置,咱们要告诉卡。六十四位的基址,寄存器的一格只有三十二位,所以得分成两笔写:低半写下去,收尾的是高半。提交的次序有讲究:当年在 xHCI 那里口传反过一回,按提交协议重判过的,这一卷原样沿用了那个词。环长寄存器写的是字节数:深乘十六。起手的还有一笔,收尾寄存器偏偏不写零,写的是环深减一,写在寄存器里的是三十一。为什么偏是三十一?哨兵的纪律,咱们这一章末了正面讲,眼下把闸开了。

开闸的是两笔。接收控制开的是三位:使能、广播接纳、剥 CRC。广播接纳为什么必要,ARP 的请求是广播帧,不接纳广播的话,问路的话一句都听不见,咱们跟网关的第一句对话就是广播。剥 CRC 是让硬件把帧尾的校验剥干净再搬进门,咱们收到的是裸帧:长度里也不带那四字节,词书的十五案里没有一个字要管它。发送控制的闸随下一章的发环一起开。两笔都落定了,收环就活了。

收一帧的样子,poll_frame 的次序:头一件事读收头,这一读的讲究大,咱们在后面单开一章整个留给它,这里记的只是流程。收头与咱们的尾相等,环是静的,答的是没有。不相等的话,看自家尾上格子的描述符状态,卡写过了才算真有一帧,把帧拷了出来,长度取描述符与帧上限的小者,然后清了状态与错误,尾进了一格,收尾寄存器写的是新尾减一。

poll_frame 的原文,咱们照树裁来,判空的两道门与末了的哨兵三行都在:

```cpp
bool E1000::poll_frame(RxFrame& into) {
    const uint32_t kHead = reg_read(regs_, e1000::kRegRdh);
    if (kHead == rx_tail_) {
        return false;
    }
    auto* const kRing = base::PtrAt<e1000::RxDescriptor>(mm::DirectMapVirt(ring_page_.raw));
    if ((kRing[rx_tail_].status & e1000::kRxStatusDone) == 0) {
        return false;
    }
    const unsigned long kLength =
        std::min(static_cast<unsigned long>(kRing[rx_tail_].length), kMaxEthernetFrame);
    const auto* const kBytes =
        base::PtrAt<const unsigned char>(mm::DirectMapVirt(rx_buffers_[rx_tail_].raw));
    for (unsigned long index = 0; index < kLength; ++index) {
        into.bytes[index] = kBytes[index];
    }
    into.size = kLength;

    kRing[rx_tail_].status        = 0;
    kRing[rx_tail_].errors        = 0;
    rx_tail_                      = (rx_tail_ + 1) % kE1000RxRingSize;
    const unsigned long kSentinel = (rx_tail_ + kE1000RxRingSize - 1) % kE1000RxRingSize;
    reg_write(regs_, e1000::kRegRdt, static_cast<uint32_t>(kSentinel));
    return true;
}
```

末了这笔写在哪儿,是这一卷收环上的大判例,哨兵的纪律。病根在模拟器的判满逻辑,收头与收尾相等了,环满的判决就下来。咱们拿三十二格的环把数算具体。起手的收头在零,咱们的尾也在零,收尾寄存器写的是三十一。消费了第零格之后,咱们的尾进到一,写进收尾寄存器的是零。一般地说,咱们把 k 从零数,消费到了第 k 格,尾进到了 k 加一,写进寄存器的是 k(下一格减一)。这样一来收尾永远比咱们的尾慢一格,环里永远有一格是卡拿不到的,等收头与收尾真相等了,那一定是真满了,让出去的一格,就是哨兵站的位置。错的样子也好算。消费完把 k 加一写了进去,卡写完了第 k 格之后,收头正好停在了 k 加一,两头叠在了同一格上,模拟器张口报的就是满环,回包从此堵在设备的队列里,怎么摇也不进门。这样的错法,起手给了三十一也只救得了第一发,第一帧落环之后就堵死了,面板上看着像迟到了约一秒,而真象是它压根没进过环。起手写零的话更干脆,开场收头收尾就叠在了零上,一发都进不了环。三行的纪律,当年拿挂机换来的,这一遍原样进了代码。环立了,闸开了,按理说咱们发一只包出去,网关就该回话了。
