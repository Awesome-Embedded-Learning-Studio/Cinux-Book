# 发环与门铃

发环是收环的镜像:深八,同款十六字节的描述符,发形的排法:八字节的地址,两字节的长度,一个字节的命令,一个字节的状态,校验的起止各一,末了两字节的特殊。缓冲一张领了一整页四 KB,咱们把发缓冲按一千五百三十六字节用,是自家簿子里的容量上限,最大的数据报一千五百加以太头十四,装得下而有余。为什么收的发的不一样深,簿子里记的就是收三十二发八,当年这么配的,咱们原样搬来:不改簿子不改逻辑。

发送的路 send_l3:一层载荷进来,咱们替它穿衣服。长度进了门就验,超了当场拒:不许往缓冲里硬塞。以太头的三笔:目的地址,自家的源地址,末尾的类型字。类型字落笔用的是大端的写词,上一卷补 Be 四张脸的时候判过案,线上说的是大端,构包的手顺再没有小端混进来的借口,那套词今天到驱动里当差了,家法从协议的册子扩到了设备的册子。载荷跟着抄进了缓冲,然后挂上描述符:地址,长度是连头的,命令占的是包尾、插 CRC 与报状态三位。报状态的位,请的是卡把完成写回状态字节。今天的发送路其实不读那个回写,环深取了八:连发四发之内,旧描述符是盖不着的,余量是在的,这一读是欠着的,真要看发送完成的那天再补。

挂完了摇门铃:尾进了一格,发送尾寄存器写的是新尾,卡看见尾动了,就来环上取走它的货。收尾的活还有一笔,发控照开闸的原值再写一遍,写的值与开闸那次一个样。它为什么在那儿,要等悬案的那一章才见分晓,咱们把话挂在这里,设备模型听见发控的那一笔,会替咱们把发送环当场扫一遍。发控的闸还管一件正经事:补短帧。以太网的最小帧是六十字节,不算尾巴上的校验四字节。咱们的回声请求也矮,咱们算一算,十二字节的 ICMP,加二十字节的 IP 头,再加十四字节的以太头,得的是四十六字节,差了一截。问路的 ARP 更矮:十四加二十八,不过四十二。不够最小帧的帧出门就是废帧:补短帧一开,补零的活硬件自己干,补到合法的长度,是一劳永逸的事。

发送路收尾的三行,咱们照树裁来,看门铃与发控怎么挨着:

```cpp
    tx_next_ = (tx_next_ + 1) % kE1000TxRingSize;
    reg_write(regs_, e1000::kRegTdt, static_cast<uint32_t>(tx_next_));
    reg_write(regs_, e1000::kRegTctl, e1000::kTctlEnable | e1000::kTctlPadShortPackets);
    return true;
```

起手的显式一笔也记下:发送头写零。咱们要靠它从零起步,就亲手把它放成了零,不信复位后的默认。硬件校验和的卸载,卡是会的,咱们登记不做,进出全是软件算的,上一卷的反码和一件包办。慢是慢了一点,来路是清楚的,谁算的哪一步,词书里是查得到的。

到这里收发两端的环都立了,闸都开了:按理说发一只 ARP 请求出去,网关该回话了。可咱们头一回把两头全接好的那天,线上静得跟深更半夜似的。剩的那一桩悬案,咱们下一章破。
