# 按名认卡

协议的世界接好了,就轮到硬件了。第一步的活不在内核里,在模拟器的命令行上,顶层 CMakeLists 的设备参数表末尾添两行,一行起了用户网络,一行把卡挂了上去,原文咱们照树抄来:

```cmake
    -netdev;user,id=net0
    -device;e1000,netdev=net0
```
用户网络是没有真线的网络,模拟器自己当了网关,地址也归它派,客人的地址 10.0.2.15,网关给了 10.0.2.2,咱们要 ping 的就是它。它回什么不回什么,边界验收的那一章如实念,这里咱们就把卡点着。

说插卡的这件事,其实咱们的机器一直驮着一张。驱动基本框架那一卷收卷时点过名:机器上的网络控制器,八台设备里的 0:3:0,咱们没怎么多看。模拟器有省事的脾气,命令行上一个网络字都不给的话,它自作主张挂一张默认的 e1000。以前咱们不认它,它就这么安安静静地占着一个座。这一卷把插卡写成了白纸黑字,显式的网络参数一给,模拟器就不再补隐式的默认卡,座次跟着重排了,AHCI 挪到了 0:3:0,xHCI 挪到了 0:4:0,参数表里点的卡落座队尾的 0:5:0,面板走线的报数里,它的户口行念的是:

```text
[kern] pci 0:5:0 8086:100E network 2:0
```

8086 是 Intel 的厂号,100E 是 82540em 在型号线上的名字。认卡的脸,PCI 的家为新添了一张:find_by_ids,收的是厂号加型号两个词,在走线的名册里挨个对,对上了把设备的档案交回来,对不上的话交一个空。为什么按名认,而不是按类别认,这里边是有一层道理的。类别字节报的是网络,可网络的类别底下坐着不止一家,virtio-net 报的也是同一个类别,寄存器图却是完全不同的另一张。按类认卡的话,绑错了硅,写出去的每一笔都是乱写。驱动只认自己摸得透的硅,认人认的是名字,衣着的那一栏看都不看。这个判例当年是立过一回的,这一遍咱们原样沿用。

认到了,咱们接着开的是两道许可。enable_device 动的是命令字,总线主的那一笔要开,内存空间的那一笔也要开。前者是 DMA 的许可,搬数据进门的是卡自己,没有它的话卡只能干看。后者是 MMIO 的许可,寄存器的窗口不开,写多少笔都是往空气里写的。两道许可都开了,卡才算活了。

寄存器的窗口叫 BAR0,开的是三十二 KB。这个数有来历:卡的家当不都住在门口,接收地址寄存器排在 0x5400 那一带,四页的窗盖不到那里。当年头一版给的就是四页,地址寄存器那一带出了窗,才学会了给八页。重走的这一遍直接从簿子里领八页,这笔学费咱们不再交第二遍。开窗用的是驱动基本框架那一卷的手法,窗口的页带缓存禁用,读到的必须是设备本尊,不能是缓冲里的旧照片。窗开到了八页,寄存器的词就有了落笔的地方。驱动基本框架那一卷挂过一笔 MMIO 统一窗口分配件的欠,说第二个消费者出现的时候再立。今天第二个消费者来了,回话倒是仍不必立,窗口按物理地址自索引落座,一家的 BAR 一家的物理地界,各开各的窗,当年担心的两家互相占窗,在这件里其实没有土壤,分配件的活继续往后顺延。
