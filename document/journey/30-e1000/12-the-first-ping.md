# 第一声真线的 ping

大戏的台口在 kernel_init。它的开场比上一卷忙了两步:坐了泵,连发了四发 ping 10.0.2.2,报了数,才起了 shell。咱们跟着第一发走一遍。IPv4 构好了头,连同载荷交给了汇,汇查了一回路由,目的在外地,查的是名册,里面是空的,头一回问路的事,造出了 ARP 请求,广播出了门,这一发就花在了问路上。等待的窗里,泵一圈一圈地摇,每一圈读的都是收头,主循环被踢着走了一路,网关的 ARP 应答落进环,上了座,内嵌件递给了名册,10.0.2.2 的以太地址入库。

第二发:名册是命中的,回声请求封帧出了门,走的是真线。等了约莫一秒,回声进了环,读收头的那一读把它接了进来,栈判了两次,包在座上派发了下去,ICMP 记了分。第三发第四发走的同款,一发跑了一个来回。四发打完了,三声回音落了地。第一发花在了 ARP 上,是设计内的。面板的原文,咱们逐字抄来:

```text
[kern] kernel_init: ping 10.0.2.2 answered 3 of 4, launching shell
/ #
```

前头还有两行新的,咱们也抄来,挂在开机的走线里,跟 PCI、AHCI、xHCI 的报数住在一处,都排在老面板的头一行之前:

```text
[net] loopback stack wired, pump seats with init
[net] e1000 up, mac 52:54:00:12:34:56
```

第一行是接线的话,第二行是卡的报数,名认上了,窗开了,环活了,门牌读着了。咱们看 kernel_init 那一行,是整行换过的,上一卷收尾念的是 root mounted 跟 launching shell from the volume,这一卷收尾念的是 ping 的成绩跟 launching shell,挂载的话让位给了报数。四发里答了三发,提示符落了地,shell 照常起了,泵在后台常驻地摇——泵与 shell 同住一台机器,谁也不踩谁的脚。而卡要是没插上,认卡的那一步空手而归,面板会换一句念的([net] no e1000 answered 跟 loopback only),机器退回纯回环的形态。参数表里少了那两行的读者,开机看到的就是它。

这个当网关的服务有自己的名字,模拟器的手册里叫它 SLIRP,用户网络的整个后端就是它。口径照当年的实测:它答的是 ARP,答的是 DHCP,ICMP 的回声也答。TCP 与 UDP 的 echo 服务,它是没有的。握手的应答它回不回,当年是没测过也没断言过的,咱们不替它说话,往后的部要用它试 TCP 的时候,实测过了再下判断。ICMP 的验收走的就是今天这一声,e1000 的往返,不借别的光。

机内的第三案,真网的回声案,说的是同一台世界的话,ktest 里咱们认了卡,挂了线:连发,断言的是答数非零。长凳盖不住的两件事,起卡的全套与真线的往返,这一案就一起盖住了。三案齐了,这一卷的机内答卷交齐。
