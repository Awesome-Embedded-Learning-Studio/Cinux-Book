# 复位、静音、报名字

窗口开了,寄存器的词能落笔了,起卡的次序照手册走,是一步不跳的。头一步的活是复位:控制寄存器写复位位。它是自清的,写下去的活由卡自己干,干完了自己把位清零。咱们有界轮询一千次等它归零,卡要是磨蹭过了头,咱们也不陪它挂死:往下走,后面读门牌的那一步自然会把真相报出来,起不来的卡,读回来的词是空的。

第二步的静音。往中断屏蔽清除寄存器写了一笔全一,一声不响地把所有的中断源一起按住。这一步的背后是一个旧判例,轮询驱动从驱动基本框架那一卷承袭下来的,这一卷照用而已,新讲的只是它的又一处现场。模拟器的设备模型,只在客人陷出去的时候才推进,这个脾气咱们在驱动基本框架那一卷的 xHCI 上领教过,中断线这一路在咱们的组合里不指望。消息中断也不挂:驱动基本框架那一卷的面板上写过那句老实话,表项按协议是要保持屏蔽的,货是由排空来扛的。e1000 支持的还是老一代的消息中断,连表形的那一代都不是,判例是照旧的,一口都是不开的。排水靠的是泵,叫醒靠的是读,路都排在后面的章节,这里的静音是把话说在前头:咱们跟卡打交道,全靠咱们主动去看,不指望它开什么口。

第三步拉链路:控制寄存器读了回来,把置链路位或成了一,再写了回去。用的是读改写,不做整笔的覆盖,默认的位一个都不动。卡的出厂默认里有咱们没读懂的位,整笔写等于替卡做了主,读改写只动自己认得的位。链路不拉起来的话,后面的帧一发都出不去。

第四步的活是报名字:MAC 地址不在配置空间里,而是住在 EEPROM 里,要一个词一个词地问。问的路数:往 EEPROM 读寄存器写起始位,地址挪到第八到十一位上,然后轮询的是完成位,第四位立了起来,答案就躺在了高十六位里,一次一个十六位的词。这样的三个词合起来是六字节:低字节在前,拼出来的就是 52:54:00:12:34:56。52:54 开头是这类虚拟网卡常有的姓,这一串门牌当年第一遍点卡的时候咱们读到的就是它,重走的这一遍原样再读一遍,偏偏一字不差,顺带也就验了复位、问词、窗口这一整条路都是通的。

读到了就写回去:接收地址寄存器的零号,低半写的是头四个字节,高半写的是末两个,高半的最高位是有效位。缺了它,整条地址是死的,单播的帧一张都进不来。广播的接纳位在接收控制那边,随收环的那一章一起开。走到了这里,卡的身份证齐了,咱们知道它是谁,它也知道咱们是谁。
