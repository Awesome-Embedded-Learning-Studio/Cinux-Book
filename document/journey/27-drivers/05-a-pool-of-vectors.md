# 给消息一个座

上一卷收卷的时候,消息中断的路咱们撂了一整条没铺。现在设备侧的方言认得了,该轮到内核这侧了。头一件要想清楚的事:消息进来,落点跟线走的不是一条路。会听那一卷立的中断桌,十六个座位管的是引脚线,线号是中断门房的编号,拽线的是设备,分拣的是中断门房。消息中断不走这套分拣:设备往地址上写一个字,那个字直接落在某颗核的本地 APIC 信箱里,信箱里的话说的是一个向量号,向量就是当年铺满二百五十六格的中断表里的格号。这么一说,线中断要的是线的座,消息中断要的是向量的座。十六格就是线桌的全部,号段偏偏紧挨着线桩,把向量往里塞的做法,等于把新住户塞进门房的衣帽间。所以咱们不扩线桌,给消息立一张自己的侧脸:同一间服务里,另一组小脸面是给消息的,线走线的,消息走消息的,谁也不多占谁的座。

侧脸立了三张。头一张立的是注入区间:哪个号段给消息用,由架构层说了算,服务收下就是了。为什么不叫服务自己挑,理由跟当年把芯片名锁在架构层是同一个:向量号段是平台的布线知识,哪一段住着什么样的住户,只有装中断桩的人知道全图。第二张管的是入座:设备要一个消息座位,服务从区间里找的是头一个空位,把处理函数放了上去,答回的是那个裸向量号。第三张派发:向量响了,跑座位上的函数,没人坐的向量,静默地丢掉,这是线桌那边无人应答照答后丢弃的老纪律,消息这边一个字不差地继承。词汇上咱们立了 MsiVector 这个词,它的值就是裸向量号,设备写进消息数据的那个字,与座位号其实是同一个数,中间省了第二次翻译。一来一回用的都是它,少一道翻译就少一处对错号的机会。

区间安在哪?咱们把住户表整个念一遍,你就明白 0x40 这个起点是怎么来的。0x20 到 0x2F 住的是十六条线桩,老门房的线换了新门房,桩还是原来的十六个。0x30 是本地定时器,每颗核自己的心跳。0xE0 住的是调度广播,第二颗脑子那一卷立的让位中断。0xFF 住的是假中断,APIC 递上来无来路的话,专门备了一个座位收它静音。今天在住的就是四家。其实还有一号 0x80,当年第一遍给信号收尾留的是 int 0x80 的走法,如今信号收尾走的是十五号系统调用,0x80 早就没了人走,空下的号位咱们也不去占。四家在住的加上一个空着的旧门牌,把两头都占了,中间 0x40 起的这一段是空的,咱们划八个座,一个字的评价:够用,满了诚实答满。桩也是现成的路数:一类与线桩同款的模板实例,进门存的是浮点现场,把派发的活干完,给本地 APIC 送客,末了看要不要让位。这里有一条跟线不一样的地方得说清:线的谢客找的是线芯片,消息的谢客找的是本地 APIC,因为消息压根没进过门房的门槛,谢客自然也不登门房的门。还有一条纪律:八个桩只在 APIC 的世界里武装,开机头一程装老门房的阶段,咱们一个消息桩都不装,MSI 这路东西在 PIC 的世界里无家可归,咱们不硬给它安。

座位有了,设备的表项怎么武装,咱们把四步协议摆开,这是上一章那沓解码词的写侧对家。第一步做的是屏蔽住表项。为什么屏蔽要打头:不屏蔽的表项是活的,地址与数据两笔写之间的任何一刻,设备都可能拿一个写了一半的地址开火。第二步写的是地址与数据。第三步把写的读回来,跟写的对一对,这一读是栅栏:设备的内存窗是不缓存的,写下去什么时候真到设备手里,咱们说了不算,读回来还是咱们写的那对字,才算落了地。第四步要等对上了才解屏蔽。四步里最要紧的是失败一路的走法:读回来的字不是咱们写的,保持屏蔽的状态,答的是失败。你想那一层:一个没接住写的哑设备,屏蔽位上写的是零,它随时可能拿一个陈旧的旧地址旧向量开火,把中断打到不知道谁的头上去。宁可让它好好地哑着。地址怎么写也有讲究,咱们用的是本地 APIC 的老形态那套约定:基地址 0xFEE00000,目标核的物理身份号左移十二位拼进去,剩下的约定位保持零,表达的意思就是固定投递、边沿触发,数据字装的就是向量号本身。投给哪颗核?咱们今天固定投引导核,外面那片路由芯片也是这么干的,逐核的定向投递,咱们登记在案,而这一版不做不装。

宿主的长凳上,四桩新案配齐了:没注入区间时拒座,区间内的座位与派发,空座的静默,满池的诚实。可这些全是在内存里演的,真消息到底会不会来?来了走不走得通?这样的戏内存里演不出来。第一个真的消费者马上就到:USB 的主机控制器,一台指名要 MSI-X 的设备。所以下一章,咱们去敲它的门。
