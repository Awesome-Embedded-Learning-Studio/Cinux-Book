# 一枚回调,三席汇流

代码长到能跑枚举链的时候,咱们停下来看了看它的形状,定了动一次刀的主意再往前走。当时控制器那一层什么都干:复位、对讲、枚举、读描述符、翻译键盘报告,一屋子活挤在了一个单例里。再往后要来的客人不止键盘,平板那一头也挂上了端口,挤下去的结局只有一个:每来一台设备,控制器那层就厚了一圈。所以咱们把 USB 这套栈裁成两层。主机层只管控制器本身:窗口、复位、三只环的其中两只、门铃、事件环的排空。设备层是模板:每台坐上槽位的设备一个对象,自带它的上下文页、它的端点环、它的控制传输。两层之间只留了一条缝:主机层排空事件环时,按事件里的槽位号把传输事件路由给坐那个槽的设备,路由处的那对指针——下一节回调里的处理函数与它的主人——做一次类型擦除。擦除的地点只限缝上,这套家法咱们从块设备那一类一路守到今天。

设备层要收完成通知的话,回调是少不了的。回调这东西咱们不想再手搓一遍函数指针加 void 星了,那副模样全内核已经见过太多次:每次都要猜上下文里装的是谁,猜错一次的话,落下的是一桩悬案。所以 base 里落了一枚新词:异步回调,一个模板的值类型。真身咱们摆出来,承重的次序全在里头:

```cpp
template <typename Owner>
class AsyncCallback {
public:
    /// What a completed operation hands its owner: status and length.
    using Handler = void (*)(Owner& owner, unsigned long status, unsigned long length);

    /// @brief   An empty callback, armed by nothing yet.
    AsyncCallback() = default;

    AsyncCallback(const AsyncCallback&)            = delete;
    AsyncCallback& operator=(const AsyncCallback&) = delete;

    void arm(Handler handler, Owner* owner) {
        handler_ = handler;
        owner_   = owner;
    }

    void invoke(unsigned long status, unsigned long length) {
        const Handler kHandler = handler_;
        handler_               = nullptr;
        if (kHandler != nullptr) {
            kHandler(*owner_, status, length);
        }
    }

private:
    Handler handler_ = nullptr;
    Owner*  owner_   = nullptr;
};
```

成员配了两个,一个管处理的函数,一个管它所服务的主人,函数签名直接带上主人的引用,中间没有任何无类型的字。咱们看 invoke 里那三行,一次触发的次序全在里面:头一步取的是座位上的函数,第二步清空的是座位,第三步进的才是函数,打头的自解除与随后的调用,说的就是这两步排列的次序,来晚的完成、重复的完成,落在的是空座,什么都不说。这个次序不是随手的安排,它有承重:键盘的报告回调在函数的末尾就重新武装自己,自解除要是排在了调用之后,回调里刚装好的新座会被收尾那一笔清掉,第二份报告就永远落了空。它是个值的类型,拷贝与赋值干脆删掉了,组合进谁的成员就是谁的,不搞继承的戏法,不占堆的地界,两套世界都编得了,宿主的长凳用普通假人就能驱动。键盘设备层把它用作报告的座位:中断读武装回调在前,提交传输的事在后,报告落地,完成事件按 TRB 地址反查到这笔传输,回调开了火,响一次就把自己解除了。这里面有一个次序咱们改过一版:补下一笔传输,要在消费完了报告之后,不能在回调开了火之前。报告的缓冲就是那页 DMA 内存,提前补环的话,下一笔传输的设备写会跟还没消费的报告挤同一页,咱们不赌那个时序。

报告到了手,怎么变成字,咱们说 HID。人机接口设备的正式协议相当隆重:设备自带一份报告描述符,自述它的数据长什么样,正经的驱动要解析描述符。好在 HID 给简单设备留了一条后门,boot 协议:键盘在 boot 模式下保证报告是固定的八字节,头一个字节装的是修饰键,Shift 与 Ctrl 们各占了位,后六个字节是当前按下的六个键位号。咱们不解析描述符,直接吃下这八字节的报告。翻译用两张等长的表,平表与 Shift 表的搭配,字符挨个地排,两张表一样长的这件事用静态断言锁住,因为漏占了一个位,后面的整排全错位。这里有一个真实的坎:美式键盘上那个 Non-US 的井号波浪键,占了键位号 0x32,第一版表里咱们漏了它,占位空空的,它后头的每个键都念成前一个的字。占位补上了,边沿翻译才算齐:只认新按下的,按住的与松开的不出字,前后两份的对比里,新出现的键位翻成字符,进一个十六字的环形队列。

而后是两条汇流。头一条是键盘的入册。它以输入字符设备的身份进名册,归的是字符册,名字报的是 usbkbd,主号给了十,总线记的是 usb,驱动记的是 xhci-hid。它在设备文件世界里的脸面,咱们如实交代:读,静默地答零,写的话照单全收。它不是给 read 用的,它的字走的是另一条路。第二条汇流去的是控制台。终端的取字函数,咱们给它添了第三席:头一问串口,二问的是 PS/2 老键盘,末了问 USB。三席连成了一排,三条线上无论来什么字,行规程、回显、信号翻译的老礼数全都自动管上,USB 键盘敲的字跟串口敲的字,在行规程的眼里再无分别。

运转的泵,咱们选的是读路径轮询:读字的动作本身带头排空一次事件环。这里有一个模拟器脾气的小机关,咱们单独记一笔。排空每一轮都读一次控制器的状态寄存器,哪怕什么也不查。为什么:纯内存的轮询,虚拟 CPU 不陷出去的话,模拟器的设备模型主循环就不跑,咱们在内存里盯多久都白盯,控制器那边一帧都不带推进的。读一次 MMIO 的寄存器把 CPU trap 出去一趟,主循环才有转一圈的机会。这其实不算病,它是轮询驱动在模拟器上的正确相处方式,当年第一遍在网卡上就遇过的同一道坎,咱们把它记熟,后面的网络那几卷还会再见面的。末了把消息中断的边界如实报:武装链咱们全接通了,解码、入座、四步武装的路数,连开中断器使能的活都在了。中断器说的是控制器运行时区里专管事件中断的那一小组寄存器,事件环来了货要不要喊一声,由它说了算。可咱们的模拟器加 KVM 的组合下,表项回读就是不上钩的,咱们按协议保持屏蔽,面板如实地打印,原文咱们抄来:

```text
[kern] xhci msix entry stayed masked, the drain carries the cargo
```

表项留在了屏蔽,扛货的活由排空来做。武装留在了那里:代码一步不缺,只是当下的模拟器走不到开火的那一步,换到真硬件或换了脾气的模拟器,路是通的。还有一处小修也记下:键盘的初始化在开机序列与文件世界装配里各被叫了一次,第二次枚举去抢了个新槽位,控制器把多余的那一口回了 TRB 错误。咱们把初始化改成幂等:头一回跑完,第二回看见槽位在手的话,直接答了声好。到了这一步,键盘的字已经能流进终端了。可实弹打字的时候,屏幕上偏偏还是没字,这最后一段路上的连环坎,咱们下一章一个一个过。
