# 收不回的会话

假文件与真终端那一卷收官时挂下的疑点,咱们原样摆上桌。busybox 的 script 是这么个用法:开一台伪终端,里头再起一个干活的 shell,外头把里头的来往都录下来。咱们在实弹里跑它,三层回显走通了,可里层的 shell 一敲 exit,外层的提示符再也不回来,^C 敲了不应,敲下去的字也没有回显,机器活得好好的,会话死了。当年那一卷收卷时只记了症状,没下什么诊断。同一段合卷话里还挂着两笔各自独立的边界,座位铸了就不还,行池认不出文件的尾。这一章咱们收的是会话,行池认文件尾的那一笔顺手补上,座位的那笔照旧挂回边界清单。

把两层病都找齐了再动手,咱们是一层一层剥的。头一层的病是伪终端不认挂断。master 与 slave 是铸好的一对环,里层的 shell 退出,slave 那侧的描述符全关了,可在咱们内核里,这件事对 master 侧一个字都没有:master 的读永远等不到人,因为没人告诉它对面已经散了场。busybox 的 script 恰恰指着这个信号收尾,它把 master 设成了非阻塞,收孩子的信号之后还有一段排空 master 的循环,指的就是非阻塞读答一个再试,来知道排完了。这就牵出第二层病:咱们的读路径压根不看非阻塞位。状态字早就存进了文件对象里,可读的脸一遇空队列就无条件地等,非阻塞等于白设了。两层病叠在了一起,死在哪一段是说不准的,咱们不猜,病根都给修了。

修法咱们从两条边界倒着推。头一条管的是 master 侧的语义:最后一个 slave 关闭之后,master 的读应当读尽环里的存量,然后答零表示文件尾到了。继续写答的是 IO 错误。第二条更细:slave 侧的等待发生在行规程的肚子里,一行没敲满的时候,读的人睡在里头,master 关闭的那一刻,这个已经睡下的读也要放得出来,而且 canonical 模式下半行的收尾得有说法。咱们的次序:已经敲完的行头一拨走,raw 环里的字节跟上,末了半行的尾巴也读尽,然后答出的还是零。而且半个字都不许吞,吞了,客人丢失的数据就无处对证。

数人头是修法里最要紧的一步。怎么知道最后一个 slave 关了?咱们头一个想到的是给两端各立一个布尔,关了就置。马上就被自己问倒了:pts 这一头,同一个从端可以被独立地开好几次,三次 open 是三份独立的文件对象,谁早关谁晚关各凭各的本事,任何一次 release 就把 slave 报成了已关,另外两个还开着的人就被报了死讯。dup 与 fork 倒是不添乱,它们共用的是同一份文件对象,对象自己的引用计数天然盖住,要数的是独立 open 的份数。所以设备脸面上添两笔可选的钩子(retain 与 release),文件系统逐个独立打开的文件对象转发它们,伪终端的这一对,两端各自数自己的开灯数。还有一处初见就得防的误报:ptmx 刚开、slave 还没头一次打开,这可不是挂断的,这是还没来人的阶段,两种状态的认法得分开。重开也就顺理成章了:数人头回到非零,设备回到了存活态。座位照旧是不回收的,这是当年铸对子那天就写明的边界,咱们不偷偷改。

非阻塞与信号的活,咱们也放在这一章补齐。读的脸遇到空而未挂断,答的是再试,读路径看的是非阻塞位,设了就答 EAGAIN,没设的话就让出处理器重试。等待期间来了没屏蔽的信号,答的就是 EINTR,把打断权还给了客人。读的人手里握着的文件对象,跨过等待的当口得有人保着,不然睡一觉醒来对象没了,读了个寂寞。零长度的读立即成功,这是老章法了。宿主长凳为这一整段新立了一批案子:release 的真接线、独立多次开、描述符的继承、进程退出真的放掉了 slave、挂断后的文件尾与错、canonical 半行的保留、读路径的 EAGAIN 与 EINTR,一排全数过了。

实弹咱们打得细,咱们在普通与检查两个镜像里各来一遍:起手抄一份终端设置,起了 script,里头敲了 echo,敲了 exit,外层的提示符回来,再敲了 echo,有了回显,再抄了一份终端设置,前后两份是一个字都不差的,末了敲半条命令按 ^C,未执行的输入取消,后续的命令照常。为什么前后两份设置必须一样,这里头正藏着当初回显死掉的秘密:script 起跑时把自己的输入设成了裸模式还关了回显,指望的是退出清理时恢复,它死等了,恢复的活永远排不上,控制台就永远停在无回显无信号的形态。如今会话能收尾了,恢复自然跑到了,前后一致正是活过来的证据。这桩疑点收了,名册那边的活也告一段落,咱们把眼光转回总线:配置空间里还有一沓没翻过的活页。
