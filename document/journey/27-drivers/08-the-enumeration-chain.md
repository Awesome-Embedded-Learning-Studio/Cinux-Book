# 走一遍枚举链

环上空空的,咱们去请头一位住户。枚举这个词说的就是内核把总线上挂着的设备一台一台认下来的过程,从咱们看端口上有没有东西,一直走到设备能收发数据的地步。xHCI 的枚举链,咱们把链子整条摆出来,再一环一环讲:扫端口看谁挂了东西,复位那个端口顺便测出它的速度,发命令领一个自己的槽位,替设备写一份输入上下文的申请,发置地址的命令,从设备的零号端点读描述符认人,叫设备进配置的门,给它的中断端点配上上下文。七环走完了,一台 USB 设备才算真正在控制器里有了户口。

头三环是控制器的家事。扫端口就是读每个口的端口状态字,最低位说的是这个口上有没有挂东西,咱们的机器上口是有的。复位端口的活是往状态字里写复位位,复位位倒是自己会清,清完的速度域报出设备是哪一代速度。领槽位是一条命令环上的条子:Enable Slot,控制器答的是槽位号,从此设备在控制器里有了自己的槽,咱们在设备上下文数组页里属于它的格子填上它的输出上下文页地址。输出上下文是控制器替设备记事实的那一页,它写的,咱们只读。咱们要改设备的状态,递的是另一页申请书,名字叫的是输入上下文,到了第四环咱们马上讲。到这里为止的活都是照章办事,真正的学问从第四环开始。

第四环的输入上下文,是整个枚举链的心眼。咱们想让控制器改变设备的状态,偏偏不直接改,而是写一份申请书,连问什么带新状态一起递上去。申请书的第一页是控制上下文,八句话的篇幅:头一句话装的是 Drop 的掩码,说的是要扔掉哪些旧上下文,第二句话装的是 Add 的掩码,说的是要新建哪些,其余六句是保留与配置的信息。顺序是死的:Drop 在前、Add 在后,写反了控制器直接一条 TRB 错误回绝,连商量都不跟咱们商量。为什么反写会被拒,推一遍就明白:掩码换了位,Drop 领到的就是 Add 的差事,置地址那一步等于下令扔掉一个还没建过的槽位上下文和零号端点,不成立的还是参数本身,控制器照章回了错。头一回置地址,Add 的是两样:一样是槽位上下文自己,另一样加的是零号端点。槽位上下文里写的是路由、根端口号、速度、往后有几个端点上下文跟着。零号端点是每台 USB 设备出厂就有的控制端点,咱们按速度给它包长,高速的六十四字节,别的八字节。第五环干的是置地址。这里有一条从老 USB 时代过来的人最容易踩的沟:传统 USB 协议里枚举要发一条 SET_ADDRESS 的标准请求,xHCI 偏偏不用,置地址命令把这事连设备地址带上下文一口办了。咱们当年第一遍就是揣着老协议的地图来的,在沟边上转了两圈。

咱们把申请书连着置地址的命令一起摆出来,真码是这么一段:

```cpp
    auto* const kContext = base::PtrAt<uint32_t>(mm::DirectMapVirt(input_page_));
    InitRing(base::PtrAt<Trb>(mm::DirectMapVirt(ep0_page_)), kTransferRingTrbs, ep0_page_);
    ep0_ = RingState{.index = 0, .cycle = true};
    SetAddFlags(kContext, 0x3U);
    BuildSlotContext(kContext + 8, 0, port_, speed_, 1);
    BuildControlEpContext(kContext + 16, ep0_page_,
                          speed_ == kSpeedHigh ? kPacketHigh : kPacketElse);
    const uint32_t kSlotBits = static_cast<uint32_t>(slot_) << 24U;
    uint8_t        answered  = 0;
    return host.run_command(input_page_, TrbControl(kTrbAddressDevice, kSlotBits), answered);
```

上下文页是按三十二位一句排开的,控制上下文占了头的八句。SetAddFlags 把 0x3 写进了第二句,那正是 Add 掩码的最低两位:位零加的是槽位上下文,位一加的是零号端点。头一句的 Drop 全是零,一个旧上下文也不扔的,Drop 在前、Add 在后说的就是这两句排列的次序。槽位上下文落在第九句起的地方,BuildSlotContext 一个函数写齐了路由与根端口号,速度和往后的端点数也一起写了进去。零号端点落在第十七句起的地方,咱们拿 InitRing 把它的传输环织好了,包长按速度挑的是六十四或者八字节。末一行是真正的递件:命令的载荷就是输入上下文页自己的物理地址,槽位号挪进了控制字的高八位,控制器翻开的正是这页申请书,该新建的是哪几句,答案写在了掩码里。

第六环读的是描述符。控制传输在 xHCI 里是三段式的格局:setup 段、数据段、状态段,三枚 TRB 排在零号端点的传输环上。八个字节的 setup 包,干脆骑在 TRB 自己的载荷里,不用另外的缓冲。咱们读三回:头一回要设备描述符的头八个字节,看清设备的包长脾气,再要全份的十八字节,然后要配置描述符的头九个字节,里头说的是整份配置有多长,咱们照着全长把剩下的要回来。拿到了配置描述符,咱们扫接口:类码三、协议一的接口就是 HID 的 boot 键盘,再在它底下找方向为 IN、类型为中断的端点,端点地址、包长、轮询间隔,一样样地记下。HID 这个词的白话是人机接口设备,键盘鼠标触板全算它的,后面一章咱们细说它的 boot 协议。第七环管的是进配置加配端点:发的是 SET_CONFIGURATION,无数据段的三段式,再写一份新的输入上下文,这回 Add 的掩码换成槽位加三号上下文位,中断端点的上下文写上自己的传输环地址、包长与间隔,发的是 Configure Endpoint。间隔还有一个按速度换算的小机关:高速设备配置描述符里报的是二的幂次,减一就落了位。低速设备报的是毫秒,咱们从三起头换算,毫秒数反复地对半、每除得动一次二、幂次加一,除到不能再除的时候为止,咱们两支都写了。到了这里,面板上那句自报家门就打出来了,咱们把串口原文逐字抄来:

```text
[kern] usb keyboard seated, config 1 ep 81 max 8 interval 7
```

咱们看:一号配置,端点用的是 0x81,包长报的是八字节,间隔给的是七,链上每一环的话它都带到了。

链子讲顺了,咱们把调试的战记摊开,这一段链子当年是连着断的,三案咱们挨个破。破案的工具有两样:模拟器的 trace,把控制器眼里每一笔 TRB 打了出来,还有开机固件在咱们之前做过的那一遍枚举,SeaBIOS 开机的时候把 USB 键盘认过一遍,它的成功字节就是咱们的对照样本。头一案是控制字的语义。命令完成事件回的是 TRB 错误,拿 trace 逐一地看,咱们发的置地址命令槽位号是零,被控制器回绝了。病根在咱们给入队函数递的东西:它要的是类型号,咱们递的是拼好位的完整控制字,它再造了一遍类型位,把咱们控制字里的槽位号挤出了座位。改法是立一个拼控制字的助手,类型入了位,其余的位原样拼上,谁也不挤谁的地盘。第二案是方向编码记反了。setup 段有个字段说的是这一趟后面跟不跟数据段、往哪个方向,咱们的记忆跟规范是反的,还顺手漏了两样。头一样是立即数据的位,setup 段控制字里声明八字节载荷就地骑在 TRB 上的,靠的就是它。另一样是状态段的长度字,状态段的传输长度要报的零,说的就是它。对着 SeaBIOS 的成功字节一笔一笔比,记反的翻正,漏的补齐。第三案是上下文里环指针的真位。端点上下文里传输环的地址该落在哪两个字,咱们按错记忆写在了后头,间隔字段也跟着错了位。控制器收了这样的上下文,倒是一点不抱怨,就是静默地不干活,trace 里连一次取件的影子都没有。翻它的源码,它从咱们写错的位置读出队指针,读了个零,于是转身就走了。指针归位到了第二第三两个字,间隔也归了位,链子这才通了。三案下来有一个共性:咱们自己写的东西,自己说了不算,看 trace 里控制器收到的是什么要走在前头,回头查咱们的猜想错在哪一步要走在后头。

链子通了,键盘的户口落了,端点也配好了。可它的报告还躺在控制器的环里没人取,取出来又怎么变成敲进终端的字,咱们把这一段留到分层与回调那一章。不过在那之前,咱们还得讲这一路进门时摔的最狠的一跤,那一跤差点让咱们以为控制器根本起不来。
