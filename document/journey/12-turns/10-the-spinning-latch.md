# 转圈的门闩

想让抢占常开的话,守门的差事总得有人担。咱们把现在机器上的处境摆一摆:两条执行流轮流上 CPU,时钟中断随时进门——就绪队列、堆的空闲链、名册的位图,全是它们共用的财产。一个任务把堆的空闲链拆到一半,时间片到了,换上来的另一个任务也去要内存,它看见的是一条断到一半的链。这在单线程的时代不是问题,因为拆到一半的中间态根本不会被打断。现在会了。所以共享的每一段,进门前的看守不能省。看守的办法,单核的世界里拢共三条:把中断关了(屋里没人能进来)、原地转圈(等现在屋里的人出来)、干脆睡觉(把 CPU 让给别人,等别人的叫醒)。本节立的是转圈的那一件,自旋锁——名字直译是转圈的锁,拿不到的话就在门口转圈等,它管的是最短的那些临界区。

它的全部身子,核心就这么两下原子操作。拿锁的一下,test_and_set:把锁上的旗改成已占,同时告诉你改之前是什么——改之前是空的,你拿到了。改之前是占的,说明有人在你前头,你转圈再试。放锁的一下 clear,旗清回了空。咱们把真身摆出来:

```cpp
void Spinlock::lock() {
    cinux::base::safety::Check(!held_.test(std::memory_order_relaxed),
                               "spinlock re-entered on one core");
    irq_state_ = cinux::arch::SaveAndDisableIrq();
    while (held_.test_and_set(std::memory_order_acquire)) {
        cinux::arch::CpuRelax();
    }
    SpinLedger& ledger = ledger_ != nullptr ? *ledger_ : DefaultSpinLedger();
    ledger.note_acquire();
    holder_ = Scheduler::self().current();
}
```

这一段里叠着的是四层心思,咱们一层层揭。第一层是进门的那声 Check:同一个任务、同一把锁,拿两回?在单核上这不是等待,是死局的别名。自己手里的这杆旗,转圈等的也是自己,这样的等待永远没有结果。所以重入不让它悄悄发生,而是当场叫。第二层讲的是自旋锁在内核里的看家本分:持有期关中断。SaveAndDisableIrq 的那一行,讲守卫的时候您刚认识,进门存了旗,跟着落了闸。为什么自旋锁必须管中断:您想,一个任务拿着锁去改共享的链表,改到一半时钟的中断进来,中断的服务也要碰同一条链表,它要的也是这把锁。可在单核的机器上,持锁的人正悬在中断里出不来,放锁的那行代码排在它身后永远轮不到执行,机器当场死机了,连转圈的机会都不给。所以内核的自旋锁天然带着关中断,出门的时候按快照原样还。就这么一进一出,正是 IrqGuard 的纪律穿在锁的身上。第三层是转圈里的那声 CpuRelax,一条 pause 指令:告诉流水线我在等,劝它从容地往前走,也省了电,还给同核心的兄弟执行流让出点喘息。它住在 arch 新立的 instructions.hpp 里,这类对 C++ 毫无意义、对 CPU 一字千金的指令,往后一个个归回自己的家,不再散落成裸汇编的零碎。第四层轮到的是那对内存顺序:拿锁配 acquire,放锁配的是 release。咱们给它俩配句白话:release 是放行前的承诺:我临界区里的所有写入,在我放锁之前统统落定,后拿锁的人一定看得见。acquire 是进门时的要求:我拿锁之后的读取,一定读得到上一任留下的一切。就这么一放一拿,两个执行流之间就架起了一条可靠的传话管道——而这对顺序,正是上一节 relaxed 那个松亲戚的两个严亲戚,共享的不只是旗,还有旗护着的数据。

锁上的家当之外还有一件小家具:登记簿。它的名字叫 SpinLedger,数着这个核上现在活着的自旋锁有几层。它的差事,下一节您会看到它在睡觉的路上设卡。这里把纪律立在前头:持着自旋锁的人,是不许去睡的。您想,睡眠两个字的意思是把 CPU 让给别人,可拿着自旋锁的您,是全机唯一能放这把锁的人,您睡了,等您的人转圈转到天荒地老。响亮地叫,总比挂了强一万倍。登记簿还留了个小心眼:锁可以自带一本私册,不挂公共的那本——长凳上的测试世界各挂各的,谁也不干扰调度器的查。

本节的最后一段,咱们交一笔用一次缺页换来的学费。锁家族造好的头一天,生产者消费者的演示首跑,机器直接缺页崩了,崩的位置匪夷所思:登记簿的自增那一行。咱们顺着崩溃地址回去看,看到的东西起初无法理解:那个全局锁对象,躺在 .bss 里的字节全零——咱们给它的构造函数,一个字节的代码都没执行过。对啊,这就是咱们从内核出生那天起的世界的样子:没有全局构造,没有任何静态对象的初始化代码会跑。咱们一边立着零构造的纪律,一边顺手写了带构造参数、带引用成员的锁。要绑定的引用,要设初值的计数,这些全是要跑代码的事,而那段代码永远不会跑。悬空的引用、没落的初值,一个看似无害的自增踩上去就是缺页。修法分三件:锁对登记簿的引用改成可空指针,空了就自动挂公共那本。信号量也补上了默认构造,全零起步——计数的值是零,等待队列也是空的,这是一个完全合法的语义:货还没补,等货的人自然要排队。至于要几个货的开场补发,开场发的活归用例自己。三件都修完了,一条家规也落了定,和单例的 constinit 是同一条:静态寿命的对象,全零字节必须是合法的默认态,凡是需要跑代码才能变得合法的设计,在这个世界里都是错的。咱们把它写进案卷,往后的每一件全局物件,出厂的时候过这一关。

长凳的那一头,test_sync 四案把状态机按住:持有者计数与报号、嵌套锁的层数回卷,无争用的互斥锁一进一出、有存货的信号量从不停车。门闩立好了,可自旋终究是门口的等待,等得久的事,比如等一件还没生产出来的货,得有更体面的办法,咱们下一节就讲它。
