# 12 · 轮流当家:让出来的,抢出来的,排出来的

上一卷收工的时候,咱们把家底数得很清楚:城里水电全通,就等住户了。堆在等自己的进程对象,地址空间在等调度,这两句话咱们撂下还没凉,这一卷就来兑现了。不过真要动工之前,咱们把要造的东西说成人话:内核打出生那天起,就只有一条执行流——从入口一路跑到主流程末尾的 hlt,中间不管进了多少次中断,回来的还是它自己。这一卷要给它添的就是第二条执行流。存得下的照片,换得动的人,愿意的时候让得出,睡着了也等得到人来叫,咱们管它叫任务。第二条立稳了,往后添的第三条第四条不过是排队领号的事。

动工的顺序咱们反着排了一回:护具赶在雷区前头,咱们再进雷区。上下文切换这一类的活,崩起来是三重故障的黑箱,寄存器换到一半的机器连报丧的力气都没有。咱们趁城里还是单线程、什么都好查的日子,把帧指针、栈回溯、gdb 挂钩这几件备在了手边,真的崩了,至少知道死在哪一行的门口。接下来的三幕才是正戏。头一幕讲的是协作:任务自己愿意让,yield 一声就把 CPU 交了出去,两个任务乒乓了三轮,机器稳稳当当地跑。第二幕讲的是抢占:任务不让,替它让的是时钟——时间片一到,轮换就在中断的出口处完成,全程的代码里一句 yield 都不用写。第三幕排队:让出去的人挂上等待队列睡觉,等人来叫醒——自旋锁、互斥锁、信号量的三件套,配齐了之后,抢占才能放心地常开。

这一卷的坎,几乎全长在了交界处。汇编与 C++ 的约定,靠一把 static_assert 锁在了编译期。上一卷堆里 8 字节的尾巴,被一个要 16 对齐的任务对象当场问罪,旧债在这一卷还清了。一面 IF 的旗在中断帧里跟着 iretq 走,当年为它打的补丁,在咱们这个结构里无从下手。还有一段被编译器删掉的等待循环——中断改内存这件事,咱们从来没表达给它,旧代码能跑靠的只是碰巧挡住。考古箱这一卷是满的:当年的四月,上下文切换、调度器、同步的三件套在 36 个小时里连落三站,笔记五篇里四篇是主菜——上一卷咱们翻到的是没有笔记的日子,而这一卷,当年的话留得足足的。

机器如今当家的不只是一个了:时钟每一响,出口处问的是一句该不该换人。想让的人有 yield,想让又怕等的人有等待队列,睡下去还有叫醒的人。可咱们心里有数:这一卷立起来的全是内核自己的线程——同一个特权级,同一副的页表,轮流坐庄的是自家人。下一卷该请的,是内核之外的执行流了:ring3 的用户进程,特权级里最低的那一层,用户程序住的地方,自带的世界跟着它进门。等到了那天,内存当家那一卷留下的 activate 才等到真用户,切换连页表一起换的那一拍,咱们到下一卷讲。下一卷咱们开门迎客。
