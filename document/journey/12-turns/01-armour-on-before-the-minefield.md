# 趁雷区还没开门,把护具穿上

上一卷交割的时候,咱们知道交到本卷手里的是什么地段:上下文切换。上下文切换的崩法咱们提前就能想象:寄存器换到一半、栈换到一半,机器直接来了个 triple fault,连会疼那一卷立起来的异常转储都未必来得及开口。崩了不知道死在哪,当年的头一遍就是这么过来的,全凭一晚上的盲猜。所以这一卷动手之前,咱们赶在切换前头把护具穿好——趁城里还是单线程,什么都好查,等出了事再现造工具,现场早就没了,造出来的是遗物。咱们盘点家底:串口打头装配有了,异常转储六件有了,Check 断言、机内测试的红路、QEMU 都有了。缺的只有一件:崩了之后,那行触发崩溃的地址,咱们拿什么对回源码。本节要补的就是这一件,补的是三层:编译期留线索、崩溃时报线索、活着的时候查线索。

头一层要办的,是让编译器把回访的路留下来。函数在机器上的调用是一串栈帧,每个帧里存着返回地址,顺着帧走回调用链的路,得有人记着上一帧在哪——留路的差事,归在帧指针寄存器 rbp 的名下。默认的编译选项为了省一个寄存器,经常把它给省了,帧与帧就断了线。咱们把 `-fno-omit-frame-pointer` 写进了内核的编译旗组,每个函数进门压下旧的 rbp,再把当前的栈顶请进 rbp,链就接上了。这一件是典型的晚开成本高的东西:今天不开,哪天崩了想开,得付的代价是整个内核重编一遍,而崩溃的现场早没了。反汇编里咱们抽查过,内核主流程的序言老老实实建着帧。

崩起来的时候,顺着 rbp 的链走就是第二层。会疼那一卷立的异常转储,六件现场报得出死在哪个地址,却报不出怎么走到这儿的。咱们新立了一个 `kernel/debug/` 目录——这是工程头一回有 debug 这个顶层目录,它就是为本卷的切换排查而生的,往后的锁观测、内核恐慌都来这儿安家。三件套照咱们熟悉的样式:`trace_config.hpp` 放旋钮(最多走十六帧),`trace.hpp` 公告的是一张脸,`trace.cpp` 装的是实现。实现咱们整个看一遍:

```cpp
void TraceFrom(unsigned long long frame_base) {
    cinux::print::Println("[kern]  trace:");
    unsigned long long frame = frame_base;
    for (unsigned int depth = 0; depth < kMaxTraceFrames; ++depth) {
        if (!link_plausible(frame)) {
            break;
        }
        const auto* slot = cinux::base::PtrAt<const unsigned long long>(frame);
        cinux::print::Println("[kern]   #%u 0x%X", depth, slot[1]);
        frame = slot[0];
    }
}
```

走链的手艺就三步:看这一帧像不像帧(非零、16 对齐、落在内核半边,三关全过了才敢解引用),印出帧里第二个字——那就是返回地址,再拿它的第一个字走到上一帧。异常的现场取的是被打断的那一帧:转储函数自己的 rbp 解一层,迈过中断桩的帧,落回出错代码的链上。实弹咱们真放过一发:临时往代码里塞了一条 ud2,一开机机器真的崩了,串口上走出了两帧,咱们拿 addr2line(把地址对回源码文件和行号的小工具)一对,头一帧的落点正中崩溃调用点,第二帧报的是内核入口。验完之后咱们把改动撤干净重建,面板的十行照旧全亮。这一发实弹也划出了本层的边界:trace.cpp 自己排进了不开向量化的岛——中断路径会调它,岛上的住户名单,是会听那一卷立下的,这一卷又添了几户。

第三层活在平时:机器没崩的时候也要能查。boot 那一头新立了 `run_debug` 目标:QEMU 起来就冻结在复位,gdbstub 开在了 1234 口,gdb 的命令文件由构建自动生成,吃的是未剥离的内核 ELF——符号全在,断点才认得它们的名字。这一件咱们也真挂上去跑了一回,还当场吃了一记教训,值得原样讲给您听。咱们头一个试的是软件断点:`break KernelEntry`,咱们 continue 下去,结果永远不命中。是 gdb 偷懒吗?把机制一条一条看就明白了:软件断点的身子,是 gdb 往那段内存里写下的一个 int3 字节,机器的执行流走到它身上才停。可咱们的内核是 boot 从磁盘上加载进内存的,加载器把整副镜像原样拷了进来,断点字节就被覆盖了,从此那个地址上跑的是正经指令。软件断点在咱们这儿,天生活不过加载这一关。咱们到同一家人里找答案:`hbreak`,它的全名是硬件断点,断点记在 CPU 的调试寄存器里,连一根内存的边都不碰。换了它,起机停在了入口,寄存器的内容读得到,回溯的链也走得动。用法其实拢共就两行,您开两个终端:一台敲 `cmake --build build --target run_debug`。而另一台敲 `gdb -q -x build/kernel.gdb` 挂上去。第二句 run_debug 起来时自己也会 echo 给您,忘了跟着敲一遍就行。这套用法咱们固化进了 gdb 模板,往后 run_debug 出来的就是它。

护具各有各的边。帧指针的链,只对编译器生成的函数有效。本卷马上要写的切换汇编是手写的,它是不建帧的,回溯链走到切换点就断了。手写汇编的面目本来如此,其实谈不上缺陷,咱们真排查到那儿也不硬走回溯,换一条直接看寄存器的路,本卷稍后对齐那桩案子里您会看到怎么个走法。有了这三层,咱们可以进雷区了:下一节,咱们给内核添第二条执行流。
