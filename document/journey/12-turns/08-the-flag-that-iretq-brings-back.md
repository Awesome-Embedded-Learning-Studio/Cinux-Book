# 跟着 iretq 回来的旗

上一节咱们说好,本节专讲的就是一面旗。它的名字叫 IF,是 RFLAGS 寄存器里的第 9 位,CPU 的中断总闸。会听那一卷开闸的日子咱们就认识它了:拉它起来的是 sti,放它下去的是 cli。它跟本卷的关系,得从一份 62 行的旧笔记讲起,那是当年抢占式调度落地时写下的一份病历,咱们把它当考古主菜端出来。

咱们补一块机制的地基:中断进门的时候,旗去了哪。硬件响应中断的那一瞬,CPU 往栈上压的东西只有三样:rip、cs、rflags——被打断代码的回家行李,行李里躺着的就有 rflags。rsp 和 ss 的这两件行李,要等中断把执行流拽去别的特权级才会跟着压进来,那一幕留给下一卷的 ring3。紧接着的这一步,中断门自己动手把 IF 清了。为什么清?不请自来的中断套中断,栈就被压了一层又一层,办到一半的事又从头办起,世界很快就乱了——所以门是进门就关上的,这是硬件立的体面。那 IF 什么时候回来?iretq。中断服务跑完了,iretq 把三样行李逐件弹回各自的寄存器,rflags 原样归了位,IF 原来的值是 1 就回 1,原来的值是 0 就回 0。咱们把它记成一句话:旗不跟任务走,跟的是中断帧,iretq 是它的还乡路。

当年的病历,病根咱们一句话就点破了:这句话当年连一个看见的人都没有。当年的 context_switch 和咱们这一版一样,只存取 callee-saved 的八槽,RFLAGS 的边都不沾,八槽里没有旗的位置。协作式的日子里这不是事:切换发生在正常代码里,那儿的 IF 本来就开着,存不存其实都一样。可一到抢占式的地界,切换的地点就变了:它发生在中断的 handler 里,进门时硬件已经把旗清了。咱们跟着当年的机器走一遍:任务 A 正跑着,时钟的中断一进来,旗就被清了,handler 里发起了切换,任务 B 就上了桌。B 的照片里没有旗,B 起跑时的旗就是切换那一刻的旗,而且是关着的。B 从此收不到任何中断:时钟进不来了,抢占轮不上了,计数器也不走了,B 关着闸跑完了自己的一生,退了场,切到了 C,C 也同样关着闸跑完了。那机器怎么没死透?因为 A。A 的照片停在 handler 里,哪天它被换了回来,恢复点之后迎来的就是 handler 的尾声和 iretq。iretq 把 A 自己的中断帧弹了回去,旗就还原成了 1。于是整个系统里只剩头一个被抢占的任务还活着轮转,而后来者全部在寂静里出生、又在寂静里退场。这个病最阴的地方是它不出声:串口照常打印,任务照常跑完了,您只觉得慢、只觉得怪,想不通为什么两个任务井水不犯河水。当年的修法是在切换汇编里、栈换过去之后、跳转之前补一条 sti——不管谁上桌,把闸开了再说。它的粗暴是真的,有效也是真的。笔记的末尾还留了一笔更精细的方子:用 pushfq 把 RFLAGS 也拍进照片,切换的时候连旗一起换,谁的旗归谁。方子留在了纸上,病治好了,当年的事就到这儿。

现在咱们看自己的结构,问的还是同一个问题:这个病灶,在出口调度下会在哪儿发生?答案是没有哪儿。您看三条换手的路。打头的一条是抢占换手,发生的位置在 dispatch 之后、iretq 之前。被切走的任务,照片里的 rip 停在中断出口附近,它被换回来的那天,恢复之后走几步就是 iretq 了,旗由中断帧还——这正是它一步都不绕远的还乡路。协作换手的路在守卫身上:yield 的身子裹在一个关中断的守卫里,切换发生的地点在守卫之内,被切走的人回来时还在守卫之内,守卫退出时按自己进门时存的快照还原旗。旗跟守卫的快照走。新任务走蹦床:蹦床的头一条指令就是 sti,旗自己就开了。咱们数下来是三条路,旗各有各的来路,其实没有一条要照片替它背。您看出口调度真正的收益在这儿:躲开应答次序的缝只是头一层,更要紧的一层,是把所有切换点定在了旗的语义自明的地方——要么 iretq 门口,要么守卫怀里,要么蹦床上。当年的病根不是少存了一个寄存器,是切换可能发生在旗的语义没人管的地方。结构把地点定下来,这个病灶就找不到落脚的地方了。咱们在蹦床那儿埋过一句“为什么 sti 必须在蹦床里”,答案今天到齐了。

咱们顺着守卫这个词把守卫族正式立起来,因为从立起它的这一刻起,关中断不再是裸的 asm,它成了一种有纪律的物件。而纪律拢共就四个字:条件还原。想象嵌套的两层临界区:外层关了中断,内层进来了,存到的快照是关着的,内层退出的时候要是无条件 sti,就把外层还想要关着的世界提前打开了——这个 bug 太经典了,咱们给它留了个名字的位置:早开。防它的写法是进出都按快照办事:进门一记 pushfq 把整个 rflags 存进自己的 State 槽,跟在后面的是一记 cli,出门的时候看快照,快照里的 IF 是 1 才 sti。咱们看真身:

```cpp
unsigned long long SaveAndDisableIrq() {
    unsigned long long snapshot = 0;
    __asm__ volatile("pushfq\n\tpopq %0\n\tcli" : "=r"(snapshot) : : "memory");
    return snapshot;
}

void RestoreIrq(unsigned long long snapshot) {
    if ((snapshot & kIfBit) != 0) {
        __asm__ volatile("sti" : : : "memory");
    }
}
```

这一对函数咱们还办了件分家的事:声明只有一份,真身却配了两副,内核这边走的是真 pushfq 真 cli,长凳那边是空操作——链接期各取各的。这是老家法的再版:声明定了一份,实现配了两组。长凳上压根没有可关的旗,可守卫的形状、锁的逻辑、调度器的状态机,全都能在 host 上跑通了。有了这一对,早开就不是一个需要小心提防的 bug 了,它是一个写不出来的形状:您手里根本没有无条件 sti 这件工具。

壳咱们也统一了。关中断、禁抢占、往后的拿锁放锁,进和出的动作千变万化,可进、干、出的骨架始终是同一个,所以 base 家新进了一件轮子 scoped_guard:策略给出一个 State 槽、一个 enter、一个 exit,壳负责构造的时候进、析构的时候出,拷贝与移动全删了——拷贝一个守卫等于一次双重退出,事故从类型上就堵死了。旗的纪律是 IrqLockPolicy(State 装快照),抢占的纪律是 PreemptLockPolicy(State 是空的,记忆只有调度器里的深度计数)。咱们手里同一副壳,装的是两种纪律,往后谁需要进与出的纪律,咱们就把这副壳留给谁。守卫的验收两边都有:长凳拿玩具策略验的是进出次序、嵌套从里往外旋,空状态策略要的只是编译即过、计数照走。机内一案是给旗的纪律上实弹——守卫里嵌守卫,内层退出了,时钟依然是冻结的,三千万次的空转里一拍不涨,最外层也退出了,计数器重新走起了字,五拍之内必须听到它的动静。

第二幕到这里才算真正收工:换手有了,旗的来路也条条都清。可咱们这一卷写到中途,还岔出去办过一场官司——一场关于编译器的官司,主角是一个被删掉的等待循环。这么一场官司,咱们马上开庭。
