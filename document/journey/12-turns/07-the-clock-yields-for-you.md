# 时钟替你让

协作式跑通了,咱们马上请它让位。yield 是君子之间的协定,而内核等不起君子:一个算死循环的任务、一段跑飞了的驱动,它不喊 yield 的话,全机就归了它,连串口都跟着哑了。所以本节办第二幕:抢占——任务偏偏不让,替它让的是时钟。目标咱们开篇立清楚:两个死循环的任务连一行 yield 都没写,串口上照样交错地响。而要达到它,咱们得回答两个问题:谁来扣换人的扳机?又在哪儿扣?而第二个问题里,藏着一道本卷最深的缝。

咱们把缝量出来。直觉的答案是在时钟中断的 handler 里直接切:tick 一到,咱们在 handler 里调一把调度,当场把人换了。当年的头一遍就是这么写的,它的 irq0 处理,给芯片的应答在前、发起切换在后,之后它就爱切哪儿切哪儿了。可会听那一卷立的章程您还记得:dispatch 跑 handler 在前、应答在后,应答内化在了服务里,跑完 handler 无条件谢客——次序跟当年正好是反的。这么一个次序,是会听那一卷用一场实验立下的老章程:当年把 dispatch 里的应答注掉再开机,芯片从此扣住了 0 号线,心跳只来了一拍。本卷照的也是这个章程。那么在咱们这次的次序下,要是照旧在 handler 里直接切换的话,会发生什么?切换一走,被切走的任务停在 handler 里,应答的那一行还没执行——它要等的是下次被换回来,谢客的事得排到那之后。可芯片的那一头,0 号线的应答不来,这一线就还处在服务中的状态,PIT 后续的拍子一次也递不进来:别的任务被饿上几秒,机器的时钟就慢上几秒。切换是对的,时机是错的。

所以扳机可以由时钟来扣,响枪的位置却得挪出 handler。咱们的解法起名叫出口调度:handler 只数拍,该给的应答照常给,真正的切换搬去中断的出口。回头您看代码,打头的就是心跳,irq_stubs.cpp 里它多了半句:

```cpp
void heartbeat() {
    cinux::time::Tick::self().on_interrupt();
    cinux::proc::Scheduler::self().on_timer_tick();
}
```

数拍的一句就是 on_timer_tick:当前任务又跑了一拍,咱们给它计上一笔。攒够了时间片的拍数,置一个该换人的标志,完事之后正常地返回。dispatch 的应答一行没动,谢客的延迟是零。咱们再看出口,IRQ 桩的模板里添了后半句:

```cpp
template <unsigned int Vector>
__attribute__((interrupt)) void irq_entry([[maybe_unused]] InterruptFrame* frame) {
    cinux::interrupt::Irq::self().dispatch(
        cinux::interrupt::IrqLine{.value = Vector - kFirstIrqVector});
    cinux::proc::Scheduler::self().maybe_preempt();
}
```

dispatch 回来了,应答谢完了,iretq 还没执行的当口,maybe_preempt 站出来问一句:该换人吗?不该换人的话,iretq 照旧走它的路,被打断的任务毫发无伤地回去。该换的话,那就在这儿把轮换办了,iretq 留给下一个任务的恢复路径去用。这个位置是整个设计的要害:它在中断上下文里,却已经在中断服务的尾声,IF 的还原来路清晰,下一节咱们专讲 IF 旗。咱们给这道问询也拦上三重门,门门过了才动:换人的标志立了没有,抢占的总开关开了没有,禁抢占的计数是不是零。第一门是时钟的意见,第二门是世界的意见——开关默认是关的,因为眼下堆和名册还是不设防的共享财产,两个任务各改各的就乱了,等本卷的末尾锁家族把它们护起来,咱们才敢让开关常开。第三门是临界区的意见:有任务把共享的临界区护在手里时,就不许被抢走了。您会问这门谁在看。本卷的锁家护临界区用的是关中断,时钟连门都进不来了,哪里还轮得到第三门表态?这门之所以立着,是给将来关不起中断、又不许被换走的长临界区留的,眼下还没有穿戴它的人。

时间片的数也交代:两拍一片。心跳的频率是 100Hz,一拍的长度是 10 毫秒,两拍叠成的一片是 20 毫秒。这个数咱们不是拍脑袋定的,这里有一桩当年的旧案。当年头一遍的片长是十拍,100 毫秒——听起来很短不是吗?三个线程跑下来,串口上是整整齐齐的三段,每一段里只住着一个线程:头一个跑完了全程,下一个接了手,再下一个收了尾,一丝一毫的交错都没有。抢占开着的,怎么像没开?答案是虚拟机里的 CPU 密集循环比直觉快得多:100 毫秒够一个忙循环把活全干完了,任务在自己的片里善终,时钟的一次意见都没来得及提。修法是咱们把片长砍到两拍,再把每个任务的负载加重。这桩旧案咱们单独拿出来说,修法一句话就完了,值得说的是验法:怎么证明抢占真的发生了?交错输出就是证据,而负载不够重,咱们就永远看不到证据。测试要的是红路实弹,会听那一卷立下的方法论,在这里换了个方向再用一次——不是让失败大声响,而是让成功有迹可循。

现在咱们把这一幕的演示跑了。咱们起两个任务,入口是同一个忙等函数:从当前的拍数起忙等 15 拍,打印了一行,又等了一轮,跑满了三轮才退场——全程的代码里没有一声 yield:

```text
[task] tid=3 'spin_a' round 0 (no yield)
[task] tid=4 'spin_b' round 0 (no yield)
[task] tid=3 'spin_a' round 1 (no yield)
[task] tid=4 'spin_b' round 1 (no yield)
[task] tid=3 'spin_a' round 2 (no yield)
[task] tid=4 'spin_b' round 2 (no yield)
```

每行后面跟着的那句 (no yield),是任务自己亮出的免责声明:交错不是我让的。真跑的串口上,这六行紧跟着的是第三幕的买卖,preemptive tasks drained without a single yield 那一行收工的话,排在买卖收摊之后才轮到——为什么收工条陈压在买卖后面,咱们到验收的时候逐行读。长凳和机内的配套也齐了:长凳的 scheduler 测试添了时钟用例,把时钟模式的世界喂满两拍,断言出口问询真的发起了换人,而全程没有一声 yield。机内的 sched 台添了两案,一案就是上面的双任务死等,两个任务各自记下的 tid 序列都得有字,而且头一笔记的都是各查各的号——而单核上,两份序列的来源只能是轮流上 CPU,这是轮换的直接物证。另一案是给关中断纪律的,咱们放到下一节跟 IF 旗一起说。

第二幕收了场。可您也许已经注意到,咱们从头到尾没提 RFLAGS——中断进门的那些拍,IF 旗发生了什么、换走的任务拿什么把它找回来,这正是当年 62 行笔记的全部内容,也是下一节的主角。
