# 验收,和笔记成堆的日子

收尾的演示,咱们开一间小铺子。货架空了四个槽,看店门的是一把互斥锁,管供需的是两杆信号量:free_slots 数的是空槽有几格,goods 数的是货架上躺了几件。生产者的活是来六件货:每件从 free_slots 里取一格,空槽取完了就睡觉等。取到了格子,进了店门把货放上架子,再朝 goods 里放了一件。消费者把路子倒过来:每一件都从 goods 取——没货也就睡了,取到了货,进了店门把货拿走,再朝 free_slots 把一格还了回去。机内把环走通的案子比演示更重:八件货、开抢占,收工的断言拢成两句——生产和消费两边的总和都得是 36,取放的趟数都得是 8。八件货全部过了手、一件没丢、一件没重,这一案同时压着互斥锁的进出门、两杆信号量的交接、抢占下的真并发。产品内核上跑的是轻一档的六件货,咱们把买卖这一段的串口原文抄在下面:

```text
[task] tid=5 produced item 1
[task] tid=5 produced item 2
[task] tid=5 produced item 3
[task] tid=5 produced item 4
[task] tid=6 consumed item 1
[task] tid=6 consumed item 2
[task] tid=6 consumed item 3
[task] tid=6 consumed item 4
[task] tid=5 produced item 5
[task] tid=5 produced item 6
[task] tid=6 consumed item 5
[task] tid=6 consumed item 6
[kern] preemptive tasks drained without a single yield
[kern] market closed the loop, preemption stays armed
```

串口上排在买卖之前的,还有第二幕的六行 spin 输出,更早的第一幕留下了六行乒乓,和紧跟六行的条陈 `cooperative tasks drained, back on main`。第一幕的条陈跟在自己的六行后头,第二幕的条陈却压到了买卖后头,本节抄的是买卖这一段。这十四行值得咱们逐行读,因为它就是本卷全部机制的字幕。打头的四行,生产者连放了四件——四个空槽正好填满,第五件再要空槽就要不到了,生产者睡了。接着的四行,消费者连取了四件。每取一件还一格的路数照旧,而可生产者还睡着(它不是转圈,是等到货的人叫),消费者把四件全搬空了,朝 free_slots 攒够了格子,把生产者叫醒了。再往后的四行,生产者补上了五六两件,消费者跟着取走了,双双退了场,店门关了张。末了两行是主流程的收话。drained 那行说的是第二幕死循环任务的事:三幕各有各的 run_until_done,第二幕自己那次跑完没留下收工的条陈,那句 preemptive tasks drained 的打印语句被排在了演示代码的最末尾,落在小铺子那场买卖的 run_until_done 打烊之后。market closed 那行是收官的谢幕,preemption stays armed 则交代了一句:抢占开着收的摊,咱们没有为收官关它。您看,行序本身就是证据:一睡一醒的节奏、槽满即止的节拍,全写在行与行的次序里——这跟讲时钟时说的验法是一脉的:并发对不对,时序的字会自己招供。

咱们再看面板。发货用的还是老命令,`cmake -B build && cmake --build build --target run`,kern 十行咱们原样抄来对数:

```text
[kern] 64-bit C++ world alive
[kern] gdt+idt self-owned, sse on
[kern] bootinfo: 8 e820 entries, fb 1024*768*32
[kern] screen console 128 cols 48 rows
[kern] kernel at 200000 size 8F1D0 entry 200040
[kern] pmm: 32336 pages free (probe 100000 ok)
[kern] vmm: address space up, magic 114514
[kern] heap: new/delete live (probe 114514)
[kern] irq on, tick 100Hz
[kern] keyboard on, type to echo
```

十行里的八行是老面孔,数字动了的是 kernel at 和 pmm 两行,咱们一笔一笔核。kernel at 的 size 从上一卷的 0x8C780 涨到 0x8F1D0:折成十进制 586192 个字节,向上取整占了 144 页,上一卷是 141 页——长了三页。长在哪:proc 全家、切换的汇编、调试地基、锁家族,连着单例模板一起进了盘。entry 的门牌跟着挪了窝,从 200670 挪到了 200040。咱们在讲单例的时候把入口搬进了独立的 entry.S,它排进了 .text 的最前头,门牌自然也就往前挪了。pmm 那行从上一卷的 32339 落到 32336,少了三页——您看这两行是一笔同源的钱:镜像长了三页,名册就少记了三页可用,一笔就对上了,谁也不欠谁的。probe 的读数还是 0x100000,种子柜的地界照旧是保留区,名册的记录一笔没乱。盘上咱们也量了:kernel.bin 从 27424 字节长到 37472,镜像的大小还是 1MiB,原来的格子一格没动。

两头的测试数咱们也报。长凳的那一头,本卷新进了五件:test_context、test_scheduler、test_guard、test_self_list、test_sync,收到的总数 27 件——决策流、守卫次序、链表形状、锁的状态机,全是 host 上断言得了的,这正是决策/动手分离当年许下的愿。机器里的那一头,测试内核从六台涨到了七台,新丁是 sched:老底的五案全在,乒乓、哨兵、生灭回平、时钟轮换、旗的冻结,再把第三幕那间小铺子的买卖收进来,凑成了六案,一台跑下来的耗时在 0.86 秒上下。全部的台子加起来,ctest 的三十四件全部通过。七台里有几台的性命,是靠讲单例那桩案子救回来的——原子化之前的等待循环,在长凳上可是全数通过的。

收尾之前咱们照例翻考古箱。这一卷翻出来的日子,跟上一卷恰好凑成一对的反义词。上一卷咱们翻到的是空白:当年的四月二十,页表、堆、地址空间三件挤在同一天,连一个字的笔记都没有。这一卷的三件,上下文切换、调度器、同步的三件套,就落在那同一个四月的紧后头:深夜里切换头一个落地,它是那一整天九站连落的尾班车。调度器和同步在第二天接连跟了上来,三站前后的时间拢共 36 个小时。上一卷沉默的人,这一段话很密:五篇笔记留了下来,四篇是主菜级——退场崩溃那篇里的两个 bug、时间片太长、丢失的 IF 旗,这三篇咱们本卷都端上了正桌。第四篇修的是高半边的地址,它的主菜排在下一卷换页表的那一拍,咱们到时再端。还有一篇讲字节模式检查的,说的是汇编器给同一条指令换了套编码、按字节找指令的检查就认不出了,这一篇在本卷没有对应的故事,咱们只带走一句话:语义等价,编码相同却是没有保证的。日子挤成那样了,笔记却写得那么勤,您把两卷连起来看就有意思了:写了笔记的那两天,是当年手上最顺的两天。没留字的那一天,人正埋头赶自己的路。

三件活交割:内核有了第二条执行流,轮流当家的排班交给了时钟,排队等的人和叫醒它的人都有了章程。可这一卷立起来的,全是内核自己的线程——同一个特权级、同一副页表,坐庄的再怎么轮,轮到的都是自家的人。下一卷来的是别人的执行流:ring3 的用户进程,自带的世界跟着进门。等到了那一天,咱们的 ContextSwitch 才头一回连页表一起换,内存当家那一卷留下的 activate 终于等到真用户,换世界那一拍的完整故事,咱们到那一卷讲。地基打到这里,城里能住人了——现在,该开门迎客了。
