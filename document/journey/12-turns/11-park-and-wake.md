# 让出去,还能被叫醒

自旋锁的适用范围,咱们得诚实:它管的是几十条指令的短巷子。可要是等的东西一时半会儿来不了呢(等一件还没生产出来的货、等一段还在别人手里的长活),转圈就是烧 CPU 了:您转的每一圈,都是全机唯一那颗核上的电。所以第三条路才是等的长策:睡觉。睡觉在咱们的机器上是个准确的说法,不是修辞:把自己从就绪的队列里摘下来,挂到某个等待的队列上去,状态标成了 kBlocked,然后发起一次切换——调度器从此跳过您,直到有人把您叫醒,重新塞回就绪的队列里。摘下、挂上、叫醒的这三步,落在调度器的新动词上:block_current 和 unblock。您注意所有的队列入口,就绪的也好等待的也好,全都裹在关中断的守卫里,道理跟上一节说的是同一个:队列本身也是共享财产,挂到一半时被别的执行流抢看,看见的又是断链。

这件等待队列的家具,咱们没有往堆里 new 节点,而是让节点长在任务自己身上。Task 继承了 base 家新轮子 SelfNode,自个儿的身上就带一根链,等待队列 SelfList 拿这根链把排队的任务串成一条。这个形状的行话名字叫侵入式链表,好处咱们数实的:头一条,睡觉的路径上一分钱分配都不花——您想,睡前还提心吊胆地去 new 一个排队节点,堆要是正好满了,这觉就都睡不成了。错门也天生防得住:每个任务名下的节点只有一根,同时排在两条队里的事在物理上就办不到,等待队列最怕的错队,从数据结构的根上就不存在。还有链的 next 是私有的,只有链表类自己能碰——任务连自己的 next 都看不见,想绕过队列私下改队?门都没有。轮子在长凳上的六案验瓷实:到达序就是出队序、插队插在头上、头中尾三处摘除,不在队里的摘除如实报假、摘下来还能重新入队,尾指针的指向在连环摘头之后依旧不偏。到了锁家,它就是等待队列的标准件。

本节的正主这就登场,睡觉的两把锁。头一把的互斥锁叫 Mutex,它护的是长活:进去的人可能待很久,等的人不该转圈。拿锁的身子咱们看:

```cpp
void Mutex::lock() {
    Task* const kSelf = Scheduler::self().current();
    {
        const SpinGuard kGuard(spin_);
        if (owner_ == nullptr) {
            owner_ = kSelf;
            return;
        }
        waiters_.push_back(*kSelf);
    }
    Scheduler::self().block_current();
}
```

您看出它的双层结构:里层一把自旋锁,只护两样家当——现在的主人是谁、等待队列长什么样。外层才是真正的竞争。锁空着的时候,当场改了名易了主,三两步就完事了。锁有了主,咱们干的事只有一件:在自旋锁的护短下把自己挂上等待队列,然后放掉了自旋锁,踏踏实实地睡觉。注意这个次序的精细:挂队完成之后才放手里的自旋锁,睡觉发生在自旋锁的外面——持自旋锁入睡的红线,这里是一步也不越的。而睡觉前的最后一步,调度器还会再查一道登记簿的深度,谁带着门闩上了床,当场就叫破了。

咱们看放锁的那一边,这是这把锁最有戏的地方:

```cpp
void Mutex::unlock() {
    const SpinGuard kGuard(spin_);
    cinux::base::safety::Check(owner_ == Scheduler::self().current(),
                               "mutex released by a non-owner");
    Task* const kNext = waiters_.pop_head();
    if (kNext != nullptr) {
        owner_ = kNext;
        Scheduler::self().unblock(*kNext);
        return;
    }
    owner_ = nullptr;
}
```

有人排队的话,锁是不放空的——直接把队头改成本锁的新主人,然后叫醒了他。这一手叫唤醒即转移:被叫醒的人睁开眼,锁已经划到了自己名下,重新排队、重新抢的功夫全省了。为什么这么设计?咱们看反例:unlock 把锁放空、叫醒队头,队头醒来还得再走一遍拿锁的路。可从恢复执行到真正拿到锁的这一段里,任何新来的任务都可以插进来抢走。睡了一觉醒来发现还得再睡,运气差的话睡到天荒地老——饿死,行话这么叫。这么一手直接移交,到达的次序从此长在队里,FIFO 的公平成了结构的一部分。没人排队的话,锁就放空了,天下也就太平了。同一案里您还看到那声 Check:不是主人不许放锁,放别人锁的手,十有八九是写错了作用域,当场就叫出来了。

第二把是名叫 Semaphore 的信号量。它护的不是一段代码,是一堆货:一串可以数的东西——缓冲槽、事件、配额。wait 是取货:有存货的话,咱们把计数减一,把货拿到了手。没存货的话,咱们就挂上队去睡觉。post 的意思是到货:

```cpp
void Semaphore::post() {
    const SpinGuard kGuard(spin_);
    Task* const     kNext = waiters_.pop_head();
    if (kNext != nullptr) {
        Scheduler::self().unblock(*kNext);
        return;
    }
    count_++;
}
```

有等人的人,这件货是不进仓的——而计数不加,直接越过柜台交到队头的手里,这就是一次单位的直达。没人等的话,咱们把计数加一,存进仓里的货留给下一位。跟互斥锁的移交同一个心思:叫醒的人保证手里有货,不会再空欢喜地转一圈。上一节的伏笔在这里合拢:信号量的默认构造全零起步,计数归了零、队也空了,正是仓里没货、来人请排队的合法态,零构造的家规在这一件上不是将就,而是语义本身。

三件套齐了,最后的一件大事是把护甲穿上。抢占的总开关此前一直关着,关的理由讲时钟的时候说过——堆和名册还是不设防的。现在守卫是现成的,咱们给堆和名册的每一个入口,都穿上了 IrqGuard。为什么它们配的是关中断而不是锁:这些路径短而深,堆的空闲链一拆一合就几条指令,可调用链上的任何一层都可能赶上抢占或中断。关中断这么一穿,拆到一半的链谁也看不见,这是守卫里最重的一件,重兵器配的只是短仗。护甲上了身,抢占自此就常开了——也正是从这一刻起,演示代码里再没有关了抢占再开的仪式,时钟的轮换是常态,不想被换走的,自己拿了守卫说话。
