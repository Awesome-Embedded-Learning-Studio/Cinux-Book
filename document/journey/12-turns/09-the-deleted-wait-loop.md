# 被删掉的等待循环

本节咱们离开主线一步,办一桩小小的案中案。它没排进本卷的计划,是写作中途自己找上门的,而它教的东西,比原计划里任何一节都更贴近并发的本质,所以咱们给它整节的篇幅。案由说起来很小:内核里的十个单例类,每一个都手写着同样的五行 self(),咱们想把它们收进 base 一件 Singleton 模板,继承一下就完事了。咱们把它当纯重构来办:不改一行逻辑,host 那头全数通过了,机器上的测试却坏了:中断链异常,好几台测试内核一启动就退出了。代码什么都没改,只是搬了个家,病从哪儿来?

咱们把当年的误诊如实摆出来,因为误诊本身的教学价值比真因还大。头一个误诊:咱们看着符号表断言三个单例的实例地址互相重叠,以为是链接器把对象折到了一处。被证伪得很干脆:两个地址起点紧挨着、而其中一个类压根没有数据成员,间距其实是完全正常的。而比较两个对象是否重叠,必须拿各自的起点加尺寸算区间,咱们拿两个起点直接比,比法就是错的。又一个误诊:咱们看模拟日志,发现 IRQ0 只被注入了一次,断定是中断应答丢了、时钟停摆。因果整个是反的:循环被删之后测试迅速失败退出,机器只活了一小会儿,日志里当然只有一次注入。一次注入是死亡的结果,而不是死因。还有一个误诊最值得记:咱们在 gdb 里单步走完了整个中断处理,iretq 是正常的,咱们看着时序也毫无问题——可单步模式和自由运行,根本是两个不同的世界,单步的时候调试器默认替咱们关着中断、掐着时钟,这样的单步走得通,证明不了自由运行时的任何事。取证的手艺不过关,下得越自信的判断越危险,三条咱们原样记进册子。

真因是什么?咱们把等待循环的代码请出来看。机内测试里有这样的段落:记下当前拍数,原地循环,等拍数涨过目标再往下走(会听那一卷 tick 台的下界断言,用的就是这个形状)。循环一圈一圈地转,每一圈都要读一次名叫 ticks_ 的普通整数。关键来了:手写 self() 住在独立的编译单元里,等待循环调用它是一次跨单元的外部调用,所以编译器看不穿,只好每一圈老老实实地重新读。而收进 base 模板之后,self() 是头文件里的内联,调用没了,编译器眼前只剩下一个铁的事实:这个循环里,一行写 ticks_ 的代码都没有。一个没人写的变量,循环里读一万次也都是同一个值——按 C++ 的标准,这样的循环整个儿是可以删除的死代码。于是等待循环就这么消失了,测试瞬间就失败了。咱们再把它翻译成通用的话:ticks_ 确实有人写。写它的就是中断服务程序,每个时钟中断的当口写一次。可偏偏这件事,内存与编译器的约定里没有中断的位置:编译器看得见的写,只有这个翻译单元里、这个执行流里的写。中断会异步地修改内存,这件事咱们从来没表达给编译器。旧代码能跑的底气,靠的是外部调用碰巧挡在编译器和循环中间。挡得住靠的纯属运气,内联这么一开,运气就用完了。

您要是读过内存当家那一卷“消失的那通 call”,会发现这是同一位主角的续集。那一次删的东西,是结果没人看的写——new 出来的东西没逃出编译单元,分配连同读写一起蒸发了。这一次删的,是没人写的读——等待循环等的变量在本单元里没有作者,等待连同循环一起蒸发了。这么一对镜像,透出的是同一条原理:编译器的世界里只有它看得见的因果,看不见的那些,一律不在它的世界里。

修法在原理里已经写好了:把有人异步写这件事,明明白白地表达给编译器。表达的语言是原子。您要是记得上一卷那句“volatile 的读写算可观测”,这里多半要问:volatile 不行吗?答案是不行。volatile 管的是每次都真读,读改写的不可分它管不了,跨执行流的次序它也管不了,而数拍子要的恰是这两样。裸的 asm volatile 带上 memory clobber 也能挡这一回,不过计数这件事,语义统一走原子的路子才算正。咱们把计数改成 std::atomic:自增走 fetch_add,读走的是 load,再拿 is_always_lock_free 的静态断言,把这套原子在咱们机器上真的不靠锁这句话,在编译期白纸黑字地断下来。原子这个词您第一次正经用上,咱们给它配一句白话:一次原子读或写是不可分割的,编译器和硬件都不许把它缓存、合并、重排到别的线程看不见——换句话说,它就是跨执行流共享变量的语言。顺序上咱们选的是 relaxed,最松的一档:只保证这一次操作本身的原子性,不额外承诺它前后的读写次序。单纯数拍子的活,够用了,往后的锁家族里您会见到它的两个严亲戚。第二件是一并落下的家规:单例的静态实例写成了 static constinit,而 constinit 拒绝任何动态初始化,哪个类敢带个要跑代码的构造,编译期当场就红了脸,而咱们零构造的世界里,这一红就是替咱们把住了门。

案子结了,顺手还清了一笔旁债:内核入口那几行在 C++ 函数里改 rsp 的汇编,一直违反着编译器对内联汇编前后栈指针一致的约定——所以这一次,咱们把入口整个搬进了独立的 entry.S,汇编里设好了栈再 call 进 C++,约定就两清了。这桩案子的收尾,咱们想留一句话在案卷上:跨执行流共享的变量,咱们必须用原子或屏障来表达,这是一条实打实的底线。改了不该出事的代码却出了事,别急着怪到机器的头上,去看看编译器看见了什么、又假装没看见什么。回到主线——切换有了,抢占有了,旗的来路清了,可抢占常开还差最后一道工序:共享的数据结构,看门的活得有人来干。下一节咱们请出门闩。
