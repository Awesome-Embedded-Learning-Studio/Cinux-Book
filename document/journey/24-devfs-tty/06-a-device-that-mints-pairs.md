# 一开就铸一对的设备

伪终端解决的是咱们面前的一个尴尬:程序想要的,是一台归自己使唤的终端,可真的只有一台,偏偏还长在键盘与屏幕上,咱们挪它也挪不走,第二台是分不出来的。咱们的办法是铸一对,中间不接任何的硬件。主机这头叫的是 master,握在程序的手里,读写走的都是普通文件的路。从机那头叫的是 slave,咱们把它造得跟真终端一模一样,行规程、开关、问话门样样都是齐全的,跑在它身上的程序察觉不出任何的差别。中间接的是两截环:master 写的字节进一截 raw 环,slave 的纪律从这截环上取键,纪律的回显与程序的输出汇进另一截回读环,master 收的也是这截环上的话。

从机的本体咱们一件新的都不用造:一台真的 Tty 实例,接线的四座全指着自家这一对环。取的键是从 raw 环里弹出来的,回显推进的是回读环,这就是拆单例那一篇埋的伏笔。配上主从两截环的预算,raw 环给的是二百五十六字节,回读环给的是四千零九十六字节,整对咱们收成了一个纯逻辑类,宿主上直测了六案:键盘跨对进从机成行,纪律的回显流回主机,从机自己的输出只到主机不到自己,ECHO 落下的时候只剩静默,ICANON 落下的时候裸字节直通,外加清对复位的一案。

设备这头怎么挂进 devfs,是这一篇真正的新词。/dev/ptmx 这个名字底下的设备,open 的语义与众不同:寻常的 open 把表里的节点原样交回给您,开 ptmx 却是另一回事:它当场铸出一对全新的伪终端,把主机那头递到您手里,座次号您拿 ioctl 一问便知。咱们给设备表立了两个钩子。

头一个管的是开:open 的时间点上,表里的每个节点都过一道换座的手续,寻常的节点原样通过,ptmx 这个名字换回来的是新铸对的主机节点。钩子装在设备表的脸面上,签名咱们原样抄来:

```cpp
    void set_open_adopter(base::Result<FsNode> (*adopt)(FsNode node, std::string_view path));
```

吃的是一根函数指针:open 把手里的节点连同它的名字递进去,钩子交回来的还是一个 FsNode,可交回来的允许不是递进去的那个,换座换的就是这一进一出。咱们拿 ptmx 那一问来看:递进去的是表里静态的那一行,交回来的是新铸对的主机节点。寻常的设备把节点原样递了回去,办的是同一道手续,对谁都是不偏不倚的。

另一个管的是名字:表里的名字是写死的,可 /dev/pts/0 这样的座次名字,要等对子铸了出来才知道,咱们给表装了一台动态解析器:

```cpp
    void set_dynamic_lookup(base::Result<FsNode> (*resolve)(std::string_view path));
```

解析器的脸更瘦,收的只是一条路径,答的是整个节点。查表的手续走在前头,查不到的路径才落到它手里:pts 带着座次号在这里解出活的从机,/dev/tty 这个名字解出的是您自会话的控制终端,它的戏份后面作业控制的篇里再细说。

当年工程线上的旧实现,用的也是一对钩子,咱们这一次是照着语义重新落的地,算不上头一回的发明。

钩子要通到系统调用的层,咱们就得给后端接口添脸。咱们给后端接口添了三钩子:readable 问一句读者现在能否有进展,ioctl 把问话递给设备的脸,adopt_open 接住 open 时的换座。新脸的第一站是后端接口的约束清单,想穿这件外衣的后端得把三问全答出来:

```cpp
    { backend.readable(node) } -> std::same_as<bool>;
    { backend.ioctl(node, word, argument) } -> std::same_as<long long>;
    { backend.adopt_open(node, name) } -> std::same_as<base::Result<FsNode>>;
```

过了这道检查,咱们让擦脸的机械把三张脸各铸成一根函数指针,挂进后端擦掉脸面的表:

```cpp
    /// Whether a reader would make progress on this node right now.
    bool (*readable)(void* self, FsNode node);
    /// One device question, answered with zero or a negative errno.
    long long (*ioctl)(void* self, FsNode node, unsigned long long word,
                       unsigned long long argument);
    /// Replaces a node at open time, for backends whose open seats a fresh device.
    base::Result<FsNode> (*adopt_open)(void* self, FsNode node, std::string_view path);
```

三行注释顶了三句语义的活,承重的一格是 adopt_open:它与设备表的换座钩子是同一桩事的两岸,open 在文件世界的门口交出节点,devfs 在它自己的一侧换好了座,系统调用这一层拿到换完的节点接着走。接口是机械扩展的,ramfs 与 ext2 各补了三行默认,咱们让管道的三个钩子空着,系统调用这一层从此就不用再写一个特判了,设备的就绪、问话、开新对,全走的是后端自己的脸。系统这一层拆干净了之后,fd 三号以上打开的 console 也能答 isatty 了,设备的问话从此不问出身,问的是节点自己的脸,这就是拆单例那一篇立下的分派。

设备号咱们照 Linux 编,把两个新词说定了才好往下念。身份字说的是整台的设备号,也就是 stat 答出来的那一整个数:大号挑的是主从,主机给的是一百二十八,从机给的是一百三十六,小号坐的是对子的序号,开出来的是第几对,答的就是几。所以 ptmx 自己的身份是五比二,第二对的从机答出来的就是一百三十六比一。

这里头送出去的复核又逮住咱们一处手误。头一版的小号不是这么算的,它是从节点编码用的座位字里折出来的。那个座位字装的是节点的内部座位:对子序乘二,腾出的末一位记主从。折算的时候,小号从它的身上挤,记主从的末位又写反了,咱们拿 stat 一问,主机答的却是一百三十六。改成了按实情算:身份字里的小号就是对子序号,主从的事只归大号管,同一个对子的主从,答出来的号只差大号给的那一段,与 Linux 的编号对上了。

座位的生命周期,咱们交一笔当卷更正,教训是不小的。头一版咱们让主机末座关闭时还座:对子清空复位,座位空了出来留给下一对用,防悬的手续看起来齐全。送出去的复核拿一个专门造的复现案一试:开第一对,关它的主机,又开了第二对,拿第一对还活着的从机写字,第二对的主机收到了。旧从机的字写进了新主机的环里,座位复用把两个时代的对子缝在了一起。修法是彻底不回收:座位只铸新的,八个座铸满了之后,第九次开 ptmx 老老实实答的就是内存不足,对子的完整生命周期,谁还活着、从机要不要挂断、控制终端怎么解绑,登记在后面的活里。回收的事与其猜着办,咱们不如诚实地说满了。

同一轮送出去的复核还给咱们捎出一件复用的残留病:从机重新接线的时候,头一版只清了字节,半行、挂着的信号、旧开关,全留给了下一任。定向的复现案来得很干脆:前一个会话攒的半行,后一个会话一开口就收到了。修法是接线这一步做一遍全量的重置:半行清掉,挂起的信号归零,termios 重建回出生的三位,窗口也清了,咱们一分旧状态都不许它过夜。

实弹咱们请 busybox 出场,请的还是 1.38 的版本,当年工程线上使的是 1.36,版本上的差异咱们注在这里,机制是一件不差的。它自带一个叫 script 的命令,开的正是一对伪终端,把一个交互 shell 跑在了从机上,自己在主机这头当的是转播。头一轮全链咱们逐门念:它开 /dev/ptmx 铸出对子,问过了座次号,那一问的词名是 TIOCGPTN,解从机锁的那一问走的是 TIOCSPTLCK,咱们答一个零就算解锁,随后它才开下了 /dev/pts/0,这一串手续一件不缺地走通了,孩子却在搬家的那一步死了。翻的车出在 fd 头三号的三张特权假座上,跟伪终端倒是没关系,翻出来的价值不小,咱们单独给它一篇,修完了座位再回来重跑。

重跑的孩子在从机上活了起来,跑的是第二个 ash。咱们从键盘喂一句 echo pty-works,串口上看见的字,来自三个不同的终端实例:控制台的行编辑回显了一遍,从机的行规程又回显一遍,命令的输出从从机写进回读环,由 script 转回控制台的是第三份。三层回显咱们看下来一层不混,三个实例各司各的职,这就是拆单例换来的画面。有个小字咱们不遮丑:这时从机上的 ash 还报着 can't access tty,控制终端与前台组咱们都还没立,它降了级也要活,整台戏的锣,后面作业控制的篇里敲。
