# 线上三十六字节

开关面的三个位,管着行纪律的行为:ECHO 管的是回显,ICANON 管的是行编辑,ISIG 管的是信号字符。咱们把出生的开关定为三位全开,终端生下来就是最讲章法的形态,谁要裸的,自己来关掉就是了。ioctl 的问话门这一篇开大了:TCGETS 管读,TCSETS、TCSETSW、TCSETSF 管的是写,写的三问共用一份记录,分的是生效的时机:裸的 TCSETS 当场就换,W 那一问等输出排空了再换,F 那一问连攒着的输入也冲了再换。四问全落地,读的那一问顺手修了一笔旧欠,上一卷它只验了指针非空,如今读写两侧过的都是整段的区间检查。窗口那一问也改了形:窗口的形状归了实例,控制台的终端答的是文字屏幕的真行列。

两位开关的行为咱们做全了。ECHO 落下的时候,纪律取了键不再送回显,静默地攒行。ICANON 落下的时候,行编辑整个停了摆,字节来了直通进池不等行,回车也不当成换稿的信号。ISIG 咱们存位不动作:信号字符的翻译与投递是作业控制那一篇的正菜,开关住进记录里的只有位,行为是后到的,这句分界咱们说在前面。

然后是这一篇真正的案子:记录在线上到底几字节。量错的经过讲在前,量对的层讲在后。上一卷答 TCGETS 的时候,给的是三十六字节全零,当时咱们谁也没验过尺寸。这一卷咱们立开关,决定走真 ABI 的路,拿宿主上的两套 C 库各探了一发 sizeof,两套答的都是六十,咱们就照六十写了。写完了当晚自查,才发现教学演示程序的缓冲只有三十六字节,内核一次写了六十,把缓冲后面的二十四字节邻栈也写了,没炸靠的是运气,演示的缓冲跟着改到了六十。到这里为止的故事,看着是圆的。

圆的是假象,层量错了。六十是 C 库那一层的结构,里头装的是四个开关字、一个行字节、三十二格控制字符,外加两个波特率的字段,这几样咱们真加一遍,得的是五十七,报出的 sizeof 却是六十,差的三格是结构体按四字节对齐凑整、垫在尾巴上的对齐垫,库量的数把它也一并算了。可 TCGETS 与 TCSETS 走的是系统调用的线,线上带的从来是内核那一层的形状:四个开关字、一个行字节、十九格控制字符,咱们一数合共三十六字节,这一层数字是加得齐的,您一格垫也找不出来。库在它自家的 tcgetattr 与 tcsetattr 里做两层的转换,库大的是库,线小的是线,各是各的。咱们把案卷又送了出去,请外面的眼睛复核,到了这一层才量对:写六十,越界的正是调用方记录后面的二十四字节,与演示程序里炸出来的现场对上了。上一卷那版答的三十六,尺寸恰好是对的,属于没炸错的口径,算不得量对的结果,两回事咱们分清。修复连断言一起改了:static_assert 改锁的是线格式,三十六字节加 lflag 的座位,库结构的 sizeof 从此不再作依据。

这一案咱们单独记下,因为它是有家谱的。stat 的一百四十四字节案,咱们在上一卷交过学费,立的家训是跨边界结构的教学简化是隐性的双胞胎旧病。这一回病又来了一遍,穿的新衣是量层:跨边界的记录,量的必须是线上那一层,库那一层再标准也是别人的。同一处栽了两回是蠢,栽到第三回就是没立章程了,咱们把这句写进名册。

开关立好了,咱们写一个真用它的演示程序,起的名字叫 ttydemo。它的戏码是一段秘密问答:头一步拿 TCGETS 读现行的开关,然后把 ECHO 也关了,提示您敲一行密码,纪律静默地攒行,屏上连一个字的影子都没有,读完了整行,把开关原样恢复了,交零退了场。它是与 hello 同款的裸程序:不经任何库,ioctl 的号与三十六字节的记录全是它自己摆的。号与布局咱们照老章程报全:问读的 TCGETS 坐的是 0x5401,写开关的三问从 0x5402 起排,开关字 lflag 坐在记录的第 12 字节,ECHO 的位值是 0x8。咱们把关回显的那几行原样抄来:

```cpp
    unsigned char quiet[kRecordBytes] = {};
    for (unsigned long index = 0; index < kRecordBytes; ++index) {
        quiet[index] = record[index];
    }
    put_word_at(quiet, kLflagAt, word_at(quiet, kLflagAt) & ~kEchoBit);
```

咱们跑了机器,敲进去了一行秘密,而屏上果然一字不出,读到的行一字不少,开关恢复之后回显照旧了。开关面立住了,可这枚演示的头一枪没有这么顺:它开机一声异常死在了入口,病根在八个别处丢掉的旧字节上,丢了又找回来的八字节那一篇,收的就是它。
