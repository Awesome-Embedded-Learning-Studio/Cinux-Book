# 头一件活:两位老师傅上工

两位老师傅上工的头一天,活是咱们替他们挑的:hello,最朴素的一只。生态那一卷领进门的第一位 glibc 客人也叫 hello,不过那回端上桌的,是在咱们开发它的电脑上编好的现成身子。这回给老师傅的是生料,一段同样在电脑上按 -fno-pie 预编好的 hello.s,和 hello.c 一起躺在盘上备好了。班子里干编译本体的匠人 cc1 还没进门,头一件活是轮不到他的,咱们从汇编起手,把 .o 汇了出来,链成能跑的身子,两位老师傅一人一场地接着来,手艺各自过了一遍。

活分的是三步:as 把 /hello.s 汇成了 /hello.o,ld 把 /hello.o 连成了 /hello,咱们再跑它一遍。三步连成了串,咱们叫它手链。麻烦出在 ld 那一步的命令行上。链接一环要的东西多,crt 家族那几件祖传的家什、咱们刚汇出的 /hello.o、要找的库,一样一样地排上去,排成的是长长一列。可串口的那行缓冲,约百个字符就到了顶,再往后敲的话,后半截就直接给丢了,老师傅收到的会是句残话。办法是响应文件:链接要的参数一行一件,写进盘上的 /hello.ldargs,ld 见了 @ 打头的名目,就去文件里把参数一条一条地读出来。于是串口上敲的主干是三行,每行末尾其实还缀着一句报退出码的记号,咱们省去不抄:

```
/ # as /hello.s -o /hello.o
/ # ld @/hello.ldargs
/ # /hello
Hello from GCC!
```

Hello from GCC! 的这一声,咱们听着盘上头一只在屋里链出来的程序开了口。

烙进 /hello 的门牌,咱们看着眼熟,就是 /lib64/ld-linux-x86-64.so.2 的老门牌。生态那一卷给第一位 glibc 客人烙的,正是同一条 /lib64 的路。ld 把它写进产物的 PT_INTERP,开机装载照的是精确路径去请解释器,路径是一个字都差不得的。请师傅进门那一章立下的话,在咱们链出的产物上原样适用。

老师傅交活的时候,门上跟着开了一座新号位,这座是实测当场点出来的。as 写的是 /hello.o,ld 写的是 /hello,肚子里使的都是 BFD,全名写的是 Binary File Descriptor,GNU 家管二进制格式的那套老库。BFD 写文件的路数有来有回:写 .o 的时候,段头常常是回头补的,数据落了盘,游标搬了回去,把段头里的地址与尺寸填实。搬游标的号位是 8 号 lseek,咱们门上原来没有这一座。开工前的单子上写着,盘烤好了就不动内核。冒烟的头一轮,这句就被划掉了。师傅的活要点什么,门里当场就缺什么,实测说了算。

游标的旧话,门里原本是有底的。生态那一卷 pread64 那道小题立过分寸:游标住在打开的描述里,定位读拿参数当地址,读完了游标一动不动,读了不算走过。真把游标搬来搬去的号位,lseek 是头一个这样的号位。搬法照内核 ABI 定的三个锚:0 号锚在文件头,1 号锚在当前的游标,2 号锚在文件的末尾。前两个锚门里是自己答得出的,2 号锚的答案在文件总长,就得问后端的家底。三锚落在了 anchor 一个字上,您顺着这段看:

```cpp
    auto* const kFile  = kSlot.value().get();
    long long   anchor = 0;
    if (frame.rdx == kSeekCur) {
        anchor = static_cast<long long>(kFile->offset);
    } else if (frame.rdx == kSeekEnd) {
        if (kFile->ops->stat == nullptr) {
            return -kEspipe;
        }
        fs::FsStat probed{};
        if (!kFile->ops->stat(kFile->backend, kFile->node, probed).ok()) {
            return -kEio;
        }
        anchor = static_cast<long long>(probed.size);
    }
```

anchor 起手的那个零,咱们认得,认的就是 0 号锚,咱们谁也不用问。1 号锚取的是自家描述里那枚游标。2 号锚进门就查后端的 stat 面,查不到的话,当场回了 ESPIPE。锚定了,落点就是锚加偏移的和。加出来的数是负数,游标要退到文件头之前的时候,EINVAL 就把人拒了。锚码出了 0 到 2 的范围,同样回的是 EINVAL。描述符不在桌上的时候,答的是 EBADF。搬的正是打开描述里那枚游标,往后的定位读、普通读,看的都是同一枚。答不出的只有一种情形,对一股流问总长的事,问题本身就不成立了。errno 词表里跟着添的新词,排的是 29 号:

```cpp
inline constexpr int kEspipe          = 29;   ///< The open is a stream; it has no cursor to move.
```

注释替咱们把话说尽了:这次打开是股流,没有游标给咱们搬。

手链跑起来的时候,门上的 unserved 探针跟着上了工。那枚探针是跑别人的程序那一卷立的,空号被敲了,案上就记了一笔。这一回记下的头一笔是 98 号 getrusage,客人叫了,门里是没人应的。号位被叫到门上的事,咱们叫它问询。叫了没人应,连一句办不办的话都不说,咱们叫它装聋。装聋没碍到什么事,glibc 不怎么较真,活是照干的,路是没被挡的。跟着记下的还有 273 与 334 两个号位,一样地被叫了,怎么叫都没人应,计较的也一个没有。三笔都记在了案,咱们不在这儿销,后头摆问询单的那一章,getrusage 转成明说的不办,门里显式回的是一句 ENOSYS,有人应了,应的是不办,客人拿这句回话自己找自己的退路。装聋与明说在验收里是两码子的事,咱们留到那一章再算。

交活验收的时候,咱们报三面。冒烟的一面,两位老师傅是在座的,/hello 是链得出、跑得起的,Hello from GCC! 的那一声报得干脆。全量的老验收一面,排开的是四条线,普通构建、地址加泄漏的排查、线程竞争、内核检查构建的四条线,条条都过了。回归的一面,生态那一卷的全套实弹照跑一遍,过了。ET_EXEC 老路上的客人,一位受惊的都没有。这一章门里添的是号位,没动老客人的路。

当年的第一遍,同样的头一件活,笔者交得远没有这么体面:ld 一上手就崩,崩的是段错误。破案用的法子是分层。崩在了哪儿,就只查哪儿的那一层,把这一层的嫌疑一项项排干净,修掉了再跑。要是还崩的话,说明底下压着的还有另一层,咱们等它自己冒头接着剥。四层 bug 就是这么剥出来的,修掉了一层,露出的还有一层,层层见了底,没有一层是一眼望穿的。这门手艺您记走,崩了哪儿就查哪儿,修完了再跑,让下一层自己站出来见咱们。

两位老师傅的头一件活,交了。盘上头一只在屋里链出来的程序,咱们看着它跑了起来。可有一件事跟着摆上了桌。hello.s 的生料是按 -fno-pie 备的,链出来的是老形态的身子,主程序的座照老样子收下了它。等班子在盘上凑齐了,师傅亲手编出来的东西,默认摆的都是 PIE 的形态,位置无关的身子——主程序的座,是还不认的。
