# 师傅怎么开工:spawn 与保留旧世界

问询单上的一号,咱们答的明明是不办,师傅倒是每轮开工都要敲它,敲完了也不恼,转过头把活干完了。咱们说的那个号是 clone3。咱们请进门的是 GCC 16,它的领班每开一道工序都要叫起一位匠人,预处理的、编译的、汇编的、链接的,一位一位地叫,一道一道地开。叫人的家什统一是 posix_spawn,落到系统调用的那一层,glibc 起手探的就是 clone3,一扇 Linux 后来才另开的新门。探一声的是 glibc,听答话的是咱们。咱们答的是 ENOSYS,glibc 心里有数了:新门没开,退回来走的是老的。

所以明说不办那一栏里,clone3 坐得是理直气壮的。glibc 的路数两头都写明了:clone3 答 ENOSYS,就退到 clone 的老路上去。咱们这一头要是装聋,让这个号没人应答的话,答案倒是 ENOSYS,整轮的验收却要按 unserved 记败。有人应答的,答的是不办,暗号才算立住了。回退的路,两边是提前约好的,谁也不欠谁的。

退回来的 clone 递上两面旗。头一面是共世界的旗,旗号写的是 CLONE_VM,线程那一卷的清单上它排头一个:孩子的地址空间直接指父亲的,爷俩跑的是同一个世界。另一面是 vfork 的旗,线程那一卷立清单的时候,它是没被写进去的。清单之外的旗,咱们整个拒掉,答的是 EINVAL,半份的忙不帮。照旧章程办的话,glibc 这一手就要当场吃闭门羹了。

两面旗都是得收的,收 vfork 还得给它真的语义。咱们把处境摆出来:孩子带着父亲整个的世界跑,栈和堆都是两家共用的家当。共世界的这段日子里,父亲凭什么敢撒手睡去?

敢的。glibc 那头的合约把另一头也写明白了:父亲睡去的日子里,孩子要办的只有两件事,exec 办成了,或者退了场,办完了其中一件父亲才醒。Linux 给 vfork 定的就是这个语义。咱们拿线程那一卷的手艺接活:fork 的全套照走,共世界的旗把孩子的世界指回父亲的,再把一件完成件挂在了孩子身上。接活的几行,您贴着看:

```cpp
    proc::Completion done;
    if ((kFlags & kCloneVfork) != 0) {
        kChild->vfork_done = &done;
    }
    proc::Scheduler::self().unblock(*kChild);
    if ((kFlags & kCloneVfork) != 0) {
        done.wait();
    }
    done.retire();
    return kPid;
```

完成件是线程那一卷传下来的老件:一次性的状态,finish 把它从等待挪进了终态,挪的只有一次,wait 是要把当前任务泊到终态为止的。咱们再看它安在哪儿:父进程这次系统调用的内核栈上,孩子身上带的是指针。父亲一进 clone 就睡在了 wait 里,孩子给放进了队列,爷俩的接力全看完成件那一声。

> 咱们没拿现成的信号量顶这个差,有讲究:多出来的一枚令牌会放跑下一个等的人。一次性的状态到了终态就封笔,多喊一声也改不了什么。

放行的那一声,两个地方都能喊。咱们看第一处,exec 的末尾:参数铺完,新的世界装好,连返回的帧都改写了,轮到它的才是末尾。

```cpp
    if (kSelf->vfork_done != nullptr) {
        auto* const kDone = kSelf->vfork_done;
        kSelf->vfork_done = nullptr;
        kDone->finish(true);
    }
    return 0;
```

另一处是退场:孩子要是不 exec、直接就退出的话,收尾的代码同样把完成件喊完,父亲照样是要醒的。咱们把两个口子一合计,父进程恢复的时机就一个不差:孩子要么换好了新世界,要么已经退了场,共世界的那段日子,父亲是全程不在场的。

合约的失败路径,得一行一行地兑现。咱们故意让叫人这件事本身失败:GCC 的领班有个 -wrapper 选项,让它把每位匠人经一个中转程序的手去叫。咱们递过去一个不存在的路径 /absent,叫人的头一步就得出错。出错的那一刻,孩子的世界一草一木没动:exec 办不成就原路退回,glibc 的孩子把 errno 写回共用的内存,然后自己退了场。父亲醒来读到的就是错,gcc 报给敲命令的人,退出码交的是一。

失败的孩子也得有人收。glibc 收 spawn 的孩子用的是 waitid,摆问询单那一章的三种答法里,它站在的是真办那一栏。收据的四个格子,摆问询单的那一章咱们已经一格一格数过,信号号、来路、孩子的号、交代本身,版式照 Linux 的 siginfo 布局落,glibc 拿到的与它在 Linux 上用惯的一模一样。这一回的不同只在开收据的人,spawn 失败的孩子不 exec 别的世界,把 errno 写回共用的内存就退场,waitid 收的就是孩子退场时留下的交代。生与收那一卷立过的老话是:wait 给的是收据,退出码装的是货。wait4 的收据是一格 int 的暗码,waitid 的收据宽到一百二十八字节,一格格地写明白。

门上安静了,futex 那边又上了一课,这课是 glibc 亲手教的。libstdc++ 与 glibc 的锁,词上写的是等待,操作码递来的却是 128、129。线程那一卷立的章程还在:操作码只认 0 与 1,别的不认,答的是 ENOSYS。咱们照章办事,glibc 当场就翻了脸:它对错误码较真,认得的错才走得下去,陌生的 ENOSYS 不在册,直接就 abort 了,报的是 unexpected error code。

翻案翻得干脆:咱们把 128 与 129 摊开看,号其实还是 0 与 1,各自加了一面私有旗。旗说的事很老实:这个词只在本进程里用,等待的队列不必跨进程共用。桶表咱们全机只用一张,本来就没想到按进程分家的事,把旗摘掉了再认号,语义是一点不缺的:

```cpp
    constexpr Word kPrivate = 128;
    const Word     kOp      = frame.rsi & ~kPrivate;
```

摘旗的两行就位,两家的锁都走得通了。这一课咱们记在案上:号位上来了新面孔,得辨一辨的,它是新添的号,还是老号添了旗。

长凳上跟着添了两件。一件是真实编译轮:as、ld、gcc、g++ 的全链在串口壳里真跑一遍,纪律也一并立下了,轮里出现任何一声 unserved 的话,整轮就记败了,编译器的每一步都不许靠装聋混过去。另一件就是缺了 wrapper 的探针,咱们在自家盘上敲下去:

```text
gcc -wrapper /absent /hello.c -o /bad; echo SPAWN_FAIL_$?
```

咱们要的判据只有一行:`SPAWN_FAIL_1`。退出码交的是一,这一分是记在失败路径头上的。

开工的路通了。真到交接收活的时候,笔者下了一条改令:exec 把参数交给新程序的那一套,是要整个按正本重写的。正本是 Linux 内核源码里的 fs/exec.c。下一节咱们照着正本把交接重办一遍。
