# 重启的证明

机内的活干完了。串口报完最后两行,QEMU 关机,256 MiB 的源码卷安静地躺在宿主的盘上。卷里的 /src/out 下面,装着这一轮长出来的货:一只启动镜像,一份链接完的内核 ELF。内核本体 590656 字节,上一章念过数的那轮完整构建,交的就是这个尺寸。机器自己喊完工不算数,这一卷的章法从来如此,自报的不算,亲手核过才算。咱们把货掏出来,当面验。

机内还留了字据。咱们把构建驱动脚本末尾那几行请出来,它给自己刚写完的镜像留了一份指纹:

```python
        target.flush()
        os.fsync(target.fileno())
    digest = hashlib.sha256(image.read_bytes()).hexdigest()
    print(f"[kernel-selfhost] IMAGE_SHA256 {digest}", flush=True)
```

您留意算指纹的时机,数据真落了盘,fsync 做完,哈希才开算,取样的对象就是刚写进去的镜像本尊。给 busybox 立进料册的时候咱们就领教过它的脾气,内容变一个字节,整串十六进制就换一副面孔。机内把这串数打进串口,等于在单子上签了名,我造的货,长这个样。

宿主这边掏货,咱们用的还是生态那一卷烤盘的老家什,debugfs。那会儿它是往 ext2 镜像里一件一件写货,这回反过来,往外掏,不挂盘。掏出来的镜像整个重新过一遍哈希,验货就两行:

```python
    if hashlib.sha256(product.read_bytes()).hexdigest() != digest:
        raise RuntimeError("extracted boot image differs from guest hash")
```

宿主算出的得数,与机内记下的那串逐字核对,以 377dc9f1 打头,64 个十六进制字符一位一位全对上才算过,差一位,脚本当场报错走人。有朋友可能要嘀咕了,掏个文件出来,犯得着再算一遍哈希吗。咱们不赌这个。字节出了机器的门,要过 debugfs,要过宿主的文件系统,一路上谁都不许悄悄动一个字节,这一遍哈希,验的就是路上清白不清白。

哈希只证货没被换。还有一层疑心,咱们得单独排:凭什么信内核真是机内从头编的,而不是宿主提前塞了半成品进去?立目标那一章划输入清单的时候,边界已经摆在明处,宿主给的只有配置,命令,工具链,Python,引导器,这一轮没有重新编译 GCC 与引导器。剩下的清白,源码卷自己作证。卷里的源码与当前的源码树逐文件对哈希,一份一份全对上。带进卷里的内核对象,数了数,是 0。装料脚本,scripts/prepare-kernel-selfhost.py,在宿主上把命令清单装进卷,出工的时候自己报过行:

```python
    print(f"[kernel-selfhost] exported {len(commands)} source compilations + kallsyms; no kernel objects")
```

带进卷的只有源码与编译命令,现成的 .o 一个没有。镜像里那两段引导器倒是宿主构建的正身,随卷带入,清单上写得明白,咱们不冒领。整只内核,从一次次编译,kallsyms,两轮链接,到镜像封装,全是机内长出来的。

货验明白了,该上最后一击了。掏出来的镜像换个身份,不当数据盘,当启动盘,再开一台全新的 QEMU,从它引导。源码卷照旧当数据盘挂在旁边,/hello.c 就住在里面。开机,串口上新内核一行行把报告吐出来,`Cinux up`,提示符拉起来。刚才那一轮里,它还只是卷里的一堆源码,现在它坐在内核的位子上,给咱们当机器。

接下来敲的,还是咱们自举的老戏码。驱动脚本喂进串口的是两条命令:

```python
        output = guest.command("gcc /hello.c -o /reborn; echo REBORN_CC_$?", "REBORN_CC")
        output += guest.command("/reborn; echo REBORN_RUN_$?", "REBORN_RUN")
        if not re.search(rb"\r?\nHello from GCC!\r?\n", output):
            raise RuntimeError("new kernel failed the compiler/runtime check")
```

咱们在自家造出来的内核里,用盘上的 GCC,把 /hello.c 编成 /reborn,再跑。判据就写在脚本里,输出里必须有 `Hello from GCC!` 这一行,两条命令的退出码都得是 0。同一轮的整份串口记录还要再筛一遍,任何一条装聋的 syscall,任何一次内核异常,都让这一轮作废。点名那一章立的零装聋口径,验师傅的时候管用,验刚出炉的新内核,一样管用。

`REBORN_RUN_0` 落下来,紧跟着,咱们等的那一行到了,`Hello from GCC!`。造出来的自己,开得了机,也干得了活了。

这一发实弹的分量,值得您停一拍细看。/reborn 是盘上 GCC 的默认产物,PIE 的身子,ET_DYN 的形态。它能在新内核里跑起来,靠的是座位认得 ET_DYN 那一章安的座位,那个座位,如今长在一只由 GCC 自己编出来的内核里。加冕那一章咱们拿 od 逐字节核过三个 PIE,验的是 STL 与异常的成色。同一具编译器,这一回交的活,是整只内核。

收官的大戏,三层,到这里合龙。头一层,串口壳里的 ./hello,咱们看着它由盘上工具链编出来、跑起来。第二层,g++ 把带 STL 与异常的 C++ 编出来,跑通。第三层就是方才这一场,机内从空对象目录长出整只内核,重启,开机,再编一只 hello。“编译自己”四个字,写到串口这一行输出上,才算落地。

咱们该把全卷的成绩单合在一起念了。收卷的活,留给下一章。
