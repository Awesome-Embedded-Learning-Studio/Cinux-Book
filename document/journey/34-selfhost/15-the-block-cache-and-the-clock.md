# 炉子通了风:块缓存与测出来的数

上一章撂下的那句慢,这一章动手还。834.685 秒,这个数是咱们守着串口一口一口等回来的,量的是基线轮里跑完的那一段,那一轮没能跑到头。可越看越不是滋味。一场编译翻来覆去读的,明明就是那几样东西,工具链的身子,头文件,目录块,哪一样第二回不该从内存里直接拿?

嫌疑落定的速度快得很,垫在 ext2 和盘队列中间的那块块缓存。您跟它是老熟人了。认字那一卷它头一回上工,八个槽,一槽一 KiB,写穿。懒到家那一卷的《缓存长到页》那一章给它动过手术,槽养到四 KiB,写懒成了脏页。可槽的数目,从立身那天起就没动过,八个,三十二 KiB。三十二 KiB 的家底,cc1 一个就四十七 MB 上下,连人家的零头都盛不下。客人前脚刚坐下,后脚就被请出去腾地方,下一回来,又得排一趟队列,发一道盘命令。整场编译上百个单元,这样的冤枉路要走多少回,咱们心里都有数。

动手之前,咱们还做了一趟只读的分析,不改一行代码,只让 QEMU 采样。这一趟跑下来,采样摆出两个数:累计的 rchar,13.6GB,真落到盘上的 read_bytes,54MB。差出来的这一大截,是同一批东西被翻来覆去地读。

这一遍咱们给它动三处,饭量,查法,逐出。头一处,饭量。开机那天文件世界起身,顺手把新家底算出来:

```cpp
    const auto kAvailable = mm::Pmm::self().free_page_count() * arch::page::kSize;
    const auto kBudget =
        base::math::Min(kAvailable / driver::kBlockCacheMemoryDivisor, driver::kBlockCacheMaxBytes);
    const auto kSlotBytes = driver::kCachePageSectors * driver::kSectorBytes;
    cache_                = new driver::BlockCache(*queue_, kBudget / kSlotBytes);
```

头一行咱们就看得懂,空闲页数乘上页大小,是当下真正空着的字节。除以三十二,再跟 64 MiB 比一比,取两者里小的那个,按一槽 4 KiB 折成槽数,交给缓存。两个定数住在 block_config.hpp 里,除数 kBlockCacheMemoryDivisor 是 32,上界 kBlockCacheMaxBytes 是 64 MiB。家底随机器长,内存大的多分,内存小的少分,顶到 64 MiB 为止。花名册开机就立好,可每一槽的数据页,等头一回真被用上,才从堆里领,册子本身那点地方,紧巴的机器也出得起。

第二处,查法。八个槽的时代咱们挨个数,数八个,无所谓。如今一开口就是上千槽,每回问页都得把全册扫一遍,这个便宜占不起了。册子改成哈希链:

```cpp
unsigned long BlockCache::find_slot(unsigned long page) const {
    for (unsigned long index = buckets_[page % bucket_count_]; index != ~0UL;
         index               = slots_[index].next_hash) {
        if (slots_[index].page == page) {
            return index;
        }
    }
    return ~0UL;
}
```

页号对桶数取余,落进哪只桶,桶里串着一条链,咱们顺着链摸下去,几步就到。桶数在构造里立好,槽数的两倍加一,桶比槽多,平均一条链上摊不到一个槽。省下来的,是每回问页的那趟全册扫描。

第三处,逐出。老办法是轮换,指针 next_ 一格一格走,停谁算谁,谁最近被摸过,一概不问。新的走法有名字,CLOCK,二次机会。针就立在这几行里,咱们跟着它转一圈:

```cpp
unsigned long BlockCache::choose_victim() {
    for (;;) {
        const unsigned long kIndex = next_;
        next_                      = (next_ + 1) % slot_total_;
        Slot& candidate            = slots_[kIndex];
        if (!candidate.live || !candidate.referenced) {
            return kIndex;
        }
        candidate.referenced = false;
    }
}
```

next_ 就是针,每看一格,往前挪一格。针停在哪格,咱们就看两样,格子里有没有字,还有最近有没有人摸过它。空槽直接征用。活槽要是 referenced 立着,针放它一马,把标记摘掉,接着走,等针转完一圈回来,这中间没人再摸它,标记是躺着的,它就轮上了。摸过的标记就是这么立的,命中那一拍,claim_slot 里就把 referenced 置了起来。于是热页总有人在摸,针底下总活得下来,冷页一圈没人理,自然让位。全局就一根针,全部的槽归它转,逐出的全部家当,一位标记,连时间戳都不用记。

失败的两条纪律,咱们一条一条守着。一条是旧话,出自《缓存长到页》,写回被拒的脏页原地保留,索引不动,槽还是脏的,等下一趟逐出或者 flush 重试。另一条管填充,盘拒绝把页读上来,填不上的槽干脆不出列,不进索引,不标活。谁也别想从它那儿拿到一个字,下一回有客上门,换一格重填。宁可让请求失败,也不拿没见过盘的字冒充数据。

长凳四面,咱们挨着面点。头一面热读,24 页的工作集,32 槽,头一遍读盘 24 次,第二遍原样再走,盘命令一次没发。第二面碰撞,3 槽的小缓存,页号 0、7、14,桶数 7,三页取余全落同一条链,链没乱,而且 7 号页后来又被人摸过一回,再问它,盘纹丝不动。第三面淘汰,就是同一案的后半段,0 号页一圈没人理,被请了出去,再问它,盘多读一次。二次机会保的是刚用过的页,踢的是真冷的页,一保一踢,都在这一案里。第四面 I/O 失败,让盘拒收写,脏页原地留脏,字照样答得出,盘缓过来,flush 补上,让盘拒收读,填不上的页不发布,恢复之后重填,字节一个都没有少。机内另有一桩,一个槽,三个读者,各拿各的副本,填页睡在半路也不串字。

三处改完,量的章程得立明白。条件是同一套,Debug 构建,-g 加 -O2,内存 512 MiB,2 vCPU,构建树与 QEMU 都串行。口径也只有一副,数的是编译命令的墙钟,命令敲下去,到它收工为止,装载,编译,链接,全算在内,不单拎哪一段。这一卷里凡是秒数,说的都是这副口径,装载的耗时是另一副尺子,咱们从不混着量。

缓存上机,头一轮全量,187 个常规编译单元全过。两轮对出来的数,咱们原样记下。两边共同完成的编译单元,138 个,墙钟从 834.685 秒降到 281.288 秒,快 2.967 倍,少 66.3%。

有一句边界必须原样带上。旧基线没能跑完全场,第 139 个编译单元上,目录满了,停在那儿。所以整场构建的耗时,咱们不拿来同比,快的数只对那 138 个作数,替整场发言的话,一个字不说。您要是想把 281.288 秒跟 834.685 秒摆在一起看,可以,只是边界那句得一直跟着。

全过的是编译,链接那一环又响了一声。真实的链接器一开工,一口气开门的件数,坐满了文件表的六十四座,报错交上来,这一卷最后一件大的修复,就让这一声亲手逼了出来:文件表换骨架。这表从无盘起家那一卷立册起就是定长的,六十四这个数,还是这一卷前面迎 C++ 家当上桌的那一章放宽出来的。咱们给它换了骨架:

```cpp
constexpr unsigned long kChunkSlots = sizeof(base::bit::WordMask) * 8;

struct FileTable::Chunk {
    Chunk() { cloexec.init(&word, kChunkSlots); }
    base::container::SlotTable<base::Shared<OpenFile>, kChunkSlots> slots;
    base::bit::WordMask                                             word;
    base::bit::Bitmap                                               cloexec;
};
```

每块按一个位图字的宽度装座,用到哪块长哪块。逻辑上界学的是 Linux 默认的 nr_open,一百零四万八千五百七十六,可存储按需生长,没人开门,一块都不多占。用户态来领号,守的是它自己的 RLIMIT_NOFILE,超了答 EMFILE。表住在堆上,内核栈上不摆按上界大小的临时数组。长凳上咱们再点一遍,动态生长碰上降限额,高座的旧客照旧活着。稀疏的高座跨 clone 与 close-on-exec 各管各。后端释放走锁外,重进表也不打架。

表换好,咱们看着全量从头跑到尾。188 次编译,把生成 kallsyms 的那一次也算在内,两轮链接,封出 590656 字节的内核,369.811 秒。

炉子通了风,这一轮却止步在量得出收益的改动上。还有五件,咱们照实记在案,一件没做,一件也不冒领。几个进程读同一个文件,内存里各存各的页,共享的一份没有立。目录项与 inode 的缓存没有立。一次搬一大段的 read/write 没有。vfork 的路没另铺。构建还是串行。五件各归各,留作后续独立测量,它们任何一件的快慢,这一轮的数都代言不了。当年那一遍在同一段路上还动过 ext2 读的聚合,一笔盘命令捎回更多字节,省了两成五,那笔旧话《缓存长到页》收尾时念过,口径是当年的,这一遍不扩那个界。

数测完了,咱们就差最后一击,让造出来的内核自己开机。
