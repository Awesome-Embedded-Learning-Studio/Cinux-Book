# 18 · 幕间:为什么重来一遍

上一卷收卷的时候,咱们说过下一卷要歇一站。这一卷就是用来歇脚的。机器没有变化:面板还是上一卷的读数,盘上的 /bin 还住着,楼上的 init 等着重拉 shell,验收和实弹的会话都在上一卷的末尾,这一卷咱们不添一行代码,也没有自己的面板可看。

咱们不添代码,其实有的是可讲的。这一卷讲的是两个故事,一头一个地过。头一个是当年的故事:第一幕收官一个月之后,五月末的一个早晨,前后只用了不到半个钟头,同一套源码分成了两家——一家接着当课本,一家撒开手去当真正的工程。推倒重来是旁人的叫法,咱们把那个早晨的三个动作、分家的清单、还有为什么不接着往下修,一节一节地摆开讲。另一个是咱们自己的故事:带着当年的案卷重走到这儿,回头看了眼,当年的旧病哪些没有再犯,哪些还是绕了,数出了一张对照单,没再犯的有五处,三处还是绕了,每一处都写清凭什么。

咱们把话说在前头:没再犯的,凭的是代码的版式和案卷,不凭什么运气。还是绕了的,也不是粗心闯的祸,有那么一类毛病,后见之明天然是够不着的,它其实不住在代码里,住的是窗口和组合,要等实弹来了才炸。这一层看明白了,往第二幕去的路,脚下是实的。

合卷的时候,咱们把第二幕的走法定下:当年的答案揣在怀里,自己的路自己挣。旧路咱们一趟一趟都在案卷里点过,躲得开的弯就躲开,躲不开的,下一幕里咱们陪它再走一遭,当场把案子破了。接下来的一卷就是第二幕,头一站咱们教机器偷懒,内存的登记册立起来,缺的页按需补,用什么,到什么。歇够了,咱们动身。
