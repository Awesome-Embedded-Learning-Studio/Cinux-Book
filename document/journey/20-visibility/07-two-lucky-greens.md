# 两个绿得侥幸的案子

这一卷的收官验收里,有两件老东西翻了案。翻出来的两件都是一直绿着的测试,它们绿了这么久,运气的成分占了大头。咱们一件一件地摆。

头一件的主角是调度类基类的析构。咱们给两个类取件的那对函数,学的是轮流当家那一卷在 sync.cpp(同步三件住的编译件)里立下的范式:函数内的 static constinit 单例,头一回调用的时候落座,进程活多久它就活多久的性子。这个范式咱们用得顺手,可它藏着一条没写在门口的前提:类型得是平凡析构的。调度类的基类,咱们起笔写的是虚析构,多态基类的教科书姿势。定义里的虚析构就不平凡,而函数局部 static 的退出是要登记的:编译器在头一回落座的时候,往运行时递了一份析构的登记,用的名字是 `__cxa_atexit` 和 `__dso_handle`。

为什么咱们一直没看见它?因为普通的构建把咱们保护得好好的。基类的析构体是空的,普通构建的编译器干脆把登记常量折叠掉了,nm 里对它们的引用是零,宿主的测试全数通过,现场被捂得严严实实的。验收四条配置里的内核检查线一上来,它的构建开着 UBSan,析构被插了桩,登记保不住了,真正的死法当场现形:内核的机内测试走两段链接,头一段是 `-nostdlib` 的裸世界,能找到它们的地方是没有的,链接当场就死了。同一份的代码,普通的构建绿着,加了检查的构建死在了链接上,这告诉咱们的是:范式的前提平时不吭声,得靠更强的灯去照。

修法把姿势换了:基类的析构改成了 protected 的非虚平凡析构。类是进程级的单例,从来不会有人经基类的指针去 delete 它,析构永远走的是具体的类,虚不虚的分别在这里没谁用得上。protected 顺手还封了一个口子:经基类指针的删除,现在根本写不出来了。sync.cpp 里同范式的另一个单例一直没事,就是管锁名册的那个,咱们回头查过它:它管的类型是平凡可析的,前提生来就是满足的。所以这一案的收尾不止改一行代码:函数内 static constinit,前提是类型的平凡析构,前提不满足的,要么类型改平凡,要么别用这个范式。

第二件的主角是浮点闸门的宿主案,懒到家那一卷立的。那件案子里藏着的一处断言,读的是物理的 XMM0:让出之前写一个值进去,切换回来了再读出来,要求读回的还是那个值。在宿主的测试世界里,咱们录决策流的那个切换是普通的函数调用,而 XMM0 在调用约定里是 caller-saved,被调的那一方对它没有任何保存的义务,想怎么用就怎么用。断言押在了它的身上,签的其实是一张运气的单子。

运气怎么走的,咱们上探针量过。让出之前的 XMM0 是对的。切回来了,读出来的是 0xf5 重复八次的那个词——ASan 栈投毒的魔数,加上拦截器的残渣,是被调方一路铺过来的。拦截器(interceptor)是 ASan 的改写手法,memcpy、memset 一类常用的库函数都被它换成了带检查的替身,被调方一路擦过的就是这些替身,而替身干活,用的也是寄存器。再跑了一遍,垃圾又换了一副,回回的样子都不一样。普通构建的代码生成恰好不碰 XMM0,所以旧案子此前五十连跑都是绿的,第一次验收过了,终态的验收却挂了,说的就是它:任何一个编译件的风吹草动,都能让运气签下的单子作废。修法把断言押的东西换了:不读物理的寄存器,读任务自己的进场图像——那是闸门按约定保管的内存,深度的计数一路保留,案名也随之改成了一句更诚实的话,`only the outer exit consumes the task's own entry image`。真实硬件上的切换路径,本来就不归宿主案管:机内的哨兵案,直写 XMM0 的魔数、真实的上下文切换,从轮流当家那一卷起就立在了岗上。改完了之后,普通线和地址排查线两个矩阵各二十连跑,失败的数目是零。

咱们把两案合起来看,收下的教训是两条。断言要押在约定保护的东西上,内存的图像、深度的计数,约定怎么写的就怎么押,caller-saved 的物理寄存器不在此列。范式藏着的前提,这次被照了个正着:平凡析构的四个字,是拿一次链接死换回来的。下一节咱们收卷。
