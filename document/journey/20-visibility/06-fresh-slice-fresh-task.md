# 接手的人,不背旧拍数

四问里最要当心的是第四问,`wants_rotate`,咱们把它单独开成了一节,因为它的语义是重推过的,不是搬来的。当年工程线的类钩子叫 task_tick,干的是在时钟中断的上下文里直接切人:滴答一响,问的是片够没够,够了当场就换。这样的路子,工程线自己后来的审查判了它的刑,判词有四条:中断里切人用的是共享的栈,覆盖的风险摆在那。切之前无条件地开了中断,递归的窗口开着。抢占的计数挂在每颗 CPU 的身上,任务一迁移就作了废。自旋锁的计数和它对不上时序。末一条说的两个计数,一个是抢占禁用的层数,一个是此刻手里还持着的自旋锁数,都记在 CPU 的身上,属于正占着 CPU 的那个人。切人要是落在计数没归零的窗口里,接手的人就带着前任留下的计数往下跑,日后解禁的抢占是别人禁的,开掉的锁也是别人上的,时序坏就坏在了这里。四条的罪状,当年的它们一条也答不上。

咱们的机器生来就是另一副骨架,这一点咱们重走的运气一直好:轮流当家那一卷立的形,心跳只管数它的拍,应答照常地做,真正的换人发生在中断的出口,iretq 之前的那一声问的就是该不该换。所以第四问在咱们这儿的正确形态只能是:类看着当前任务跑过的拍数,答一个想不想换人的是非。答案为真的时候,调用方把轮换的旗翻了起来,人还是在中断出口换的。钩子只答是非的形态,宿主的测试够得着:不开中断、不碰真的时钟,直接驱动的就是记拍和出口问询两个入口,类的意见和调度器的反应就都能逐条地对上。今天两个类对第四问答的是同一句话,拍数到了片长就说够——这句问句的价值在明天,类的片长各说各话的日子,问句已经在了。

然后是名存实亡的旧案,咱们当着您的面把它办了。当年工程线的注册表一直有人在填,可调度、退场、起跑三处调用绕开了表,直调默认的类,第二个注册的类永远没人问过一句。判词当年就写下了,咱们念一遍:接口的存在,不等于机制的生效。这一遍咱们的纪律是把每一条选人的路都拦到注册表上:主动让位、出口轮换、退场、泊车、主流程发牌,五条路走的都是按注册序问询的同一个入口。泊车说的是任务睡进了等待的队列,等的是人来叫醒,发牌说的是主流程把头一批任务交进调度器。宿主的倒序咨询案专门守着它:两个类都注册了,一个无类的任务加一个权重的任务,跑完了全程,断言访问的次序必须是无类的任务在头里。头一个类不清空的时候,第二个类就没得问了,案里的次序就是这句话的实证。

时间片的功课里还藏着一处旧数没清的错,咱们把案发的经过摆出来。拍数是调度器记的:当前任务每过一拍记一拍,类说到了片了,记拍的数归了零,轮换的旗翻起。错处不在记的身上,在交的那一拍:主动让位、退场、泊车、主流程发牌,把 CPU 交给别人的四个地方,交出去之前清拍数的活谁都没干过。咱们拿半张片的故事说:片长是两拍,这是轮流当家那一卷定下的数,任务甲跑了一拍,主动让了位,乙接手的时候,记拍的数还停在甲的那一拍上。乙再跑了一拍,数到了二,类说到了片了,乙提前挨了轮换——半张片是凭空少的,而它什么错都没有。今天的片长是两拍,亏的顶多是半张,将来类的片长各说各话了,前任亏给继任的就能放大成一整张。

咱们用一句话修:四个交出 CPU 的点,交出去之前把拍数清了零。接手的人从零起算,自己的片自己跑。宿主那边立了一案专管它,案名说的是接手的人挣得一整片的新鲜片,咱们简称 fresh slice 案:无类的甲跑到差一拍满片的时候让了位,权重的乙接手,走完了一拍,再过一次出口的问询,断言的是乙依然在 CPU 上——修之前的乙在这里被提前换下,案是红的,修之后乙稳稳地跑满,案是绿的,甲来过的恰好是两回,两回的数目也对得上。机内那头同批添了一案:同是权重类的两位,一位带着的是权重九,另一位带着的是权重一,主流程发的牌,压的是真实内核栈,走的是真实切换,访问的次序必须是带一的在头里,带九的随后。

调度类到此立完了,连转储里自称的名字都定好了,fifo 与 priority 的两份名字,宿主一案把它们按住——名字是给将来的崩溃行预备的自称,拼写打今天起就不许变了。两个验收的发现还压在后面,都是一直绿着的测试,这一卷被开着插桩检查的构建配置照了出来,咱们下一节看灯。
