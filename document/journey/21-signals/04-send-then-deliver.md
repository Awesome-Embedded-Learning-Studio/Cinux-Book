# 发送与投递,两段路

一个信号从生到死的全程,走的路是两段,咱们现在把两个名字立起来:发送占的是头一段,投递占的是第二段。发送干的是把号落在目标身上的活,投递是目标自己把事办了。为什么分两段?因为喊人的和办事的几乎永远不是同一个人:甲给乙发信号的那一刻,乙多半正在 CPU 上跑着别的活,或者压根就没排上 CPU 的份。咱们总不能让甲替乙把句柄跑了,所以甲只留记号,乙在自己的合适时机回头处理。这个合适的时机,咱们选在 syscall 的回程,上一篇那段分派代码里问的那一句,问的就是它。

咱们看任务身上添的家当。每个任务一座信号的小世界,装的是三样:一张二十二格的动作表,外加屏蔽的集合与待办的集合。全零就是合法的出厂态,句句的意思都是默认,什么都不欠。两张表的继承章程咱们也定了:fork 把动作表和屏蔽集整个抄给孩子,待办集是不抄的,孩子不背父亲没办完的事。exec 那头轮到咱们推倒重来,三样全回了出厂,新程序有新的章程。

发送的这一段路,咱们把 SendSignal 的三道关念一遍。头一关查的是号,出了合法区间的,答的是不行,这是唯一的拒绝。第二关查生死:目标已经是僵尸或者死透了,咱们答照收,但什么都不做。死人是收不到信的,发信的人却没犯错,这句实话咱们得让发信的知道。第三关查蒸发:目标的动作表里,这个号装的是蒸发的话,咱们当场丢弃,答的还是照收,连待办集的门都不进。三关都过了的,咱们把它落在待办集上,让它等自己的窗口。您留意三关的口径:除了号不合法,发送永远是成功的,信号世界的头一段路没有失败这个说法,而成败的裁判,归的是投递那一边。

投递的这一段路,咱们跟着 DeliverPendingSignals 走。它只在 syscall 的回程被叫,一进门算的是头一笔:待办集抠掉屏蔽集,剩下的才是今天能办的。能办的里面挑号最小的办,低号的在前,这是 POSIX 立下的口味,咱们照办。然后咱们按动作词分三路。蒸发路:把这个号清了,接着咱们挑下一个,耽误掉的工夫是一拍都没有的。默认路按处置表分三岔:处置是杀的,当场走的是 exit 带着号死,这一路是不回头的,死讯怎么编码,后面的篇专门讲。处置是停的,清了位之后把自己停走,那也是后面专门的一篇。处置是蒸发的,清了位接着走。表的第四值是照旧跑,十八号独一份:没停着的任务接到它,投递时清了位接着走,停走的任务,发送的那一拍就被它叫醒,停与醒的篇里细讲。定制路:咱们把帧改写到句柄门口,这是下一篇的大戏。改写要是成不了,比如用户栈浅得摆不下投递要摆的东西,咱们按杀处理,栈区间的判定下一篇细看。还有一条纪律值得咱们单独说:一句回程最多送一个定制句柄,送完了就散,ring3 认的就是这个形状,堆着送会把用户栈摆成什么样,咱们谁心里都没数。装了 RESSETHAND 旗的,送完了这一次,动作词整个回了出厂,一格一格地清零,不只是把句柄词归了零,掩码旗子也一并归了位。

这里有一句诚实的边界,咱们把它画在明处:投递的窗口只有 syscall 的回程。一个睡在等待表上的任务,比如守着 wait 的父亲,信号落在它的待办集上,可它是不回程的,信号是追不上它的,要等它自己醒了、办完了事、走回程的那一步,信号才是追得上它的。您会问,那杀一个睡死的任务怎么办?咱们今天的答案是:等它睡醒。信号打断睡眠、把等待的 syscall 直接叫醒答 EINTR,这件事咱们和当年的工程线一样没有做,它需要给等待的链路再开一个口子,咱们记在了明处,等真正需要它的日子。

宿主的长凳上,信号的套件这一批起了批,二十二案把两段路考了个全:表占了四案,发送占了两案,投递占了六案,找人的有一案,死讯配对的有一案,组的等待占了三案,停与醒占了五案。帧的校验案有个讲究:投递要往一个假想的用户栈上摆东西,咱们按内核自己的栈区间常量,在宿主里 mmap 出一块真的内存,把它摆在了那个位置上,引擎的地址算术跑的全是真常量,布局要是跑了偏,案子里当场红给您看。两段路是修通了,可定制句柄怎么进门、进门之后怎么回家,还是两张空白的纸,咱们下一篇把它们写满。
