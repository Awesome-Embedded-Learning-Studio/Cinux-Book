# ifconfig 与那张名册

第二位上桌的客人轮到的是 ifconfig,它的吃法侦察时记过一句:问话走 ioctl 的字,号位是不另开的。进门的次序是固定的:枚举的问在前,细节的问在后。枚举问的字是 SIOCGIFCONF,形叫的是 ifconf,客人递的是长度加一块缓冲,咱们按口回一张张 ifreq,四十字节的长:头十六是口名,接着的是两字节族字,再四字节的地址,地址的词照线上的大端写。枚举的名册,原文是不长的:

```cpp
for (unsigned long ordinal = 0;; ++ordinal) {
    char name[net::kIfNameMax] = {};
    if (!net::NameInterfaceAt(ordinal, name)) {
        break;
    }
    net::InterfaceFacts facts{};
    if (!net::ReadInterfaceFacts(name, facts)) {
        break;
    }
```

名册的货色咱们照实报:纯值的快照,是不挂回调也不追状态的。头一位摆的是 lo,地址答的是 127.0.0.1,掩码答的是 255.0.0.0,广播就是自家的,硬件类型是回环的七百七十二,号出自人家头文件里 ARP 硬件类型的表,咱们照表挂,MTU 报的是六万五千五百三十六。eth0 这一席是挂着线才有的,地址答的是 10.0.2.15,掩码答的是 255.255.255.0,广播按掩码的算式补全,补出来的是 10.0.2.255,硬件类型答的是一,MTU 报的是一千五,MAC 是不写在名册里的,是问世界要的,世界是问卡要的。口名对不上号的,答的是 ENODEV,名册上没有的人不装认识。

这桩判例是拿客人的源码换来的。不带参数的 ifconfig 本想抄近路读 /proc/net/dev 列口,可它读 proc 的路对空口名是答零返回的:枚举要是只靠 proc 的话,面板是一行都出不来的。所以不带参数的显示,必须走 SIOCGIFCONF 的枚举问。咱们把判例立在 ioctl 的门内:枚举的问题枚举的字答,是不指望客人绕道 proc 的。实弹里 ifconfig 敲了下去,面板落的是 eth0 Link encap:Ethernet HWaddr 52:54:00:12:34:56 一行,inet addr:10.0.2.15 Bcast:10.0.2.255 Mask:255.255.255.0 的一行,lo Link encap:Local Loopback 的一行,inet addr:127.0.0.1 Mask:255.0.0.0 的一行,末了的 MTU:65536 收尾,断言守的就是这五行加提示符。

掩码的字节序踩过一案,值得咱们单独讲,因为它是屏幕卖的。掩码的值存在名册里是本机序的一个词,词写的是 0xFFFFFF00。答话的时候要照线上的写法翻成大端。有一版笔误写反了,出去的词成了 00FFFFFF。这个错嘴上是查不出来的:地址是对的,口名是对的,旗也是对的,可 ifconfig 是拿掩码自己算广播的,算式一进它的用户态,屏幕上落的是 Bcast:255.0.2.15——一个四不像的地址,当场把它卖了。修完了屏幕回到的是 10.0.2.255。这个错在长凳上是查不出来的:笔笔都过,客人的算式一进用户态就把它算了出来,字节序的错,是对着字节看才看得见的。

挨口的细问一排是挂齐的:旗字答的是 UP 与 RUNNING,回环口添的是 LOOPBACK,其余添的是 BROADCAST。地址、掩码、广播三个字共用的是一条答法,选好了词照大端写。硬件地址答的是类型加六个字节,类型答的还是名册里的号,MTU 答名册的数,metric 答的是零,发送队列长答的是一千,这些都是人家问什么咱们答什么,答得出与答零是分清楚的。点对点的目的地一问答 ENOTTY,咱们的口没有点对点的形,是不装的。

/proc/net/dev 那边是同一张名册的另一张脸。形照人家的排:两行表头一字不差,下面排的是每个口一行。行里填什么?填的是十六个零。名册不记每个口的流量,收了多少发了多少的数是一笔都没有的,咱们选的是零得诚实:节点拒绝编造字节。cat /proc/net/dev 敲了下去,断言守的是两行,lo 的一行,eth0 的一行,各背的是十六个零。空表与假表是两回事:这一行行的零是空表,往后哪一卷把流量的数立起来,填的事就归那一卷。
