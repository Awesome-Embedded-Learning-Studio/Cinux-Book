# ifconfig 与那张名册

第二位上桌的客人轮到 ifconfig,它的吃法侦察时记过一句:问话走 ioctl 的字,不另开号位。进门的次序是固定的:枚举问在前,细节问在后。枚举问的字是 SIOCGIFCONF,形叫 ifconf:客人递一个长度加一块缓冲,咱们按口回一张张 ifreq,四十字节:头十六是口名,接着两字节族字,再四字节地址,地址的词照线上的大端写。枚举的名册,原文不长:

```cpp
for (unsigned long ordinal = 0;; ++ordinal) {
    char name[net::kIfNameMax] = {};
    if (!net::NameInterfaceAt(ordinal, name)) {
        break;
    }
    net::InterfaceFacts facts{};
    if (!net::ReadInterfaceFacts(name, facts)) {
        break;
    }
```

名册的货色咱们照实报:纯值的快照,不挂回调不追状态。lo 一位,地址 127.0.0.1,掩码 255.0.0.0,广播就是自家,硬件类型是回环的七百七十二,号出自人家头文件里 ARP 硬件类型的表,咱们照表挂,MTU 六万五千五百三十六。eth0 一位,挂着线才有,地址 10.0.2.15,掩码 255.255.255.0,广播按掩码的算式补全,10.0.2.255,硬件类型一,MTU 一千五,MAC 不写在名册里,问世界要,世界问卡要。口名对不上号的,答 ENODEV,名册上没有的人不装认识。

这里有一桩判例,是拿客人的源码换来的。不带参数的 ifconfig,本想抄近路读 /proc/net/dev 列口,可它读 proc 的路对空口名是答零返回的:枚举要是只靠 proc,面板一行都出不来。所以不带参数的显示,必须走 SIOCGIFCONF 的枚举问。咱们把判例立在 ioctl 的门内:枚举的问题枚举的字答,不指望客人绕道 proc。实弹里 ifconfig 敲下去,面板落的是 eth0 Link encap:Ethernet HWaddr 52:54:00:12:34:56 一行,inet addr:10.0.2.15 Bcast:10.0.2.255 Mask:255.255.255.0 一行,lo Link encap:Local Loopback 一行,inet addr:127.0.0.1 Mask:255.0.0.0 一行,MTU:65536 收尾,断言守的就是这五行加提示符。

掩码的字节序踩过一案,值得咱们单独讲,因为它是屏幕卖的。掩码的值存在名册里是本机序的一个词,0xFFFFFF00。答话的时候要照线上的写法翻成大端。有一版笔误写反了,出去的词成了 00FFFFFF。这个错嘴上查不出来:地址对、口名对、旗也对,可 ifconfig 拿掩码自己算广播,算式一进它的用户态,屏幕上落的是 Bcast:255.0.2.15——一个四不像的地址,当场把它卖了。修完屏幕回到 10.0.2.255。这个错长凳上查不出来:笔笔都过,客人的算式一进用户态就把它算了出来,字节序的错,得对着字节看才看得见。

挨口的细问一排挂齐:旗字答 UP 与 RUNNING,回环口添 LOOPBACK,其余添 BROADCAST。地址、掩码、广播三个字共用一条答法,选好词照大端写。硬件地址答类型加六个字节,类型答的还是名册里的号,MTU 答名册的数,metric 答零,发送队列长答一千,这些都是人家问什么咱们答什么,答得出与答零分清楚。点对点的目的地一问答 ENOTTY,咱们的口没有点对点的形,不装。

/proc/net/dev 那边是同一张名册的另一张脸。形照人家的排:两行表头一字不差,下面每个口一行。行里填什么?十六个零。名册不记每个口的流量,收了多少发了多少,一笔数都没有,咱们选的是零得诚实:节点拒绝编造字节。cat /proc/net/dev 敲下去,断言守着两行,lo 一行,eth0 一行,各背着十六个零。空表与假表是两回事,这一行行的零是空表,往后哪一卷把流量的数立起来,哪一卷再来填它。
