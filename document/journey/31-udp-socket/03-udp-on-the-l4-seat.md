# UDP 坐上四层的座

栈那边的话咱们接着用:校验与回环栈那一卷立过四层的座,协议字是座的门牌,谁入座谁递自己的 handle。ICMP 当年坐的是一号的座,UDP 这回来坐十七号的,姿势一个模子:世界接线的时候,L4Seat 装上了 UdpModule,seat_protocol 的一句话,座就算坐定了。汇那边判完了两次,协议字十七的包,从今往后有主了。世界里的接线也顺手:UDP 拿到汇的出站口与自家地址,起手落在回环的地址上,等真网卡挂了线,汇重瞄的时候它跟着一起重瞄,套路数 IPv4 与 ICMP 都走过了,UDP 照着走就是了。

词书补上了条目,这一步是走在头里的,这是校验与回环栈那一卷立的家法:每个协议一张自己的字表,收到的包死在哪一句,名字是说得出的。UDP 的头是八个字节,装的是四个字:源端口两字节、目的端口两字节、长度两字节、校验和两字节,长度说的是整个数据报连头在内。拒因两个名字:不足八字节的,咱们叫它短。长度字段跟字节吵架的,咱们叫它长度不对。这里有一笔分工的讲究,咱们照词书里的注念:词书只判头自己跟自己合不合,声明的长度跟实到的字节对不对得上,是收侧模块的事,因为搬运的底下一层可能往包尾垫了填充,垫了还是没垫,咱们得问模块才知道。所以三重门是这样排的:词书管短包,模块管的是核对,校验和管的是折数,一门一门地过,死在了哪一门,计数器上记的就是哪一笔。

校验和这一门值得咱们单讲一页。UDP 的校验和折的不只八个字节的头加载荷,它前头押着的是一段伪首部,咱们数一数:源地址四个、目的地址四个、零字节一个、协议字一个,末了的两个是 UDP 长度。这十二个字节是不在包里走的,是收发两头从 IP 头里现抄的,押的是 IP 头里的字段:包要是半路被人改了地址或者截了尾,伪首部的数就折不拢。收侧的三重门,咱们把原文摆在这儿,核对长度的那行与折校验和的那几行都在:

```cpp
const auto kView = ParseUdp(bytes, length);
if (!kView.ok()) {
    if (kView.error() == UdpError::kDatagramTooShort) {
        ++stats_.refused_short;
    } else {
        ++stats_.refused_length;
    }
    return;
}
if (kView.value().length < kUdpHeaderBytes || kView.value().length > length) {
    ++stats_.refused_length;
    return;
}

if (kView.value().checksum != 0) {
    unsigned char pseudo[kPseudoHeaderBytes] = {};
    build_pseudo_header(pseudo, header.source, header.destination, kView.value().length);
    base::InternetChecksum verifier;
    verifier.add(pseudo, sizeof(pseudo));
    verifier.add(bytes, kView.value().length);
    if (verifier.value() != 0) {
        ++stats_.refused_checksum;
        return;
    }
}
```

咱们盯着 verifier 那三行看,一段折的是伪首部,一段折的是数据报本体,用的是同一个累加器接着算。这就是校验与回环栈那一卷撂下的话的兑现:反码和分段累加的本事,栈里其实一直没有主顾,它的活排在 UDP 的伪首部这里。主顾今天上门了。至于线上零字段的直过,那是跟 IPv4 一对的老约定:零在线上是没算的暗号,IPv4 的头允许不算,UDP 挂在 IPv4 底下也随了这个俗,收方见了零,这门是不开的,直接就放行了。

另一笔兑现的话更要紧,校验与回环栈那一卷点过名:算出零发全一的特例,三个说话的协议都用不上,UDP 到了才用。道理咱们拿数上说:折出来的数要是恰好是零,算不算出了错?反码和真有可能算出零来,这样的零不是异常,是数据巧了。可线上的零已经被没算占了,真算出的零要是照发,收方一看是零就当没算放行了,校验这门就等于白立了。所以发方算出零,改发的就是 0xFFFF。收方那边这笔数照样平:0xFFFF 进了折叠,折出来的还是通过。长凳上有一案字节级的实证:源端口填 0xFFFF,目的端口填 0x01DC,载荷是空着的,伪首部的十二加头八,二十个字节的数算出来恰好是零。这一包 send 出了门,回环上收了回来,校验和的两个字节断言的就是 0xFFFF。两头的数笔笔对得上。

三重门全过、端口也有人认的包,模块把载荷连同回信地址一起递给端口座上的听客,咱们到下一章细说。端口没人认的包,就安静地计数死掉,不回一个字的错,安安静静的。UDP 是数据报的脾气:包是散件,丢了不补,没主的更不值得兴师动众,计数器上有它的坟头就行。接下来的问题是包往哪儿去,咱们接着看端口表。
