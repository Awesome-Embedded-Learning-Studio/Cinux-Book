# 会具名拒绝的词书

地基齐了,咱们往上立的第一层是词书。net_layout 这一件的差事,就是把线上的字节读成字段,它是只读不写的,构包的活往后跟着各自的消费模块走,词书是不掺和的。四张脸:以太的帧头、ARP 的包、IPv4 的头、ICMP 的回声头。每张脸的问答只有两种答案,要么给字段,要么给一个有名字的拒因,第三种答案是没有的。

拒因为什么要具名,答案在坏包的日常里:线上一阵噪声、一个截断、一个说错了话的邻居,全以坏包的形态进门。词书要是只会拿一句不行了事,上头的模块就只能笼统地丢,负测就只能笼统地断言没崩。所以每个拒因是一个枚举里的词。以太的拒因一个:帧不足十四字节。ARP 的拒因四个:包不足二十八字节,硬件域写的不是以太,协议域写的不是 IPv4,地址尺寸不是六与四。IPv4 的拒因四个:数据报不足二十字节,版本的高半字节不是四,头长写的不足五个字,声明的总长比自己的头还短。ICMP 的回声头一个:不足八字节。收到的坏包死在哪一句上,咱们凭计数与断言都说得出来,枚举里的每个名字,都是往后负测逐类断言时要抓的那个字。
名字全在树里写定了,咱们逐字搬过来:

```cpp
enum class EthernetError : uint8_t {
    kFrameTooShort,
};

enum class ArpError : uint8_t {
    kPacketTooShort,
    kUnexpectedHardware,
    kUnexpectedProtocol,
    kUnexpectedAddressSizes,
};

enum class Ipv4Error : uint8_t {
    kDatagramTooShort,
    kBadVersion,
    kBadHeaderWords,
    kBadTotalLength,
};

enum class IcmpEchoError : uint8_t {
    kDatagramTooShort,
};
```


这门词书只说一种形状的话,咱们把边界立在这里:ARP 在这一卷只认以太上载 IPv4 的 ARP。硬件域、协议域、地址尺寸,三个字里凡有一个不对的就具名拒绝,不留猜测的余地,不留将就的余地,也不给未知的形状留松口。往后要认别的形状,那是往词书里添词的事,不是放宽检查的事。

IPv4 的解析脸里有个分工,值得咱们单独讲一讲。词书判的是头跟自己说的话合不合:版本是四,头长的下限是五个字,声明的总长不短于头。至于声明的总长装不装得进它实际到达的那个缓冲,词书是不管的,那是收包模块的问题,它手里才有缓冲的真长度。词书管的只是字,容量的事归不到它头上,这个边界写进了注释里,往后 IPv4 那一章咱们会看见模块怎么接这一棒,取小的那一边。

解析的细节咱们一样一样看,都是老实的活。以太头是目的地址、源地址、类型字,目的地址占头六个字节,源地址占中间的六个字节,类型字占末尾的两个字节,读出来的一并装进 View 结构,解析脸交出去的是值不是指针,字段的生死跟着值走,而不是跟着缓冲走。IPv4 的头长藏在第一个字节里,高半写的是版本,低半写的是字数,字数乘四得出来的才是字节数,落在二十到六十的范围内,所以第一个字节 0x45 说的就是版本四、头二十字节。ICMP 的回声头五个字:类型、代码、校验和、配对的标识、排序的序号。标识与序号是问答双方对暗号用的,词书管的只是读出来,解释的事没有它的份。

长凳上词书考了十五案,咱们挨个报。以太的两案:全帧读出两址与类型,十三字节的帧具名拒。ARP 的五案:应答解出两对地址,截断的包、改了硬件域的、改了协议域的、改了地址尺寸的,四种各死各的名字。IPv4 的五案:最小的头读出头长、总长、协议与两址,十九字节的、版本写了五的、头长写了四个字的、总长短过自己头的,具名的就是这四样。回声的两案:八字节读全五个字,七字节的具名拒。末一案考的是大端读词。一张词书而已,同一张脸上写的是读与拒,同一套代码里写的是坏路与正路,不是事后补的补丁。词书立了,咱们搭栈。
