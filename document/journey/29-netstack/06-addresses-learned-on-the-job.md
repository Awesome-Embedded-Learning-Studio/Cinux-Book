# 学来的地址

头一位住户其实不进栈,栈外记名的就是 ARP。地址解析问的是同一个问题:一个 IP 地址,对面的以太地址是什么。咱们这一卷给它的件是纯名册 ArpCache,它的三张脸:学的是 observe,查的是 lookup,造请求的是 build_request。发包收包的事它一概不沾,不知道任何设备的存在,连时钟都是不问的,是一个真正零耦合的件。

记名的章法有讲究:每一只路过的 ARP 包都教课。应答是带着答案的,这一点倒是好懂。请求也这么教,发请求的人,他自己的 IP 与以太地址这一对就写在包里,白送的。所以 observe 不分请求应答,一律学的都是发送者那一对,词书拒掉的包除外,一个字也是不教的。请求里目标那一对咱们不学:发请求的人自己就不知道答案,他那里填的是零,学了就是把无知当学问记进名册。

lookup 的答案有两种:学过的,给的是指针。没学过的,给的是空。查不着的事不当错误,这一点是当年就立下的判例,咱们原样继承。理由在异步:答案说不定下一个瞬间就到了,查不着的这一轮,正确的动作是把请求发出去,再查就是下一轮的事。miss 是等待的一个瞬间,不是一个要抹平的缺陷。真把 miss 变成请求的那段接线,要等第二部的泵立起来,这一卷要做的就是把名册立对,立对的标准就是查与学都干干净净。

build_request 是纯函数:调用者递一块二十八字节的缓冲,它把固定的形状填上:硬件域一,协议域写的是 0x0800,地址尺寸六与四,操作字写的是一,发送者的地址与 IP 照着参数写,目标的 IP 写上要问的人,目标的以太地址填零,因为问的人也不知道。填完了拉倒,发不发的事,往哪发的事,广播怎么写,都是发送那一头的活,词是一个都不管的。构包的字段全走大端写词,上一章的家法,咱们在这里兑现。

名册的容量是四条,满了的办公法是新来的条目环形地顶替最老的一条,记名不设永久的户口。同一个 IP 后来的答案会更新他名下的地址,换卡不换 IP 的日子,名册认的是现世界,这样的行为,长凳上的案子守着。环形顶替的路数,五个案子各建各的名册,最多占过一条而已,满员的情形,这一卷的案子没考到,这一层咱们如实登记。

名册考了五个案子,咱们挨个报:造出的请求解析回来还是请求,发送者的那一对对得上,目标硬件填的是零。真应答教的只是发送者那一对,目标的那一对学不进,10.0.2.15 学到了,10.0.2.2 是学不到的。被词书拒掉的包,少一个字节的都不行,什么都不教。请求教的是问话人,不是被问的。后来的答案替换名下学到的地址。名册是干净的,ARP 在这一卷的活就到这里,resolve 真正转起来的样子排在第二部,那时回环之外的真邻居才进门。
