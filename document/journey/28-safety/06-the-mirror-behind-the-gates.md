# 开闸,与开闸后的镜子

台阶一到头咱们就开闸。开位的件小得与它的分量不相称:读 CR4,CPUID 点了名的位一个一个 OR 进去再写回。而整字永不重建,机器自己的位机器自己管,咱们只添咱们的两位。咱们把开位排在第二颗核上线之前,蹦床把引导核的 CR4 抄给每一颗到来的核,双核见的是同一面。机器的跑面这时也动了一笔:主跑参数加上了处理器直通,旗的名字是 -cpu host,KVM 收到了它,就把宿主处理器的特性面原样递给客人。默认的模拟面是 qemu64 的一张老脸,SMEP 与 SMAP 是 2011 年以后才进册子的特性,老模型的册子上没有这两页,三位怎么也到不齐,这一卷的戏就开不了场。特性不在的机器,门走不带窗的路,面板报它自己的实情。回读的机制不撒谎。

面板上的第一句新话,咱们逐字抄来:

```text
[kern] cr4 300620 after core protections
```

后面每一颗核上线的时候,各自又报了一行,EFER 报的是 d01,CR4 报的是 300620,两颗核的字一模一样。咱们把 300620 这个字拆给大伙看:高头那一片 0x300000,说的正是二十位与二十一位,SMEP 与 SMAP 的两位双双在册在岗。低头的 0x20 与 0x600,是物理地址扩展与浮点那些老住户。EFER 的 d01,讲六十三位的那一章拆过,位十一的不可执行使能在里面。面板上的三个位,全数亮成了一片。

开闸的这一天,咱们把话说明白:闸一开,咱们拿到的就是一面镜子,漏网的活自己现身。果然动态链接的 hello 首跑,SMAP 的页错误当场逮住两处收编时的漏网:一处是状态查询里的一笔直写,当初盘点清单上的漏项。一处是时间那一件里的分段补丁漏了缝。页错误的死法够响,漏网的藏不住,咱们照着这个思路把全树又复扫了一遍,才敢说覆盖齐了。当年第一遍也有一笔可以放在这里讲的旧话:那一遍在跳向用户态的路上,内核态里就大笔写过用户的内存,当年跑它的机器没透传 SMAP,侥幸地活了下来。闸开了之后,这一类的事当场就死,死在人人看得见的明处。

SMEP 的实弹咱们请 smepdemo。它把调用目标指到内核正文的基地址,打了一句预告之后跳过去。串口原文咱们逐字抄来:

```text
/ # /bin/smepdemo
[smepdemo] about to call into kernel text
Segmentation fault
/ # 
```

死在取指的向上,页表的分界与 SMEP 的闸都在岗,shell 活了下来。这里咱们把 SMEP 的正主戏码也说清楚:它真正防的是反方向,骗内核把客人的用户页当指令跑。内核的手里存着特权,栈与返回地址被人牵着走的时候,用户页里的代码就借上了内核的身子。咱们的机器今天还没有一条会被牵着走的路,没有哪条内核路径会跳客人给的地址,所以位现在就开上,防的是那天。它打的这一跳,是咱们今天够得着的方向,验的是执行这一向的闸是活的。

开闸的同一段里,咱们顺手收掉了名单上挂着的信号位共同协议那一笔。信号的 pending 位,历史上攒下了五处无锁的读改写,终态的代码把它们全数收进了闸,并成了三段闸窗:送信号时的置位,投递侧的清位,exec 时整个信号状态的重置,每一段窗里都可能同时有别的核在写。闸外另有两笔自家回程的写:投递路径里并掩码,写的是 blocked,按旗清动作的写,清的是 actions,碰的都不是 pending 位,只有任务自己的回程会走到,按跨核会碰的才要闸的判据,留在了闸外。位图的读改写不是一锤子买卖,中间断了就是丢信号,进了闸的五处从此断不了,闸窗绝不沾调度器的边。这与 SMAP 的窗是同一条道理的两种写法,两边都不跨会把执行流换走的路口。

三道保险的实弹至此全命中,常用的全家桶,动态链接的 hello、管道、各位客人,普通与检查两个镜像各过了一遍,跑下来的结果全数照旧。咱们该给栈帧配哨兵了。
