# 会道歉的指令

门还差的最后一件本事是道歉。范围的那一问,拦得住空指针、高半地址、绕回的假区间,拦不住翻译层的坏消息:界内的地址可以是一个没人登记的洞,可以是登记了还没补页的懒页,可以是只读页上的一次硬写。搬运死在这些地方,页错误一路走会疼那一卷立的老路,ring0 的未解错误没有活路,内核整个儿地躺下。可客人递来的要是一个坏指针,该死的是这一次搬运,答一个 EFAULT 了事,内核到了第二天还得开机。咱们没有语言级的接异常,页错误是异步踹进来的一条路,能接住它的只有出错的路径自己。生产内核的家法给了答案:例外表。每一条明知可能死的指令,身边挂一行小注:我要是死在这儿,请把我的执行流改道送去那儿。

形状是这样的。咱们在链接脚本里开一个对齐十六的新段,让条目一个紧挨一个排成完整的数组,二分的路才走得通。保命的差事交给 KEEP:例外表的条目恰好谁也不引用,没有 KEEP 的话,链接器会把没人引用的段当死物扔掉。段的两头立两个链接符号当门牌。每条小注十六个字节:前八个是出事的指令地址,后八个是落点地址。链接器收条目按编译件的来路顺序躺,不讲地址次序,所以开机的时候,咱们用标准库的排序把整张表按出事地址排一遍,以后每一次问走的都是二分。表里条目就那么几条,排序一辈子就跑这么一次,标准库的排序拿来就用,比手搓的排序体面,咱们不另造。

门的搬运这时换了内联汇编的真身。rep movsb 的前后各挂一个数字标号,一条 .quad 把出事标号与落点标号写进了段里。这里有一条汇编器的脾气,咱们立个案:数字标号的注解必须写在落点标号之前。而数字标号可以重号,靠前向与后向的记法解析,注解排到了落点标号之后,汇编器翻遍了也找不到那个前向引用,当场答不上话了。落点的代码干两件事,次序是死的:头一件 clac 把窗关上,带着开着的窗跳走,等于把窗漏给了全世界,后头的代码全在裸奔。第二件把判词清了零:判词就是汇编块里那个输出操作数,搬运走完的时候它还是一,落点把它清成了零,门看到的是零,答的就是搬运没走完,syscall 那一头把它翻成负十四的 EFAULT。汇编块的输出操作数,咱们从硬件自己走过的三个寄存器里回读:搬运走到哪一步,目标指针、源指针、剩余计数就停在断掉的那一步,落点接手时看到的就是断口的现场。

页错误那边的次序,咱们摆得很正:修页在前而问表在后。一个地址在登记册里有合法的登记,只是补齐的活还没做,缺页路径把页补上了,执行回到了断口,rep movsb 接着数它的字节,剩下的路由搬运走完,这是与生产内核同款的走法。修不了的才轮到表:ring0 的错误,出事地址在表里命中,改写返回地址落进落点,搬运答的是败,syscall 把它翻成了 EFAULT。ring3 的未解照旧走杀进程的老路。还有一路单独分流:错误码说是 ring0、出错地址在用户半、SMAP 开着、AC 又没置,这是窗没开就伸手的抓现行,咱们不必劳驾缺页路径,直接走问表的近路。这一次序的安排还出过一桩案子,咱们记在后面那一章,这里把话搁在这儿:次序反了,例外表会抢在补页的前面,把好地址弹成 EFAULT。

负测的选址有一条判例,是当年第一遍传下来的。当年头一版的负测地址,落在直映射碰巧盖住的地界,搬运的成绩全数是成功,测试的绿亮得晃眼,其实根本没走到坏地址上,假绿了一场。重走的这一遍,咱们把选址的讲究换了个根子:咱们的直映射在内核半,不经用户的地址,老机理构成不了。可补页会吃登记册内的地址,所以洞必须选任务空间里没有任何登记的地方。有登记的地址,缺页路径会把页补上了,搬运接着走它的路,怎么也答不出 EFAULT。

咱们把测试分两层。机内的门件一共八案,这一章里当证人的是其中洞地址双向弹回的两案,内核活了下来。可机内测的只是表的几何,因为机内测试直接调内核的函数,递的是内核地址,门的真闸碰都碰不到,假绿的根子与当年那一场相同。真闸要 ring3 的真程序来把门:efaulter,一位专门递坏指针的客人,往洞地址上写四个字节。串口原文咱们逐字抄来:

```text
/ # /bin/efaulter
[efaulter] writing four bytes at the hole address
[efaulter] write answered -14 (14 is EFAULT, the door apologized)
/ # 
```

答的负十四,是门的道歉,内核原样地活着。这一章咱们自己也摆过一回乌龙,如实记下:排版工具的名单里混进了链接脚本,被啃过的脚本混进了提交,随后头一次构建就炸了,从干净的版本重建了事。门齐了,台阶也上到头了,下一章咱们开闸。
