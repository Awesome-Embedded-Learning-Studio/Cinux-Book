# 记号笔与篱笆

身份的这一摊,咱们立的是四个数:真身的 uid,行事的 euid,真组的 gid,行事的 egid。真身记的是生下来的身份,平时不会悄悄地变,只有显式的 setuid 动得了它。行事记的是现在借着的身份。生产系统里临时借特权再还回去的那套戏,靠的就是真身与行事两格的分家。四个数的住处是任务结构,就是四个普通的数,不带任何附带的结构。fork 整行地抄给孩子,孩子生下来就是爹的身份。exec 换了戏服不换身份,进程还是原来的那个。

咱们排了六张号位,对齐 Linux 的老编号:getuid 一百零二、getgid 一百零四,setuid 与 setgid 的号位是一百零五与一百零六,geteuid 与 getegid 的号位是一百零七与一百零八。读的四张各答各的格子。写的两张各守一条同款的章法:行事身份是零的,想设谁设的就是谁,root 的特权就特权在这儿。不是零的,只许退回自己的真身,想冒旁人的,换来的是拒绝,答的是权限不足。setuid 设下去的时候,真身与行事是一起换的,咱们今天没有需要两个格子分裂着过的戏码,所以不预写。

诚实的边界要挂在明处:四个数今天没有一个消费者盘查它们。权限检查的面还不存在,文件的属主还没有,系统调用不问来者的身份,所有进程的身份仍然是 root,零号想设谁设的就是谁。记号笔画下了身份,篱笆的桩还没立。边界上还挂着一条:setuid 的可执行文件,跑起来自动换身份的那套,咱们明确不做。那套东西要立得起来的话,篱笆与盘查的岗两样都得在前头,都在后面的路上。

实弹咱们请 id,硬链接补名字的时候它占了一个。串口原文咱们逐字抄来:

```text
/ # id
[kern] syscall 115 unserved
uid=0 gid=0id: can't get groups
/ # 
```

前两问的答案干脆,uid 与 gid 的答数全是零。第三问问的是组清单,一百一十五号的系统调用,咱们的号位表上没人接,内核如实报了 unserved,id 自己也接了话,答的是一句拿不到组。客人问到了咱们没有的东西,这一行串口里三方都没装:客人问了,号位表报了实情,程序认了。数点完了,收卷的活就到了。
