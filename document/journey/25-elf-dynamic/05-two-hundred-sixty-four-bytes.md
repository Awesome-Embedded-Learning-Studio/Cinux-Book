# 二百六十四字节,与一个新偏移

画像画好了,情报备齐了,摆之前还剩的一道工序。栈页就那么一页,四千零九十六字节的地皮,画像的章法是两支队伍抢同一页的地皮:指针从入口的栈顶向上排,字符串从页的底部往上摞,中间碰上了就是满,满了答 E2BIG,这个词是开门迎客那一卷立下的。咱们动刀改画像之前,把新画像的字数算了一遍,这一遍的算术,救了一次实弹翻车,咱们把这笔数摆出来给各位看。

栈顶的老偏移是 0x108,丢失又找回来的八字节那一篇讲过它的身世:入口的栈顶除十六要余八,这是 movaps 的形态。学费咱们前后交过两回,懒到家交了一回,立画像新常量又交了一回,那篇正文里的两笔都记着,再捡回来就不容易了。0x108 的意思是,从入口的栈顶到页的上边界,留给指针的字区只有二百六十四字节,里头要住 argc、argv 的指针,结尾的零词,envp 的指针,后面跟的又是一个零词,末了还有 auxv 的对子们,全体共用地皮。静态年代它绰绰有余:开门迎客那一卷的画像只有 argc 加几支指针加两个零词,auxv 只有一条裸的 AT_NULL。

现在 auxv 摆全了,咱们数一数最省的那一路,init 直拉 shell 的那一路:argc 一词,argv 摆了一支指针加一个零词,envp 摆了一支指针加一个零词,这头凑的是五词。auxv 从硬需到 EXECFN 的十三对,连 AT_NULL 的收尾在内,凑的就是二十八词。结果合计三十三词,随机载荷的字节还没算,字区已经贴着二百六十四字节的顶了。迎头的是余量的检查:每写一对之前都验一次余量,光装得下当然不算数,验的是装完这一对之后,页里还得留得出十六字节开外的富余。随机载荷的那十六字节也不在字区里住,而它跟串区一起从页底向上摞,和指针们抢的是同一页的预算。真贴着顶反倒死不了,死点其实在那道检查上,偏偏最后那两三对正好骑在边界上,一验不过,作废的是整张画像,给的是 E2BIG。炸的位置想想都替它冤:连命令行太长的演示程序都轮不上,炸的是 init 本尊,开机那一步它自己起不来了。这样的炸法要是留到实弹才发现,咱们得在串口前坐半天才能对上号,而它本来用一支笔就能算出来。

所以修法是一支笔的修法:偏移从 0x108 抬到 0x208,字区有了五百二十字节。为什么是 0x208 不是 0x200?按 0x200 算,栈顶除十六的余数是零,movaps 的形态就丢了,八字节的学费咱们交过两回,不会再交第三回了。而 0x208 除十六余八,形态保住了,地皮翻倍。抬完再盘一遍余量:busybox 那样的典型用量是 argc 一、argv 与 envp 各几支,连 auxv 的总数三十九词上下,三百一十二字节的占用,当然富余。真有客人把十六支 argv 和十六条 envp 都塞满了,再加全量的 auxv 和串区,页是装不下的,画像照旧答的是 E2BIG,咱们不偷第二页。页就这么大,预算说了算,极端的客人得到一句诚实的拒绝,比得到一页悄悄画歪的栈好。

这一改还验证了一件老事:那个偏移常量住在 proc_config 的配置头里,单点的一个名字,init 直拉的路、execve 的路,所有用点引用的都是它。改了一处,全路的栈顶一起搬家,消费点的一行没动。当年这个单点怎么立起来的咱们不知道,今天的这一改,好处轮到咱们领了。

这篇讲的都是算术,可咱们想留下的是次序。画像要摆的是十四对新词,这么大的动作之前,把它吃多少地皮算出来再动刀。开门迎客那一卷咱们说过,布局的事眼睛看对了也不算数,咱们得有断言锁着。这一篇补上它的另一半:动刀之前把数算出来。算在了前面,断言锁在了后面,两样都齐了,布局的案子才算关上。
