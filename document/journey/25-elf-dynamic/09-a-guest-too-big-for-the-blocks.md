# 大个子客人,与当年的绕行

解释器的个头是 822368 字节,咱们按习惯约着叫它 822KB。把它整读进内核的这一步,咱们这一遍做得毫无戏剧性,而毫无戏剧性恰恰是认字那一卷挣来的:ext2 的地界表,直接的十二格,单间的一跳管到第 267 块,双间的地界再往上,256 乘 256 的方阵,读路的上限是 64MiB。822KB 落在双间的地界里,读路铺好的,读就完了。busybox 1.2M 天天走的都是同一条路,咱们没有多看它一眼。

当年的教学线上,这一步是全卷最大的案子。咱们把当年的数翻出来算,算术本身的味道就很足。当年的盘,块的大小是 1024 字节,一个 inode 的十五格块指针,文件的第 0 到 11 块走直接格,第 12 块到第 267 块归第十三格指去的单间表管,再往上该轮到双重间接出场的地方,当年的读路没铺。当年一块盘上文件的读路上限是:十二加二百五十六,结果二百六十八块,而乘 1024 字节,所以 268KiB——这就是全部。822KB 的解释器,是上限的三倍,咱们装载它,读到三分之一就断了。

断在哪儿?当年串口报的是 segment read failed,断点的位置是 offset 274432。这个数咱们当场拆:274432 除以 1024,得的是 268。文件读到的是第 274432 个字节,就是读到第 268 块的开头,而第 268 块,恰好是双重间接的第一块。报错的位置就是断路的位置,数是严丝合缝地对上的,这一案当年是定得干净的。这里咱们停半拍,赞一赞这样的报错:失败信息里带着一个可拆的数,拆出来正好落在机制的缝上,这比一句笼统的 read error 值钱得多。咱们自己往后写失败路径,照的也是这个标准。

当年的解法没有去补双重间接,选的是绕行:造盘把块大小从 1024 改成 4096。块大了,间接表自己也跟着大:同样一格指针引出的单间表,1024 字节的时候装二百五十六格,4096 字节的时候装 1024 格,格数翻了四倍。每格指的块又从 1024 字节长到 4096 字节,再翻了四倍。两头相乘凑出的十六倍,单间一跳的天花板从 256KiB 顶到了 4MiB,822KB 稳稳落在单间地界里,双重间接根本不用碰了。盘照烤它的,程序照跑它的,活干完了再说。真修的话,把双重间接的读路补全,登记在册了,留给了后面的卷,而咱们这一遍的认字那一卷,已经把它做掉了。所以这一篇在咱们这一遍是纯考古,一步都不用绕了,咱们把当年的绕行讲出来,为的是那笔取舍本身。

取舍是这样的。块大小是一个盘的性格。小块省地方:文件尾巴平均浪费半个块,当然块越小浪费越少,目录项、位图、指针都跟着细了。可小块的间接地界窄:十五格指针怎么排,天花板压得低低的,大文件是装不下的。大块是反过来的:间接表一跳管得远,大文件是从容的,可每个小文件的尾巴都吃一个 4096 字节的块,一盘子的小文件,装的就是一盘子浪费。当年的绕行是工程上的正着:手上没有双间读路,把块改大让活干完了,机制补全的日子另排,绕完了登记在册,这就算办得干净了。咱们这一遍把双间做了,块就回到了 1024,一盘子教学小文件不再吃大块的亏,这是两个版本的各取所需,都是对的。

考古的收尾,咱们把这一案在两遍工程里的位置摆正。当年它炸在动态装载的卷里,是那一卷最大的坎。这一遍它连案子都算不上了,只是咱们讲考古时的一页插图,因为前面的卷已经把地基打好了。教程的次序有时就是这么值钱:同一块石头,排在泥路上的它绊倒人,排在铺好的路上它只是风景,咱们把当年最陡的那一段拆成三卷来走,拆的就是这个次序。
