# 给解释器一个固定的家

装载器原本只认一种落法:段表里的虚地址就是绝对地址,base 的隐含值是零。解释器来了,它的身份是共享对象,虚地址全是相对的,所以装载得添一个新词:基址。座位与基址两个词一起收进了装载的世界包 LoadWorld,结构多了两格,role 说的是这具身子坐哪个座位,base 说的是这具身子落在哪。这么收是有来由的:咱们给函数递参数,超过四个的话,参数上限的家法就要咬回,role 与 base 分开递的话正好是两回,合进包里就成了一趟。

基址进了算术,改动就一处:段的第一行算出落的虚地址,往后的页号、页内偏移、跨度全跟着它走。出口的四个数也一样,程序入口加的是基址,头表落点加的也是基址,主程序那边的基址是零,加了个寂寞,数值当然一个不变。解释器那边的基址是 256MiB,整具身子平移了过去。装载循环的一行逻辑没改,这正是咱们第一遍抽好这件构件的红利:算术的骨架没变,变的是骨架的原点。

exec 的流程里,两位客人是这么进场的。头一个进场的是主程序:整读、解析、按程序座位装载,堆的种子贴着程序顶落进登记册。然后才轮到解释器:扫出 PT_INTERP 的路径,咱们照着路径在盘上把它找出来,把整个文件读进了 buffer,按解释器的座位装进同一个新世界,给的基址是 256MiB。两份段、两套权限的家当,记进了同一本登记册,住在同一个地址空间里。这里有个次序的细节咱们如实交代:堆种子在前,解释器的段后到,谁也不挡谁的路,靠的就是两处的地盘离得远。

离得多远?咱们把用户半区的地图摊开看。用户的地址从零到 128TiB 的规范边界,栈的位置在顶上,往下是自顶向下找空档的 mmap 区,brk 与 mmap 的默认分界在 64TiB,程序和它的堆住在低处的 brk 半区。256MiB 的家,十六进制写下来的是 0x10000000,就落在 brk 半区的前排。主程序自身的住处在 0x400000 上下,几兆的身量,堆种子贴着它的顶上起跳。咱们的堆要往上长,长过了 64MiB 长过了 128MiB,一直长到了 256MiB,才有机会够得着解释器的家门。QEMU 给咱们的内存量级下,那是一个大得离谱的堆,真有程序把堆长到那个地步,它的麻烦早就不在解释器身上了。

为什么基址要固定,不随机?两个理由。头一个是排障:固定的家意味着每一次开机、每一次 exec,解释器都住在同一个地址,串口里抄下来的地址可以直接对符号表,昨天看的是它,今天看的还是它。第二个是进度的事:基址随机化,而行话叫 ASLR,地址空间布局随机化,是安全那一侧的活,它随机的对象是一整套布局的协同,解释器只是其中的一员,咱们把这件事整个留给后面讲安全的那一卷。这一卷咱们明明白白选了确定,想过之后才挑的这一边,代码的注释里就写着这句话:求确定,是故意的。

这里咱们照例把旧债挂上明处。堆种子落进登记册的时候,重叠是会被拒的,可 brk 系统调用往后长的路,眼下只在收缩的时候检查重叠,扩张倒是不查。真有程序把堆一路长到了 256MiB,解释器的地盘是可能被啃进去的。旧一代的布局里,堆顶着两百四十兆字节的天花板,想长也长不过,天然就挡了这一手。懒到家那一卷当年记下的绝对上限,记的正是这个数。咱们这一遍,brk 与 mmap 的分界画在 64TiB,离 256MiB 的距离远得很,硬顶没有了,这道防线也就空了。咱们如实登记:正解是堆的扩张也查重叠,这一卷咱们不动它,挂上了。诚实的话说完,咱们也要说回平常心:这是理论上的债,眼下它距离被踩到还隔着一整个 brk 半区的长途。

末了一笔伏笔。解释器的段装进世界的时候,每一段的读、写、执行三问,照旧记进了登记册。这一步在静态年代没什么稀奇,可解释器进场之后的第一件事里有一手,要拿这三问的记录去改权限,那一手会替咱们翻出两桩案子。咱们把话放在这儿,讲到实弹的那一篇,回来兑现就是了。
