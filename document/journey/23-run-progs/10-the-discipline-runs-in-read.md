# 行规程在 read 里跑

fd0 从来交的是裸键:键盘给一个字节,read 交的也是一个字节。回显、退格、攒整行的活,全在楼下的那一层,自家 shell 的 read_line,就是一个字节一个字节亲手攒出来的。真客人也想自己干的活,ash 带的是一整套行编辑,可它干它的、内核干内核的,两边就要打架了。这一篇咱们把行编辑搬进内核,给终端立了一个真身:住进 kernel/driver/tty,落成了一个单例。

核心的决定就一句:行规程在 read 里跑,而不在中断里。中断里只该有最短的活,这是从第一幕起就没破过的家规。于是 fd0 的读者在 read 里一键一键地取,取键的那一等是睡在按键之间的,整条编辑的路上没有一行中断侧的代码。编辑的活归 feed,咱们把判退格的两行抄来:两种约定它都认。

```cpp
bool is_erase(char key) {
    return key == '\b' || key == 0x7F;
}
```

咱们看 feed 怎么干活:可打印的键,进了缓冲,console 回显的也是一个字。咱们看到退格与 DEL 的回显是三连:退一格、抹一格、再退回来,行尾也跟着退了回去。结行的键是回车或换行,整行连着换行符压进了行池:一行一百二十八字节,池里备了八行,咱们让 console 补一个新行。read_line 从池里交的是整行:客人要得少就短读,剩下的留在池里给下一位。sys_read 的 fd0 分支从此直指这个单例。设计上的取舍有三句,咱们如实交代:write 侧不进它,输出的拥有者不是终端,console 走的照旧是直写。TCGETS 保持上一篇的形态不动。ECHO 那一类 termios 的开关没做,行编辑是常开的,开关面记给了后面讲假文件与真终端的那一卷。

咱们自家的 shell 得跟着改手续。内核学会了回显之后,shell 的 read_line 把用户态的回显与退格撤了,只做拼行的活:不然一个字要回显两遍,屏幕上的字是双份的。改完 shell 的手感没变,变的只有分工。

机内立了两案:回显停行与双退格吃尾,案名咱们原样念:喂 hi 加换行,行池里该躺着的是 hi 加换行。咱们喂的是 ecg、两记退格、ho,再回车:退格喂的两记里,\b 与 DEL 的约定各占一记,把 cg 都吃掉了,池里交出来的是 eho 加换行:四个字节。这两案把测试世界自己的两笔纠偏也带了出来,如实记下了。头一笔:初版的断言写的是池空的时候 read_line 答零,可它真实的约定是阻塞到有行。泊车要的是有任务,测试的世界里一个也没有,泊车的调用一进门,炸的就是里头的断言,越界的断言删了才安生:约定没立对,替客人喊冤的倒是测试。第二笔犯的是笔误,四个字节初写成了三。feed 因此公有化:键盘的脸与读者各持输入路径的一半,咱们在测试世界直接喂键,不经键盘的手。

实弹在自家 shell 里过:咱们敲一句 echo tty2:按一个字,内核回显的是一个字,回车落了地,整行交进了 shell,echo 把 tty2 原样念了回来,新行规程的全链走通。中间还有个小疑云:咱们想从模拟器的送键喂一记退格,把编辑的全链从外面过一遍,键送了进去,咱们没等到机器的动静。咱们疑了内核一圈,病根在工具的键名表里:它不认 bksp 这个名字,它的正名是 backspace,正名送了进去,全链当场通了:内核一个字没改。这一案教咱们的是:验工具的活要走在疑内核的前头。

ash 那头多了一笔新观察,如实记下:ash 检测到终端之后会走它自己的行编辑,内核的回显与它的回显叠在一起,双重回显就冒出来了。要治它的病,得给终端立 raw 模式的开关,这笔欠的记到下一卷,那里才是终端的完整体。行编辑进了内核,可咱们到这一篇为止还没亲手玩过它,实弹都是脚本喂的。下一篇咱们坐到键盘前。
