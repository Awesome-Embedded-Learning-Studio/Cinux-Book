# 打表救的是它自己

咱们把四层的旧病清完,客人 busybox 拉起来了,也活了一小会儿。它报的头一行是:

```text
ash: can't access tty; job control turned off
```

这句话的意思是:没有终端可等,它降了级也要活。可咱们一敲命令,机器就死了,死得没有面目:屏上停在半行报告的开头,机器转了又转,再没有了下文。咱们头一个判读是堆区没人补页,死面里的地址看着就在堆的边上,为此咱们还真写过一小段代码。判读是错的,那段代码后来撤了个干干净净,这一段经过咱们如实记着:误诊不丢人,装作没误诊过的才丢人。

咱们重验用的还是 gdb:堆区和 mmap 区的补页,一回一回地试,回回都是成功的。补页的路没病,病的是看路的报告。咱们诊断靠的是打表,就是缺页的时候把四层页表逐层打印出来的报告,它的第一层拿 CR3 里的物理值当虚地址,直接就解引用了,漏了物理转虚地址的那一换。后面三层倒是都带着这一换,偏偏第一层没有。于是内核态一旦在打印的路径里再缺页,就又进了打印,打印里又缺了页,层层叠进了进去,直到栈见了底。死面永远停在了半行,第一因被报告自己吞了。修的是一行:

```cpp
    unsigned long     table          = cinux::mm::DirectMapVirt(kRoot);
```

这一改的分量比一行重得多。过了懒到家那一卷,任何用户任务真要是出了段错误,死的样子全都是同一副面孔,第一因全被吞掉了,咱们自以为的尸检,验的其实是验尸官。从今往后的尸检链路才算得上可信。

打表自己的病,数下来排的是第五层。修好了它,死面推进了一格,露出来的是第六层:getcwd 的笔误。新的死面上,肇事的地址是 0x1000,咱们一查,busybox 递进来的 size 正是 0x1000。getcwd 的 handler 检查的是 rdi,写却写去了 rsi,把第二参的尺寸当成了缓冲的地址。寄存器座位上的笔误,修的还是一行。自家 shell 的 pwd 一直是好的,大概率是当年的版本就写对了,后来哪次重构翻坏的,这笔旧欠咱们记下不挖,修了就走。

第七层改的是懒到家那一卷的资产,行为也该放宽了。getcwd 修完了,死面又推进:内核态写用户的栈,被补页的门拒了。syscall 是代表用户写用户的缓冲,那一笔触发的是内核态的缺页,而那一卷立的门规要求缺页来自用户才肯服务。咱们把门规放宽成了:用户半区之内、册上有承诺的,无论缺页出自谁的手,咱们都照补。保护性的写与无承诺的地方,咱们照旧拒,getcwd 那类的笔误还会响,笔误的地址是没有承诺的。这是那一卷立下的章程的行为变化,咱们如实追认。机内的两案跟上:内核来的写,落在有承诺的页上,咱们补。落在无承诺的地方,咱们拒。

然后是这一卷的第一个里程碑:ash 活着吃下了第一句命令。咱们喂进去的是 echo station23,它交回来的是 station23。有个细节得交代:那会儿它的输出在串口上有明显的时滞,敲了半天没有动静,直到关机的一瞬,串口把积着的字一次排了出来,咱们是看着关机那一刻的输出复核的,实弹跑了两遍。为什么这时候就能吃命令了?argc 是一、argv[0] 是 /bin/sh 的降级形态,busybox 进了主入口,echo 是它的内置命令,fork 全程省了,管道也省了。无作业控制的 ash 能吃命令,头一个里程碑落了地,比咱们预估的还早:原本以为要把 uname、getrandom 那些号都补齐它才肯干活,真客人的容忍度,比侦察单子上看着的要大。

时滞的这一桩,咱们疑在 writev 上:ash 的输出走的是 writev,咱们号位表上还没有这个号,吃了闭门羹还不出声。这一桩的销与不销,下一段就见分晓了。咱们去铺号。
