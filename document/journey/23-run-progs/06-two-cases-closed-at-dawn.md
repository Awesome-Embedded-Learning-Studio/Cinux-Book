# 凌晨销掉的两案

凌晨的这一场,两桩悬案咱们一桩一桩过,头一桩的真相让咱们很没有面子,照实记进了档。ENOENT 案破案的头一步,竟是查咱们自己的复现配置:busybox 只写进了 /bin/sh 的座位,咱们敲的命令却是 /bin/busybox uname,而盘上从来没有过 /bin/busybox 这个文件。路径查找答的是 not found,是对的。ash 报的也是 not found,也是对的。错的是咱们:追了半宿的 fork 子读坏目录块,人家读得好好的,是咱们让它找一个不存在的东西。在复现盘的副本上给 /bin/busybox 建上了链接,uname 当场报出了 Cinux,1.2M 的 fork 加 exec 全链通了。还有一笔要还原:此前被压扁成 I/O error 的失败里,有一类缺的本来就是路径,整读 Result 化了之后,它们报回了真实的 ENOENT。您回头看上一篇末尾咱们那句自查,三刀砍的是真病,而第一因谁也没抓到过,现在可以说了:那个现场根本不存在,它是一桩乌龙投下的影子。

乌龙咱们认了,证据落了袋才算数。咱们写了一个复跑脚本进了仓,独立的盘副本,一轮一轮地造孩子、换世界、收尾,连打二十发:hello 交的退出码是四十二,false 交的是一,缺路径的命令交一百二十七,父 ash 交的是零,一处 I/O error 也没有了,一处段错误也没有了。往后大文件的 exec 再出事,跑它就是了。

顺路的三笔,咱们也分开记清楚。头一笔是旧块设备的测试,只跑了一轮收工就拆台,局部的队列底下还睡着没干完活的工人,后续的活写进了已释放的内存,这是测试基建的旧病,修了,等三个工人都退了场才收。第二笔是洗清一条嫌疑:AHCI 的传送路径取证追到底,从命令列表的基址到命令表,再到数据的散布表,咱们一路看下来,实测的样子是数据落进专用页:再由 CPU 拷进缓存槽,不存在直捣堆缓存的传送,这层嫌疑咱们说得清。咱们的第三笔不好听也不好写:观察说的是同一条目录缓冲跨重拉内容不同,归不了案。现有的修补解释不了它,取证的脚本备着,咱们重编之后偏移还得重对。这案子咱们还挂着,不装作办了。

第二桩是 ash 的段错误,根因落在了信号帧,病了四处,咱们一处一处数。听得懂喊声那一卷立的投递摆栈,咱们把它转述一遍:摆得最低的是一个槽,写着归乡上下文的地址,往上的一个槽写着蹦床的地址,再往上摆的是一百四十四字节的上下文本体。真客人装上句柄跑了一回,ret 一弹就死了,死在 rt_sigreturn 的门口。病的第一处,sigreturn 进门的时候,句柄的 ret 已经弹掉了蹦床槽,栈顶躺着的本来就是上下文本体,咱们却又解引用了一层,把上下文里存的旧栈顶当成了上下文的指针。第二处更冤:那个摆在返回地址下方的上下文指针槽,句柄一进门自己的普通压栈就把它盖掉了,凡是存在返回地址以下的东西,都活不过一次像样的调用。病的第三处,投递往下摆东西的时候,没给被中断的函数留 ABI 许给它的一百二十八字节红区,人家的局部变量就住在那儿。病的第四处,栈窗的检查里有一处无符号下溢。全修了:sigreturn 直接从入口的栈顶读上下文,指针槽索性删了,红区留足了,栈窗的下溢堵上。动作记录也照 musl 认的 x86_64 词序重排,四行断言把形状定住了:

```cpp
static_assert(sizeof(SigAction) == 32, "Linux x86_64 kernel sigaction is four words");
static_assert(offsetof(SigAction, flags) == 8);
static_assert(offsetof(SigAction, restorer) == 16);
static_assert(offsetof(SigAction, mask) == 24);
```

分界的话也交代。信号上下文咱们保留教学自己的格式,蹦床是内核的可执行页,完整的 Linux SA_SIGINFO 与 ucontext 没有做,如实交了底。这一案与 stat 的座次案踩的是同一条缝:自家的测试与自家的内核对齐,怎么绿都绿,外头编译出来的程序不认这样的对齐,一进门病灶就现了形。

两案销完了,验收全过了,客人总算能跑能退了。可 ash 里那根竖线还画不直:echo 的输出接不到 cat 的嘴里,因为管道的出生还排在后面。下一篇咱们造管子。
