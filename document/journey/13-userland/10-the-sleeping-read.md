# 睡着的读

上一节收工的时候,MSR 的词汇表立好了,咱们说过要转头接客人真正的需求——等一个键。现在咱们就来接。要接的 shell 是个常驻程序,等键盘等了大半辈子。怎么等,就是接下来要解的全部问题。

咱们来看当年的等法。当年的 sys_read 碰上空队列,干的是这样一段活:

```cpp
constexpr uint32_t SPIN_WAIT_ITERS = 1'000'000;

for (uint32_t i = 0; i < SPIN_WAIT_ITERS; i++) {
    __asm__ volatile("pause");
    if (cinux::drivers::Keyboard::poll(ev)) {
        got_key = true;
        break;
    }
}
```

空了就自旋:pause 一百万次,期间反复问队列来货了没有,一百万次转完了还没等到,就交了白卷返回,上头的 shell 把 sys_read 再发一遍。功能上这套自旋真等得到键:白卷交了回去就是重发,一百万次接着一百万次地转。可中间那段 CPU 是纯空转——人手落键的工夫,CPU 早把一百万次烧完好几轮了,烧完了还得从头再来。咱们替当年说句公道话,那会儿的内核里没有调度器,写出来的代码里连“把 CPU 让出去”的概念都立不住,一个想等的内核,除了原地转圈没有第二种姿势。可今天不一样了,调度器开张的那一卷,把睡眠、唤醒连同持锁入睡的纪律全铺好了。这套睡眠与唤醒的本事,那卷里生产者消费者的演示用过,可那不过是内核演戏给自己看,真正的用户态客人一位都没来过。这时候咱们再让客人空转,就说不过去了。

新的等法,咱们做进键盘自己身上。Keyboard 里内嵌的信号量名叫 readable_,初值咱们定成零。中断路径 on_byte 每翻译出一个可印的字符就入队一份,而后顺手 post 一份。队列照旧是那个 64 格的环形队列——一格永远空着,满与空才分得开——队列本身咱们没有动,加在它旁边的是那个会喊人的计数。对外咱们只开一个入口:

```cpp
char Keyboard::take(bool wait) {
    if (wait) {
        while (!poll()) {
            readable_.wait();
        }
    } else if (!poll()) {
        return 0;
    }
    char code = 0;
    events_.pop(code);
    return code;
}
```

等不等待的事,参数说了算。咱们没有立 take_wait 这样的第二个名目,因为两个入口迟早会有两个略有差别的说法,而一个入口,把差别摆在了明处。不等的走法眼下是机内键盘测试台在用的,那边喂完了字符当场验收,睡是不用睡的。想看它睡觉的话,咱们就跟着 take(true) 往下走。它碰上的是空队列,走的就是 readable_.wait(),存货是没有的,当前任务把自己挂上信号量的等待名单,进了 block_current,任务睡进了调度器,CPU 也让了出去。下一次键到的时候,IRQ1 进来了,三件事一口气办了:翻译、入队、post。名单上一旦有了人,post 就不走计数加一再等人来减一的弯路了,直接把份额移交了出去,顺手还把任务请回了就绪队列。等调度器再把它请上了 CPU,wait 的等待这才算到头,循环回过头又把队列查了一遍,把那个字符也取走了。这一趟咱们是从头看到尾的,三份差事各管各的,队列管的是存货,中断管的是进货,信号量管的则是喊人。您再留意一处,中断上下文与任务上下文是永不见面的,它们碰头的地方只有队列。

您回头看键盘 IRQ 线的履历:立起来那天下游是内核自己的回显主循环,到了首跳那一章主循环功成身退,到今天真正的下游到岗——一位会睡觉的常客。IRQ 路径的老一套一点没动:整数活、入队、post——慢活一件不沾。睡觉的是客人,不睡觉的是中断。

这里有个细节咱们得当着您的面推一遍:wait 为什么套在 while 里,不是 if?您看非阻塞的走法:队列有货就直接取走,信号量的存货一个没花。这说明存货和队列可以对不上——post 过的字节早被拿走了,不过计数还躺在信号量里。等待的 take 醒来,花掉的正是陈年存货,它对应的字符早没了,队列还是空的——这时候 if 会把空手当收获,while 倒是回头再查:查到才拿,而没查到就接着睡。那一圈 while 是这个不对称设计里货真价实的一环。

柜台那头咱们把 read 也实装了:

```cpp
for (unsigned long long got = 0; got < count; ++got) {
    char glyph = cinux::driver::Keyboard::self().take(true);
    if (glyph == '\r') {
        glyph = '\n';
    }
    out[got] = glyph;
    if (glyph == '\n') {
        return static_cast<long long>(got + 1);
    }
}
return static_cast<long long>(count);
```

进门咱们查两道,还是柜台开张那天立下的那两道:描述符不是 0,返的是 -EBADF。缓冲区越过了用户半边界,返的是 -EFAULT。而后逐字搬,键盘交上来的 CR 回车,咱们顺手转成 NL,读的人要的是换行。真碰上了换行就整行交差,连换行本身也计了数。您再注意 shell 讨字的方式,一次讨的只有一个字节。为什么不开口要整行?回显得在每一个字落地的当口做——整行读上来再回显,退格就做不成了。整行的合同留在内核这边,一个字一个字讨的用法,把逐字回显的门给客人留着。

末了咱们说这次会师。block 与 unblock 在进程那一卷里就铺好了,到今天终于有了用户态的消费者。持锁入睡的纪律也在岗:block_current 进门就查一遍手里有没有攥着自旋锁,查到了就当场停机报名字。为什么宁可出声也不安静?自旋锁的家法是持有人不睡、睡人不持锁:单核上一旦有人攥着锁睡去,等锁的中断路径就只能陪着空转——谁也叫不醒谁,安静地死锁比吵着停机难查得多。咱们从 IRQ 那头一路看到 syscall 这头,睡与醒从头到尾通了。

零件齐了。下一节咱们把常驻的客人整个写出来。
