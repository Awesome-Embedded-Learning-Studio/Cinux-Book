# 验收与三块砖

上一节末了咱们把话放下:机器真的活着了——面板与串口都能作证。收卷的活就是把证一件一件摆到桌面上。这一卷的验收集齐了三样:面板逐字对了数,测试全部通过了,实弹走通了整条链。三样都过了,咱们才合得上这一卷。咱们一样一样来,您不妨对着自己机器上的输出跟。

第一样看的是面板。开机爬完了那架梯子,咱们数一数串口上落下的,如今添到了十二行:

```text
[kern] 64-bit C++ world alive
[kern] gdt+idt self-owned, sse on
[kern] tss loaded tr=18 gs base FFFFFFFF8028B960 efer 501
[kern] kernel gs base FFFFFFFF8028B960
[kern] bootinfo: 8 e820 entries, fb 1024*768*32
[kern] screen console 128 cols 48 rows
[kern] kernel at 200000 size 90A20 entry 200040
[kern] pmm: 32316 pages free (probe 113000 ok)
[kern] vmm: address space up, magic 114514
[kern] heap: new/delete live (probe 114514)
[kern] irq on, tick 100Hz
[kern] keyboard on, type to echo
```

跟上一卷收工时的面板比,新添的是第三、第四两行,咱们逐个读开。tr=18 的意思是任务寄存器读回 0x18。排七个座位的时候咱们就说过:ltr 不是哑巴指令,装任务寄存器之前 CPU 当场校验的就是描述符,槽位、access、limit 一样不对的话,装的那一下就是异常,所以这个 18 咱们没有自己报,它是 CPU 收了货开的回执。底下两行 gs base 与 kernel gs base 的数一模一样,这正是当初安家时的设计目标:两个 base 指向同一块,swapgs 换了等于没换。这个数本身也是有讲究的,它是写进去又读回来的——安家写了两笔,如今面板上两笔都读回来了,读回的正是落脚点实体的真地址。第二行还是后来的事,词汇表出生的时候才添上,这么一写入一读回,一来一回都对上了。您要是读过编号那一案,该记得两笔同数恰恰骗过咱们一回,所以这一回连读法都换了:这两笔如今从词汇表里拿名字去读,同数才是真的同块。至于地址本身,您别跟书较真,链接挪一挪它就搬了家,您机器上跑出别的数才是正常的。末了 efer 501,第 0 位的 SCE 亮着。画客人世界的时候它还是 500,第 0 位摆了那么久没人读,还被咱们当过反面教材。如今门是天天开着的——它就是灯。

老的那十行,咱们只对两个数:pmm 的空闲落在 32316 页,magic 的读数还是 114514,家底没出什么意外。倒是末行那句老话值得多看一眼,`type to echo`。打字有回显的这句承诺,当年是内核的回显主循环在兑现,如今接活的是楼下的常客——键还是那个键,回显的手换成了 ring3 的 read_line。这行字是一处都没改的,主权交割的事,它自己写在了明处。

第二样验的是测试。全树构建出来的警告一条都没有,测试台的三十四件全部通过:宿主侧跑了二十七件,机内开了七台测试内核。机内每台零点三秒上下就出了一趟结果,sched 的测试因为双向初态要各跑一轮,也花不了一秒。咱们把产物一并交底:内核本体 kernel.bin 是 43456 字节,整张启动镜像的大小是 1MiB。面板里 kernel at 那行的 size 90A20,您别拿去跟 43456 对数,那是连对齐填充一起、按加载尺寸算的口径,两个数都是对的,量的不是同一件东西。

第三样打的是实弹。面板滚完三段调度器的旧收据,落下的是 `launching shell in ring 3`,咱们从 QEMU 的门口把键一组一组递进去。help 递了一组,echo hi 递了一组,yield 也递了一组。咱们把串口原文逐字贴在下面:

```text
cinux> help
commands: echo <text...>, help, yield, exit
cinux> echo hi
hi
cinux> yield
yielded and back
cinux>
```

每一个 h 走的都是整条链:主机递键,IRQ1 的中断进来,字符入了队,信号量 post 了一声,睡着的常客被请回 CPU,回显了一个字,又睡了回去。屏幕上的脸咱们也验了,把画面截下来数了数,前面的十来个文本行,行行都有亮像素——面板与演示同时落在 framebuffer 的控制台上,串口走了一份,屏幕上也留了一份,两张脸都是活的。末了机器停在提示符上,常客睡着了,当班的是 hlt 里的 Main,等的就是下一记键。

收卷之前咱们还想把后见之明集中数一遍,因为这一卷有个鲜明的脾气,它是收红利的一卷。当年把程序放进用户态的那段路上,有四样活是在现场救火补的,如今四样全提前有了着落。FPU 的上下文,当年是见了用户程序才现场补的,如今进程那一卷早把存档随任务带上了。SSE 的开禁,当年也是现场开的,如今会疼那一卷第一天就开了,面板第二行的那句 sse on 就是收据。当年 exit 还得给世上尚无调度器的日子留一条停机的退路,如今调度器是常在的,连防御分支都不必想了。变化最大的是排查的手段:当年两桩大案,两百多行的笔记,靠的全是 addr2line 加手插打印,一遍一遍地重跑拼现场。这一卷的案子,咱们靠反汇编当面对质,证据是面板与调试器直接读出来的,丢 IF 的那一桩,断点下去当场把机器按住了。红利是前头各卷一分一分攒下的。

末了,把卷首亮过的那颗北极星摘下来对一对。咱们说过,机器的远景是跑别人的程序:把 musl 装进来跑 busybox,再往远处 rootfs 里的程序都来上这套柜台递话。凭的就是这一卷垫下的三块砖。头一块定的是编号,read 的号是 0,write 的号是 1,yield 拿的是 24,exit 拿的是 60,全照 Linux x86_64 的原样。第二块定的是寄存器,rax 里装的是编号,参数各坐各的座位,rcx 与 r11 是硬件征用的。第三块定的是返回值,成功给的是正数,出错给负的 errno。三块砖说的是同一件事,人家编译好的二进制,进门是不用改一个字的。装库那一卷的 libc 为什么选 musl 不选 glibc,展开的理由留给那一卷,咱们这里只报一句路数——musl 静态打底,跟着的是 musl 动态,最远的那一级才是 glibc 动态,一级一级的台阶,踩的全是今天这三块砖。

对完了北极星,该交棒了。您看看常客的家底:echo 打出来的字,是您刚刚敲进去的,help 报的菜名,是编进镜像里的。shell 自己睡在内核镜像的怀里,整台机器的盘上一无所有。程序想从盘上被请进来的话,得等有了盘,有了文件,有了名字。下一卷开工的正是这摊差事,头一步是把文件和名字在内存里的盘上立起来,真正的盘,和程序从盘上被请进来的日子,都排在了更后面。这一卷合上的时候,机器是活的,客人是常驻的,柜台是通的。
