# 丢了的 IF

上一节的实弹是绿的:help、echo、yield 三轮往返,常客开张了。然后咱们让它闲下来——shell 阻塞在 read 上,等的就是一个键。键敲了下去,屏幕倒是纹丝不动。咱们当时在键盘中断的处理里临时加过一行诊断打印,它其实也没执行。这就有意思了,要是键盘的线断了,该报的是“收不到键”。现在连中断里的打印都不出,说明收键的活根本没人接,而中断压根进不来。

该 gdb 上场了。断点落在 Main 的 hlt,断住了,读到的 eflags 是 0x46。咱们单独看第 9 位是零,IF 是关着的。机器抱着关中断停了机:hlt 睡着,所以可屏蔽中断一个都进不来——NMI 之外谁也叫不醒它。丢失的不是键,是中断总开关:咱们顺着 gdb 的现场一路看下来,看到的正是它。

咱们顺着时间把链条捋一遍。链条的头一拍,SYSCALL 一进门就把 IF 清了,这是设计使然:写进 SFMASK 的值是 0x200,恰恰就是 bit9 的掩码,SYSCALL 通道出厂的时候就带着“进门就关中断”的设定。咱们往里再走一站,入口汇编把十二槽帧建完了之后,紧跟的是一条 sti,帧立好了,内核这才有接中断的底气,所以任务在 C++ 那一侧跑的时候,IF 是开的。咱们再往下走,就到了 read 阻塞,block_current 进门落的是一个 IrqGuard,IF 又被收走了,任务进了临界区,这是早就立下的纪律。到了切换这一拍,park 上场了,切换器的约定咱们背得出,通用寄存器加一份 FPU 的镜像,rflags 从来不在它的清单上——进程那一卷立的家法,切换器是不懂中断的。然后 Main 落了地,它继承的正是切换那一瞬的 IF,是关着的。末了,旧版的 run_until_done 出口没有守卫,排干了就返回,Main 抱着关中断走进了 hlt。您回头看,没有一环是在出错的,每一环都在照自己的家法办事。丢的是“谁来把 IF 还给 Main”的那一环,而这一环,是从来没人写过的。

那为什么进程那一卷没引爆?咱们把当年的机器形状摆出来看。那一卷的开中断只给了新任务蹦床,每个新任务的第一条指令就是 sti。任务之间切换时各自经自己的守卫还原。被抢占切走的任务回来时走的是 iretq,rflags 早躺在中断帧里了。唯独 Main 落地的路上没有还原点,可那卷的 Main 排干队列从不睡觉,IF=0 只是悄悄地路过,下一段演示一开张就被蹦床的 sti 盖了过去,其实谁也没看见。今天 Main 第一次 hlt——老伤这才上了台。

修法的第一版看着顺理成章,任务侧的三个出口:yield、park、exit,切走之前各补了一条 sti。咱们跑机内测试,结果是绿的。宿主侧的单测一跑,当场就报了段错误。为什么?sti 是特权指令,而调度器的代码是两个世界共用的,宿主测试进程链接的就是同一份实现,裸特权指令在宿主的用户态进程里,执行到那一行的时候,报的就是一发段错误。其实这正好是“一份声明、两组实现”家法的用武之地——同一份声明,内核世界拿到的是真关真开,宿主世界拿到的是空操作,选边的活儿留给链接期。中断开关的那一对函数,生下来的时候就是这个形状。裸 sti 绕开了这套家法,宿主世界替咱们把它拦下了。

定稿的修法咱们只动了一处,落在 run_until_done 的入口:

```cpp
void Scheduler::run_until_done() {
    const cinux::arch::IrqGuard kGuard;
    ...
    while (ready_.pop(next)) {
        current_    = next;
        next->state = TaskState::kRunning;
        enter_from_main_(sink_, *next);
        reap_pending();
    }
}
```

这段代码的语义,是把调度器的整个往返圈成一个临界区,Main 保存的是进门时的 IF,中断是一路关着的——任务阻塞、退出、排干全都罩在这一趟里,出门的时候 guard 析构,把 IF 还原成进门的样子。您数数这里的便宜。打头的是单点,一处就盖住了所有回到 Main 的路。跟着的是复用,用的是 guard 家族,还原看的是条件而不是无条件 sti,关着进的就关着出,嵌套也就天然安全了。末了一份是双轨,IrqGuard 是天生的双轨件,宿主侧走的是空操作,带进宿主世界的特权指令一行都没有。

为什么不在切换器里动 rflags?咱们有两个理由。头一个是约定:切换器的脸面就是通用寄存器加 FPU,咱们要它碰 rflags 就得扩那套约定,而所有调用点陪着改,跟着扩的还有验证面。第二个是时序:切换窗口里当前任务、栈、CR3 都换到了一半,而提前开中断,等于把一次中断放进一场没完成的切换。把 sti 包成钩子也躲不开:危险的是时机,指令落在了切换序列的中间。真正要守的性质是整个往返对外不可分,临界区恰好就是它的机器实现。

回归台得做成双向的,咱们两种初态各跑一轮。IF 开着进的那一轮,进门的时候量一遍 rflags 作基准,任务在信号量上睡去了,run_until_done 排干了回来,咱们再量一遍,量出来的结果得与基准一致,exit 的往返也同样再量一遍。关着进的那一轮,咱们在外面套一层 IrqGuard,把整套戏重唱了一遍,这回要求排干回来还是关的。醒来的任务也自己量一遍 rflags,IF 必须是开的,任务的世界里中断开着才是常态。为什么两个方向都不能省?咱们只测开着进的话,修法哪怕做成的是无条件 sti 也能绿。只测关着进的那一轮,忘了还原也照样是绿的。修完咱们实弹重打:同一个断点再读 eflags,读到的值是 0x206,bit9 翻成了 1。hlt 是睡得着也醒得来的——咱们一敲键,IRQ1 就进来了,全链从头再走了一遍。

机器真的活着了,面板与串口都能给咱们作证。下一节咱们收卷验收。
