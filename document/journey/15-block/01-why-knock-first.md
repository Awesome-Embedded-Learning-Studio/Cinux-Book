# 为什么是认门

上一卷立起来了整个名字的世界,可您把机器翻个底朝天,找不出一块盘。这一卷咱们把盘请进门。盘从哪来?咱们自己造:构建脚本在产物目录里建出一块空文件,把它撑到 1 MiB,再嘱咐模拟器一句——这块文件,你拿去当 AHCI 控制器上的硬盘。构建脚本的原文就这么几行:

```cmake
add_custom_command(
    OUTPUT ${CINUX_SCRATCH_IMG}
    COMMAND ${CMAKE_COMMAND} -E touch ${CINUX_SCRATCH_IMG}
    COMMAND truncate -s 1M ${CINUX_SCRATCH_IMG}
    COMMENT "scratch disk for the AHCI experiments")
```

`touch` 负责让文件存在,`truncate -s 1M` 负责把它撑到 1 MiB。模拟器那头,启动参数里挂一个 AHCI 控制器,再把这块文件当成硬盘接到它的口上。1 MiB 是 2048 个扇区,每扇区 512 字节——这就是咱们这块盘的全部家底。您要问了,为什么不给它弄个文件系统?因为这一卷认的就是裸盘:扇区就是扇区,字节就是字节,盘上是什么组织,答案留给下一卷。文件系统是下一卷的客人。

那为什么标题说认门?您想想盘在机器里的位置。它不在 CPU 的边上,也不在内存的边上,它插在总线上,总线后面还隔着 AHCI 控制器这么一位中介。想跟盘说上话,咱们得过三道门:总线的门(总线上插着什么,哪一台是存储)、控制器的门(寄存器在哪儿,引擎怎么开)、盘自己的门(它是谁,它听得懂什么命令)。三道门一道都绕不开。这一卷的四件活,就是按这三道门加一间值班室排的:

- **走线**:开机把 PCI 总线整个走一遍,报出七台设备,谁是存储控制器,一眼可查。
- **对讲**:推开 AHCI 的寄存器窗,把命令引擎的起停次序走对,学会 FIS 这套黑话。
- **验明**:一条 IDENTIFY 命令让盘自报家门,咱们拿六道准入查它的证件。
- **排队**:值班队列坐镇,多少个任务抢一块盘,也得一个一个来。

排队这件事值得多说一句,因为它管的是往后所有任务的体感。进程那一卷里咱们让任务学会了睡觉,调度器会挑人,可睡觉的人得知道等的是什么。任务想读盘,它睡在哪?谁叫醒它?叫醒的时候,数据到没到?这些问题的答案,是这一卷要添的两个新原语:发判决的 `Completion`,和睡觉用的 `EnableIrqAndHalt`。一个管判决,一个管睡姿,块队列把它们串在盘上。

末了预告一下面板。上一卷咱们交底说一行不添,这一卷翻了个个儿:开机面板添十行,而且全排在老面板头一行的前面。头七行是走线的收成,七台设备一台一行。再一行是总数。末了两行,是盘认下之后的自检汇报。验收那一章,咱们把这十行逐字端出来。现在,上总线。
