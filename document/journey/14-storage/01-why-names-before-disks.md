# 名字排在盘前

上一卷合上的时候,咱们数过常客的家底:echo 打出来的字,是您当场敲进去的,help 报的菜名,是编镜像时一起烤进去的,shell 自己呢,睡在内核镜像的怀里。盘上什么都没有——机器上压根就没有盘。要请更多的客人进门,靠往镜像里塞程序是喂不久的,程序得能从盘上被请进来。可是您低头看看,盘还没有。这一卷咱们办的,就是这件看上去本末倒置的事:盘连影子都没有,文件和名字就住进了机器。

住在哪?住在内存里,更准确地说,住在内核的堆里。头一个文件系统,咱们把它整个种在堆的字节上:文件的内容就是堆上的一段缓冲,开机的时候还随身带着一小份行李——两份小文件,编译时就烤进了内核镜像,落地即栽。这么干合理吗?您看名字是给谁用的:柜台后面的系统调用、将来的 C 库、rootfs 里的程序,人家认的全是名字。盘是名字背后真金白银的仓库,仓库晚一点进场,倒不耽误柜台把招牌挂起来。

当年这一段路,次序跟今天正好相反:从盘的实体动工,盘的驱动、拿内存扮的盘、文件系统的门面、盘上的文件系统,连成一大段一口气修完。这一遍咱们把它倒了过来,理由摆在地上:名字的世界立稳之后,真盘哪天来了,就是往门面后面再挂一个新后端的事。反过来讲,盘再大再快,没有名字的世界,它也只是一堆读得写的字节,程序拿它毫无办法。

这一卷的活,咱们点名四件。头一件,名字的规范:一条路名怎么念,一个名字多长算长。第二件,头一棵树:名字在内存里挂成什么形状。第三件,一座大门面:挂载表把后端藏在身后,客人只报路径,不问姓氏。第四件,一份随身的行李:编译期烤进镜像的小档案,开机就栽进树里。四件之外,还有三笔连带的家务:柜台一口气添五件业务,每个任务领一本文件册,顺手给全内核的锁立一张座次图。

还有一件事咱们说在卷首,省得您对着屏幕犯疑:这一卷的开机面板,一行都不会添。老十二行还是老十二行,变的只有里头两个数。这一卷看得见的变化,全在 shell 的会话里——ls、cat、echo 的重定向、mkdir、rm,件件都是新业务。验收那一章,咱们把整段会话逐字摆出来给您看。现在嘛,咱们从名字动身。
