# 行李箱的格式

开机要带的行李,长什么样?咱们的答案是磁带时代的老格式:tar。您没看错,就是把一堆文件打成一个包的那个 tar,它的底子叫 ustar——格式老得体面,好念,没有一层压着一层的历史包袱,内核里百来行就伺候得动它。选它的理由就这么实在:开机头一天,咱们要的就是一个读得懂、验得了的小册子。

ustar 的世界里一切按块算,一块 512 字节。每个条目开头是一块头部,数据跟在头部后面,不足一块的补足一块,念到全零的块,行李就到底了。头部这 512 字节里,咱们用得上的就四处,列成一张偏移表给您看:

```text
偏移 0    宽 100   名字,NUL 收尾
偏移 124  宽 12    大小,八进制的 ASCII 数字
偏移 156  宽 1     类型旗,'0' 是文件,'5' 是目录
偏移 257  宽 5     魔数,必须是 "ustar"
```

表上每一格都值得念一遍。名字这一项最宽,一百个字节,读到 NUL 为止都是名字。目录的名字带着尾斜杠进场,`docs/` 就是这么躺着的,栽树那一章咱们去它的尾。大小这一项呢,12 个字节装的居然还是字符:readme.txt 有 61 个字节,域里躺的就是 `00000000075` 这一串——075 是八进制,读回十进制恰好 61。当年设计的人,把磁带机的世界里什么都当字符传,数字也不例外,咱们尊重当年的古意,拿 `ParseOctal` 把它读回来。类型旗认两样半:字符 `'0'` 是文件,`'5'` 是目录,还有半样是空着的老条目——早年的 tar 给文件留白,咱们也当文件收。魔数的五个字节,咱们逐个比过,差一个都不认。

读取器拿着这些格子,咱们陪着它逐块往前走。每一步的次序是死的,咱们照代码的次序念。头一拍查的是截断:剩下的字节连一块头部 512 都凑不齐,这就是截断的档案,当场回错。第二拍看它全零不全零,全零,干净收工。第三拍对魔数,五个字符对不上,回 `kInvalidArgument`,不猜不救。然后读名字、解大小、认类型。末了数据登场,头在哪、按块补齐之后尾在哪,再过一遍边界,越过了照样拒收。半截的头部、截断的档案,在这套关卡的面前一律回错。

说到这儿,有一处咱们得跟您交底:真正的 ustar 头部里还有一个校验和的域,咱们这个读取器没有去验它。眼下的关卡就是上面那几道——魔数、边界、截断、类型。校验和拦的是另一种事故:字节在搬运的路上磕碰坏了。烤进镜像的档案没经历过搬运,镜像本身就是校验,校验和这一道,眼下就欠着。哪天档案改从真盘上进货,路上有了颠簸,它就得补上。格式里欠下的检查,咱们一页一页还。

这个读取器还有一个舒服的脾气,咱们也交代给您:零拷贝。`next` 递出来的条目,名字是档案内存上的视图,数据也是,一个字节都不抄:

```cpp
entry.name = std::string_view(
    reinterpret_cast<const char*>(kHeader + kNameOffset), kNameBytes.value());
entry.data = std::string_view(
    reinterpret_cast<const char*>(base_ + kDataHead), kSize);
```

咱们还得顺手交代一句 `kNameBytes` 的来历:名字的长度不是定数,得去头部的百格名字区里找 NUL 在哪儿收尾,`name_length` 干的就是这个活,它捧回来的是 `Result<unsigned long>`——查得回数、查不回错,`.value()` 把里头的数取出来用。道理也直白:您想,档案本来就躺在内核镜像的腹地里,它活多久,视图活多久,咱们再抄一遍纯属白费。真正的搬运发生在栽树那一步——档案是原件,堆里长出来的才是可写的活字。

格式认得了,读取器齐了。下一步,把它烤进镜像、开机栽进树里——下一章,咱们动工。
