# 锁的座次图

文件世界一进门,内核里持锁的地方多了起来:每座后端一把,文件册的每个动作也都在关中断的卫兵里过。挂载表呢,开机由文件世界挂那一回,眼下没有谁跟它抢,不上锁。锁一多,死锁这道老病就得认真对待。咱们不想拿“代码里没这么写”当保证,想让机器自己盯着:每一回拿锁都记一笔,谁在谁手里的时候又去拿了谁,全部画进一张有向图。图的顶点是锁,边是获取的次序——持着 A 的同时去拿了 B,就连一条 A 到 B 的边。环在哪?拿之前查一遍:这一手要是能让图上绕回自己,取锁的次序就埋着死锁的种子,当场 Check,机器响着停,您顺着栈就能把次序揪出来。

盯梢的差事,咱们交给一个叫 `LockOrder` 的类。它验收每一笔获取的里子是这样:

```cpp
for (const auto kHeld : held_.view()) {
    if (kHeld == index) {
        return Status::kRecursive;
    }
    if (graph_.reaches(index, kHeld)) {
        return Status::kCycle;
    }
}
```

手里已经攥着这一把,还伸手来拿,回 `kRecursive`——单核的世界里,这就是自己跟自己僵住。第二关查的是环,咱们把边的方向提前说死:待会儿要连的新边,从手里的锁指向新锁——箭头的起点是攥在手里的那把,终点是新进门的这把。而 `reaches` 查的是反方向:它从这把新锁出发,看回不回得到手里的锁,真回得到了,回的就是 `kCycle`。为什么这就断定了环?您想,图里要是已经躺着一条从新锁回到手里锁的路,今天再连上从手里锁指向新锁的新边,首尾在这一接里碰了头,环就合上了。绕得回来的次序,今天不死锁,改天也会。两关都过了,咱们才给手里每一把连上边,把这把新锁压进手里的栈。

给盯梢员配家当,咱们往 base 里添了三件容器,正好在这一章一起交底。头一件是槽表 `SlotTable`:固定容量,格子加占用位,插入发最低空槽,常量初始化,生下来就能躺进单例——它的差事这一卷有三份:挂载表是它,每个任务的文件册是它,锁的名册还是它,三种户口,一件家伙。第二件是定深栈 `StaticStack`:容量刻死在类型上,存储内联,不碰堆,手里攥着哪几把锁、里外次序如何,就是它那十几格。第三件是有向图 `DirectedGraph`:定员的有向图,连边、查可达、摘顶点,`reaches` 连零长路径都算——自己到自己,也算够得着。第四件 `RefCount` 您已经在 ramfs 那一章认过了,数数的小家伙,这里不算新面孔。三新一件旧,本卷往 base 里添的就是这四样。

容量这件事,咱们立的是宁响不漏:锁的名册 64 个位子,手里的栈 16 层,超了的回 `kCapacity`,Check 当场报——悄悄丢一条边,图的保证就成了纸面上的话,这样的便宜占不得。释放那头同样较真:只许弹手里的栈顶。里层的锁还没放,外层的倒伸手放,回 `kOutOfOrder`——中断开关的还原次序靠的就是这个里外,弹错一层,当时看不出什么,后患在别处爆发。销毁还有一道销户的手续。这里有个撞名的词,咱们得说开:咱们一路说的“活锁”,说的是还活着的锁,活生生放在内存里的锁对象本尊,跟并发课上那个互相谦让、谁也办不成事的 livelock 只是共用了两个字,说的压根不是同一样东西。锁的身份证,就是活锁的地址:锁对象住在内存的哪儿,身份证号就是哪儿的地址。ramfs 整个析构的时候,它那把锁的存储也要还。地址还了、名册还记着,下一个新锁万一落在这个地址,就顶了死人的身份。`retire` 就是回收前的销户——销户在前,还存储在后,ramfs 的析构函数里那一行,等的就是这里。

边界咱们如实交代:这道检查眼下只看着自旋锁的获取次序,Mutex 和 Semaphore 睡得着,次序另有记法,接到它们是往后的事。还有,盯梢员默认不在岗:构建给它备了真名的开关,叫 `CINUX_LOCKDEP`,默认关着,配置构建时点亮它,机器才带着这一章的座次图出门。lockdep 这个名字,白话说开就是 lock dependency,锁与锁的依赖:谁在谁手里的时候去拿了谁,座次图画的就是这样的依赖。仓库自带一份验收脚本,`scripts/checks/acceptance.sh`,把四条构建线各跑一遍,后三条都开着 `CINUX_LOCKDEP`。您要亲眼看看它干活,从脚本进门最省事。

座次图立完,咱们这一卷的家底盘齐了。下一章,把东西一件件摆上桌,验收。
