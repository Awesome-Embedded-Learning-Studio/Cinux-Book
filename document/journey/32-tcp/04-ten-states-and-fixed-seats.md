# 十个座位上的状态机

协议的头与门卫立住了,咱们进来看主人家。TCP 模块的家当,一言蔽之是三张固定座位的桌子。头一张坐的是连接,备了八个座,每一座是一整份连接的家当,这个咱们下面慢慢数。第二张坐的是听客,备了四个座,一个听客看的是一个口。第三张是最小的,藏在每个听座的背后,两个候客座:握手走完的连接在这里排队,就等 accept 把人领走了。座位都是固定的,满了答的是专名拒,不排没有边的队,这门纪律从端口表的八个座传下来,观察哨那十六座也是这么办的,咱们一路走到这里,家法是从来没变过的。

一个连接的一生要走十个状态。咱们把名字念一遍,顺手把戏份点了。关着的座是空的。SYN 已发:主动开门的一方把第一个握手包递出去了,就等回音了。SYN 已收:被动开门的一方回了一手,等的也是那一声认。通行:两头都通了,字节可以上路了,这是连接的正午,大部分的光阴在这里过。往后是道别的一段:fin 一等,自家的告别信递出去了,认它的还没来。fin 二等:告别信被认了,对端兴许还有没说完的话。对端道别等自家:对端把再见道了,轮到自家的告别信。同时道别:两边的信在海上擦了肩。末笔应答:被动道别的一方把信递了,欠的是一声认。而末一个状态多留一程,道别都道完了还要再守一程,它有一整章的戏,咱们到时候讲。

找座靠的是票。票备了两张:连接票与听票,而两张票长得一模一样,咱们看原文:

```cpp
struct TcpTicket {
    /// Which seat in the connection table.
    unsigned long slot  = 0;
    /// The seat's generation when the ticket was minted.
    unsigned long stamp = 0;
};
```

咱们在票上写两个词:座位号加这一座的代数。而座位每腾一回,这一座的代数加一。旧票再来敲门的话,对不上的是代数,门是不开的。连接表备了八个座,座号是转着圈用的,某一座的上一任是甲,票还在谁的手里攥着,甲的座腾了,乙搬了进来,恰好坐回了同一号。没有代数的话,甲手里的旧票能把乙的连接收走、关掉、读空。有了代数,旧票就成了废纸。这门手艺咱们在这一卷还要再用一回,钟的票也是这么印的。

段进了门,等着它的是四重审验。头一重的审验在词书,短、谎、越身的三拒,第二章咱们讲过。而第二重是校验和,折的是伪首部连同整段,折不拢零的话死得专名。第三重第四重在座位上:序列号跟这一连接的期待对不对得上,旧重复的段、越窗的段、认了没发过的字节的应答,各有各的判法,各有各的计数器,咱们随后几章一件件讲。而段死在哪一重,接住它的又是哪一口计数器,这套家法从校验与回环栈那一卷传到了今天,咱们一笔都没欠过。

最后一件家当讲完了,这一章就齐了:回调的送法。模块把消息送出去靠客人递进来的三张回执:到货、受理、道别,不过回执一律不在锁内点。收段的路上,事件一路收进一个待发的信封,咱们看信封的头一句是怎么写的:


头一句进门挂的就是事件源。然后该收的收,该答的答,锁放完了,信封是在闸外点的火。客人收到数据到货的回执,不过兴许当场就折回模块里来收包,收包是要拿锁的。要是回执点在了锁内,锁还没放而偏偏又要拿锁,自己等自己当场就结成死结了。闸外点火的话,自己等自己的路就断了。起手的版本里笔者踩过一回:挂事件源的只有受理与道别两处,数据的路上一声不响,长凳上数据的断言是鸣不出来的,查下来才知道信封是空着出门的。修法就是这一句的事:定死在了首句,任何路径进门头一句挂的是事件源,再办自己的事。
