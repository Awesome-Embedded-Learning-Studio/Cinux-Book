# 十个座位上的状态机

协议的头与门卫立住了,咱们进来看主人家。TCP 模块的家当,一言蔽之是三张固定座位的桌子。头一张坐连接,八个座,每一座是一整份连接的家当,这个咱们下面慢慢数。第二张坐听客,四个座,一个听客看一个口。第三张最小,藏在每个听座的背后,两个候客座:握手走完的连接在这里排队,等 accept 把人领走。座位都是固定的,满了就专名拒,不排无边的队,这门纪律从端口表的八个座传下来,观察哨那十六座也是这么办的,咱们一路走到这里,家法没变过。

一个连接的一生,走十个状态。咱们把名字念一遍,顺手把戏份点了。关着的座是空的。SYN 已发,主动开门的一方把第一个握手包递出去了,在等回音。SYN 已收,被动开门的一方回了一手,也在等。通行,两头都通了,字节可以上路,这是连接的正午,大部分光阴在这里过。往后是道别的一段:fin 一等,自家的告别信递出去了,还没被认。fin 二等,告别信被认了,对端兴许还有话没说完。对端道别等自家,对端把再见道了,轮到自家的告别信。同时道别,两边的信在海上擦了肩。末笔应答,被动道别的一方把信递了,只欠一声认。末一个状态多留一程,道别都道完了还要再守一程,它有一整章的戏,咱们到时候讲。

找座靠票。票两张,连接票与听票,长得一模一样,咱们看原文:

```cpp
struct TcpTicket {
    /// Which seat in the connection table.
    unsigned long slot  = 0;
    /// The seat's generation when the ticket was minted.
    unsigned long stamp = 0;
};
```

一张票两个词:座位号,加这一座的代数。座位腾一回,代数加一,旧票再来敲门,对不上代数,门不开。连接表八个座,座号转着圈用,某一座上一任是甲,票还在谁手里攥着,甲的座腾了,乙搬进来,恰好坐回同一号。没有代数,甲手里的旧票能把乙的连接收走、关掉、读空。有了代数,旧票就是废纸。这门手艺咱们在这一卷还要再用一回,钟的票也是这么印的。

段进了门,四重审验等着它。头一重在词书,第二章讲过,短、谎、越身,三拒。第二重校验和,伪首部连同整段折拢,折不拢零死得专名。第三重第四重在座位上:序列号跟这一连接的期待对不对得上,旧重复的段、越窗的段、认了没发过的字节的应答,各有各的判法,各有各的计数器,咱们随后几章一件件讲。死在哪一重,哪一口计数器接住,这套家法从校验与回环栈那一卷传到今天,一笔没欠过。

最后一件家当讲完,这一章就齐了:回调的送法。模块把消息送出去靠客人递进来的三张回执,到货、受理、道别,可回执一律不在锁内点。收段的路上,事件一路收进一个待发的信封,咱们看信封的头一句是怎么写的:

```cpp

                               size_t segment_length, PendingFire& fire) {
    fire.events = connection.events;
```

头一句,进门就挂事件源。然后该收的收,该答的答,锁放完,信封在闸外点火。客人收到数据到货的回执,兴许当场就折回模块里来收包,收包要拿锁。要是回执在锁内点,锁还没放又要拿锁,自己等自己,当场死结。闸外点火,自己等自己的路就断了。起手的版本里笔者踩过一回:事件源只在受理与道别两处挂,数据的路上一声不响,长凳上数据的断言鸣不出来,查下来才知道信封空着出门。修法就是这一句定死在首句,任何路径进门头一句挂事件源,再办自己的事。
