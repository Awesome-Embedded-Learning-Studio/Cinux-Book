# 流式的成员进门

协议层的活到上一章齐了,可客人的手里还是拿不到:客人拿的是描述符,连接票是不到客人手里的。这一章咱们把流式的成员送进套接字的家族,上一卷门后那句诚实拒在这里兑现:类型字要流式的,门后站着真的东西了,协议字是点六或留空的,别的是不认的。socketpair 照旧答的是不支持,那扇门后是没有东西的,空着比挂假门是更诚实的,老话是不改的。

咱们看成员的长相:一张票,跑的是两态。TcpSocket 出生的时候什么都不是:bind 记下自家的口,listen 换的是一张听票,攥在模块的听座上。connect 换的是一张连接票,连着模块的连接座。两态是不并立的,听着的时候就不能再去连,连着的时候就不能再听。accept 递下来的新套接字最省心,出生就是已开的连接:候客座里的票递过来,对家的地址从模块问一句,新成员是不握手的,握手是爹娘在协议层早就办完的事。它在描述符表里就是一件普通的文件,read 落进收的路,write 落进发的路,外衣是上一卷缝好的那件,一针是没有改的。

listen 与 accept 背后的那套机制,上一卷收卷时交代要立的,咱们看 accept 的门怎么等。等的圈子是上一卷 recvfrom 那四步,原样搬了过来:

```cpp
        if (kTaken.error() != base::KernelError::kWouldBlock) {
            return kTaken.error() == base::KernelError::kNotSupported
                       ? -kEopnotsupp
                       : errno_of_socket(kTaken.error());
        }
        // accept4 flags apply to the new descriptor. Only the listener's
        // O_NONBLOCK decides whether an empty queue may wait here.
        if ((held->status_flags & kOpenNonblock) != 0) {
            return -kEagain;
        }
        if (signal_pending()) {
            return -kEintr;
        }
        proc::Scheduler::self().yield();
```

引文里的那半句特判,咱们交代明白:accept_one 递回来的错读出 kNotSupported,门答的是 EOPNOTSUPP,不走 errno_of_socket 的公用表。有它的道理:公表把 kNotSupported 映成 EMSGSIZE,那个号是给 UDP 大包超限预备的。listen 与 accept 这两扇门共用公表就成了误报,所以两处各自特判,答的是操作本身不支持。候客座是空的,答的是 would-block,门看意愿:描述符生下来带着非阻塞位的,是不陪等的,答的是 EAGAIN。有信号候着的,答的是 EINTR,门外的投递照老章程办。都不是的话,让出一圈的位子来,把处理器交了出去,下一圈回来了再看。没有期限:客人挂一个口在后台等的是人上门,等多久都是该等的,期限是咱们替人做的主,咱们不做。accept4 的两个旗要分家,注释里的原话说得明白:旗归新生的描述符,听者自己身上的非阻塞位才决定门里等不等。旗里认出了别的位,答的是 EINVAL,生面孔是不装熟的。

connect 的门里立了这一卷唯一一处任务侧的软限,咱们把三态念齐。门办的头一件事是把 SYN 递出去,然后一圈一圈地等:对端回了 RST,握手就算失败了,答的是 ECONNREFUSED,门没开就是没开的。七十五秒软限到了还握着手,答的是 EINPROGRESS,连接是还在路上的,客人拿这个号去问进程的也好、拿它去等拨号音的也好,是客人的事。通了,答的是零。软限这个数不是拍的,回环上是一瞬就通的,真线上跨洋是一百多毫秒的量,重传五次花满也就一分钟的量,七十五秒是罩得住的,又不至于把死等的客人吊太久。

shutdown 这一回是有真话可答的。参数要的是一,送的是告别信,close 的路数,半闭是这一卷真给的。答二收向的关,答的是不支持,收的路由对端的信说了算,咱们不冒充。过了二,答的是 EINVAL,数的范围都不对。sendto 的限额按出生的类型分三档:裸的一千四百八十,流式的一个最大段是一千四百六十,数据报的一笔是一千四百七十二。流式的限额最小,短写在这里是家常便饭:窗就那么宽,一笔递不下的分几笔,字数是如实报的,客人按报的数续递,这正是流的语言。

上一卷撂过一句整包的话:可打断的真睡、软超时、唤醒的令牌,排在了下一卷。现在下一卷写到了门口,咱们对单。钟立了,内核侧的等待吃上了它,重传与多留一程都是靠钟活的。软超时在 connect 的门里开了一回张。可圈还是让位的圈:任务还在调度圈的座位上,一圈一圈地醒,睡进自己的上下文、有人拿令牌来唤醒,这两样是没立的。咱们不把话说满,单子续了期,挂在了明处。长凳三案守着这一章:回环口上一场完整的会话穿过 accept。挂上真网卡再验回环的握手与字节,是照旧的,这一案是下一章那桩案子结了之后回头补上的,时序上它排在了后头,名字是记在这里的。写的人早走一步,套接字销毁递的是道别不是撕脸,计数器里 RST 是一笔没记的,候客座里的字节与流尽替他守着,accept 把人领了进来,读到最后一笔的时候还有货,读完答的是零。死讯的发送半边顺手交代:自家的告别信递了,发送的路就算打烊,客人还往里递字的话,门答的是 EPIPE,管子断了。收的方向答流尽,发的方向答断管,与道别那一章报被拒走的是同一口径:死讯不走回调,是挂在票上的,哪头的门被问,如实答的也就是哪头。还有一案专考旗的分家,accept4 的旗落在新描述符的身上,听者是不带的。成员进了门,戏台齐了。
