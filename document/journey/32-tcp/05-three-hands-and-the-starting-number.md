# 三次握手与起始的号

连接的开场分两路走,咱们把两路都走到。主动开的一方走 connect:模块领一个空闲的连接座,口要是没人报名,悄悄领一个短命号码落座,短命号码的挑法跟上一卷 UDP 一个模子,从段首扫起,头一个没主的号。然后是这一章真正的角色登场,起始序列号。咱们照主动开的原文念:

```cpp
    const uint32_t kIss        = (isn_cursor_ += kIsnStep);
    connection->snd_una        = kIss;
    connection->snd_nxt        = kIss;
    transmit_segment(*connection, kTcpFlagSyn, nullptr, 0, connection->snd_nxt);
    connection->snd_nxt = kIss + 1;
```

一个计数器,每个连接来读一回,读一回加一大步,步长是个定数。SYN 递出去,占一个号,所以下一笔从加一的地方起:序列号的空间里,SYN 自己就是一个货,一个字节的货都没带,它也占一号。这是 TCP 全部生意的第一原则,咱们在这一卷反复要用的:SYN 占一,FIN 占一,数据占它的字节数,谁也不豁免。

被动开的一方在听座上等。SYN 到了没人听的口,那是后面对抗负测的戏。到了有人听的口,模块替听客领一个连接座,把两边的号都记下:对方的号加一,记作本连接期待的下一笔,自家的号也起一个,SYN 加 ACK 一手递回,同样占号加一。咱们跟着第三手回来:一个不带货的纯 ACK,客户端把服务端那一手的回执捎了回去。这一手到,服务端把连接升成通行,受理的铃响,票挂进听座背后的候客座,accept 随后来领人。

三次,为什么不是两次?您也别急着答,咱们把错的版本摆出来看:两次的版本是客户端的 SYN 到、服务端一手 SYN 加 ACK 回,握手就算完。可服务端凭什么确信自己那一手到了?没到,客户端不知道连接的存在,服务端却已经把门开了,座占了,字节流等着,等来的是一场空。三次握手的第三手就是给这个疑问的回执:客户端收到服务端那一手,顺手把纯 ACK 捎回去,不另起炉灶。服务端见着第三手,两头的手都验完了,这才开门挂铃。当年第一遍的笔记里就记着一条不变量:第三手的 ACK 值必须恰是自家的下一笔,差一点都不算,咱们这个版本照判,对不上就死在 ack_beyond_dropped 那口计数器里:偏高,是认了没发的字节。偏低,也一并归它接。

起始的号,咱们单独讲,因为它的设计里藏着一层防。为什么不从零起,不从固定数起?因为线上的段会迟到、会迷路、会在网线里游荡很久才撞进某个门。同一条四元组,旧连接的段还在海上漂,新连接开了,要是两代的号从同一个数起,旧段的名字恰好落进新连接的期待里,一个幽灵就把新连接的字节流搅了。所以每一连接的号都要错开。当年的版本是确定性递增:计数器起 0x4000,每个连接加六万五千五百三十六,不同连接的号空间测试里不重叠。这一遍换了步长:

```cpp
constexpr uint32_t kIsnStep = 0x9E3779B9;
```

黄金比例的分数常数,二进制里每一位都参差着,每个连接跨一大步,相邻连接的号空间咬不着。可咱们得把话说全:这仍是确定性递增,不是随机。真的随机化,当年的欠单上明记着,对齐的是地址随机化那一路的思路,防的是有心的对门掐着规律猜号。这一卷不还,如实续欠,长凳要的确定性,全靠它可复现。

座满的答话也立在这儿,咱们听机器怎么答。听座在、连接座满了,SYN 进门,refused_full 专名记一笔,回一个 RST 礼貌送客:八个座都满员的机器,第九个连接就是这么被答的,不装能接。候客座满了呢,握手照走,票挂不进队,accept 慢一步,人就得重敲。
