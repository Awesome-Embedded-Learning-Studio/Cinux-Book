# 三次握手与起始的号

连接的开场分两路走,咱们把两路都走到。主动开的一方走 connect:模块领一个空闲的连接座,口要是没人报名的话,就悄悄领一个短命的号码落座,短命号码的挑法跟上一卷 UDP 一个模子:从段首扫起,拿头一个没主的号。然后是这一章真正的角色登场:起始序列号。咱们照主动开的原文念:

```cpp
    const uint32_t kIss        = (isn_cursor_ += kIsnStep);
    connection->snd_una        = kIss;
    connection->snd_nxt        = kIss;
    transmit_segment(*connection, kTcpFlagSyn, nullptr, 0, connection->snd_nxt);
    connection->snd_nxt = kIss + 1;
```

起始号的出处靠的是一个计数器:每个连接来读一回,读的每一回加一大步,步长是编译期就定下来的。SYN 递出去了,占了一个号,所以下一笔从加一的地方起:序列号的空间里,SYN 自己就是一个占号的货,一个字节的货都没带,它也占了一号。这是 TCP 全部生意的第一原则,咱们在这一卷反复要用的:SYN 占的是一号,FIN 占的是一号,数据占的是它的字节数,豁免是一个都没有的。

被动开的一方在听座上等。SYN 到了没人听的口,那是后面对抗负测的戏。到了有人听的口,模块替听客领下了一个连接座,把两边的号都记下:对方的号加一,记作本连接期待的下一笔,自家的号也起一个,递回的是 SYN 加 ACK 这一手,同样占了号加一。咱们跟着第三手回来:一个不带货的纯 ACK,客户端把服务端那一手的回执捎了回去。这一手到了,服务端把连接升成了通行,受理的铃响,票挂进听座背后的候客座,领人的 accept 随后就到。

要的是三次,为什么不是两次?您也别急着答,咱们把错的版本摆出来看:两次的版本是客户端的 SYN 到、服务端一手 SYN 加 ACK 回,握手就算走完了。可服务端凭什么确信自己那一手到了?没到的话,客户端不知道连接的存在,服务端却已经把门开了,也把座占了,候着的是字节流,等来的是一场空。三次握手的第三手就是给这个疑问的回执:客户端收到服务端那一手,顺手把纯 ACK 捎了回去,炉灶是不另起的。见着第三手的服务端,两头的手都验完了,这才开了门挂上铃。当年第一遍的笔记里就记着一条不变量:第三手的 ACK 值必须恰是自家的下一笔,差一点都不算数的,咱们这个版本照判,对不上的就死在 ack_beyond_dropped 那口计数器里:偏高,是认了没发的字节,偏低的话,也一并由它接了。

起始的号,咱们单独讲,因为它的设计里藏着一层防。为什么咱们不从零起,也不从固定数起?因为线上的段会迟到、会迷路、会在网线里游荡很久才撞进某个门。同一条四元组上旧连接的段还在海上漂,新连接开了,要是两代连接的号从同一个数起,旧段的名字恰好落进新连接的期待里,一个幽灵就把新连接的字节流搅了。所以每一连接的号都要错开。当年的版本是确定性递增:计数器起 0x4000,每个连接来了就加六万五千五百三十六,不同连接的号空间测试里不重叠。这一遍换了步长:

```cpp
constexpr uint32_t kIsnStep = 0x9E3779B9;
```

黄金比例的分数常数,二进制里每一位都是参差的,而每个连接跨一大步,相邻连接的号空间是咬不着的。可咱们得把话说全:这仍是确定性递增,随机的成分一点没有。真的随机化那一笔,当年的欠单上明记着,对齐的是地址随机化那一路的思路,防的是有心的对门掐着规律猜号。这一卷是不还的,而欠是如实续在明处的,长凳要的确定性,靠的是它可复现。

座满的答话也立在这儿,咱们听机器怎么答。听座在、连接座满了,SYN 进了门,refused_full 的专名记一笔,回一个 RST 礼貌地送客:八个座都满员的机器,第九个连接就是这么被答的,不装出一副能接的样子。候客座满了,握手照走它的,票是挂不进队的,accept 慢了一步,人就只好重敲了。
