# 错侧的源地址与顶爆的栈

协议的活齐了,门也开了,实弹一开张,翻出来的头两桩就是案子。两桩都差点冤枉好人,咱们一桩一桩结。

咱们从头一桩结起:回环上的握手死活不通。排面是这样的:挂上真网卡,起 nc,客户端的 SYN 递出去,服务端的听座在等,然后就没有然后了,accept 等了约二十秒,答一声 EAGAIN 早退收场。当时的怀疑按次序来:一头疑等待的毛病,可等待的圈四步写得端端正正。再疑开机镜像里装的不是新码,证据是启动行打出来的字节数,跟编译出来的内核文件对不上,越看越像旧镜像。查到底,两个疑都是表象,根子在别处。

咱们把根子挖出来,居然是源地址错侧。

世界起手落在回环上,自家地址是 127.0.0.1。挂了线,自家地址重指成十点零点二点十五。TCP 组包的时候,源地址一贯取自家地址,这在只挂回环的日子里天经地义。可现在发往 127.0.0.1 的段,源地址也取了十点零点二点十五:货走的是回环的道,名牌却写着外线的号。服务端收到 SYN,把对端记成十点零点二点十五,回 SYN 加 ACK 的时候,咱们跟着它查一回路由:目的地不在回环网,也不等于回环号,按外线的章程递给网卡,ARP 问路,段从真线上飞走,一去不回。握手断在半路。那二十秒的早退是哪一层叠出来的,当时没有深究,只把它记在案上。案子最后结在根子上,源地址修对,握手一通,早退跟着一起销案,再没回来。

> 启动行那笔疑也有下文:那一行打的从来是内存尺寸,文件尺寸与内存尺寸本就不是同一个数,一个疑云两案同结。修法把两个数分开打,以后谁再疑镜像,一看便知。

修法一行函数,咱们立在这儿:

```cpp
constexpr uint32_t SourceAddressFor(uint32_t own_address, uint32_t destination) {
    return (destination & kLoopbackNetMask) == kLoopbackNet ? kLoopbackAddress : own_address;
}
```

按目的地取源地址:目的地在回环网里,名牌用回环的号。走外线,用自家外线的号。这一句立下之后,咱们把四处取词全部统一:IPv4 组包一处,TCP 的段与 RST 各一处,UDP 的伪首部一处。为什么非要一处不落,因为伪首部押的就是 IP 头里的源与目的,头里写一个号、校验和折的是另一个号,收方一折就死,错得比不通还隐蔽。接着补一笔:自发自收也走回环,目的地等于自家号的货,不再外线绕圈。这一案最扎心的地方在长凳:手摇的世界里自家地址永远是回环号,错侧根本无从发生,host 全过,ktest 全过,过得恰好把病盖住。所以结案之后长凳添了一案:头一件挂真网卡,再验回环的握手与字节,把挂线这个前提本身钉进测试。

第二桩,咱们接着结,屏幕与串口分了叉。机器活着,测试也在过,可屏幕上落的字与串口里记的对不上,输出像被人随机咬了几口。这一案的方向一开始就偏了,疑过输出的锁,疑过两颗核抢串口,都不是。根子在连接块入座的那一句:

```cpp
        // Reconstruct in the table: an assignment from Connection{} creates
        // a ~14 KiB temporary on a 16 KiB kernel stack with this toolchain.
        seat.~Connection();
        new (static_cast<void*>(&seat)) Connection{};
```

咱们看注释,写的就是病历。一个连接块,收件箱、底稿环、四个修包座,加起来约十四 KiB。入座起手写的是一句普通的赋值,右边的临时对象在调用者的栈帧里造出来再拷过去,内核的栈十六 KiB,一个临时就顶掉九成。连接一开张,栈越界,踩的不是自家院里的东西,是隔壁输出的缓冲,于是字被咬了几口,机器还一脸无辜。修法就是这两行:就地析构旧的,再在原地把新的放置生出来,临时一个都不造。往后这个文件挂上栈深的警钟,一帧超四千字节,编译器当场叫,不等人踩。
