# 十六个座的钟

还单的次序走到最要紧的一步。当年旧单上的重传、往返估算、道别后的多留一程,好几笔债的原因栏写的是同一句话:需要内核的定时唤醒基建,当年没有。所以这一卷还单,咱们头一件还的不是债本身,是那句原因。基建立起来,后面每一笔才有落笔的地方。

这件活儿本身的来历值得交代一笔。起手的打算里,它登记在远期:让 TCP 自己揣一张截止表,泵每摇一圈顺手扫一眼。备料的时候笔者改了判,理由说出来不复杂:生产内核里定时的器件是标配,人家有的东西,咱们最好也做一下,别让教学机的栈长出一副只有这一卷认得的骨头。于是器件立进了时钟的家里,与单调钟住同一处,做的是最通用的一件事:谁有约,把时间、上下文、要叫的函数留下,到点它叫人。它不知道什么叫重传,也不认识 TIME_WAIT,它只管到点。

形状咱们从叫人的那一头看。一个座要收两个运行期的值:叫谁的事,加拿着谁。两个值装不进一个擦除的函数词,这是类型擦除的老难题,解法是蹦床:座里存一个裸的函数指针加一个裸的上下文,函数指针指向一个静态的蹦床,蹦床把上下文还原成对象的指针,再叫它真正的成员函数。这门手艺不是新发明,早在会听那一卷,时钟家里管节拍的 Tick 老哥就带了这个头,这里照着来。表本身十六个座,固定,满座答一个 kOutOfMemory 的专名拒,不排队,老纪律。租约的写法与连接票一门手艺,座位号加代数,咱们不多讲,只讲它比连接票多走的一格:

```cpp
void TimerTable::advance(TimerDeadline now) {
    for (Seat& seat : seats_) {
        if (!seat.used || now < seat.deadline_ns) {
            continue;
        }
        const unsigned long kStamp   = seat.stamp + 1;
        void* const         kContext = seat.context;
        void (*const kCall)(void*)   = seat.call;
        seat                         = Seat{};
        seat.stamp                   = kStamp;
        kCall(kContext);
    }
}
```

您看这一段:到点的座,把要叫的人抄进局部,再把座清干净,代数加一,然后才调用。清座在调用之前,这一步次序是器件的全部性格。回调进门的时候,自己的座已经是空的:它想把同一座再租回去接着用,可以,新租约的代数是旧票的加二。它想把别的座退了,可以。它什么都不动,也行。咱们反过来想错会怎样:要是清座放在调用之后,回调一路重租、一路退租,退到自己头上,座处在半死不活的中间态,回调的余下部分就踩在悬空上。清座在前,调用在后,回调看到的永远是干净的表。

摇钟的人也有章程。advance 不自带锁:谁喂时间,谁负责这一趟的安稳。这一卷里,咱们让摇钟的永远是 TCP 模块的检修趟。检修趟是泵每摇一圈都要跑的一趟巡检:泵把线上的包问一圈,再叫模块进自己的锁里,推一回钟,给还欠着回执的连接挂重传的座,收拢要出门的信封,出锁再点。模块自己的锁把整趟罩住,表因此一件锁都不用穿。表自己也薄,整个器件常量初始化,单例的形状照着 Tick 的老例,第一次问它要之前,谁都不用铺路。

长凳六案,咱们挨个点名。一案到点一响,响一回不响第二回。二案退了租的座哑到底。三案烧过的票再拿来退租,答的是退不动,座位号对得上,代数对不上,门不开。四案最要紧:回调里把自己的座再租出去,租得成,新的约定照常到期照常响,重传的钟往后全靠这一手活着。五案十六个座租满,第十七个约,专名拒。六案一趟里几个座接连到期,按座序挨个响完。六案全过,器件立住了。接着轮到它的头一个消费者:等不到回答的时候,该等多久。
