# 三声一样的应答与四个修包座

上一章的重发等钟叫人,钟是笨办法里的稳妥办法:什么都不知道,就按估的等。可这一卷写到这儿,咱们手里其实多了一样新东西:对端也是自家栈,它收不着期待的号,不会一声不吭。您想它的处境:期待第一千号,海上漂来第一千一百号,它收不了,可它也不能装聋,它得答话,答什么,把自己的期待号重申一遍。于是发送侧看见的景象是:三声应答,三个应答值一模一样,都停在同一个没被认的号上。它在指路:一千号到一千一百号中间,缺了一块。

判法咱们拿真的排一遍:

```cpp
    } else if ((view.flags & kTcpFlagAck) != 0 && view.acknowledgement == connection.snd_una &&
               segment_length == 0 && connection.snd_una != connection.snd_nxt) {
        ++connection.duplicate_acks;
        if (connection.duplicate_acks >= kTcpFastRetransmitAcks) {
            connection.duplicate_acks = 0;
            ++stats_.fast_retransmits;
            resend_oldest(connection);
        }
    }
```

四个条件一个不能少:旗立着,答的是应答。应答值恰好停在最老的未认号上,一步没走。段长为零,纯应答,不带别的货。在途确实有货。都齐了,重复的应答记一声,攒到第三声,最老的一段当场补发,不等钟。三声这个数不是拍的,咱们把海上的情形想一遍:段不一定按发的次序到,后发的反而早到,收方也会重申期待,一声两声可能只是路走岔了,第三声才认下丢了这件事。还有一条分寸:这笔补发不占放弃的额度。重传的预算五次,是给沉默的准备。三声一样的应答是热闹的丢,对端明明活着还在说话,不该拿沉默的尺子罚它。

收的一侧,咱们看它对称地办事。段进来,头一道过旧重复的判法:整段都落在期待号之前的,重申一声现状,游标不动,号码带那一章讲过。还有一种骑线的:起点在期待号之前,尾巴伸到之后,这是重传的新版本,头部被跳过,新尾巴照收,怎么收怎么算,下一章讲收件的窗时一并算齐。真正的乱序货是第三种:起点落在期待号之后,中间隔着缺口。它不能进收件箱,号的次序是这一卷的天条,可丢了也白瞎,对端要重发一遍。于是给它备了四个修包座,一座记起点、字节数,加一段底稿。收割的判法朴素到家:

```cpp
            if (!seat.used || seat.start != connection.rcv_nxt) {
                continue;
            }
```

座的起点恰好等于期待号,缺口填上了,整座搬进收件箱,期待号往前推。推完咱们不收工,循环再扫一遍:修包座里的货常常是连着缺的,补上一号,下一座恰好又对上了,一茬一茬收下去,直到没有座对得上。

拒收的单子咱们照实念,每一拒都专名计数。带告别信的不收:信也占号,还牵着状态机的道别,让它躺在缺口里过夜,收的时候状态怎么迁,算不清,宁可等对端重发。零长的、比一个最大段还胖的、起点越出接收窗的,不收。与已入座的货重叠的,不收,缺的又不是它。四座满了,第五段专名拒,不排无边队,老纪律。拒归拒,重申期待的纯应答照答,对端的重传有的是路回来。这一章的两件,快速重传与修包座,当年欠单上写的是乱序直接丢、不缓存,今天连本带利还清:丢的那一半改成暂存,等的那一半改成听暗示。
