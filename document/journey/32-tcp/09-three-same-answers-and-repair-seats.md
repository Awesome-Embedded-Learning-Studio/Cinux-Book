# 三声一样的应答与四个修包座

上一章的重发等钟叫人,钟是笨办法里的稳妥办法:什么都不知道,就按估的等。可这一卷写到了这儿,咱们手里其实多了一样新东西:对端也是自家栈,它收不着期待的号,是不会一声不吭的。您想它的处境:期待第一千号,海上漂来了第一千一百号,它收不了,可它也是不能装聋的,它是得答话的,答的是什么,把自己的期待号重申一遍。于是发送侧看见的景象是:三声应答,三个应答值是一模一样的,都停在同一个没被认的号上。它在指路:一千号到一千一百号的中间,缺了一块。

判法咱们拿真的排一遍:

```cpp
    } else if ((view.flags & kTcpFlagAck) != 0 && view.acknowledgement == connection.snd_una &&
               segment_length == 0 && connection.snd_una != connection.snd_nxt) {
        ++connection.duplicate_acks;
        if (connection.duplicate_acks >= kTcpFastRetransmitAcks) {
            connection.duplicate_acks = 0;
            ++stats_.fast_retransmits;
            resend_oldest(connection);
        }
    }
```

四个条件一个不能少:旗是立着的,答的是应答。应答值恰好停在最老的未认号上,是一步都没走的。段长取的是零,是纯的应答,不带别的货。在途确实是有货的。都齐了,重复的应答记一声,攒到了第三声,最老的一段当场补发,是不等钟的。三声这个数不是拍的,咱们把海上的情形想一遍:段不一定按发的次序到,后发的反而早到,收方也是会重申期待的,一声两声可能只是路走岔了,第三声才认下丢了这件事。还有一条分寸:这笔补发不占放弃的额度。重传的预算五次,是给沉默的准备。三声一样的应答是热闹的丢,对端明明活得好好的还在说话,不该拿沉默的尺子罚它。

收的一侧,咱们看它对称地办事。段进了门,头一道过旧重复的判法:整段都落在期待号之前的,重申的是一声现状,游标是不动的,号码带那一章是讲过的。还有一种骑线的:起点在期待号之前,尾巴伸到了之后,这是重传的新版本,头部是跳过去的,新尾巴是照收的,怎么收怎么算,下一章讲收件的窗时一并算齐。真正的乱序货是第三种:起点落在期待号之后,中间隔着的是缺口。它是不能进收件箱的,号的次序是这一卷的天条,可丢了也白瞎,对端是要重发一遍的。于是给它备了四个修包座,一座记的是起点、字节数,加的是一段底稿。收割的判法朴素到家:

```cpp
            if (!seat.used || seat.start != connection.rcv_nxt) {
                continue;
            }
```

座的起点恰好等于期待号,缺口填上了,整座搬进了收件箱,而期待号往前推。推完咱们不收工,循环再扫一遍:修包座里的货常常是连着缺的,补上了一号,下一座恰好又对上了,一茬一茬地收下去,直到没有对得上的座。

拒收的单子咱们照实念,每一拒都有专名的计数。带告别信的不收:信也占号,还牵着状态机的道别,让它躺在缺口里过夜的话,收的时候状态怎么迁,是算不清的,宁可等的是对端重发。零长的、比一个最大段还胖的、起点越出接收窗的,是不收的。与已入座的货重叠的,也是不收的,缺的又不是它。四座满了,第五段答的是专名拒,无边队是不排的,老纪律是照旧守着的。拒是拒了,重申期待的纯应答是照答的,对端的重传有的是路回来。这一章的两件:快速重传与修包座,当年欠单上写的是乱序直接丢、不缓存,今天连本带利还清了:丢的那一半改成暂存,等的那一半改成听暗示。
