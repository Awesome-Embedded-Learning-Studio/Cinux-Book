# 号码带上的算术

序列号住在一条环形的号码带上:一圈三十二位无符号的数,头尾是相接的,一圈走完了是四十二亿九千多万个号。一条连接把自己的每一个字节都编在带子上,写得久了,号会从大往小绕:0xFFFFFFFC 的下一笔是 0xFFFFFFFD,再往下三步就绕回了 0x00000000。绕回的这一下,朴素的大小比较当场翻车。咱们拿两个号看:0xFFFFFF00 与 0x00000010。拿无符号的比法比,前者比后者大了四十二亿多,可它其实是前辈,后者是绕了一圈之后的晚辈。而谁在前谁在后,这道题在环上是不能拿大小答的。

这里的解法是模差,咱们看,两行就够了:

```cpp
bool seq_before(uint32_t left, uint32_t right) {
    return static_cast<int32_t>(left - right) < 0;
}
```

咱们拿两个号相减,减完的差读成有符号的三十二位。同一圈里的两个号,真差不过半圈的时候,这个读法把次序答得分毫不差:差是负的,在前的是 left。差是正的,在后的是 left。差恰好是半圈的话,这门算术就答不了,而次序在环上本来就是不成立的。可咱们不怕:半圈是二十一亿多的号,一条连接的窗口四千零九十六字节,在途与期待的号都挤在眼前几步地,而离半圈远得很。这门算术的适用范围,恰好罩住协议的工作范围,而一分都不浪费。

一条连接的发送侧靠两个游标,接收侧用的是一个,咱们把三个都数一遍。最老的未被认的号,记的是发送缓冲里头一个还没拿到回执的货。下一笔要用的号,记的是字节流往前写的笔尖。夹在两者之间的,就是在途的字节:递出去了,认它的还没来。对方的 ACK 值答的就是老游标与笔尖中间的某个位置,认到了哪儿,老游标就滑到了哪儿。接收侧的游标记的是期待对方的下一笔,后文咱们简称它读标,我方每一个段里 ACK 字段答的就是它。三个游标是这么分工的,两头各记各的,一条流的进度全在三个数里。

段的长度,咱们按占号数,占多少号在进门那一步就算清了:

```cpp
    const size_t kPayloadBytes  = length - view.header_bytes;
    const size_t kSegmentLength = kPayloadBytes +
                                    ((view.flags & kTcpFlagSyn) != 0 ? size_t{1} : size_t{0}) +
                                    ((view.flags & kTcpFlagFin) != 0 ? size_t{1} : size_t{0});
```

载荷的字节数照算,SYN 立着的加一,FIN 立着的也加一。为什么非这么算,咱们错一回看:FIN 要是白占座不算长,对端把 FIN 认下来了,ACK 的值就得比笔尖小一,而发送侧拿 ACK 一滑,滑是滑不到笔尖的,道别也就永远悬着了。SYN 是同样的道理,握手第三手的值就差那一。占了号的就有一份长度,旗标是没有豁免的,这门生意的纪律全在这一句里。

旧重复段的判法直接长在这门算术上,咱们跟着一个段进门看。把它的起点加占号长,得它占的末格。整段都落在了期待游标之前,模差一比就比出来了,这认的就是一段旧货:上个月认过的字节,今天又漂来了。答法不是丢下了事,是把现状重申一遍的:一个带着当前期待号的纯 ACK 递回去,让对方的对齐纠回来。计数器记了一笔,游标是一步不动的。长凳上有专门的一案:迟段与乱段各喂一个,答话各归各的专名。还有更狠的一案,四段旧货排成风暴打了过去,读标是纹丝不动的,重申的 ACK 一声一声照答。
