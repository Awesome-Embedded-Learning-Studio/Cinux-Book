# 队列、钟与摇泵的人

鼠标上了电,字节解得成样本,上一节收尾撂下两句,12 号线门口谁来接,两股流在哪儿合。头一句,咱们从门里答起,接货的就是中断处理自己。12 号线一进门,处理把上一节单独成件的解码器吐出来的样本接住,当场翻成事件的记录,哪一路动了,动了多少,按下还是抬起,再请钟打上时间戳,一条一条递进流里。键盘那边的 1 号线早就在这么干了,翻好的键号进门就递。发布这一步住在中断里,活掐得很短,盖个时间戳,递进环,出门,别的什么都不碰。

顺着往下,就问到队列的配法。如今机器上有两位生产者。省事的配法是开一条大队列,谁来了都往里塞,读者从另一头取,咱们偏不这么配。跟客人对上的口径,是一条流单生产单消费。这句话说的是流两侧的身份:写的那一头,永远只有一位。读的那一头,也永远只有一位。身份干净,次序就不用谁来主持。键盘和鼠标共用一条队列,两位写者就都得算数,这句话当场就破了。拿守卫补呢?写以前关掉本核的中断,单核真挡得住,可咱们的机器是两颗核的,关得住本核的闸,关不住另一颗的门。所以咱们不在一条队列上赌,键盘的记录进键盘的环,鼠标的进鼠标的环,一人一条流,谁生产,谁消费,两头数得清。环深六十四条,外头搭着一把自旋的小锁,那是内核自家的谨慎,本钱是身份,不是锁。环要是真灌满了,内核清环记一笔丢,下一趟读开的头一条,就是丢了东西的口信,还按着的键一律补报抬起,免得桌面以为有手指没松开。

门外的这一半,读的礼数三件。头一件,整记录读,二十四字节一条,装得下几条给几条,半条从来不过线,上一节立过的老礼,咱们门里照办。第二件,空了不硬撑,环里一条都没有,流答一句 would-block。第三件,等的礼貌不住在流里,照旧住在门上。描述符生来带非阻塞位的,门答 EAGAIN,眼下没有东西可读,说完就走。没带的,门里有只圈,收着了,抄出去答字数,有信号候着,答 EINTR 出门,都不是,就让位一圈,把处理器交给别人,下一圈轮回来再收。这个圈您见过,UDP 与 socket 那一卷的门上,一模一样的四步,同一位老师教出来的。

圈转起来,总得有人一圈一圈地摇。摇泵的人是谁?这一卷的答案跟前几卷不一样,咱们数数家谱。泵是咱们的老词了,点亮网卡那一卷,给排水立过一具泵,UDP 与 socket 那一卷,控制台收字又立过一具,两具都是常驻的内核任务,摇一圈让一圈。这一卷的泵不住内核。内核到收官那天一行 GUI 代码都没有,自然也不会养 GUI 的泵,摇把子头一回换了主人,从咱们的手里交到客人手里。桌面的主循环就是这具泵,它把两个节点的描述符攥在手里,一趟一趟地读,键盘的记录,鼠标的记录,到它手里才照面。两股流在内核里从头到尾没见过面,合流这一步,内核压根不掺和。前几卷撂过一句话,引擎归引擎,调用者归调用者,这一卷把这句话挪进用户态。引擎是内核的环和门,摇引擎的,是别人家的主循环。

当年这一口,恰是栽得最疼的一口,笔者把案卷摊开讲。当年的 GUI 住在内核里,泵也跟着住了进去,还挑中了最不该挑的住处,时钟中断的回调。机器的心跳一秒一百下,每一下都进回调里干三样活,事件泵摇一遍,画面合成跑一遍,终端轮询转一遍。中断上下文是什么地方,打断别人进门、放下东西就该走的客座,让一具常驻的泵住进去,门就被长活占了。桌面一忙,回调干不完,下一次心跳进不来,调度器收不到让位,整台机器陪着桌面一起僵,画面冻着,键也不应。这桩病当年拖着走完了收官,第二幕花了一整段功夫,才把 GUI 从中断里解出来,搬去用户态。这一遍谈不上修它,这病从结构上就生不出来:内核里没有 GUI,泵想搬进时钟中断,连门都找不着,它生下来只有一个住处,客人自己的主循环。

接线拢共四口,像素的正门,两股流,摇泵的人,末一口是钟。这一口最薄。函数指针表上,问钟的那一项,要的只是此刻,走的路数是不回头,后一次问,不会比前一次小。这样的钟,咱们手里早就有两座,心跳那一座一百赫兹,开机起就在跳,细针那一座是块高精度的事件定时器,跑别人的程序那一卷请进来的,专管两次心跳之间的刻度。问钟的那一号也早就挂上了号,单调的那一问,答的是开机以来走过的工夫,事件记录头两笔的时间戳,打的也是这同一口钟。这一口没有新活,门开着,钟走着,客人伸手问就是。

到这儿,家当与边界咱们一起挂明。咱们讲的始终是兑现,环怎么排,等待怎么答,钟怎么走。事件的词汇,记录里每个字段的含义,表上究竟要什么,正本写在客人自家的说明里,咱们不在这儿重述。咱们要是凭记忆背写一份,写岔一个字段,读者手里就攥着两份对不上的正本,照哪一份做都是错。重述必然漂移,漂移的说明,比没有说明还坏。

像素的正门,两股流,摇泵的人,钟,四口接齐了。桌面画得出,听得见,掐得住钟点。可它上头坐着的终端,是一扇一扇拖得动的窗,窗一改大小,里头的壳就该听见一声。下一节,咱们去量窗口。
