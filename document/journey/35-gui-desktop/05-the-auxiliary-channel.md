# 鼠标上电:8042 的辅助通道

上一章立了两股流,键盘那股从扫描码一路走到了键的身份,鼠标那股却只立了个门牌。门牌挂是挂上了,门后是黑的、没有生产者,谁来读不扑空?这一章咱们把源头接上。

源头不在什么新房子里。鼠标住的还是老熟人 8042 的房子,跟键盘共用的是同一个门房,自己走的是第二口。自己的脸,自己的耳朵那一卷带键盘上电,咱们照六步礼数办事,顺手把这第二口关了,配置里管它的 bit1 也清了零。理由当年咱们说得很直白,咱们没有鼠标,别让一条没主人的线也去敲门。如今鼠标搬来了,当年关上的那道口就是它的大门,行话叫的是辅助通道,手册上的名号是 AUX。

带电的次序是怎么走的,咱们把 init 原样摆出来,照旧拿码来对咱们说话:

```cpp
bool Ps2Mouse::init() {
    const arch::IrqGuard               kQuiet;
    const cinux::driver::ps2::Ps2Ports kPorts = ps2::HostPs2Ports();
    if (!ps2::SendCommand(kPorts, ps2::kCommandEnableSecond)) {
        return false;
    }
    if (!ps2::SendAux(kPorts, kAuxDefaults)) {
        return false;
    }
    if (!ps2::SendAux(kPorts, kAuxEnableReports)) {
        return false;
    }
    if (!arm_irq12(kPorts)) {
        return false;
    }
    cinux::interrupt::Irq::self().register_handler(
        cinux::interrupt::IrqLine{.value = kMouseIrqLineValue}, irq12_thunk);
    cinux::interrupt::Irq::self().enable_line(
        cinux::interrupt::IrqLine{.value = kMouseIrqLineValue});
    return true;
}
```

这段码咱们慢慢走。头一行的 kQuiet 请您记下,它是轮流当家那一卷立的关中断守卫,构造的时候把中断的旗拍成快照,析构的时候原样奉还。它为什么站在最前头,咱们把谜底押到后头的判例再揭。往下的第一道令是 0xA8,管的是把辅助口的门开开。当年关第二口用的是 0xA7,如今 0xA8 原路开了回来。这道令是发给门房本人的,是不指望回话的,门开了就往下走。

再往下的两道令,收令的换了人,轮到的是鼠标本人。您想,鼠标又不直连咱们的任何一个口,递话的事全靠门房转交。转交有个约定的暗号:0xD4 打头,意思是数据口的下一笔,请转给后头的辅助设备。于是 0xD4 的后头跟 0xF6,让鼠标回的是一身默认。再来一轮 0xD4 的后头跟 0xF4,为的是让它开始上报。

每道令发了出去,咱们都原地等一声应答。0xFA 回的是办妥。0xFE 是请您再讲一遍,那就守着预算重讲就是了。预算花完了,或者咱们等到的干脆是一声不吭,init 是不硬撑的,把失败原样地交上去。

末一步的 arm_irq12,咱们看着眼熟,办的是读改写配置的旧活,自己的脸那一卷演过一遍,0x20 读了出来,改了一笔,0x60 写了回去。改的就是当年清掉的 bit1,把它置回了 1,鼠标的 12 号中断线这才喊得动。再往中断桌上落座、开门的事,走的都是会听那一卷立的老礼,次序是一点不变的。到了这儿,鼠标每挪一寸都是 12 号线上的一次敲门。

这套次序不是一遍写对的。复审的那一轮,每一步都重新问了一遍,问出来的纪律有三条,咱们一条一条看。头一条落在落笔的事上:写下去之前,咱们得等输入缓冲空。老门房消化命令是要工夫的,发命令前看 `INPUT_FULL` 的礼数当年就立过,这一遍收紧到了每一笔,不管来的是命令还是数据,都等它清了零再写,忙了就等,等不来咱们就认失败。

再一条是失败的上送。哪一步等不来该等的东西,init 当场交的是 false,咱们不硬撑,替设备圆场的事咱们也不做。老话还是咱们说过的那句:宁可承认聋,也不装作听得见的样子。

末一条说的是等待本身。等待在咱们这儿不是死转,咱们每一拍按 PIT 的实延时小睡一会儿。这里的旧写法偷过懒,拿 TSC 硬折算了时间。TSC 是处理器里一颗数时钟圈的计数器,拿圈数折时间的话,得摸准的是一圈有多长,频率要是摸错了,折出来的每一拍全都不对。复审把折算删了,钟摆挂回了 PIT。

谜底现在可以揭了,判例就藏在您眼前这段 init 里。机制是这样:8042 回话的时候,不带辅助标记的回读字节,它当键盘的货,1 号线是照抬的,当班的键盘腿手脚快,应答字节一露头就被它捞走了,咱们原地等回话,等了个空。处置您已经看见了,就是开头立在最前头的 kQuiet,初始化全程罩着关中断的守卫,闸是关着的,键盘腿想抢也是没有门的。验证的法子也干脆,机内测试曾因为这件事吃过一吊五十七秒的超时才收场,守卫立起来之后才安生了。

这桩案子有当年的影子,笔者从考古箱里把它请出来讲两句。当年第一遍接鼠标的时候,初始化同样招来过虚假的 1 号线,更不巧的是,当年的中断栈没有十六对齐,虚假中断一进了门,栈上一条要求操作数十六对齐的指令当场翻车,报的正是会疼那一卷的老熟人:一般保护异常。病出在没对齐的栈上,鼠标是没病的,虚假的敲门声只是把它踩了出来。

电带上了,12 号线上往后送的就是运行期的、三个字节算一包的字节流。咱们从包头看起。包头的 bit3 恒为一,签名靠的是它,校验靠的也是它。流里没有别的对齐记号,解码器要是迷了路,全靠这个签名找回自己的头,当不成包头的字节直接丢,咱们不攒着。包头里还住着的是两粒溢出位,那是设备的自首,位移计数器装不下的那包,数据是不可信的,溢出位但凡不清的话,包连当头的资格都没有了。三粒按键位住包头的低位,按下、抬起的读数,咱们都从这儿来取。

包身装的是两笔位移,在前的是 X,在后的是 Y。Y 这段的值要取反,拧的是两套坐标系:鼠标报的 Y,正方向是朝上的,屏幕的坐标,偏偏朝下长。您把手往屏幕下方拖,包里报的 Y 是负的,解码的时候翻个面,样本里的正方向才落成朝屏幕下方。

干活的解码器,咱们把它单独成了一件纯函数:喂的是字节,出的是样本,端口是不认识的,中断也是不认识的。这样的件,长凳上不用开机咱们就能考它,普通的包、带负位移的包、从半截开始喂的包,咱们都当场对答案。初始化的应答字节也不进它的门,那些在问答里当场收走了,它只管开机之后的粮。

还有最后一桩当年的旧案,跟位移的口径有关,咱们顺手在这儿念掉。当年桌面上出过两个光标的怪事,窗口那头画了一个,桌面自己又画了一个,永远差了那么一截,当时的评语就成了那句“不是毛病的毛病”。PS/2 报的是相对位移,窗口那头给的是绝对坐标,两套坐标系是对不拢的,谁也不是坏的。这一遍的实弹不开真窗口,说话的只有截屏,这桩毛病就生不出来了。相对位移怎么积分成绝对坐标,留给往后验收的那一章。眼下鼠标上了电,字节也解得成样本了,可 12 号线门口谁来接、两股流怎么合到摇泵的人手里,下一章咱们去排队列、请钟。
