# 两股流与键盘的第二张脸

像素的正门开了,桌面就把画面递上屏了。可它眼下有的只是脸,还没有耳朵听咱们说话,您敲什么它都听不见。咱们把镜头拉近,看一个具体的动作。您坐在桌面前,按下键盘上的下方向键,想的是让选中的图标往下挪一格。这一按落进机器里变成了什么?自己的脸、自己的耳朵那一卷立的路,键盘进来的字节全喂给翻译机,交出来的是字符。可方向键在字表里是查不出字的,查不出的就交零,这一按也就等于没发生了。咱们再往宽里想,有毛病的还不止方向键一处,拖窗口您得按住标题栏,松手您得抬起来,按下与抬起的动作,字符的世界里同样一个字都说不出来。桌面问键盘的话,问的是哪一把键,现在是什么状态,字反倒从不在它要的名单里。这一章咱们就给输入立两股流:键盘咱们给一股,鼠标咱们也给一股,各走各的设备节点,键盘那股还要在老翻译机的旁边,添上一张新的脸。

两股流立的是两个节点。键盘的门牌是 /dev/event0,鼠标的是 /dev/event1,跟 fb0 是一样的,平摆在设备目录的根上。您也许想问,业界那边明明砌了一个 input 子目录,把键盘的流与鼠标的流收在里头,咱们怎么两口平摆?道理在设备表的骨头上。假文件与真终端那一卷立设备表的时候,章法就是一层平的名字:一件家当一个名字,名字本身就是一整串的字。斜杠想挤进名字里来的话,它也只是名字里的一个普通字符,倒是变不出一层目录来,平名字的表上,压根没有子目录的语法。砌不成的事咱们就不硬砌,两口平摆就是了。平摆带来的是一个小麻烦,客人上哪儿知道门牌去?猜是猜不着的。好在咱们根本不请客人猜,桌面是被当成普通用户程序拉起的,拉它的人把三条路径写进启动参数,一条是 /dev/fb0 的,一条是 /dev/event0 的,一条是 /dev/event1 的,桌面照着单子挨个开它的门,谁都不会走错门的。

门牌立了,咱们看流里走的货。一条事件的线记录二十四字节,身子写在公告的头文件里:

```cpp
struct InputEventWire {
    uint64_t seconds;
    uint64_t microseconds;
    uint16_t type;
    uint16_t code;
    int32_t value;
};
```

咱们一个字段一个字段慢慢走。头两笔装的是时间戳,打的是开机以来的单调钟。为什么分两笔?整秒是一笔,秒以下的小数另住一笔,这是跟人家记录的记法对齐。第三笔装的是类型字,说的是这笔属于哪一类,咱们眼下用得着的一类叫键类,键盘的按下抬起、鼠标的按键,都算它家的成员。第四笔装的是号码,在这一类里挑出具体的哪一把键。末一笔装的是值,按下记的是一,抬起记的是零。您拿一个熟键对一遍就顺了,您按下 a,类型字说这是键类的一笔,号码那一栏落的是三十号,值说按下了,抬起的时候再出一条,值就换成了零。三十号这个数咱们记下,它是从哪儿来的,下文有它自己的戏。

版式咱们不发明,也是没法发明的。业界那套输入事件的口径,它的名字叫 evdev,客人程序是照它自家 C 库里的头文件编出来的,记录长什么样,人家编译那一刻就定死了。咱们递出去的记录跟人家头文件里的形状逐字节一样,客人读到的就是自家的语言,一行代码是不用改的。节奏也守人家的拍子,一份按键的报告出两条记录,键的记录在前,落在后头收尾的是同步字。为什么多出一条?您想,读的人拿到键的记录,没法知道报告说完了没有,得攒到同步字露了面才敢动手处理。人家自家的设备守的就是这一拍,咱们照人家的拍子走,节奏是不另创的。读的章法也跟着定了,整条整条地走,二十四字节是一条的分量,您递的字数装不下一条,门上是不接的,装得下几条给的就是几条,装完几条剩下的零头留在门外。半条是从来不过线的。

节点的背后,键盘的同一股字节流,现在要喂的是两张脸。字符的脸是老朋友,自己的脸那一卷立的翻译机,查的是字表、管的是 shift、报的是字符,一路用到了今天。键号的脸是新立的,字表是不查的,报的是键的身份。方才的三十号,来历就在新立的脸上,咱们把一笔 a 键从数据口一路走到门牌。键盘本上来说的码是 set 2,老门房 8042 的身上有个翻译开关,自己的脸那一卷带键盘上电时把它置上了,从那以后进门的就是 set 1 的码。巧的是,set 1 主块的 make 码,号数跟业界键号是一个对一个的。0x1E 在字表里查出来的是 a,在键号的册子里,它就是三十号的 `KEY_A`。数本来就是一样的数,所以主块的键号翻译是恒等的,make 码落了进来,号码原样地递出去,表是连一张都不用立的。

扩展组就是另一回事了。0xE0 打头的两字节组,自己的脸那一卷整组丢弃,老话当时是写在明处的,按了方向键没动静,这是设计好的,而不是失灵,当年第一遍也是有意丢的,终端是用不上方向键的,吞了咱们也不心疼。那一卷收尾还撂了一句,等真要方向键了,再给这组立正经的语法,旗已经立好在那儿了。桌面一来这句旧话就到期了,方向键在窗口的世界里忙得很,选的是图标、挪的是光标、拖的是窗口,处处都是它的地界。新的翻译面为它补一张十七键的表,方向键是全在座上的,右边的 ctrl、alt 在,小键盘里那几位跟主块同号的也在,十七个座全都有自己的名字。咱们拿下方向键真走一遍。0xE0 进了门,键号脸立了旗,报是按住不发的。0x50 跟着进了门,旗是立着的,拿它的 make 码进表里对,对上了,报出一笔一百零八号的按下。字符的脸在同一时刻在干什么?照旧整吞就是了。它的旗它自己立,0x50 它也一并咽了下去,字就是查不出来的。两个翻译面就这么住下了,各留各的 0xE0 旗,头一个字节各记各的,后一个字节各归各地读,同一股流上各过各的日子,咱们谁也不打扰谁。

两张脸各有各的读者。字符腿的口上,常蹲着控制台的终端,假文件与真终端那一卷把终端从单例改成可以成群造的类之后,控制台还是从字符腿上取它的字,串口的登录会话,吃的就是腿上的字。键号腿通到的是事件流,读它的是桌面。麻烦也就出在这儿了,咱们把一个具体的场景演一遍您就看明白了。您在桌面的终端窗口里敲一个 a。字符腿把这个 a 送给串口的登录会话,那边是没人敲字的,凭空多出了一个 a。桌面终端吃的却是键号,自己把键拼成了字节,喂进它开的伪终端,窗口里这才见着那个 a 了。一笔键进了门,忙的是两位读者,串口里还多出一串没人要的字。同一副键盘上养两张脸的话,就得有一个分家的礼数,礼数说的就是抓座。

抓座说的是一条问话,用的词是 `EVIOCGRAB`,递了一是抓、递了零是放。桌面开了键盘的节点,头一件要办的事就是抓,理由很直白:不让内核的控制台跟桌面抢同一副键盘。抓上了,字符腿就收了。您留意,被关掉的并不是翻译机,它照旧转它的,shift 照旧折它的,算出来的字符只是不再进控制台的队列,等字的终端从此等了个空,桌面的键一个字不往串口漏。放的时候递零,或者干脆把描述符关掉了事,抓是自己跟着放的,腿是自己回来的。

送出去的复审,又给抓座补了一条硬边。抓座认的是独立的主人,已经有人抓着的时候,再问一句答的就是 EBUSY,连主人自己手滑多问了一遍,答的也是忙,成功是不装的。咱们在机内的键盘台真抓了两把,第二把收的就是 EBUSY,又拿注入走了一遭。抓着的时候注入一笔 a 键,事件流里三十号是照报的,字符的队列里是一条都没有。放掉了再注入,a 立马就回到了字符腿上。同一个案子咱们把两条腿的边界一起看清了。

机内测试的子弹从哪儿来,咱们顺着交代一句。自己的脸那一卷用过 0xD2,写的是命令口一笔、数据口又一笔,模拟器就假装键盘发了这个字节。鼠标口有同族的 0xD3,测试把字节塞进的是第二口,打这儿起走的全是 8042 的真路,解码、进流、出门的活一步不缺。至于鼠标那股流的源头怎么带电,三字节的包讲什么礼数,下一节咱们去敲辅助通道的门。键盘这半边到这儿齐了:门牌立了,第二张脸也添全了。
