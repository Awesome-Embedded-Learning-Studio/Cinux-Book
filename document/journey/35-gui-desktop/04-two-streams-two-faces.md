# 两股流与键盘的第二张脸

像素的正门开了,桌面能把画面递上屏。可它眼下只有脸,还没有耳朵,您敲什么它都听不见。咱们把镜头拉近,看一个具体的动作。您坐在桌面前,按下键盘上的下方向键,想的是让选中的图标往下挪一格。这一按,落进机器里变成了什么?自己的脸,自己的耳朵那一卷立的路,键盘进来的字节全喂给翻译机,吐的是字符。可方向键在字表里查不出字,查不出就交零,这一按等于没发生。再往宽里想,毛病还不止方向键一处,拖窗口您得按住标题栏,松手您得抬起来,按下与抬起,字符的世界里同样一个字都说不出来。桌面问键盘的话,问的从来不是字,是哪一把键,现在是什么状态。这一章就给输入立两股流,键盘一股,鼠标一股,各走各的设备节点,键盘那股还要在老翻译机旁边,多长一张脸。

两股流,立两个节点。键盘的门牌是 /dev/event0,鼠标的是 /dev/event1,跟 fb0 一样,平摆在设备目录的根上。您也许想问,业界那边明明砌了一个 input 子目录,把键盘鼠标收在里头,咱们怎么两口平摆?道理在设备表的骨头上。假文件与真终端那一卷立设备表的时候,章法就是一层平的名字,一件家当一个名字,名字本身就是一整串字。斜杠想挤进名字里,它也只是名字里的一个普通字符,变不出一层目录来,平名字的表上,压根没有子目录的语法。砌不成,咱们就不硬砌,两口平摆。平摆带来一个小麻烦,客人上哪儿知道门牌去?猜是猜不着的。好在咱们根本不请客人猜,桌面是被当成普通用户程序拉起的,拉它的人把三条路径写进启动参数,/dev/fb0 一条,/dev/event0 一条,/dev/event1 一条,桌面照着单子挨个开门,谁也不会走错门。

门牌立了,咱们看流里走的货。一条事件的线记录二十四字节,身子写在公告的头文件里:

```cpp
struct InputEventWire {
    uint64_t seconds;
    uint64_t microseconds;
    uint16_t type;
    uint16_t code;
    int32_t value;
};
```

咱们一个字段一个字段慢慢走。头两笔是时间戳,打的是开机以来的单调钟。为什么分两笔?整秒是一笔,秒以下的小数另住一笔,这是跟人家记录的记法对齐。第三笔是类型字,说这笔属于哪一类,咱们眼下用得着的一类叫键类,键盘的按下抬起、鼠标的按键,都算它家的成员。第四笔是号码,在这一类里挑出具体哪一把键。末一笔是值,按下记一,抬起记零。您拿一个熟键对一遍就顺了,您按下 a,类型字说这是一笔键,号码那一栏落的是三十号,值说按下了,抬起再出一条,值换成零。三十号这个数咱们记下,它从哪儿来,下文有它的戏。

版式咱们不发明,也没法发明。业界那套输入事件的口径,名字叫 evdev,客人程序是照它自家 C 库里的头文件编出来的,记录长什么样,人家编译那一刻就定死了。咱们递出去的记录跟人家头文件里的形状逐字节一样,客人读到的就是自家的语言,一行代码不用改。节奏也守人家的拍子,一份按键的报告出两条记录,键的记录在前,同步字在后头收尾。为什么多出一条?您想,读的人拿到键的记录,没法知道报告说完没说完,得攒到同步字露面,才敢动手处理。人家自家的设备守的就是这一拍,咱们照拍子走,不另创节奏。读的章法也跟着定了,整条走,二十四字节是一条的分量,您递的字数装不下一条,门上不接,装得下几条给几条,装完几条剩下的零头留在门外。半条,从来不过线。

节点背后,键盘的同一股字节流,现在要喂两张脸。字符的脸是老朋友,自己的脸那一卷立的翻译机,查字表,管 shift,吐字符,一路用到今天。键号的脸是新立的,不查字表,报的是键的身份。方才的三十号,来历就在新立的脸上,咱们把一笔 a 键从数据口一路走到门牌。键盘本上来说的码是 set 2,老门房 8042 身上有个翻译开关,自己的脸那一卷带键盘上电时把它置上了,从那以后,进门的就是 set 1 的码。巧就巧在这儿,set 1 主块的 make 码,号数跟业界键号一个对一个。0x1E 在字表里查出来是 a,在键号的册子里,它就是三十号,`KEY_A`。数本来就是同一个数,所以主块的键号翻译是恒等的,make 码落进来,号码原样递出去,连一张表都不用立。

扩展组是另一回事。0xE0 打头的两字节组,自己的脸那一卷整组丢弃,老话当时写在明处,按了方向键没动静,这是设计好的,不是失灵,当年第一遍也是有意丢的,终端用不上方向键,吞了不心疼。那一卷收尾还撂过一句,等真要方向键了,再给这组立正经的语法,旗已经立好在那儿。桌面一来,这句旧话就到期了,方向键在窗口的世界里忙得很,选图标、挪光标、拖窗口,处处是它。新的翻译面为它补一张十七键的表,方向键全在座上,右边的 ctrl、alt 在,小键盘里那几位跟主块同号的也在,十七个座全有名字。咱们拿下方向键真走一遍。0xE0 进来,键号脸立旗,不报。0x50 跟着进来,旗立着,拿它的 make 码进表里对,对上了,报一笔一百零八号按下。同一时刻,字符的脸在干什么?照旧整吞。它的旗它自己立,0x50 它也一并咽下去,查不出字就是查不出。两个翻译面就这么住着,各留各的 0xE0 旗,头一个字节各记各的,后一个字节各归各读,同一股流,互不打扰。

两张脸,各有各的读者。字符腿的口上,常蹲着控制台的终端,假文件与真终端那一卷把终端从单例改成可以成群造的类之后,控制台还是从字符腿上取字,串口的登录会话,吃的就是腿上的字。键号腿通到事件流,读它的是桌面。麻烦也就长在这儿,咱们把一个具体的场景演一遍您就看明白了。您在桌面的终端窗口里敲一个 a。字符腿把这个 a 送给串口的登录会话,那边没人敲字,凭空多出一个 a。桌面终端吃的却是键号,自己把键拼成字节,喂进它开的伪终端,窗口里才见着那个 a。一笔键,两位读者各忙各的,串口里还多出一串没人要的字。同一副键盘养两张脸,就得有个分家的礼数,礼数就是抓座。

抓座是一条问话,词是 `EVIOCGRAB`,递一是抓,递零是放。桌面开了键盘的节点,头一件事就是抓,理由很直白,不让内核的控制台跟桌面抢同一副键盘。抓上了,字符腿就收了。您留意,翻译机并没有被关掉,它照旧转,shift 照旧折,算出来的字符只是不再进控制台的队列,等字的终端从此等了个空,桌面的键一个字不往串口漏。放的时候递零,或者干脆关掉描述符,抓自己跟着放,腿自己回来。

送出去的复审,又给抓座补了一条硬边。抓座认的是独立的主人,已经有人抓着,再问一句就答 EBUSY,连主人自己手滑多问一遍,答的也是忙,不装成功。咱们在机内的键盘台真抓了两把,第二把收的就是 EBUSY,又拿注入走了一遭。抓着的时候注入一笔 a 键,事件流里三十号照报,字符的队列里一条没有。放掉再注入,a 立马回到字符腿上。同一个案子,两条腿的边界一起看清。

机内测试的子弹从哪儿来,咱们顺着交代一句。自己的脸那一卷用过 0xD2,往命令口写一笔、数据口再写一笔,模拟器就假装键盘发了这个字节。鼠标口有同族的 0xD3,测试把字节塞进第二口,打这儿起走的全是 8042 的真路,解码、进流、出门,一步不缺。至于鼠标那股流的源头怎么带电,三字节的包讲什么礼数,下一节咱们去敲辅助通道的门。键盘这半边,门牌立了,第二张脸也长全了。
