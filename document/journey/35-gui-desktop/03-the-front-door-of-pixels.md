# /dev/fb0:像素的正门是共享映射

上一节的收尾,座是安好了,显存那一段帧进了登记表,咱们一枚也不外借。可咱们要是闭上眼,把自己当成那个还没出生的桌面程序,马上就觉得哪儿不对劲了。座安在内核的册子上,咱们手里连显存的门牌都摸不着,想画一个点的话,落笔总得有个地址。这一章办的就是这件事:给像素开一扇正门。

门牌挂在熟地方。假文件与真终端那一卷立设备表的时候,章法就立下了,一张设备的脸配一对号,设备类挪的是高位,实例落的是低位。帧缓冲照章住了进来,咱们给它登记的名字叫 fb0,号编的是二十九比零。为什么跟着 Linux 家的号编?客人是拿自家 libc 编出来的,头文件里帧缓冲坐的就是二十九这个类,号一对上了,进门就认得对面是谁了。

> 名字里的零是实例号。显卡要是带上了第二块屏,轮到的就是 fb1。咱们只有一块屏,所以这个零眼下还是独生子。

进了门,客人头一件要办的事,是把屏好好地摸清楚。问什么呢?咱们替它把要问的话过一遍。画布的宽高是多少,一个像素吃的是几个比特,红绿蓝各占像素字里的哪几位?这些是会变的一半,屏换了,答案也就跟着换了。显存的起点在哪个地址、一共多长,一行横过去占几字节?这些是定死的另一半,开机定了就不动。Linux 家给帧缓冲这套设备接口起的名字叫 fbdev,它的老词表把这堆话分成两份,会变的记进虚屏,定死的记进定屏,咱们照着分,问话走的是 ioctl,词是现成的,`FBIOGET_VSCREENINFO` 问的是虚屏,`FBIOGET_FSCREENINFO` 问的是定屏。

版式可就轮不到咱们发明了。客人心里的记录是照 glibc 的 fb.h 长的,哪个字段落在第几字节的位置上,人家编译的时候就已经定死,门要是自作主张挪了一位,客人读到的宽就成了来路不明的数字。所以两份记录的线版式,咱们单独立进一张头文件,几个要紧的尺寸,全用编译期的断言把着:

```cpp
inline constexpr unsigned long long kFbGetVarScreeninfo   = 0x4600;  // FBIOGET_VSCREENINFO
inline constexpr unsigned long      kFbVarScreeninfoBytes = 160;
inline constexpr unsigned long long kFbGetFixScreeninfo   = 0x4602;  // FBIOGET_FSCREENINFO
inline constexpr unsigned long      kFbFixScreeninfoBytes = 80;
```

断言把着的不止总尺寸,还有几个要紧字段的偏移,哪天咱们手一抖挪了位,编译当场就红了,轮不到运行的时候给客人递歪掉的记录。

门内的问话,咱们还有一道手续。问话脸立起来的时候,门内备了一块暂存区,客人递来的是它家里的地址,咱们不直接往人家家里写,答案落在自家的院里,答完了整份送回去。这块地当初四十四字节就够用,虚屏的记录一来,要的就是一百六十,暂存区就跟着最宽的答案加宽,打那以后就没再瘦回去了。

答案也不是现场编的。配屏那一卷咱们趁 BIOS 还应话,一笔一笔问回来的屏参数,誊在了交接单上,开机以后就留在帧缓冲手里了,今天就穿戴成两份记录递了出去,打底的是每像素三十二比特。也有交接单上一个字都没有的字段,时序的余量、同步的长度,问价的时候咱们没问到它们,门上偏偏不装懂,老老实实地落零。您别嫌零难看,客人拿到的是零,至少明白这块屏是没有那些故事的,总比收一个编出来充场面的数强。

尺寸问清了,咱们这才把正门开起来。您把 fb0 的描述符递给 mmap,带上了 `MAP_SHARED`,把整块显存映进自己的地址空间,您往里写一个字,屏幕上亮起来的就是一个点。走起来是痛快的,闸门却比看上去的要窄。mmap 不看您递的是什么,它看的是描述符背后站着谁,设备得备着答帧的座,拿偏移去问的时候,答出来的得是落在哪一枚帧上。放行的时候咱们头一帧问一遍,末一帧咱们再问一遍,两头都答上了才让过。没有这座的,哪怕递来的是正经文件,也吃一个 EINVAL 的闭门羹。而匿名共享照旧拒,匿名内存的背后,是没有谁能替帧作保的。所以共享映射这件事,开口的从来不是客人单方面,它是设备请进门的客。

映进门之后活就交回上一节的座了,您的笔落到头一页,缺页也就进来了,裁决者认出的是设备区间,拿偏移问的是设备,帧直映进您的页表,章程全是上一节立好的。往后的每一笔像素,内核是一概不经手的,您写显存,屏幕就亮了,中间没有传话的人。痛快啊!

正门是开着的,旁路咱们就得拒明白。您要拿 read 和 write 把帧缓冲当字节流使,门上两头都给干脆的答复。read 答的是 EOF,给的是零字节、零报错。write 就更直了,直接答的是不支持。这么拒当然不是闹脾气,咱们想一层就明白,字节流是有次序的,读了就少一个,帧缓冲没有这样的次序,第几行第几列住着什么颜色,字节流这套语法是说不上来的。假文件那一卷的 null 是另一种活法,读给的是零,写就全吞了,人家真是个字节流的家。fb0 是不装这个样子的,能走共享映射的,就不假装成字节流的模样。

开门还带出了一件麻烦事,屏幕是只有一块的。文本控制台从开机起就在这块屏上画它的字,内核的报数、壳的回显,笔笔都是它落的。客人现在要画的是桌面,两个笔手挤的是一块屏,所以总得有个让法。让法咱们记在持有上,打开了就算持有,头一位客人落座的瞬间,画字的活当场停笔,等最后一份描述符放了手,控制台收了屏,接着画它的字。谁持有了帧缓冲,谁就拥有了屏幕。

让了屏,内核自己的话可没有断流。开机报数的面板本来两路同发,屏幕走的是一路,串口走的是另一路。桌面在场的时候,屏幕那路就安静了下来,那块屏是客人的画布,内核再往上糊自己的字,糊掉的是人家的桌面。串口那路是一个字也不停的,出了事您到串口上看,报数照旧一行一行地来。谁持有了帧缓冲,谁就拥有了屏幕,连内核自己也是守这句话的。

当年的 GUI 是另一种住法,这段旧话笔者来念。第一幕的那会儿,GUI 是靠编译开关整个住进内核的,帧缓冲是直写的,咱们想画就画,门是没有的,让屏也是没有的,代价是内核里攒出了一整座桌面,收场之后才整座搬去了用户态。这一遍倒过来了,内核一行 GUI 的代码都没有,咱们立的是门面,两问问的是尺寸,一扇共享映射递的是像素,一句让屏收屏定的是秩序。门开好了,不过桌面不光要画得动,还得听得见手上的动静。键盘与鼠标的两股流,下一节咱们就进门。
