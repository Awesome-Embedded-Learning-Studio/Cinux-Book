# /dev/fb0:像素的正门是共享映射

上一节的收尾,座是安好了,显存那一段帧进了登记表,一枚也不外借。可咱们要是闭上眼,把自己当成那个还没出生的桌面程序,马上就会觉得不对劲。座安在内核的册子上,咱们手里连显存的门牌都摸不着,想画一个点,落笔总得有个地址。这一章就办这件事,给像素开一扇正门。

门牌挂在熟地方。假文件与真终端那一卷立设备表的时候,章法就立下了,一张设备的脸配一对号,设备类挪到高位,实例落在低位。帧缓冲照章住进来,咱们给它登记的名字叫 fb0,号编的是二十九比零。为什么跟着 Linux 家的号编?客人是拿自家 libc 编出来的,头文件里帧缓冲就坐二十九这个类,号一对上,进门就认得对面是谁。

> 名字里的零是实例号。显卡要是带上第二块屏,轮到的就是 fb1,咱们的机器只有一块屏,这个零眼下是独生子。

进了门,客人头一件要办的事,是把屏摸清楚。问什么呢?咱们替它把要问的话过一遍。画布多宽、多高,一个像素吃几个比特,红绿蓝各占像素字里的哪几位?这些是会变的一半,屏换了,答案就跟着换。显存从哪个地址起,一共多长,一行横过去占几字节?这些是定死的另一半,开机定了就不动。Linux 家把帧缓冲这套设备接口叫 fbdev,它的老词表把这堆话分成两份,会变的记进虚屏,定死的记进定屏,咱们照着分,问话走 ioctl,词是现成的,`FBIOGET_VSCREENINFO` 问虚屏,`FBIOGET_FSCREENINFO` 问定屏。

版式可就轮不到咱们发明了。客人心里的记录是照 glibc 的 fb.h 长的,哪个字段落在第几字节,人家编译的时候就已经定死,门要是自作主张挪了一位,客人读到的宽就成了来路不明的数字。所以两份记录的线版式,咱们单独立进一张头文件,几个要紧的尺寸,全用编译期的断言把着:

```cpp
inline constexpr unsigned long long kFbGetVarScreeninfo   = 0x4600;  // FBIOGET_VSCREENINFO
inline constexpr unsigned long      kFbVarScreeninfoBytes = 160;
inline constexpr unsigned long long kFbGetFixScreeninfo   = 0x4602;  // FBIOGET_FSCREENINFO
inline constexpr unsigned long      kFbFixScreeninfoBytes = 80;
```

断言把着的不止总尺寸,还有几个要紧字段的偏移,哪天咱们手一抖挪了位,编译当场就红,轮不到运行的时候给客人递歪掉的记录。

门内问话,还有一道手续。问话脸立起来的时候,门内备了一块暂存区,客人递来的是它家里的地址,咱们不直接往人家家里写,答案落在自家院里,答完了整份送回去。这块地当初四十四字节就够用,虚屏记录一来,要一百六十,暂存区就跟着最宽的答案加宽,从此没再瘦回去。

答案也不是现场编的。配屏那一卷咱们趁 BIOS 还应话,一笔一笔问回来的屏参数,誊在交接单上,开机以后留在帧缓冲手里,今天穿戴成两份记录递出去,底子是每像素三十二比特。也有交接单上一个字都没有的字段,时序的余量、同步的长度,问价的时候咱们没问到它们,门上就不装懂,老老实实落零。您别嫌零难看,客人拿到零,至少明白这块屏没有那些故事,总比收一个编出来充场面的数强。

尺寸问清了,正门这才开。您把 fb0 的描述符递给 mmap,带上 `MAP_SHARED`,把整块显存映进自己的地址空间,往里写一个字,屏幕上就亮一个点。走起来痛快,闸门却比看上去窄。mmap 不看您递的是什么,它看描述符背后站着谁,设备得备着答帧的座,拿偏移去问,要答得出落在哪一枚帧上。放行的时候,头一帧问一遍,末一帧再问一遍,两头都答上了,才让过。没有这座的,哪怕是正经文件,也吃一个 EINVAL。匿名共享照旧拒,匿名内存的背后,没有谁能替帧作保。所以共享映射这件事,从来轮不到客人单方面开口,它是设备请进门的客。

映进门之后,活就交回上一节的座,您的笔落到头一页,缺页进来,裁决者认出设备区间,拿偏移问设备,帧直映进您的页表,章程全是上一节立好的。往后每一笔像素,内核都不经手,您写显存,屏幕亮,中间没有传话的人。痛快!

正门开着,旁路就得拒明白。您要拿 read 和 write 把帧缓冲当字节流使,门上两头都给干脆的答复。read 答 EOF,零字节,零报错。write 更直,直接答不支持。倒不是闹脾气,咱们想一层就明白,字节流是有次序的,读一个少一个,帧缓冲没有这个次序,第几行第几列住着什么颜色,字节流这套语法说不上来。假文件那一卷的 null 是另一种活法,读给零,写全吞,人家真是个字节流的家。fb0 不装这个样子,能走共享映射的,就不假装字节流。

开门还带出一件麻烦事,屏幕只有一块。文本控制台从开机起就在这块屏上画字,内核的报数、壳的回显,笔笔都是它落的。客人现在要画桌面,两个笔手挤一块屏,总得有个让法。让法咱们记在持有上,打开就算持有,头一位客人落座的瞬间,画字的活当场停笔,等最后一份描述符放手,控制台收屏,接着画它的字。谁持有帧缓冲,谁拥有屏幕。

让了屏,内核自己的话可没有断流。开机报数的面板本来两路同发,屏幕一路,串口一路。桌面在场的时候,屏幕那路安静下来,那块屏是客人的画布,内核再往上糊字,糊掉的是人家的桌面。串口那路一个字不停,出了事,您到串口上看,报数照旧一行一行地来。谁持有帧缓冲,谁拥有屏幕,连内核自己也守这句话。

当年的 GUI 是另一种住法,这段旧话笔者来念。第一幕那会儿,GUI 靠编译开关整个住进内核,帧缓冲直写,想画就画,没有门,也没有让屏,代价是内核里长出了一整座桌面,收场之后才整座搬去用户态。这一遍倒过来,内核一行 GUI 代码没有,咱们立的是门面,两问问清尺寸,一扇共享映射递像素,一句让屏收屏定秩序。门开好了,可桌面不光要画得动,还得听得见手。键盘与鼠标的两股流,下一节进门。
