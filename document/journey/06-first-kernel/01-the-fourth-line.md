# 第四行字,是谁打的

上一卷收工的时候,面板的尾巴停在三行:16 位世界的遗言 `[stage2] leaving real mode`,32 位世界的报到 `[pm] 32-bit world alive`,64 位世界的报到 `[lm] 64-bit world alive`。三个世界咱们都亲自对过,桥也通了。可您要是这时候追问一句:那第四行呢?咱们只能摊手。第四行的字根本不存在,因为它的主人还躺在磁盘的第 32 号扇区里。2624 个字节的内核镜像,连一次执行的机会都没轮上。本站咱们要办的,就是把它接进来、让面板上多出第四行的字。

接它回来要办的四件事,咱们在上一卷结尾其实已经预告过了:boot 把它从磁盘读进内存。它拿走问内存、配屏幕时存下的家底。它往高处安自己的家。终点的交接,把执行流亲手递到它的手里。四件事听着倒是四步,真的做起来,头一件就够咱们喝一壶的——因为装载这件事,当年笔者在第一遍里栽的结构性的跟头,比任何一行代码都值得咱们讲。咱们从头说起。

咱们去考古箱里翻当年的装载。第一遍的做法,走的是接力。BIOS 用它的老读盘,把一个小小的内核装进低内存——那时候想着,装内核嘛,跟装 stage2 其实是一回事,一次读盘的事。小内核进了 64 位世界才发现不对:真正的大内核它装不动。BIOS 已经喊不应了,它要再读盘的话,就得有自己的盘驱动。要认大内核的格式,就得有自己的解析器。于是小内核开始长肉:串口输出、格式化打印、物理内存的位图、描述符表和中断表,三站基建盖了下来,它已经成了半个操作系统,这才用自家的流水线把大内核搬了进来。然后呢?大内核一进场,头一件事是把小内核的家当重写一遍、搬进自己的屋檐下——输出那一套,前前后后写了三遍。表也写了三遍。内存的位图,写了两遍。

您听出问题了吧。咱们当年给这段历史下过的判词很短:同一件事写了好几遍。可病根其实不在懒——没有人愿意把串口写三遍。病根在接力的结构:装载被排在了告别 BIOS 之后,每一段要往下传接力棒的时候,就得自带全套的家当。下家接过了棒,又得把家当重抄一份才算自己的。小内核的宿命,就是搬运工:为了让真正的内核进场,它被逼着成了半个操作系统,然后在新主人进门的那天整套作废。这不是哪一步走岔了,是整条流水线的形状就不对。

所以这一遍,咱们不接力。boot 在跟 BIOS 的告别之前,把内核直接装完:一段式的直载,从盘上的第 32 号扇区,一路送进内存里的最终住址,所以全程无一处需要 BIOS 复活。装载排在所有的告别之前,这就是本站的次序原则,咱们管它叫单向门流水线:BIOS、32 位、64 位、内核,整整的四道门,过一道少了一道,偏偏谁也不回头。而装载是唯一处处要用 BIOS 的活,所以它必须赶在头一道告别之前全部干完。当年的小内核被迫自造盘驱动,根子就是接力把装载排到了告别后头。次序摆正了,那个结构病连出场的资格都没有了。

构建那头的大事,咱们开头提过,现在把它落成一句话:本站出生的是 `kernel/` 这棵树。上一卷咱们数过工程里的四户编译世界——host 一户,16 位的 boot 一户,32 位的 boot 一户,还有那 68 个字节自带的一户 64 位。本站添的是第五户,按 `-m64` 编的内核自己。它和当年的 blob 走的是同一条老路:64 位的目标件进不了 32 位的链,只能自家成链、把字节剥成裸的。不同的地方在待遇——blob 是拼进 stage2 镜像里的一包数据,搭 MBR 读盘的顺风车进来。内核是躺在磁盘上的正主,要 boot 亲手去接的。至于接的手艺,咱们下一节从那道墙讲起。

收工的时候,面板的尾巴会长成这样——问内存的图谱行和配屏的行都在它上头,咱们只看最后这几行:

```text
[stage2] kernel image ok
[stage2] kernel ferried
[stage2] leaving real mode
[pm] 32-bit world alive
[lm] 64-bit world alive
[kern] 64-bit C++ world alive
[kern] bootinfo: 8 e820 entries, fb 1024*768*32
[kern] kernel at 200000 size C40 entry 2001B4
```

您一眼就看到了那行 `[kern] 64-bit C++ world alive`,还有它身后跟着的两行家底。这三行得等咱们把内核装进来、把家底誊给它、把高半的门开好、把执行流递过去,四件事全齐了才肯亮。本站从头到尾忙的,还是老一套的活:把它们亲手点亮。
