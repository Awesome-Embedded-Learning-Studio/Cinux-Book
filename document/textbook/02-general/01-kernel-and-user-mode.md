# 01 · 内核态与用户态:两副门牌,一条快门

cinux>,六个字符,尾上还坠一枚空格,后头连换行都没带。第 1 部的机器只会一口气把话讲完,讲完就停。眼下的机器不一样了,它打出六个字符,停在半截,等您接话。等在哪儿,这就有意思了:不在内核里。那行提示符,是住在 ring 3 里的程序递出来的。开机以来头一回,执行流站在内核之外,等着您说话。

第 1 部收尾时咱们说,认全了的机器,接下来要看它怎么长出章程。章程的头一道,就是这道提示符背后的户口:同一台机器,凭什么有的代码能使唤全部指令,有的代码连一条 cli 都摸不着。两边要递话,又得走哪扇门。前置卷《四象限导览》里,您拿 ps、top 看过的那些进程,张张都是 ring 3 的脸,这一部咱们下到底层,看这样的脸怎么长出来。这一章咱们办三件事。头一件,看门牌怎么换,头一跳怎么把执行流送进 ring 3。再一件,认快门怎么装,SYSCALL 与 SYSRET 那对指令,靠哪几件寄存器当家。末一件,验往来的章程,内核凭什么不把客人递来的指针照单全收。

量法这一章,门牌走书,快门走屏。门牌那一半,书是全的:前置卷《计算机怎么工作》的《保护模式与长模式预览》整篇替咱们铺过,DPL=3 的段项您亲手排过,ring 3 里一条 mov %cr0 被 #GP 当场摁住的屏也亲眼看过,那边的机理本章直接接手,不重铺。《深入理解计算机系统》第 8 章整章讲异常控制流,内核态与用户态的分节就在里头,咱们照 1.7 立下的口径,只核到章号,一页没引。快门那一半,书架上没有书:SYSCALL 与 SYSRET 的正式条文住在 Intel 的手册里,咱们没这本,所以这一半只有源码和自家屏,快多少慢多少,只有量级,没有数。

> **同一只 cs,0x33 与 0x8,机器看的是哪两位?那两位,念的又是什么身份?**
>
> 看的是尾巴,两枚门牌各自的末两位。这两位念的就是特权级,咱们逐枚认过去。住 0x8 的,是机器的主人。住 0x33 的,是请进来的客人。

## 门牌:两枚选择子,一层身份

特权级这个名字,咱们正式立起来。x86 把机器分成四层,行话叫 ring 0 到 ring 3。这个编号得反着念才对:数字越大,权限越低,ring 3 是最不特权的一层。咱们两头各用一层,ring 0 住内核,ring 3 住客人。中间两层,x86_64 的系统们几乎没人真用,咱们也不置办。顺带认个亲:本章说的门牌,是 cs 里装的那枚段选择子,跟 1.5《与设备打交道》里端口的门牌不是一回事,那头是设备的地址,这头是 CPU 自家的户口。

门牌长在两处,咱们各认一遍。头一处长在 GDT 的描述符里。1.4 拍过,描述符八个字节一项,权限字节里躺着两位 DPL,那是段的出身:主人的段 DPL=0,客人的段 DPL=3,前置卷的镜像里您把 DPL=3 的两项亲手排过。另一处长在段选择子上。选择子您也熟:cs 可见的那半截装着它,右移三位查表,1.4 走熟的换算。低两位是 RPL,门牌自带的前缀,念的是这枚门牌要求享受的权限。装载那一刻两边要相认:客人的门牌配客人的段,RPL 3 对 DPL 3,对得上才装得进去,前置卷压栈掉进 ring 3 走的就是这一路。而机器此刻是谁,cs 的低两位说了算:cs 装着 0x8,全机按 ring 0 办事。装着 0x33,全机按 ring 3 办事。

住在 ring 3 里到底少了什么?前置卷的屏给过答案:同一条 mov %cr0,ring 0 里读得,ring 3 里一执行,#GP 当场把机器拉回 ring 0,cli 同罪。这类指令行话叫特权指令,管的全是要紧处:关中断,改页表,停机,客人世界里一个都不卖。前置卷《内核是什么》里您还见过另一面:用户态一条 hlt 送到真正的机器上,当场吃一个 SIGSEGV。那是别人家机器上的观察。自家的这道墙,今天咱们亲手砌,砌墙的手续在实况节。真拿 cli 撞这道墙的实弹,在正文《第一跳实弹》,那头机器按异常的惯例收场。

**门牌的念法容易念反:0x33 与 0x8,数字大的那枚,您猜它手里的权限更高还是更低?**

0x33 折成二进制是 0b110011,末两位 11,念 3。0x8 是 0b1000,末两位 00,念 0。3 比 0 大,权限反倒低:ring 3 的门牌,连一条特权指令都使唤不动。往后您再见着 0x2b、0x23 这类数,都照这个法子办:末两位头一眼看,右移三位再查表。

## 快通道:进门的 SYSCALL,出门的 SYSRET

客人住进 ring 3,总得有条路办事:打一个字上屏,等一键进门,办完还得能退场。第 2 部下一章讲中断与异常,那套机构里有一扇老门,客人拿 int 指令也能敲,可那扇门关卡多:要过 IDT 查表,要按门里定好的格式压帧,一路盖章。x86_64 给系统调用另开了一对快指令,SYSCALL 进,SYSRET 出,咱们叫它快门。快门的路标不躺在 IDT 里,躺在 MSR 上。进门以后的帧,也不劳硬件压,咱们自己的汇编铺。

机关全安在四件 MSR 上。MSR 是一批编号暗格,1.4 换长模式时您跟 EFER 打过交道,EFER 就是头一格。四件各管一样,咱们一件一件过。

EFER.SCE,开关。EFER 的第 0 位立起来,SYSCALL 与 SYSRET 这对指令才算在指令集里活着。自家日志里咱们见过它:1.4 认过的读数 0x500,LME 与 LMA 两位,如今串口上印的是 501,多出来的那个 1 就是 SCE。

STAR,两段选择子的住处。一格 64 位,装两枚门牌。usermode.cpp 里 kStarValue 一行拼算式:0x23 左移 48,0x08 左移 32,拼成一个数写进去。63 到 48 位住着 0x23,SYSRET 出门用的基值。紧挨着的 47 到 32 位住着 0x08,SYSCALL 进门用的内核代码门牌,余下的低位机器留着自己用。这两句眼下空口无凭,实况节咱们拿两屏读数当场对。

LSTAR,快门的地址,咱们往里写的是 &SyscallEntry。SYSCALL 一执行,RIP 就跳去这个址。

SFMASK,进门那拍顺手摘旗的清单。咱们写进去的值是 0x200,正是 IF,1.6 里认过的第 9 位。客人进门,旗当场摘下来。syscall.S 里十二槽帧压完,一句 sti 再把旗请回来,十二个槽的构成,正文《柜台与三条约定》逐格摆过。摘与还之间,换栈、建帧那十几拍,谁也插不进来。

这四件在启动次序表里占一步。次序表,您在正文《桌还缺四件》见过它的来历,如今 init_sequence.cpp 里十二步排开,fast system calls 一步,干的就是这四次写。

头一跳下楼,借的是 SYSRET 的回程半边。头一回跳的时候,SYSCALL 进门受理的那座柜台还没接过一单,客人一个都没有,没有回程票可买,想下楼,只能把出门的道倒着走一遍。跳板在 usermode.S 里,五条指令,咱们逐条念:

```asm
JumpToRing3:
    movq %rdi, %rcx
    movq $0x202, %r11
    movq %rsi, %rsp
    subq $8, %rsp
    sysretq
```

咱们一条一条对下来。开头 movq %rdi, %rcx,入口地址从 rdi 挪进 rcx,SYSRET 落地时 RIP 从 rcx 里拿,回家的址,存好。跟着 0x202 写进 r11,落地的旗:第 9 位 IF 立着,客人落地时中断是开的。往下栈顶从 rsi 挪进 rsp,再降 8。页顶除 16 余 0,本来齐整,这 8 个字节降下去,落点除 16 余 8,不在整边上,恰好是 SysV 定的进场落点。SysV 是 x86_64 上 C 程序通行的调用约定,函数进场寻常靠 call,返回地址一压上栈,进场的栈口就落在余 8 上,客人那头的代码由编译器排位,暂存的位置全照这副样子来放。跳板不是 call,这 8 个字节替它把返回地址的位子空出来,后头排开的家当,才都落得回 16 的整边。末了 sysretq,出门:cs 落成 0x33,ss 落成 0x2b,执行流从此住在楼下。

出门落成的 0x33 与 0x2b,是 STAR 基值 0x23 拼出来的:基值加 8 得 ss,加 16 得 cs。基值自己的末两位是 3,拼出来的门牌天生带着 RPL 3,usermode.cpp 里那枚断言管的就是这一折。当年这基值填过 0x20,拼出来的 ss 不带 RPL 3,SYSRET 出门装出一枚内核身份的栈段,头一个时钟中断就吃了 #GP,救火烧了两百来行。这一遍,这个数由编译期断言摁住,细节咱们留到对照里再认,全本在正文《七个座位与一口备用锅》。

**两样家当,进门那拍得寄存:客人回家的地址,和身上带的旗。您猜,各进了哪只寄存器?**

地址进了 rcx,旗进了 r11。SYSCALL 指令自带的章法:执行那一拍,RIP 自动存进 rcx,flags 自动存进 r11,然后才跳 LSTAR。这不是咱们的代码搬的,是指令自己的动作。SYSRET 出门,照原样取回去:rcx 里的址还给 RIP,r11 里的旗还给 flags。实况节咱们把两只寄存器冻在进门那一拍,当场翻出来对。

## Code: Cinux 实况:首跳、两屏、一道章程

实况锚 r13_userspace,ring 3、syscall 与 shell 齐活的那一版。您要亲手跑,git switch --detach r13_userspace 切过去,行号都按这一版数,看完 git switch - 切回来,新克隆的仓落回 main。起机的两条老话照旧:镜像得显式重打,拿陈镜像开机,开出来的还是上一版的机器,楼下一位客人都没有。这一版的日志全走真串口,build/console.log 整本收下,debugcon 那头一个字节都没有。另外,这一版的机器有个新脾气,起它之前您得知道:它不会自己停。跑到末尾,shell 在 ring 3 里等您敲字,您不敲,它就在那儿等。所以咱们外头包一层 timeout,到点收场。至于 -S,它把机器冻在头一条指令上,断点才来得及候场。

```bash
git switch --detach r13_userspace
cmake -B build && cmake --build build --target boot_image
timeout 90 qemu-system-x86_64 -accel tcg \
  -drive format=raw,file=build/boot/cinux.img \
  -display none -no-reboot -S -gdb tcp:127.0.0.1:1214 \
  -serial file:build/console.log \
  -debugcon file:build/debugcon.log &
```

头一拍,首跳的手续,咱们在 kernel.cpp 里逐行看。:155 一声 [kern] launching shell in ring 3 报幕,:157 起四件套开张。第一件,:157 到 :158,AddressSpace 起新开一张空户口,init 把页表根立起来。第二件,:159 到 :169,安家。kUserCodeBase 定在 0x400000,kUserStackBase 定在 0x500000,一枚代码页一枚栈页。代码页的家底在 :162 到 :163,shell 的本尊编在内核镜像里,链接符号 g_user_shell_start,nm 念出 0xffffffff8020a000,减掉 kKernelImageBase,物理址 0x20a000。map_user(0x400000, 0x20a000),盘上进来的那页字节,从此在客人的世界里有了门牌。本尊 0x4dd 个字节,一页绰绰有余。栈页 :166 另请,Pmm 分一页物理内存,:169 同样映过去。第三件,:171,user_root 把户口记下,调度器从此认得楼下的住户。第四件,:172 到 :174,cli,activate,JumpToRing3:关中断,LoadCr3 把新户口换成现役,跳板五条下楼。activate 之后内核自己的高半世界还在,同一张页表里两边都画了,客人的世界是新画的那半。地界的全本在正文《客人的世界》,咱们实况只认次序。

机器跑起来,串口整本收进 console.log,59 个换行,前 55 行咱们顺着念下去,前头认过的 efer 501 也排在里头。您认得的旧面孔:e820 打 1.5 起,心跳打 1.6 起,名册也是 1.6 里照的面,1.7 接过来细读。堆、键盘,外带六位内核任务的三场拉练,头一回在这本日志里跟您照面,来路住在正文后面的几卷,教科书层走到那儿再认。咱们从拉练收尾处接抄,末五行是原文:

```text
[kern] preemptive tasks drained without a single yield
[kern] market closed the loop, preemption stays armed
[kern] launching shell in ring 3
cinux shell - type 'help'
cinux>
```

末行 cinux> 后头那个换行,是咱们排版补的,机器没打。cinux shell - type 'help' 这一整行,连那枚提示符,全是 ring 3 里的 shell 打出来的。递法分两层:shell 那头横幅一整串,一回 write 就递完,提示符也是一回。柜台这头,handle_write 里 PutChar 一字一字落屏。一回递,一字落,边界正好踩在 syscall 上。机器把等您说话这件事,交给了楼下的客人。

第二拍,楼下的现场。GDB 上场,咱们布两枚断点,一枚候在客人门口,一枚候在柜台:

```bash
gdb -q -nx -batch \
    -ex 'set architecture i386:x86-64' \
    -ex 'target remote 127.0.0.1:1214' \
    -ex 'break *0x400000' \
    -ex 'break *0xffffffff80207089' \
    -ex 'continue' \
    -ex 'info registers cs ss rip' \
    -ex 'continue' \
    -ex 'info registers cs ss rip rcx r11 rax' \
    -ex 'x/i 0x400021' \
    -ex 'detach'
```

第二枚断点的址,是 LSTAR 里写的那个 SyscallEntry,咱们拿 nm 在自家产物上查得着:nm build/kernel/cinux_kernel 里 grep SyscallEntry,0xffffffff80207089。头一停:

```text
Breakpoint 1, 0x0000000000400000 in ?? ()
cs             0x33                51
ss             0x2b                43
rip            0x400000            0x400000
```

target remote 的报到,Breakpoint 的落锚,detach 的道别,这类程序行抄屏时咱们一并略去,只留您要认的读数,后头两屏同此。

cs=0x33,ss=0x2b,rip 正落在客人的门口 0x400000 上。咱们把两枚门牌当场验一遍:0x33 末两位 11,RPL 3。右移三位得 6,GDT 第 6 项,用户代码段。0x2b 末两位 11,右移三位得 5,第 5 项,用户数据段。gdt.hpp 里 0x2B、0x33 两条断言管值,第 5 项、第 6 项两条管座位,SYSRETQ user data lands at 0x2B,SYSRETQ user code lands at 0x33。楼下,名实相符。

第三拍,进门的那一拍。咱们一句 continue 放行,shell 头一件事是把开张的横幅打上屏,write 的 syscall 就在门口候着,第二枚断点应声而停:

```text
Breakpoint 2, 0xffffffff80207089 in ?? ()
cs             0x8                 8
ss             0x10                16
rip            0xffffffff80207089  0xffffffff80207089
rcx            0x400023            4194339
r11            0x206               518
rax            0x1                 1
```

进门即 ring 0:cs 已经是 0x8,ss 已经是 0x10,STAR 里那枚内核代码门牌,SYSCALL 一到就换上了,没有半个内核态可讲。再看 rcx,0x400023,这是客人回家的址。信不信,咱们拿反汇编验一条,x/i 0x400021:

```text
   0x400021:	syscall
```

syscall 是条两字节的指令,0x400021 加 2,正是 0x400023,指令自己把下一条的址存进了 rcx,严丝合缝。r11 是 0x206,咱们在里头认得出 0x200,IF 的开关,客人那边中断开着,旗原样寄存在这儿。rax 是 1,write 的编号。syscall.hpp 里的编号表,read=0,write=1,yield=24,exit=60,号码整套跟 Linux x86_64 排的一样,为什么跟它排,留到对照里交代。快通道一节末那两问,这一屏全答了。

第四拍,柜台上的章程。客人递话,内核不照单全收。咱们看 syscall.cpp 的 handle_write,头两道检查在 :39 到 :44:

```cpp
    if (descriptor != 1) {
        return -cinux::syscall::kEbadf;
    }
    if (buffer >= cinux::syscall::kUserAddressLimit) {
        return -cinux::syscall::kEfault;
    }
```

头一道验 fd,不是 1,退 -9,kEbadf。第二道验指针,buffer 不小于 kUserAddressLimit,退 -14,kEfault。0x0000800000000000,低半世界的天花板,客人的指针只许住在它底下。这道验咱们不当作多疑,它是章程。客人递来的只是一个数,数落不落在客人自己的地界里,得内核说了才算。不验,客人写歪一个数,内核就要照着它往自家屋里落笔。1.8 那两道魔数闸,boot 验户口本,与这道指针闸是同一门里的手艺,咱们都是验明白了才用。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,咱们核过的还是书页 25 与 28 那两页:加载器把内核搬进 0x80000000,跳进 _entry,特权级在那两页上一个字都没有。RISC-V 的机器自然也分主客两层,叫法还不一样,可书没翻到那儿,咱们不越页引,它家的章程,等翻到的那天再说。

Linux 那头,两副门牌是天天在用的日常:您在前置卷里敲过的每一声 write,背后都是一位 ring 3 的客人递话、ring 0 的柜台收单。它家章程的底细,咱们没去翻人家的手册,号码为什么排成这样,不知道。可有一层公约,两边早通着:咱们的编号表打出生起照 Linux x86_64 的号码抄,为的是将来 musl 那样的 C 库、busybox 里那样的程序来敲门,报号就认,咱们不用改一行,它们也不用学新话。号码是门通用的黑话,咱们把自家柜台的字,写成跟人家一样。

为什么咱们不把楼修得再大些,这笔代价摊开算。老门不走,有些内核拿 int 指令那扇门做系统调用,门里机关多,咱们只装快门。vDSO 不设,成熟的系统会把问时间这样的小活直接搬进客人的半区,省一趟敲门,咱们楼下的客人就两位,犯不上。客人的家一刀切,两位客人都住 0x400000,一次只请一位进店,想同时住店,得等第 3 部的分页正戏唱完再添床位。三条全是实打实花出去的,咱们如实记下,不装白得。

C++ 这一回出场的地方在 usermode.cpp,咱们去看两条断言,一上一下守着 kStarValue。:20 的一条,断言把 kStarValue 右移 48 位,要求结果还是 gdt::kSysretStarBase,也就是说,STAR 拼好之后基值末尾那个 RPL 3 不许在拼装里丢。丢的那年,SYSRET 出门的 ss 不带 RPL,头一个时钟中断就 #GP。:21 的一条,断言把 kStarValue 右移 32 位再取低 16 位,要求落在 gdt::kSelectorCode 上,进门那半必须是 0x8。两条都不信运行期。基值哪天手滑改了,编译不过,机器根本起不来,更轮不到时钟中断来揭发。gdt.hpp 那边还有一排同门,0x2B 与 0x33 两条管值,第 5 项与第 6 项两条管座位,同一副门牌,两道岗。当年两百来行的救火,这一遍全折进编译期这几行里。装反了,喊出来的不是崩屏,是编译器一句硬话。

## 这一章留下了什么

落下的物件不多,咱们一样一样点。两枚门牌,cs=0x33 与 cs=0x8,末两位念特权级,数字大的权限低,0x2b 与 0x10 是栈段那一对。四件 MSR,EFER.SCE 开指令,STAR 装两段门牌,LSTAR 定门址,SFMASK 摘旗。一对快门,SYSCALL 进,址与旗寄存在 rcx 与 r11,cs 换 0x8。SYSRET 出,原样取回,cs 落 0x33。一道章程,kUserAddressLimit 立界,客人递来的指针,验过再用。楼下的客人开张了,可机器还欠一样活:客人要是跑飞了、跑死了,或者外面的世界来敲钟,谁去拉它一把。那是中断与异常的戏,下一章开场。

| 术语 | 一句话口径 |
|---|---|
| 特权级 | CPU 自带的分层户口:ring 0 到 ring 3,数字越大权限越低 |
| 段选择子 | 段寄存器可见半截里的门牌:末两位 RPL,右移三位查 GDT |
| RPL | 门牌自带的权限前缀:0x33 尾巴上的 11,念的就是 3 |
| 系统调用 | 客人隔柜台递话:编号进 rax,SYSCALL 进门,SYSRET 出门 |
| MSR | 一批编号暗格:本章四件,EFER、STAR、LSTAR、SFMASK 全住这排 |

## 练一练

门牌与快门都认过了,考手艺的三道题,两道对着屏,一道对着断言。头一道动手,您自己起机器截那两屏。第二道猜想,拿断言当判官。第三道读屏,把进门那屏的几行逐格认主。

**题一,动手。** 切版、构建、起机,实况节那三行原样抄来就能用,不重印了。机器冻在复位点上,您把 gdb 这半边接上,跑完抄两屏:

```bash
gdb -q -nx -batch \
    -ex 'set architecture i386:x86-64' \
    -ex 'target remote 127.0.0.1:1214' \
    -ex 'break *0x400000' \
    -ex 'break *0xffffffff80207089' \
    -ex 'continue' \
    -ex 'info registers cs ss rip' \
    -ex 'continue' \
    -ex 'info registers cs ss rip rcx r11 rax' \
    -ex 'x/i 0x400021' \
    -ex 'detach'
```

detach 之后机器接着跑进 cinux> 等您,timeout 到点它自己收场,console.log 里五十九个换行,一个都没有少。末了 git switch -,回家的址 git 早替您存好,新克隆的仓落回 main。

**题二,猜想。** gdt.hpp 里 kSysretStarBase 这一枚,哪天手滑把 0x23 改成 0x20,编译器会喊哪几条断言?还是一条都不喊,要到机器跑起来才见分晓?您对着 gdt.hpp 与 usermode.cpp 里那几条 static_assert 推一推,再回参考答案里对。

**题三,读屏。** 实况节第三拍那屏,rax、rcx、r11 各念的什么?您再把 r11 的 0x206 摊开认一认:0x200 是哪一位,客人那边中断开着还是关着?

### 参考答案

题一:您跑出来,两屏应当长这样:

```text
Breakpoint 1, 0x0000000000400000 in ?? ()
cs             0x33                51
ss             0x2b                43
rip            0x400000            0x400000

Breakpoint 2, 0xffffffff80207089 in ?? ()
cs             0x8                 8
ss             0x10                16
rip            0xffffffff80207089  0xffffffff80207089
rcx            0x400023            4194339
r11            0x206               518
rax            0x1                 1
```

您看 cs 从 0x33 换到 0x8,换上的正是 STAR 里那枚内核代码门牌。rcx 与 r11 里,客人回家的址和旗都寄存着,与快通道一节末那道寄存题对上。

题二:编译器喊的是 gdt.hpp 里 0x2B 与 0x33 对应的两条断言。kSelectorUserData 与 kSelectorUserCode 都从基值加出来的,基值 0x20,加 8 得 0x28,加 16 得 0x30,一个不等于 0x2B,一个不等于 0x33,编译当场停。usermode.cpp 里的两条反而不响:0x20 折进 kStarValue,右移 48 还是 0x20,跟改过的基值自己相等,自洽。要不是 gdt.hpp 里这两道岗守着,0x20 就真写进 STAR,SYSRET 出门的 ss 换算成 RPL 0,当年那场 #GP 就重演。咱们让编译器喊在前头,机器一次都不用起。

题三:rax=1,write 的编号。rcx=0x400023,咱们认过,是客人回家的址,syscall 下一条的落点。r11=0x206,客人那边的 flags,0x200 是 IF,立着,客人那边中断开着。
