# 03 · 系统调用:号、话、错,柜台开张

打头的是三枚负数:-9、-38、-14,机器亲口报出来的。三枚报的都是拒单:头一枚嫌的是门牌不对,中间那枚嫌的是号没登记,末一枚嫌址越了界。拒得是干脆的,名目还各是各的。这一章咱们看它怎么开张。

上一章末了记下三件差事:编号怎么定,话怎么递,错怎么报。更早一章还埋着一单:头一跳下楼的时候,SYSCALL 进门受理的那座柜台还没接过一单。这一章咱们三件差事一并交卷,埋下的那一单,今天咱们接上。柜台门外的样子,咱们其实看过:前置卷《内核是什么》里拿 strace 数调用,一行一次的调用,写成的是名字(参数) = 返回值,`write(1, "hello\n", 6) = 6` 的那一行,是程序在用户态里喊的一声,内核替它把六个字节写到了 1 号,再交还了一个 6。同一卷里还借书上的话记过一笔:系统调用有唯一的整数编号,背后挂着的是一张表。门外看的,那是别人家的机关。进了门里看,编号和表都得咱们自己立。

这一章的量法,门里的家当对码,门外的回音对屏,公约的那一头,书翻到了。表与帧咱们逐件读的是自家源码。三枚负数与五单会话咱们自家起机亲手抄。书是 xv6 那本:2.2 对照节里咱们许过愿,等书翻到的时候当面比。如今翻到了第 4 章,书页 46、47、48 的三页咱们逐字读过,今天比的就是这三页,守的是一页不越。

> **客人隔着柜台喊的那一声,内核凭什么听得懂?听懂了,又凭什么敢照办?**
>
> 怎么算听得懂,靠的是约好的三条黑话:号怎么报,话怎么递,错怎么回。怎么才敢照办,靠进门以后的验与拒:号在表里才有人应,址在界内的话才动手,办完了回执走原路。三条黑话的约定,配的一副家什,这一章咱们一件一件立起来。

## 号、话、错:开张的三条约定

头一条立的是号。号码咱们整套照 Linux x86_64 抄:read 0 号、write 1 号、yield 24 号、exit 60 号,躺在内核头文件 kernel/syscall/syscall.hpp 的 SyscallNr 枚举里,四枚值挨着各自的 Linux 真名写注释。

为什么照别人家的抄,2.1 写柜台字的时候交代过:号码是行话,将来 musl 那样的 C 库带着编译好的程序来敲门,报了号就认。这里补一层:枚举住在内核的头文件里,客人的封装把它一并包含,号码的这本词典,门里门外读的是同一份。24 号为什么夹在 1 和 60 中间,怎么不顺着自家排成 2?因为空号位不是无主的地:24 号在 Linux 那边住着 sched_yield,咱们让 yield 认下同一块门牌,词典里就出不了重号。往后再添号的话,也轮不到咱们去挪空位。等词典重排了,照老词典背号的客人,就找不着家门了。

第二条递的是话。咱们递话的家什是 user/api/syscall.hpp,文件名和内核的一模一样,两户是同名的,您别走错门,文件头的第一句写着 Not a libc——它不是 C 库,咱们也没打算让它当,每个封装就是一条内联的汇编,桥就这么宽:

```cpp
    __asm__ volatile("syscall"
                     : "=a"(ret)
                     : "a"(number), "D"(arg1), "S"(arg2), "d"(arg3)
                     : "rcx", "r11", "memory");
```

看住两头的是一条指令。进去的那头:号进的是 rax,头一件话进的是 rdi,第二件进了 rsi,第三件进了 rdx,座位照的是 Linux 的排法。rcx 与 r11 也列在了 clobber 里,缘故 2.1 拍过的:进门那一拍,指令把回址写进了 rcx、旗写进了 r11,这是指令自己的动作,咱们的代码没有搬过它,可两枚跨过这趟门就丢了原值,咱们得让编译器知道。剩下的那句 clobber 清单,是写给编译器的一句许诺:过这趟门,烧掉的只有 rax、rcx、r11,再没有别人了。这句许诺两头各认一半:客人信了它,才敢把值驻在别的寄存器里跨门复用。内核就得认下它的一头,进门碰过什么,出门就原样奉还什么,兑现的活,下一节咱们亲眼看。Linux 的座位表上,四五六号参数占的还有 r10、r8、r9 三枚,Cinux 眼下的话只收三件,那三枚在帧里留了座位,咱们没派差事。

第三条报的是错。回执走的是 rax。办成了,咱们回零或正数:write 回写出去的字节数,yield 回的是 0。办不成的话,咱们回负数,负号后头跟的是一枚 errno:号没登记的话,退的是 -38:kEnosys。门牌不对的,咱们退 -9:kEbadf。址越了界的话,咱们退 -14:kEfault。-9 与 -14 的语义,2.1 在 handle_write 的两道岗上拍过,这里咱们只把它们并成一家:拒号、拒门、拒址,拒在了哪个环节,说话的是负数本人。exit 是没有回执的。办完了这一单,收话的人已经不在了,封装里把 Exit 标了 [[noreturn]]。这副公约不是咱们独造,xv6 的书页 47 有句原话,对照节里咱们当面引。

## 门里:一张表,一副帧

SYSCALL 进了门,门里接活的家什是一张表、一副帧:表管谁应单,帧管怎么活着回来。咱们各认一遍,起头打的是表。syscall.cpp 里的 kHandlers 有 61 格,编号排的是 0 到 60。exit 的 60 号住最末一格,表就铺到了头。立表用的是 constexpr make_handler_table,编译期就排完了:read、write、yield、exit 四格有主,余下的 57 格是 nullptr。接单的入口是 InvokeSyscall,头一句摆的就是岗:

```cpp
    if (number >= cinux::syscall::kSyscallCount || kHandlers[number] == nullptr) {
        return -cinux::syscall::kEnosys;
    }
    return kHandlers[number](arg1, arg2, arg3);
```

号出了表长的话,或者格子里空空的,咱们一律退 -38。空号的应答还是有的,-38 就是应答:拒收的也是一句话,柜台是不装聋的。真有客人来敲空号会是什么样,实况节咱们拿 99 号当面试。表的差事办完,轮到的是帧。帧的正文在 syscall.S,咱们把进门那一段念:

```asm
SyscallEntry:
    swapgs
    movq %rsp, %gs:8
    movq %gs:0, %rsp
    pushq %rbp
    # (中间十拍:自 rbx 一路压到 rcx)
    pushq %gs:8
    sti
```

头一拍的 swapgs,换的是 GS 的基址。GS 的本体是一枚段寄存器,咱们往它身上挂了 gs:0、gs:8、gs:16 一排编号暗格,基址定的是这一排编号落在哪片地上。GS 备着的是两枚基址:客人世界、内核世界各一枚,swapgs 对调的就是这两枚。咱们眼下把两枚 base 都写成同一片地的地址,换了其实等于没换,可这一拍省不得:将来客人有了自己的 TLS(线程局部存储,每个线程一块自留地),它才是两个世界的分界线。来历的全本在正文《MSR 件与 GS 落脚点》。跟着的两拍换栈:进门前 rsp 还是客人的,暂存进了 gs:8,gs:0 里备着的是内核栈,一拍就换上了。往下的十二拍压帧:rbp 打头,跟着的是 rbx、r9、r8、r10、rdx、rsi、rdi、rax、r11、rcx 十枚居中,末一拍把 gs:8 里那枚客人栈顶也压了进去。咱们管它叫十二槽帧:十二槽、96 字节。帧压齐了,sti 才把中断请了回来。为什么排在末尾?马上咱们就对。再往下的四拍搬参数,汇编里写的是 movq 24(%rsp), %rdi 一类:24 是 rax 的槽,编号搬进的是 rdi,32、40、48 三槽装的是话,搬进了 rsi、rdx、rcx,C++ 那边的 InvokeSyscall 收四个参数,座位跟座是对得上的。搬完了 call InvokeSyscall,C++ 接了手。

**咱们停一停,99 号的班咱们来当一回。** 假如这一单是您在柜台里当值:客人敲的是 99 号,从进门的那一拍起,这一单怎么走?走到了末了,rax 里躺着的是谁?

咱们当班走一遍:swapgs 换基址,客人栈顶进了暗格,内核栈换上了,十二槽压齐了,sti 开了中断,参数搬了座,InvokeSyscall 上了工。头一句问 99:比 61 小吗?不小的话退 -38,原路返回:-38 进了 rax,十二槽还原了,sysretq 送了客。您数数,受理一单的工序一步没少,只是查表的那一步,给了句拒收。空号的待遇就是全套工序加一句 -38。

出口在汇编的后半段,咱们挑头几拍念,回值那一枚绕了一道手:

```asm
    movq %rax, %gs:16
    movq 32(%rsp), %rdi
    movq 40(%rsp), %rsi
    movq 48(%rsp), %rdx
    movq 56(%rsp), %r10
    movq 64(%rsp), %r8
    movq 72(%rsp), %r9
```

头一拍的活:回值从 rax 挪进了 gs:16 暂存,一进一出像白走了一趟,为什么绕这一道,后头 rdi 与 rbx 的两案就是答案。跟着的六拍:rdi、rsi、rdx、r10、r8、r9 自帧还原。再来的四拍:rcx、r11、rbx、rbp 归位。rcx 与 r11 进门时硬件替咱们存过一份,C++ 这一路又随便用了它们,帧里的存底是出口时唯一信得过的。末了,rsp 从第 0 槽重建了出来,回值自 gs:16 取回了 rax,客人的 GS 基址换了回来,sysretq 出了门,cs 落了 0x33,执行流回到了楼下。

sti 为什么排在帧尾,这笔咱们对前后两头算。进门的那一拍,SFMASK 预写好的 0x200 把 IF 摘了,2.1 讲快门的时候拍过。帧立稳了,sti 请了回来。出了门,SYSRET 从 r11 把旗原样还给了客人,也是 2.1 拍的。摘到 sti 的中间,换栈、建帧的那十几拍一个中断都不许插进来。跟 2.2 的中断门对着看,干的工一样,位子是不同的。老门的两下全由硬件包办:进门自动摘、iretq 出门自动还。快门的两下归了软件:预写的清单摘、r11 寄存着还。守的是同一件事:现场没铺齐的时候,咱们不许来客。往后柜台里等活也不闭门:read 等键的当口 IF 立着,时钟照旧响它的,1.6 拍过的外线与本章立起的柜台互不耽误,在这里合上了圈。

**咱们停一停,回程的家当咱们逐项过一遍。** yield 的那一单:封装递的是 24 号,进了门,InvokeSyscall 里 Scheduler 打了个转,CPU 让了出去又拿了回来,SYSRET 落了地。落地的那一刻,咱们回看这副十二槽的帧:哪几槽换了值?

咱们逐槽查下来:一槽都没换。yield 切活是 CPU 跑去别的任务的栈上转了一圈,这一副帧躺在自家任务的内核栈上,原样地候着。帧是跟着任务走的,不跟着 CPU 的脚步走。真变了的东西都在帧外:执行流出去绕了一圈,回值 0 要等任务回来才生出来:yield 把 0 交了出来,InvokeSyscall 收进了 rax,出口才进了 gs:16。帧外还有一件悬的,下一段咱们说它。

悬的是第 0 槽。客人栈顶进门的时候存过 gs:8,出口要重建 rsp 的时候,为什么不再读 gs:8,非要压进帧里带着走?因为 gs:8 是枚公共暗格:柜台中途会换任务,yield 就是这么换的。换进来的下一位 ring 3 客人一进门,头一拍就把自家栈顶写进了 gs:8,旧值就地被盖了。第 0 槽是不一样的,它长在任务的内核栈上,任务在的时候它就在。咱们回程重建 rsp,只能信跟任务走的存底。十二槽里十一槽存的是寄存器,唯独这一槽存的是任务的退路,帧结构里它的字段名就叫 user_rsp。

帧里为什么连参数寄存器都要存、出口还要一拍不少地还原?这一版咱们自己疼过一回,咱们把案子办了。案发在了 hello 头上:连写两行,第二行无声地丢了,别的照常。破案走的是反汇编,全本在正文《只烧三个寄存器的承诺》,裁决念出来的是这样:包装许过编译器,过门只烧的是 rax、rcx、r11,编译器信了,打的是很精的算盘。fd 的 1 装进 rdi 一回,两次调用共用了一回,write 的编号也是 1,连编号那一拍都是从 rdi 派生的。可门里这头 rdi 正是 C++ 排头的参数寄存器,InvokeSyscall 一路走了下来,它早被碾成一个高半区的内核地址。第一版出口只还原了 rbx 与 rbp。按编译器的行话,rbx、rbp 一类的 callee-saved,被调的一方保证原样奉还。rdi、rsi、rdx 这类的参数寄存器是 caller-saved,保它们的事归调用者自己。它只顾了前一半,rdi 出门时是什么就是什么。于是第二单进了门,编号栏里躺的换成了 0xFFFFFFFF8028A6E0 一类的数,远超了表长,柜台照章退了 -38,整整齐齐地拒了,悄无声息地丢了。修法就是出口的那六拍:caller-saved 自帧还原了回来。许诺许出去的,兑现的是内核自己。

咱们把时间拨回第一遍,这一案有位当姐姐的。第一遍的 shell 也演过怪戏:回显正常,命令全失效了,字是打得上屏的,回车敲了下去,什么也没发生。查下来:read_line 内联了之后,写入的位置 pos 驻在 rbx。那年的入口汇编拿 rbx 暂存返回值,用完了也不还,callee-saved 就这么毁了。pos 每过一次门就被回值的 1 压回原处,字符一个个全写进了 line[1],行首的 line[0] 从出生起没人碰过,末了 tokenize 收到的是一枚空串。修的路子跟刚才那一案同根:返回值挪去 gs:16,rbx 自帧还原了回来。咱们把两案并排,病根一条:硬件自保的只有 rcx 与 r11,其余寄存器的平安全凭内核进门出门的自觉。约定是双向的,兑现的那一方恰恰是内核。今天帧布局的断言群里,给 rbx 留的断言,消息说的还是这桩旧案:`the rbx lesson stays pinned`。

## Code: Cinux 实况:起机、五单、三根针

实况锚 r13_userspace 是 ring 3、syscall 与 shell 齐活的那一版,2.1 首跳用的也是它,切版与镜像的老话那边念全了,这里不重印了。这一场的新意在喂键:前两章咱们要么冻机器上断点,要么扎一针读日志,这一回柜台开了张,咱们得当客人,亲手把单下了。QEMU 的 monitor 接在 stdio 上,起机等到了横幅,一行一条 sendkey 把话递了进去:

```bash
git switch --detach r13_userspace
cmake -B build && cmake --build build --target boot_image
timeout 120 qemu-system-x86_64 -accel tcg \
    -drive format=raw,file=build/boot/cinux.img \
    -display none -no-reboot \
    -serial file:build/console.log \
    -monitor stdio
```

-display none 底下是没有屏幕看的,横幅全走的是串口文件,您再开一窗跑着 tail -f build/console.log,TCG 起机您要等上一阵,那一窗里日志一行行地积起来,积到 cinux> 露头的时候,就能喂键了。键名的事 monitor 自己认,咱们只记三样:字母原样,空格记的是 sendkey spc,回车记的是 sendkey ret。头一单的 help:sendkey h、sendkey e、sendkey l、sendkey p,末了 sendkey ret。往后的每一单照此喂。exit 敲完了,串口连一行都没有了,timeout 到了点收了场,五单全录在了 console.log 里。面板上的 e820 还是 7 条,老话就不重叙了,kernel at 200000 size 90A20 是 1.8 讲过的那套户口,个头是随版本长的。pmm 报的是 32316:1.6 的屏 32347,1.7 的屏 32350,2.2 的屏 32348,四站四屏各认各的,咱们别互相串。再往下的 vmm、heap、keyboard 全是新面孔,咱们只认名不展开,堆的去处是第 3 部的戏,调度与任务的排场是 2.4 的戏。irq 是咱们的旧相识,1.6 的屏里就是这一行,1.6 的实况里追过它的来路,咱们不再展开。面板咱们从 pmm 那行起抄在底下:

```text
[kern] pmm: 32316 pages free (probe 113000 ok)
[kern] vmm: address space up, magic 114514
[kern] heap: new/delete live (probe 114514)
[kern] irq on, tick 100Hz
[kern] keyboard on, type to echo
```

再往下的六位内核任务的拉练,流水打进了日志,这一场是老班子的保留节目,咱们不逐行数、直接翻到会话:

```text
cinux> help
commands: echo <text...>, help, yield, exit
cinux> echo ring3 knocking
ring3 knocking
cinux> kernelx
unknown command: kernelx
cinux> yield
yielded and back
cinux> exit
```

咱们逐单读。help 的头一单,shell 把菜单印了出来:家当四样,这一单落在了 write 上。echo ring3 knocking 的单子里,三枚词递了进来,后两枚原话回了出去,递与回两头走的都是 write。kernelx 的单子回的是 unknown command: kernelx,拒它的是 shell 不是柜台:这个词 shell 认不得、压根没往柜台递,拒信本身走的倒是一次 write。yield 的单子真进了门:24 号装进了 rax,SYSCALL 敲了门,Scheduler 打了个转回来,shell 接着打了一行 yielded and back。门里那道逐项过的题,屏上应了它。exit 的单子没有回执:封装里它是 [[noreturn]],内核里 handle_exit 把当前任务换下了场,Halt 兜了底。屏上的戏码是:exit 敲了下去,串口连一行都没有了。这样的单子是从不回来的,长的就是这个样。

房客的过法咱们也认一眼:read_line 一字节一字节地 Read,每回只讨的是一个字符,讨到了换行才住手。退格与 0x7F 都按退格的办法办,回它的是三枚字符 `\b`、空格、`\b`,屏上的字抹掉的是一格。tokenize 的切词拿的是空格与制表符。它过的全是柜台日子:一屏会话,几十次地进出门,没有一次是绕得开柜台的。还有一枚翻译在柜台那侧:键盘给的是 `\r`,handle_read 把它翻成了 `\n`,遇 `\n` 立刻收了单,返回的是 got+1,那枚换行也数在了字数里。read 的等法是睡,轮询是谈不上的:等键的当口任务睡着,键来了才醒,睡法的全本在正文《睡着的读》。

开篇的三枚负数,咱们当面试。针咱们这么下:shell.cpp 里添一个打印小函数 print_num,把 long long 打成了一行,再在 _start 的开头排三根:头一根试门牌,Write 的 fd 递的是 9。第二根试的是空号,Syscall3 直敲的是 99。Syscall3 连编号带三件话都自己带全了,Write、Read、Yield、Exit 四家走的全都是它,名字里的 3 数的是话,数的不是号。第三根试的是天花板,Write 的 buffer 递的是 0x800000000000。print_num 必须标的是 always_inline 强制内联,咱们这一标有来历:内核请客人进门,ELF 的 entry 是不读的,跳的是写死的 0x400000。print_num 要是没内联的话,GCC 给它独立成了函数,排进了 .text 头一截,0x400000 就归了它。起机的时候,客人门口站的是 print_num 本人。跳板把入口址递在了 rdi 里,同样的递法 2.1 拍过,print_num 拿它当第一参数打出了 4194304,正是 0x400000 本人的十进制,跟着 ret 到了一枚垃圾址:#PF。这一炸咱们亲手看过,楼下的入口是一枚写死的址。标上了内联,把门口还给了 _start,咱们起机:

```text
[kern] launching shell in ring 3
probe write fd9: -9
probe nr99: -38
probe hi buf: -14
cinux shell - type 'help'
cinux>
```

三行读数各有各的拒法,咱们逐行认。fd 递的是 9,柜台头一道岗问一声:是 1 吗?不是的话退 -9。号敲的是 99,越了表长,InvokeSyscall 头一道检查截了下来,退的是 -38:handler 都没上岗。址递的是 0x800000000000,分毫不差压在天花板上:kUserAddressLimit 定的上界,buffer 不小于它的话,柜台退的就是 -14。开篇那三枚负数的来路全找到了。看完咱们撤针,重建复跑了,横幅是干净的,克隆还了它原样。

## 对照:同一件事,别的机器怎么做

书页 47 比的是公约,2.2 对照节里许下的当面比,咱们从这一页比起。书页上的话直译过来:出错回的是负数,成功回的是零或正数。原话咱们单摆一行:

- “System calls conventionally return negative numbers to indicate errors, and zero or positive numbers for success.”

咱们公约里报错的半边,照的正是这副。同一页还坐着递话的家什:usys.S 里每个封装三行,li a7 把号装进了 a7,ecall 敲了门,ret 回来了。a7 与 a0 是 RISC-V 那头的两枚寄存器,一个装的是号,一个收回的是回执,合起来干的正是咱们 rax 一人兼的差事。进门后的查表归 syscall(),回值进了 a0。三行桩对咱们一条内联汇编,查表对的是查表,a0 对的是 rax,指令集隔着的是两家,出来的章法是一副。

书页 46 比的是回址与家当。RISC-V 的 ecall,硬件是不存回址的,trapframe 里的 pc 指着 ecall 本人,下一条的位置得软件自己加 4 去找。x86 的 SYSCALL 反着来:回址硬件存,存进了 rcx,存的正是下一条,咱们在 2.1 的断点上验过 0x400023。同一页还有一比:它家的 trapframe,32 枚寄存器一枚不落地收。咱们的帧十二槽,进门烧的只是 rax、rcx、r11 三枚,其余的平安,一半靠的是帧存,一半靠的是出口还。家当的多寡各随各家,客人回到了楼下,寄存器里还是他出门时的那副。

书页 48 比恶意指针:客人递来的址,内核凭什么不敢直接用。它家的解法叫 copyinstr,把客人递的串逐字往内核里搬,搬到页表不认的地方就停。咱们验得糙:kUserAddressLimit 一枚天花板,址低于它的话就放行。糙有糙的代价,咱们也试过:递一枚低半区里没映射的址,天花板是拦不住的,内核自己挨了一记 14 号,报告的事交给了异常那套机构,机器停在了报告上。简化照实记:咱们的岗拦高不拦空,逐字验的细活,等第 3 部页表齐了再补。

Linux 那头的话,这一章咱们一个数都不报。手册还没到咱们手里,表长多少、errno 备几条咱们都没数过也不猜。号码跟它排的道理,2.1 交代完了。真要对表的话,得等哪天翻开它的手册,那一页翻开了,数才有的报。

轮到自家的窄处,咱们逐件交底。眼下的话只收三件,r10、r8、r9 的三枚座位没派差事,四件以上的活现下接不了。表 61 格里开张的只有 4 格,余下的 57 格不硬凑,凑了一格就得养一格,眼下的房客点不着那些菜。read 只认的是 0 号,write 只认的是 1 号,fd 是写死的检查,够不上一本户口的资格。errno 只备了三枚。指针是一刀切的,拦高的不拦空。这些窄处是咱们记下的功课,省事不是白得的,放宽的手续,后头的章节一站一站办。

C++ 在这一章出的手有两处,一处管的是表,一处管的是帧,咱们各看一眼。管表的一处:make_handler_table 是 constexpr,61 格编译期就排完了,进镜像的就是成品,号对格的对应全交给枚举,不劳的是人眼。第一遍不是这么办的:表开的是 256 格,入口是 134 行的手搓汇编,read 在表里挂了名,格子里是没人坐的。真来敲门的话,dispatch 一句 unhandled 打发了,回的是光秃秃的 -1,错了与错在哪儿都分不出,要等装库的那年才知道得返工。管帧的一处:内核侧 syscall.hpp 里四条 static_assert,rcx 坐的是 +8,rax 坐的是 +24,rbx 坐的是 +80,整帧的 96 字节逐条把座位跟汇编对齐,哪头挪了座,编译期就吵了起来,机器开口的份儿都轮不到。给 rbx 留的断言,消息还是前头姐姐案末尾引过的那句英文原话,旧案就住在了帧布局里。134 行与 256 格是第一遍的家底。到了这一遍,表交给了 constexpr,帧交给了断言。

## 这一章留下了什么

咱们趁打烊之前把柜台上下再点一遍。三条约定立好了:号随 Linux 报,话走的是 rdi、rsi、rdx,回值走的也是 rax,错回的是负数,负号后头跟的是 errno。表是一张 61 格的,constexpr 编译期就立好了,开张的是四格,空号与空格退的一律是 -38。帧是十二槽的 96 字节,进门压齐了才 sti,出口还原靠的是帧,user_rsp 骑的是第 0 槽。拒法咱们报三种:拒号 -38、拒门 -9、拒址 -14。柜台开了张,yield 与 exit 已经会在门里换任务了,帧却跟着任务活了下来,换任务的门道,开戏的是下一章《进程与上下文》。

| 术语 | 一句话口径 |
|---|---|
| 系统调用 | ring 3 隔柜台递话:号进 rax,SYSCALL 进门,回值回 rax |
| 三条约定 | 号随 Linux,话走 rdi、rsi、rdx,错回负 errno |
| 分发表 | kHandlers 的 61 格:constexpr 立表,空格 nullptr,空号 -38 |
| 十二槽帧 | SyscallEntry 压的 96 字节:user_rsp 骑第 0 槽,压齐才 sti |
| 负 errno | 拒单的回音:-38 空号,-9 错门,-14 越界 |
