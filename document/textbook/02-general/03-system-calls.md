# 03 · 系统调用:号、话、错,柜台开张

-9、-38、-14,三枚负数,一台机器亲口报出来的。三枚都是拒单:头一枚嫌门牌不对,中间那枚嫌号没登记,末一枚嫌址越了界。拒得干脆,还拒得各有名目。这一章,咱们看它怎么开张。

上一章末了记下三件差事:编号怎么定,话怎么递,错怎么报。更早一章还埋着一单:头一跳下楼的时候,SYSCALL 进门受理的那座柜台,还没接过一单。这一章三件差事一并交卷,那一单,今天接上。柜台在门外看,咱们其实看过:前置卷《内核是什么》里拿 strace 数调用,一行一次调用,写成名字(参数) = 返回值,`write(1, "hello\n", 6) = 6` 那一行,是程序在用户态喊一声,内核替它把六个字节写到 1 号,再交还一个 6。同一卷里还借书上的话记过一笔:系统调用有唯一的整数编号,背后挂着一张表。门外看,那是别人家的机关。门里看,编号和表,都得咱们自己立。

量法这一章,门里的家当对码,门外的回音对屏,公约那一头,书翻到了。表与帧,自家源码逐件读。三枚负数与五单会话,自家起机亲手抄。书是 xv6 那本:2.2 对照节里咱们许过愿,等书翻到,当面比。如今翻到第 4 章,书页 46、47、48 三页逐字读过,今天比的就是这三页,一页不越。

> **客人隔着柜台喊一声,内核凭什么听得懂?听懂了,又凭什么敢照办?**
>
> 听得懂,靠约好的三条黑话:号怎么报,话怎么递,错怎么回。敢照办,靠进门以后的验与拒:号在表里才有人应,址在界内才动手,办完回执走原路。三条约定,一副家什,这一章咱们一件一件立起来。

## 号、话、错:开张的三条约定

头一条立号。号码咱们整套照 Linux x86_64 抄:read 0 号,write 1 号,yield 24 号,exit 60 号,躺在内核头文件 kernel/syscall/syscall.hpp 的 SyscallNr 枚举里,四枚值挨着各自的 Linux 真名写注释。

为什么照别人家的抄,2.1 写柜台字的时候交代过:号码是行话,将来 musl 那样的 C 库带着编译好的程序来敲门,报号就认。这里补一层:枚举住在内核的头文件里,客人的封装把它一并包含,号码这本词典,门里门外读的是同一份。24 号为什么夹在 1 和 60 中间,不顺着自家排成 2?因为空号位不是无主的地:24 号在 Linux 那边住着 sched_yield,咱们让 yield 认下同一块门牌,词典里就不出重号。往后再添号,也轮不到去挪空位。词典一重排,照老词典背号的客人,就找不着家门了。

第二条递话。咱们递话的家什是 user/api/syscall.hpp,文件名和内核的一模一样,两户同名,别走错门,文件头一句写着 Not a libc——它不是 C 库,也没打算当,每个封装就是一条内联汇编,桥就这么宽:

```cpp
    __asm__ volatile("syscall"
                     : "=a"(ret)
                     : "a"(number), "D"(arg1), "S"(arg2), "d"(arg3)
                     : "rcx", "r11", "memory");
```

一条指令,看住两头。进去那头:号进 rax,头一件话进 rdi,第二件 rsi,第三件 rdx,座位照 Linux 排。rcx 与 r11 也列在 clobber 里,缘故 2.1 拍过:进门那一拍,指令把回址写进 rcx、旗写进 r11,这不是咱们的代码搬的,是指令自己的动作,可两枚跨过这趟门就不再是原值,编译器得知道。剩下那句 clobber 清单,是写给编译器的一句许诺:过这扇门,烧掉的只有 rax、rcx、r11,再没有别人。这句许诺两头各认一半:客人信了它,才敢把值驻在别的寄存器里跨门复用。内核就得兑现它,进门碰过什么,出门原样奉还,兑现的活,下一节咱们亲眼看。Linux 的座位表上,四五六号参数还有 r10、r8、r9 三枚,Cinux 眼下话只收三件,那三枚在帧里留了座位,没派差事。

第三条报错。回执走 rax。办成了,回零或正数:write 回写出去的字节数,yield 回 0。办不成,咱们回负数,负号后头跟一枚 errno:号没登记,退 -38,kEnosys。门牌不对,退 -9,kEbadf。址越了界,退 -14,kEfault。-9 与 -14 的语义,2.1 在 handle_write 的两道岗上拍过,这里咱们只把它们并成一家:拒号、拒门、拒址,拒在哪个环节,负数自己说话。exit 没有回执。办完这一单,收话的人已经不在了,封装里把 Exit 标了 [[noreturn]]。这副公约不是咱们独造,xv6 书页 47 有句原话,对照里当面引。

## 门里:一张表,一副帧

SYSCALL 进了门,门里接活的,一张表,一副帧:表管谁应单,帧管怎么活着回来。咱们各认一遍,打表起头。syscall.cpp 里的 kHandlers,61 格,编号 0 到 60。exit 的 60 号住最末一格,表就铺到头。立表用 constexpr make_handler_table,编译期排完:read、write、yield、exit 四格有主,余下 57 格是 nullptr。接单的入口是 InvokeSyscall,头一句就是岗:

```cpp
    if (number >= cinux::syscall::kSyscallCount || kHandlers[number] == nullptr) {
        return -cinux::syscall::kEnosys;
    }
    return kHandlers[number](arg1, arg2, arg3);
```

号出了表长,或者格子里空着,一律 -38。空号不是没有应答,-38 就是应答:拒收也是一句话,柜台不装聋。真有客人来敲空号什么样,实况节咱们拿 99 号当面试。表的差事完了,轮到帧。帧的正文在 syscall.S,咱们把进门那一段念:

```asm
SyscallEntry:
    swapgs
    movq %rsp, %gs:8
    movq %gs:0, %rsp
    pushq %rbp
    # (中间十拍:自 rbx 一路压到 rcx)
    pushq %gs:8
    sti
```

头一拍 swapgs,换的是 GS 的基址。GS 是一枚段寄存器,咱们往它身上挂了 gs:0、gs:8、gs:16 一排编号暗格,基址定这一排编号落在哪片地上。GS 备着两枚基址,客人世界、内核世界各一枚,swapgs 对调的就是这两枚。咱们眼下把两枚 base 都写成同一片地的地址,换了等于没换,可这一拍省不得:将来客人有了自己的 TLS(线程局部存储,每个线程一块自留地),它才是两个世界的分界线。来历的全本在正文《MSR 件与 GS 落脚点》。跟着两拍换栈:进门前 rsp 还是客人的,暂存进 gs:8,gs:0 里备着内核栈,一拍换上。往下十二拍压帧:rbp 打头,跟着 rbx、r9、r8、r10、rdx、rsi、rdi、rax、r11、rcx 十枚居中,末一拍把 gs:8 里那枚客人栈顶也压进去。十二槽,96 字节,咱们管它叫十二槽帧。帧压齐,sti 才把中断请回来。为什么排在末尾,马上对。再往下四拍搬参数,汇编里是 movq 24(%rsp), %rdi 一类:24 是 rax 的槽,编号搬进 rdi,32、40、48 三槽是话,搬进 rsi、rdx、rcx,C++ 那侧 InvokeSyscall 收四个参数,座位对座。搬完 call InvokeSyscall,C++ 接手。

**停一停,替 99 号当一回班。** 假如这一单是您在柜台里当值:客人敲的是 99 号,从进门那拍起,这一单怎么走?走到末了,rax 里躺着的是谁?

咱们当班走一遍:swapgs 换基址,客人栈顶进暗格,内核栈换上,十二槽压齐,sti 开中断,参数搬座,InvokeSyscall 上工。头一句问 99:比 61 小吗?不小,退 -38,原路返回:-38 进 rax,十二槽还原,sysretq 送客。您数数,受理一单的工序一步没少,只是查表那一步,给了句拒收。空号的待遇,就是全套工序加一句 -38。

出口在汇编的后半段,咱们挑头几拍念,回值那一枚绕了一道手:

```asm
    movq %rax, %gs:16
    movq 32(%rsp), %rdi
    movq 40(%rsp), %rsi
    movq 48(%rsp), %rdx
    movq 56(%rsp), %r10
    movq 64(%rsp), %r8
    movq 72(%rsp), %r9
```

头一拍,回值从 rax 挪进 gs:16 暂存,一进一出像白走,为什么绕这一道,后头 rdi 与 rbx 两案就是答案。跟着六拍,rdi、rsi、rdx、r10、r8、r9 自帧还原。再四拍,rcx、r11、rbx、rbp 归位。rcx 与 r11 进门时硬件替咱们存过一份,C++ 这一路又随便用它们,帧里的存底,是出口时唯一信得过的。末了 rsp 从第 0 槽重建,回值自 gs:16 取回 rax,客人的 GS 基址换回,sysretq 出门,cs 落 0x33,执行流回到楼下。

sti 为什么排在帧尾,这笔咱们对前后两头算。进门那一拍,SFMASK 预写好的 0x200 把 IF 摘了,2.1 讲快门时拍过。帧立稳,sti 请回来。出门,SYSRET 从 r11 把旗原样还给客人,也是 2.1 拍的。摘到 sti 之间,换栈、建帧那十几拍,一个中断都不许插进来。跟 2.2 的中断门对着看,同工不同位:老门是硬件进门自动摘、iretq 出门自动还,快门是软件预写清单摘、r11 寄存着还。位子不同,守的是同一件事,现场没铺齐,不许来客。往后柜台里等活也不闭门:read 等键的当口 IF 立着,时钟照响,1.6 拍过的外线与本章立起的柜台互不耽误,在这里合上。

**停一停,给回程点一遍名。** yield 那一单:封装递 24 号,进门,InvokeSyscall 里 Scheduler 打个转,CPU 让出去又拿回来,SYSRET 落地。落地那一刻,咱们回看这副十二槽的帧:哪几槽换了值?

咱们点名:一槽都没换。yield 切活,是 CPU 跑去别的任务的栈上转了一圈,这一副帧躺在自家任务的内核栈上,原样候着。帧跟着任务走,不跟着 CPU 走。真变了的东西都在帧外:执行流出去绕了一圈,回值 0 那时还没生出来,要等任务回来,yield 把 0 交出来,InvokeSyscall 收进 rax,出口才进 gs:16。帧外还有一件悬的,下一段说它。

悬的是第 0 槽。客人栈顶进门时存过 gs:8,出口重建 rsp,为什么不再读 gs:8,非要压进帧里带着走?因为 gs:8 是枚公共暗格:柜台中途会换任务,yield 就换。换进来的下一位 ring 3 客人一进门,头一拍就把自家栈顶写进 gs:8,旧值就地被盖。第 0 槽不一样,它长在任务的内核栈上,任务在,它在。咱们回程重建 rsp,只能信跟任务走的存底。十二槽里十一槽存的是寄存器,唯独这一槽,存的是任务的退路,帧结构里它的字段名,就叫 user_rsp。

帧里连参数寄存器都要存,出口一拍不少地还原,这一版自己疼过一回,咱们把案子办了。案发在 hello 头上:连写两行,第二行无声丢失,别的照常。破案走反汇编,全本在正文《只烧三个寄存器的承诺》,裁决念出来是这样:包装许过编译器,过门只烧 rax、rcx、r11,编译器信了,算盘打得很精。fd 的 1 装进 rdi 一回,两次调用用一回,write 的编号也是 1,连编号那一拍都是从 rdi 派生的。可门里这头,rdi 正是 C++ 排头的参数寄存器,InvokeSyscall 一路走下来,它早被碾成一个高半区的内核地址。第一版出口只还原了 rbx 与 rbp。按编译器的行话,rbx、rbp 一类 callee-saved,被调的一方保证原样奉还。rdi、rsi、rdx 这类参数寄存器是 caller-saved,保它们的事归调用者自己。它只顾了前一半,rdi 出门时是什么就是什么。于是第二单进门,编号栏里躺的不是 1,是 0xFFFFFFFF8028A6E0 一类的数,远超表长,柜台照 -38 拒收,整整齐齐,悄无声息。修法就是出口那六拍,caller-saved 自帧还原。许诺许出去的,内核自己兑现。

咱们把时间拨回第一遍,这一案有位姐姐。第一遍的 shell 也演过怪戏:回显正常,命令全失效,字打得上屏,回车一敲,什么也没发生。查下来:read_line 内联之后,写入的位置 pos 驻在 rbx。那年的入口汇编拿 rbx 暂存返回值,用完不还,callee-saved 就这么毁了。pos 每过一次门就被回值的 1 压回原处,字符一个个全写进 line[1],行首的 line[0] 从出生起没人碰过,末了 tokenize 收到的,是一枚空串。修的路子跟刚才那一案同根:返回值挪去 gs:16,rbx 自帧还原。两案并排,病根一条:硬件自保的只有 rcx 与 r11,其余寄存器的平安,全凭内核进门出门的自觉。约定是双向的,兑现的那一方,恰恰是内核。今天帧布局的断言群里,给 rbx 留的断言,消息还是这桩旧案:`the rbx lesson stays pinned`。

## Code: Cinux 实况:起机、五单、三根针

实况锚 r13_userspace,ring 3、syscall 与 shell 齐活的那一版,2.1 首跳用的也是它,切版与镜像的老话那边念全了,不重印。这一场的新意在喂键:前两章咱们要么冻机器上断点,要么扎一针读日志,这一回柜台开张,咱们得当客人,亲手下单。QEMU 的 monitor 接在 stdio 上,起机等到横幅,一行一条 sendkey 把话递进去:

```bash
git switch --detach r13_userspace
cmake -B build && cmake --build build --target boot_image
timeout 120 qemu-system-x86_64 -accel tcg \
    -drive format=raw,file=build/boot/cinux.img \
    -display none -no-reboot \
    -serial file:build/console.log \
    -monitor stdio
```

-display none 底下没有屏幕看,横幅全走串口文件,您再开一窗,跑着 tail -f build/console.log,TCG 起机要等上一阵,那一窗里日志一行行长出来,长到 cinux> 露头,就能喂键了。键名 monitor 自己认,咱们只记三样:字母原样,空格是 sendkey spc,回车是 sendkey ret。头一单 help:sendkey h,sendkey e,sendkey l,sendkey p,末了 sendkey ret。往后每一单照此喂。exit 敲完,串口再无一行,timeout 到点收场,五单全录在 console.log 里。面板上,e820 还是 7 条,老话不重叙,kernel at 200000 size 90A20 是 1.8 讲过的那套户口,个头随版本长。pmm 报 32316:1.6 的屏 32347,1.7 的屏 32350,2.2 的屏 32348,四站四屏各认各的,咱们别互相串。再往下的 vmm、heap、keyboard 全是新面孔,咱们只认名不展开,堆的去处是第 3 部的戏,调度与任务的排场是 2.4 的戏。irq 是旧相识,1.6 的屏里就是这一行,1.6 的实况里追过它的来路,咱们不再展开。面板从 pmm 那行起抄在底下:

```text
[kern] pmm: 32316 pages free (probe 113000 ok)
[kern] vmm: address space up, magic 114514
[kern] heap: new/delete live (probe 114514)
[kern] irq on, tick 100Hz
[kern] keyboard on, type to echo
```

再往下是六位内核任务的拉练,流水打进日志,老班子的保留节目,咱们不逐行数,直接翻到会话:

```text
cinux> help
commands: echo <text...>, help, yield, exit
cinux> echo ring3 knocking
ring3 knocking
cinux> kernelx
unknown command: kernelx
cinux> yield
yielded and back
cinux> exit
```

咱们逐单读。help,shell 把菜单印出来,家当四样,这一单落在 write 上。echo ring3 knocking,三枚词递进来,后两枚原话回出去,递与回,两头都是 write。kernelx,unknown command: kernelx,拒它的是 shell 不是柜台:这个词 shell 认不得,压根没往柜台递,拒信本身倒是一次 write。yield,这一单真进了门:24 号装进 rax,SYSCALL 敲门,Scheduler 打个转回来,shell 接着打一行 yielded and back。门里那道点名的题,屏上应了。exit,没有回执:封装里它是 [[noreturn]],内核里 handle_exit 把当前任务换下场,Halt 兜底。屏上,exit 敲下去,串口再无一行。从不回来,长这个样。

房客的过法,咱们也认一眼:read_line 一字节一字节地 Read,每回只讨一个字符,讨到换行才住手。退格与 0x7F 都当退格办,回它三枚字符 `\b`、空格、`\b`,屏上的字抹掉一格。tokenize 拿空格与制表符切词。它过的全是柜台日子:一屏会话,几十次进出门,没有一次绕得开柜台。还有一枚翻译在柜台那侧:键盘给的是 `\r`,handle_read 把它翻成 `\n`,遇 `\n` 立刻收单,返回 got+1,那枚换行也数在字数里。read 的等是睡,不是轮询:等键的当口任务睡着,键来了才醒,睡法的全本在正文《睡着的读》。

三枚负数,当面试。针咱们这么下:shell.cpp 里添一个打印小函数 print_num,把 long long 打成一行,再在 _start 开头排三根:头一根试门牌,Write 的 fd 递 9。第二根试空号,Syscall3 直敲 99。Syscall3 自己带编号、自带三件话,Write、Read、Yield、Exit 四家全打它走,名字里的 3 数的是话,不是号。第三根试天花板,Write 的 buffer 递 0x800000000000。print_num 必须标 always_inline 强制内联,咱们这一标有来历:内核请客人进门,不读 ELF 的 entry,跳的是写死的 0x400000。print_num 要是没内联,GCC 给它独立成函数,排进 .text 头一截,0x400000 就归了它。起机客人门口站的不是 _start,是 print_num 本人。跳板把入口址递在 rdi 里,同样的递法 2.1 拍过,print_num 拿它当第一参数打出来,4194304,正是 0x400000 本人的十进制,跟着 ret 到一枚垃圾址,#PF。这一炸咱们亲手看过,楼下的入口是一枚写死的址。标上内联,把门口还给 _start,起机:

```text
[kern] launching shell in ring 3
probe write fd9: -9
probe nr99: -38
probe hi buf: -14
cinux shell - type 'help'
cinux>
```

三行读数,三种拒法,咱们逐行认。fd 递 9,柜台头一道岗:不是 1,退 -9。号敲 99,越了表长,InvokeSyscall 头一道检查截下,退 -38,handler 都没上岗。址递 0x800000000000,分毫不差压在天花板上:kUserAddressLimit 定的上界,buffer 不小于它就退 -14。开篇那三枚负数,来路全找到了。看完咱们撤针,重建复跑,横幅干净,克隆还它原样。

## 对照:同一件事,别的机器怎么做

书页 47 比公约,2.2 对照节里许下的当面比,从这一页比起。原话抄来:“System calls conventionally return negative numbers to indicate errors, and zero or positive numbers for success.”——出错回负数,成功回零或正数。咱们公约里报错的半边,照的正是这副。同一页还坐着递话的家什:usys.S 里每个封装三行,li a7 把号装进 a7,ecall 敲门,ret 回来。a7 与 a0 是 RISC-V 那头的两枚寄存器,一个装号,一个收回执,合起来干的正是咱们 rax 一人兼的差事。进门后 syscall() 查表,回值进 a0。三行桩对咱们一条内联汇编,查表对查表,a0 对 rax,指令集隔着两家,章法是一副。

书页 46 比回址与家当。RISC-V 的 ecall,硬件不存回址,trapframe 里的 pc 指着 ecall 本人,软件得自己加 4 才找得着下一条。x86 的 SYSCALL 反着来:回址硬件存,存进 rcx,存的正是下一条,咱们在 2.1 的断点上验过 0x400023。同一页还有一比:它家的 trapframe,32 枚寄存器一枚不落。咱们的帧十二槽,进门只烧 rax、rcx、r11 三枚,其余的平安,一半靠帧存,一半靠出口还。家当多寡各随各家,客人回到楼下,寄存器里还是他出门时的那副。

书页 48 比恶意指针:客人递来的址,内核凭什么不敢直接用。它家的解法叫 copyinstr,把客人递的串逐字往内核里搬,搬到页表不认的地方就停。咱们验得糙:kUserAddressLimit 一枚天花板,址低于它就放行。糙有糙的代价,咱们也试过:递一枚低半区里没映射的址,天花板拦不住,内核自己挨了一记 14 号,异常那套机构接手报告,机器停在报告上。简化照实记:咱们的岗拦高不拦空,逐字验的细活,等第 3 部页表齐了再补。

Linux 那头,这一章咱们一个数都不报。手册没到手,表有多长、errno 备多少条,没数过,也不猜。号码跟它排的道理,2.1 交代完了。真要对表,得等哪天翻开它的手册,那一页翻开了,数才有的报。

轮到自家的窄处,咱们逐件交底。话只收三件,r10、r8、r9 三枚座位没派差事,四件以上的活现下接不了。表 61 格开张 4 格,57 格不硬凑,凑上一格就得养一格,眼下的房客点不着那些菜。read 只认 0 号,write 只认 1 号,fd 是写死的检查,不是一本户口。errno 只备三枚。指针一刀切,拦高不拦空。这些窄处不是白得的省事,是咱们记下的功课,放宽的手续,后头的章节一站一站办。

C++ 在这一章出手两处,一处管表,一处管帧,咱们各看一眼。管表:make_handler_table 是 constexpr,61 格编译期排完,进镜像的就是成品,号对格全由枚举点名,不劳人眼。第一遍不是这么办的:表 256 格,入口 134 行手搓汇编,read 在表里挂了名,格子里没人坐。真来敲门,dispatch 一句 unhandled 打发,回的是光秃秃的 -1,错了与错在哪儿都分不出,要等装库那年才知道得返工。管帧:内核侧 syscall.hpp 里四条 static_assert,rcx 在 +8,rax 在 +24,rbx 在 +80,整帧 96 字节,逐条把座位跟汇编对齐,哪头挪了座,编译期就吵起来,轮不到机器开口。给 rbx 留的断言,消息还是前头姐姐案末尾引过的那句英文原话,旧案就住在帧布局里。134 行与 256 格,是第一遍的家底。这一遍,表交给 constexpr,帧交给断言。

## 这一章留下了什么

打烊之前,咱们把柜台上下再点一遍。三条约定立好了:号随 Linux 报,话走 rdi、rsi、rdx,回值也走 rax,错回负数,负号后头跟 errno。表是一张 61 格的,constexpr 编译期立,四格开张,空号与空格一律 -38。帧是十二槽 96 字节,进门压齐才 sti,出口自帧还原,user_rsp 骑在第 0 槽。拒法三种,拒号 -38,拒门 -9,拒址 -14。柜台开了张,yield 与 exit 已经会在门里换任务,帧却跟着任务活下来,换任务的门道,下一章《进程与上下文》开戏。

| 术语 | 一句话口径 |
|---|---|
| 系统调用 | ring 3 隔柜台递话:号进 rax,SYSCALL 进门,回值回 rax |
| 三条约定 | 号随 Linux,话走 rdi、rsi、rdx,错回负 errno |
| 分发表 | kHandlers 的 61 格:constexpr 立表,空格 nullptr,空号 -38 |
| 十二槽帧 | SyscallEntry 压的 96 字节:user_rsp 骑第 0 槽,压齐才 sti |
| 负 errno | 拒单的回音:-38 空号,-9 错门,-14 越界 |
