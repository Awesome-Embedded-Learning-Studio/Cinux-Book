# 02 · 中断与异常:一张表,两类来路,六件现场

前置卷《内核是什么》里,咱们看过内核的三张脸,这一章咱们接住其中两张。一张出自 divzero 那个小程序:除数一为零的当下,shell 报了 exit=136,折成的信号是 SIGFPE,这脸是程序自己吃出来的。另一张在 /proc/softirqs 里:您把 TIMER 那一行隔两秒再读一遍,每一栏的数都在涨,这脸是外头的钟替它翻的,其实程序自己全不知情。同一位内核伺候的,是两路完全不同的打断,一路是屋里来的,一路是屋外来的。

上一章收尾咱们问过:客人要是跑飞了、跑死了,或者外面的世界来敲钟,咱们该找谁去拉它一把。拉它的就是今天这套机构。前置卷里它只露了个脸,收场的活全是内核替咱们包了的,这一章咱们把它请到桌边看清楚:打断分几路来,来了躲进哪张表、进哪扇门,疼了怎么把现场报得有名有姓。

上一章咱们还留过一扇老门,客人拿 int 指令也能敲的那扇,进门要过的关卡多:要过 IDT 查表,要按门里定好的格式压帧,一路把章盖了。本章咱们就把那几道关卡一道道走一遍。次序也顺着来:来路怎么分,rip 怎么记,表和门长什么样,末了咱们亲手往代码里扎一针,听机器把疼一五一十地喊出来。

这一章的量法,一半认的是码,一半认的是屏。表、门、桩、名表(给号报名字的小表),四样家当全在自家的源码里。实况退回的是 r08_idt,表自家立起来的那一版,咱们挨件读,读了什么写什么。疼的那一半,咱们得听机器亲口喊,五行面板加两行异常报告的实况,都是咱们自家起机抄下来的。有两处来历咱们要交代清楚。门描述符与异常分类的正式条文,住在 Intel 的手册里,书架上还是没有那本书的影子,fault、trap 这类通行的名目,咱们借名字、不引页。《深入理解计算机系统》的第 8 章,这一回咱们只取它一小截:开场给异常分类、给 fault 和 trap 落名字的那部分,名字借了就用,条文原样留在了书里。

> **机器正跑得好好的,谁有资格让它停下来?停完凭什么回得来?**
>
> 有资格的来路只有两条:CPU 自己喊的疼,和外线按的铃。停完了还回得来,靠的是一表一门:打断的那一拍,现场压上了栈,门里记的是该去哪儿,办完了 iretq 再原样奉还。来者换了个叫向量号的名牌,谁来了都拿它查同一张表。咱们这一章,就把表、门、现场一件件地认全。

## 来路:自己喊的疼,外线按的铃

机器自己喊的这路,咱们行话里叫异常。喊的时机认得很准:出的事,永远出在机器正在执行的指令身上。除零记的是 0 号。一条念不懂的指令,记的是 6 号。手伸过了权限线,记的是 13 号 #GP。第三种您见过实弹:前置卷《保护模式与长模式预览》的镜子里,ring 3 的一条读 CR0、一条 cli,当场就被 #GP 摁住了。上一章咱们还留过话,真拿 cli 去试身手的实弹在正文《第一跳实弹》,那头机器按异常的惯例收场。收场走的就是今天这套机构:越权那一拍,13 号门开了,机器被拉回了 ring 0,处理程序接了手。

外线按的这路,行话里叫的是中断。它跟当前指令没有冤仇:时钟到了点要响,键盘按下了也要响,机器那会儿正跑的是哪条指令,它们其实不挑。1.6 里咱们陪心跳数过 792 声铃,每一声走的都是同一条路。铃怎么从设备一路递到 CPU,那一章拍过全本了,咱们不重叙,本章只管铃进了 CPU 之后的事。

两路来的人,脾气其实差得远,进了 CPU 却享同一套待遇:都折算成一个向量号,拿号查的都是同一张表。号的地界是架构划死的,1.6 报心跳的时候咱们照过一回面:0 到 31 是架构异常的自留地,咱们认几个熟脸,0 号的除零,6 号的无效指令,13 号的一般保护。14 号的缺页眼下还只是个名字,到了第 3 部它才是正角。32 到 255 是外线的地界,想开口的设备到这片来领门牌,心跳领的 32 号门就在这片里。

前置卷《内核是什么》里,咱们给内核收过一句定位:替咱们照看资源的那一层。管家日常伺候的,一大半就是这两路的打断。客人出了事,收场的是它。外头来了活,应门的也是它。Cinux 眼下刚把表立了起来,应门的手艺咱们一站一站学。

> 软件那头还有位远亲:前置卷《Unix 使用侧》里您拿 kill 递过信号,它也长着一张打断、处理、回来的脸,可那是软件层的手艺,咱们认个亲就走。

## 停在哪儿:故障与陷阱的分界

异常这一路的底下,还分出了两副脾气。咱们拿一件东西当分界线:进异常门之前,CPU 压进栈里的 rip,指的是哪儿。凭的就是 rip 指向哪儿,异常分成了故障与陷阱。

故障的 rip,停在肇事指令本人的身上。除零归的是它,无效指令归的也是它,咱们表里挂了桩的大头全是这一副脾气。道理推一层就通:故障的意思,是出事的指令没办成,回去重头再办的就是它本人。缺页的戏最典型,您听个梗概:访存的指令伸手要一页,页不在家的时候,处理程序把页请了回来,iretq 把机器送了回去,CPU 从 rip 的位置接着取指,取回的还是同一条访存指令,这回再办就办得成了。

陷阱反过来:事办完了才停,rip 指的是下一条。上一章的那对快门,走的正是这副语义:SYSCALL 执行那一拍,RIP 自动存进了 rcx,存的是下一条的址。您回头想想,这个安排跟陷阱的脾气对得严丝合缝:系统调用是替客人办事,办完了就该顺着往下走。要是 rip 停的也是 SYSCALL 本人,回去把系统调用又发了一遍,一个 write 就成了两个。

**咱们停一停,推一步**:您拿除零想,它走的正是故障,压栈的 rip 指着除法指令本人。要是处理程序什么也没修,拿 iretq 就回去了,CPU 办的头一件事是什么?这出戏演到第几遍才收场?

回去办的头一件事,是把刚才的除法再取一遍:rip 停在它身上,CPU 从 rip 取回的还是它,除数其实还是零,开的又是 0 号门,又进了一回桩。这出戏是没有大幕的,一遍一遍地演下去没有头。所以故障要回去,处理程序得替咱们把路修好。修不好的话,就别回去了,想法子把现场留了下来。咱们眼下的桩怎么办,往下读到六件现场的时候,您就见着了。

## 一张表,一扇门

打断的机构,咱们要认的正主是一张表:中断描述符表,行话里叫的是 IDT,1.6 里您见过这个名字。规格咱们一口气报完:二百五十六格,一格记的是一门,一门的十六字节折出整张 4KiB,家安进了 .bss。这副规格 1.6 讲心跳的时候原样报过,那会儿只借了门的数目和屏上一行 limit,本章咱们把表真立起来。住 .bss 有讲究:盘上的镜像一个字节不为它多花,起机清完了零,咱们再往里填。idt.cpp 里 g_table 一声落地,就是这么一张空表。这一户您也见过:刚出生时它只有三十二格,那会儿它的名字还叫 g_idt,1.8 的 .bss 院子里数过它。到了这一版,改叫了 g_table,铺满了二百五十六格。

表装好了,咱们得让 CPU 认。装表的指令叫 lidt,lgdt 的兄弟:1.4 里咱们拿 lgdt 给 CPU 递过 GDT 的身长和地址,lidt 递的是同一副格式,递的对象换成 IDT。1.6 的 monitor 屏上您见过它的产出,IDT 那行末尾的 00000fff 正是身长:256 乘 16 减 1,咱们一字不差地核过。从递出去的那一拍起,CPU 再遇打断认的就是咱们自己的表。

门里装什么,咱们把十六个字节摊开看。idt.hpp 里它的名字叫 GateEntry,长的是这样:

```cpp
struct [[gnu::packed]] GateEntry {
    unsigned short offset_low;
    unsigned short selector;
    unsigned char  ist;
    unsigned char  type_attr;
    unsigned short offset_mid;
    unsigned int   offset_high;
    unsigned int   reserved;
};
```

您扫一眼就有个疑问:处理程序的 64 位址,怎么被切成了三截?offset_low、offset_mid、offset_high,低、中、高三段是散住的,中间还夹了 selector、ist、type_attr。这是 CPU 定下的格式,咱们只有照装的份。把一个址照这副格式切好、填进了门里,是 idt.hpp 里 EncodeGate 的活:三次移位加掩码,进的是一个址,出的是十六个字节,一身的纯函数,别的什么都不碰。

selector 一格记的是 0x08,自家三槽表里的代码段,进门那一拍 CPU 拿它查眼下当值的 GDT。1.6 的 monitor 里报过 limit 0x17 的三槽表,说的就是它。ist 一格记 0:那是换栈的机关,真用得上得等中断自带栈的年头,咱们眼下不动它,数字 0 的意思是这门手艺搁着不用。

最要紧的一格是 type_attr,咱们写 0x8E。一个字节摊开了念:最高位是在场位,1 表示的是门里真住着人。挨着它的两位是 DPL,咱们记 0:眼下能拿 int 指令敲门的只有内核自己,楼下的客人敲,门是敲不开的。真要客人也敲得开的话,咱们得把 DPL 放到 3。咱们记 0,客人敲过来的那一下,应门的还是 #GP。尾巴上的 0xE 写的是中断门。中断门的脾气就在这儿:进门那一拍,硬件自动把 IF 清了零,出门的 iretq 又自动把它还回来。您听着耳熟就对了,上一章 SFMASK 讲过同工的一手:快门进门,摘旗靠的是软件预写好的清单。老门进门的时候,摘旗是硬件自带的动作。为什么进门要摘它,道理在嵌套的那一课,得等真有多级中断的日子,今天咱们只认下这副脾气。

进门时压栈的家当,咱们还差一处要交代。有一类带码的异常,CPU 压完了现场还会自己再多压一个错误码,#GP 压了,#PF 也压了,事故的详情折在里面。另一类什么也不压,#0 除零、#6 无效指令都在不压的这一边。这一差其实不要紧,要紧的是桩的读法:栈上差一个字,桩要是照同一个姿势去读的话,后头全错了位。所以桩有两种形状。带码的门,签名里多接的是一个错误码,CPU 压的原样递进去。不带码的门,桩自己垫了个零,把栈面也找齐了。带码不带码的号,记在一张三十二格的小表里,咱们装桩的时候照表选形状,一行的人眼功夫都省了。

32 号往上的地界,眼下没有住户:咱们只装了 0 到 31 的异常桩,外线的一根都还没接上。可门牌簿是全的,256 格的户口都在。哪天一条 int 指令踩上了空门,机器报出来的会是谁?

**咱们停一停,断个案**:您拿 int 0x80 试,踩的是 128 号门,门里眼下是空着的。屏上报名的会是谁的号?真凶 128,又藏在报告的哪一件里?

咱们断案:报名的是 #GP,它替缺席者顶了名。门不在场的话,按架构的章法,出面的是 13 号。真凶的号没丢,折进了错误码里:err 右移三格,得的就是被踩的门号。空门是不撒谎的,它只是暂时没住户的门。往后哪扇门真住进了人,走的也是同一套章法。

还有一条边界咱们要画在纸上。异常还没应完又出新异常、接不住的时候,CPU 把机器送进了 8 号门:双重故障。这重保护再失手一回的话,CPU 就不找人了:当场复位了事,屏一黑连遗言都省了,行话叫的是三重故障。咱们让桩报告完就 Halt,把机器停在有名字的地方,别让它滚到那片黑里去了。

## 六件现场,一件不缺

疼是要喊得出名字的,喊名字的活在 exception.cpp,咱们分两样认。头一样是叫 kExceptionNames 的三十二格名表,0 到 21 各有各的名,除零、无效指令、双重故障一路排了下去,唯独 15 号的名空着,它和 22 往后都老老实实写了 Reserved。问到表外的号,它宁可交出去的是 Unknown,编名的事它从来不做。第二样是叫 ReportFault 的报告,用的是两行 Println:头一行名字带号,第二行印的是余下那五件,印完了就 Halt。长什么样,咱们实况节马上见。

两行合起来的六件,咱们一件一件过。名字说出的是什么事:6 号事主在代码,14 号的事主在页表,方向一报就分开了。rip 说出在哪儿出的事,故障指的还是肇事指令本人。cs 说的是出事那一刻住在哪个段世界,咱们门里记 0x08,报出来的就该是 8。rflags 装的是状态字,手册里有整页的明细,咱们只认 IF 那一粒:第 9 位的 0x200,它立着的时候中断就开着,它躺着的时候中断就关着。rsp 记的是栈的落点,现场全压在了栈上,栈要是被人写花了,它头一个露了馅。err 报的是事故详情,带码的异常它真有来历,不带码的,它是桩垫的零。

有个小出入咱们要交代。CPU 压栈的现场是五件:rip、cs、rflags、rsp、ss。报告出面的是四件,添上的是名字和 err,凑成屏上的六件。ss 也压在了栈上,这一版的报告没请它出面,咱们知道它在栈里睡着就行。

桩的末尾备着 iretq,可咱们的报告不走它。为什么,停一停里那道除法题您已经推过了:不修路就回去,同一出戏的无限重演,这是故障的 rip 定死的。所以桩报告完就地 Halt,把六件现场原样留在了屏上。这当的是遗言,不是急诊:能修好路再回去的故障处理,得等内核再多几站的家底,第 3 部缺页的正戏开锣,那才是它的场子。

## Code: Cinux 实况:面板五行,一针 ud2

实况锚用的是 r08_idt,正文《会疼:自己的表,有名有姓的疼》那一卷。咱们照旧拿克隆说话,您看到的代码与屏,都是同一个检出态里的东西,`git switch --detach r08_idt` 切了过去,看完了拿 `git switch -` 切回来。这一场咱们不冻机器也不用 gdb:戏全写在日志里,咱们起机、读文件就够。镜像的老话再念一遍:机器认镜像不认源码,改完了代码,boot_image 得显式地重打,真拿陈镜像开了机,起来的还是旧机器。

```bash
git switch --detach r08_idt
cmake -B build && cmake --build build --target boot_image
timeout 30 qemu-system-x86_64 -accel tcg \
    -drive format=raw,file=build/boot/cinux.img \
    -display none -no-reboot \
    -serial file:build/console.log \
    -debugcon file:build/debugcon.log
```

timeout 是给机器上的保险:这一版跑完面板就进 Halt,机器停在原地不再往前走,真要一直停下去的话,三十秒一到 timeout 替咱们把 QEMU 请出门。console.log 里落了二十三行。头十八行是 boot 一路的报平安,连它们也全落在真串口的日志里。debugcon.log 打开是空的,0xE9 整场没过一个字节的动静。咱们要看的是末尾五行,面板逐字抄在了下面:

```text
[kern] 64-bit C++ world alive
[kern] gdt+idt self-owned, sse on
[kern] bootinfo: 7 e820 entries, fb 1024*768*32
[kern] kernel at 200000 size 83C00 entry 200330
[kern] pmm: 32348 pages free (probe 100000 ok)
```

五行的面板里,老相识当中混了新面孔。头一行是见过的老面孔:64-bit C++ world alive,说话的是内核。第二行换的是新话:gdt+idt self-owned,段表、打断表都自家立了,这句话是本章的正主。尾巴上的 sse on,SSE 的开禁也在同一站办的,全本请的是正文《开禁》,咱们认字面。到了第三行,e820 给的图是七条,您的 QEMU 未必出同一个数,机器报多少咱们记多少,1.5 讲过它的脾气。到了第四行,报的是内核住哪儿、多高、从哪儿进,1.8 讲过的那套户口,数字是随版本变的。到了第五行,pmm 报的是 32348 页自由,比 1.6 手里的那版多了一页:那一版内核个头大些,多占了一页地,1.7 里对过同款的出入,这里就不重算了。

面板是干净的,咱们这就给它扎一针。您打开 kernel/kernel.cpp,Main 的五行 Println 之后、cinux::console::Halt() 那一行之前,塞进去的就一行:

```cpp
    asm volatile("ud2");
```

咱们扎的就是 ud2:x86 特意留的坏指令,生来两字节的个头,谁执行了它谁挨 6 号,报的是无效指令。针扎的就是这个位置:往下挪一行,等会儿屏上的 rip 就跟着挪,它认的是注入点,人是不认的。扎完了还是那两步:重打镜像、起机,咱们再读日志。

console.log 从二十三行变成了二十五行,咱们要看的新戏就是末尾两行:

```text
[kern] exception #6 Invalid Opcode
[kern]  rip=FFFFFFFF8020031C cs=8 rflags=10006 rsp=8FEE0 err=0
```

六件咱们逐件对。名字报的是 #6 Invalid Opcode,ud2 应的号,名表 6 号的格子。rip 报的是 FFFFFFFF8020031C,头上一串 F 是高半世界观的记号,1.8 里咱们换算过:减掉世界观原点,加上物理的家,落在了 0x20031C,内核的地界之内。停一停里推过的那副脾气,这里让您亲眼见:ud2 是故障,rip 停在它本人的身上,一行一行地数过去,正落在了那根针上。cs 报的是 8,门里记的选择子,自家三槽表的代码段,对上了。它还带一层证词的分量:内核刚出生那会儿借 boot 的段表过日子,门里记的选择子还是 0x18,1.4 第二场远跳落的那枚,屏上要报的就得是它。报出来的是 8,办差的是新门新表,面板第二行的那句 self-owned,这一件替它验了明正身。rflags 报的是 10006,咱们只认 IF 一粒:第 9 位的 0x200,10006 里没有它的影子,IF 是躺着的。外线的一根都没接,总闸还是关着的,听铃的活是 1.6 那一场的。rsp 报的是 8FEE0,栈立在了 0x90000,往低处的方向长,离栈顶二百八十八个字节的距离,落点是正常的。err 报的是 0,#6 是不带错误码的,压码的不是 CPU,这个零是桩垫的,自家人递的数。

咱们验完就撤。`git checkout -- kernel/kernel.cpp` 一句拔了针,重打了镜像再起机,console.log 回到了二十三行,exception 那两行没了,家底还了它干净。疼这个东西嘛,咱们验过一回,知道了它喊得出名字,往后就不必一直疼着了。QEMU 要是到点赖着不退的话,收它的法子在这儿交底:ps -eo pid,comm 里按号收了它,pkill 认不全它的长名。

## 对照:同一件事,别的机器怎么做

xv6 那边咱们核过的库存,还是书页 25 与 28 的那两页,打断的机构在里头一个字都没提。书里讲它的章节翻到哪儿了,笔者还在半道上,今天咱们借不出一个字。RISC-V 也是分异常与中断的,它家自有的一套章法,等书翻到的时候,咱们当面比。

Linux 那头的同一张 IDT 天天接活,可拿咱们的报告去想它的处理,差的可是一个段位。咱们的桩印完就 Halt,当的是遗言。真实内核的异常处理是急诊:缺页来了,查的是缘由,再把缺的页补上,iretq 送挨那一记的指令回去重办,戏是接着演的。急诊室的底细,缺页怎么修、修不好怎么发落,咱们连 Linux 那头处理入口的头一行都没读过,手头一本核过的书也没有。这一档今天咱们空得踏实,货是真的没有。

自家的取舍,没做的活也摆在明处。外线的一根都没接,IF 从保护模式躺到了今天,sti 开闸、接铃、回礼 EOI 的活,全在 1.6 和正文往后接外线的那几篇里排着。急诊是不做的,理由上一段说过了:家当不够。名表止步在架构地界,22 往后写的 Reserved,表外答的 Unknown,名是一个也不编的。门型认的只是 0x8E 一种,进门清 IF 的最稳脾气:陷阱门那副不清 IF 的性子,得等真有多级中断要嵌套了再请。这四笔全是排期的功课,不是现成的便宜,消费者来了再添,这纪律咱们认得久了。

这一章的 C++,戏台只搭在了 isr.cpp 一户人家。桩的差事,第一遍是五百多行的手搓汇编:两个宏、十五个桩,一个一个地展开,对号靠的是人眼。这一遍咱们一行宏都不写。GCC 在 x86 上给了个 interrupt 属性,函数挂上了它,寄存器的保存、栈面的找齐、末尾的 iretq,编译器全包了。咱们要写的只有两个模板:一个接不带错误码的门,签名里带的只有帧指针,一个接带的,签名里多的是一个 error_code。向量号怎么进桩?走模板参数:实例化 exception_with_code<13> 的那一刻,13 就烤进了函数体,报告收到的就是自家那个号,错不了格。哪种号带的是码,装桩的时候模板自己查三十二格的小表选形状,靠 if constexpr 的一分,一口气就装完了三十二扇门。当年靠人眼对五百行的事,如今编不过就是编不过,号传错了根本到不了机器跟前。

## 这一章留下了什么

收工了,咱们把这一章挣下的东西摆上桌。头一笔是表的底子:IDT 的 256 格,一格记的是一门,一门的十六字节折出整张 4KiB,家安进了 .bss,lidt 一声递了下去,CPU 从此认下了它。第二笔是来路的两类。异常是 CPU 自己喊的疼,0 到 31 号是架构的自留地。中断是外线按的铃,32 号往上是它的地界,来路是不一样的,进门的手续是一样的,查表拿的都是向量号。第三笔是异常的两副脾气。故障的 rip 停的是肇事指令本人,回去重办的也是它本人。陷阱是办完了才停,rip 指的是下一条,系统调用靠的正是这副脾气。第四笔记的是门型:0x8E 摊开是在场位加 DPL 0 加中断门,进门自动摘的是 IF,出门的 iretq 又自动还回来。第五笔记的是六件现场:名字、rip、cs、rflags、rsp、err,机器临睡前把口袋整个翻了出来,咱们数下来一件没落下。表立了,疼也喊出了名姓。可上一章的那对快门,到这一章还没接上成套的活:编号怎么定,话怎么递,错怎么报,这就要等下一章《系统调用》来立了。

| 术语 | 一句话口径 |
|---|---|
| 异常 | CPU 自己喊的打断:肇事指令惹的祸,号落在 0 到 31 |
| 中断 | 外线按的铃:时钟、键盘这一路,32 号往上,不挑当前指令 |
| 向量号 | 打断的名牌:0 到 255,两类来路都拿它查同一张表 |
| IDT | 中断描述符表:256 格,一门 16 字节,整张 4KiB,住 .bss |
| 中断门 | type_attr 0x8E 的门:进门自动清 IF,出门 iretq 自动还 |
| 故障与陷阱 | 异常的两副脾气:故障 rip 停在肇事指令,陷阱停在下一条 |

## 练一练

针咱们扎过也拔过,轮到您了:三道题,动手的、推脾气的、读屏的各一道。

**题一您来动手。** 实况节的那三拍,您自己整场走一遍:您起机认面板,扎针对的是六件,拔了针还它干净。命令就不重印了,实况节里的那几行,原样搬了来就能用,针照 Main 末尾 Halt 前那一行的位置塞。撤完了针再 git switch - 一敲,克隆落回了 main,针、面板、那两行报告全都留在了 r08 那一版里。您抄下来的 rip 若不是 FFFFFFFF8020031C,头一个查的就是针挪没挪:它认的是注入点,人是不认的。

**题二咱们猜一猜。** 咱们把 ud2 的脾气换一换:要是它踩的是陷阱,压栈的 rip 指向下一条,这出戏怎么变?屏上那个 rip 会差几个字节?桩要真 iretq 回去了,机器还会一遍一遍重演吗?推完回参考答案对。

**题三您来读屏。** 实况节的那两行报告,六件里头哪一件的数是咱们自己人递的、CPU 没经手?再把 rflags 的 10006 摊开:第 9 位的那粒 IF,立着还是躺着?

### 参考答案

题一:您跑出来,面板的五行、报告的两行,行数与次序跟实况节的那两块都不差。e820 的条数、pmm 的页数随您的内存图走,就不必对数了。rip 要是不同的话,您查针挪没挪:挪一行,数跟的也是一行。

题二:差的是 2。ud2 生来两字节的个头,rip 指的是到下一条。循环没有了,iretq 把机器送了回去,CPU 从下一条的位置接着取指,这出戏是只演一遍的。您再往深一层想,陷阱的记法生来给办完了的事用,系统调用靠的正是它。

题三:答的是 err。#6 是不带错误码的,压码的不是 CPU,桩垫的零,报告里那件 err=0 是自家人递的。rflags 报的是 10006,咱们摊开只认 0x200 那粒,它的影子不在里头,IF 还是躺着的,外线的总闸从来没拉过。
