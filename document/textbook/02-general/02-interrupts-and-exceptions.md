# 02 · 中断与异常:一张表,两类来路,六件现场

前置卷《内核是什么》里,咱们看过内核的三张脸,这一章接住其中两张。一张出自 divzero 那个小程序:除数一为零,shell 报上来 exit=136,折成信号是 SIGFPE,这脸是程序自己吃出来的。另一张在 /proc/softirqs 里:TIMER 那一行隔两秒再读一遍,每一栏都在涨,这脸是外头的钟替它翻的,程序自己全不知情。同一位内核,伺候的是两路完全不同的打断,一路来自屋里,一路来自屋外。

上一章收尾咱们问过:客人要是跑飞了、跑死了,或者外面的世界来敲钟,谁去拉它一把。拉它的就是今天这套机构。前置卷里它只露过脸,收场的活全是内核替咱们包了的,这一章咱们把它请到桌边看清楚:打断分几路来,来了躲进哪张表、进哪扇门,疼了怎么把现场报得有名有姓。

上一章还留过一扇老门,客人拿 int 指令也能敲的那扇,关卡多:要过 IDT 查表,要按门里定好的格式压帧,一路盖章。本章就把那几道关卡一道道走一遍。次序也顺着来:来路怎么分,rip 怎么记,表和门长什么样,末了咱们亲手往代码里扎一针,听机器把疼一五一十喊出来。

量法这一章,一半认码,一半认屏。表、门、桩、名表(给号报名字的小表),四样家当全在自家源码里。实况退回 r08_idt,表自家立起来的那一版,咱们挨件读,读了什么写什么。疼的那一半,得听机器亲口喊,五行面板加两行异常报告,都是咱们自家起机抄下来的。有两处来历要交代清楚。门描述符与异常分类的正式条文,住在 Intel 的手册里,书架上还是没有那本书,fault、trap 这类通行名目,咱们借名字、不引页。《深入理解计算机系统》的第 8 章,这一回咱们只取它一小截:开场给异常分类、给 fault 和 trap 落名字的那部分,名字借来就用,条文原样留在书里。

> **机器正跑着,谁有资格让它停下来?停完凭什么回得来?**
>
> 有资格的来路只有两条:CPU 自己喊的疼,和外线按的铃。停完回得来,靠一表一门:打断那一拍,现场压上栈,门里记着该去哪儿,办完 iretq 原样奉还。来者换个名牌,叫向量号,谁来了都拿它查同一张表。咱们这一章,就把表、门、现场一件件认全。

## 来路:自己喊的疼,外线按的铃

机器自己喊的这路,行话叫异常。喊的时机认得很准:出的事,永远出在机器正在执行的指令身上。除零,0 号。一条念不懂的指令,6 号。手伸过了权限线,13 号 #GP。第三种您见过实弹:前置卷《保护模式与长模式预览》的镜子里,ring 3 的一条读 CR0、一条 cli,当场被 #GP 摁住。上一章咱们还留过话,真拿 cli 去试身手的实弹在正文《第一跳实弹》,那头机器按异常的惯例收场。收场走的就是今天这套机构:越权那一拍,13 号门开,机器被拉回 ring 0,处理程序接手。

外线按的这路,行话叫中断。它跟当前指令没有冤仇:时钟到点要响,键盘按下要响,机器正跑哪条指令,它们不挑。1.6 里咱们陪心跳数过 792 声铃,每一声走的都是同一条路。铃怎么从设备一路递到 CPU,那一章拍过全本,咱们不重叙,本章只管铃进了 CPU 之后的事。

两路来人,脾气不同,进了 CPU 却享同一套待遇:都折算成一个向量号,都拿号去查同一张表。号的地界是架构划死的,1.6 报心跳的时候咱们照过一回面:0 到 31 是架构异常的自留地,咱们认几个熟脸,0 号除零,6 号无效指令,13 号一般保护。14 号缺页眼下还只是个名字,第 3 部它是正角。32 到 255 是外线的地界,设备想开口,门牌从这片领,心跳领的 32 号门就在这片里。

前置卷《内核是什么》里,咱们给内核收过一句定位:替咱们照看资源的那一层。管家日常伺候的,一大半就是这两路打断。客人出了事,它去收场。外头来了活,它去应门。Cinux 眼下刚把表立起来,应门的手艺咱们一站一站学。

> 软件那头还有位远亲:前置卷《Unix 使用侧》里您拿 kill 递过信号,它也长着一张打断、处理、回来的脸,可那是软件层的手艺,咱们认个亲就走。

## 停在哪儿:故障与陷阱的分界

异常这一路,底下还分两副脾气。咱们拿一件东西当分界线:进异常门之前,CPU 压进栈里的 rip,指的是哪儿。就凭 rip 指向哪儿,异常分成了故障与陷阱。

故障的 rip,停在肇事指令本人身上。除零是它,无效指令是它,咱们表里挂了桩的大头全是这一副脾气。道理推一层就通:故障的意思,是出事的指令没办成。没办成,回去就得从它本人重头再办。缺页的戏最典型,您听个梗概:访存的指令伸手要一页,页不在家,处理程序把页请回来,iretq 回去,CPU 从 rip 接着取指,取回的还是同一条访存指令,这回再办,办得成了。

陷阱反过来:事办完了才停,rip 指着下一条。上一章那对快门,走的正是这副语义:SYSCALL 执行那一拍,RIP 自动存进 rcx,存的是下一条的址。您回头想想,这个安排跟陷阱的脾气对得严丝合缝:系统调用是替客人办事,办完就该顺着往下走。要是 rip 也停在 SYSCALL 本人身上,回去把系统调用再发一遍,一个 write 就成了两个。

**停一停,推一步**:您拿除零想,它是故障,压栈的 rip 指着除法指令本人。要是处理程序什么也没修,拿 iretq 就回去了,CPU 办的头一件事是什么?这出戏演到第几遍才收场?

回去办的头一件事,是把刚才的除法再取一遍:rip 停在它身上,CPU 从 rip 取指,取回来的还是它,除数还是零,又是 0 号门,又进一回桩。这出戏没有大幕,一遍一遍演下去没有头。所以故障要回去,处理程序得把路修好。修不好,就别回去,想法子把现场留下来。咱们眼下的桩怎么办,往下读到六件现场,您就见着了。

## 一张表,一扇门

打断的机构,正主是一张表:中断描述符表,行话 IDT,1.6 里您见过这个名字。规格一口气报完:二百五十六格,一格记一扇门,门十六个字节,整张 4KiB,住 .bss。这副规格 1.6 讲心跳时原样报过,那会儿只借了门的数目和屏上一行 limit,本章咱们把表真立起来。住 .bss 有讲究:盘上的镜像一个字节不为它多花,起机清零完,咱们再往里填。idt.cpp 里 g_table 一声落地,就是这么一张空表。这一户您也见过:刚出生时它只有三十二格,名字还叫 g_idt,1.8 的 .bss 院子里数过它。到了这一版,改叫 g_table,铺满二百五十六格。

表装好了,得让 CPU 认。装表的指令叫 lidt,lgdt 的兄弟:1.4 里咱们拿 lgdt 给 CPU 递过 GDT 的身长和地址,lidt 递的是同一副格式,递的对象换成 IDT。1.6 的 monitor 屏上您见过它的产出,IDT 那行末尾的 00000fff 正是身长,256 乘 16 减 1,一字不差。从递出去那一拍起,CPU 再遇打断,认的就是咱们自己的表。

门里装什么,咱们把十六个字节摊开看。idt.hpp 里它叫 GateEntry,长这样:

```cpp
struct [[gnu::packed]] GateEntry {
    unsigned short offset_low;
    unsigned short selector;
    unsigned char  ist;
    unsigned char  type_attr;
    unsigned short offset_mid;
    unsigned int   offset_high;
    unsigned int   reserved;
};
```

您扫一眼就有个疑问:处理程序的 64 位址,怎么被切成了三截?offset_low、offset_mid、offset_high,低、中、高三段散住,中间还夹着 selector、ist、type_attr。这是 CPU 定下的格式,咱们只有照装的份。把一个址照这副格式切好、填进门里,是 idt.hpp 里 EncodeGate 的活:三次移位加掩码,进的是一个址,出的是十六个字节,纯函数,别的什么都不碰。

selector 一格,记 0x08,自家三槽表里的代码段,进门那一拍 CPU 拿它查眼下当值的 GDT。1.6 的 monitor 里报过 limit 0x17 的三槽表,就是它。ist 一格记 0:那是换栈的机关,真用得上得等中断自带栈的年头,咱们眼下不动它,数字 0 的意思是这门手艺搁着不用。

最要紧一格是 type_attr,咱们写 0x8E。一个字节摊开念:最高位是在场位,1 表示这扇门真住着人。挨着它两位是 DPL,咱们记 0:眼下只有内核自己能使 int 指令敲开这扇门,楼下的客人敲,门不开。真要客人也敲得开,DPL 得放到 3。咱们记 0,客人敲过来的那一下,应门的还是 #GP。尾巴上 0xE,中断门。中断门的脾气就在这儿:进门那一拍,硬件自动把 IF 清零,出门的 iretq 又自动把它还回来。您听着耳熟就对了,上一章 SFMASK 讲过同工的一手:快门进门,摘旗靠软件预写好清单。老门进门,摘旗是硬件自带的动作。为什么进门要摘它,道理在嵌套,那一课得等真有多级中断的日子,今天咱们只认下这副脾气。

进门时压栈的家当,还差一处要交代。有一类异常,CPU 压完现场会自己再多压一个错误码,#GP 是,#PF 也是,事故的详情折在里面。另一类不压,#0 除零、#6 无效指令都不压。这一差不要紧,要紧的是桩的读法:栈上差一个字,桩要是照同一个姿势去读,后头全错位。所以桩有两种形状。带码的门,签名里多接一个错误码,CPU 压的原样递进去。不带码的门,桩自己垫个零,把栈面找齐。哪种号带码哪种不带,记在一张三十二格的小表里,咱们装桩的时候照表选形状,一行不用人眼去对。

32 号往上,眼下没有住户:咱们只装了 0 到 31 的异常桩,外线一根还没接。可门牌簿是全的,256 格都在。哪天一条 int 指令踩上了空门,机器报出来的会是谁?

**停一停,断个案**:您拿 int 0x80 试,踩的是 128 号门,门里眼下空着。屏上报名的会是谁的号?真凶 128,又藏在报告的哪一件里?

咱们断案:报名的是 #GP,它替缺席者顶了名。门不在场,按架构的章法,13 号出面。真凶的号没丢,折进了错误码里:err 右移三格,得的就是被踩那扇门的号。空门不撒谎,它只是暂时没住户。往后哪扇门真住进了人,走的也是同一套章法。

还有一条边界要画在纸上。异常还没应完又出新异常、接不住的时候,CPU 把机器送进 8 号门,双重故障。这重保护再失手一回,CPU 就不找人了:当场复位,屏一黑,一句遗言没有,行话叫三重故障。咱们让桩报告完就 Halt,把机器停在有名字的地方,别让它滚进那片黑。

## 六件现场,一件不缺

疼要喊得出名字,喊名字的活在 exception.cpp,咱们分两样认。头一样是名表 kExceptionNames,三十二格,0 到 21 各有各名,除零、无效指令、双重故障一路排下去,唯独 15 号无名,它和 22 往后老老实实写 Reserved。表外去问,它宁可回 Unknown,也不编。第二样是报告 ReportFault,两行 Println:头一行名字带号,第二行是余下那五件,印完 Halt。长什么样,实况节马上见。

两行合起来六件,咱们一件一件过。名字,说出的是什么事:6 号事主在代码,14 号事主在页表,方向一报就分。rip,说出在哪儿出的事,故障还指着肇事指令本人。cs,说出事那一刻住在哪个段世界,咱们门里记 0x08,报出来就该是 8。rflags,状态字,手册里有整页的明细,咱们只认 IF 那一粒:第 9 位,0x200,它立着中断就开着,它躺着中断就关着。rsp,栈的落点,现场全压在栈上,栈要被人写花,它头一个露馅。err,事故详情,带码的异常它真有来历,不带码的,它是桩垫的零。

有个小出入要交代:CPU 压栈的现场是五件,rip、cs、rflags、rsp、ss。报告出面的是四件,添上名字和 err,凑成屏上的六件。ss 也压在栈上,这一版的报告没请它出面,咱们知道它在栈里睡着就行。

桩的末尾备着 iretq,可咱们的报告不走它。为什么,停一停里那道除法题您已经推过了:不修路就回去,同一出戏无限重演,这是故障的 rip 定死的。所以桩报告完就地 Halt,把六件现场原样留在屏上。这当的是遗言,不是急诊:能修好路再回去的故障处理,得等内核再长几站,第 3 部缺页的正戏开锣,那才是它的场子。

## Code: Cinux 实况:面板五行,一针 ud2

实况锚是 r08_idt,正文《会疼:自己的表,有名有姓的疼》那一卷。照旧拿克隆说话,代码与屏,全部出自这个检出态,`git switch --detach r08_idt` 切过去,看完 `git switch -` 切回来。这一场不冻机器,也不用 gdb:戏全写在日志里,咱们起机、读文件就够。镜像的老话再念一遍:机器认镜像不认源码,改完代码,boot_image 得显式重打,拿陈镜像开机,起来的还是旧机器。

```bash
git switch --detach r08_idt
cmake -B build && cmake --build build --target boot_image
timeout 30 qemu-system-x86_64 -accel tcg \
    -drive format=raw,file=build/boot/cinux.img \
    -display none -no-reboot \
    -serial file:build/console.log \
    -debugcon file:build/debugcon.log
```

timeout 是给机器上的保险:这一版跑完面板就进 Halt,机器停在原地不再往前走,真要一直停下去,三十秒一到,timeout 替咱们把 QEMU 请出门。console.log 里二十三行。头十八行是 boot 一路的报平安,连它们也全落在真串口的日志里。debugcon.log 打开是空的,0xE9 整场没过一个字节。咱们要看的是末尾五行,面板逐字抄来:

```text
[kern] 64-bit C++ world alive
[kern] gdt+idt self-owned, sse on
[kern] bootinfo: 7 e820 entries, fb 1024*768*32
[kern] kernel at 200000 size 83C00 entry 200330
[kern] pmm: 32348 pages free (probe 100000 ok)
```

五行里,老相识混着新面孔。头一行是老面孔:64-bit C++ world alive,内核在说话。第二行是新话:gdt+idt self-owned,段表、打断表都自家立了,这句话是本章的正主。尾巴上 sse on,SSE 的开禁也在同一站办的,正文《开禁》有全本,咱们认字面。第三行,e820 出图七条,您的 QEMU 未必出同一个数,机器报多少咱们记多少,1.5 讲过它的脾气。第四行,内核住哪儿、多高、从哪儿进,1.8 讲过的那套户口,数字随版本变。第五行,pmm 报 32348 页自由,比 1.6 手里那版多一页:那一版内核个头大些,多占一页地,1.7 里对过同款的出入,这里不重算。

面板干净,咱们这就给它扎一针。打开 kernel/kernel.cpp,Main 的五行 Println 之后、cinux::console::Halt() 那一行之前,塞进去一行:

```cpp
    asm volatile("ud2");
```

咱们扎的就是 ud2:x86 特意留的坏指令,生来两字节,谁执行谁挨 6 号,无效指令。针就扎在这个位置:往下挪一行,等会儿屏上的 rip 就跟着挪,它认注入点,不认人。扎完还是那两步,重打镜像,起机,读日志。

console.log 从二十三行变成二十五行,咱们要看的新戏就是末尾两行:

```text
[kern] exception #6 Invalid Opcode
[kern]  rip=FFFFFFFF8020031C cs=8 rflags=10006 rsp=8FEE0 err=0
```

六件咱们逐件对。名字 #6 Invalid Opcode,ud2 应的号,名表 6 号的格子。rip=FFFFFFFF8020031C,头上一串 F 是高半世界观,1.8 里咱们换算过:减掉世界观原点,加上物理的家,落在 0x20031C,内核地界之内。停一停里推过的脾气,这里亲眼见:ud2 是故障,rip 停在它本人身上,一行一行数过去,正落在那根针上。cs=8,门里记的选择子,自家三槽表的代码段,对上了。它还带一层证词的分量:内核刚出生那会儿借 boot 的段表过日子,门里记的选择子还是 0x18,1.4 第二场远跳落的那枚,屏上要报的就得是它。报出来是 8,新门新表在办差,面板第二行那句 self-owned,这一件替它验了明正身。rflags=10006,咱们只认 IF 一粒:0x200,第 9 位,10006 里没有它,IF 躺着。外线一根没接,总闸没拉过,听铃的活是 1.6 那一场的。rsp=8FEE0,栈立在 0x90000,往低处长,离栈顶二百八十八个字节,落点正常。err=0,#6 不带错误码,CPU 没压,这个零是桩垫的,自家人递的数。

咱们验完就撤。`git checkout -- kernel/kernel.cpp` 一句拔针,重打镜像再起机,console.log 回到二十三行,exception 那两行没了,家底还它干净。疼这个东西,验过一回,知道它喊得出名字,就不必一直疼着。QEMU 要是到点赖着不退,收它的法子在这儿交底:ps -eo pid,comm 里按号收它,pkill 认不全它那个长名。

## 对照:同一件事,别的机器怎么做

xv6 那边,咱们核过的库存还是书页 25 与 28 那两页,打断的机构在里头一个字都没提。书里讲它的章节翻到哪儿了,笔者还在半道上,今天借不出一个字。RISC-V 也分异常与中断,它家自有章法,等书翻到,当面比。

Linux 那头,同一张 IDT 天天接活,可拿咱们的报告去想它的处理,差着一个段位。咱们的桩印完就 Halt,当的是遗言。真实内核的异常处理是急诊:缺页来了,查缘由,把页补上,iretq 送挨那一记的指令回去重办,戏接着演。急诊室的底细,缺页怎么修、修不好怎么发落,咱们连 Linux 那头处理入口的头一行都没读过,手头一本核过的书也没有。这一档今天空着,空得踏实,货是真没有。

自家的取舍,没做的活也摆在明处。外线一根没接,IF 从保护模式躺到今天,sti 开闸、接铃、回礼 EOI,全在 1.6 和正文往后接外线的那几篇里排着。急诊不做,理由上一段说过,家当不够。名表止步在架构地界,22 往后 Reserved,表外 Unknown,一个名不编。门型只认 0x8E 一种,进门清 IF 的最稳脾气:陷阱门那副不清 IF 的性子,得等真有多级中断要嵌套了再请。这四笔全是排期的功课,不是现成的便宜,消费者来了再添,这纪律咱们认得久了。

这一章的 C++,戏台只搭在 isr.cpp 一户人家。桩的差事,第一遍是五百多行手搓汇编:两个宏,十五个桩,一个一个展开,号靠人眼对。这一遍一行宏都不写。GCC 在 x86 上给了个 interrupt 属性,函数挂上它,寄存器的保存、栈面的找齐、末尾的 iretq,编译器全包。咱们要写的只有两个模板:一个接不带错误码的门,签名里只有帧指针,一个接带的,签名里多一个 error_code。向量号怎么进桩?走模板参数:实例化 exception_with_code<13> 的那一刻,13 就烤进了函数体,报告收到的就是自家那个号,错不了格。哪种号带码,装桩的时候模板自己查三十二格的小表选形状,if constexpr 一分,三十二扇门一口气装完。当年靠人眼对五百行的事,如今编不过就是编不过,号传错了根本到不了机器跟前。

## 这一章留下了什么

收工,咱们把这一章挣下的东西摆上桌。一张表,IDT,256 格,16 字节一门,整张 4KiB 住 .bss,lidt 一声,CPU 从此认它。两类来路,异常是 CPU 自己喊的疼,0 到 31 号是架构自留地,中断是外线按的铃,32 号往上,来路不同,进门的手续一样,都拿向量号查表。两副脾气,故障的 rip 停在肇事指令本人,回去重办,陷阱办完才停,rip 指下一条,系统调用靠的正是它。一扇门,0x8E 摊开是在场位加 DPL 0 加中断门,进门自动摘 IF,出门 iretq 自动还。六件现场,名字、rip、cs、rflags、rsp、err,机器临睡前把口袋整个翻出来,一件没落下。表立了,疼也喊得出名姓。可上一章那对快门,到这一章还没接上成套的活:编号怎么定,话怎么递,错怎么报,下一章《系统调用》接着立。

| 术语 | 一句话口径 |
|---|---|
| 异常 | CPU 自己喊的打断:肇事指令惹的祸,号落在 0 到 31 |
| 中断 | 外线按的铃:时钟、键盘这一路,32 号往上,不挑当前指令 |
| 向量号 | 打断的名牌:0 到 255,两类来路都拿它查同一张表 |
| IDT | 中断描述符表:256 格,一门 16 字节,整张 4KiB,住 .bss |
| 中断门 | type_attr 0x8E 的门:进门自动清 IF,出门 iretq 自动还 |
| 故障与陷阱 | 异常的两副脾气:故障 rip 停在肇事指令,陷阱停在下一条 |

## 练一练

针咱们扎过也拔过,轮到您了:三道题,一道动手,一道推脾气,一道读屏。

**题一,动手。** 实况那三拍,您自己整场走一遍:起机认面板,扎针对六件,拔针还干净。命令不重印,实况节里那几行,原样搬来就能用,针照 Main 末尾 Halt 前那一行的位置塞。撤完针再 git switch - 一敲,克隆落回 main,针、面板、那两行报告,全都留在 r08 那一版里。您抄下来的 rip 若不是 FFFFFFFF8020031C,头一个查针挪没挪:它认注入点,不认人。

**题二,猜想。** 咱们把 ud2 的脾气换一换:要是它踩的是陷阱,压栈的 rip 指向下一条,这出戏怎么变?屏上那个 rip 会差几个字节?桩要真 iretq 回去了,机器还会一遍一遍重演吗?推完回参考答案对。

**题三,读屏。** 实况那两行报告,六件里头哪一件的数是咱们自己人递的、CPU 没经手?再把 rflags 的 10006 摊开:第 9 位那粒 IF,立着还是躺着?

### 参考答案

题一:您跑出来,面板五行、报告两行,行数与次序跟实况节那两块不差。e820 的条数、pmm 的页数随您的内存图走,不必对数。rip 要是不同,您查针挪没挪:挪一行,数跟一行。

题二:差 2:ud2 生来两个字节,rip 指到下一条。循环没有了,iretq 回去,CPU 从下一条接着取指,这出戏只演一遍。您再往深一层想,陷阱的记法生来给办完了的事用,系统调用靠的正是它。

题三:err。#6 不带错误码,CPU 没压,桩垫的零,报告里那件 err=0 是自家人递的。rflags=10006,咱们摊开只认 0x200 那粒,它不在里头,IF 躺着,外线的总闸从来没拉过。
