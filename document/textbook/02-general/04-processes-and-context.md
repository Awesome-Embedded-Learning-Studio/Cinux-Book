# 04 · 进程与上下文:一副影像,一拍换手,一条新执行流

内核打出生那天起,身上就只有一条执行流:boot 把它牵进门,Main 一条道跑到底,中途进来的全是打断,办完一场,还给它接着跑。上一章收尾咱们留过一句话:yield 与 exit 已经会在门里换任务,换任务的门道本身,一个字没讲。这一章开的就是这门戏:给内核添第二条执行流,一路添到第六条。添的家当只有一副,谁穿上它,谁就是此刻的执行流。

调度与任务的排场是本章的戏,这话上一章也记了一笔。排场咱们照着机器造它的次序看:任务长什么样,切换那一拍发生了什么,调度器凭什么只动嘴、不动手。三样认全,您回头再看上一章 yield 那一单,门里走的每一步都有名有姓了。

还有一件旧事,拖了两章,今天认领。2.1 的日志里,六位内核任务的三场拉练头一回照面,那会儿咱们说过,来路住在正文后面的几卷,教科书层走到那儿再认。走到这儿了。六位任务是谁、三场拉练各演的什么、屏上那些交错是怎么冒出来的,这一章一次交齐。底子是一台机器的五十五行日志,实况节咱们逐场读。

量法这一章,家当几乎全在自家码上:一副影像、一份切换汇编、一座调度器,咱们照着源码一件一件认。戏文在屏上:一台机器,三场拉练。书那一头,xv6 翻到了第 8 章,书页 75、77、78 三页咱们逐字核过,对照一节挨页引。

> **CPU 里只有一套寄存器,屏上凭什么站着六位任务?**
>
> 咱们把落差摆开。屏上站着六位任务,CPU 手里却只有一套寄存器,可值能整副换。每位任务自带一副 576 字节的影像,切换就是把当值者的值存回它的影像、把下一位的值装进 CPU:装到 rip 那一拍,跑着的就是别人了。任务不住在 CPU 里,住在各自的影像里。点谁上、谁让位,交给一位只管点名、从不动手的调度器。

## 任务的家当:五件行李,四页栈

咱们头一个看任务本人。它的全部身子躺在 kernel/proc/task.hpp 里,五件行李:

```cpp
struct Task : cinux::base::container::SelfNode<Task> {
    cinux::arch::CpuContext ctx{};
    TaskState               state{};
    unsigned long long      tid{};
    const char*             name{};
    unsigned long long      stack_base{};
};
```

一件一件过,咱们挨个认。ctx 是那副影像,下一节的主角,且欠着。state 记它这一生走到哪儿了,四个状态。就绪的,排队等着。在跑的,正占着 CPU。停摆的,睡在谁的等待席上,进出的门道要等第 4 部锁家什开讲,这里只认个名。已死的,退了场,家当待收。tid 是发到头上的号,名字是给日志看的。stack_base 单独说一句:它记的是栈的整段起点。任务一旦跑起来,rsp 千变万化,可退场那天要还的是整段四页,存不住起点,就找不着家门了。

栈从哪儿来。TaskBuilder 的 build() 办两件事:从名册领连续四页,凑成 16KiB 一副内核线程栈,名册报的物理门牌按一笔写死的加法换成高半的虚拟门牌,这笔路数 1.8 换算入口门牌时见过,只是那边减的是世界观的原点,这边加的是另一枚写死的基数,方向也倒过来。然后 new 一个 Task,把影像填好。两步之间有次序,就有失败组合:页到手了、new 却空了,章程是把页原样还给名册再空手归,半件行李都不留。您要是问栈的页为什么从名册领、不找堆切一份,那是第 3 部堆的一桩搬家事,分配器立起来才办得动,咱们记下不展开。

栈底下埋着一个数,0xDEADC0DE,写在整段栈最低的一个字上。它是溢出的验尸记号:栈往下长,长过了自己的 16KiB,头一个被改写的就是它。这个数的能力得说准,它不拦任何人,踩穿了它才会变——事后指认,不是护栏。真到崩溃那天,栈底这个字还是不是原值,能替咱们报出死因。

新任务的影像怎么填,活归 PrepareTaskContext,咱们看真身:

```cpp
void PrepareTaskContext(cinux::arch::CpuContext& ctx, const StartPlan& plan) {
    cinux::base::SetBytes(&ctx, 0, sizeof(ctx));
    plant_clean_fpu_image(ctx);
    auto* const kBottomWord = cinux::base::PtrAt<unsigned long long>(plan.stack_bottom);
    *kBottomWord            = kStackMagic;
    ctx.rsp                 = plan.stack_top;
    ctx.rip                 = plan.trampoline;
    ctx.r12                 = plan.entry;
    ctx.r13                 = plan.exit_hook;
}
```

头一行清零,给零里种上干净的浮点出厂态,然后五处落笔:魔数进栈底,rsp 落栈顶,rip 指蹦床,差事的地址进 r12,退场钩子的地址进 r13。落点的讲究有两处。一处是 rsp:栈顶站在 16 的整边上,蹦床进门头一个动作就是 call,一压返回地址,差事函数看到的栈口正好落在调用约定的落点上——2.1 楼下那 8 个字节的讲究,这里原样再办一遍。另一处是浮点出厂态:出厂的 x87 控制字 0x037F、SSE 的 MXCSR 0x1F80,种在 512 字节影像的第 32 字节上。为什么强调位置,这里有一桩旧案:MXCSR 头一回被笔者种到了第 24 字节,那是 32 位 FXSAVE 老布局的住址,FXSAVE64 把它挪到了 32。种错了机器上死不了人,可哪个任务头一回浮点运算继承了别人的舍入脾气,查起来要绕死弯。如今两个字位有断言看着:PrepareTaskContext 是纯算术,开发机上的测试直接链它的代码,不起虚拟机就能跑,种错一位当场红。

还有一层劈法咱们得看出来:这一整段给它地址它就能办,不起机器也能考。真分配的活,页从名册来、块从堆来,另住一层,只有内核自己能干。算术与分配劈成两层,这门手艺第 3 部的堆还要再用一回。

影像填好了,rip 指着的是三行汇编。咱们请蹦床出场:

```asm
TaskTrampoline:
    sti
    call *%r12
    jmp *%r13
```

新任务的头一条指令,不是差事本人,是这三步登台。sti 开中断总闸,为什么偏偏在这儿开,咱们记下这一问,本节末尾的题里答。中间 call 进差事:差事是个普通的 C++ 函数,该跑什么跑什么,跑完了 return,call 压在栈上的返回地址把它送回蹦床。末一跳 jmp 进退场钩子。退场只有一条路,这是刻意的:入口正常返回要走它,将来显式退场也走它,钩子里是调度器的 exit_current,把任务标成已死、发起换手。万一控制权在不该发生的路上还了回来,收尾一句 Halt 兜底,机器停下,不乱跑。[[noreturn]] 加一道兜底停机,上一章 Exit 的封装是同一个脾气。

为什么是 call 进差事、jmp 进退场,当年笔者头一遍写反过。那一遍用的是裸 jmp 直跳差事,栈顶还压着一个假返回地址当保险。差事老老实实跑完 return,CPU 从栈顶弹出来的就是那个假地址——恰是栈底魔数一类的值,RIP 指去 0xDEADC0DE,取指当场翻车,一声 triple fault。call 与 jmp 的全部分别就在一个返回地址:call 压,jmp 不压。用 call,return 有家可回。用 jmp,return 弹到的是栈上恰好躺着的随便什么数。那一年的教训,这一遍落在蹦床的三行里。

**停一停,数一数头一条。** 咱们填影像填了八枚寄存器,您翻遍也找不到中断闸的格子:IF 不住在八槽里。那新任务起跑那一拍,闸是开是关?它接的是谁的闸?要是蹦床三行里没有 sti,会缺什么?

闸接的是切换那一刻的闸,而来路决定那一刻,咱们把三条来路各看一眼。头一路是主流程进任务,run_until_done 把新任务直送进 CPU,主流程的闸开着,新任务接着开。第二路是协作的让位,yield 裹在一道关中断的守卫里,换手那一刻闸是关的,从让位换进来的新任务抱着关着的闸起跑。第三路是抢占的换手,换手发生在中断出口,中断门摘的旗还没人还,新任务一样抱着关着的闸起跑。实况节头一场拉练里一让一接的两位差事 echo_a 与 echo_b,echo_b 的头一跑,走的正是第二路,echo_a 喊 yield,守卫里换手,它这才从蹦床起跑。蹦床头一条 sti 把三条来路统一,不管打哪儿来,自己的闸,自己的头一条指令亲手开。少了它,抱关着的闸起跑的任务,这一关就关一辈子:时钟进不来,拍数没人记,自己不让位,谁也换不下它。至于让位者自己,被换回来那天还站在守卫里,守卫退出时按进门存的快照还原旗。三条路各管各的旗,没有一条要影像替它背。

## 切换那一拍

家当备齐,正主上场。两个任务换手,换的就是一副影像,办这件事的是 ContextSwitch,咱们把全文摆出来:

```asm
ContextSwitch:
    movq %r15, 0(%rdi)
    movq %r14, 8(%rdi)
    movq %r13, 16(%rdi)
    movq %r12, 24(%rdi)
    movq %rbp, 32(%rdi)
    movq %rbx, 40(%rdi)
    movq %rsp, 48(%rdi)
    leaq .Lresume(%rip), %rax
    movq %rax, 56(%rdi)
    fxsave64 64(%rdi)

    movq 0(%rsi), %r15
    movq 8(%rsi), %r14
    movq 16(%rsi), %r13
    movq 24(%rsi), %r12
    movq 32(%rsi), %rbp
    movq 40(%rsi), %rbx
    movq 48(%rsi), %rsp
    fxrstor64 64(%rsi)
    jmp *56(%rsi)

.Lresume:
    ret
```

两个参数走老座位:rdi 指旧任务的影像,rsi 指新任务的影像。上半场存,十行:七枚通用寄存器挨个落槽,fxsave64 把浮点现场一口气存进 512 字节。您留意 rip 那一槽,它不是一条 movq,是两行:leaq 把 .Lresume 的地址算出来,再存进去。这是整份汇编最要紧的一处心思——旧任务的影像里,指令指针不存它被换走时正跑的下一条,存的是切换函数自己的恢复点。为什么要这样,等下半场看完您就明白了。

下半场装,九行:八槽装回来,fxrstor64 把新任务的浮点现场也装回来,末了一记 jmp,跳进新任务影像里的 rip。这里为什么是 jmp 不是 call?call 会在当前栈上压一个返回地址,可这个栈马上就要换成新任务的了,压进去的返回地址落在别人的栈顶,那是纯粹的污染。jmp 干净利落,走过去就完了,谁的返回都不欠。您要觉得耳熟就对了:蹦床三行刚讲过 call 与 jmp 的分别,同一条道理,一处救的是差事的 return,一处防的是脏了别人的栈。

那要是新任务不是新造的,是个被换下场的老任务呢?咱们看它的 rip 槽,里面躺的正是当年存进去的 .Lresume。jmp 落过去,那儿只有一条 ret。于是对 C++ 的世界来说,ContextSwitch 就是一次函数调用:调进去,过了很久很久,正常返回了。ret 弹出的返回地址,是它当年作为调用者压在栈上的。栈指针,装回来的也是它自己的。被切走的代码根本不知道自己离开过多久。这就是恢复点的全部用意。

为什么影像只有八枚,十六枚通用寄存器不全存?这一半上一章替咱们算过了:调用约定把寄存器分成两半,rbx、rbp、r12 到 r15 归被调方保,跨一次调用原样奉还。另一半 caller-saved,跨调用本来就是死的,谁也没指望它们活着。咱们的切换全安排在调用边界上——yield 是一层层调用进来的,抢占的换手也在调用链的深处——所以死的半边不用存,活的半边一枚不能少,外加 rsp 和 rip,八枚齐了。上一章 rbx 那桩案子的教训,反着念就是这里的省事:约定保下来的,才值得存进影像。

槽 64 往后那 512 字节,补一句来历。开禁 SSE 之后,编译器会给普通 C++ 代码生成 XMM 指令,咱们随手一个循环,中间结果就住在 xmm0 到 xmm15 里。两个任务各自的中间结果不能互相看见,所以 SIMD 现场得整副跟着走,fxsave64 存、fxrstor64 装。SIMD 是个学名,说的就是 SSE 伺候的那类活,一条指令管一排数。这也解释了结构体上那个 alignas(16):fxsave64 与 fxrstor64 对操作数有 16 字节对齐的硬要求,结构体自己站齐,槽 64 的 fpu 才永远落在合法位置。这个 16 当年还欠过一笔债:堆的块尾巴是 8 字节,块与块的接缝就歪 8,第二个任务的影像恰好落在歪门牌上,fxrstor64 一声 #GP。债主是堆,教科书层要走到第 3 部才开讲它。修法是把尾巴垫到 16。八槽与 512 字节的每一处偏移,咱们在 context.hpp 里拿十一条 static_assert 跟汇编逐条对表:结构体与汇编是两份文件各认一套数,断言让它们只能一起改。

## 只管点名的调度器

任务会造了,切换会跑了,谁说了算该谁上 CPU?这就轮到调度器。它的家当咱们一遍点清:一条 16 席的就绪队列,队里排的是 Task 指针。一个 current 记着当值者,它不驻队,队里永远只有等着的人。四个状态各记在册,头一节里咱们认过了。tid 从 1 起往后发。座位满了怎么办?Check 断言当场叫停。这里咱们把话说重:入队要是无声无息地失败,丢的就是一次唤醒,一个任务从此无声消失,不崩溃、不报错。丢唤醒比死机难查得多,所以宁可响亮地死,不许悄悄地丢。

yield 的路,咱们跟着上一章那一单走完整。差事里喊一声 yield,调度器门口有一道关中断的守卫,门里把自己标成就绪、排回队尾,然后换手:弹出队头。弹出来的要是自己,接着跑,连切换都省了。是别人,ContextSwitch 上场。就这么朴素——协作式调度的全部,是弹出队头再塞回队尾的轮转。

这座房子有一道劈法值得专门看:调度器只管决定,从不动手。谁换谁、何时进、何时退、死者何时收,这些它拍板。可压栈存寄存器换指针这套机器活,它一件不干,全走注入。注入的接口立成一个 concept,四个动词:任务换任务、主流程进任务、任务回主流程、给死任务收尾。内核侧装的是真家伙,前三个动词落 ContextSwitch。收尾的动词不换手,还页给名册、还块给堆,不经切换汇编。外加主流程自己的一副影像——主流程不是任务,可它也得有地方存影像,不然任务回主流程就找不到路。这套分家的便宜,咱们在对照一节的 C++ 段里细看。

时钟进场,咱们把戏凑齐。1.6 立起的 100Hz 心跳,如今多一嗓子:

```cpp
void heartbeat() {
    cinux::time::Tick::self().on_interrupt();
    cinux::proc::Scheduler::self().on_timer_tick();
}
```

heartbeat 里的新嗓子是 on_timer_tick,它只记拍:当值者又跑了一拍,计上一笔。攒够时间片,立一个该换人的标志,完事正常返回,应答一行没动,谢客的延迟是零。时间片两拍一片:心跳 100Hz,一拍 10 毫秒,一片 20 毫秒。片长为什么这么短,旧案咱们只提一句:当年头一遍是十拍 100 毫秒,虚拟机里一个忙循环够把活全干完,屏上一丝交错都没有,砍到两拍、把负载加重,证据才现形。

真正的问询在出口。咱们把 irq_entry 的形状念一遍:dispatch 回来了,应答谢完了,iretq 还没执行的当口,maybe_preempt 站出来问一句,现在换吗?三道门全过才动:标志立了没有,抢占的总开关开了没有,禁抢占的计数是不是零。不该换,iretq 照旧走它的路,被打断的任务毫发无伤地回去。该换,轮换就在这儿办,iretq 留给下一位的恢复路径去用。为什么把换手挪出 handler、安在出口,您拿应答次序想一遍就通:当年头一遍在 handler 里直接切,被切走的任务停在 handler 里,应答还没执行,芯片那头 0 号线一直占着,后续的拍子一次也递不进来,别的任务饿上几秒,时钟慢上几秒。切换是对的,时机是错的。出口调度把时机定死在应答之后。

被换走的任务,旗怎么办?咱们把三处旗的关口在这儿互校一句:蹦床头一条 sti,新任务自己的闸自己开。上一章十二槽帧压完一句 sti,进门的静场到建帧为止。中断门进门自动摘旗,出门 iretq 自动还。同一面旗,三处各管各的位,谁也不多管。

抢占的总开关,默认是关的。为什么货造齐了还不常开,咱们得说准:堆和名册眼下还是不设防的共享财产,两个任务各改各的就乱了。得等第 4 部的锁家什把它们护起来,开关才敢常开。所以眼下开着的每一场,差事都是挑过的,不碰不设防的共享财产。这不是缺陷瞒着,是排期摆着。

末了咱们看退场。差事 return,蹦床把它送进退场钩子,钩子里是 exit_current:标成已死,挂上待收的名目,换手。收尾有个时序讲究:任务断气那一刻,还踩在自己的栈上,exit_current 这行代码就跑在它的栈里,这时候要把四页栈和 Task 块还回去,接下来的代码就没地方站了。所以收尾必须等换手落地,由接手的人代劳:死者的四页还给名册,块 delete 掉,干干净净。队列空了,主流程接回,CPU 回到 Main,run_until_done 走完一圈。

**停一停,查一面旗的下落。** 时钟把任务换下场,咱们跟着旗走:它的 RFLAGS 此刻存在哪儿?八槽影像里有它的格子吗?换手的人碰它了吗?将来谁替它还?

咱们一件一件答:不存,没它的格子,碰都没碰。硬件进门那一拍,rip、cs、rflags 就压进了它自己的中断帧——2.2 认过的压栈现场,物件躺在那儿。换手换的是影像,中断帧原封不动地挂在它的栈上。它被换回来那天,恢复点之后走几步就是自己的 iretq,旗从自己帧里原样还。两套随身物件各走各的路:影像管那八枚槽,中断帧管旗与回址。当年笔者的头一遍没这个结构,切换写在 handler 里,新任务从切换那一刻的旗起跑,闸是关的——除了头一个被抢占者能经 iretq 把旗还回来,后来者全在寂静里出生、寂静里退场,串口照常打印,病得一点声音都没有。这一遍把换手定在中断出口,旗的语义在每一个换手点上都自明,病灶找不到落脚的地方。

## Code: Cinux 实况:五十五行,三场拉练

实况锚是 r12_process。前几章咱们看的 r13_userspace,比它晚一站:教科书层把《下楼开张:ring3、syscall 与第一位常客》一卷的货刊在前头,这一章回头补《轮流当家:让出来的,抢出来的,排出来的》一卷,2.2 退回 r08_idt 看表,走的是同一条回头路。照旧拿克隆说话,代码与屏全部出自这个检出态。这一趟的起机素得很:不冻机器,不接 gdb,debugcon 一个字节都不用,一条 timeout 加一本串口日志,家什就齐了。镜像的老话照旧:改完代码 boot_image 得显式重打。三场拉练跑完,机器进空转等键盘,timeout 25 到点把它请走,退出码 124 是截停,不是出错。


日志整本五十五行。前十六行是 stage2 一路进门的报平安,第 1 部拍过它们的来历,咱们不重印。紧跟着 [pm] 与 [lm] 换世界的两声报平安,那场戏 1.4 拍过,也不重印。面板从 64 位那句到 keyboard 整段十行,一句不少,全抄在底下:

```text
[kern] pmm: 32336 pages free (probe 100000 ok)
```

老面孔居多,要认的有三样,一行新报的,两枚新数。screen console 那行教科书层头一回照面,报的是屏幕控制台的规格,一屏 128 列、48 行,它的来历还没开讲,咱们只认下它报的。pmm 32336:这个数咱们一路数过来了,1.6 的屏 32347,1.7 的 32350,2.2 实况的 32348,上一章 r13 的 32316,如今 r12 的 32336。五站五个数,谁也不是谁的笔误:内核个头一站一站不同,占的地就不同。kernel size 8F090 同理,您拿它跟 r13 的比大小没意义,跟自己的 entry 200040 对上就行。tick 100Hz 那行是本章时间片的娘家:一拍 10 毫秒,两拍一片,来历就在这行里。

第一场,协作。咱们请出两位差事,echo_a 与 echo_b,跑的是同一段代码:打一行,喊一声 yield,三轮退场:

```text
[task] tid=1 'echo_a' round 0
[task] tid=2 'echo_b' round 0
[task] tid=1 'echo_a' round 1
[task] tid=2 'echo_b' round 1
[task] tid=1 'echo_a' round 2
[task] tid=2 'echo_b' round 2
```

您对着调度器的路数读:echo_a 打完 round 0,yield 把自己排回队尾,echo_b 从队头接手。六行下来,一让一接,严丝合缝。tid 1 和 2,是 seat 的次序,seat 就是进队就位的那一声,发号从 1 起,头两位自然是一二。这一场里换手全是自愿的,谁让位,谁自己喊的。

第二场,抢占。咱们直接看屏,头两行长这样:

```text
[task] tid=3 'spin_a' round 0 (no yield)
[task] tid=4 'spin_b' round 0 (no yield)
```

两位忙等的差事 spin_a 与 spin_b,从当前拍数起忙等 15 拍,打一行,三轮退场,全段代码里没有一声 yield。后四行照这个样子轮完,一共六行,一来一回与第一场同形,只是每行尾巴多那半句 no yield。那是差事自己打出来的免责声明:交错不是我让的。让位的是时钟:两拍一片,片到出口,maybe_preempt 三道门一过,换人。两位谁也没喊,交错照样来,这就是上一节那套出口调度的实证。

第三场,生产与消费。咱们最后请一座四槽货架进场:tid 5 是生产者,tid 6 是消费者。

```text
[task] tid=5 produced item 1
[task] tid=5 produced item 2
[task] tid=5 produced item 3
[task] tid=5 produced item 4
[task] tid=6 consumed item 1
[task] tid=6 consumed item 2
[task] tid=6 consumed item 3
[task] tid=6 consumed item 4
```

节奏您一眼就看得出来:产四件,消四件。后头还有一小段,产二件、消二件,货色编号接在四后面,同款节奏,咱们不重印。来路在货架上:空位发四枚,生产者产到第五件,一枚空位都不剩,wait 把它撂下睡——停摆状态的头一位用户,进出的门道第 4 部开讲。消费者这才上手,逐件取,每取一件还一枚空位,取完四件,生产者醒了接着产。货架进出的门有一道锁护着,锁的姓什么,同样第 4 部再认。这里咱们只看戏:睡觉与叫醒头一回真用了,而且用对了。

收尾两行,2.1 的日志尾巴上咱们见过它们,如今来龙去脉交齐:

```text

[kern] market closed the loop, preemption stays armed
```

## 对照:同一件事,别的机器怎么做

xv6 那头,同一出戏书里写了三页,咱们挨页念。书页 75 分型:原话是 “The former are called voluntary switches, the latter involuntary.”——自愿的切换与被迫的切换。咱们前两场正好一型一场:echo 是自愿的,spin 是被迫的,教科书都没凑例子,拉练自己长出来了。同页还有一句更狠的:“the fact that this cannot be expressed in C makes it tricky”。换寄存器这件事 C 写不出来,咱们那二十来行汇编为什么非它不可,人家一句话点了题。

书页 77,讲 swtch 的存与不存:“saves callee-saved registers (ra,sp,s0..s11) but not caller-saved registers”。跟咱们八枚是同一条道理,连不存的那半边都一样——上一章认过的约定,两边通用。这一页最值得抄的是机关:“X's call to swtch() returns as if returning from Y's original call to swtch()”。X 调 swtch 切到 Y,将来 ret 落回的,是 Y 当年调用 swtch 的返回点——咱们的 .Lresume,一模一样的思路,白纸黑字写在人家书里。同页还有一句:“swtch() need not directly save or restore the program counter”,后头跟着的理由是 “it's enough to save and restore ra”。RISC-V 的 ra 归 callee-saved,存它一箭双雕,回址与恢复点都在里头。咱们的 rip 不归 callee-saved 管,所以单独开槽,八枚里占一席。机关同款,家什各随各家的约定。

书页 78,讲拓扑:“swtch() always has the scheduler thread as either source or destination”。xv6 的任务从不直切,换手必经中转:每台 CPU 配一位专职的调度线程,scheduler 跑一个循环,找人,swtch 过去,迟早 swtch 回来,接着循环。咱们的换手从任务直切任务,少一层中转、少一副调度线程的栈。代价也明摆着:人家那一层中转,换来的是跨切换持锁的纪律和往多核扩展的好走法。咱们单核直切,图的是薄,那道锁纪律等第 4 部锁家什进门时,该补的课一门不少。

Linux 那头,这一章一个字都不比。CFS、每 CPU 一份就绪队列,这些名字您多半在别处听见过,听见的不作数:它家的手册一行没翻过,源码一行没读过,比不了的就是比不了,这一段留给将来的书。

自家的窄处,照实摆。队列只有一条,十六席,轻重急缓一概不排,饿不饿全看队尾轮到没轮到。排序权重、调度类那类字段,眼下一个消费者都没有,咱们不置办。每 CPU 一套调度机构,多核那一层,整个欠着。抢占默认关,理由前面说过,共享财产还没穿护具。

这一章的 C++,咱们压轴看一个 concept。Scheduler 这个类,打生下来没见过一枚寄存器的名字:scheduler.cpp 通篇没有 ContextSwitch,它只认注入进来的四个函数指针。接口立成这样:

```cpp
template <typename Sink>
concept SwitchSink = requires(Sink& sink, Task& outgoing, Task& incoming) {
    { sink.switch_tasks(outgoing, incoming) } -> std::same_as<void>;
    { sink.enter_from_main(incoming) } -> std::same_as<void>;
    { sink.return_to_main(outgoing) } -> std::same_as<void>;
    { sink.reclaim(outgoing) } -> std::same_as<void>;
};
```

requires 表达式把四个动词的原型列全,谁来都得过这道概念关。init 是个模板,Sink 的类型到它这儿为止:lambda 转成函数指针,上下文跟着一个 void* 走,类型当场擦掉,调度器存下的就是四个指针加一个地址。分家分到类型这一层,便宜立刻兑现:咱们给开发机上的测试装一个假 sink,每个动词把发生了什么记进日志、顺手把差事调起来往前推,跑的和内核里跑的是同一份 scheduler.cpp,断言念的就是决定流。这套东西首跑就抓过一桩真泄漏:两个任务接连退场,退得早的那个收尾记录一直没来——挂新的之前旧的没收,单槽被覆盖了。修法一行次序,可要是这段逻辑只能上机器验,得等名册的页数哪天对不上数才露头。分家把能断言的半边整个搬下了机器。

## 这一章留下了什么

拉练散场,咱们把台上的家什点一点。一个 Task,家当五样:影像、状态、号、名、栈的起点。一副影像,576 字节:六枚 callee-saved 加 rsp 加 rip,八枚槽,外带 512 字节浮点现场,16 字节站齐。一次切换,存十行取九行,末了一记 jmp。rip 槽里存的是恢复点,回来那天 ret 一声,像一次特别慢的函数调用。一座只管点名的调度器:十六席队列轮转,四态各记在册,tid 从 1 发号,时间片两拍,出口问询,死者换手之后才收。旗没有新添的进出:被换走的,旗在自己帧里,自己的 iretq 还。任务会生、会跑、会让、会退了,可它们经手的活还落不下地:write 递出去的字,进了串口就没了影。字得有地方住,下一章《文件系统抽象》给第 2 部收卷。

| 术语 | 一句话口径 |
|---|---|
| 任务 | 调度的单位:一副影像加身份加四页栈,Task 五样 |
| 影像 | CpuContext 的 576 字节:六枚 callee-saved 加 rsp 加 rip,八枚槽,外加 512 字节浮点现场 |
| callee-saved | 被调方保证原样奉还的寄存器:rbx、rbp、r12 到 r15 |
| 恢复点 | rip 槽里存的 .Lresume:回来落的地方,不是走时的下一条 |
| 蹦床 | 新任务的头三条指令:sti、call 差事、jmp 统一退场 |
| 抢占 | 时钟替不让的任务让位:两拍一片,出口问询换人 |

## 练一练

三道题留给您:一道动手,一道翻源码,一道读屏。

**题一,动手。** 实况那一场您自己跑一遍:切版,起机,抄下三场的屏。命令不重印,实况节那个块里有什么,您就敲什么。想加一问也行:翻回 2.1 的日志尾巴,那五行拿着您手里这本 r12 的日志对一对,哪几行对得上,哪几行对不上,为什么。末行停在 market closed,它后头一行都没有,这趟就算跑齐了。

**题二,翻源码。** 时间片两拍一片。设一位任务跑了一拍,主动喊了 yield:接手的人从几拍数起?那个计数器 slice_ticks_,清不清零?您去 kernel/proc/scheduler.cpp 里把 yield 和 on_timer_tick 的路数读一遍,再回参考答案对。

**题三,读屏。** 生产消费那一场,生产者一口气产了四件,消费者才上手。为什么偏偏是四?您拿货架的槽位和空位的枚数推一推,再说出一件事:产到第五件的那一刻,生产者的状态从哪一态换到了哪一态。

### 参考答案

题一:您跑出来,面板十行、三场的交错、收尾两行,次序与实况节那几块不差。三场中间日志里还夹着一行 [kern] 的过场,echo 散场、主流程接回的那句,实况节没抄它,您抄到了别当多出来的东西。加问的答数:对得上的只有收尾两句,shell 那三行对不上,这一版还没有 shell。e820 的条数、pmm 的页数随您的内存图走,不必对数。交错的大形状不变,具体哪行挨着哪行,随时钟的拍子走,您抄的和咱们抄的未必行行同序。

题二:不清零。yield 的路一行都不碰 slice_ticks_,咱们把它清零的位置数出来,只两处:攒满两拍、把标志立起来的那一拍,set_preemption 动总开关的时候。所以接手的人从一拍数起,再跑一拍,标志就立了。自愿让位与被迫换手,共用同一个计数器,前者的余数后者接着记。

题三:货架四槽,空位开张四枚。产到第五件,一枚空位不剩,wait 把生产者撂下睡,状态从在跑换到停摆,消费者这才轮上。四不巧,正好是空位的枚数,咱们数一遍空位就对上了。
