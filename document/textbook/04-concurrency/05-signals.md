# 05 · 信号:两段路,一扇回家的门,四笔如实交底

4.4 收卷时指了一座桥,咱们今天开正门。睡着的人被信号拍醒之后,睡觉的原语拿什么话回,您回 4.4 借过的 xv6 书页 88 那句,接头的地方就点给了本章。同页咱们自己还要搭一座,说的其实就是它家没有信号,咱们把话留给对照节接。开篇咱们把话搁稳:回话分两屋,等待圈里答 EINTR 的那一屋,和等待表上追不上的那一屋,咱们到诚实边界一笔一笔对清,正路今天也就修通了。

这门活计为什么存在,正文《为什么教进程听懂喊声》一篇开卷盘过家底,咱们把三件缺的事原样搬来:跑飞的程序在自己的循环里转,咱们的机器没有一句号令喊得停它。父亲想听孩子的死讯,手上只有守在 wait 里睡死的一招。想让一条战线上的任务一起收摊,连喊一片的名字都还没有。其实三件共用同一个答案,答案的名字叫信号。那一篇的原话咱们整句摘:进程组是喊一片的门牌,喊人的嗓子是信号。

用户面的用法,前置卷《信号》一章教全了:产生、挂着、送到三拍,默认、忽略、自装句柄三种处置您都学过,kill 的 pid 怎么填,全教过了,咱们本章只一句领走。教科书层看的是另一头,这些词在内核里怎么兑现。地界咱们顺手划一处:信号量与信号,您看名字里都有信号两个字,其实两家无涉,数货的归 4.2 与 4.3,传话的也就归本章。

本章的活,咱们数下来还是三样。头一样是立地基:号表与集合,帧在咱们手里从十二槽长到十六槽,发送与投递的两段路修通。再一样是装门:定制句柄怎么改帧、怎么靠蹦床与 sigreturn 回家,死讯怎么编码,喊一片的门牌怎么立,停与醒怎么兑现。末一样是咱们对清:四笔诚实边界,咱们一笔一笔如实交代,那是本章的正戏,也就算不得脚注了。

量法还是老的样子,咱们挨条交代。码打的头,实况锚是 r34_compile_self 的终态克隆。信号的机件在正文那一卷之后又长了几笔,咱们数下来是投递让出红区、动作记录长到四词、返回槽按旗选路,教科书层以终态的正身说话,当年的旧面貌只在演进叙事里出现,依据是正文卷的记载。屏的事,咱们也照实说,本章没有要印的屏,sigdemo 的两段屏正文《验收:喊得应的机器》一篇印过,您回着看,test_signal 的案子引名不引屏。书的事,教科书层头一回引的就是 TLPI《Linux/UNIX 系统编程手册》,五段书证是随各节走的,原话都是整句摘的、页号也都写明。xv6 只动 4.4 引过的第 9 章 88 页,同页添的也就一句。

> **九号喊给一个正在跑的任务,发送的那一拍,它多半正在 CPU 上干自己的活。您想:内核为什么不顺手当场把句柄跑了,非要等回程?**
>
> 答案是咱们手里没有现场。跑句柄要在收信人的地址空间里、用它的栈,那一刻 CPU 上坐的是别人。收信人完整的用户现场只存在一个地方,就是它进内核时压下的帧。所以咱们只有一条正路走,发送的人只留记号,等收信人自己回用户态的前一刻再拿着帧办。回程窗口是唯一拿得到完整现场的时机。

## 号表:二十二个名字,两个例外

号表咱们头一个立。一号到二十二号的名册,照的是 Linux x86_64 的原样:九号管杀,十一号管踩了不该踩的内存,十四号管的是闹钟,十七号是孩子的死讯,十八号到二十二号住的是停与醒和终端那伙号。正文的原话:咱们一个字都不能自创。为什么原样照录,正文交代过理由了,将来装库跑别人的程序,人家编译好的二进制认的就是这套约定。

集合咱们不另造轮子。SigSet 是 base 家位词件的别名,底子是一个 64 位的无符号长整型,第 n 位喊的是 n 加一号,装二十二号是绰绰有余的。正文里是专门记过一笔的,这是用户世界第一条通向 base 的依赖边,除此之外再没有第二条了。任务身上那座信号的小世界(signals.hpp:59 一带)装的是三样:一张 22 格的动作表,再有的就是屏蔽集与待办集。待办集咱们配上白话:喊到谁,就在谁的位上立一记,号到了还没办的就是待办,里头一位一位的叫待办位。三样的旁边住着第四件,一把自旋的小闸 gate,要改待办位的人拿的也就是它,名字您且记下,对清的时候它有正戏。

动作记录的正身,咱们把终态的四词一字不差抄来,signal.hpp 的 :89:

```cpp
struct SigAction {
    unsigned long long handler{};   ///< Handler address, kSignalDefault or kSignalIgnore.
    unsigned long long flags{};     ///< kSaRestart, kSaResethand, or zero.
    unsigned long long restorer{};  ///< User restorer address; delivery uses the kernel trampoline.
    SigSet             mask;        ///< Extra signals held while the handler runs.
};

static_assert(sizeof(SigAction) == 32, "Linux x86_64 kernel sigaction is four words");
static_assert(offsetof(SigAction, flags) == 8);
static_assert(offsetof(SigAction, restorer) == 16);
static_assert(offsetof(SigAction, mask) == 24);
```

记录有它自己的长成史。当年正文里的它是句柄、掩码、旗三词。后来开门迎客那一卷销掉真客人 ash 的段错误,照 musl 认的 x86_64 词序重排成四词,restorer 的格子从那天起就在。再往后返回槽按旗选了路,那笔欠的活才还上,演进的正戏在改写帧一节演。词义您过一遍:句柄词零是默认,一的话就是蒸发,别的任何数都是用户态句柄的地址。掩码是句柄跑的当口额外屏蔽的一伙。旗里头住的是 RESTART、RESSETHAND、RESTORER 三面,RESTORER 的值是 0x04000000,RESTART 咱们收词不收机制,正文交过底了,重跑的家什是没有的,这笔也画在了诚实边界。

整张表里管杀的九号、管停的十九号,是仅有的两个例外。它们是装不上句柄的,也进不了掩码。问答的两个函数 SignalCatchable 与 SignalBlockable,真身在 signals.cpp 的 :154。对谁都答的是同一句,答的都是不行。正文的道理讲得直白,原话整句摘:一个跑飞的任务头一件事就是给九号装上自己的句柄,从此谁也杀不了它。掩码那边换的只是演法,同一出戏照样也就唱得成了。谁也碰不得的两个号,是咱们手里最后的家伙。

掩码操作的词里带着九号十九号怎么办?进门前静默剥掉再存(sys_signal.cpp:38 的 strip_uncatchable),Linux 也是这么办的。咱们把 TLPI 书页 392 的原话摘来:

- “This is the sure kill signal. It can’t be blocked, ignored, or caught by a handler, and thus always terminates a process.”

九号在书里的名分,与咱们给它的地位,一句话对上了。

用户态使唤这套词汇的号开张两个,您记号位:rt_sigaction 认的是 13,rt_sigprocmask 认的是 14。字头那截 rt_ 的来历正文交代过,Linux 当年给信号机制换血留下的字头,借的只是名字和号位,与实时不实时是没有关系的。装句柄的那一号,第四参坐在帧的 r10 槽里,报的是集合的字节数,报不对的话答的是 EINVAL。递进来的指针过 uaccess 的门,越界的答 EFAULT。句柄词要待的地方是用户半区之内,越界的当场回 EINVAL。装的时候不查句柄那页映没映射,这个口子正文里是留过话的:真跑不到页的话,是缺页进门的事,错在调用者的身上。

## 帧长全:十二槽长到十六槽

您在 2.3 的柜台里读过的帧,印的是当年的旧印:十二槽,96 字节的身子,rbp 打的头,参是汇编里搬的,InvokeSyscall 收号加的是三个词。这里咱们特意对齐一句:那印的是当年的形状,长全的正戏在本章,机件长全的原委正是信号。

为什么非长全不可。信号要接手的是整个执行现场:停下手上的用户代码,转头办别的事,办完了再从断点接上。接手落笔的地方是回用户态的现场,现场指的就是帧。您会问中断帧不行吗,不行的,咱们的中断帧是五个字段的身子,住着的是 rip、cs、rflags、rsp、ss,通用寄存器是没有位置的,想改写都找不到落笔的地方。

正路是只有一条的,把 syscall 帧缺的四格补上。咱们把入口汇编新的头四拍抄来,syscall.S 的 :8:

```asm
    pushq %r15
    pushq %r14
    pushq %r13
    pushq %r12
```

打头的是新四拍,r15 到 r12 是倒着压进去的,r12 住的是 96,r13 住的是 104,r14 住的是 112,r15 住的是 120,底下的十二拍是一拍没动。十二槽长成的是十六槽,96 字节长成的是 128 字节。布局是有断言把守的,syscall.hpp:385 一带有四条:rcx 的位置在 8,rax 的在 24,rbx 的在 80,r12 的在 96。帧从此是任务在内核期间的整套用户寄存器档,您要读任务的现场,读它就是了。银行也就跟着关门了:当年 fork 的帧缺着四格,在 per-CPU 的块里开过一个小银行,入口汇编每次顺手白存的就是四格。帧全了,银行缩回了四格,fork 取孩子的 r12 到 r15,直接从父进程的帧里读,当年每次 syscall 白存四个 mov 的日子,结清了。

真正改的是办事人的脸,您接着看。入口的一句 movq %rsp, %rdi 把整张帧递了进去,Handler 的脸统一成吃帧:号住的是 rax 槽,参数散在 rdi 往后的槽里,五参六参是自己伸手取的,正文的说法是门已经在帧里开好了。整个系统调用面三十八处签名跟着换了装,这是正文卷的记载。写帧的差事收归两处,exec 的换世界,sigreturn 的回现场。分派对其余的 Handler 承诺只读。

## 发送:三关,待办上立一记

一个信号从生到办走的路是两段:发送占的是头一段,投递占的是第二段。发送干的是把号落在目标身上的活,投递是目标自己把事办了。为什么分两段,正文的原话照录:喊人的和办事的几乎永远不是同一个人。甲给乙发信号的那一刻,乙多半正在 CPU 上跑着别的活,咱们总不能让甲替乙把句柄跑了。

发送的正主 SendSignal,咱们把带闸的那一截抄来,signals.cpp 的 :213:

```cpp
    SigAction action{};
    {
        const arch::IrqGuard kIrq;
        const auto           kGate = target.signals.gate.guard();
        action                     = target.signals.actions[number - 1];
        if (action.handler == kSignalIgnore) {
            return true;
        }
        if (number == cinux::syscall::kSigCont) {
            target.signals.pending = target.signals.pending & ~stop_class_mask();
        }
        target.signals.pending = target.signals.pending | bit_for(number);
    }
```

三关的口径,正文立了口诀,原话咱们照录:除了号不合法,发送永远是成功的。号出了一号到二十二号的地界,答的是不行,这是全函数唯一的拒绝。目标已经是僵尸或死透了,答是照收的,死人是收不到信的,发信的人却没犯错。动作表里装的是蒸发,当场就丢弃了,是连待办集的门都不进的。头一段路是没有失败这个说法的,成败的裁判,归的是投递那一边。

闸里那几行您再认一遍:读的是动作,查的是蒸发,继续号进闸清的是停类四位(19 到 22),末了置的是待办位,一口气在 IrqGuard 配 gate 的护下办完。为什么改一个位也要进闸,咱们挂个名字,到诚实边界的时候对清。尾巴上的事还有三笔,继续或杀落在停走的人头上当场 resume,默认停落在排队的人头上当场 withdraw,那是停与醒在发送侧的差事,正戏是留在后面的。

继承的章程咱们顺带定下:fork 把动作表和屏蔽集整个抄给孩子,待办集是不抄的,孩子不背父亲没办完的事。exec 的三样全回出厂,真身是 signals.cpp:182 的 SignalState::reset,新程序有新的章程。有一处细节是码里写着的,重置的时候 gate 自己是活着不重置的,闸不是该归零的家当。

## 投递:回程一问,挑最小号

投递的窗口,咱们画在 syscall 的回程上。InvokeSyscall 把答案写回帧的 rax 槽之后,多问的一句在 syscall_dispatch.cpp 的 :285:

```cpp
    const long long kResult = kHandlers[kNumber](frame);
    frame.rax               = static_cast<unsigned long long>(kResult);
    if (cinux::proc::DeliverPendingSignals(frame)) {
        return static_cast<long long>(frame.rax);
    }
    return kResult;
```

这一问是全库唯一的生产调用点:投递是只在回程发生的,别处是谁也不调它的。您看窗口挑得刁不刁?TLPI 书页 388 的原话正好拿来对读,咱们摘来:

- “A signal is said to be generated by some event. Once generated, a signal is later delivered to a process…Between the time it is generated and the time it is delivered, a signal is said to be pending.”

同页的半句咱们也念上:“delivered as soon as it is next scheduled to run”,赶上下一回被调度也就办了。前置卷教过的三拍,产生的学名是 generated,挂着的学名是 pending,送到的学名是 delivered。咱们的机器没有进程级的调度前夜,咱们的兑现时刻更具体,回程的那一问。

进门头一件事算 lowest_runnable:待办集抠掉的是屏蔽集,剩下的才是今天能办的,能办的里面挑号最小的。低号在前的口味是 POSIX 立下的,咱们照办。取号和清位是住在同一把闸里的,咱们把那一截抄来,signals.cpp 的 :246:

```cpp
        int       number = 0;
        SigAction action{};
        {
            const arch::IrqGuard kIrq;
            const auto           kGate = kSelf->signals.gate.guard();
            number                     = lowest_runnable(kSelf->signals);
            if (number != 0) {
                action                 = kSelf->signals.actions[number - 1];
                kSelf->signals.pending = kSelf->signals.pending & ~bit_for(number);
                if ((action.flags & cinux::syscall::kSaResethand) != 0) {
                    kSelf->signals.actions[number - 1] = SigAction{};
                }
            }
        }
```

循环的走法咱们走一遍:取到零的话就散伙。取到的是号,位进闸就清掉了,动作是抄一份出来的。动作走的是蒸发,白捡的是一拍,接着挑的是下一个。动作走的是默认,分岔按的是处置表,下场四种:处置杀的 die_by_signal 带着号当场退场。处置停的,清了位自己停。处置蒸发的与照旧跑的,路走的是同一条,清了位接着走。RESSETHAND 的旗立着,送完这一次动作整个回了出厂,就在闸里一并办了。

动作词是句柄地址的话,走的就是定制路:改帧的是 frame_handler_entry,改得成的话,投递就把句柄的掩码并进屏蔽集。改不成的,处死走的还是十一号,栈浅得摆不下投递要摆的东西,本来也就是个将死的任务。正文的原话里有一条纪律:一句回程最多送一个定制句柄,送完了就散,ring3 认的就是这个形状,堆着送会把用户栈摆成什么样,咱们谁心里都没数。TLPI 书页 412 替咱们的待办集作过保,咱们把原话摘来:

- `The set of pending signals is only a mask; it indicates whether or not a signal has occurred, but not how many times it has occurred…later delivered, just once.`

位集报的只是有没有,不报的是几回,同一个号连发了三发,并成的是一个位,送的也就是一回。Linux 的 rt 信号为此另立了排队,咱们一句带过,也就不展开了。

## 改写帧与回家的门

定制句柄的投递,是整套机制里最像变戏法的一段:任务明明要回自己的用户代码,咱们让它落在句柄上,办完了一字不差地回原来的断点。秘密是全在栈上的,咱们一段一段看。红区这个术语配上白话:ABI 划给叶函数的一块自留地,函数是不再挪栈顶的,把最多 128 字节的家当直接暂存在栈顶底下,调用者是不看那块地方的。投递是要往用户栈下摆东西的,摆的位置贴着栈顶,就把人家暂存的家当压住了。

这段是有一笔演进史的,咱们摆开。当年正文《改写帧与回家的门》一篇印的投递,最低处摆的是一个槽,写着归乡上下文的地址,往上的才是蹦床槽和上下文本体,是没给红区留地方的。后来的真客人进了门,ash 的段错误把这笔旧事翻了出来,销案的那一阵投递搬了家:指针槽删了,栈顶往下让出的是 128 字节红区,再留的是 15 字节对齐余量,上下文和返回槽是摆在更底下的。咱们记下 kRedZoneBytes 与 kDeliveryBytes 两个名字,住的地方是 signals.cpp:31。栈区间够不够摆的判断,如今问的是登记册,vmas 的 stack_contains(signals.cpp:46),登记册说了算。

摆的是两样,咱们一样一样数。头一样是 144 字节 18 个词的归乡上下文 SigReturnContext,白话说的就是一幅回家图:被中断的那行代码怎么回去,rip 回哪、栈在哪、当时的 rax 是多少,全都写在这幅图里了。词的构成是帧里十六个词按帧自己的次序镜像一份,外加的是投递以前的旧屏蔽字,末了补的一个零词凑 16 字节对齐,144 这个数是有断言把守的,咱们数下来一个不多。再一样说的是返回槽,8 字节的大小,住在上下文的底下。

帧是只改四个词的。咱们把选路与改写那一截抄来,signals.cpp 的 :138:

```cpp
    const unsigned long long kReturnAddress =
        (act.flags & cinux::syscall::kSaRestorer) != 0 ? act.restorer : SignalTrampolineAddress();
    if (!cinux::syscall::uaccess::CopyToUser(kContext, &image, sizeof(image)) ||
        !cinux::syscall::uaccess::CopyToUser(kReturnSlot, &kReturnAddress,
                                             sizeof(kReturnAddress))) {
        return false;
    }
    frame.user_rsp = kReturnSlot;
    frame.rcx      = act.handler;
    frame.rdi      = static_cast<unsigned long long>(number);
    frame.rax      = 0;
```

四个词咱们一个一个认。user_rsp 是落在返回槽上的。rcx 换成的是句柄地址,syscall 进门的那一拍硬件把回路记在 rcx,sysretq 出门照的还是它,一进一出认的是同一个寄存器,换进去的是句柄地址,出了内核的门落到的就是句柄。rdi 带的是信号号,C 的第一个参数。rax 清了零,还它一张干净的脸。其余十二个词是一动不动的,栈上的镜像里也各存一份。返回槽的位置也讲究,栈顶是除十六余八的,正文的原话照录:刚被 call 完的函数,进门那一刻的栈顶就是除十六余八。句柄一进门看到的,就是一次普通调用刚发生完的栈形。

句柄跑完了,ret 一弹落在返回槽写的地址上。地址给谁,旗说了算:立了 kSaRestorer 的话,落的就是客人指定的 restorer,没立的话,落的是内核蹦床页。字段自己说了不算,restorer 格里写了字而旗没立,是不算数的,长凳的案里记着的就是它。蹦床是咱们起的名目:独立的一页,给的是可读可执行,写是永不许的,顶在匿名映射天花板的上一页,exec 出厂就装上了,fork 的孩子靠共享白得。页里装的一共是七个字节,signal_trampoline.cpp 的 :29 一行:

```cpp
    constexpr unsigned char kStub[] = {0xB8, 0x0F, 0x00, 0x00, 0x00, 0x0F, 0x05};
```

头一段的 `B8 0F 00 00 00` 是 `mov eax, 15`,收尾的 `0F 05` 是 `syscall`,句柄的 ret 就这样变成一次系统调用,落的正是十五号 rt_sigreturn。为什么住独立页,正文是备着两笔旧话的。当年头一遍的蹦床是摆在用户栈上的两字节机器码,能跑靠的是栈页可执行的便宜,开执行限制那天那两字节当场成了违禁品,被迫搬了家。当年的定制投递走的是中断路,因为帧存不全的是 r12 到 r15,只好靠专门立的陷阱门收全帧。今天的帧是十六词俱全的,那个前提整个没了,syscall 的回程才是正路。那一篇的收话咱们照录:信号帧的形状,从来是由谁存着完整现场决定的。

sigreturn 进了门就按帧找人,咱们把走法说全。此刻帧里的用户栈顶,正是句柄 ret 之后剩下的那个上下文地址,当年的形状从栈上的槽里解引用去找,后来直接读的就是 user_rsp,少绕了一扣。头里排着的是两道护栏:上下文要落在登记的栈窗之内,还要的是 16 字节对齐,答不上来的按十一号处死,一段跑偏的栈就是任务自己的死法,内核是不替它圆的。护栏过了,十六词也就从上下文镜像回了帧,旧屏蔽字归了位,被中断的那行代码连着它当时的 rax,一字不少地回了家。

rax 咱们单独再说一遍,在它身上是踩过一脚的。分派对每一笔的 syscall 都把返回值写回 rax 槽,sigreturn 若是按寻常答零的话,分派紧接着把零写进了帧里,刚恢复出来的 rax 就被冲没了。修好的形状,sigreturn 答的是它刚恢复出来的那个 rax,出处的行号在 sys_signal.cpp:183。正文的原话是:写回写进去的,与上下文里躺着的,是同一句的真话,一个数都丢不了。

## 死讯:一纸收据,两种死法

信号的另一头,是内核自己的事件说这门语言,配对落地的有两对。头一对是缺页配十一号:裁决者不受理的缺页,看是谁惹的,来自用户的,是不再劳驾全机转储的,惹祸的任务以十一号的身份自己退场。正文的原话整句摘:从前是一个程序写飞了指针,全机器陪着它一起停了摆,现在还是一个程序写飞了指针,死的是它自己,父进程收得到的死因,机器照样跑它的活。内核自己惹的缺页,老章程是一字不动的。咱们跟着补一句诚实的边界:十一号的句柄装得上,可缺页不走投递的回程,句柄接住了它之后,要不要回出错的那一行重跑,这套语义是没验过的,门是留着的,路是没修的。

第二对说的是退场配十七号。exit 把任务安置成僵尸之后给父亲发的就是十七号,次序咱们点出来:置僵尸的一步在前,发信号的一步随后,末了的叫醒排在最后。三步走的就是生产排在消费前头,咱们在 scheduler.cpp:336 一带指给您。十七号是默认蒸发的,装默认动作的父亲日子照旧,wait 的唤醒另走一路。想边干活边听死讯的父亲从此有路,死讯是落在待办集上的,回程自然就办掉了。

死法是要写进收据的,收据指的就是退出词。咱们把 exit 的码抄来,sys_exit.cpp 的 :10 一行:

```cpp
    proc::Scheduler::self().exit_current(static_cast<long long>((frame.rdi & 0xFFULL) << 8ULL));
```

自愿退场的,码是只取低八位的,左移八位住进的是高八位,低字节也就永远是零了。死于信号的,退出词装的就是信号号,落的正是低字节。正文的原话照录:一个三十二位的收据,两种死法各说各的,谁也冒充不了谁。会读的人当场就能对上号:shell 认得的是两种报法,低字节非零的话报 killed by signal 加号,为零的报 exited with 码,sigdemo 那一屏里两种正读各露了一次脸,您回正文《验收:喊得应的机器》那一篇,那里教的念三遍,第三遍读的就是它。

孤儿的事,咱们有一笔演进史要如实交代。当年正文是明说的,孤儿是不送人收养的,孩子就地散了伙,因为咱们的收养人还不存在。如今的码里,收养人上了岗。detach_offspring 头一个问的是 find_adopter,真身在 scheduler.cpp 的 :398。问得到的话,孩子的父亲就改指收养人。已经是僵尸的孩子,补发给收养人的是一声十七号,叫醒的也是他。来路咱们如实说:这笔是正文卷未及记载的,机器给 glibc 换血那一阵它悄悄上的岗,为什么收养,咱们不编,码在了就是在了。

## 门牌:喊一片的地址

嗓子有了,喊一片的话还得有地址。Unix 的答案是进程组:一伙任务共挂的是一块门牌 pgid,门牌的上面还有一层院子 sid,两个字段都住在 Task 的身上。出身正文是定过的,开机的骨干任务和 shell 是各自成组自成会话的,fork 出来的孩子抄父亲的。咱们对读 TLPI 书页 701,原话摘了来:

- “Each process has a numeric process group ID…A new process inherits its parent’s process group ID.”

老家的常例,咱们对读过,书与码说的是同一句。

换门牌走的是正门,咱们跟着 setpgid(号位 109)过两道问:动谁的话自己随时都可以,别人的话必须是我同一会话的亲生孩子。进哪个组的话,目标自己的 pid 是自立的新门牌,别的值必须是本院子里已立着的门牌。回话分的是三档:人找不着的话答 ESRCH,不是自家的,答的是 EPERM,门牌查无此组的答 EINVAL。setsid(112)是简单些的,当了组长的拒,不然就自立了门户。

kill 的号位是 62,它的 pid 参数有四种读法,咱们叫四读:正数报的是号,喊的是一个人。零喊的是本组,连我自己在内。负一是除我之外的全机。再小的负数走的是组广播,喊门牌取负之后的那一组。还有的是个零号信号,只问的是人还在不在,东西是一个也不发的,咱们叫探针。四读落进的是同一个 HandleKill,正数支走的是如今的形状,sys_kill.cpp 的 :27:

```cpp
    if (kNamedPid > 0) {
        long long result = -kEsrch;
        scheduler.with_task(static_cast<unsigned long long>(kNamedPid), [&](proc::Task& target) {
            result = (kNumber == 0 || proc::SendSignal(target, kNumber)) ? 0 : -kEinval;
        });
        return result;
    }
```

正数支是有一笔演进的,您对着正文当年的印子看:那时印的是自己 find_by_pid,后来的形状换成的是 with_task 守卫查找,拿着调度器的锁在册子上问人,只走访的是在册坐着的任务。真正承重的是括号里 kNumber == 0 那半句:号是零的话,压根是不调 SendSignal 的,人找着了答零走人。探针只问不发的章程,落到码里的就是它。

后头的三读合走的是一条,由 for_each_task 扫全机的名册广播,听着的记进 heard,一个都没喊着的答 ESRCH,喊人没喊着是不算错的,咱们总得给话一个交代。您再看 wait 这边,它也学会了听门牌,收据上的 pid 同样四读挑人,外加一面 WNOHANG 旗(sys_wait.cpp:17 的位置,住在 rdx 的最低一位):有匹配的孩子活着还没退场的,答的是零,人是不停泊的。正文的原话:这把钥匙开的是轮询的门。一个想看着孩子又不想睡死的父亲,从此有了正路的问法。

前台的事咱们只指门。终端把按键交给的那一伙就叫前台组,咱们把 TLPI 书页 708 的原话摘来:

- “The controlling terminal maintains the notion of a foreground process group.”

咱们的终端那边如今真立着一格前台门牌,行规程问出的是一声信号,SendToGroup 喊给的就是前台组(console_node.cpp 里那一笔)。^C 那个字节怎么从键盘走进这套门牌,是第 5 部的戏,咱们指个门就收。

## 停与醒:第五种活法

三件缺里最难的一件:喊停了,它凭什么真的停。停走的不是死、也不是睡:死了的话尸身等收,睡了的话还挂在等待表上等叫。停是第五种的活法,状态名册从五档长到了六档。从前的五档:就绪、在跑、阻塞、僵尸、死透。新档的名字叫 stopped,咱们叫停走。正文的原话是:人是不动了,可接下去的动作,咱们随时都接得上。

光有状态是不够的,停走的人得从所有能被选中的地方消失,而能被选中的地方握在调度类手里。SchedulingClass 添了一手纯虚的 remove,队列是类自家的家当,人排第几位、抽走后怎么补位,知道的只有类自己。这是正文讲的道理,咱们照着办进了码里。

调度器配的是三件兵器,咱们一件一件过。stop_current 管的是自己停,进门的是两道查:头一道问的是在不在任务里,第二道对自旋的登记簿,停走的人抱着内核栈换人,攥着自旋锁没放的话,等锁的人就等成了没有头。状态改成了停走之后,切栈走的是与睡觉共用的道(scheduler.cpp:519)。resume 管的是唤醒,查的确实是停走,改回的是就绪,塞进类的队列。withdraw 管的是就地摘,只对还在就绪队里排着的生效,摘完顺手把状态也改成了停走。终态的 stop_current 比正文卷印的那版又收了一道,置停走的那一拍裹进了调度队列的锁里,睡觉的那套口径当年也这么补齐过,来路咱们在 4.4 讲过。

要紧的分野在时机,咱们把线画下来:同一件停的事,发送办的是一半,投递办的是另一半。落在排队的人头上,回程什么时候来没有保证,默认停类的信号在发送那一拍就 withdraw,人就地出了队。落在跑着的人头上,回程是近在眼前的,信号进的是待办,回程投递时清了位自己停,syscall 把该答的话照常答完了。落在停走的人头上的,单独说:停走的人永不被调度,永远等不来自己的投递回程,所以继续和杀在发送那一拍由发信人亲手 resume。杀为什么也亲手,正文的原话:它得醒来走上自己的死路,死讯的编码才进得了退出词,父亲的 wait 才收得到。长凳上另有的一案配的就是这句话,`stop and cont: kill wakes the halted task, a plain term stays parked`,九号是叫得醒的,十五号是叫不醒的,也就只在待办集上多立了一记。

继续这一号是还有个前置的:发送时把 19 到 22 的停类四号清干净再置自己的位(stop_class_mask 的真身,住在 signals.cpp 的 :72)。不清的话,醒来转脸又吃一记停的招呼,继续也就不成其为继续了。长凳有一案替咱们记着这一课。案名记的是 `stop and cont: a continue sweeps the pending stop-class bits`,说的就是把停类的待办位扫干净。

停走的人醒在哪?继续来了,resume 把人放回了队列,轮到它上 CPU 的那天,切换器把照片装了回去,那一跳落回的是恢复点。正文的原话咱们整句摘来:对 C++ 的世界来说,stop_current 像的是一次普通的函数调用,调了进去,过了很久,正常地返回了。被停的那笔 syscall 没有被打断半个字,这是停走和睡眠、和死都不一样的地方。末了一笔也如实登记了。跨类的次序,正文的那一卷就没动过,正身的原话是今天的咱们只学会了摘人,排位是没有学会的。

## 诚实边界:四笔对清

欠的活对清是咱们本章的正戏之一。四笔咱们一笔一笔来,4.4 的桥,也在头一笔里接上了。

头一笔是睡着的任务追不上,今天的正身仍是这句:睡在等待表上的任务,比如守着 wait 的父亲,信号是落在待办集上的,可它不回程的话,信号也就追不上了,得等它自己醒了办完事走回程的那一步。这就是 4.4 桥上问的拍醒之后怎么回话。咱们把回答分两屋。

第一屋管等待圈里的睡眠,答的是 EINTR。正文《开门迎客》的那一卷《亲手一玩,三件补齐》一篇的原话照录:听得懂喊声那一卷欠下的信号打断睡眠,在 ppoll 的门上还上了一角,别处的睡眠门口还是老的样子,咱们如实记着,不把一角说成了一片。那一角后来扩成了一排门。ppoll 的等待圈里,每个来回自查待办(sys_ppoll.cpp:188 一带的 HasPendingSignal),有的话就答 Eintr。read、sendfile、nanosleep、socket 的等待圈,终态里也都挂了同一问。ppoll 的 sigmask 参数,当年正文说的是收下不验。终态也不是了。真换的话,出门也真的恢复,干这两件事的就是 armed 与 restore_blocked。等待圈回话的那一截,咱们抄来,sys_ppoll.cpp 的 :195:

```cpp
            if (kDue) {
                return static_cast<long long>(ready);
            }
            if (kSignal) {
                return -kEintr;
            }
            return 0;
        }
        proc::Scheduler::self().yield();
```

第二屋管的是等待表上的真睡眠,还是老的样子。等待圈是轮询的睡法,yield 出去了又回来,每个来回有一次自查的机会。等待表是真睡的,挂上队列就切了栈,中间是没有回程可言的。所以一角扩成了一排门,等待表却是纹丝没动的,咱们把地界说清:不冒充全好。SA_RESTART 的旗,词是照收的,重跑机制是没有的,正文当年交的底今天还押着。

第二笔说的是纯计算循环杀不掉。这笔的出身咱们交代清:正文没说过,是教科书层对着码看出来的一笔,不冒充正文的话。投递全库唯一的生产调用点是 InvokeSyscall 尾上那一问。一个不进系统调用的用户循环,九号喊过去、落的只是待办,是永不投递的。任务是会被时钟抢下 CPU 的,可每一拍抢回来的还是那段循环,死讯的编码进不了退出词,父亲是收不到的,机器是陪着它空转的。它自己碰一次系统调用的话,哪怕写的是一个字节,回程那一问就把欠的活结了。

第三笔说的是待办位的共同协议。单核上发送与投递是不会同时改一个待办位的,双核上就说不准了。咱们把现场摆出来:一颗核忙的是给目标置位,目标自己恰在另一颗核上的回程里清位,两头都是读了改、改了写,后写的盖掉早写的,那一发信号就没了,发送的人手里还攥着成功。正文《请第二颗脑子上线》的那一卷合卷时把这笔挂在了明处,原话咱们整句摘下:

- “信号位的共同协议、共享文件表的竞争这些边界,验收里逐条地写着。”

后来正文把这笔收掉的是《开闸,与开闸后的镜子》一篇,它与《还一笔旧债》是同卷的,原话摘了两处。头一处咱们顺手收掉了名单上挂着的信号位共同协议那一笔。第二处说的就是闸窗绝不沾调度器的边。终态的形状您已经见过两段了:发送侧的 IrqGuard 配上 gate,投递侧取号清位进的是同一把闸,exec 的重置也进门。闸外只剩一笔自家回程的写,投递尾上并句柄掩码的那一笔,写的是 blocked,待办位是不碰的,只有任务自己的回程会走到。按 RESSETHAND 清动作的那一笔,正文那一卷记它的时候还裸在闸外,后来重组了投递,与取号清位一起收进了闸,投递一节您已经见过它进闸的样子。这把 gate 是 base 那枚零系统耦合的极小互斥件传下来的,正文《同步层的旧债》一篇立的。它拿的时候配的是获取,放的时候配的是释放,次序为什么非这么配不可,深一层的道理归《内存序与缓存一致性》,咱们交棒点到为止。

第四笔说的是 restorer 的旧债。动作记录长到四词的那年,restorer 的格子就在了,咱们收下了客人的字,却从来没有人读过它:投递一律写的是内核蹦床页,客人明明说了收尾走谁家的门,咱们不认。正文《还一笔旧债》一篇的原话是:接口收了话,该办的事一件没办,这笔欠的活。还法是小得可怜的,就是返回槽按旗选路的那一问,您在改写帧一节已经看过。长凳的两案记的就是它。`signal delivery: without the restorer flag the kernel trampoline keeps the slot`,旗没立的话,格里有字也是不算的。`signal syscall: musl's four-word action preserves flags, restorer and mask`,四词是一词不丢的。实弹的两条路也走过了:自家的 sigcatch 不设 restorer,自己给自己发了一号,handler 记到了数。musl 的客人 trap 挂一号,收尾走的是自家 restorer,shell 活得好好的。

## 实况:二十九案,案名对号

长凳上信号这件家什如今攒下了二十九案,咱们引名不引屏,案名是原文照录的,您拿名字对科目。表与发送的底座:`signal tables: the catchable set excludes kill, stop and the outside`,同一底座的另一案 `signal tables: the blockable set answers the same two exceptions`,两个例外是各记一案的。`signal send: bad numbers refuse and zombies shrug`,同一出的另一案 `signal send: an ignored signal drops, anything else parks a bit`,三关各答各的话。

帧与投递的那几案,咱们看下来最见功夫。`signal delivery: a custom handler rewrites the frame onto its stack`,改写的四个词逐个对。`signal delivery: handler return restores registers, mask and the interrupted red zone`,回家的那幅图连红区一起对,红区 128 字节涂了记号,句柄跑了一个来回,记号是一个也不许丢的。`signal delivery: SIGCHLD returns through a stack slid below the old window`,投递是把栈挪到旧窗口底下再回家的,专防一种想当然的摆法。`signal delivery: a delivery that cannot fit the stack window kills`,同一题的另一道 `signal delivery: the registered guard rejects SIGCHLD with SIGSEGV`,两道死法都是有案可查的。

门牌与停醒的案子咱们接着点,案名各自记的是各自的话。`signal scheduler: guarded lookup visits seated tasks and nobody else`,说的是守卫查找。`signal pairs: an exit marks the parent's pending chld`,记的是死讯落位。`stop and cont: a queued task stands stopped the moment stop lands`,办的是发送侧就地摘。`stop and cont: a continue sweeps the pending stop-class bits`,讲的是前置清位。`stop delivery: the halting stop consumes itself and halts mid-delivery`,说的是投递侧自己停。

验证范围的实话,咱们接着说。正文当年是交过底的,定制句柄的这一路,验的是宿主长凳上的断言,栈是宿主里 mmap 出来的假栈,真客人登门的日子在后头。后来那日子来了,sigcatch 与 musl 的 trap 两条实弹路都把门真的走过了一遍,当年的期票兑了,咱们替读者记下了这桩兑现。sigdemo 的两段屏不再重印,您回正文《验收:喊得应的机器》那一篇,头一遍看的是名字和门牌,第二遍看的是停与醒,第三遍看的是组杀和死讯,念三遍的方法还给您留着。

## 对照:同一件事,别的机器怎么做

xv6 那头是没有信号这门活的。4.4 在书页 88 引过被信号拍醒回 EINTR 的那句,本章开桥点的就是它。同页咱们再添一句新的:

- “Xv6 doesn’t support signals and this complexity doesn’t arise.”

它家是没有信号的,复杂度是压根不会出现的,同类的事,办的是 sleep 与 wakeup。页码咱们如实记:第 9 章 88 页,4.4 引过的页,本章只添同页的一句,别的页没动。

Linux 那头这门亲是实打实的:号表、rt_ 字头、四词动作记录、kSaRestorer 旗,咱们全是照它的内核 ABI 抄的,正文里照它家门牌开的门。收尾那一段两家走了两条路:通行的事实是,x86_64 的 Linux 内核要求 libc 这一类的客人在装句柄时递上自家的 restorer,内核不替客人备收尾的页。咱们的内核两头都开,自家人走的是内核蹦床页,立了旗的客人走自家的门。咱们认亲归认亲,深浅是不比的,它家源码咱们没翻过。

## 练一练

三道题留给您:一道推演的,一道回望的,一道读册的。

**题一咱们来推演。** gate 撤了,待办位回的是裸读改写。一颗核在给目标置的是九号的位,目标自己恰在另一颗核上的回程里,投递正清着十号的位。您推一遍:哪一发会丢,丢在了哪一拍,发送的人拿到的是什么。

**题二咱们来回望。** 开篇的三件缺:喊不停、死讯追不上、喊一片没门牌。您说说各归哪一段路办的。您再答一问:头一件在咱们的机器上为什么只兑了一半,缺的那一半卡在哪个窗口上。

**题三咱们来读册。** 回到 TLPI 书页 412 的那句原文。您答:同一个号连发三发的话,投递送几回?挡住再解挡的话,又送几回?您再往深一问:rt 信号为什么非另立排队不可,位集装不下的是什么。

### 参考答案

题一:丢的是九号那一发。两头做的都是读改写:发送读到的是旧集,投递读到的也是旧集,发送把九号位改了进去,投递把自己手里的,没有九号的旧集,写了回去,后写的盖掉早写的,九号无声地没了,发送的人手里还攥着成功。丢的那一拍,在投递写回的那一句上。咱们那把闸把它关死:两头进门,排好了队再改,后写的也就盖不掉早写的了。

题二:咱们按件数,喊不停归投递的默认处置带号死,死讯归十七号的配对加退出词编码,门牌归 kill 的四读与组广播。缺的那一半:投递只办在 syscall 的回程,纯计算循环是没有回程的,九号落的只是待办,任务抢得上 CPU 却是死不成的,直到它自己碰了一次系统调用。窗口就是回程的窗口。

题三:三发并成的是一个位,送的是一回,挡住了再解挡,送的也还是一回,位集是不记次数的。rt 信号要表达的是每一发各自是一件独立的事,一发是一发、各算各的,位集答的只是有或没有,次数与次序它是装不下的,所以 Linux 给它另立了排队。咱们那二十二号信号的位集,脾气也是同款的。
