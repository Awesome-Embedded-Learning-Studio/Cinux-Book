# 03 · 死锁与锁序:一声断言,一张锁序图,两种满

4.2 收卷留了话:门闩毕业了,可锁自己的一生一个字没管,锁生要登记,死要销册,那本册子的容量是六十四个身份。双核实弹里一声容量断言炸响,满员了,第一个进不去门的,是管道的加写者路径,您带着断言过去。您进门了,咱们补一笔口径:那一声不是宿主案册里的产物,是机内实弹炸的,正文《锁的生卒》那篇记的全程。断言自己当时还坏着嘴,喊了半天没喊出重点。所以开门的次序是,修证人的嘴,认病,办案。

本章的活,咱们数下来还是三样。头一样,修嘴认病:断言的嘴怎么修,死锁是什么,谁也不放,谁也等不到。药方落在全机的次序上,一张锁序图替机器盯着。再一样,添两件新家什:名号与尸检,出事头一步亮册子。私册与公图,链各记各的,图全机一张。末一样,办两场满员的案:一场满的是骨灰,假满,销户能治。一场满的全是活着的锁,真满,病根落在引用那边的欠款上,4.2 讲过的旧案,这里只对一对。

量法还是三条。码,两代对读:旧形状是 r19 的 lockdep.hpp,83 行,lockdep.cpp,109 行,《锁报名号》那篇带出来的单核版。今天的主角是 r26 的 lockdep.hpp,86 行,lockdep.cpp,129 行,实况锚 r26_smp 的正身。配角三件:kernel/lib/assert.cpp,34 行,断言的嘴。kernel/proc/sync.cpp,263 行,4.2 量过,本章只取退役那几段。kernel/init/init_sequence.cpp 里转储的那座桥。屏,两站:头一场 r26_smp,4.2 刚走过,起机面板不重印,本章把 lockdep 那块八案的屏升正席。第二场 r19,对读的旧形状,不另录屏。您要亲手翻,git 里的名字是 r19_lazy_alloc_page。书,xv6 第 7 章,4.1 与 4.2 引过六页,70 已在其中。本章新引的页是 69,在 70 上引的是没引过的句子。原话一律整句摘,页号写明,您对着书核。

> **两把锁各自都是好的,门闩的心脏 4.2 也验过是好的。您想:死锁的病,到底生在哪?**
>
> 病不在哪一把锁上,在两把锁相遇的次序里。每一把都尽职,拿、放、验手、登记,一样不缺。背对背的那一拍谁也没犯规,可谁也走不动了。所以药方落在次序上:给全机的锁排一张座次,谁都照着座次拿。座次这种东西,人守着守着就松,正文《无盘起家》那一卷的原话是,咱们不想拿“代码里没这么写”当保证,想让机器自己盯。盯的是哪一路,那卷也说了:绕得回来的次序,今天不死锁,改天也会。

## 断言的嘴:消息在前,位置在后

案子开审,证人得把话说清。那一声容量断言,头一版喊出来的时候嘴是坏的,正文《锁的生卒》记的:模板函数的实名实姓把单行塞满,真正的原因被挤出了屏幕,断言喊了半天没喊出重点。修法正文一句话,消息的打印在前,位置的打印在后。真身就是这两行,您看,kernel/lib/assert.cpp 的 :27 与 :28:

```cpp
    cinux::print::Println("[panic] %s", k_message);
    cinux::print::Println("[kern] %s:%u in %s", loc.file_name(), loc.line(), loc.function_name());
```

重点喊在前头,名字报在后头,单行塞不下也就塞不下了,重点已经落地。函数后头还有两步::30 把 rbp 抓进栈帧,:31 交给 PanicDump 把调用栈倒出来,嘴好了,栈跟得上,顺着栈就能找到拿锁的路。它只在内核世界当值。宿主世界同名的声明,打印合一行,位置在前消息在后,链接期各选各的脸,这门手艺您在 4.1 的长凳上见过,这里又照了一面。

还有一条纪律写在它的文件头注里:内核世界的 Check 一响就不回头,打完这几行,机器就地停住,不再碰任何状态。现场原样冻在屏上,您后头读到的所有尸检,吃的就是它留下的现成饭。

## 死锁:谁也不放,谁也等不到

嘴修好了,咱们认病。xv6 书页 69 的病例最干净:两段执行流,书里记作 C1 与 C2,各要过 A 与 B 两把锁。C1 拿到了 A,伸手去要 B。B 在 C2 手里。C2 拿到了 B,伸手去要 A。A 在 C1 手里。谁也不放,谁也等不到。书里一句定案,原话整句摘:

> “This situation is called deadlock.”

药方同页,也是一句,摘原话给您:

> “all code paths that hold multiple locks must acquire locks in the same order”

凡是拿多把锁的路径,拿的次序都得是同一条。同页末尾,它把这句抬进了函数的规约。规约配句白话,就是函数对外承诺的事,您照这个记。原话摘:

> “locks are effectively part of each function's specification: callers must invoke functions in a way that causes locks to be acquired in the agreed-on order”

锁实际上是每个函数规约的一部分,调用的人得按约定好的次序把锁拿进来。这句话的分量,对照节再回来称。咱们自己也真死过一回,不是书上的病例。正文《请第二颗脑子上线》那一卷《一个队列,两颗核》记的现场,原话摘:唤醒别人发生在持锁登记的路上,等孩子退场发生在持锁扫描名册的路上,等待的等待一层叠一层,每层的操作都抢锁,结果自己等自己,当场就死锁了。

修法的全本在正文《一个队列,两颗核》,那篇的原话:只有从零到一那一拍才真的抢锁。往下的意思是,嵌套只数层,不层层抢锁,每一层记在按核的计数上,最外层那一把旗包了全场的门。您在 4.2 见过的影子,是按核计数的那一半。嵌套计数的表,4.1 对过,门闩的四层心思不再重讲。这里只记一笔:调度队列那场,单方是同一把旗。书页 69 那场,两把旗背对背。病是同一个,次序的病。

死锁还有一位近亲,4.1 引过的那句次序警句:旗立着,闸开着,一个掐得准的中断进来,也是死锁。同一科病,治法同款,持锁的日子闸就得落下,拿之前也得查一遍。那一页 4.1 花过了,咱们本章不重去。

## 锁序图:不靠自觉,靠机器

药方是排座次,座次靠谁守?开篇问框引过那句,咱们不想拿“代码里没这么写”当保证,想让机器自己盯。盯梢员是正文《无盘起家》的原词,白话说,它替咱们守次序,真名 lockdep,白话是 lock dependency,锁与锁的依赖:谁在谁手里的时候去拿了谁,它记的就是这样的依赖。

它手上的图,咱们全章叫锁序图。名字交代一句:正文《无盘起家》那一卷立它的时候叫座次图,正文《锁的生卒》那篇的段落里又写过顺序图,同一件东西换过名,引原话时保留原名,咱们的话统一叫锁序图。

图上两样东西。顶点是锁的身份,而锁的身份证,就是活锁的地址,这也是正文原话。活锁在这儿说的是活着的锁,与 livelock 撞名这件事正文交代过,不展开。顶点的道理您一听就懂:对象在,地址在。对象没了,身份证成了空号。边是次序:手里已经攥着 A,又去拿 B,画一条 A 指向 B 的边。方向,正文里定死了,新边从手里的锁,指向新拿的锁。查环走的是反向的道理:从新拿的锁出发,顺着边往回走,看回不回得到手里的锁。回得到,把边加上去,图就成了环。正文还有一句压舱的:绕得回来的次序,今天不死锁,改天也会。

两道关就设在拿锁的路上,咱们看真身,lockdep.cpp 的 :49 到 :56:

```cpp
    for (const auto kHeld : held().view()) {
        if (kHeld == index) {
            return Status::kRecursive;
        }
        if (graph_.reaches(index, kHeld)) {
            return Status::kCycle;
        }
    }
```

对手里攥着的每一把,新来的各问一遍。头一问,是不是同一把:是,报 kRecursive,重入。第二问,从新来的出发,可不可达手里的那一把:可达,报 kCycle,环。可达配句白话,顺着边一格格走,走得过去就叫可达,当差的函数叫 reaches。当场 Check,机器响着停,您顺着栈就能把次序揪出来,这三句也是正文原话。两问各报各的案由,诊断分得清:重入是重入,环是环。

两关都过了,才轮到落笔,顺序就在后头几行,您接着看,lockdep.cpp 的 :57 到 :63:

```cpp
    if (locks_.get(index) == nullptr) {
        base::safety::Check(locks_.insert(lock) == index, "lockdep identity slot changed");
    }
    for (const auto kHeld : held().view()) {
        graph_.connect(kHeld, index);
    }
    base::safety::Check(held().push(index), "lockdep held stack lost capacity");
```

身份落格,身份没在册的当场登记。对手里攥着的每一把,各连一条边。末了进链,进不去链的又是一声 Check。咱们把这三步连起来看:查在写的前头,判词不过,一笔都不落。

全册的判词一共六个,lockdep.hpp 的 :44 到 :51,咱们整段摆:

```cpp
    enum class Status : unsigned char {
        kOk,
        kCycle,
        kRecursive,
        kCapacity,
        kNotHeld,
        kOutOfOrder,
    };
```

kOk 是放行,kCycle 与 kRecursive 您刚认得,kCapacity 马上讲到。后两个是出门那侧的:放一把手里没有的锁,报 kNotHeld,册里查无此锁也是这一案。放的不是最里层那一把,报 kOutOfOrder。出门只许弹栈顶,这是正文立过的纪律,中断开关的还原次序,靠这个里外对上。

家当咱们点齐。名册一件,SlotTable,地址住格,常量 kLocks,64,六十四格。这个户口本不是新造的,内核里三处当差,挂载表、文件册、锁名册,正文原话,三种户口,一件家伙。名字一排 names_,与名册同长,下一节讲它。边图一件,DirectedGraph,连边、查可达、摘顶点。手里的链一件,StaticStack,常量 kDepth,16,十六层,拿一把进一格,放一把出一格。名册与链的容量,都刻死在类型上。容量的态度,正文《无盘起家》那一卷也立了原话,宁响不漏:超了的回 kCapacity,Check 当场报,悄悄丢一条边,图的保证就成了纸面上的话。同一门家风,4.1 走过两处岗哨,就绪队列的入队与睡觉的门。这里是第三处,册子的门:宁可响亮地死,不许悄悄地丢。

## 名号与尸检:出事头一步亮册子

名册记的是地址,地址不认人。正文《锁报名号》那篇记的苦,原话摘:串口上响的那一行,报的是一个地址,您拿着地址对源码,翻了好一阵子才对上是谁。药是预登名号:set_name,真身在 sync.cpp 的 :124 到 :128,构造之后、出事之前,把人话的名字交给名册存着。名字跟地址,登记的时候一起来,清的时候也得一起来,这件事到销户那里见。

出了事,亮什么?尸检报告,这个叫法也是正文领来的,倒出来的那页持有链就是报告。次序是救命的那一句,正文原话摘:最能救命的是次序:检查失败,头一步把持有链亮了出来,响是第二步的事。真身两处,咱们挨个看。一处是拿锁路上的安排,sync.cpp 的 :30 到 :33:

```cpp
        const LockOrder::Status kOutcome = order.acquire(lock);
        if (kOutcome != LockOrder::Status::kOk) {
            dump();
        }
```

判词不是 kOk,头一步把册子倒出来,后头两道 Check 才开口。咱们看另一处,倒出来的样子,转储的桥架在 init_sequence.cpp 的 :59 到 :65:

```cpp
            proc::InstallLockdepSink(+[](const char* label, unsigned long long address) {
                if (label != nullptr) {
                    print::Println("[lockdep] held: %s", label);
                } else {
                    print::Println("[lockdep] held: lock@%llx", address);
                }
            });
```

有名字的报名字,没名字的报地址。持有链从最外层到最内层,一行一把,谁套着谁,屏上一目了然。这座桥是个函数指针的座,内核世界装的是串口桥,宿主世界装捕获器,与 2.4 的假 sink 同门的手艺,4.1 认过亲,咱们一句带过。

尸检报告自己也出过案:头一版转储,把名册槽位的指针当成锁的地址报了,宿主测试当场按住,改法是解引用再报。丢人,正文照实记,咱们照实引。

这桩小案顺手立了条家法,两个世界的另一面。同一份声明,两个世界各链各的实现,这门手艺 4.1 的长凳上教过:链接的时候挑走哪份。这里是验收侧,正文原话摘:默认构建里早退的用例,真行为要到开着检查的构建里跑过才算数。同篇还有一句更狠的,这个绿什么都没证明,也摘给您。

## 私册与公图:链各记各的,图全机一张

单核年代,这套册子一个人看就够。咱们看旧形状 r19 的成员,lockdep.hpp 的 :77 到 :80:

```cpp
    base::container::SlotTable<const void*, kLocks>    locks_;
    const char*                                        names_[kLocks] = {};
    base::DirectedGraph<kLocks>                        graph_;
    base::container::StaticStack<unsigned int, kDepth> held_;
```

末一件,手里的链,全机独一份。方法门口一件守卫也没有,acquire 进门就查。双核一上线,两件事都得改。头一件,链得按核发。4.2 讲过登记簿搬家,深度从一册发成一排。手里的 held_ 链,是同一场搬家的另一名成员,搬家本身不重讲,您对着新形状认一遍,就认得它。r26 的 lockdep.hpp,咱们抽三行:

```cpp
    using HeldChain = base::container::StaticStack<unsigned int, kDepth>;
    HeldChain&                 held();
    HeldChain                                       held_[arch::per_cpu::kMaxCpus];
```

一格一核,机器至多八颗核,取格的钥匙是核号,held() 报的就是本核的链。真身就一行,您认一下,lockdep.cpp 的 :23 到 :25:

```cpp
LockOrder::HeldChain& LockOrder::held() {
    return held_[arch::per_cpu::PerCpu::self().cpu_id];
}
```

问核号,报本核一格。4.2 的 depth() 同款身材,同一个 PerCpu,一个取深度,一个取链。链与图怎么分,正文《请第二颗脑子上线》那一卷的原话讲得最清,摘:每核一条自己的持有链,谁在谁的手里套着谁,一人一册地记,全机共享的是一张记录谁在谁前的有向边图,边图自己另有一把原始的小锁护着,图是共享的财产,链是各核的私册。私册这个词正文亲造,公图是咱们给共享的图起的短名,后头就用它俩。

第二件,图只有一张,两颗核同一瞬间都可能来写,守卫不能再缺。咱们接着看 r26 每个方法的头两行,以 acquire 为例,lockdep.cpp 的 :37 与 :38:

```cpp
    const arch::IrqGuard kIrq;
    const auto           kGate = g_graph_gate.guard();
```

头一行护甲,防本核的中断插脚。第二行 g_graph_gate,防对面核同一瞬间动同一张图。您在 4.2 的 console PutString 那儿见过两行证人,护甲防本核,门闩防对面,这里每个方法门口都站着同款。

两代的行数也对得上数,您自己加一遍:头文件从 83 到 86,添了三行:两行是链的搬家,一行是 include,把按核的那套接进来。源文件从 109 到 129,添的二十行,大头是每个方法门口的守卫两行,外加取格的 held() 与销户时扫全排的那一圈。

**停一停,g_graph_gate 自己,为什么是个光秃秃的 base 互斥件,而不是咱们内核的门闩?您推一遍:要是它换成 Spinlock,头一个人进门会发生什么?**

咱们推一遍,这段是咱们的推演,不是正文原话。内核的 Spinlock 拿到手之后,末一件事就是在登记簿记一笔,记的活落到名册 LockOrder 的方法里,而名册的每个方法,头两行正是拿 g_graph_gate。旗还在自己手里,同一颗核又要去拿同一把旗。这一步走不到转圈:门闩进门,转圈还隔着一道重入检查,4.2 修法二认的就是它,当场就叫,机器响着停,响在防死锁的那道岗门口。盯梢员的家什用上了被盯梢的锁,站岗的自己把自己拦下,这班岗也就站不成了。所以它生在 base,零系统耦合,不关中断,也不进名册。4.2 点过它的五家用处,锁序图的门是其中一家。门里护的财产,恰好是给全内核的锁记名的册子,守门的自己决不能也是册上有名的一把。

## 骨灰案:生要登记,死要销户

册子会满。头一场满,满的是骨灰,案情正文《锁的生卒》全本记着,咱们顺着捋。管道是这套教材里少有的会死的对象,测试开了关、关了开,一根接一根地生,一根接一根地死。每一根自带三把锁,环形缓冲一把,读写两侧的计数各一把,本章头一回点名。生的时候,原话摘:锁在构造里自动地登记进锁序图,登的是地址。死的时候呢,跟锁序图说一声的都没有。地址入了册,对象没了,下一根管道落在同一个地址上,倒是能复用身份。可堆不是省油的灯,新管道常常落在新鲜地址上,册子上攒起一条又一条死地址,每条占着身份的一格,没有任何活着的锁用它。几十根管道开合下来,正文原话:六十四格装的全是骨灰。

假满。格被死地址占着,活锁想进门,门没有了。销户能治,而这门功课,正文《无盘起家》那一卷早教过,原话是,retire 就是回收前的销户,销户在前,还存储在后。管道忘了办,给锁补上的礼数,正文叫生卒礼:析构之前挨个退役。您看真身,sync.cpp 的 :86 到 :91:

```cpp
void Spinlock::retire() {
    const cinux::arch::IrqGuard kGuard;
    cinux::base::safety::Check(!held_.test(std::memory_order_relaxed), "destroyed held spinlock");
    SpinLedger& ledger = ledger_ != nullptr ? *ledger_ : DefaultSpinLedger();
    ledger.forget(this);
}
```

头一道 Check,确认没被持有:攥着的锁不许销,销了,持锁人手里就成了空旗。销的活本身在 forget,一共三笔,lockdep.cpp 的 :95 到 :97,您逐笔看:

## 反向敲打与还炸:满册的两种满

生卒礼的头一版,自己挨过一记反向的敲打。正文记的:头一版退役为了检查时不被人打扰,进门头一件抢的就是一把自旋锁,而锁一进门就会在顺序图里登记一笔身份。审查指出来了一回:已经满六十四槽的时候,析构反而要申请第六十五个身份,越退越满。多余的抢锁删掉,退役只做检查与摘除的本分。您回头看上一节印过的 retire,头一行只有护甲,没有第二行抢锁,那行单薄是故意的。forget 门里那两行守卫,护图的 g_graph_gate 是 base 件,不进名册,前头推演立过的道理,这里又站了一岗。

补齐了,案子还没完。正文原话:退役补上了之后,生产实弹还是炸了容量,响的还是同一声断言。这回查了个底朝天,原话里笔笔俱全,咱们跟着对:调试器把锁序图的原始册子整个倒出来,六十四个身份个个是活的,地址对得上内存里真站着的管道对象,持有链全是空的,深度也个个归了零,占座的事没发生。案子就此翻了面,正文的原话:那么问题换了主语:谁说它们该死。

**停一停,同一声断言响了第二回,您在屏前头一步查什么,才不会把两场满认成一场?**

头一步,把原始册子倒出来对地址。骨灰案,死地址对不上任何活对象。这回,个个对得上。满册从此分两种:满的是骨灰,假满,销户能治。满的是活锁,真满,销户治不了。真满的病根,顺着引用的数目走:管道生下来三笔引用,创建者一笔,文件表两端各一笔。两个描述符关得干干净净,只从三减到一,创建者那一笔没人还。这桩引用的案子,4.2 全案讲过,创建者改用带归还的共享指针、每个出口都还,修法也讲过,咱们只记落点:锁的生卒背后是对象的生卒,对象的生卒背后是没还清的引用。册子记到六十四就喊,喊的就是这个病。

## Code: Cinux 实况:八案点名,那声断言不在此列

实况还是 r26_smp。宿主测试座上 lockdep 自己的八案,4.2 那三块屏里夹着印过,本章咱们升正席:

```text
[PASS] lockdep: CPU held stacks are private while lock order edges cross CPUs
[PASS] lockdep: another CPU observes established lock-order cycles
[PASS] lockdep: remembers AB then rejects BA
[PASS] lockdep: rejects transitive cycle
[PASS] lockdep: invalid operations leave held stack intact
[PASS] lockdep: forgetting a destroyed lock permits address reuse
[PASS] lockdep: held depth exhaustion fails visibly
[PASS] lockdep: graph capacity is reclaimed on destruction

=== Results: 8 passed, 0 failed ===
```

头两案 4.2 讲跨核时点过名:链是各核的私册,边是全机的公图,案一看住链的私密,案二看住边的共享。后六案,咱们逐案一句。remembers AB then rejects BA,拿过 A 再拿 B,回头想拿 B 再拿 A,环检查当场拒,座次立了就得认。rejects transitive cycle,环隔着层也抓得住,A 到 B 到 C,想从 C 回到 A,可达那关接住。invalid operations leave held stack intact,被拒的申请不许在册子上留痕,持有链原样。forgetting a destroyed lock permits address reuse,销户之后同一地址再进册,干干净净一个新身份,骨灰案的药在这案上验。held depth exhaustion fails visibly,十六层深用满,响亮地报,不悄悄截断,宁响不漏落在深度那一头。graph capacity is reclaimed on destruction,六十四格销了真还,寿命案六十五个地址能过关,站岗的是它。

开场那声容量断言,屏上没有,也不该有。它是机内实弹炸的,口供与修案的全程,正文《锁的生卒》里记全了。咱们不造那块屏,口径开篇立过,这里兑现。

## 对照:同一件事,别的机器怎么做

书页 69 那句规约,锁是函数规约的一部分,书页 70 紧跟着算代价,咱们摘原话:

> “Honoring a global deadlock-avoiding order can be surprisingly difficult”

遵守一张全局的死锁规避次序,可以难得出人意料。难在哪,它家照页摆了几样,咱们跟着点。叫醒的次序:consoleintr 护着控制台的锁去叫醒等它的人,叫醒又要拿进程的锁,所以 cons.lock 得排在进程锁前头。链条长:翻路径的目录一把,新文件的 inode 一把,再到盘块缓冲、盘驱、进程锁,一条链五把锁,每一节的次序都得排对。次序跟模块的上下级打架:一个模块要调另一个模块,锁序却要求被调那方的锁走在前面。身份未知:有一种锁,拿到上一把之前,根本不知道下一把是谁,按路径逐级翻目录、扫进程表找孩子,都是走一步才知道下一步,座次没法提前写死。

页上还有一笔总的,咱们按页转述,不是原句:锁越多,死锁的机会越多。排得粗了好守,并发就窄,排得细了并发宽,次序就难守,所以锁序常常是内核实现里的主要约束。4.1 摘过同页的重入之争,立场咱们同站,不重讲。

Linux 那头,这回比得了,但只比一句。生产内核里有一位同名的 lockdep,配置名 CONFIG_PROVE_LOCKING,打开它,按锁的类建依赖链,报的口径是 possible,可能发生的环,不只当真发生的。六十四格的身份册是教学器物的取舍,静态、定长、满员就喊。它家是跑在生产上的家底。咱们不展开,只认这门亲:盯着的是同一件病,教具与家底,各干各的活。

### 参考答案

题一:拦得住。第二次进门,循环里那把 kHeld 与 index 是同一格,reaches 从同一格出发,查的还是同一格,零长路径也算够得着,返回真,环检查报 kCycle。案子破了,案由报歪:重入报成了环,您顺着环去查两把锁的座次,查不出所以然,真正的病是一把锁进了两次门。环检查独自也拦得住,单立一关,为的是诊断的准头。

题二:自己等自己,同一把旗进了两次门。您今天再走同一条路,旗还没转起来就会响:门闩那一层的重入检查当场叫。要不是它拦在前头,轮到册子,报的也是 kRecursive,两级岗哨,同一案由。两把旗背对背,手里的与对面手里的一左一右,环检查 kCycle 接住。边记在全机的公图上,隔着一双手也看得见,机器响着停,不等背对背真的成形。两场病一句话总:拿多把锁的路径,次序得是同一条,书页 69 的原话。

题三:案一 CPU held stacks are private while lock order edges cross CPUs,一案里两头都验,链各记各的,边两核都看得见。案二 another CPU observes established lock-order cycles,补的是公图的眼睛,这核立的环,那核去撞,照样响。家法咱们这么念:宿主绿了不算数,同一用例在开着检查的构建里跑过才算,acceptance.sh 后三条线就是给这句家法备的。
