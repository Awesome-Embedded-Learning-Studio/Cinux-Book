# 06 · 内存序与缓存一致性:两个作者,三档刻度,三口锅归位

>

## 两个作者:一个在编译器里,一个在处理器里

次序的第一位作者,咱们是老相识。4.1 办过那桩删循环的案中案:编译器看没人写那个旗,把读连同等待循环一起删了。案子 4.1 整案收过,xv6 书页 71 它自己招供的原话,读写指令的次序它敢换,没用的读写它敢删,4.1 也整句摘过,招供状咱们不重念。今天升一层,把压在案子底下的原理请出来。

正文《轮流当家》那一卷记下的话,咱们整句搬来立在本章门口:编译器的世界里只有它看得见的因果,看不见的那些,一律不在它的世界里。同卷还有一笔:中断会异步地修改内存,这件事咱们从来没表达给编译器。挡得住靠的纯属运气。两句合起来,作者的脾气就出来了:界内它讲理,界外它不讲,而中断与另一颗核,都住在它的界外。

第二位作者在处理器里,xv6 同一页介绍了它,原话咱们整句摘,书页 71:

> “Another reason is that the CPU may execute instructions out of order to increase performance. For example, a CPU may notice that in a serial sequence of instructions A and B are not dependent on each other. The CPU may start instruction B first, either because its inputs are ready before A’s inputs, or in order to overlap execution of A and B.”

译过来:CPU 为了跑得快,指令可以不按程序的次序执行。比方一串指令里 A 与 B 互不依赖,它可能让 B 提前走,要么 B 的料备得早,要么 A 与 B 正好叠着一起办。您看,第二位作者挪起指令来,与编译器挪起读写来,是同一种脾气。

原理落到处理器身上,一字不改:它的世界里,也只有它看得见的依赖,看不见的那些,一律不在它的世界里。编译器看的界,是源代码与语言约定划的。处理器看的界,是指令之间的数据来往。界内它老老实实:您一个人的程序,跑出来永远像按次序跑,1.1 教过,行话叫 as-if 顺序。界外没人担保:两条执行流隔着共享内存打交道的地段,谁写的何时被谁看见,两位作者一个字都没许诺过。

次序要人管,管的手法就是把许诺买回来。正文《轮流当家》那卷里,《被删掉的等待循环》一案的收尾立过一条底线,咱们原句搬来:跨执行流共享的变量,咱们必须用原子或屏障来表达,这是一条实打实的底线。咱们一直在花这笔钱,只是没细看过。今天把花销摊开:钱花在哪一档,谁收的,强机器为什么打折。

## push 反例,与约定的名字

挪坏了是什么样,xv6 同页给过咱们一桩现成的反例,原话整句摘,书页 71:

> “As an example of what could go wrong, in this code for push, it would be a disaster if the compiler or CPU moved the store corresponding to line 4 to a point after the release on line 6:”

原书接着摆了六行,咱们按它的行号数着念:头两行备料,造节点、填数据。第三行 acquire(&listlock) 拿锁。第四行 l->next = list,把新节点的 next 指向旧表头。第五行 list = l,表头改指新节点。第六行 release(&listlock) 放锁。要出事的正是第四行:这笔写要是被哪位作者挪到第六行之后,后果原书也写明白了:

> “If such a re-ordering occurred, there would be a window during which another CPU could acquire the lock and observe the updated list, but see an uninitialized list->next.”

咱们译过来:真这么挪了,就开出一扇窗。另一颗 CPU 拿到锁,看得见表头已经改指新节点,转到节点身上读 next,读到的却是没写过的垃圾。

您细看这桩祸的形状:互斥一点没破,锁还是一把,进门的次序还是一前一后。破的是另一件事,拿锁的人本该看得见上一任临界区里的全部写入。看得见的这一层,4.1 用传话管道的白话立过:release 是放行前的承诺,写统统落定才放行。acquire 是进门时的要求,进门就要求读得到前任的一切。push 反例,就是管道失约之后的具体惨状。

担保上哪儿买,xv6 紧跟着就给了名字,咱们整句摘,书页 71:

> “The good news is that compilers and CPUs help concurrent programmers by following a set of rules called the memory model, and by providing some primitives to help programmers control re-ordering.”

咱们译过来:好消息是,编译器与 CPU 并非无法无天,它们照着一套名叫内存模型的规则办事,还给程序员备了几件家什,用来管住重排。

内存模型这个词,咱们今天头一回正用,白话配上:一份写明的约定,两位作者哪些挪动许做、哪些不许做,全写在上面,程序员还能掏钱,多买到几条不许。

C++ 把约定刻成了刻度,名字叫 std::memory_order,咱们一路上用过的,正好三档。relaxed 最松,只保这一拍操作自己不可分,前后的读写次序一概不承诺,正文数拍子那一桩选的就是它,白话 4.1 配过。

acquire 与 release 是两个半边,进门的要求与放行的承诺,4.1 立门闩时配齐的那一对。acq_rel 一个名字装两个半边,读改写用的,下一节正戏。标准里还有更严的 seq_cst 与用途冷僻的 consume,咱们全书不立它们的正题,点到为止。

## 库里三处:三档各配各的仗

刻度念完,拿终态的码对照,三档各有一处真身,一处一个道理。头一处,tick.hpp 的心跳计数。4.1 那桩删循环案,修法的真身就落在这儿,案子不重讲,咱们只认亲:fetch_add 带 relaxed 在 :98,读的 load 也走 relaxed 在 :108,旁边 :114 到 :115 立着 is_always_lock_free 的静态断言,断言的话写得明白,这个计数不许走会拿锁的运行时。

为什么最松的一档就够,咱们看它数的是什么:数拍子只数这一拍本身,数到多少是多少,前后没有要跨流看见的家当。relaxed 保住这一拍的不可分,事情就清了,再严的档都是白花钱。

第二处,门闩的拿与放。sync.cpp 的 test_and_set 配 acquire 在 :98,clear 配 release 在 :116,真身 4.2 印过,咱们这里只看次序:门闩护的是临界区,进门的人要求读得到前任的一切,出门的人承诺写统统落定,两个半边,一对档位,push 反例就是这对档位在防的祸。

门闩身上还有一笔松弛的,正好练一练您的眼力:owner_cpu_ 的登记走 relaxed,拿锁时写在 :102,放锁时清回负一在 :115。格子要紧的读者是本核自己,重入检查问的是这把锁是不是本核拿着,别的核写下的值,答案里用不上。本核关着中断写、读,天然一前一后。跨流的次序它一项不用买,relaxed 刚好。

第三处正戏,ref_count.hpp,4.2 押的那道题,咱们当面答。押题您还记得:正文说的是 acquire 配 release 那一档,代码里落的是 acq_rel,凭什么一档当得起两样。

咱们把形状认了。fetch_add 与 fetch_sub 都是读改写:一拍里读旧值、改、写回,一口气办完。4.2 摆这两段代码的时候,当的是计数讲。今天换个眼光,当次序讲。读改写的一拍里有两个半边:读的那半边,要的是 acquire 的要求,读回来之后,别人前头写下的东西都得看得见。写的那半边,要的是 release 的承诺,我这一拍落下之前,我前头的写统统落定。acq_rel 一档,就是两个半边各领各的名分,合写在同一笔里。

凡读改写都是这门亲:fetch_add、fetch_sub,后头会合要用的 fetch_or,全一样。您往后见到读改写,就在心里分出两个半边,档位怎么配,答案就在分出来的两半里。

这套答案在实弹里怎么承重,正文《请第二颗脑子上线》那一卷的原话给得干脆:减到零的那颗核,必须看得见所有曾经持引用的核写下的全部操作,保证这一点的正是拿与放那一对顺序。咱们顺着数:每一位放手的核,release 半边把自己临界区里的写封进那一笔减法。轮到减到零的那一笔,acquire 半边把历代前任的写全都收进眼底,析构这才敢做。

4.2 那桩十万次加减的实弹,您回头想,十万笔里,笔笔都是两个半边在担。

码上的落位,咱们一处一处报。retain 的 fetch_add 带 acq_rel,在 :49。release 的 fetch_sub 同款,在 :61,减出来的旧值等于一,:63,认下最后一任。旁边 use_count 的读配 acquire,:67,给外头的旁观者一个读得到的口径。计数出生自带一,:70,头一个引用是娘胎里带的。

答完题,4.2 摆下的那笔措辞差,今天摆到第三层。第一层,正文那一卷的原话:顺序咱们选 acquire 配 release 那一档,念的是两个名字配成一对。第二层,ref_count.hpp 的类注,:24,写的是 publish with acquire/release ordering,还是那对名字。第三层,落到码上,:49 与 :61 两处,写的都是 std::memory_order_acq_rel,一档一个词。

三方谁也没改谁,三种念法都对:名字念的是两个半边,档位念的是合写的一档,合起来的意思您在上一段已经读到。咱们把三层原样摆开,不替谁圆场,您三门对过,自己对得上。

## 只拦编译器的墙

三档之外,还有一道屏障要认清射程。SpinMutex 的拿锁您在 4.2 看过三层,咱们只请围栏那一行出来,spin_mutex.hpp 的 :52:

```cpp
                std::atomic_signal_fence(std::memory_order_seq_cst);
```

这声围栏有个正名,信号围栏,今天咱们头一回点名,白话:一道只拦编译器的墙。它管两件事:不许编译器把圈里的等待优化没了,不许把圈里圈外的读写挪错位。这两件 4.2 都说过,今天补的是它的射程与身价:它对处理器一个字也没说,落到机器码里一条指令都不添,处理器侧一分钱不花。参数里那个 seq_cst,全谱里最严的一档,4.2 印那三层的时候它露过脸,今天给它配上白话,全书就配这一回。

处理器层的次序归谁管?4.2 答过半句,由拿与放自身的语义担着,话说到往深处去为止。今天咱们把这半句接完:管的就是 acquire 与 release 这对名字,它们是写给处理器的承诺。正文《请第二颗脑子上线》那一卷的原话,给这问答得干脆:拦住编译器乱序的墙只有编译期的信号屏障,处理器层的顺序,由拿与放自身的语义担着。

圈里那声 test(relaxed) 为什么敢用,咱们顺着这问再走一步。4.2 从钱上讲过一遍:原子那一拍要把缓存行攥在手里独占,普通读只看不动手,便宜得多。今天从次序上补一刀:圈内的读只有看的份,没有一笔要跨流保的写,acquire 与 release 的承诺,它一项也用不上。墙拦编译器,名字管处理器,圈内的读两边都不沾,这笔花销才配得这么省。

这道墙的前身您其实见过。前置卷《写:内联汇编》那一篇教 asm 的时候引过手册的话:“memory” 告诉编译器,这块 asm 对操作数之外的内存也动过手。手册说,这为编译器构成了一道读写的内存屏障。

那一篇当时也划了界:这道屏障管的是编译器,处理器自己往 asm 之后做推测读,它拦不住,处理器那边的乱序另有 fence 一类的东西管着。划界划掉的那半句,今天接上了:另有的 fence,就是 acquire 与 release 这些承诺,接上的地方就是本章。前置卷三根线头,内联汇编这根结在这儿。《设备怎么碰》那根,咱们到欠债一节结。保护模式那根,门开了就算结了。

**停一停,同一对拿与放,源码里写着 acquire 与 release,x86 底下编出来一条 xchg 一条 mov 就交代了,屏障钱一分没收。您想:这套次序,到底是写给谁的?**

写给约定,不写给某台机器。内存模型只认承诺,不问兑现的成本。底下压着哪台处理器,编译器自己去掂量。咱们看两家各怎么算,价差就在两家中间。

## 价差:一家砌真墙,一家免单

xv6 一头,书页 71,原话咱们整句摘:

> “To tell the hardware and compiler not to re-order, xv6 uses __sync_synchronize() in both acquire (1271) and release (1302). __sync_synchronize() is a memory barrier: it tells the compiler and CPU to not reorder loads or stores across the barrier.”

译过来:要告诉硬件与编译器别重排,xv6 在 acquire 与 release 两处都放了 __sync_synchronize(),行号 1271 与 1302。它是一道内存屏障,咱们给它配白话:墙立在哪儿,读和写就不许挪过去,不分只管读还是只管写,两边统统拦。xv6 的机器是 RISC-V,弱内存序的一头:处理器天生答应得少,约定上没买的次序它一概不担保,拿与放两头都得砌真墙,屏障钱一分省不下。

咱们这边,拿自家编译的产物对。抽形状的小程序咱们叫探针,拿它往编译器身上扎一针,看它吐出什么。探针的源码,把 SpinMutex 的形状抽出来:一把 atomic_flag 当门闩,test_and_set(acquire) 抢,test(relaxed) 在圈里盯,clear(release) 放,在家用编译器 g++ -std=c++23 -O2 下编成汇编。三处要害,各请一行。抢那一拍,test_and_set 配 acquire:

```asm
	xchgb	(%rdi), %al
```

咱们看圈内那一眼,test 配 relaxed:

```asm
	cmpb	$0, (%rdi)
```

咱们看放锁那一笔,clear 配 release:

```asm
	movb	$0, (%rdi)
```

三行咱们挨着念。抢那一拍落成 xchg,x86 的交换指令。xchg 指令跟内存打交道时,硬件自动配上锁定,前缀都不用另写,原子的一拍与次序的承诺,一条指令全包。

放锁那一笔,落成一条普通的 mov。圈内那一眼,落成一条普通的 cmp。您数源码里的次序名,acquire、relaxed、release 各一,机器码里没有一条屏障指令。

为什么敢不掏:x86 这边是强内存序的机器,它天生答应的次序就严,咱们买的那点次序,它本来就白送,编译器掂量完,免单。

RISC-V 是弱的那一头,同样的源码,兑现要真掏屏障,xv6 那两声 __sync_synchronize 就是掏钱的凭证。强弱内存序这对词,咱们今天立成术语:强机器答应多、屏障钱少,弱机器答应少、什么都得另买。

xv6 自己也给这道墙收了话,句子跨页,起头在 71 页末行,咱们整句摘,页码记 71-72:

> “The barriers in xv6’s acquire and release force order in almost all cases where it matters, since xv6 uses locks around accesses to shared data. Chapter 11 discusses a few exceptions.”

译过来:这两道屏障在几乎一切要紧的地方都压得住次序,因为 xv6 访问共享数据都裹着锁。第 11 章讨论少数例外。例外那半句咱们点到即收,第 11 章咱们没翻开过,不越界替它念。

末了把边界钉牢。探针是同款形状在家用编译器手里的产物,不是内核构建的镜像。它证明的是约定在 x86 这门指令集上的价钱,不冒充实况。真到实况,咱们也演不出弱序机器上的差价:机器跑在 TCG 上,1.7 说过,上半截没有屏,TCG 不演缓存,弱序同样不演。两头都没有现场,咱们手里只有规格常识,这句诚实话,与 1.7 那半句同款。

## 上线握手两场:发布带 release,开门用 acquire

约定与价码都清了,咱们看两场真枪实弹,都在 smp.cpp,第二颗核上线的路上。第一场,就绪屏障。副核一路跑到内核世界的门口,把自己收拾利落:本地的中断芯片、定时器、机制快照,全弄妥了,才轮到发布。发布那两行,咱们抄来,smp.cpp 的 :157 起:

```cpp
    g_online[cpu].store(true, std::memory_order_release);
    g_online_count.fetch_add(1, std::memory_order_release);
```

咱们看这两笔:一笔写自己的在线旗,一笔给全机的在线数加一,都带 release。带它干什么:发布之前的全部收拾,统统要赶在旗立起来之前落定。头核看见旗,就得看见收拾利落的全部。

一放一取,正是 4.1 传话管道的两头,在真弹里握手。顺带咱们报一笔出生家底:在线数生下来就是一,:66,头核把自己算作一颗。副核到齐,头一笔加法把二添上。

头核那一头,咱们看 smp.cpp 的 :230,原地自旋,等在线数涨过自己,load 配的正是 acquire:

```cpp
        while (g_online_count.load(std::memory_order_acquire) <= cpu) {
```

正文《请第二颗脑子上线》那一卷记这段的话,咱们对读两句:发布的那一笔带 release 顺序写在线标志,累加走的是原子加法。一颗一颗地来,不做批发的生意。为什么一颗一颗:头核等的是每一颗各自到齐,谁的快照谁自己发布,谁的旗谁自己立。

您试想图快的样子:数目涨在头里、收拾补在后头,头核看见数目就抬脚进门,遇到的就是没写完的家当,与 push 反例同一个病,只是把锁换成了计数。

第二场,咱们看分发许可位。核上了线,不等于能开工:g_dispatch 出生就是关的,:69。副核进了空闲循环,一遍一遍只问这一句,:160,load 配 acquire。头核那一头,把调度器的类注册表、初始任务、文件世界都备齐了,才把许可位这么一放,:253,store 配 release:

```cpp
    g_dispatch.store(true, std::memory_order_release);
```

正文同卷记这段的话,咱们接着对:全局一个分发许可位,头核把许可位这么一放,再广播了一声。分两拍发布的思路,第一拍就绪屏障,第二拍这道许可。为什么非要两拍:许可开早了,副核冲进共享的队列,拿到的是没写完的元数据,头核单手的半成品。

您看,没写完的元数据,又是 push 反例的亲戚。

4.5 交棒问的那句,为什么拿与放非配这一对不可,答案全在这两场里,咱们再收拢一遍:发布带 release、开门用 acquire,一放一取,管道才接得上。配反了或者不配,开门的人看见的就可能是没写完的世界。信号那把 gate 也是同一门配法,真身 signals.hpp:64,拿与放一对档位,护的是 4.5 交下的那两段路。

## 会合与欠债:报号那一拍,与硬件的私务

握手之外还有一场次序的实弹,三个人凑齐才开场。机内块设备测试里的 meet_on_both_cpus,test_block.cpp 的 :39,咱们整段抄:

```cpp
void meet_on_both_cpus() {
    const cinux::arch::IrqGuard kGuard;
    g_cpu_mask.fetch_or(cinux::base::bit::MaskBit<unsigned int>(
                            static_cast<unsigned char>(cinux::arch::per_cpu::PerCpu::self().cpu_id))
                            .raw,
                        std::memory_order_acq_rel);
    while (g_cpu_mask.load(std::memory_order_acquire) != 3) {
        cinux::arch::CpuRelax();
    }
}
```

咱们把会合走一遍。三位工人,活的开场全压在这场会合之后。会合认核不认人:进来头一件事,把中断关死,:40 那件 IrqGuard。第二件,把自己那一核的位 fetch_or 进 g_cpu_mask,:41 起,次序落 acq_rel。末一件,acquire 的读盯着掩码,:45,等到它变成 3,两位都到齐,放行。

您眼熟吧,fetch_or 又是读改写,acq_rel 又是两个半边一起担,与引用计数那道押题,同一个答案换了件衣裳:报号那一拍,读半边把别人前头的报位收进眼底,写半边把自己的报位封进这一拍。凑成的 3,两位看得见同一个 3。

为什么全程裹着 IrqGuard,正文《破案:被吞掉的完成通知》一篇的原话:报号到放行的全程本核关中断,不然刚记完号人就给迁走了,凑数的永远差一位。您把这句与 4.4 那口 `sti; hlt` 的锅放在一起看:两口都是中断的缝,一个怕的是刚记完号就被迁走,一个怕的是刚开闸就被人叫醒,封法各是各的,要护的东西一样,窗口里的状态,谁也不许插手。

同款会合,咱们再点一处,机内的 smp 测试里也立着,test_smp.cpp 的 :83 起:报位走 fetch_or(acq_rel),等齐走 acquire 自旋,与块设备测试同一个形状。案名起得直白,:219,smp: two CPUs dispatch shared tasks and contend on a real spinlock,两颗核办同一批活、真抢一把自旋锁。块设备测试末了还有一声断言,:100,ASSERT_EQ(g_cpu_mask.load(), 3U),两位到齐,钉进案卷。两处咱们引名引行,不引屏。

会合的次序是咱们自己管得着的。再往下问一层,就问到硬件跟前:两颗核各揣着各的缓存,同一个格子,你写一笔我读一笔,怎么保持同一个说法?4.2 白话过半句,原子那一拍要把缓存行攥在手里独占,那是已刊的半张脸。今天升到问题层,给它正名:问到这一层就停,机制有名有姓,协议怎么商量不再往下拆。这背后有一整套硬件内部的商量,行话叫缓存一致性,白话:各核的缓存副本之间保持同一个说法的那套机制。

它怎么商量、协议长什么样,是硬件的私务。咱们一台 TCG 机器验不了,书架上也没有核过的本子,规格常识到问题层为止,一句不多写。您只需记牢线画在哪:承诺是语言的,原子与次序咱们找语言买。兑现是硬件的,承诺落到缓存行上怎么变成真,硬件自己的事。硬件兑现得了,咱们买的承诺才算数。

头一笔欠债,咱们记 TLB。3.2 教过,它是翻译的速查缓存,页号到物理页的小本本。小本本每核一本,所以它也是一种各揣一份的缓存,而它不在那套商量机制里,各核各记各的。

考古的案子,咱们在正文《破案:被吞掉的完成通知》一篇里同场见过:写时复制改页那阵,父进程把页改成只读,没冲另一颗核的 TLB,那颗核的簿子里还留着可写的旧翻译,照着旧翻译写下去,共享页就此污染。当年修的全局冲刷够用,靠的是 fork 全程关着中断。

如今 fork 的路不再全程关中断,当年那刀治不了今天的病,而跨核的远端冲刷,那一篇的原话咱们照录:那个真正的完备解,咱们如实登记为欠债。欠条今天还挂在明处,几时还、怎么还,书里走到那儿再算。

第二笔,咱们记设备。前置卷《设备怎么碰》那一篇两回露头的线头,问的是设备寄存器出现的地方为什么不能让缓存随随便便吞掉,今天结到问题点名为止。机器对外的两扇门您在 1.5 见过,显存那一扇不用报门牌,地址算好 mov 就到。这样的门,行话名 MMIO,内存映射 I/O,白话:设备寄存器编进内存地址里,读写当内存使。

地址背后坐的是设备,您读它,问的是设备的现状。写它,是在按铃。差事要是被缓存当热字扣下副本,问话就答不准,铃也可能按了没响,所以这一扇门,走法上要绕开缓存。

DMA 那头反着来。引擎替设备往内存搬字节,这笔买卖 1.6 教过。搬完的字要是还压在缓存的旧副本底下,CPU 读到的就是搬家前的旧底。所以 DMA 的搬运要与缓存打招呼。怎么绕、怎么打招呼,是设备模型的细节,咱们没翻到那页书,不编。第 5 部的块设备与驱动开讲,欠条记在那边。1.7 挂下的那句线头,那桩细目叫缓存一致性,连着内存屏障,今日两头都点到了名,结清。

## 练一练

三道题留给您:一道推演,一道回望,一道读册。

**题一,推演。** SpinMutex 的 unlock 里,clear 那一笔要是从 release 降成 relaxed,您推一遍:互斥坏不坏?坏的是哪一样?祸要几样东西凑齐才现形,又在哪台机器上才现形?

**题二,回望。** 三档刻度,终态码里三处真身:tick 的计数、门闩的拿与放、引用计数。您各配一句,为什么非那档不可,降一档会少什么?

**题三,读册。** 回 xv6 书页 71 那六行 push,您答两问:第四行的写挪到放锁之后,另一位 CPU 拿到锁,看得见的是什么,看不见的是什么?xv6 的拿与放两头都要 __sync_synchronize,咱们的 test_and_set(acquire) 与 clear(release) 一条屏障不另掏,差价差在谁身上?

### 参考答案

题一:互斥不坏。clear 自己还是原子的一拍,旗还是一份,谁翻到谁进门,门还是一扇。坏的是管道:release 承诺的临界区里的写在倒旗之前统统落定,这一档撤了,写与倒旗之间没了次序,下一位拿到锁,读到的可能是没落定的写。祸要两样凑齐才现形:临界区里真有一笔要传的写,另一颗核拿到锁就去读它。x86 强内存序还替咱们兜着,真现形要等弱序机器。4.1 那对白话里,放行的承诺那一半,担的就是这个活。

题二:咱们一处一处配。tick 数拍子,relaxed 是刚好:它只要这一拍自己不可分,前后没有要跨流看见的家当,再严是白花钱。门闩要一对半边:进门读得到前任一切,出门写统统落定,少半边就是 push 反例。引用计数是读改写,acq_rel 两个半边一起担:减到零的那颗核要看得见全部前任的写,降成 relaxed,数目照样算得对,家当却看不见,析构就敢在别人的写还没被看见的时候动手。

题三:咱们来答。看得见的,表头已经改指新节点,那一笔写在放锁之前落了地。看不见的,新节点自己的 next,那一笔被挪出了门。差价差在机器,不差在约定:xv6 的 RISC-V 是弱序,买下的次序要真屏障兑现。咱们的 x86 强序,买的那点次序它本来就送。同一句源码,两家两种价。源码里写的,永远是约定。
