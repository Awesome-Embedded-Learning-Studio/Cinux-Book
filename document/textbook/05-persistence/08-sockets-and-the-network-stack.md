# 08 · socket 与网络栈:不按铃的卡,让位的圈,十态的钟

教科书层接的是网络的第三棒,前两棒是旅程网络四部里头两卷跑掉的。网络四部的第一部《校验与回环栈》开卷时撂过一句话,“socket 是排在第三部的”,第三部的货今天到齐了,咱们把 socket 与他背后的网络栈一次摆开。押着的票也有两张:5.7 收尾时说 socket 是同一张脸的第五户,没路径的门牌,4.5 说 socket 的等待圈里挂着信号那一问。押着的两张,咱们今天都兑。

本章的活,咱们按帧的旅程数下来八样。头一样是设备侧的卡,网卡把中断铃全摘了,搬运靠一位常驻的泵。第二样是一帧的旅行,从网卡的收货环走到套接字的环,回程的路由也一并看。第三样是 socket 的脸,5.7 教过的函数表今天坐进第五户。第四样是号位的名册,生齐的是十四个,缺的是 46、47 两座,咱们在表下头如实补报。第五样是让位的圈,阻塞读写的骨架,4.5 的口径在这里对上正主。第六样是 UDP 全家的端口、环与丢的计数,咱们挨个看。第七样是 TCP 十态的一生,咱们跟着连接从头走到尾,握手的双手、道别的两封信、到点叫人的钟都在路上。末一样是多路复用与本机通道的家底,咱们把 epoll、eventfd 与 poll 两兄弟摆在一起,再加上不走网线的 AF_UNIX。

量的家法还是老的三条,码打的头。实况锚的名字还是 r35_gui_fin,5.3、5.6、5.7 引的也是他,行号的写法一律是文件名加冒号加行号,数都是这一棵树里的数。5.1、5.2、5.4、5.5 的家在 r34_compile_self,两边的行号对不上是常事,您别拿着旧数来对新一章。树里的 net_config.hpp 有两份,管语义的一份住 kernel/net,管帧与器件容量的一份住 kernel/driver/net,本章数数引的都是前者。屏没有新起的,泵的活与连接的迁移是按码推演的,咱们照实标。外部的书是一本都没请的,语义对的是手册页,单子咱们开在延伸里。

> **您停一下,想想看:网络栈是谁在推着走?中断来的时候会发生什么?读着读着把自己挂住了,谁来叫醒?**
>
> 其实这里的答案是:没有中断,铃也摘了,叫醒的人也没有。搬运靠一位常驻的泵一趟趟地摇,读的人把自己挂进让位的圈,回来了自己看。不按铃的卡是设备侧的正主,让位的圈是等待读写的骨架,十态的钟管的是 TCP 节里的重传与守程。

## 设备侧:把铃全摘了的卡

锚树里的网卡没有接中断线,这是咱们进网络世界的头一件事实。驱动认卡走的是 PCI 的名册,认的是厂号 0x8086、卡号 0x100E,对上了号才往下走(e1000_config.hpp 的 :64 到 :71),认完把寄存器的窗口映进内存(e1000.cpp 的 :51),把卡复位了,等复位位自己清了零,再把链路拉起来(e1000.cpp 的 :53 到 :60)。收货的环开了三十二格,每格装的是两千零四十八字节,发货的环开了八格,每格装的是一千五百三十六字节,格子数与格子深都写在驱动自己的配置头里(e1000_config.hpp 的 :36 到 :57)。

摘铃的那一手,咱们在码里就写一行:

```cpp
reg_write(regs_, e1000::kRegImc, 0xFFFFFFFF);
```

咱们把中断屏蔽寄存器写成了全一,一是一片铃全数哑掉(e1000.cpp 的 :59)。为什么不接中断?因为中断一来,处理就要分两截了,响铃的一截与善后的一截,读者得同时看两条时间线。轮询把两条并成了一条,泵摇到哪儿咱们就知道字在哪儿,看链路的时候从头到尾只有一条线。回环口走得更素了,他没有 MAC 地址,他的帧也没有以太头(loopback.cpp 的 :29 到 :39),send_l3 把发出去的帧直接送进自家的收货环(:49 到 :58),读的一侧 poll_frame 再从环里取出来(:45 到 :47),地址就是自己,头也就没必要装了。

搬运的活归泵管。起机的时候,NetWorld 把世界接好了,线挂上了就挂线,挂不上的话就“仅回环”地过下去(init_sequence.cpp 的 :264 到 :274),然后一个名叫 net_poll 的常驻任务立了起来(net_world.cpp 的 :89 到 :103)。泵的一趟活计在 pump_once 里,咱们数得清清楚楚:栈的 poll 至多搬十六帧,再替 TCP 做一轮到点的杂务(net_world.cpp 的 :105 到 :109)。十六的预算写在 net_config.hpp 的 :346,理由是泵是全家的公仆,一趟搬多了的话,别的活就插不进话。

泵的身条儿,咱们看码里的死循环:

```cpp
void NetWorld::pump_entry() {
    for (;;) {
        self().pump_once();
        proc::Scheduler::self().yield();
    }
}
```

咱们看泵搬一趟让一步,再搬下一趟(net_world.cpp 的 :234 到 :239)。开机名单里泵立起来了之后,init 还连发四发 ping 去探网关 10.0.2.2 的门(init_thread.cpp 的 :283 到 :295),答的是三发,头一发花在 ARP 的问路上,点亮网卡那一卷开卷交代的也是这个数,三声回音落了地,线就是通的。设备侧咱们就交到这儿,铃摘了,泵立了,线也探过了,往下该看帧自己怎么走。

## 一帧的旅行

一帧的进站,咱们跟着他走一遍。网卡把帧收进自己的收货环,泵的 poll 把他取出来交到栈的门口(e1000.cpp 的 :145,net_stack.cpp 的 :41 到 :49)。分发口问的事只有一件,以太头还在不在(net_stack.cpp 的 :55 到 :79):回环来的帧没有头,咱们一律当 IPv4 放行,有线来的帧按类型字分家。IPv4 的门里坐着词书与一道算术(ipv4.cpp 的 :43 到 :86):头的字读得动吗,声明的头长盖得住实际吗,校验和折不拢吗,三问有一样答不上的话,帧就死在门厅了,死因记在他自己的计数里。过了门,裸通道的观察哨看上一眼,观察哨是安在线上的眼睛,想旁听整条线的往来,找的就是他(:73 到 :75),接下来的事是按协议号发座,ICMP 的 1、TCP 的 6、UDP 的 17 各归各位,座号写在 net_config.hpp 的 :104 到 :118,派发的手续在 :77 到 :85。解头的词书有专门的住处,住处是一对叫 net_layout 的文件,咱们知道他是零状态的纯逻辑,当年拿纯逻辑的卷子考过身手,六个解析器的展开,本章是不做的。

座上的人各有各的接法。ICMP 的回声答门(icmp.cpp 的 :19 到 :28),进门折的第一道是校验和(:30 到 :35),折过了才答,UDP 与 TCP 把货卸进各自模块的桌,再送到套接字的环里,这一段的路咱们到 UDP 与 TCP 的节里细看。

回程的路由口在 route_send,他把手里的货按去处分成三路(net_world.cpp 的 :126 到 :154):发往自己的走回环,发往线上的查一查 ARP 的名册,名册里有 MAC 地址就直发,没有就造一封问路的信发出去,货撂在原地等名册回音。ARP 的名册是四条目的轮转缓存,lookup 查、observe 记、build_request 造信的本事,咱们都写在 arp.hpp 的 :36 到 :95 里。开机的四发 ping,走的就是问路加回声的全程(net_world.cpp 的 :172 到 :192)。

校验和的清单有四道,咱们在这里并排放好。IPv4 的头算一道,ICMP 的头与货算一道(收的时候折在 icmp.cpp 的 :30 到 :35,发的时候在 :47 到 :49),TCP 与 UDP 的伪首部各算一道,伪首部的十二个字节,源地址、目的地址、零、协议号、长度,折的时候跟载荷一起折。UDP 的算术有个绕:算出来恰好是零的话,线上发的是全一(udp.cpp 的 :108 到 :118),TCP 用的是同款。这道绕的来路是“零当免算”的老约定,发全一的意思就是告诉对门,我算过,结果真是零。

## socket 的脸:第五户,还是没路径的门牌

咱们在 5.7 见过两张脸,擦法擦出来的表,与手写的表,pipe 走的是手写。socket 也是同款的路子,全家共享一份手写的函数表(socket.cpp 的 :66 到 :80):

```cpp
const fs::FsOps kOps{
    .lookup     = nullptr,
    .make_file  = nullptr,
    .make_dir   = nullptr,
    .unlink     = nullptr,
    .read       = socket_read,
    .write      = socket_write,
    .read_dir   = nullptr,
    .stat       = socket_stat,
    .retain     = socket_retain,
    .release    = socket_release,
    .readable   = socket_readable,
    .ioctl      = nullptr,
    .adopt_open = nullptr,
};
```

socket 手写的十三格全在块里,咱们不逐格重念,与 5.7 的 pipe 表对看,差异的格子数得出来。pipe 的 readable 是空的,socket 的 readable 有主,转手的对象是 holds_input。pipe 的 try_read 与 try_write 是全树独一份的有主,socket 的两格压根是空的,填的人是没有的。名字侧的五格与 ioctl、adopt_open,两家是都空着的,stat、retain、release 与 read、write 的五格,两家是有主的,socket 这边转手的对象,换成了 receive 与 transmit。空得有它的道理,socket 生来没有路径的牵挂,他不归名字的那套流程管,他的门牌是一枚 FsNode,直接就坐进了 fd 表。5.7 收尾押的第五户,票在这里兑了。

门卫站在调用的门口。socket_of 头一件事是查外衣(sys_socket.cpp 的 :46 到 :58),咱们看 fd 背后的函数表不是 socket 家的,答的是 -ENOTSOCK,网络第三部(《UDP 与 socket》)教过的门卫,正身就是他了。accept 领人的时候铸的也是门牌:听者的候客座里有客了,accept_common 给来的客铸一枚 FsNode,再开一个新描述符挂上(sys_socket.cpp 的 :206 到 :258,门牌的手续在 :235 到 :247),客人拿到的号,背后是全家共用的函数表。5.7 把这两扇的来历押给了这一章,现在咱们兑:生号与 accept 领客的座,座号都要过那把软尺(sys_socket.cpp 的 :246 与 :329),两头走的是同一道手续。

地址的脸也值得一念。SocketAddress 一个结构两用(socket.hpp 的 :79 到 :87),inet 的场子装地址加端口,AF_UNIX 的场子装 108 字节的名字,门口分选的活归 family 字段。TCP 读到底的口径也在 socket 的脸上:对门道别、货读完了,read 答零(socket.cpp 的 :344 到 :358,NotFound 换成零的那一手在 :353 到 :356),Unix 的老口径,读到底送的就是 EOF。UDP 的空环答的是“再候”而不是零,两家的分别,咱们到 UDP 的节里对。

脸上还有一格空着的,咱们单独交底。ioctl 的格子是空的,可 ifconfig 的问话有得答:系统调用那一层做了特判,套接字的外衣一到手,问话就转给名册办事(sys_ioctl.cpp 的 :221 到 :222),SIOCGIFCONF 的答话归 answer_ifconf 办(:103 到 :105),办事的手在 :55 起,数据的家在 ifaces 的名册里,名册里报的本机地址,与 bind 认下的 10.0.2.15 是同一户(ifaces.cpp 的 :40,常数住在 net_config.hpp 的 :391)。

## 号位一次生齐

家族的号位,咱们照 Linux 的数一次生齐了十四个(syscall.hpp 的 :152 到 :165,分发的座次在 syscall_dispatch.cpp 的 :252 到 :271):

| 号 | 名 | 一句话的事 |
| --- | --- | --- |
| 41 | socket | 开一个通信端 |
| 42 | connect | 把对门的名字报给端 |
| 43 | accept | 答一声敲门,领一位客 |
| 44 | sendto | 一包出门,带着去处 |
| 45 | recvfrom | 一包进门,带着来路 |
| 48 | shutdown | 关一个方向或两个 |
| 49 | bind | 把端坐在一个地址上 |
| 50 | listen | 挂出牌子,说肯接客 |
| 51 | getsockname | 问自己坐在哪儿 |
| 52 | getpeername | 问对门是谁 |
| 53 | socketpair | 一口生成两个端 |
| 54 | setsockopt | 拧一个旋钮 |
| 55 | getsockopt | 读一个旋钮 |
| 288 | accept4 | accept 带描述符旗 |

缺的座咱们如实报:sendmsg 与 recvmsg 的 46、47 没有立,客人调了他们,分发表对他们倒是查无此人,面板上打的一行是 unserved,答 -ENOSYS(syscall_dispatch.cpp 的 :308 到 :313)。

socket() 的门后是三分叉(HandleSocket,sys_socket.cpp 的 :273 到 :335),咱们一门一门看过去。family 只认两家的号,AF_INET 的 2,AF_UNIX 的 1(:274 到 :277)。type 字里的两道旗剥出来记在描述符上,说的是 Cloexec 与 Nonblock(:279 到 :280)。然后按类型落了座,STREAM 坐进 TCP 的场子(:289 到 :293),DGRAM 坐进 UDP 的场子(:294 到 :298),RAW 的门只给 root,而且协议号必须是 ICMP(:299 到 :305)。RAW 的门槛为什么这么高?因为裸通道看见的是整条线,别的家的往来他都看得见,这样的视野不该落在寻常任务的桌上。

发送的天花板按家各有一道(send_ceiling_of,sys_socket.cpp 的 :138 到 :146):RAW 的一千四百八十字节,UDP 的一千四百七十二字节,流式的一千四百六十字节。数目是这么算的,咱们挨个算一遍。一帧的上限是一千五百字节,IP 的头占二十,RAW 从 IP 的货开始装,就装到一千四百八十了。UDP 再让八个字节装自己的头,就剩一千四百七十二了。流式的装法是按最大段长,一千五减 IP 的二十,再减 TCP 头的二十,剩一千四百六十(net_config.hpp 的 :353 到 :363)。

bind 认的地址有三样(HandleBind 的 :352 到 :356),全零的 0.0.0.0,本机地址 10.0.2.15,回环地址 127.0.0.1,三样之外的地址一律拒。拒得有理:锚树里能收信的地址就三个,报了也收不着。shutdown 只办一个方向(HandleShutdown 的 :489 到 :494):how 报了大过 2 的数,门答的是 -kEinval(:489 到 :490)。0 与 2 是收得下的,办不了的时候回的是 -kEopnotsupp(:492 到 :494)。办得了的数是 1,关的是写的那一半。读的那一半没立座,因为半闭的读要连着收窗一起想,收窗说的是收方的那扇窗,锚树里咱们只开了写这一半。

本章的旋钮有两件,咱们合在一起念。setsockopt 是看名下菜的(sys_socket.cpp 的 :616 到 :626):叫得出名字的旋钮,SO_ 家的四枚加 IP_TTL 的两枚,收下了就忘,存是一点不存的(:621 与 :626),叫不出名字的回 -kEnoprotoopt。这算不算骗客人?得两说:对码是留了门面,人家家的程序进门爱拧缓冲的尺寸,不收下的话人家连门都进不来。对读者咱们交底,旋钮是不生效的。getsockopt 有两问有名堂(:642 到 :646):问类型答家的类型,问收货缓冲的尺寸答环的总深,UDP 家的答法就是环深。

## 让位的圈:问信号,让一步,再试一把

4.4 教条件等待的时候,谱系票上的一句话是“转圈就是烧电,睡觉才是正路”。本章的正主偏偏就是一圈转,不过转得有章法,每一拍都是干干净净的:“试一把,看旗子,问信号,让一步,回来再试”。真睡与唤醒的令牌是锚树立定之后才接上的事,树里的骨架咱们如实按树讲,演进的后续开在延伸里。

正主的脸,咱们看 recvfrom 的圈(sys_socket.cpp 的 :454 到 :479):

```cpp
for (;;) {
    net::SocketAddress from{};
    const auto         kTaken = socket->receive(payload, kWant, &from);
    if (kTaken.ok()) {
        if (!uaccess::CopyToUser(frame.rsi, payload, kTaken.value())) {
            return -kEfault;
        }
        /* 略:把来路地址写回客人那儿的几行 */
        return static_cast<long long>(kTaken.value());
    }
    if (kTaken.error() != base::KernelError::kWouldBlock) {
        return errno_of_socket(kTaken.error());
    }
    if ((held->status_flags & kOpenNonblock) != 0 || (frame.r10 & kMsgDontwait) != 0) {
        return -kEagain;
    }
    if (signal_pending()) {
        return -kEintr;
    }
    proc::Scheduler::self().yield();
}
```

四拍咱们逐拍念。头一拍试一把:receive 有货的时候就连来路一起交,没货答的是 kWouldBlock,码的意思是“再候”。第二拍看的是旗子,fd 上挂了非阻塞旗,或者这一把带了 MSG_DONTWAIT 就不候,答的是 -EAGAIN(两道旗的值在 sys_socket.cpp 的 :40 到 :43)。第三拍问的是信号,signal_pending 为真的时候答 -EINTR,4.5 教的等待圈里那一问,正主就在这里接上了,而且每转一圈都自问一回,信号在圈里是闷不死的。第四拍让一步:yield 把 CPU 交出去了,轮到自己了再回来试。

骨架是全家共用的。accept 等客是同一副圈(sys_socket.cpp 的 :214 到 :234),听者自己挂了非阻塞旗就答 -EAGAIN(:227 到 :229),领了客铸门牌开新号,咱们上一节看过了。connect 走的也是这副圈,不过圈上多了一道期限:七十五秒(sys_socket.cpp 的 :383 到 :384),到点还没握上手的时候,答的是 -EINPROGRESS(:391 到 :392),对门拒了答 -ECONNREFUSED(:388 到 :389)。期限为什么立在 connect 而不在 accept?等客的人不怕等:没人来就没人来。敲门的人得有个说法,对门根本不在的时候,SYN 一封封地出去都是石沉大海,不给说法的话就是一辈子敲下去。

写的一侧还有一道礼数。往断了的连接上写的时候,transmit_wait 会看旗(sys_socket.cpp 的 :180 到 :201),客人没带 MSG_NOSIGNAL 的话,信号 SIGPIPE 就送到了任务身上(:187 到 :190),然后给出来的才是 -EPIPE。Unix 的老礼数,咱们在 5.5 挂过的 SIGPIPE 欠条,今天在 socket 的门里兑了。

代价咱们也照实说。圈每转一圈的工夫,任务都是醒着跑的,泵与别的活一起分 CPU,等的时候越久,烧的电越多,比真睡是费一点的。为什么锚树敢这么转?因为整台机器都是让位的世界,泵自己也是让位的,圈转起来不独占谁的时间。真睡长全了以后,这副圈的后半截会换成睡与唤醒,叫醒的差事交给令牌那样的信物。

## UDP 一家:端口、环与丢的计数

UDP 的门面是端口。全局的端口表开了八座(kUdpPortSeats,net_config.hpp 的 :174),bind 认座的手续在 udp.cpp 的 :134 到 :150,座满了拒,座被别人占了也拒。没绑端口就发的客人,咱们看内核从短命号码的号段里替他领的号,落在三万两千七百六十八到六万零九百九十九之间(net_config.hpp 的 :183 到 :190)。短命号码的号段为什么照 Linux 的数对齐?客人家的程序写惯了,短命端口的家就在这个段里,对齐了省得奇怪,网络第三部(《UDP 与 socket》)也是这么交代的。

到货的路,咱们从四层的座一路走到套接字的环。每只 UDP 套接字有一只自己的环,报文整只整只地排队,环开八格再多开一格(socket.hpp 的 :294 与 :365),多出来的一格是环自己分辨满与空的记号,货是不往里住的。环满了怎么办?泵替他抄货的时候,抄不进就丢掉新来的报文,丢的计数往上加一(socket.cpp 的 :200 到 :216,计数器的家就在 :200 到 :203)。为什么堵泵是坏主意?泵是全家的公仆,一只环不收货的话就把线停住,全家的报文都得陪他等,丢客记一笔是公道的代价。客人读的时候,空的环答的是“再候”而不是零(socket.cpp 的 :105 到 :120),整只报文边界不破地交,与 TCP 的流式读到底送零,是两家的分水岭。

进门时的词书咱们也要念。UDP 的 handle 头几行就是词书的问话(udp.cpp 的 :48 到 :60):头的字读得动吗,声明的长度出得了格吗,答不上就地拒。校验和带伪首部的绕,旅行的节里看过了,这里就不重念了。recvfrom 给客人填的来路地址,就是环里随包记下的那一笔,recvfrom 圈里省略的那几行,办的就是这件事。

## TCP 十态:连接的一生

TCP 的家底咱们盘一遍。连接座开了八座,听座开了四座,每个听座背后挂着二座的候客座,收窗的深是四千零九十六,四个数目都住在 net_config.hpp 的 :239 到 :262 一段里。座座都是有限的,满座回绝是有名有姓的,报的是自家的错误码,不排无边的队,网络四部一路的纪律就是这样。连接块上的家当,咱们挑重的看(tcp.hpp 的 :477 到 :529)。游标备了三根:最老未认、笔尖、期待对方下一笔,在 :499 到 :503 的地方。对门通告的窗在 :506。往返估算的平滑值与方差在 :486 到 :491。收件箱与底稿环各备了四千零九十六,在 :508 与 :510 的地方。修包座备了四座在 :512。同样的应答计了几声,计数的座在 :515。守程的座在 :523。

连接的一生,咱们在名册上记的是十个名字(tcp.hpp 的 :49 到 :70):

| 状态 | 是什么 |
| --- | --- |
| Closed | 门还关着,连接还不存在 |
| SynSent | 问名帖递出去了,等回帖 |
| SynReceived | 收到问名帖,回帖也递了,等收条 |
| Established | 生意做起来了 |
| FinWait1 | 自己的告别信递了,等回执 |
| FinWait2 | 告别信的回执到了,等对门的信 |
| CloseWait | 对门的信到了,自己的还没递 |
| Closing | 两边同时递信的岔路 |
| LastAck | 最后的回执递了,等收条 |
| TimeWait | 道别完了,多守一程 |

听的差事一句交代:listen 调用立的是听座(tcp.cpp 的 :530 起),门面上的手续走的是 begin_listen(sys_socket.cpp 的 :506),answer_unclaimed 来客时查的就是监听座(tcp.cpp 的 :301),监听座是听座在码里的名字,一户两叫的写法,经典图里的第十一名在枚举里没有座,树里的听是座上的事,不是名册上的名字。握手的两只手,咱们分头看。被动的一侧,answer_unclaimed 接住生面孔(tcp.cpp 的 :298 到 :329):听座后面有自由座就开一只新连接,座满的时候,当面回绝的是一记 RST 送客(拒客与回手的手续在 :303 到 :314),然后 SYN 加 ACK 一手递了回去,递回的手在 :316 到 :328。第三手纯 ACK 进了门,候客座自己立的软旗亮了,不是卡上那道摘了的铃,客人的连接票落进 accept 的队里(:420 到 :446,入队的手续在 :438 到 :445)。主动的一侧,connect 领了起始号、大步递进(:589 到 :621,递进的手在 :614),SYN 出了门,笔尖拨到号后一字(落点的一笔在 :617 到 :618)。两次握手的错在哪里?服务端不知道自己那一手到没到对门,所以收条必不可少,三手是缺一不立的。

道别走的是两封信四只手,咱们一只一只看。close 递了告别信,信占的号排在底稿的后头,字节补完了信才上路(tcp.cpp 的 :710 到 :740,主动侧的手在 :720 到 :728,被动侧的在 :729 到 :736)。主动方递了信等回执,FinWait1 转进 FinWait2 的座(:374 到 :376),对门的信到了落进 CloseWait,人家递完了转 LastAck,主动方收着最后的收条,转进了 TimeWait,岔路 Closing 处理两边同时递信(两边的一手在 :377 到 :378),LastAck 的座位在收条到手那刻释放(:380 到 :382)。半闭是真的半闭,shutdown 关了嘴,耳朵是还听着的。

> **道别完了多守两个最大段寿命,守的是什么?**
>
> 守的是两层,咱们一层层看。最后的那声收条也会丢,丢了的话对门会把告别信重发一遍,得有人在座上把这一声应了。旧连接的段还在海面上漂,同四元组的新连接要等海面干净了才开。教学值的一个最大段寿命是一秒,真栈倒是三十秒,咱们如实标注(net_config.hpp 的 :322 到 :330)。守程里同四元组的新 SYN 来了就静默让位,座位即刻让给新的握手。起始号的大步递进也是替旧段让路的手,让新旧连接的段在海面上分得清,与守程是同根的手笔。

等不着的回答,靠的是钟。重传的钟是时钟家里真座的 TimerTable,到点叫人(tcp.cpp 的 :1001 到 :1002):初值一秒(kTcpInitialRto,net_config.hpp 的 :282),每空等一回间隔就翻了一倍,封顶的时候停在六十四秒(:996 到 :1000)。五次花满了,放弃了,连接按不可达收场(收场的码在 :983 到 :991),连 RST 都省了,对门听不见了,发什么都是白费。往返的估算滚着样本走,平滑值加方差的路数,行李就挂在连接块上了。等不及钟的还有一条捷径:纯应答停在同一个期待号上,攒够了三声,补发最老的那段,不等钟也不占放弃的额度(absorb_ack 的 :363 到 :370,三声的常数在 net_config.hpp 的 :310)。Karn 的简化,重传过的段不采样,网络第四部(《TCP 完备》)里讲过的,咱们在这里对个表。

窗是收方说了算的。收窗的算术咱们一行就列完:四千零九十六减收件箱里躺着的,每个出站段的头里捎带着通告。发侧的两把尺取小,自家固定的一扇是四千零九十六(net_config.hpp 的 :272),对门的通告来了会回写(tcp.cpp 的 :347 与 :415),没通告之前两家默认同值(tcp.hpp 的 :506),谁小听谁的,取小的那一下在 tcp.cpp 的 :638 到 :639。满窗的写也有一句交底:连上了的满窗,写这门答的是零,一小格都是不收的(tcp.cpp 的 :640 到 :641),这时的零说的是这会儿一格也塞不进,不是对门收了摊,没连上的才在圈里再候(:631 到 :632),有零有整的短写是常态(:643 到 :644),非阻塞与 MSG_DONTWAIT 的客,答的是 -kEagain(sys_socket.cpp 的 :193 到 :194)。乱序的货有四个修包座接(kTcpReorderSeats,net_config.hpp 的 :320,座在 tcp.hpp 的 :512),起点恰好是期待号的货整座搬进收件箱,一茬收完了接着扫。

讲全了吗?没有,咱们也不打算讲满。拥塞控制是没有的。IP 是不分片的,树里的发送路径压根没有分片的工序,段长记的是一千四百六十,装不下的得上层自己拿主意。发窗的周期探活也没做,理由是两端都是自家的栈,收方排空了会主动说。骨架讲全了,剩下的细节,咱们留给网络第四部(《TCP 完备》)。

## 多路复用:epoll、eventfd 与 poll 两兄弟

复用要办的差事,是一个任务守着好几个口的活。写壳的时候要同时看键盘与网络,挨个转圈的办法就笨了,咱们把一堆口交给一处看,谁来了就应谁,这是复用的主意。这里说的口,是描述符的号,不是 UDP 那门的端口,两样咱们别混。epoll 一家占了四个号位(syscall.hpp 的 :116 到 :123),建例的 291,管座的 233,候事的 232,带掩码候事的 281。例的上限六十四,一座例里挂的口也至多六十四(:27 到 :28)。ctl 的三手各答各的:ADD 一座挂过的口,答的是 -EEXIST(:124 到 :125)。DEL 一座没挂过的,答的是 -ENOENT(:139 到 :140)。MOD 换了旗重挂,三手就齐了。候事之前是有一轮 scan 的(:197 到 :217),逐口问的是 readable 与 poll_events,出错的口与挂掉的口也一并报上来(:203 把两道错位并进旗单)。

wait 本身还是咱们熟悉的那副让位的圈(:264 到 :292):scan 一轮有货就交货,没有的话就问一声信号,再看看到点了没有,三样都不是的话就让一步回来再扫。用的圈是同一副,用的口径也是同一个,-EINTR 是在圈里等着信号的。

边缘触发的事,咱们立个简称,下文咱们都叫它边触,按树里的事实分三行摆。常数是真的在,kEdgeTriggered 是立在文件头上的,值是最高位那一枚(sys_epoll.cpp 的 :32)。门也是真的在,ctl 收旗的时候,旗单里带上边触或 ONESHOT 的,一律答的是 -EOPNOTSUPP(:252 到 :254),ONESHOT 想办的是一次一枚、响完自摘的事。门是朝里锁的,常数立了,门却是不开的,树里的读者看到的是拒绝边缘触发,念头是起过的。锚树立定之后的一次提交把边触接上了,那是树外的演进,去向咱们记在延伸里。

eventfd 其实是个哨子,号位占的是 290,门后一粒计数器(码在 sys_eventfd.cpp 的 :21 到 :24):咱们写一把加一把、读一把取走整把的数,信号量的姿势下每次只取一(:26 到 :44),数到顶了不再收。哨子的口也挂得进 epoll,守着计数器等的是非零,是复用名单上的正经一员。

poll 两兄弟是复用的老门面。poll 的号位是 7,不带掩码(sys_ppoll.cpp 的 :173 到 :209)。ppoll 的号位是 271,带的是掩码。掩码是真的,进门记下旧的(:137),客人的拷进来装上(:139 到 :146),出门的时候 restore_blocked 恢复回去(:157)。4.5 教的口径咱们在这里对表,真的换,出门真的恢复,armed 与 restore_blocked 两个名字都是码里现成的。装上的掩码是滤过一道再装的(kernel/syscall/signal.hpp 的 :90 到 :93),九号与十九号是进不来的,4.5 教过九号管杀、十九号管停的原话。epoll 那门的带掩码候事也是同款,旧的存下(:295),客人的拷进来装上(:301 到 :304),出口把恢复办了(:308),与 ppoll 是同一副的手法(sys_epoll.cpp 的 :293 到 :311)。

旧的注也有一案,咱们顺手交底。sys_ppoll.hpp 的头上有一段注(:52 到 :55),说掩码参数搭车是不查的,要等真睡的令牌才有。注说旧了话,码是真的,掩码装得上也恢复得了。这是 5.7 教过的:注是证人的话,码是实打实的物证,证人也是会记岔的,这里是第二例了。

## 本机通道:AF_UNIX 与 socketpair

AF_UNIX 的家是 LocalWorld,独立于 inet 栈:不过 IP,端口是一口不占的,名字就是 108 字节的一条字符串(local_config.hpp 的 :17,family 号 1 的家在 :15)。座位的家底咱们也有数:绑定名十六(:19),每端的队列八(:21),流方向的深是四千零九十六字节(:23)。他与回环其实是两回事,回环走的是栈的正门,他偏偏连门都不进,本机的两只端直接配对。

配对的枢纽是 Channel(local_socket.cpp 的 :25 到 :30),口与端的交底也在这儿立下:本节说的口就是端,一物两名的叫法,与 UDP 的端口是两样东西。两只口共享的是一只 Channel,Channel 里的 streams 两道、datagrams 两道,双向都是通的,0 号口写的流从 1 号口读出来,反过来也是一样的。pair_with 把两只 socket 拴上了同一只 Channel,一只认的是 side 0,另一只认的是 side 1(:148 到 :157)。socketpair 的门只认 AF_UNIX(sys_socket.cpp 的 :558 到 :559),咱们一手就能生成两只端,号是现成的两只 fd。

咱们拿 pipe 来对对表:pipe 的两只口一进一出,是单向的。socketpair 的两只端,各自都是能读能写的。pipe 的表是手写的,socket 的表也是手写的,同一张脸的两户,坐法倒是不同。

## 诚实边界

座位的家底都是硬数,咱们并排报一遍,每笔都带着码里的凭证:UDP 的端口表八座(net_config.hpp 的 :174),TCP 连接开了八座,听座开了四座,候客的座每听二座(net_config.hpp 的 :239 到 :262),修包座开了四座(net_config.hpp 的 :320),epoll 的例六十四、挂口六十四(sys_epoll.cpp 的 :27 到 :28),本地的绑定名十六(local_config.hpp 的 :19)。sendmsg 与 recvmsg 是没立的,调了答 -ENOSYS(syscall_dispatch.cpp 的 :308 到 :313)。RAW 的门只开给 root,进门要的协议号是 ICMP(sys_socket.cpp 的 :299 到 :305)。epoll 拒的是边触与 ONESHOT(sys_epoll.cpp 的 :252 到 :254),常数是真的在,门是不开的。带掩码的 poll 没有,ppoll 是有的,装得上也恢复得了(sys_ppoll.cpp 的 :137 到 :157)。拥塞控制是没有的,IP 是不分片的,段长记的是一千四百六十(net_config.hpp 的 :362 到 :363)。树里 grep 不出边触放行的码,拒绝是彻底的,这里报的边界,读者写程序的时候都得记在明处。

### 参考答案

第一题的答案,咱们把三家的下场挨个摆:UDP 客的环不再进新货,recvfrom 的圈空转。TCP 客写的货躺在底稿环里,重传的钟到点也没人叫,因为到点办事的 service 是替 TCP 干活的,而 service 本身是跑在 pump_once 里的。守程的座解不开,守程的客出不去。钟的结构还在,叫人的手停了,全家的线一根也动不了。

第二题的答案,三个减法咱们并排列:一帧一千五,RAW 减 IP 头的二十,剩的是一千四百八十。UDP 再减自己头的八,剩的是一千四百七十二。流式减 IP 的二十再减 TCP 头的二十,剩的是一千四百六十。流式是最短的,因为他的头最长,IP 与 TCP 的两顶帽子都扣着。

第三题的答案,咱们摆在一起看,是不矛盾的。常数是立着的,说的是有人开过这个念头。门是不开的,说的是树里这版没有收客的座。旗交进去的时候,当场拿回的是 -EOPNOTSUPP,拦下它的是 :252 到 :254 的两行。

第四题的答案,咱们对过表了:pipe 的两只口一进一出,是单向的。socketpair 的两只端,各自都是能读能写的,流与包两个方向都是走的。门是只认 AF_UNIX 的,因为配对走的是 LocalWorld 的 Channel,LocalWorld 是只住本机的,inet 的 family 进不了这门。

第五题的答案,咱们按码推演:ping 应答的是三声,那是冷名册的数,头一发花在 ARP 的问路上,正文 :42 交代的也是这个数。您手敲的时候名册是热的,发几发应的就是几声,冷名册那一发是开机才有的待遇。回环的 nc 两头都收得着,字节从自己的环里走了一遭。ifconfig 报的是 lo 与 eth0 两户,eth0 的地址是 10.0.2.15。SO_TYPE 答的是家的类型(:642 到 :643),SO_RCVBUF 答的是 UDP 环的容量积,算的是每格载荷乘格数(:644 到 :646),问不出名的旋钮,答的是 -kEnoprotoopt(:647 到 :648)。对不上的话,咱们按 5.7 第四题的老办法,把读到的原样带回来对码。
