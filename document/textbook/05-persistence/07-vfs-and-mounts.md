## open 的一整条链

一条 open 从客人的手里走到后端,要过的是至多六站,咱们按动手的次序一站一站走。入口是 HandleOpen(sys_open.cpp 的 :30 到 :36),他自己只办打头的折路:客人递来的路要折好,栈上装路的缓冲 storage 按 kFsPathMax 的尺开格,折的活交给 FoldUserPath(sys_path.cpp 的 :40 到 :55)。折路的这一步,5.1 讲全了:原始路的限长是 4096,折成的是从根起的、没有回头箭头的绝对路。为什么打头的是折路?因为门面认的是折好的路,折好的路里没有点与点点,后端的树也不认回头箭头。

第二站认的是门。接手的是 OpenPath(sys_open.cpp 的 :38 起),头一行拿折好的路找 FileWorld 认门(:39),回出来的是一枚 FsView,细则咱们留到后头数表的那段当面数。认门失败的,错就当场回给了客人。

第三站找的是名字,咱们看柜台递的是什么。柜台递给后端的已经是 lookup_held(:45),2.5 那会儿用的还是 lookup。held 两个字有讲究:找名字的交付,找着的当时就回了,看住也一并办了,两步并作了一步。可 open 找到了节点之后,还要 retain 一道的手续才敢立户口,两步之间要是别的任务 unlink 了一笔,节点就没命了。lookup_held 把找到并看住并成了一把交付,槽边的注写的是与 unlink 赛跑(vfs.hpp 的 :236)。后端自家没这手艺的怎么办?擦法替他兜底:拿 lookup 找到了,retain 的手续补上,再交出去(vfs.hpp 的 :328 到 :339)。兜底的做法不与 unlink 赛跑,可至少不是空着手回的。

第四站是 O_CREAT 的分岔(:46 到 :59),咱们跟着旗走。lookup_held 回了查无此人,旗里又带着创建的旗,柜台接过了旗,看的头一样是截断与读写的旗,两样都占着而后端又没挂 truncate 的格子,回的就是 -kEopnotsupp(:47 到 :50),免得客人白跑了一趟。过了这一问,请的是 make_file_held 现造一个。造完了还有半笔:客人递来的八进制模式位,创建的格子收不下,柜台再拿 chmod 把模式补盖了一回(:52 到 :59)。为什么拆成了两笔?held 格的签名里没有模式的座位,补盖是唯一的路。

第五站换的是节点。adopt_open(:65)管的正是开门的那一下,后端可以递回的是一枚别的节点,lookup_held 交出来的那枚临时持有,当场就 release 掉了(:66)。为什么开门的时候要换节点?名字查到的固然是名字,开门开到的,常常就不是名字本人了。devfs 的 ptmx 就是样板:您按 /dev/ptmx 这个名字来开,后端当场立起的是一副伪终端,递回来的节点是新立的那半边,5.5 讲伪终端的时候开过这场门,内里走的就是 adopt_open。ramfs 的答法是原样退回,retain 了再递回,没有换的故事,锚在后头讲 ramfs 的那段里。

第六站入的是表。files 的 alloc(:72 到 :79)发号,带上的是四样:状态位、close-on-exec 的旗、命脉的票,外加的是每任务的限额。命脉的票是挂载表发的,内里到讲挂载的那段咱们分开看。发号的章程,咱们在后面讲 fd 表的地方细看。号发了出去,adopt_open 递回的节点也 release 掉了(:80),户口里另有 retain 看着的,谁也不欠谁的。

尾巴上的两笔,咱们挨笔念。O_TRUNC 的一笔(:84 到 :94):带旗、带读写模式、又是普通文件的,才请得动后端的截断。后端没挂 truncate 的格子,按不支持的算,刚发的号当场收回了,错也回给了客人。截断失败的,一样是把号收回的。开出来的是字符设备的,还可能认下控制终端的差事(:96 到 :100):客人没带 O_NOCTTY 的,任务的手里还没有终端的,自己又是当会话首领的(sid 与 tgid 相等),柜台拿 ioctl 递过去的正是一道 TIOCSCTTY,答不答的,咱们都不等他。认终端的手续 5.5 讲过,这里接的只是线。

openat 是他的亲兄弟,咱们并排走一遍。路是相对的、dirfd 又不是 AT_FDCWD 的,走的是另一条梯:OpenPathAt(sys_open.cpp 的 :144 到 :195)不查挂载表,直接锚在 dirfd 手里的开档上,锚不是目录的,回的是 ENOTDIR(:150 到 :152),然后 lookup_at 拿手里的目录节点当了基座往下找(:157)。为什么绕开了挂载表?vfs.hpp 的 :185 到 :188 把话说直了:这一问按基座节点的身份作答,目录改了名、换了主、重挂了,从节点出发的相对路还认原来的意思,字符串是办不到这一层的。后端压根没挂 lookup_at 的,进门的守卫就拒了,回的是 -kEopnotsupp(sys_openat.cpp 的 :26 到 :28),已挂了这一问、后端答了不支持的,翻译的行号在后头诚实边界那段。creat 是懒人的写法(:22 到 :28),改了旗重入 HandleOpen,一个字都不另写的。fstatat 的那一头是同款,StatPathAt(sys_stat.cpp 的 :60 到 :95)也锚在 dirfd 的开档上,后端不认这一问的,回的也是 -kEopnotsupp,翻译的路数与 openat 那道特判是同一条。

## 脸的两半:十三法与二十四槽

脸是有两半的,咱们一层一层看。头的一半,咱们看的是概念。FileSystem(vfs.hpp 的 :117 到 :135)是一份编译期的考卷:一家后端要有 InodeType(节点怎么表记的在 :48 到 :52)、FsNode(租来的节点在 :64 到 :69)、FsStat(身家的格式在 :94 到 :104),还得把十三个本行法一道答齐了。找名字的 lookup、make_file、make_dir、unlink,读写内容的 read、write、ioctl,报清单的 read_dir,看身家的 stat,看引用的 retain、release,答读的 readable,开门换节的 adopt_open。文件头的注一句顶一句,十三个平平无奇的法(vfs.hpp 的 :5 到 :6)。缺了一门,考卷是当场不成立的,连擦法都是进不来的。

必答的凭什么是这十三?咱们挑几根说理。lookup 与 read_dir 是名字这一侧的根,找得到名字、报得出清单的,一家文件系统的架子才立得起来。read、write、ioctl 是内容这一侧的根。retain 与 release 是引用的看护,节点是租来的,租契的事就得有人看着生死,门面把看护的章程定死在了脸里。adopt_open 是开门换节点的权,上一节见过他的用场。readable 看着是单薄的,问答那一侧的门全靠他:一张脸连现在读不读得出都答不上的,问答的门就开不了。

再看擦出来的那一半。FsOps(vfs.hpp 的 :148 到 :240)是一整把二十四槽的函数指针,格格带的都是一个 void* 的 self。数法咱们念一遍:头的十三根是必答的转译。跟着的七根是可选的,lookup_at 与 make_file_at 管贴着目录的手,append 与 truncate 管的是尾巴,frame_at 管 mmap 的门,rename 与 chmod 管的是改名换装。再往后排的是 try_read 与 try_write 的两根,咱们叫他们探路的一对:动不成的时候,他们替您问一句能不能动。末了是 lookup_held 与 make_file_held 两根。

擦法 EraseFs(vfs.hpp 的 :252 到 :353)负责把概念的后端压进这把指针,装配分了三步。头的一步是十三枚必答的捕获(:255 到 :280),一家后端一支笔地写,十三根是一道写满的。走的第二步,是七根可选的逐格试探(:281 到 :327):if constexpr 配上了 requires,问一句这一户有没有这样的姿势,有这姿势的才挂上,没有的就留着空。第三步生成的是 lookup_held 与 make_file_held 两根,生成是无条件的(:328 到 :351):后端自带的就用后端的,没有的就拿 lookup 加 retain 兜底。try_read 与 try_write 的两根,擦法是从来不生的,空着的就是空着的,谁填的,后面讲没路径的门牌时咱们再见面。

```cpp
template <FileSystem Fs>
[[nodiscard]] constexpr FsOps EraseFs() {
    FsOps ops{
        [](void* self, std::string_view path) { return static_cast<Fs*>(self)->lookup(path); },
        // (余下十二枚必答捕获同一副擦法)
    };
    if constexpr (requires(Fs& backend, FsNode base, std::string_view rest) {
                      backend.lookup_at(base, rest);
                  }) {
        ops.lookup_at = [](void* self, FsNode base, std::string_view rest) {
            return static_cast<Fs*>(self)->lookup_at(base, rest);
        };
    }
    // (make_file_at、append、truncate、frame_at、rename、chmod 同一款试探)
    ops.lookup_held = [](void* self, std::string_view path) -> base::Result<FsNode> {
        auto& backend = *static_cast<Fs*>(self);
        if constexpr (requires { backend.lookup_held(path); }) {
            return backend.lookup_held(path);
        } else {
            auto node = backend.lookup(path);
            if (node.ok()) {
                backend.retain(node.value());
            }
            return node;
        }
    };
    // (make_file_held 同一款,拿 make_file 加 retain 兜底)
    return ops;
}
```

(EraseFs 的码是咱们节选的:七根可选的试探只展开 lookup_at 一处,两根 held 展开的是兜底的路)。

三条章程是一条都没动的。资格还是编译期验的,考卷还是挡在门口的。擦法还是机械生成的,人手是一支笔都用不上的。后端还是不报名字的,脸不收名字:您翻 ramfs.cpp、ext2.cpp,RamNode、Ext2 这样的名号都见得到,可脸上的格、表里的格,没有哪根是收名字的,类型名是挂载的人在 mount 那一刻报的,mounts_text 报的正是这一桩。变掉的是装配的心思:5.1 数到十五那会儿,擦法走的是全量生成,十五根是一格不落的。今天的擦法改成了有一问才有一格:本行是必答的,本事是可选的,各归各的格。

咱们还有一句老话,念给新读者。2.5 是讲过的,擦出来的每一支笔都无捕获,后端指针是不藏在笔里的,叫的时候作为头一个参数递进去。vfs.hpp 的 :246 到 :248 把这句写进了注:每一支转译笔都是无捕获的,后端指针是随叫随递的,从来是不往里存的。为什么?捕获会把别的状态封进笔里,函数指针的格子就装不下了。这是 2.5 立下的章程,今天的码照办。

## 一张认前缀的表

门面认的路,靠的是一张前缀表,咱们从挂载的手续看起。手续是 Vfs::mount(vfs.hpp 的 :438 到 :469)办的,参数是四样:前缀的字符串、后端的本体、类型的名字、命脉的票。类型名与票都带了默认,不报名字的当 unknown,不带票的当没有。进门的头一道关是形状问,问的全是字符串:空的前缀、不带头斜杠的、超长的、带尾斜杠的,一律回的是 kInvalidArgument(:443 到 :448)。重挂的也拒(:450 到 :454):同一条前缀挂了第二回,回的是 kAlreadyExists。擦法在这道手续里也用了一回,注里写的是,类型的擦除就发生在挂载的一刻,一座只此一回的(:434)。

插进表里的是一格 Slot(vfs.hpp 的 :532 到 :539),存的是六样:整把指针、后端指针、类型名、命脉票、前缀的长度、前缀的本体,票的格子空着的,就是不带票的座。表的容量在 fs_config.hpp 的 :55,数出来的是八席。动格子之前咱们得落闸(:441 到 :442),这把闸不是装样子的:resolve 是所有任务的 open 都要走的路,挨席全表扫(vfs.cpp 的 :41 到 :52),mount 与 umount 是动格子的人,两路会师了,读到的就是半新半旧的格子。表里的闸是自旋的一把(vfs.hpp 的 :542),FileWorld 那头挂座另有一把(file_world.hpp 的 :174),两把闸各守各的门。八席够不够用?开机立了三座,运行期的 tmpfs 一座,这个数咱们留到讲 tmpfs 那段回来看。

resolve 的细则,5.1 讲过的是章程与裁判那几行,本章补上没展开的几处。头的一处,是余路的剥法(vfs.cpp 的 :57 到 :60):剥掉的是胜出的前缀,归整的是剩下的斜杠,递给后端的路不带开头的斜线,后端从自家的根往下爬树。第二处是命脉的移交(vfs.cpp 的 :61 到 :65):mount 带了票的,resolve 把票 retain 了一道,塞进了 FsView。第三处是 FsView 的本体(vfs.hpp 的 :362 到 :367),套的是四样:整把指针、后端指针、余路、命脉票。为什么票要进视图?开着的档得替后端续命,后端卸载的时候还有档开着,票是不走的,后端也就拆不成了,下一节咱们细看。

表里存的类型名干什么用?报家门用的。mounts_text(vfs.cpp 的 :75 到 :93)把整表拼成文字,锁上了表闸才动笔(码在 :77),一席一行地排,格式串原样在 vfs.cpp 的 :83 到 :88,写的是 %s %s %s rw 0 0,喂进去的三样参数是 none、前缀、类型名,尾巴是写死的。/proc/mounts 读到的就是他,再过一道 procfs 的活源,锚在后头四户后端的那段。咱们照着格式推演,一台起机完成的机子读 /proc/mounts,该是下面的三行:

```text
none /      ext2     rw 0 0
none /dev   devtmpfs rw 0 0
none /proc  proc     rw 0 0
```

(咱们按码推演出来的样子,不是截的屏。类型名是挂载的人报的:根那座报 ext2(file_world.cpp 的 :74),/dev 那座报的是 devtmpfs(:107),/proc 那座报的是 proc(:111),三处的码咱们都核对过了)。

头一列为什么个个写着 none?咱们对着码看:设备名这一列还没有接线,码里给每一席递的都是同一个占位的 none,与 5.1 对过的口径是同一句。表真空的时候,挨席的那道圈一圈都不转,一行也出不了,读到的就是零个字节。

## 开机三挂载,运行期一座 tmpfs

表的户口是在 FileWorld 的手里。FileWorld(file_world.hpp 的 :58)是单例,同屋的还有 PMM 与 Tick,咱们的 FileWorld 排在他们后头出生。文件头的注把分工写白了(file_world.hpp 的 :12 到 :14):初始的挂载走 ext2,运行期的座给 ramfs。咱们把 init(file_world.cpp 的 :63 到 :113)从头读一遍。

票的本体(mount_lease.hpp 的 :16 到 :25):一张引用计数的票,怀里抱着后端本体与拆家的函数指针,析构的时候调拆。为什么拆家的手要封进票里?您想,卸载的人只认票,不认 RamFs 的类型,票自己知道怎么把自己拆了。这枚票押的是后端归谁,与 5.1 教过的票不是一回事,两样走的都是引用计数,咱们别把两张并成一张。票管的还不止拆家,还有命脉:resolve 的时候 retain 一张进视图,开档把票揣进的,是 lifetime 的格(open_file.hpp 的 :58),关完了最后一枚号,走的才是票本身了。

卸载的两头,5.2 教的是脾气,咱们今天对到行号。非 lazy 的卸载,票上还有外人拿着的,回的是 kWouldBlock(file_world.cpp 的 :170 到 :172),系统调用那头翻成的是 EBUSY,号是 5.2 对过的。带了 lazy 的,占用就不拦了,格子当场就摘掉了(:173),已经开出的档手里握着票,用起来是照样用的,使到最后一放手了才散,票在最后一份 release 的时候兑现拆家(:177 到 :179)。您问谁会来挂 tmpfs?用户态能开座的门就 mount 这一扇,他认的只有 tmpfs。所以在机子的运行期里,能多出来的座,只有内存里的那一座。四座都落定了,八席用掉的是一半。

## 四户后端的接缝

门面当模式用的说法,5.1 押过的,今天兑了。同一张脸底下住着四种脾气:devfs 是设备名背后的门,procfs 是活事实的只读目录,ramfs 是概念的第一例,ext2 是生产的根。四户各挑的是一扇接缝做特写,盘上的格式 5.2 讲过,设备名册的事 5.4 讲过,终端的事 5.5 讲过,咱们引过即走。

### devfs:设备名背后的门

devfs 的接缝在名字背后,咱们从这里看起。头一场户口是 RegisterBuiltinDevices 办的,码在 devfs.cpp 的 :63 到 :82,开头立的是 null 与 zero 的两座老住户。动态的住户走另一条路:set_dynamic_lookup(:84 到 :86)把找名字的差事交给一个回调,门牌背后站的是谁,查到的那一刻才知道。ptmx 就是这么挂进来的,RegisterPtyDevices(pty_node.cpp 的 :418 到 :430)把伪终端那一对手艺接上,接线在 :428 到 :429 的两行。5.5 讲的伪终端,讲的是门面这一侧,内里走的就是这道缝。

为什么查找要拖到 open 的一刻?您想,devfs 的住户不都是开机就定死的:伪终端是开一枚长一枚的,注册表追着铸对的节奏走,静态的表装不下这样的活户口。创建倒是硬气,一面的格子全空着,想造名字、想造目录、想摘名字的,一律回的是不支持,行号在后头的清单里。住户的名单由名册说了算,5.4 的地界。

### procfs:活事实的只读目录

procfs 的接缝是一张活源的桌。WireKernelProcSource(procfs_init.cpp 的 :200 到 :220)把内核的活事实接进目录:mounts 的行读的是挂载表的文本(:202 到 :205),快照与可执行影像的来路接在同一张桌上(:207 到 :211),名册的报名钩子也接了进来(:214),/proc/devices 就是名册拼出来的,5.4 押的那句话在这儿兑了现。为什么用活源不用快照?咱们想,活事实的脾气是下一秒就旧,快照是永远慢一步的,读一次算一次才是真的。

只读是刻在格子里的。写的格子拒人,创建与摘除的格子也空着,行号都在后头的清单里。读的时候,format_stat(procfs.cpp 的 :81 到 :96)把任务的身家按 Linux 的格式拼了二十四格,答不出的格子如实填零,终端号填的是零,tpgid 填的是负一。meminfo(procfs.cpp 的 :98 到 :120)是同样的脾气,有多少是报多少的。5.5 押过的是一句,ps 列不出进程的那桩案子,咱们把病根指到 procfs 侧 stat 的细目上,细目就是上面念过的这一段,案子的另一半在 ps 自己的解析里,那一半不在内核码的锚上,本章是不替他下断语的。

### ramfs:概念的第一例

ramfs 是 2.5 立概念时的第一例,今天的码就是概念的本尊。一家后端的活,一个实现文件是装得下的,名字怎么找的、文件怎么造的、目录怎么列的、节点怎么租怎么还的,十三个本行法一格一格地摆开。您问概念为什么挑他当第一例?他是全树最素的文件系统:没有盘、没有块、没有元数据的格式,从内存里立起来的,回内存里散掉的。读懂了他,再看 devfs 与 procfs 的接缝,再看 ext2 的接缝,路是由素入繁的。

换节点的答法,咱们读到的是原样退回(ramfs.cpp 的 :267 到 :270),retain 了再递回,没有换的故事。还有一处咱们得交代:修改时刻的那一栏永远报零(ramfs.cpp 的 :279),答不上的就答不上。

### ext2:认形状的根

ext2 的接缝在盘上。背着的还是同一张脸,坐的是块缓存与值班队列,5.2 与 5.4 的全部地界都从这道缝里过。他的脾气是认形状,咱们跟着进门看一眼:头一口气查的,就是盘的形状(ext2.cpp 的 :82 到 :84),块组的计数有一道上限把着(:95 到 :96)。为什么进门就要查?盘是外面的世界,外面递来的东西不能信,脸要护住门面里的所有人。

树里的两处怪脾气也各有记录,咱们挨处看。从根往上找父目录的,回的是不支持,根是没有父的,这在数学上是定死的。绝对路径的符号链接,回的也是不支持,两处行号都在后头的清单里。重命名与改权限是他自带的两根可选姿势(ext2.hpp 的 :310 与 :312),擦法试探到了,就替他挂上了。写入的边界 5.2 讲过,双间接到头就是真的到头了,再往上走就得报错了。

## 地板是零:fd 表的真形状

fd 表的家底 5.1 教了一半,本章补的是剩下的形状,咱们把形状数全。表的容量在 file_table.hpp 的 :33 到 :34,1024 乘 1024 的积,数出来的是一百零四万八千五百七十六席。发号的章程写在类的注里(file_table.hpp 的 :50 到 :56),注里写着的原话,说的是发号永远取最低的空位,零也是在内的。照着这句注办事的,是 file_table.cpp 的 :99 到 :115:从 0 起扫(vacant_locked(0) 在 :103),找到头一格空的,立一份 OpenFile 的户口(:108),节点 retain 了一道(:111)。

## 本章留下了什么

这一章把门面的内里交齐了,咱们把总目数一遍,5.1 悬着的那一笔,债主今天到站了。open 的全链路至多六站,现造的那一步看的是旗。脸的两半,头一半是概念的十三法,擦出来的是二十四槽,装配是有一问才有一格的。挂载表认的是前缀,赢的是最长者,容量数出来的是八席,动格子走的是一道闸。开机挂的是三座,运行期添的是 tmpfs,四座齐了,八席用掉的是一半。四户后端的接缝,一户看了一扇。fd 表的地板是零,3 号是算出来的,受理调用的时候软尺与硬顶比的是小。pipe 是没路径的门牌,ustar 退了场。诚实的边界里,kNotSupported 的格子一格一格列在了案。

| seat_console_streams | 起机把 /dev/console 开成一份户口,坐满 0、1、2 三座的手续 |

交底的话有两句,咱们放在这里。socket 的座位排在后头,他也是没路径的门牌,同一张脸的第五户,那一章开了再讲。挂载表哪天真要超座了,头一个动的就是容量的那一行。

## 练一练

第一题走的是 open 的链路。`open("/dev/console")` 从系统调用的门进去,一路走到后端的柜台,您数一数要过的是哪几站?到了 devfs 的户里,递过去的是整条路还是余路?这一户的命脉票有还是没有,为什么有的有、有的没有?

第二题算的是 fd 的涌现。一个生下来 fd 表就空着的任务,头一枚 open 拿的是几号?壳手底下的任务,头一枚 open 拿的又是几号?差的 0、1、2 三个号,您说说,是谁、在什么时候、用什么手续坐上去的?

第三题读的是 EraseFs 的码。面对一家十三法齐全、一件可选姿势都不挂的后端,您猜生出来的表是什么样子?这时候客人调的是 lookup_held,走的是哪一条路?再把 pipe 摆上来对一对:pipe 的表是谁写的,与擦出来的差在哪几格?

第四题动的是手,咱们上机对一对。拿正文推演的挂载表当底,机子起好了,您把 /proc/mounts 读一回,数一数出来的是几行,每行的头一列是不是 none,尾巴是不是写死的 rw 0 0。再挂一座内存里的 tmpfs,数一数是四行还是又添了一行,类型名那一栏写的又是什么。预期咱们按码推演,读的家什念不念得动这三行,咱们不打包票,盘上的 ext2 要是没接好,推演的对照也照样收。

### 参考答案

第一题的答案,咱们一站一站数:折路的是 FoldUserPath,认门的是 resolve,找名字的是 lookup_held,换节点的是 adopt_open,入表的是 alloc。这一单 lookup 一步就答中了,而创建旗也没带,现造的那一步不开门,咱们数下来是五站。递给后端的是余路 console,前缀 /dev 已经被挂载表剥掉了。票是没有的:开机三挂载走的是不带票的 mount,票是运行期 tmpfs 独有的家什,devfs 的这座起机就立好了。

第二题的答案,咱们把两个头都摆上来,两个的头都是从零算起的。空表的头一枚 open 拿 0 号,表从最低的空位发号,零也是在内的。壳那头的任务拿的是 3 号:起机的时候,seat_console_streams 把 /dev/console 开成了一份户口,adopt_at 三连坐满了 0、1、2,三座坐的是同一份户口,头一个空位就顺势落到了 3。差出来的 0、1、2 三个号,fd 表自己是从来没有立过的,坐上去的是起机时的标准流手续。

第三题的答案,咱们逐格念。必答的十三格是满的,七根可选的格全空,两根 held 走的是兜底,lookup 找着了,retain 的手续补上,交了出去。try 的两格也空,他们本来就不归擦法管的。pipe 的表是自家手写的静态一份,姓的不是擦法:名字那一侧的格子,与 readable、ioctl、adopt_open 的三格,全都是空的。在岗的七格,念的是 read、write、stat、retain、release,外加的是 try_read 与 try_write 的两格,两格是全树唯一有主的。

第四题的答案,咱们按码推演:起机完成是三行,打头的都是 none,收尾的都是 rw 0 0,样子就是正文推演的那三行。再挂一座 tmpfs 的话,表里就是四行了,新添的那一行类型名写的是 tmpfs,首列还是 none 的占位。对不上的时候,把读到的原样带回来,咱们再对码。
