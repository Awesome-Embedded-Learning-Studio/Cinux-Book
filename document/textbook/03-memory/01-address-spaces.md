# 01 · 地址空间:一套表,一记抄,一条回家路

客人从首跳拍完到今天一直还在机器里当自己的值。上一部收工的时候,机器停在 cinux> 后头等您敲字,您不敲,他就不走:echo 替您回话,而 yield 替他让路,跟柜台开张那天的样子一个样。可他在楼下踩着的那片地,咱们到今天没看过全貌。首跳的那一幕拍得仔细,cli、activate、跳板五条的每一拍都拍了进去,拍的只是动作的次序。他脚下的地界是谁画的、画了多大、凭什么内核在他当值的每一拍里还看得见自己,那一幕只给了半句,全本其实没摊开。这一章咱们把全本交出来。

2.5 收卷时把话留在了那儿:地址空间排在《内存》名下,内存自己的正戏留给下一部,锣是今天开的。1.4 还有一句更早的期票,boot 只手铺的三张表、恒等映射的 8MB,那儿其实不铺高速公路,真正的页表体系是第 3 部的正戏。期票到这儿算到了日子,兑现的大头还在后头,所以今天这一章,咱们把整套机构在地基里立起来,立到客人能搬进去住的程度。

这一章的活,咱们数下来有三样。头一样的活是认 AddressSpace,行话叫地址空间:一个世界一套页表,世界这个词是正文《内存当家》那一卷叫开的,咱们接着把它叫顺。再一样是看客人的世界怎么画:0x400000 上的一枚代码页,0x500000 上的一枚栈页,画页的 map_user 凭什么一位都不能省。末一样是走一遍搬家的手续:activate 怎么把机器搬进新世界,搬进去了,回家的路在哪,咱们顺带回答开头那问,客人当值的时候,内核凭什么还看得见自己。

量法还是照旧的三条。码的事,是自家 kernel/mm/ 底下的四件,layout.hpp 管的是图,address_space.hpp 与 address_space.cpp 管的是世界,vmm.hpp 管内核自家的表页从哪来,咱们逐段读。屏的事,自家起机抄了,机器还是首跳的那一版。书的事,xv6 翻到了第 3 章,书页 33、38 与 39 三页逐字核过了,原话整段请了进来当面比。Linux 那头这一章咱们交白卷,缘故咱们留到对照节交代。

> **客人下楼的家底,咱们只数过步数:他脚下的地界凭什么画得出来?他当值的每一拍,内核又凭什么看得见自己?**
>
> 两问共用的其实是同一个答案。address_space.hpp 的头注,笔者落笔的头一句是 `One world of translations: a PML4 the kernel can enter.`,说的就是一个世界、一整套的翻译、一张内核进得去的 PML4。世界怎么立起来,客人的地怎么画进去,机器怎么搬进去、又怎么回得来,全在这句话的两半里,这一章其实就是给它作注。

## 一套表,立起一个世界

咱们从脸认起 AddressSpace 这个类。address_space.hpp 里的六张脸,咱们挨张认:init 立起一套页表,root 报出这套表的根,map 与 map_user 往世界里挂的是页,一个伺候内核自己的页,一个伺候客人的页,translate 拿虚拟门牌换出的是物理门牌,activate 管的是把机器整个搬进这个世界。类注里交代了一句,`Place instances in static storage`,实例请搁在静态的住处,注里把缘故也写了,内核的栈浅,深不到能糟蹋一份家当的地步,这样的对象天生该住静态的地。六张脸各管各的摊,谁也不越谁的界,本节认头三样:世界怎么立,表页的来路在哪,藏谜底的是哪一抄。

世界不是咱们新造的词。正文《内存当家:一页一页地精修》那一卷里,AddressSpace 的全本叙事住在《换世界》一节,那卷的话说得直白,一个 AddressSpace 就是一个世界:它自己的一套页表,自己的用户半边,想进就装它的根,想走的话就换回来。教科书层到今天把这套话接了过来,对着自家的码一块块落到实处。空户口的说法,2.1 的实况里叫过一回,户口空在哪、怎么就不空了,咱们今天看码。

init 的身子在 address_space.cpp 的 :28 到 :40,咱们整个看:

```cpp
bool AddressSpace::init() {
    base::PhysAddr const kFrame = Pmm::self().allocate_page();
    if (kFrame == base::PhysAddr{}) {
        return false;
    }
    auto* const kFresh = cinux::base::PtrAt<Entry>(DirectMapVirt(kFrame.raw));
    cinux::base::SetBytes(kFresh, 0, cinux::arch::page::kSize);
    auto* const kKernel = cinux::base::PtrAt<Entry>(DirectMapVirt(KernelPageRoot()));
    cinux::base::CopyBytes(kFresh + kKernelHalfSlots, kKernel + kKernelHalfSlots,
                           kKernelHalfSlots * kSlotBytes);
    root_ = kFrame.raw;
    return true;
}
```

咱们把四步一步一步对下来。头一步走的是 :29,咱们向名册领一页,Pmm 发出来的这枚物理页,就是新世界的 PML4。下一行把物理址换成能下手的门牌,法子是加一枚写死的基数,这桩换算的行话叫直接映射,口径的事几段之后再细认。名册的脾气 1.7 认过:一位管一页,领页本身的手续,归在《物理内存管理》的名下。领失败了,init 回的是 false,世界就立不起来了,后续的事调用方自己看着办。第二步的活落在 :34,SetBytes 把整页清成了零。清零是页表的出厂纪律,正文那一卷立过它的分量:表页带着上一任的残留上岗,残留里最低位恰好是 1 的项,CPU 一查就当真有了映射,translate 翻回莫名其妙的址,写一枚门牌改的却是别家的地,重启了一回,残留换了,症状跟着换了一副面孔。所以凡是新页上岗当表,交接的前提是全零,这儿的一道工序都不省。

第三步是全场最要紧的一抄。咱们在 :36 到 :37 把现役根的高半、256 到 511 项整段原样抄进新页,kKernelHalfSlots 这个名字记的就是 256。为什么抄的是这半边、抄的为什么恰好够?咱们想一件事:换世界的那一拍,正在跑的代码是谁,答的就是内核。它脚下的路、手里的栈、串口的驱动、屏幕的字库,全住在高半的门牌里。新世界要是只有客人的半边,LoadCr3 装进去的那一拍,取指的路当场就断,机器连最后的一声都来不及出。所以每个世界生下来,内核的半边必须整副都在。您要问凭什么客人当值的时候内核还看得见自己,谜底就是这一抄:高半是抄来的,所以谁上场都在。正文那一卷给这一抄留的名字就叫那一抄,还点破了一层妙处:抄的只是 PML4 这一层,底下的 PDPT、PD、PT 一张没动,PT 排的是末一级,行话叫的是叶子,各个世界共享的还是那几张表,多花的内存一分没有。

末一步的活在 :38,root_ 把领来的页记下了,这就是这个世界的根,root 报的也是它。世界的家底从它起头,咱们往里挂页,挂的就是它。顺带交代一重保险:init 没跑成的世界,root_ 躺在了零上,map、map_user 进门头一句问的就是根在不在,是零的话就回 false,translate 问的是同样的话,是零的话也回 0。没立起来的世界,页是挂不上的,址也是翻不出的,所以三张脸谁都不含糊。

世界立了起来只是开始,往里挂页的日子还长。map、map_user、translate 的三张脸,身后走的是同一条道:顺着四级表一级一级往下走。缺了表,map 两张脸就地补,translate 报的只是零,共用的正是同一条往下的道。补表的页从哪来,归的是 KernelTables,vmm.hpp 里它的两张差事写得明白:table() 拿表页的物理址换出可写的门牌,换的法子是加一枚写死的基数,物理址加的是多少,得出来的门牌就是多少,这片窗在行话里的名字是直接映射窗,全本在正文《挂在墙上的地图》里,咱们借个名就行。take_page() 向名册领的是一枚新页,领出来照例清了零再交货。三张脸的身子,咱们把 map 整个请出来,余下两张您对着看:

```cpp
bool AddressSpace::map(unsigned long virtual_address, unsigned long physical) const {
    if (root_ == 0) {
        return false;
    }
    KernelTables tables;
    return MapPage(tables, root_, virtual_address, physical);
}
```

进门头一句问的都是根在不在,没立起来的世界,咱们挂页挂不进,翻译的活翻不出。跟着造的是一枚 KernelTables,把表页的来路递给走查,咱们看末一行,三处各请各的脸:map 请 MapPage,map_user 请的是 MapUserPage,translate 请的是 TranslatePage。至于走查逐级怎么走、缺表时谁补谁报零,本章借的只是一句话,三张脸共用同一条往下的道,根是递进去的参数,机器脚下的 CR3 动都不动,给不在场的世界画图,凭的就是递进去的那枚根。细目是下一章的正戏,咱们在这儿一行都不展开。

## 客人的世界,两枚门牌起家

新世界的低半边起手是纯零,客人的家当全得一笔一笔画。眼下机器里的客人就一位:shell,他家的画法在 kernel.cpp 的 :159 到 :169,首跳里咱们只认了次序,今天连图带纸一起看了。头一枚门牌是代码的,kUserCodeBase 定在了 0x400000,页面的本体不在别处,就编在内核镜像里:链接符号 g_user_shell_start 报出它的高半住址,减掉的就是 kKernelImageBase,得出来的物理址是 0x20a000,咱们一发 `map_user(0x400000, 0x20a000)`,同一页的字节,从此在客人的世界里也认得门牌了,本尊的个头是 0x4dd 个字节,一枚页装下了它还绰绰有余。栈的那一页是另请的,Pmm 在 :166 分的是一枚物理页,:169 映到 kUserStackBase 定下的 0x500000 上,跳板接的栈顶是这枚页的页顶。门牌画了两枚,地占了两页,客人的世界开张。

地界上还有一条小约定,咱们顺手认了。客人的门牌从零起数,可最低的 64KiB,layout.hpp 给它立了常量 kUserNullTop,划成永不映射的地。C 的空指针是 0,客人哪天解引用了一个没立起来的指针,踩的就是这块注定没映射的地,14 号的报到干净利落,不会拿着 0 号址真去够到什么要紧的东西。约定的全本在正文《挂在墙上的地图》里,用户半边的约定拢共五条,本章用到的就它与天花板,余下的等用着它们的章节再认。

map_user 与 map 的差处在哪儿,差的那枚开关得单独摆上桌。页表项的低位里躺着几枚开关:第 0 位管在不在,第 1 位管的是可写不可写,第 2 位的差事,page_entry.hpp 的注释写成了英文,`ring 3 may walk through this entry`,问的就是这一级许不许客人路过,kUser 就是它的真身。脾气是硬件给的,注释下一句也写了,一路下到叶子的每一级都得带,哪一级没带的话,整条路对 ring 3 就地封死。道理摆在 CPU 的那头:查表每过一级,机器都拿当下的特权级验一遍权限,任何一级写着仅内核的话,ring 3 的脚就迈不过那一级。AddressSpace::map_user 的注释把利害交了底,`without it the page is kernel-only even in the low half`,位不带的话,页就归了内核独享,哪怕它住的是低半。当年的第一遍在这儿摔过一跤,咱们把现场复述一遍:叶子把位带足了,中间一级漏了,客人在门口就吃了 14 号。这一遍把病根治在了走查里,路上新起的每张中间表一出生就带着位,正文《客人的世界》里逐级验过。map_user 挂出去的每一页,四级全带上了位,客人才真正下得了楼。

画出去的地也得查得回来。translate 拿着一枚虚拟的门牌走一遍表,把物理址翻了出来,查无此页的时候,回的是 0。这个 0 眼下安安静静的,咱们等会儿在停一停里跟它打交道。

## 换世界,与回家的路

世界立好了,客人的地画好了,轮到机器搬家了。activate 的身子在 address_space.cpp 的 :70 到 :74,咱们整个看:

```cpp
void AddressSpace::activate() const {
    if (root_ != 0) {
        cinux::arch::LoadCr3(root_);
    }
}
```

咱们的实活就一行,root_ 不为零的话,调的就是 `LoadCr3(root_)`。CR3 是控制寄存器里记根的那一枚,1.4 换长模式的时候它在场,那时里头装的是 boot 手铺那套页表的根。现役这个词是 2.1 头一回用的,LoadCr3 把新户口换成了现役,这一章咱们请它正式当主角:CR3 里装的是谁的根,机器就住在谁的世界里,activate 换的就是这一枚。装它之前有一道纪律:中断是得关着的,kernel.cpp 的 :172 到 :174,cli、activate、JumpToRing3 的三步连着走。担子都在高半的这一边:桩也好,桩后面的服务也好,全住在内核的门牌里,这一层镜像替咱们保着,所以搬进哪个世界都不慌。真怕的只有一件事:切到一半钟响,处理手续把世界又切走了,机器落在一个谁也没画全的半路上。所以 cli 排在 activate 头里,搬家的那几拍,咱们一个中断都不放进来。跳板落地,客人旗里的 IF 自己立着,楼下的世界照常听钟。

回家的路也得备好。KernelPageRoot 住在 vmm.hpp 的 :96 到 :108,头注里笔者写的是 `this stays the road home`。接管落成的那天,内核把自家的根存进了定格,正文那一卷给它起的就是这个名字。从 activate 出现的那一拍起,CR3 成了变量,谁上场它记的就是谁,KernelPageRoot() 读的永远是那枚定格。哪天想回家的话,咱们调一句 `LoadCr3(KernelPageRoot())`,机器回到内核自己的世界。

那首跳之后的机器,现役是谁?是客人。:171 把客人的根记进任务的 user_root,记档不是白记的,proc/task_runtime.cpp 里的 arm_task_entry 读它:换任务装栈那一拍,谁的 user_root 非零就装谁的根,是零的话,装回家的定格,内核自己人的格子里躺的就是零。装根之前它还要比对一眼:ReadCr3() 读出来跟要装的根一样,它就不重装了。所以 yield 那单的一个来回,屏上只多了两行,底下连世界都没换:串口、键盘、调度这些内核的差事,全借高半的镜像,在客人的世界里照常办。您回头看实况里 echo 与 yield 的来回,客人当值的整段时间,机器就停在他的世界里,一步的位置都没挪。咱们的机器里同时住着两个世界,这在装根前的那一眼比对里看得见,arm_task_entry 的 ReadCr3 就是那双眼。真到多位客人轮着上场的那天,换任务就成了换世界,机构已经长在道上了。

**咱们停一停,把客人的天空量一量。** 客人的地界从零往上,可它是有顶的。您把顶画在哪个数上、凭什么画在那儿,自己推一推?

顶画在了 0x0000800000000000。layout.hpp 的 :161 立着断言,写的等式是 kUserTop 等于 1 左移 47 位,消息写的是 `user half ends at the canonical boundary`。这个数您自己折一折,2 的 47 次方,折成平常的单位是 128TiB。x86_64 的地址名义上 64 位,规定上真能用的却是 48 位,高 16 位的填法是仿照第 47 位填满,填出来才叫规范地址,行话叫的是 canonical。第 47 位定的是两半的去向:填 0 落的是低半,填 1 落的是高半,0x0000800000000000 恰好骑在两半的分界上。客人住的是低半,顶就画在了这道分界线上。还有同值两名的一对得点一句:syscall.hpp 里管岗的叫 kUserAddressLimit,layout.hpp 里管图的叫 kUserTop,起的两个名字,记的是同一个数,岗上的天花板,就是地图上那道线,名字跟着各自的东家走,数是没有第二枚的。顺带把两半的宽度也量了:中线以下 128TiB,以上到顶的也是 128TiB,客人与内核的两家各得一半,谁也不占谁的份。

**咱们停一停,替没有的那一页想一想。** translate 查无此页的时候回 0,那客人真的一脚踩在没映射的址上,您说谁来接他?

咱们把现场摆开。2.3 试探的那回,递给柜台的是一枚低半区里没映射的址,天花板是拦不住它的,岗的脾气是拦高不拦空,内核自己伸手去够了一下,挨了一记 14 号。客人自己踩空也是同一号:报告的机构 2.2 立起来了,14 号的缺页会来报到,可把报告接住往下修的手续,咱们还没往机器里安,报告到了也只能停在报告上。至于岗为什么拦得住高拦不住空,translate 与走查这两件器械其实已经在这章的桌上躺着,查的正是有没有。把逐字验空的活接到岗上去,是下一章的正戏。

## Code: Cinux 实况:面板四行,认两行,四单会话

机器还是首跳的那一版,实况锚的名下还是 r13_userspace,2.1 首跳用的也是它,切版、构建、起机的老话那边念全了,不重印了。有一条老话值得咱们再念一遍:镜像得显式重打,拿陈旧镜像开了机,开出来的还是上一版的机器,面板的数对不上号,您会白疑一圈。喂键的法门 2.3 交过底,monitor 接的是 stdio,字母递的原样,空格递的是 sendkey spc,回车递的是 sendkey ret。起了机,等面板长齐了,咱们从 kernel 那行往下抄:

```text
[kern] kernel at 200000 size 90A20 entry 200040
[kern] pmm: 32316 pages free (probe 113000 ok)
[kern] vmm: address space up, magic 114514
[kern] heap: new/delete live (probe 114514)
```

咱们把四行逐行认。kernel 那行是 1.8 拿户口本认过的交接单,个头是随版本长的,这一版念的是 90A20。pmm 报的是 32316,2.3 的屏上就是它,同一版的机器数不换。2.4 的 32336 与 2.5 的 32309 是别的版本各自的读数,您别到这一章来找对照。vmm 与 heap 的两行,2.3 那回认过的只有名,堆的去处当时就记在了第 3 部名下。今天开讲的是 vmm 这行,heap 的那行只指个住处。vmm 行是本章的主角:address space up,内核自家的世界立起来了。boot 交接的门牌,在这一拍换成公布的地图,layout.hpp 画的图从纸面落到了机器上。magic 后头的那枚 114514,屏上是什么就是什么,来历咱们没考证过,咱们不编。heap 的那行,来路就是 2.1 说的后面几卷,住处在《物理内存管理》名下:整页怎么切成零钱,new 和 delete 怎么开的张,动工的事本章不接。

面板往下是六位任务的三场拉练,2.4 逐场读过的排场,咱们翻到收尾。从 kernel.cpp 的 :155 那声报幕起,末段屏咱们整块抄到 exit 落定,档里长什么样,纸上长什么样:

```text
[kern] launching shell in ring 3
cinux shell - type 'help'
cinux> help
commands: echo <text...>, help, yield, exit
cinux> echo two worlds one machine
two worlds one machine
cinux> yield
yielded and back
cinux> exit
```

报幕的那一拍,咱们读过的手续正一件件跑:init 立起新世界,两发 map_user 画好客人的家,user_root 记了档,cli、activate、跳板五条的连招走完,执行流下了楼。跟着的两行横幅与提示符,全出自 ring 3 里的 shell,递的法子 2.1 拍过,一整串的横幅,一回 write 递完了。

咱们把四单逐单过。help 报的是家当,单字命令是当场应答的,2.5 那版一声不吭吞掉单字的脾气是后来的事,两版您别混。echo 把咱们递的话原样回了出来,回来的正是 two worlds one machine,机器一台、世界两个的意思都全了,这句话落在这一章的屏上,正好替咱们把题目喊了一遍:递话的是客人的世界,回话的手是内核的,一递一回过的都是同一台物理机器。yield 让了一圈回来,exit 敲了下去,串口的那头再无一行,这一版的壳,exit 是真的退了场。机器自己是不会断电的,收场交给了 timeout,2.1 交代过的老话,不重念了。

## 对照:同一件事,别的机器怎么做

咱们把 xv6 翻到第 3 章。头一段的位置在书页 33,讲的是权限位:

> 咱们把原话整段逐字请来:`PTE_U controls whether instructions in user mode are allowed to access the page; if PTE_U is not set, the PTE can be used only in supervisor mode.`

PTE_U 与咱们的 kUser 是同一枚开关的两家叫法:名字里的 PTE 就是页表项的缩写,位是长在项上的,是不跟随页走的,ring 3 想过的话,过的每一级都得带,咱们把 kUser 带在四级上。办的是同一桩差事,位号倒是各家排各家的,您哪天对着位号比两家的表,记得各按各家的项格式来。

第二段的位置在书页 38,咱们看一人一表:

> 咱们逐字请:`Each process has its own page table, and when xv6 switches between processes, it also changes page tables.`

换表的手势,咱们把书页 33 上紧挨着权限位的那一句请出来,它写的是最直白的一句:

> 原话咱们也请全:`To tell a CPU to use a page table, the kernel must write the physical address of the root page-table page into the satp register.`

把根的物理址装进 satp,机器就换了世界,咱们拿 activate 的 LoadCr3 跟它一字不差地对上,连装的必须是物理址这层细节都一样。内核在客人的世界里怎么安置,两家就分了岔,书页 39 的原话把它的安置说了明白:

> 咱们对着原话看它的安置:`Third, the kernel maps a page with trampoline code at the top of the user address space (without PTE_U), thus a single page of physical memory shows up in all address spaces, but can be used only by the kernel.`

它家的办法,是往客人的表里只画一页连 PTE_U 都不带的跳板。客人当值的每一拍里,内核的本尊不在他的表里。咱们把高半整副都画了:那一抄让每个世界出生就整副带着内核,所以谁上场都在。

咱们在书页 38 还找得到它守边姿势的原话:

> 原话咱们整段请来:`To detect a user stack overflowing the allocated stack memory, xv6 places an inaccessible guard page right below the stack by clearing the PTE_U flag.`

它把栈底下那一页的 PTE_U 清掉,踩上去缺页就来了,守的就是栈溢出这件事。咱们在地图上走的是另一条路,栈顶上方的那一页压根不画,layout.hpp 的断言原话是 `one guard page separates the stack top from user top`。它家清的是位,咱们留的是空,立意是同一句:给边界配一页进不去的地。

顶上的数也值得一比,咱们把两家的顶摆在一处。它家的顶,书页 38 的原话里带着数:

> 咱们把原话连注一起请来:`A process's user address space starts at zero and in principle ends at MAXVA (0x4000000000) (0896), though in practice only a small fraction of this is mapped to physical memory.`

MAXVA 的取值是 0x4000000000,合的是 256GiB,RISC-V 那套三极表的界,行话叫的是 Sv39。括号里的那个 0896,是它家书里标到源码行的注记,咱们照原样带着。轮到咱们自家,kUserTop 的取值是 0x0000800000000000,折成的是 128TiB,x86_64 规范地址的中线,差出的是好几百倍。原话里的 in principle 与 though in practice 一前一后,顶是原则上的界,真用满用不满的每一位客人,面对的是各家自己的事。

Linux 那头的事,这一章咱们交白卷。它家的内存文档没进过咱们的书架,高半从哪个数起、直接映射留多宽的答案,咱们报不出带出处的数,空着的地方宁肯留给手册进门那天再填,也不拿印象顶的数。

自家的窄处咱们也交底。世界退场的手续没造:销毁要把用户半边的表一层一层还回去,漏了一层,那几页物理内存就永远挂在没人用的表上,正文那一卷把话说在了明处,这套手续得跟进程的生老病死一起立才有意义,图纸留到进程来了再落笔。一人一世界的多客人排场也一样,机制是在的,第一位客人进了门,第二位的门还没进,真正的多客人戏,等客人真多了起来再唱。heap 的那行与拦空的岗,两笔各记在了各章名下,前文都指过住处了。

C++ 在这一章出手的地方,咱们放在 layout.hpp 的尾巴上看。十二条 static_assert 把每家的基址跟自家的 PML4 项号互锁,谁想单方面挪自家的一步,编译期就开了口,省的就是人等机器黑屏的功夫。停一停里读过的断言就在其中,kUserTop 拿 1 左移 47 对的表,消息的原文就是 canonical boundary 那句。图、岗、断言三处的数是同一个,谁跟谁的数都错不开。

## 这一章留下了什么

咱们在动身之前把手里添的家当点一遍名。一个 AddressSpace 的类,六张脸的样子,init 的四步:名册领页、清零、高半 256 项整段抄来,末了 root 记根,那一抄是任何世界都看得见内核的谜底。一条走查的路,三张脸共用的,根是递进去的,CR3 是不动的。kUser 占的一位,四级都带上了,0x400000 与 0x500000 两枚门牌就是它挂出来的。activate 的一行 LoadCr3,CR3 记的是现役,KernelPageRoot 存的是定格,回家装的就是它。天花板的一道,定在的是 0x0000800000000000,岗上的限与图上的线同数。屏上的事这一章没添新行,vmm 的那行 address space up,如今您知道它报的是哪一件事了。

| 术语 | 一句话口径 |
|---|---|
| 地址空间 | 一个世界的一整套翻译:自己的 PML4,高半整副抄自内核的根 |
| 世界 | AddressSpace 的共同语:想进就装它的根,想走就换回来 |
| kUser 位 | 页表项第 2 位:四级一路都带,缺一级 ring 3 就迈不过 |
| 现役 | CR3 里装着的根:谁上场记谁,activate 换的就是它 |
| 回家路 | KernelPageRoot 存下的定格:LoadCr3 它,机器回到内核的世界 |
| 天花板 | 0x0000800000000000:客人地界的顶,岗上的限与图上的线同数 |

世界立起来了,眼下在咱们手里还是一套靠软件走查伺候的图。机器自己取指访存的时候,那四级翻译是硬件一拍一拍在走的,走错了找谁、表改了机器多久知道,下一章的《分页与 TLB》接过去讲。

### 参考答案

题一:您抄下来的四行里,vmm 一行今天讲开了,报的是内核世界立起。heap 一行只指了住处,来路记在《物理内存管理》的名下。114514 在两行里各躺了一回。echo 的回话是 two worlds one machine,与实况一字不差地对上了,数对上了就算成。

题二:下不了。页照样挂进客人的世界,可 kUser 的位没带,页就归了内核独享,map_user 注释里 `without it` 那半句说的正是这个下场。跳板落地,客人在 0x400000 取指的头一脚,ring 3 迈不进只有内核能走的页,14 号当场就报了到。当年中间一级漏了这个位,客人也是在门口摔的,病根同源:您推的是位,屏上见的是号。

题三:您数下来,help、echo、yield 三单都过了柜台,exit 进了门再没回来,handle_exit 把当值的换下场,串口的那头从此无声。echo 的一递一回,递的是客人,他在自己的世界里把话装进 rdi 与 rsi,回话的手是内核的,柜台里一字一字落了屏,借的是高半的镜像。两头各在各的世界,过的都是同一台物理机器。
