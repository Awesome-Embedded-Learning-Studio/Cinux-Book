# 03 · 缺页与按需分页:一册许诺,四个号,五问补一页

咱们拿同一拍 exec 里对不上的两本记录开场。装载器往页表里真挂出去的栈,挂的只有顶上那一页。登记在册的栈段,记的却是从栈顶往下整整一兆字节,底下还多押了一页。两本记录其实差着一整段,而且差得心安理得:段是许给程序的,实铺的只有顶页,进场的时候才有处落脚。底下的兆字节,谁走到的时候谁来领。咱们把心安理得当今天这一章的章程。

这一章欠着两处的愿,咱们进门就认下。2.2 的桩报告完就 Halt,当的是遗言,当时留了话:能修好路再回去的故障处理,得等缺页的正戏开锣。3.1 咱们也问过,客人真的一脚踩在没映射的址上,谁来接?当时的答案诚实:把报告接住往下修的手续,当年的机器还没安,报告到了只能停在报告上。3.2 收卷又把两件事记到了本章名下:踩空的脚谁来接。向名册领走的页,来路其实还悬着。锣到今天敲响了,咱们两问这一章一起答。

这一章的活数下来有三样。头一样立的是懒章程:咱们把给予拆成两拍,登记的那一拍许诺,缺页的那一拍兑现。再一样认的是两件新家当:一件是每个任务一本的登记册,记的是虚拟地段上的许诺。另一件您天天要用,就是程序递申请的窗口。窗口上开的四枚号:mmap、munmap、mprotect、brk。末一样咱们把缺页的裁决从头走一遍:五问过堂,补页的三步,栈往下长的路,写时复制那枚记号的归位。量法照旧三条:码的主役是 kernel/mm/ 底下的 vma.hpp、vma.cpp、demand.cpp、vma_diag.cpp,进场的配角还有 sys_mmap、sys_exec、loader.cpp。屏要看的四样是起机面板、mapper 会话、机内自测、宿主测试,实况锚用的是 r19_lazy_alloc_page。书要引的是《深入理解计算机系统》书页 784、806、807,xv6 的书页 35 在第 3 章,还有第 5 章的书页 51,原话咱们整段录进对照节,您对着书核。

> **缺页的入口凭什么敢信一册记录?一册记录又凭什么敢自称许诺?**
>
> 凭条目自己报的身份。笔者翻 vma.hpp 的时候,在 VmaRegion 的头注里读到它自己报的:`One recorded promise: a half-open range plus its terms`,一枚登记在册的许诺,许的就是半开区间加条款。成员 start 的注是 `First byte the promise covers`,许诺盖住的头一个字节。代码自己的注释,把许诺两个字写在了纸上。咱们这一章,就给那句注作注:许诺怎么立,怎么查,怎么兑现。

## 一拍许,一拍兑:懒章程

咱们从机器勤快时的样子看起。装载器把每个段的每一页都提前铺好:领的是一帧,清的是整页,镜像里的字节从头铺到自己的份上,这是《内存当家》立下的页的纪律,纪律其实没有错。栈进场的时候领一页,应付 shell 敲的命令够用。堆在册上种下的是零长的一段,连一页的份都没有。这样的机器,跑 hello 和 shell 是体面的,可它伺候不了真程序:声明要用十兆字节的程序,从进场到退场真摸过的角落往往就几百页。配置扫了一遍就再不碰。栈浮在顶上的几页里,深递归的那几瞬才往下探。进场的那一拍把十兆字节老实铺满,铺进去的字节绝大多数在等一个永远不来的访问,而物理内存是全机最紧的家当。

所以这一章教懒。咱们把懒章程立成三个词,后头的每一节都照它办。用什么:登记在前,登记在册的才给。到什么:哪页用到了补哪页,补的尺寸永远是正好一页。不用的不占:册上记十个区段不要紧,没碰过的页一片不发,物理内存只花在真发生过的访问上。三个词连起来读的话,懒是把给予拆成了两拍:登记那一拍许诺,缺页的那一拍兑现,两拍之间隔着的时间也好页数也好,机器都是等得起的。

这门手艺是有正经名目的。《深入理解计算机系统》第 9 章在书页 784 给它落的定义,咱们整句录来:

```text
“The strategy of waiting until the last moment to swap in a page, when a miss occurs, is known as demand paging. … all modern systems use demand paging.”
```

等到 miss 的那一刻才把页搬进来,咱们叫它按需分页,所有现代系统都这么过活。教科书在这件事上其实没有流派之分,咱们照办,办得朴素:树形的册、成批的补,那样的大件,几十条区间其实暂时用不上。懒真正图的是快。当年工程线上量过的一笔:装载从整份铺好改成按需补页,工程线上最大的一份用户程序,编译器的前端,exec 从盘上请进内存的那段路,二十二秒归了零。二十二秒去了哪?整份读盘整份铺页的工夫,被拆散成了千百次一页的小事,而绝大多数页压根没人来要。快的数咱们认当年那一笔,这一遍咱们不另计时,本章收卷的时候拿实弹对功能。

## 一枚条目,一句许诺:登记册

册子长什么样,咱们端一条条目出来。一段用户地址,咱们要三件事记全。头一件记的是从哪到哪:半开区间、含头不含末,这样的边界两段挨着也不打架。第二件记的是许做什么:读、写、执行三问各占一个布尔。第三件记的是背后站着谁:三态挑一,匿名的就是一张白纸,补页的时候补零。文件的记下文件节点和页偏移,补页的话照着去读字节。栈的脾气是往下长,别的态没这脾气,所以单独算一态。条目前半截的原身在此:

```cpp
struct VmaRegion : base::container::SelfNode<VmaRegion> {
    unsigned long      start{};        ///< First byte the promise covers.
    unsigned long      end{};          ///< One past the last covered byte.
    VmaKind            kind{};         ///< What stands behind the bytes.
    bool               readable{};     ///< Loads through this range are promised.
    bool               writable{};     ///< Stores through this range are promised.
    bool               executable{};   ///< Running code from this range is promised.
    fs::FsNode         backing{};      ///< The source node when kind is kFile.
    const fs::FsOps*   file_ops{};     ///< The backend face that serves backing's bytes.
    void*              file_self{};    ///< The backend instance behind file_ops.
    unsigned long long file_offset{};  ///< File byte matching start, when backed.
};
```

条目里文件侧的那三件,咱们把分工多说两句。backing 记的是文件的身份,按值整个抄了进来,册子是不拿它去解引用的。为什么不肯存指针,是当年的亏换来的:工程线的页缓存拿指针当过键,对象腾挪了之后,新对象恰好住进旧地址,缓存里的旧记录还认这个门牌,一查吃到别人的字节。这一遍的身份一律按值抄,条目认的还是从前的它,哪怕背后的对象换了住址。把身份变成字节靠的是旁边那两件:file_ops 是后端的脸,file_self 是后端的实例,补页的时候读文件页,走的就是这一对。

册子的形状拍得不花哨:按到达序排的单链。您要是见过红黑树版的同类件,您别嫌它朴素,这是有意的。一个任务的区间数来数去几十条,线性扫一遍就是诚实的代价,换来的是没有排序要维护、没有再平衡要教,查一回连一页堆的分配都不领。区间成千上万的年月再教树不迟,那不是今天几十条要愁的事。两道家法立在登记的门上:重叠的拒收,不沾合并的边。空区间和倒区间的话,起点压过终点的,连门都是不让进的。exec 铺出来的段天然不搭界,mmap 发出来的地段互不重叠,谁拿一段跟册上重叠的地来,报的只能是调用方的毛病,错原样报了上去,替人圆的事是不做的。册子干净了,查册的时候才敢把话说满:册上没有,就是真的没有。这话您现在听着平常,等会儿的判词敢不敢说满,押的全在家法上。

册跟任务的缘分,咱们两头交代。exec 的那头,新册是在活册旁边另造的,您看装载器往新册里报段,报成了才换进任务:旧世界的页逐叶清还,旧册是被 ranges.release() 顶掉的,就地丢弃,没走析构的事,小漏了一笔,咱们照实记。报不成的话,一切退回了,活着的程序毫发无伤。fork 那头是深拷:孩子把父亲的册整本抄走,抄到一半抄不动了,已抄的全退,要的是全有或全无。父子写同一段地址会分家,那一幕正文《生与收》的那一卷拍过全本。分家靠的是页表那一层,册的这一层,父子各揣了一本,各管各的。册立起来马上接的一件真活:替缺页断案当证人。裁决者看完自己不受理的地址,转储之前多问册子的这一句,问的是地址落在谁家。判词的正文住 vma_diag.cpp,两种回答:落在册上的,那一段的底细全亮出来:起止、三态、访问是读是写,咱们一行看完。落在册外的,第二句判词整行抄了来:

```text
[kern]  vma: addr=%X sits in no registered range; a true segfault
```

真的越界了,错是程序自己的,串口上的这一行就是第一份口供。咱们顺手把两位册子对个表:1.7 的名册,一位管的是一页,管物理的地。本章的登记册,一条管的是一段,管虚拟的地。名字差的是一个字,管的差一个世界。补页的时候两位才握手:登记册说该补,发帧的是名册。

## 窗口开张,一页不发:四个号

册是立在任务里的,程序其实还够不着,够得着的路只有系统调用。咱们来认号:syscall.hpp 里的四枚枚举,kMmap 坐的是九号,kBrk 坐的是十二号,九号和十二号跟 Linux 的一样。kMunmap 与 kMprotect 坐的是十号、十一号,咱们的表上换了座,Linux 的表上正好倒过来,这一对的座次债,正文《把后半场交给解释器》的那一卷才换回,这儿记下了不重叙。为什么照人家的号位,咱们守的是老理由:往后跑别人编好的程序,人家一发 syscall 的话,号对上了就是咱们的门。

咱们跟着 mmap 进门看它办事。头一件的活:咱们把长度进页凑整,零长的请回。第二件找的是空档:mmap 区在栈底下、分界上,长法是从顶往下的,候选地盘的屋檐从顶起步,册上的哪段挡在路上,屋檐就压到那段的更下方。一整圈压不动了,地盘才算真干净。这件家什的原身,vma.cpp 的 find_free_spot,咱们整段端出来:

```cpp
base::Result<unsigned long> VmaStore::find_free_spot(unsigned long ceiling,
                                                     unsigned long bytes) const {
    if (bytes == 0 || ceiling < bytes) {
        return base::KernelError::kOutOfMemory;
    }
    unsigned long spot_end = ceiling;
    for (bool moved = true; moved;) {
        moved = false;
        if (heap_.start < spot_end && heap_.end > spot_end - bytes) {
            spot_end = heap_.start;
            moved    = true;
        }
        for (const VmaRegion* scan = regions_.head(); scan != nullptr;
             scan                  = regions_.after(*scan)) {
            if (scan->start < spot_end && scan->end > spot_end - bytes) {
                spot_end = scan->start;
                moved    = true;
            }
        }
    }
    if (spot_end < bytes) {
        return base::KernelError::kOutOfMemory;
    }
    return spot_end - bytes;
}
```

spot_end 是候选地盘的屋檐,起步的上限是 ceiling,咱们要的是屋檐底下正好 bytes 那么长的一截。压的动作两处:堆跟候选搭上边,屋檐压到堆的起点。链上的哪段搭上边,屋檐压到那段的起点。搭边的判法两头同一句:段起点落在屋檐之下,段终点又伸过候选的底,两边有了交集就算搭上。外头那层 for(bool moved) 是不动点循环:这一圈压动过了,把压下去的新位置再验一遍,说不定又跟更下面的段搭上。一圈下来一寸压不动了,循环就退出去了,交回的是 spot_end 减 bytes,半开区间的起址。整个找法走的是纯算术:册上扫一圈,分配的影子都没有,所以长凳上的测试世界也跑得动。堆为什么头一个被比?它不上链:链上条目要有起有止,堆生下来的长度是零,空区间进不了链,它骑在册子自己的成员上。第三件按旗标分两路:匿名的,册上添了一条匿名条目,完事了,咱们一页不发。文件的,查的是描述符在不在、活不活,再翻的是保护位,这一版的文件映射只做只读,映射了还想写的,咱们拿 EINVAL 请回。

munmap 干的是摘除,mprotect 干的是改词,一样都不做劈半的事:munmap 摘的必须是完整落在给定范围里的条目,半截搭边的拒。mprotect 改的必须是一整段权限,半截的也拒。页表的那头,munmap 一页一页地走,3.2 备下的 UnmapPage 等了这么久,头一个真消费者在这儿上岗:摘下的页还帧,还帧之后紧跟的是一声作废:invlpg,3.2 立的义务照章补上。次序是有讲究的,册动在前表动在后:册上不认了咱们再摘表,摘的当口缺页打进来,一查册查了个空,当场拒回了。不会出现册上还有、页上已无的悬空瞬间被当成合法访问放过去。mprotect 还特意留了半截:册上当场改,页表上的位眼下不动,已映射的页还揣着昨天的表项。您要问这算不算言行不一,咱们答算,而且是故意的:改词要收全,得等缺页裁决的新业务开张才补得上。补的那一拍,册上的词是承诺,页表跟在承诺的后头走。这半截怎么合上,咱们下一节见。

老词新开的 brk 单独说,脾气跟前三个的不同。堆的家当 exec 时种下:起点是程序影像的末页进上去,顶头是 layout.hpp 画的分界 kUserBrkMmapSplit:0x0000400000000000,堆的地界到这儿为止。brk 的语义照 Linux:传零是问询,回的是当前断点。传目标地址,对齐到页的边界,夹在起点与分界的中间,断点挪了过去。注意咱们没说 map 也没说 unmap:brk 动的只是指针,断点挪了上去,新地盘在册上有名,页的事等缺页来了再说。收缩动的同样只有指针,铺出去的页不急着摘,等的是进程退场,整个世界是连册带表一起清算的。还有一个脾气:brk 返回地址,错误码是不返的,目标落了空,返回的还是当前断点,所以调用者要自己比对出没挪动,这是 Linux 的老脾气,咱们原样学来。四个号开完了,咱们盘点真发出去的页:零。册上添了行、摘了行、改了词,断点挪了位,物理内存的占用纹丝没动。窗口开了,兑现的事另算。

## 五问过堂,补页三步

咱们把正主请上台。demand.cpp 的文件头注写着 `One fault, one promise, one frame: the fill itself`,说的是一次缺页、一句许诺、一帧,补的就是它。缺页的错误码自带口供:第一位说这错是整页没映还是权限不对,第三位说挨错的是客人还是内核。裁决的判定链如今是两段:头一段是写时复制的老脸,写路是打头试的,fork 出的父子合用一份帧,页表上带着的是 kCow 记号,谁写了谁挨缺页,裁决者见着了记号才接案,走的是分家或者复权,全本在正文《生与收》的那一卷。老业务说不受理的,接手的是新业务,问案顺序的原身在此:

```cpp
    if ((error_code & cinux::arch::isr::kFaultFromUser) == 0 ||
        (error_code & cinux::arch::isr::kFaultProtection) != 0 || address >= kUserTop) {
        return false;
    }
    const VmaRegion* const kRegion = ranges.find(address);
    if (kRegion == nullptr) {
        return false;
    }
    const unsigned long kPage = cinux::base::math::AlignDown(address, kSize);
    if (kRegion->kind == VmaKind::kStack && kPage == kRegion->start) {
        return false;
    }
    KernelTables       world;
    const walk::SlotAt kSlot = walk::FindSlot(world, space.root(), kPage);
    if (kSlot.entry != nullptr && kSlot.entry->has(cinux::arch::page::kPresent)) {
        return false;
    }
```

咱们把五问挨个认。第一问问的是来自用户吗:错误码第三位是 ring 3 的印记,内核自己的缺页这一路不接。同一行里还夹了一判,地址过了 kUserTop,天空以上册子是管不着的。第二问问的是保护性的错吗:第一位立着的,那是权限的事,写路试过了不接,剩下的就是册和表都说不行,咱们婉拒,死法是转储里的一行判词。第三问问的是册上有这段吗:查册查了个空,就是真的越界,接它的是上头那句 a true segfault。第四问问的是栈底那页吗:栈区间的头一页永不映,谁碰了谁响,这页咱们等下单独说。第五问问的是页真没映吗:FindSlot 走到叶表,槽里那项的现在位翻没翻。这一问看着是多余的,学费就交在了这问上。判已映未映的时候,手里有的是件现成家什,3.2 的走查件,走到叶表的时候交一个指针。首版的判断写的是指针非空即已映,机内测试的头一轮,十案跑了个七绿三红。三红根子分了层。头一层在走查件的语义:它走到叶表,哪怕碰到的是零叶槽,交回来的指针也非空,因为叶表本身在了,它给的是槽位的地址,不是槽里那项的生死。同一张叶表里的第二页,头一回缺页进了门,槽位记的是零,指针仍是非空的,首版判成了已映,拒错了,程序白白死给咱们看。第二层在用例的根子上:堆的用例种下堆之后没挪过断点,册上的堆区间长度还是零,任何地址自然查不中,挪了断点再缺页才是完整的戏。第三红红得冤:栈的用例期望写错了一处地址,对齐进页之后的落点恰好是栈底那页,被拒的其实是正确行为,错的是期望。三处各自修对了,十案全过了。当年首跑与今日的屏,实况节里今昔是分开念的。

**您停一停,FindSlot 交回来的那枚指针,您认一认,它管保了什么,没管保什么?**

咱们把说明书念准。管保的:叶表在了,槽找到了,指针指的就是您要找的格子。不管保的:格子里那项活不活。指针非空说的是路走通了,说的不是页在着。页在不在的话,翻的是槽里那项的现在位。首版把前半张保单当成了整张,头一案的红就红在这。判已映的手续从此固定:查位而不查指针。家什交回来的语义要读它的说明书,别干望文生义的事,这句当年笔记里的原话,咱们化来当家法。

过了五问,补页的本体走三步,咱们跟着一页走。头一步领的是帧:物理内存发一帧,发帧的是 1.7 的名册:allocate_page 一声,一页物理地到手。第二步整页清零:匿名页的出身就是零。文件页的短读尾巴也是零,bss 的答案提前写好,程序数据段里没初始化的全局变量该是零,道理落在了这儿。第三步按三态分岔:匿名的到这儿就完了,零页上了表。文件的,把这一页对应的文件字节,经登记册上记的后端面读进这一帧,读了多少算多少,文件尾巴短的,余下的字节保持零,正好是内存大于文件那一截该有的样子。后端那头的块缓存,今天只是一座还没摊开的柜子,正戏归的是《Page Cache 与写回》那一章,咱们路过不开柜:一句带过。叶项的组装也换了脸:上表的件收一个现成叶项,谁调了谁组装,册子说这段是许写的,补出来的叶项才带写位,栈段记的是许写,补出来的栈页就带写位。上表之后紧跟的是一发作废:invlpg,3.2 认过的义务,这儿照章补上了。段权限的旧债也顺手在这儿清:装载器从前把用户页一律映成可写,ELF 段自己声明的旗标没人理,如今的程序头里读、写、执行三位,装载的时候翻进册子,loader.cpp 里三条布尔对着段旗标各翻各的,写位再翻进了页表,数据段是数据段的法,代码段是代码段的法。执行位有个如实的交代:它记在册上,页表那边的执行限制要动 EFER 里的开关,那是另外的一件事,正文《安全》的那一卷管它,这一章是不越界的。

栈的故事里最提气的一笔,咱们单独说。exec 的那一拍,sys_exec 把册种了下去:栈段从 kUserProgramStackTop 往下整整 kUserStackBytes 的一兆字节,再多押了一页,段的起点就压在一兆字节的最低处再往下一页。真铺的只有顶上一页,领的是一帧,挂上了表,进场用的栈顶从它起。往后的递归一层层往下压,压过了真铺那页,缺页进了门,咱们查册,在栈段的,往下补的永远是一页,压了补,补了压。压到一兆字节的底,再往下一步的话,接它的就是脚下押的那页:判定链里 kPage == kRegion->start 拦的就是这一步,第四问挡下了它,响亮地死,串口上的一行判词,死因是清清楚楚的。这页永不映的地,手艺跟的是正文《页进,块出》的那一篇同款,同款的还有名字:叫保护页。

**您停一停,栈的头上脚下,各押着一页进不去的地,您分分看,各拦的是哪种越界?**

咱们把两页摆开。头上的那页,3.1 对照节里量过的:栈顶上方那一页压根不画,layout.hpp 的断言原话是 one guard page separates the stack top from user top,拦的是往天花板那头窜出去的脚,程序的地界到栈顶为止,再上一步就踩空了。脚下的那页,本章 exec 押下的这页,站在一兆字节的底,拦的是递归往下压、要把栈段压穿的脚。两页还各带着一层暗活:头上的一页画在册外,它是谁也发不走的。脚下的那页登记在册,占着地,找空档的屋檐就永远不会把别人的地段发到紧贴栈底的位置。缺了脚下这页,mmap 的地盘恰好贴着栈底安家的话,压穿的脚就一声不吭写进了别人家里。

还有一枚记号到了日子,咱们看着它。kCow 是页表上的写时复制记号,父子合用的页带着它,裁决者见着了才接案。当年引擎把它留在分了家的私页上不摘,凭的是可写与可共享并存,碍不了事。这约定到 mprotect 补齐的那一拍到期:改页表要判断这页跟不跟人共享,共享页的写位不能上,而页表里唯一的共享记号就是 kCow,私页还留着它的话,会被当成共享的,写位就收错了。所以这一批把分家后的私页摘干净:kCow 只标真共享的页,册、页表、帧计数三本记录说同一个口径的话。mprotect 欠的言行一致,咱们在这儿还上:册改完了,表逐页跟上了,共享页保的是只读,私页按的是新词,下一回缺页来办事的时候,照的还是新词。到这儿懒章程的两拍全通:登记当许诺,exec 种了册,mmap 添了行,brk 挪了断点。缺页当的是兑现,过了五问,补的是一页,作废了一声,挨那一记的指令回头重跑,咱们这出戏接着演。2.2 留话里的急诊,这一章开张了。

## 对照:同一件事,别的机器怎么做

咱们把 xv6 翻到第 5 章开头,书页 51 的一句立场:

```text
“xv6 uses page faults for only one purpose: lazy allocation.”
```

它家把缺页用在懒分配的一件差事上,跟咱们这一章干的是同一件。分岔是在开关上的,书页 51 的讲法直白,sbrk 得带上 SBRK_LAZY 的旗标才走懒路:

```text
“First, when an application asks for memory by calling sbrk with the flag SBRK_LAZY, the kernel notes the increase in size, but does not allocate physical memory and does not create PTEs for the new range of virtual addresses.”
```

书记下了增量,物理内存是不发的,表项是不建的。它家的原话是 `The kernel implements lazy allocation transparently to applications`,懒的机关对应用程序透明。可进不进懒门的事,xv6 交给了程序自己递旗标。咱们的 mmap 和 brk 生下来就是懒的,开关是没有的。同走一条懒路的两家,一家把选择权交给了程序,一家把默认值定在了懒上,咱们跟后一家。代价两家都认:缺页自带一次用户与内核的来回,攒批的补页能摊薄,它家是没有做的,咱们的章程眼下也一页一页。

守边的姿势,咱们把三家对举,您看得最清楚。xv6 的内核栈,书页 35 的原话:

```text
“The guard page’s PTE is invalid (i.e., PTE_V is not set), so that if the kernel overflows a kernel stack, it will likely cause a page fault and the kernel will panic. … A panic crash is preferable.”
```

栈底一页的表项直接无效,内核栈溢过了它,缺了页,炸出了一场 `panic`:宁可崩得响,不愿悄悄写花别人的内存。咱们的内核栈走另一路:栈底埋一句魔数,溢过了它机器照跑,验尸翻栈的时候才看得见魔数被踩,是死透了才响的哨兵。本章的用户栈保护页是第三路:踩到那一拍缺页就进门,判词当场落了屏,当场就响的警铃。同一件事的三种安法:它家安在表项上,咱们内核侧安在字节上,用户侧安在了册子上。xv6 的用户栈底下也压着一页,那一段 3.1 的对照里引过,您翻回去对读正好。

轮到《深入理解计算机系统》了。书页 806 的地方,它家给 Linux 的地段条目列字段:vm_start、vm_end、vm_prot、vm_flags、vm_next,五个名字咱们个个认得,起、止、三问的权限、共享还是私有、链上下一条,咱们的 VmaRegion 逐项对得上,私有共享那一件咱们记在帧计数与 kCow 上,条目里是不放的。书页 807 的缺页处理第一步,原话咱们录来:

```text
“1. Is virtual address A legal? In other words, does A lie within an area defined by some area struct? To answer this question, the fault handler searches the list of area structs, comparing A with the vm_start and vm_end in each area struct.”
```

拿地址对每段的起止逐段比,这就是咱们的第三问,连比法都是一样的。它家紧跟着自己补了一句:顺序扫太贵,实践中 Linux 在链上叠了一棵树。咱们几十条区间的诚实,正好接在这句话的前半截上。后半截的树,等册子真厚了起来再说。Linux 本尊的那头,这一章照旧不描:它的缺页路数怎么走、VMA 树怎么养,咱们书架上还没有一份能引的材料,这一页是留着的,咱们不拿印象垫,能引的书进门那天,咱们回来落墨。

咱们把自家的窄处交底两件:文件映射只做只读,映射了还想写的,咱们拿 EINVAL 请回。mprotect 和 munmap 都不做劈半的事,半截搭边的范围一概拒,想只动半段的话,分开的活归调用方自己。C++ 在这一章出手的地方就落在登记册的单链上:VmaRegion 自己就是链结点,走的是侵入式链,链长在条目自己的身上,登记的时候不领一页堆,摘除的时候也不还,查一回的分配是零,几十条朴素区间的全部便宜,落点归到了这行继承上。三态用的是 scoped enum,枚举的名字 kAnonymous、kFile、kStack 带 k 前缀,值域写死在了类型上,switch 漏了一个分支,编译器就开口了。

## 这一章留下了什么

### 参考答案

题一:登记了没铺页的戏,咱们认下来。第二幕的 brk stretch 与 heap pages on demand 都算,断点伸五页的那一拍是零页,写到的拍才补。第三幕的 file mmap 也是登记了完事,头一次读的时候才进内存。深栈二百五十六层压了下去,exec 真铺的只有一页,一路压出了三十几页,全是缺页一页一页接出来的。

题二:您看,FindSlot 走到了叶表,交回的是槽位的地址:叶表在了,指针就是非空的,哪怕槽里记的是零。第二页与头一页共用的是一张叶表,头一页补过了,叶表已经在了,第二页头一回缺页进了门,槽位记的还是零,可指针仍是非空的,首版拿指针非空当成了已映,把还没补的页判成了在,拒错了。判已映要查槽里那项的现在位,不查的是指针。

题三:咱们推到头,断点伸五页的那一拍,少的页是零:brk 只动指针,发出去的页是零。第二幕走完了,写读走的是半页一格,五页全摸到了,补了五页,空闲数少了五页。隔在零与五之间的,正是懒章程的到什么:用一页,补的是一页。
