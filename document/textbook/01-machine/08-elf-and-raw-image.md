# 08 · ELF 与裸镜像:同一颗内核,两本护照

咱们这一章的主角,是 build/kernel/ 里的 kernel.bin,您数下来拢共 2624 个字节。内核本体那 130 页里头装着什么,ELF 的头和裸镜像差在哪儿,1.7《存储层次》把两个问题递到了这一章手上。进了这一章,咱们把骨头看个明白:咱们把文件捧在手边,把装它的那本 ELF 读一遍,再把它自己带的那本户口本读一遍,末了两本摊开逐项对。

动手之前咱们把一个数对齐。那 130 页说的是 1.7 手里 r07_serial_pmm 那一版的个头。这一章的实况锚退回更早的 r06_jump_into_kernel,这门手艺出生的站。那一版的内核小得很,mem_size 报的是 0xC40,折出来的字节是 3136,拿 1.7 认下的 4KiB 一页取整的话,咱们连一页都摊不满。个头是两说的,骨头其实是同一套:链接、护照、搬运、扫院子,一样也少不了。小有小的便宜,3136 个字节您拿眼就能扫完,咱们哪一格都不藏私。

量法的话,两本护照各记各的。ELF 那本的数目全出自工具链的嘴:readelf 和 nm,随编译器一道装上的两件小伙计,一个念的是面,一个念的是名字,咱们边走边把 ELF 的常识立起来,出处就是您眼前这些屏。CNKZ 那本的数目,一半是链接脚本给的,另一半是咱们从自家的盘和自家的内存里读出来的。《深入理解计算机系统》第 7 章整章讲的就是链接,咱们照 1.7 立下的口径,核到的只是章号,其实一页都没引。ELF 自家的规格文书,咱们一本都没核过,字段就讲本章用得着的几样,多的不添。还有一桩要认下:r06 这一版的印字走 0xE9 那扇调试口,真串口的嗓子是 r07 才换上的,这扇调试口咱们在 1.5《与设备打交道》里认过。您读这一版的日志,字是从调试口出的,串口那边落的是 0 字节,您别拍错门。

> **7f 45 4c 46 与 CNKZ 的差别是什么?同一颗内核,机器为什么只肯吃其中一份?**
>
> 差的是念给谁听。7f 45 4c 46 是工件的通用语:编译器、链接器、调试器,还有咱们人,念的都是它。CNKZ 是 boot 手里那本自家的户口本,在全世界是独一份的。其实机器两边都不认,它只认摆在跟前的两个数:盘上读多少,进了内存占多少。所以通用语在出厂前拍成裸字节,咱们把户口本焊在最前头,机器吃的,是拍完的那个。

## ELF:工件世界的通用语

链接的成品叫 cinux_kernel,咱们在 build/kernel/ 里就能找到它。咱们请 readelf 出来念它的头,`-h` 让它念的是最前头那一页:

```text
  Magic:   7f 45 4c 46 02 01 01 00 00 00 00 00 00 00 00 00
  Class:                             ELF64
  Type:                              EXEC (Executable file)
  Machine:                           Advanced Micro Devices X86-64
  Entry point address:               0xffffffff802001b4
```

`-h` 的全表还有十几行,版本、旗标一类的,您在本章用不着它们,上面抄的只是头五行。开头的四个字节 7f 45 4c 46 是这类文件的自我介绍,行话里的叫法是魔数(magic number):45 4c 46 按字符念,念出来的正是 E、L、F。三个字母罩住的实情,咱们只认眼前的:编译器出品的目标文件、链接器交出的成品,穿的都是这一套行头,readelf、nm、GDB 见了都认得。Class 那行说它按 64 位的口径记事。Entry point 那行您多看一眼:0xffffffff802001b4,高半的地址,内核本体打这一版起就住在 0xffffffff802 开头的地界,1.6《DMA 与中断》里下断点的那片高位,头一条指令的门牌就挂在这儿。

头念完了,咱们念装货的那一页。咱们用 `-l` 让 readelf 把程序头(program header)列出来,这是给装载的人看的:哪些内容进内存、放到哪儿、占多大。这一版的表上有两行,GNU_STACK 那行是栈的记号,是不带货的,咱们只抄 LOAD:

```text
  Type           Offset             VirtAddr           PhysAddr
                 FileSiz            MemSiz              Flags  Align
  LOAD           0x0000000000001000 0xffffffff80200000 0x0000000000200000
                 0x0000000000000a40 0x0000000000000c40  RWE    0x1000
```

一行报出两个地址。VirtAddr 的那一半是 0xffffffff80200000,内核自己眼里的世界观。PhysAddr 的那一半是 0x200000,肉身真正落的家。同一段的内容有两种写法,您把两边都记下,实况里对表的时候,咱们靠的就是它们两个。FileSiz 报的是 0xa40,文件里实打实的内容。MemSiz 报的是 0xC40,进了内存占的地界,两个数是不相等的,差在了哪儿,实况里算给您看。Offset 0x1000 说的是这批内容在 ELF 文件里的起点。那个文件的个头比 kernel.bin 大得多,前头还有几千字节的文书,节头表、字符串表的,是全给工具链和人用的,机器是一个字节都不要的。

文件里还住着一本名字的户口,行话里的叫法是符号表。KernelEntry、g_idt 这些名字连同各自的住址,全都登记在册了。nm 念的是它,链接器查的也是它,实况里咱们拿它对数。名字是给人看的:机器跑起来,认的是址,不认的是名。

## 裸镜像,和一本自家的户口本

机器那头是不吃这一套的。它睁开眼要干活的时候,手边有的只是盘和内存,既没有 readelf 的帮忙,也没有那样的耐心。所以出厂之前,咱们还得替它改个装:objcopy 是工具链里管改装的伙计,咱们让它按 binary 格式交货,它交出来的就是 LOAD 那段肉,文书全剥掉了。拍出来的就是 2624 个字节的 kernel.bin,这道手续登记在 kernel/CMakeLists.txt 的 :28。

裸字节有了,麻烦也跟着来了:它连自己是谁都给忘了。放到盘上哪儿算头?进了内存往哪儿放?占多大地方?从哪个字节起跑?裸文件一问三不知,boot 也是不肯猜的。办法是把一本自家的户口本焊在文件最前头,boot 把户口本读完了才动手。od 的口径,前置卷里您使过,左边的一列是字节号,右边的一列是字节本尊,咱们把 kernel.bin 的开头抄来:

```text
0000000 43 4e 4b 5a 01 00 20 00 00 00 20 00 00 00 00 00
0000016 35 0a 00 00 00 00 00 00 40 0c 00 00 00 00 00 00
0000032 b4 01 20 00 00 00 00 00 00 00 00 00 00 00 00 00
0000048 6a 00 6a 00 eb 14 6a 00 6a 06 eb 0e 6a 00 6a 08
```

开头的 48 个字节就是户口本,第 48 个字节起的 6a 00 6a 00 是内核 .text 的开场,也是五个异常桩里打头的那一桩,这一桩的戏,正文那头的《内核出生,和验收》里都是讲过的。户口本咱们一行一行念。咱们把头四个字节 43 4e 4b 5a 单拎出来,按字符念正是 C、N、K、Z:这是自家的魔数,折出来的数值是 0x5A4B4E43,咱们后文就叫它 CNKZ。紧跟上去的还有两个小字段:01 00 拼出的 1 是版本号,20 00 拼出的 32 是户口本自报的头长。这个 32 您留意一下:七个字段实打实占的是 40 个字节,补齐到 16 的整边,整本凑成了 48 字节。眼下是还没有谁去查 32 这个数的,它是留给将来头变了样的时候自报家门的。再往后的字段按小端拼,1.2《字节寄存器与栈》教的读法:00 00 20 00 00 00 00 00 拼出的是 0x200000,记的是 load_paddr,肉身的家。35 0a 00 00 00 00 00 00 拼出的是 0xA35,写的是 file_size,报的是盘上读多少。40 0c 00 00 00 00 00 00 拼出的是 0xC40,报的是 mem_size,进了内存占多少。末了 b4 01 20 00 00 00 00 00 拼出的是 0x2001b4,当的是 entry,说的是从哪个字节起跑。七个字段占了 40 个字节,数全在这儿了。

方才拼出的四个数,跟 ELF 护照上的是什么关系,咱们拿正主说话。这些数是用不着谁手抄的,链接脚本算出来的,kernel/arch/x86_64/kernel.ld 的尾巴上排着这几行:

```text
    __lma_start = LOADADDR(.image_header);
    __file_end_lma = __lma_start + SIZEOF(.image_header) + SIZEOF(.text) + SIZEOF(.rodata) + SIZEOF(.data);
    __mem_end_lma = __lma_start + (__vma_end - __vma_start);
    __entry_lma = __lma_start + (KernelEntry - __vma_start);
    __header_file_size = __file_end_lma - __lma_start;
    __header_mem_size = __mem_end_lma - __lma_start;
```

咱们念两行就够懂全局。__header_file_size 的那行,把头一节、.text、.rodata、.data 的尺寸一节一节加出一笔和,节与节之间的缝不数。__entry_lma 的那行,拿高半世界观里的门牌减掉世界观的原点,加上物理的家,0xffffffff802001b4 就换算成了 0x2001b4。链接落锤的那刻,这些名字就全变成了真数。数怎么铸进文件头?焊头的活计在 image_header_data.cpp,它怎么把链接符号的名字变成字节,到了对照的部分咱们细念,咱们这儿拿 nm 把读数摆出来:

```text
ffffffff802001b4 T KernelEntry
ffffffff80200a40 b (anonymous namespace)::g_idt
00000000002001b4 A __entry_lma
0000000000000a35 A __header_file_size
0000000000000c40 A __header_mem_size
0000000000200000 A __lma_start
ffffffff80200c40 B g_kernel_bss_end
ffffffff80200a40 B g_kernel_bss_start
```

全表的长度远不止这些,上面的屏是咱们拿 `nm -C` 解过修饰名、再用 grep 挑出来的,本章要讲的八行。A 是 absolute 的记号:这些数不带住址,说的本身就是值。户口本上的四个数 0xa35、0xc40、0x200000、0x2001b4,在符号表里挂的全是 A 的户口。KernelEntry 挂的是 T,代码的户口,门牌是 readelf 报的 0xffffffff802001b4。g_kernel_bss_start 与 g_kernel_bss_end 的两行,圈出的就是院子。g_idt 跟 start 是同址的,院子里住的就是它,实况的院子清算里见分晓。

户口本念完了,您看 boot 的章程,简单得吓人:它眼里的世界只有两个数,盘上读的是多少,内存里占的是多少。什么 BSS,什么对齐,boot 是一概不知道名字的。数是内核自己报的,报进了户口本,boot 是照办的。

**护照摊开了,您来当一回验关员**:两本护照上,哪几样数必须一字不差?哪一样,天生就该两样写法?猜好了往下走,实况里咱们逐项对。

## Code: Cinux 实况:两本护照对表

咱们把实况锚定在 r06_jump_into_kernel,行号都按这一版的文件数。您要亲手翻,咱们就拿 `git switch --detach r06_jump_into_kernel` 切过去,看完了拿 `git switch -` 切回来,新克隆的仓,落回的是 main。动手前镜像得重打一遍:build 要是留着上一站的产物,开出来的就是旧内核,护照也就换了人。咱们下面的读数,全是重打之后抄的。

头一拍咱们来对表。咱们把两本护照并排摆上桌:

| 项目 | ELF 护照 | CNKZ 护照 |
|---|---|---|
| 落址 | 0x200000(PhysAddr) | 0x200000(load_paddr) |
| 地界 | 0xC40(MemSiz) | 0xC40(mem_size) |
| 门牌 | 0xffffffff802001b4(虚) | 0x2001b4(物理) |
| 文件尺寸 | 0xa40(FileSiz) | 0xA35(file_size) |

落址、地界,两本是一字不差的。门牌那行字面不同:ELF 写的是高半世界观里的虚址,CNKZ 写的是物理的家。咱们当场换算:0xffffffff802001b4 减掉世界观原点 0xffffffff80200000,加上 0x200000 的话,得出来的正是 0x2001b4,两本指的都是同一处入口。虚址为什么要架在高半,页表怎么办它,那是第 3 部的正戏,咱们这儿记一笔就走:两本护照说的是同一种门牌,只是写成了两种字体。

末一行有戏了。文件尺寸两本不一样:ELF 的 FileSiz 报 0xa40,CNKZ 的 file_size 报 0xA35,差的是 11。哪本写错了?都没错,两本的记法不一样,差数留到末了算。盘上的实物这就请出来,kernel.bin 躺进镜像的手续在 boot/CMakeLists.txt 里,四条 dd 排成了一列,末一道管的是内核,带的参数是 seek=32,说的是从第 32 号扇区起一个字节一个字节码进去。咱们从镜像里把那 48 个字节抄回来:

```bash
dd if=build/boot/cinux.img bs=1 skip=16384 count=48 2>/dev/null | od -A d -t x1
```

```text
0000000 43 4e 4b 5a 01 00 20 00 00 00 20 00 00 00 00 00
0000016 35 0a 00 00 00 00 00 00 40 0c 00 00 00 00 00 00
0000032 b4 01 20 00 00 00 00 00 00 00 00 00 00 00 00 00
0000048
```

跟 kernel.bin 的开头一个字节不差。整份 2624 字节咱们拿 cmp 对过,也是一字不差的。户口本焊在最前头的这句话,咱们眼见为实。

到了第二拍,咱们分两道看 boot 怎么信这本户口本。头一道在搬之前:stage2 把内核的头一扇读进窗,户口本按的是一串判据,挨个过堂的是魔数、版本、尺寸、落址,有一条不过,是一个字节都不搬的。判据写的是纯函数,住在 image_header.hpp 的 ValidateImage 里,头一条判的就是魔数,过堂的手续在 stage2.cpp 的 :166。第二道在搬完之后:头一窗落地,boot 从落位处把开头的字节抄回自己的暂存地,再认一遍的是魔数,这回认的是内存里的。第二道的手续在 boot/load/loader.cpp 的 :73:

```cpp
if (LoadWord(kHeaderScratch) != kImageMagic) {
    return LoadStatus::kMagicMismatch;
}
```

搬完了头一窗,boot 把落位处开头 8 个字节抄回暂存地 0x4000,LoadWord 读出的是头 4 个字节,对的就是 CNKZ,对不上的话就拒收,报的是 kMagicMismatch。这道闸读的是哪儿,您把机理看准:落位后的内存,0x200000 上真躺着的字节。盘上那本它早就判过了,信的是到家之后的货。

boot 办的这两道,咱们请 GDB 当一回证人。咱们把断点下在内核门口 0xffffffff802001b4。软的硬的,在这套栈上都能停:QEMU 的 gdbstub 自己看管断点,不往客人的内存里塞字节。正文里的《内核出生,和验收》当年取证用的是硬件断点 hbreak,咱们试过软断点,是照样停的,就没端那个讲究了。咱们按 continue 放行,机器一路跑完了搬运和两回换世界,停在了头一条指令上:

```text
Breakpoint 1, 0xffffffff802001b4 in ?? ()
0x200000:	0x002000015a4b4e43	0x0000000000200000
0x200010:	0x0000000000000a35	0x0000000000000c40
0x200020:	0x00000000002001b4	0x0000000000000000
rip            0xffffffff802001b4  0xffffffff802001b4
```

取证命令与题一给您的是同款,末了多问一句 rip。连上报到与道别的几行,上面咱们一并略去,抄的是断住之后的五行。x/6gx 把 0x200000 起头的 48 个字节按八字节一组念出来,咱们逐组认。头一组念的是 0x002000015a4b4e43,咱们从低位往高位数,数出来的正是 43 4e 4b 5a、01 00、20 00,念的是魔数、版本、头长。后头三组念的是 0x200000、0xa35、0xc40。再来的一组报的是 0x2001b4。末一组是补齐整边的 8 个零。落了地的户口本,跟盘上的一样。rip 站在了门牌上,内核的头一条指令正要开口。

到了第三拍,咱们把锻造链走全,拢共要走的是四步。头一步的编译链接,出的是 cinux_kernel,ELF 的本尊。第二步的 objcopy 拍裸,出来的就是 2624 个字节的 kernel.bin。第三步的 dd 码盘,说的是从第 32 号扇区起。末了一开机,stage2 照户口本把它搬进了 0x200000。这四步走完了,盘上躺了一个文件,内存里占了一段地界,两本护照各念各的。盘面上的户口咱们也顺手报一遍:打头还有一条 dd,拿 /dev/zero 把整张 1MiB 的盘铺成白纸。MBR 住的是 0 号扇区,stage2 打的是 1 号起,内核打的是 32 号起,四条 dd 在 boot/CMakeLists.txt 里各管各的那一段。

**这道算术您替盘做一做**:mem_size 比 file_size 多出 523 个字节,盘上花掉了几个字节的位子?

咱们当场算:0xC40 减 0xA35,得的是 0x20B,十进制的 523。这 523 分成两截:512 个字节的院子,加 11 个字节的缝。院子里住的是 g_idt,32 项、一项 16 字节的排法,内核出生那天挂的五桩异常处理器,登记的全是它,nm 的屏上 g_kernel_bss_start 和 g_idt 同在 0x200a40,界碑和住户合的影。盘上花了几字节?院子的 512,一个字节都没花:不带货的东西不进文件,这就是 BSS 在盘上的身份。缝的 11,反倒真花了位子,而且花的是文件中段的实位,咱们带着命令抄:

```bash
od -A d -t x1 -j 2300 -N 28 build/kernel/kernel.bin
```

```text
0002300 74 03 48 89 07 48 89 d0 c3 00 00 00 00 00 00 00
0002316 00 00 00 00 5b 6b 65 72 6e 5d 20 36
0002328
```

您看 2309 到 2319,11 个零:前脚是 .text 末字节的 c3,当的是一条 ret,后脚就是 .rodata 头一个字符串 [kern] 6 的开头。.text 的尾巴没收在 16 的整边上,链接器往中间垫了 11 个零,把 .rodata 顶到了整边上。file_size 数的是各节的和,48 加 2261 加 304 得出的 2613,缝是从来不数的。可文件是实打实排下来的,缝是躺在里头的,把 .rodata 往后顶了 11 格,文件也就随之长到了 2624。末尾的那 11 个字节,咱们从 2576 起抄 48 个字节,连终线一起给您抄:

```bash
od -A d -t x1 -j 2576 -N 48 build/kernel/kernel.bin
```

```text
0002576 cf 04 20 80 ff ff ff ff 68 05 20 80 ff ff ff ff
0002592 68 05 20 80 ff ff ff ff cf 04 20 80 ff ff ff ff
0002608 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
0002624
```

咱们看 2613 到 2623,数出来的全是零。boot 照户口本搬的只是 2613 个字节,这 11 个 .rodata 的尾巴留在盘上,是一个都没过河的。这一版算运气好的,尾巴挑在了零上。哪天 .rodata 的末尾住了真数据,它们就悄悄留在盘上了。这笔差数正文《第一个内核》的《鞋码写在鞋盒上》算过全本,咱们这儿把它跟屏对齐。

内存的那头,523 的分法倒个个儿,您看。缝的 11,boot 搬的时候顺路带到家了,落位还在老地方。院子的 512,boot 是一个字节不碰的,扫院子的手是内核自己的。kernel/arch/x86_64/entry.cpp 的 :115,KernelEntry 头一口气把 rdi 存进了局部,rdi 里躺着 boot 递的单子地址。:116 跳进了 save_handoff_and_start,:76 喊的是一句 memory_zero,从 g_kernel_bss_start 抹到了 g_kernel_bss_end,512 个字节是一个不落的。界碑是 kernel.ld 立的,:18 立的是一块,:21 立的是一块。为什么头一件事是存 rdi?当年 rep stosb 拿 rdi 当指针使,院子扫完了,单子地址也跟着洗没了,那场翻车的全本在正文《内核出生,和验收》的那两篇里,咱们留个指针就走。boot 是不替内核扫院子的,这道界限在户口本的世界里是铁的:boot 只认两个数,多一个字节都是不沾的。

一场引导的落款拢共 23 行,咱们整本抄来:

  #00 base=0000000000000000 len=000000000009FC00 type=1

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,咱们核过的一直是书页 25 与 28:加载器把内核复制进 0x80000000,跳进了 _entry。内核的文件长什么样、带不带自家的户口本,那几页是一个字都没提的。它家的加载器认什么格式,咱们得往后翻,翻到的才作数,这几页里没有的,咱们不写。

Linux 的那头,ELF 是家里的母语:内核本体是 ELF,往里加的模块也是 ELF,启动它的人手里捏着读 ELF 的章程。章程的条文咱们一条都没核过,数目是一个都不引的。可两边的处境,不用数目也看得分明:那边的机器一睁眼就有伺候的人,ELF 是念给谁听都有现成答案的。咱们这边,机器睁了眼也只认两个数,ELF 出了 objcopy 的门就拍成裸的,母语在这里只当一次性的锻坯。格式的确是同一个,处境两样:一边是日常的通用语,一边是出炉就扔的模子。

护照为什么只此一家、不求通用,这笔取舍得跟您交代。完整的 ELF,咱们一样都不认:节头表不认,符号表也是不认的,重定位还是不认的。重定位管的是内核搬到别处住时把地址改回来那类事,咱们的址在链接那刻就定了死数,是用不上它的。机器要的那点东西,48 字节的户口本就够。这个头是笔者给这门手艺拍板的:自家的自述头,字段是随用随长的,不用伺候天下的工具链。CNKZ 的这本护照,别家的机器都不认,谁读了都点头的通用好处,咱们一样没沾。还有一笔刚拍过的:ELF 的 FileSiz 数的是文件里真实占的跨径,连缝也是算的。file_size 数的是各节的和,缝是不数的。通用格式里有人替咱们记着这笔差数,自家立的章程,秤就得咱们自家校。

C++ 这回的戏,咱们在一个后缀挂着 .cpp、通篇没有一句 C++ 的文件里看。image_header_data.cpp 的整个文件就一段 asm 字符串:七个字段挨个排,魔数、版本、头长是仅有的三个手写字面量,后头的四个 quad,写的全是链接符号的名字。一个 quad 就是一格八字节的槽,前文 x/6gx 按八字节逐组认的,认的正是这个尺寸。C++ 的初始化器写不下要到链接那刻才存在的数,能把名字变成字节的,只有汇编器是办得到的。链接器落了锤,真数就铸进了文件头。换一颗内核的话,长个了,搬了家,人是一个数都不抄的。配套的一手在头文件里:ImageHeader 戴着 [[gnu::packed]],数的是 40 个字节七个字段,多出来的一格也没有。boot 和内核 include 的是同一份 image_header.hpp,护照的格式只此一份,是谁也改不拧的。

要再把这一章的数对一遍,家伙什都在您手边:readelf 与 nm 念 ELF 那本,od 念的是 CNKZ 那本,23 行的日志在 build/debugcon.log 里躺着,串口的那边空着,正好给咱们当个对照。

## 这一章留下了什么

收官的数,咱们拿实物来结。一本 48 字节的户口本,打头站着的是 CNKZ,七个字段占了 40 个字节,数字全是链接符号铸成的。一份 2624 字节的裸镜像,从第 32 号扇区起住在了盘上,boot 照户口本报的两个数把它搬进 0x200000。一笔 523 的差数,11 个零垫在了 .text 与 .rodata 中间跟着过河,512 个字节的院子留给内核自己扫。两本护照说的是同一颗内核:ELF 念给工具链和人听,CNKZ 是念给机器听的,落址、地界、换算之后的门牌,三样是一字不差的,差的那个 11 也交代清楚了。从 0x7c00 的五个字节,走到 0x200000 的两本护照,第 1 部的机器,到这儿算认全了。到了第 2 部《总论》开卷,接下来的是内核态与用户态、中断与异常、系统调用,轮到看咱们认全的机器怎么立起章程来。

| 术语 | 一句话口径 |
|---|---|
| ELF | 工件的通用语:编译器与链接器的成品穿它,工具链和人念它,机器不认 |
| 裸镜像 | objcopy 按二进制格式拍出来的内容本体,没了自我介绍,只认地址 |
| 魔数 | 文件开头的自我介绍:ELF 是 7f 45 4c 46,boot 自家的是 CNKZ(0x5A4B4E43) |
| 程序头 | 给装载的人念的数:内容放到哪儿、文件里占多少、内存里占多少 |
| 入口 | 头一条指令的门牌:护照上虚址与物理址两种字体,指同一扇门 |
| BSS | 只占地址不占文件的那截院子:boot 不认识它,内核拿界碑自己扫 |

## 练一练

两本护照是咱们自己铸的,验收的手艺也该归您。头一道您动手,把落了地的户口本请出来。第二道做的是猜想,咱们拿两道闸做文章。第三道练的是读屏,咱们给末行日志认字段。

**题一咱们动手。** 您把 r06 那场跑起来,断在了内核门口,亲眼看落位后的户口本。断点软的硬的都能停,缘故实况里交代过了,命令您照下面走:

```bash
git switch --detach r06_jump_into_kernel
cmake -B build && cmake --build build --target boot_image
timeout 120 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -display none -no-reboot -S -gdb tcp:127.0.0.1:1260 \
  -serial file:build/console.log \
  -debugcon file:build/debugcon.log &
```

重打镜像的那一步是不能省的:咱们拿陈镜像开机,屏是旧的,里头那本护照还是上一版内核的,您对的数全拧了。QEMU 冻在了复位点上,咱们让 gdb 从下一条命令进场:

```bash
gdb -q -nx -batch \
    -ex 'set architecture i386:x86-64' \
    -ex 'target remote 127.0.0.1:1260' \
    -ex 'break *0xffffffff802001b4' \
    -ex 'continue' \
    -ex 'x/6gx 0x200000' \
    -ex 'info registers rip' \
    -ex 'detach'
```

detach 之后机器把剩下的路跑完,末行的报平安落在 build/debugcon.log 里,串口那边还是空的。收尾 `git switch -` 送您回出发的那一版,新克隆的朋友落回 main。这一趟看完了,盘上的镜像、内存里的字节,是谁也没少一根汗毛的。

**题二练的是猜想。** 您把镜像第 32 号扇区起头那 48 个字节里的魔数挑一个字节改掉,您再开机,您猜 boot 会在哪一道闸拦住它,报的名字是什么?动的地方是 build/boot/cinux.img,kernel.bin 您别碰,省得下次构建把试验冲了,改完了记得抄回去。它和 loader.cpp:73 那道 kMagicMismatch 是同一位吗?不必真开机,判据都在 kernel/boot/image_header.hpp 的 ValidateImage 和 loader.cpp 里,您对着源码把两道闸的位置和次序说清,您再回参考答案里对。

**题三练的是读屏。** 题一跑完了,build/debugcon.log 里躺着的是整本日志,咱们数下来 23 行,串口那边是空的。末一行的 kernel at 200000 size C40 entry 2001B4,您对着户口本认:200000、C40、2001B4 各念的是哪个字段?file_size 的 0xA35 为什么没上屏?再数一数:23 行里,VESA 那三行是谁记的?

### 参考答案

题一:您亲手跑一回,屏的样子应当长这样:

```text
Breakpoint 1, 0xffffffff802001b4 in ?? ()
0x200000:	0x002000015a4b4e43	0x0000000000200000
0x200010:	0x0000000000000a35	0x0000000000000c40
0x200020:	0x00000000002001b4	0x0000000000000000
rip            0xffffffff802001b4  0xffffffff802001b4
```

咱们逐组核:落地的户口本跟盘上的一样,魔数、版本、头长占的是一组,四个数是各占一组的,末一组是补零的。rip 站在了 0xffffffff802001b4 上,内核的头一条指令正要开口,跟实况里那屏是一个模样的。

题二的答案:拦住它的是头一道。您翻 ValidateImage,头一条判据判的就是魔数,对不上 CNKZ 的话,当场报的是 bad magic,是一个字节都不搬的。kMagicMismatch 是另有一道的:搬完了头一窗之后,从落位处的内存里读回再验,判的是到家之后的货。盘上的闸在前,内存的闸在后,两道各管各的,同一位的魔数,两头都是放不过的。

题三:您认出来的应当是:200000 念的是 load_paddr,C40 念的是 mem_size,2001B4 念的是 entry,落址、地界、门牌三个都在,这一行是内核念交接单念出来的。0xA35 没上屏:交接单里其实带着它,stage2 从户口本把它抄进了 kernel_file_size,kernel.cpp:15 的那行打印是没念它的。VESA 三行是 stage2 挑显卡模式时记下的,1.6 的日志里照过面,来历是在正文《VESA 配屏:向显卡要一块画布》里的。
