# 05 · 与设备打交道:门牌、按铃与验货

上一章收尾,咱们把一句话留在了门外:屏上那第三行字,连收尾的换行算上 24 个字节,一个一个从 0xE9 端口送了出去,门外的设备怎么接住它们。这一章就办两件事,一件是认一认接字节的到底是谁,另一件是看咱们想往设备的方向多要一样东西的时候,该怎么开口。

量法还是老两件,规格与真码。可这一章规格那一头缺了主力,out 与 int 的正式条文住在 Intel 的手册里,咱们书架上没有那本书。所以固件到底答应了什么,拿实测说话:机器冻住抄读数,答没答、答了多少,屏上见。真码这一头也换了个锚。前四章泡在 r01_mbr、r04_protected_mode、r05_long_mode 里,这一章退回 stage2 刚安家的那版,实况锚 r02_e820,`git switch --detach r02_e820` 切过去,看完 `git switch -` 切回来。

还有一句得交代在门面上。这一章牵的文件多:端口住在 boot_port.hpp,打印住在 boot_console.hpp,问固件的住在 bios.cpp,条目长什么样住在 e820.hpp。行号各数各的反而添乱,咱们点名一律把文件和函数一起报,全仓不重号,您翻起来丢不了。

## 打出去的字节,落进了谁的手里

> **前四章里,咱们往 0xE9 送了一路字,机器里究竟是谁接的?回头要向设备讨东西,又该按什么礼数开口?**
>
> 头一问的答案有点煞风景:接字节的不是哪家设备,是 QEMU 自己。第二问的答案是一场握手:参数摆齐,铃按下去,回话还得验三道。这一章咱们把两桩各走一遍,读数全是咱们当场抄的,一拍一拍摆给您看。

## 头一扇门:门牌,加一个字节

机器对外打交道的门,前置卷《设备怎么碰》里数过两扇:显存那扇不用报门牌,地址算好,mov 就到。端口那扇得报门牌,out 进 in 出。0xE9 属于端口这扇。前三章把这扇门叫得随意,串口、调试口混着来。1.2《字节寄存器与栈》里叫的是调试口,叫对了,到上一章咱们又一路顺口喊它串口。这一章把名字认准,后文一律叫调试口:它是 QEMU 自己开的调试口,行话 debugcon,不在任何一块芯片上。真串口是 0x3F8 那扇门,正文后面的站才走到它跟前,跟今天这扇不是一回事。

脾气也认一认。它是单行道,字节只出不进。您 out 一个字节过去,再从同一个门牌讨一个回来,它还您的还是 0xE9——QEMU 的实现脾气,前置卷量过。放到真正的硬件上,这扇门多半压根不存在,out 出去的字节落在没人认领的端口上,无声无息。它是 QEMU 递给咱们的一条报信小道,咱们使唤它,也记着它是借来的。

咱们这头的动作小得很。PutChar 整个函数就一句 out,汇编出来两个字节:e6 e9。e6 是 out 的操作码,e9 是门牌。门牌不长在设备身上,长在指令的第二个字节里,报门牌这动作,编指令的时候就办完了。0x7e27 那儿,咱们量过,您自己 `objdump -d build/boot/stage2` 照一眼,也能看见它俩挨着躺。PutString 在外头套了个圈:取字符,判零,送,挪一步,再来。全函数拢共一声 out,stage2 打出的屏面字,一个不落,全打这儿过。

还有两行的出身要单独认。Ready to call bios 与 Jump to Stage 2 出自 MBR 自带的另一份 PutString,512 字节的小屋里各链各的副本,送的是同一个门牌。日志里它们打头,等会儿实况里您会看见。

## 第二扇门:按铃,把桌摆齐了再按

out 的句式短,一句话说完。设备那头要是肯给的东西不止一个字节,开口的姿势就得换。问固件代办,咱们走的是另一套:int 按铃,按的还是 1.1《一条指令的一生》拍过的那道手续,控制权顺着向量表交出去,办完事带话回来。这一章的两声铃,都通向同一位固件 BIOS,走的同一条指令 int 0x15。

头一声铃轻车简从。ax 里装一个号 0x2401,int 0x15 响铃,完事。固件的答话写在 CF 位上:CF,进位标志,加减法的进位归它记。在这口铃底下,它清着算成。代码里收尾那句 setae,干的就是读它:CF 没立就置 1,“成了”从旗子变成个数。A20 开没开成,全凭固件答应不答应,咱们能担保的,只有号报得对不对。A20 为何要有这道手续,那根地址线有怎样的旧事,正文《一根地址线的老故事》专管,咱们机器层只认眼前这套动作。

第二声铃就厚道多了。问机器有多少内存,咱们要的还是同一位固件、同一口铃,礼数整整厚一层。ax 里装的换成暗号 0xE820,这一声问的是内存图谱。光有暗号不够,固件要往咱们的地里写东西,桌面上得摆四样:ecx 装 24,告诉它缓冲给多大。edx 装 0x534D4150,这是要验的签。es:di 指到缓冲头一格,货往那儿卸。ebx 里揣着续传的号,表长的时候固件一回说不完,留个号让下回接着问。es 还得专门安顿:咱们的段是平的,es 与 ds 本是同一个值,可固件只认 es:di 这对搭档,于是 push ds、pop es,当着面把 ds 抄给 es。

**停一停,您换个念法**:edx 里那个 0x534D4150,别按数念,一对一对切开,按字母念。0x53、0x4D、0x41、0x50,念出来是什么词?这个暗号为什么长成个词的模样,您也猜一猜。

答案是 S、M、A、P,固件自报家门的签。数字里藏单词,挑得巧,人眼一读就有数,验的时候好认。您往下看,签的用处马上见分晓。

回话进来,验三道。头一道验 CF。代码里那句 setb,问的是“立了没”,立了算败,跟 A20 那句 setae 问的是同一位,问法拧了个方向:那边问清没清,这边问立没立。bios.cpp 里,笔者在 EnableA20AddressLine 那句汇编的旁边留了一行注,记下 A20 与 E820 的 carry 语义相反。这句在源码里写作 setnc,反汇编里报 setae,没进位与高于等于,同一句指令的两个叫法。到机器层,这话还能再说准一点:位是同一位,问的是相反的两头。第二道验签:eax 得把 0x534D4150 原样吐回来,签对上了,才认这趟回话。第三道验斤两:ecx 报回来多少字节,低于 20 不收。为什么是 20?咱们的条目 24 字节,末尾的 acpi_attr 是 ACPI 时代添的属性格,咱们没向固件讨,固件只交头 20 个字节。20,恰好压线。

循环还有两笔交代:ebx 的号走到零,固件交清收工。咱们自己也数条数,收满 32 条打住,题二请您去汇编里数这道封顶。

## Code: Cinux 实况:一声 A20,一桌 E820

这一场的实况锚是 r02_e820,机器冻五回:两回看 A20,两回看握手,一回收数。断点拢共五枚,分住三处。头两枚落在 bios.cpp 的 EnableA20AddressLine 里,0x804d 与 0x804f 夹着 A20 那声 int。中间两枚换到同文件的 CollectMemoryMap,0x8095 与 0x8097 夹着问表那声 int。第五枚落在 0x7eed,那是 stage2.cpp 里 Stage2Main 的地界,收数那一停就停在它身上。A20 的一对断点各响一回就歇,E820 的一对跟着七项各响七回。头四停到手,咱们把前四个搁下,再一路续到收数那一停。GDB 的实模式读数有两句口径交代在头里:寄存器名得写全,写 eax、edx 才看得到全值,ax、dx 只给半截。eflags 那一行,方括号里是它认出来的旗标名单,没点名的,就是清着的。

头两停,咱们把 A20 的问答冻在铃声两侧:

```text
Breakpoint 1, 0x000000000000804d in ?? ()

eflags         0x46                [ IOPL=0 ZF PF ]

Breakpoint 2, 0x000000000000804f in ?? ()
eflags         0x46                [ IOPL=0 ZF PF ]
```

断点下装那几行、开场找不到可执行文件的抱怨,咱们一并省了。头一停,号已就位,eax 是 0x2401。eflags 0x46,名单里没有 CF,可这一拍它作不了数,int 还没响,它是上一段代码留下的值。第二停,int 落地,eflags 还是 0x46,CF 依旧清着,setae 就认它,A20 判成。有一点咱们不揽功:单看这一屏,分不清这个“清”是固件动手清的,还是压根没立过。setae 不问来历,它只读 int 落地那一拍上 CF 的值,成的凭据就是它,成不成,全看固件。

0x7eed 这个址挑得有点讲究,咱们把它的身份交代给您:它是成功路径的头一句,一条 mov,正伸手去 0x8e40 搬 count。0x8e40 的来历也报得上来:条目 32 项、一项 24 字节,32 乘 24 是 0x300,垫在 g_memory_map 头上,0x8b40 加 0x300,恰好是 count 的家。读数 0x00000007,七项落袋。往下 42 个字摊开,168 个字节,42 正是 7 项乘 6 格:每项在内存里占六格,头两格 base,中间两格 len,第五格 type,末一格 acpi_attr。

咱们拿第三项演一遍读法。第三项从 0x8b88 起头,六格跨着两行印:0x8b80 行的后两格是它的 base,0x8b90 行的头四格是 len、type 与 acpi_attr。头两格拼数,小端的躺法 1.2 教过,base = 0x0000000000100000。中间两格,len = 0x0000000007EE0000,合 126.875 MiB。第五格 type = 1,能用。末一格是 acpi_attr,0,没讨,固件没给,如实记下。七项里 type 为 1 的就两段。头一段到 0x9FC00 为止,639 KiB,距 640 KiB 差的那 1 KiB,固件记在第二项名下保留,那片叫 EBDA,固件自家的小厨房,这里点个名就走。另一段就是方才的 126.875 MiB。两段相加,约 127.5 MiB,这套配置给机器的 128 MiB。当中还有一处空当要点名:640 KiB 到 1 MiB 之间的那 320 KiB,0xA0000 到 0xF0000,清单里谁的名下都没写,显存与固件自家落脚的地界,固件不递,咱们也不问。剩下的差数,散在各保留段里。清单还一直画到 4 GiB 开外:末一项的 base 是 0xFD00000000,天边一片,也标着保留。

七项的 type 只有 1 和 2。固件手里的暗号不止两类,e820.hpp 里 EntryType 枚举立着五类:1 能用,2 保留,3 与 4 归 ACPI,5 是坏的。翻不认识的数落进哪类?咱们看看笔者在 ClassifyEntry 的源码注里写的道理:把能用的当保留,亏的是几页内存。把保留的当能用,东西就得往洞里放。所以翻译表把不认识的数一律当保留,宁可亏几页,不上洞里放东西。

末了还有一笔出身要记。这七行清单,出自 qemu-system-x86_64。同一个镜像拿 qemu-system-i386 起机器,清单短一段,固件少报了天边那一项,数到六就收。机器报多少,咱们记多少,清单跟着机器走,不跟着谁的记性走。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,1.1 立下的口径,咱们核过的是书页 25 与 28:加载器把内核复制进 0x80000000,跳进 _entry。书页 28 只捎带一句,低地址住的是输入输出设备。机器怎么认设备,那几页没展开,书里另有章节,咱们没核,不引。

Linux 认设备靠一整套发现机制,固件递来的表只是它进门的一条道。那套机制的书,咱们一页都没翻过。没翻过就写,写进书里的只能是编的,这段就空着。

咱们也把自家的取舍摆明白。boot 阶段对设备的全部社交,拢共只有一个 out。驱动不写,中断不碰,DMA 不沾。固件能代办的,开地址线、报内存图、读盘,全托给它。代价也得认下:A20 成没成,凭据只有眼前机器给出的一格 CF,换份固件,这屏说了不算。固件是能干的代办,可咱们一时还管不动它。设备自己开口叫人、不劳咱们一步一步搬的日子,在下一章。

C++ 在这一章也留了成对的一句话,两层各管一头。端口那头,boot_port.hpp 里 kDebugconPort 是个 constexpr 的 0xE9,喂进 asm 的约束写作 `Nd`:那颗 N 允许端口吃编译期常数,0xE9 不超过 255,编译器就把它写进指令肚子里,0x7e27 那对字节,e6 后面跟着的正是 e9。表那头,e820.hpp 给 MemoryMapEntry 戴上 `[[gnu::packed]]`,底下五条 static_assert:四个字段各在第几字节、整项 24 字节,编译期一条条核过。MemoryMap 整体 32 项乘 24 再加 4,也有一条守着。固件按字节卸货,结构体差一格,七项全得错位,这样的错编译器替咱们看着,等不到机器开口。

想核原文的,路牌插在这儿:前置卷《设备怎么碰》管两扇门和调试口的脾气,整篇的现场都在。正文里的《一根地址线的老故事》与《问 BIOS 要一张内存图》,管 A20 的家史和这桌握手的全本礼数。至于 in、out 的正式条文,咱们书架上没有那本手册,本章读到的每一个数,出处都是咱们自己的屏。

## 这一章留下了什么

这一章的物件不多,件件都过过手。一条 e6 e9,门牌长在指令第二个字节里。一声 int 前后的一组寄存器:eax 的暗号、ecx 的尺寸、edx 的签,外加 es:di 那个卸货地址,回来还要过 CF、验签、量斤两三道。一张七行清单,连同 0x8b40 起的那 168 个字节,能用的两段合着约 127.5 MiB,每一项都能指到址上。这批家当是固件递的,递来什么、记在哪一格,咱们如今全能对出来。哪天轮到设备不请自来,开口叫人,那是下一章的事。

| 术语 | 一句话口径 |
|---|---|
| 端口 | x86 对外的门牌,报了号 out 进 in 出,0xE9 是其中之一 |
| 调试口(debugcon) | QEMU 自开的单向口,收 0xE9 的字节落进日志,真正的硬件上没有它 |
| int 0x15 | 请固件办事的那口铃,A20 与 E820 都走它 |
| E820 | 问固件要内存图谱的暗号:0xE820 加 SMAP 签,桌面上还得摆尺寸与卸货地址 |
| SMAP | 0x534D4150,按字母念就是 SMAP,固件自报家门的签,回话要原样验 |
| carry(CF) | 进位标志,A20 问它清没清,E820 问它立没立,同一位两种问法 |

机器冻住了才看得见的东西,得您亲手去冻一回。头一道动手,把验签那一停握在自己手里。第二道猜想,数一数封顶。第三道读屏,把清单和内存对上。

**题一,动手。** 切到 r02_e820,把镜像编出来,QEMU 挂上调试口。这一回它不当后台黑箱,0xE9 收到的字节全落进 build/debugcon.log 文件里。这一套笔者写完本章又从零跑了一遍,连日志都是刚跑出来的,您跟着敲就是:

```bash
git switch --detach r02_e820
cmake -B build && cmake --build build --target boot_image
timeout 120 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -nographic -display none -no-reboot -S -gdb tcp:127.0.0.1:1250 \
  -debugcon file:build/debugcon.log &
```

`-S` 让 QEMU 把机器按在出生那一拍,0xE9 一个字节都没出门,您手头的 build/debugcon.log 眼下还是空的。断点下在 0x8097,等的是问表回话落地的那一拍:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1250' \
    -ex 'break *0x8097' \
    -ex 'continue' \
    -ex 'info registers eax ecx eflags' \
    -ex 'detach'
```

您 detach 之后,机器接着把七项问完,原地去 hlt 里待命。SeaBIOS 与 iPXE 出场那几声吆喝照旧会滚过屏,不用分神。回头 `cat build/debugcon.log`,十三行日志躺在里面。末了 `git switch -` 送版本回家,新克隆的仓落回 main。

**题二,猜想。** 本章前文里留过一句:咱们自己也数条数,收满 32 条打住。您去汇编里找这道封顶的下落:

```bash
objdump -d build/boot/stage2 | grep -B3 -A2 'cmp.*0x1f'
```

数一数 cmp 后面那个数,再猜:真有一台机器要报第 33 段,它去哪儿了?咱们手里的清单,会不会显得一切正常?

**题三,读屏。** 趁题一的机器还在 hlt 里待命,您再挂一回 gdb,把第三项从内存里请出来。要是等得太久,QEMU 让 timeout 收走了,回题一重新挂起再连,一样取得到:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1250' \
    -ex 'x/1xw 0x8e40' \
    -ex 'x/6xw 0x8b88' \
    -ex 'detach'
```

您拿着六个格子,回头对日志里 #03 那一行:base 对不对得上?len 对不对得上?type 是几?六个格子怎么念成三个数,本章前文里演过一遍。

### 参考答案

题一:您断住时,读数应该长这样:

```text
Breakpoint 1, 0x0000000000008097 in ?? ()
eax            0x534d4150          1397571920
ecx            0x14                20
eflags         0x2                 [ IOPL=0 ]
```

eax 原样吐回,签对上。ecx 报 20,压线。eflags 0x2,名单里没有 CF,清着,setb 放行。您 cat 出来的日志拢共十三行,七行清单一行不少,末行 alive。

题二:封顶住在循环收尾,`66 83 ff 1f` 后面跟着 `77 05`:count 数到 32,一句 ja 跳去收工,收工时连固件的续传号都不看,直接返回 0。所以第 33 段不进清单,清单照常打印,机器一声不吭,一切显得正常。封顶的脾气就在这儿:它不报错,它就是不多收。咱们眼前的机器只有七项,封顶没轮到出场。

题三:六个格子念三个数,小端一路。头两格 00100000 与 00000000 拼 base,得 0x0000000000100000,对上日志的 base=0000000000100000。中间两格 07ee0000 与 00000000 拼 len,得 0x0000000007EE0000,对上 len=0000000007EE0000。第五格 00000001,type=1。末一格 0,acpi_attr,咱们没讨的属性格。0x8b88 这个址也有来历:0x8b40 加 3 乘 24,第三项的门口。
