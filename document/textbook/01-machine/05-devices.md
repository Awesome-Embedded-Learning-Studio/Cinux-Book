# 05 · 与设备打交道:门牌、按铃与验货

上一章收尾的时候,咱们把一句话留在了门外:屏上那第三行字,连收尾的换行算上 24 个字节,一个一个从 0xE9 端口送了出去,门外的设备怎么接住它们。这一章咱们就办两件事,一件是认一认接字节的到底是谁,另一件是看咱们想往设备的方向多要一样东西的时候,该怎么开口。

量法咱们还是老两件,规格与真码咱们两样都量。可这一章规格那一头缺了主力,out 与 int 的正式条文住在 Intel 的手册里,咱们书架上没有那本书。所以固件到底答应了什么,咱们就拿实测说话:把机器冻住抄读数,答没答、答了多少,您在屏上见。真码这一头也换了个锚。咱们前四章泡在 r01_mbr、r04_protected_mode、r05_long_mode 里,这一章退回 stage2 刚安家的那版,实况锚咱们用 r02_e820,`git switch --detach r02_e820` 您切过去,看完您再拿 `git switch -` 切回来。

咱们还有一句得交代在门面上。这一章牵的文件多:端口住在 boot_port.hpp,打印咱们放在 boot_console.hpp,问固件的住在 bios.cpp,条目长什么样住在 e820.hpp。行号各数各的反而添乱,咱们报位置一律把文件和函数一起报,所以全仓不重号,您翻起来丢不了。

## 打出去的字节,落进了谁的手里

> **其实前四章里,咱们往 0xE9 送了一路字,机器里究竟是谁接的?回头要向设备讨东西,又该按什么礼数开口?**
>
> 头一问的答案有点煞风景:接字节的其实是 QEMU 自己。第二问的答案是一场握手:参数摆齐,咱们把铃按下去,回话咱们还得验三道。这一章咱们把两桩各走一遍,读数全是咱们当场抄的,一拍一拍摆给您看。

## 头一扇门:门牌,加一个字节

机器对外打交道的门,前置卷《设备怎么碰》里数过两扇:显存那扇不用报门牌,地址算好,咱们一句 mov 就到。端口那扇咱们得报门牌:咱们拿 out 送字、拿 in 取字。0xE9 咱们归在端口这扇名下。前三章咱们把它叫得随意,串口、调试口咱们混着叫。1.2《字节寄存器与栈》里叫的是调试口,叫对了,到上一章咱们又一路顺口喊它串口。这一章咱们把名字认准,后文一律叫调试口:它是 QEMU 自己开的调试口,行话里咱们叫它 debugcon,咱们在任何一块芯片上都找不到它。真串口您要到 0x3F8 端口上去找,正文后面的站才走到它跟前,跟今天咱们用的这个不是一回事。

咱们把脾气也认一认:它是条单行道,所以字节只出不进。您 out 一个字节过去,咱们再从同一个门牌讨一个回来,它还您的还是 0xE9——QEMU 的实现脾气,咱们在前置卷量过。放到真正的硬件上,咱们多半会发现这个调试口压根不存在,out 出去的字节落在没人认领的端口上,咱们连一点声息都收不到。它是 QEMU 递给咱们的一条报信小道,咱们使唤它,也记着它是借来的。

咱们这头的动作小得很。PutChar 整个函数咱们就写一句 out,那咱们汇编出来就是两个字节:e6 e9。e6 是 out 的操作码,e9 咱们认作门牌。其实门牌不长在设备身上,长在指令的第二个字节里,咱们报门牌这动作,编指令的时候就办完了。0x7e27 那儿咱们量过,您自己 `objdump -d build/boot/stage2` 照一眼,您也能看见它俩挨着躺。PutString 在外头套了个圈,咱们在里面取字符、判零、送、挪一步、再来。全函数咱们拢共一声 out,stage2 打出的屏面字,咱们一个都没落下,全打咱们这儿过。

还有两行的出身要单独认。Ready to call bios 与 Jump to Stage 2 出自 MBR 自带的另一份 PutString,512 字节的小屋里各链各的副本,送的是同一个门牌。日志里您见到的头两行就是它们,等会儿实况里您会看见。

## 第二扇门:按铃,把桌摆齐了再按

out 的句式短,一句话咱们就说完。设备那头要是肯给的东西不止一个字节,开口的姿势就得换。要问固件代办的话,咱们走的是另一套:int 按铃,按的还是 1.1《一条指令的一生》拍过的那道手续,咱们把控制权顺着向量表交出去,固件办完了事再带话回来。这一章的两声铃,响到的都是同一位固件 BIOS,走的同一条指令 int 0x15。

头一声铃咱们按得轻车简从。咱们往 ax 里装一个号 0x2401,拿 int 0x15 响了这一声铃,事情就算完了。固件的答话写在 CF 位上:CF 就是进位标志,加减法的进位归它记。咱们这口铃底下,它清着就算成了。咱们代码里收尾的那句 setae,干的就是读它:CF 没立就置 1,“成了”就从旗子变成了个数。A20 开成了没有,凭的全是固件答应不答应,咱们能担保的,就只剩号报得对不对了。您要问 A20 为何要有这道手续,那根地址线有怎样的旧事,正文《一根地址线的老故事》专管,咱们机器层只认眼前这套动作。

第二声铃就厚道多了。咱们问机器有多少内存,要的还是同一位固件、同一口铃,礼数就整整厚了一层。ax 里装的换成暗号 0xE820,这一声问的是内存图谱。光有暗号的话还不够,固件要往咱们的地里写东西,咱们桌面上就得摆四样:ecx 装 24,咱们告诉它缓冲给多大。edx 里装的是 0x534D4150,这是要验的签。es:di 指到咱们缓冲的头一格,固件的货就往那儿卸。ebx 里揣着续传的号,表长的时候固件一回说不完,固件留个号让咱们下回接着问。es 还得专门安顿:咱们的段是平的,es 与 ds 其实是同一个值,可固件认的就只有 es:di 这对搭档,于是咱们 push ds、pop es,当着面把 ds 抄给了 es。

**咱们停一停,您换个念法**:edx 里那个 0x534D4150,您别按数念了,把它切成了一对一对,按字母念出来的就是 0x53、0x4D、0x41、0x50,这一串念出来是什么词?这个暗号为什么长成个词的模样,您也猜一猜。

您念出来的答案是 S、M、A、P,固件自报家门的签。您看数字里藏的是单词,挑的这一手也巧,咱们人眼一读就有数,验的时候也好认。您往下看,签的用处马上见分晓。

回话进来的时候,咱们验三道。头一道咱们验 CF。咱们代码里那句 setb,问的是“立了没”,立了算败,跟 A20 那句 setae 问的是同一位,问法拧了个方向:那边问的是清没清,这边问的就是立没立。咱们翻到 bios.cpp 里,笔者在 EnableA20AddressLine 那句汇编的旁边留了一行注,记下 A20 与 E820 的 carry 语义相反。这句咱们在源码里写作 setnc,到了反汇编里报的却是 setae,没进位说的是一个,高于等于说的是另一个,那是同一句指令的两个叫法。到了机器层,咱们把这话再说得准一点:位是同一位,问的是相反的两头。第二道咱们验签:eax 得把 0x534D4150 原样递回来,签对上了,咱们才认这趟回话。第三道咱们验斤两:ecx 报回来多少字节,低于 20 的就不收。为什么是 20?咱们的条目 24 字节,末尾的 acpi_attr 是 ACPI 时代添的属性格,咱们没向固件讨,固件交的就只有头 20 个字节。交回来的 20,在咱们这儿恰好压线。

循环还有两笔交代:ebx 的号走到零,固件也就交清收工了。咱们自己也数着条数,满了 32 条就打住,题二请您去汇编里数这道封顶。

## Code: Cinux 实况:一声 A20,一桌 E820

这一场的实况锚是 r02_e820,咱们把机器冻五回:两回看 A20,两回看的是握手,末一回咱们收数。咱们拢共下了五枚断点,给它们分住了三处。头两枚落在 bios.cpp 的 EnableA20AddressLine 里,0x804d 与 0x804f 夹着的正是 A20 那声 int。中间两枚换到同文件的 CollectMemoryMap,0x8095 与 0x8097 夹着的是问表那声 int。第五枚咱们落在 0x7eed,那是 stage2.cpp 里 Stage2Main 的地界,咱们收数的那一停就停在它身上。A20 的一对断点各响一回就歇,E820 的一对跟着七项各响七回。头四停到了手,咱们把前四个搁下,再一路续到咱们收数的那一停。GDB 的实模式读数有两句口径交代在头里:寄存器名得写全,咱们写 eax、edx 才看得到全值,写 ax、dx 的话,您只拿得到半截。eflags 的那一行,方括号里是它认出来的旗标名单,名单里没提的,就是清着的。

咱们把头两停的 A20 问答冻在铃声两侧:

断点下装那几行、开场找不到可执行文件的抱怨,咱们一并省了。咱们头一停看到的是:号已就位,eax 里装的是 0x2401。eflags 的值是 0x46,名单里没有 CF 的影子,可这一拍它作不了数,这时的 int 还没响,它是上一段代码留下的值。第二停咱们看,int 落地了,eflags 的值还是 0x46,CF 依旧是清的,setae 认的就是它,A20 这就判成了。有一点咱们不揽功:单看这一屏,咱们分不清这个“清”是固件动手清的,还是压根就没立过的情形。setae 是不问来历的,它只读 int 落地那一拍上 CF 的值,成的凭据就是它,成不成就全看固件了。

咱们挑 0x7eed 这个址,是有点讲究的,咱们把它的身份交代给您:它是成功路径的头一句,是一条正伸手去 0x8e40 搬 count 的 mov。0x8e40 的来历也报得上来:条目 32 项、一项 24 字节,32 乘 24 得的就是 0x300,垫在 g_memory_map 的头上,咱们拿 0x8b40 加 0x300,恰好是 count 的家。咱们读到的数是 0x00000007,七项落了袋。往下摊开的 42 个字合成 168 个字节,42 的来路正是 7 项乘 6 格:每项在内存里占六格,头两格装的是 base,中间两格躺的是 len,第五格写的是 type,末一格留的是 acpi_attr。

咱们拿第三项演一遍读法。第三项起头的址是 0x8b88,六格跨着两行印:0x8b80 行的后两格是它的 base,0x8b90 行的头四格是 len、type 与 acpi_attr。头两格拼出来的数,小端的躺法 1.2 教过,base 拼出来的是 0x0000000000100000。中间两格拼的 len = 0x0000000007EE0000,合的就是 126.875 MiB。第五格的 type = 1,是能用的。末一格装的是 acpi_attr:0,咱们没讨,固件也没给的,咱们如实记下了。七项里 type 为 1 的就两段。头一段到 0x9FC00 为止的 639 KiB,距 640 KiB 差的那 1 KiB,固件记在了第二项的名下保留,它的名字叫 EBDA,是固件自家的小厨房,咱们记下这个名字就走。另一段就是方才的 126.875 MiB。两段相加的结果约 127.5 MiB,这套配置给机器的 128 MiB。当中还有一处空当要交代:640 KiB 到 1 MiB 之间的那 320 KiB,也就是 0xA0000 到 0xF0000 的地界,清单里谁的名下都没写,显存与固件自家落脚的地界,固件不递的,咱们也不问。剩下的差数,散在各保留段里了。清单还一直画到 4 GiB 开外:末一项的 base 是 0xFD00000000,天边的一片,标的也是保留。

七项的 type 只有 1 和 2。固件手里的暗号不止两类,咱们在 e820.hpp 里给 EntryType 枚举立了五类:1 的意思是能用,2 的意思是保留,3 与 4 归的是 ACPI,5 是坏的。翻不认识的数落进哪类?咱们看看笔者在 ClassifyEntry 的源码注里写的道理:把能用的当保留,亏的是几页内存。把保留的当能用,咱们的东西就得往洞里放。所以翻译表把不认识的数一律当保留,咱们宁可亏几页也不上洞里放东西。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,1.1 立下的口径,咱们核过的是书页 25 与 28:加载器把内核复制进 0x80000000,跳进的是 _entry。书页 28 捎带的只有一句,低地址住的是输入输出设备。机器怎么认设备,那几页是没展开的,另有的章节咱们没核过,也就不引了。

Linux 认设备靠的是一整套发现机制,固件递来的表只是它进门的一条道。那套机制的书,咱们一页都没翻过。咱们要是没翻过就写,写进书里的只能是编的,这段咱们就空着。

咱们也把自家的取舍摆明白。boot 阶段对设备的全部社交,咱们拢共只出了一声 out。驱动咱们不写,中断咱们不碰,DMA 咱们也不沾。固件能代办的,开地址线、报内存图、读盘,咱们全托给它。代价咱们也得认下:A20 成没成,凭据只有眼前机器给出的一格 CF,换一份固件的话,这屏说了不算。固件是能干的代办,可咱们一时还管不动它。设备自己开口叫人、不劳咱们一步一步搬的日子,在咱们的下一章。

C++ 在这一章也留了成对的一句话,咱们让两层各管一头。端口的那一头,boot_port.hpp 里 kDebugconPort 是个 constexpr 的 0xE9,喂进 asm 的约束写作 `Nd`:那颗 N 允许端口吃编译期常数,咱们的 0xE9 不超过 255,编译器就把它写进了指令肚子里,0x7e27 的那对字节里,e6 后面跟着的正是 e9。表的那一头,咱们在 e820.hpp 里给 MemoryMapEntry 戴上 `[[gnu::packed]]`,底下守着的五条 static_assert:四个字段各在第几字节、整项 24 字节,咱们在编译期一条条核过。MemoryMap 整体的 32 项乘 24 再加 4 也有一条守着。固件是按字节卸货的,结构体差了一格,七项也就全错了位,这样的错,编译器在机器开口之前就替咱们看着了。

想核原文的,路牌插在这儿:前置卷《设备怎么碰》管两扇门和调试口的脾气,整篇的现场都在。正文里的《一根地址线的老故事》与《问 BIOS 要一张内存图》,管 A20 的家史和这桌握手的全本礼数。至于 in、out 的正式条文,咱们书架上没有那本手册,本章读到的每一个数,出处都是咱们自己的屏。

## 这一章留下了什么

这一章的物件不多,咱们件件都过过手。咱们用过的一条 e6 e9,门牌长在指令的第二个字节里。一声 int 前后的一组寄存器:eax 的暗号、ecx 的尺寸、edx 的签,外加 es:di 那个卸货地址,回来咱们还要过 CF、验签、量斤两三道。咱们收进了一张七行清单,连同 0x8b40 起的那 168 个字节,能用的两段合着约 127.5 MiB,每一项咱们都能指到址上。这批家当是固件递的,递来什么、记在哪一格,咱们如今全能对出来。轮到设备不请自来、开口叫人的那一天,咱们在下一章见。

| 术语 | 一句话口径 |
|---|---|
| 端口 | x86 对外的门牌,报了号 out 进 in 出,0xE9 是其中之一 |
| 调试口(debugcon) | QEMU 自开的单向口,收 0xE9 的字节落进日志,真正的硬件上没有它 |
| int 0x15 | 请固件办事的那口铃,A20 与 E820 都走它 |
| E820 | 问固件要内存图谱的暗号:0xE820 加 SMAP 签,桌面上还得摆尺寸与卸货地址 |
| SMAP | 0x534D4150,按字母念就是 SMAP,固件自报家门的签,回话要原样验 |
| carry(CF) | 进位标志,A20 问它清没清,E820 问它立没立,同一位两种问法 |

## 练一练

机器冻住了才看得见的东西,得您亲手去冻一回。头一道请您动手,把验签的那一停握在自己手里。第二道请您猜想,数一数封顶的数。第三道请您读屏,亲手把清单和内存的数对上。

**题一请您动手。** 请您切到 r02_e820 把镜像编出来,咱们再给 QEMU 挂上调试口。这一回它就不当后台黑箱了,0xE9 收到的字节全落进 build/debugcon.log 文件里。这一套笔者写完本章又从零跑了一遍,连日志都是刚跑出来的,您跟着敲就是:

```bash
git switch --detach r02_e820
cmake -B build && cmake --build build --target boot_image
timeout 120 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -nographic -display none -no-reboot -S -gdb tcp:127.0.0.1:1250 \
  -debugcon file:build/debugcon.log &
```

`-S` 让 QEMU 把机器按在出生的那一拍上,0xE9 的口上一个字节都没出门,您手头的 build/debugcon.log 眼下还是空的。断点咱们下在 0x8097,等的是问表回话落地的那一拍:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1250' \
    -ex 'break *0x8097' \
    -ex 'continue' \
    -ex 'info registers eax ecx eflags' \
    -ex 'detach'
```

您 detach 之后机器接着把七项问完,原地去 hlt 里待命。SeaBIOS 与 iPXE 出场的那些吆喝照旧会滚过屏,您不用分神。回头您 `cat build/debugcon.log`,十三行日志躺在里面等着您。末了 `git switch -` 送版本回家,新克隆的仓落回 main。

**题二请您猜想。** 本章前文里留过一句:咱们自己也数条数,满了 32 条就打住。您去汇编里找这道封顶的下落:

```bash
objdump -d build/boot/stage2 | grep -B3 -A2 'cmp.*0x1f'
```

您来数一数 cmp 后面跟的那个数,咱们再猜:真有机器要报第 33 段的话,那段去哪儿了?咱们手里的清单,会不会显得一切正常?

**题三请您读屏。** 趁题一的机器还在 hlt 里待命,您再挂一回 gdb,咱们把第三项从内存里请出来。您要是等得太久,QEMU 让 timeout 收走了,咱们回题一重新挂起再连,照样取得到您要的:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1250' \
    -ex 'x/1xw 0x8e40' \
    -ex 'x/6xw 0x8b88' \
    -ex 'detach'
```

您拿着六个格子,回头对日志里 #03 那一行:base 对不对得上?len 对不对得上?type 是几?六个格子怎么念成三个数,本章前文里给咱们演过一遍。

### 参考答案

题一:您断住时,读出来的数应该长这样:

```text
Breakpoint 1, 0x0000000000008097 in ?? ()
eax            0x534d4150          1397571920
ecx            0x14                20
eflags         0x2                 [ IOPL=0 ]
```

eax 原样递了回来,签也对上了。ecx 报的是恰好压线的 20。eflags 的值是 0x2,名单里没有 CF 的影子,清的,setb 放了行。您 cat 出来的日志拢共十三行,七行清单是一行不少的,末行打的是 alive。

题二:封顶就住在循环的收尾,`66 83 ff 1f` 的后面跟着 `77 05`:count 数到 32,一句 ja 跳去收了工,收工时连固件的续传号都不看,直接返回的是 0。所以第 33 段不进清单,清单还是照常打印的,机器是一声不吭的,咱们看不出一处不对。封顶的脾气就在这儿:它不报错,它就是不肯多收的。咱们眼前的机器只有七项,封顶压根没轮到出场的机会。

题三:六个格子咱们念成三个数,走的还是小端的一路。头两格的 00100000 与 00000000 拼 base,得到的是 0x0000000000100000,对得上日志的 base=0000000000100000。中间两格的 07ee0000 与 00000000 拼 len,得到的是 0x0000000007EE0000,对得上日志的 len=0000000007EE0000。第五格的 00000001 说的就是 type=1。末一格的 0,就是咱们没讨的 acpi_attr 属性格。0x8b88 这个址的来历,咱们也报得上来:0x8b40 加 3 乘 24,第三项的门口。
