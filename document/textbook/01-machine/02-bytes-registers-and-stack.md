# 02 · 字节寄存器与栈:名字报尺码,前缀拨口径

上一章咱们贴着取指循环走了一遭,看着一条条指令把架构状态花出去。花归花,有一件事咱们一直囫囵咽着:每一回搬运,到底搬几个字节。mov 把 AX 送进内存,送的是两字节还是四字节?call 往栈里压返回地址,压的又是几格?上一章结尾咱们许过愿:把家当摊开,细看字节、寄存器和栈怎么互相搬东西。这一章就来还愿。

量法跟上一章一个路数:书给规格,真码对数。《深入理解计算机系统》,行话里叫 CS:APP,咱们引的第二版以 32 位 IA32 为纲,引到年代专属的说法,咱们随文标清楚。实况还看 r01_mbr:寄存器的宽窄、栈的进出、多字节值的躺法,要的证据都在这 512 字节里。

## 一台 16 位的机器,两个 call

> **同样一台 16 位的机器,桩里手写的 call,与 C++ 编出来的 call,压下去的返回地址一样宽吗?**
>
> 直觉多半抢着答:不一样吧,一边是 16 位的老习惯,一边是编译器的新习惯。可这两个 call 住在同一台机器,用的是同一条栈。编出来的 call 那头有配对的 ret 等着弹,压几格、弹几格得对得上,手写的 call 进的 MbrMain 也是 C++ 编的,客人一进门就按编译器的口径动栈。宽度要是各说各的,栈上的进出就得乱。咱们量了才知道。

## 宽度写在名字里:AX 切得出半截,SP 切不出

上一章点过名的家当,这一章咱们逐件量尺码,头一件量 AX。CS:APP 书页 169 给过书面定义,原话是“the low-order 2 bytes of the first four registers can be independently read or written by the byte operation instructions”。这句规格是站在 32 位一代说的:它说的头四个通用寄存器,是 EAX、ECX、EDX、EBX,低两字节可以独立读、独立写,切出来的这一截,就是 16 位的 AX。AX 低处再切一刀,最低那个字节叫 AL,第 8 到 15 位那半个叫 AH。也就是说,AX 横躺着,左手 AH,右手 AL。

切这门手艺不是家家都有。SI、DI、BP、SP 没有独立的字节户口,切不出半截来,段寄存器则是整条 16 位,进出都是一整条。所以 16 位的世界里,能按字节单独使唤的,咱们扳着指头数,拢共 AH、AL、BH、BL、CH、CL、DH、DL 这八格。

再往上还有辈分。书页 270 收过口,x86-64 支持四种数据宽度,8、16、32、64 位。AL、AX、EAX、RAX,同一份家当三次加宽。咱们这一章泡在 16 位里,32 位、64 位偶尔进来打个照面,进来的都带着自己的年代标签。

mov 这边,尺码写在名字上。操作数分作三型,立即数、寄存器、内存,书页 169 末尾分好,书页 170 接着给寄存器型立细则,按宽度报名:写 `%eax` 报双字,写 `%ax` 报单字,写 `%al` 报字节。落到指令上,书页 171 的 Figure 3.4 是定义式的表,前置卷 objdump 屏上您敲过的那几个 mov 名字,定义全打这儿来:movb 搬一字节,movw 搬两字节,movl 搬四字节,后缀就是尺码标签。

窄往宽搬,另有一类专门的桥:movz。它把窄寄存器的值装进宽寄存器,空出来的高位拿零填满。为什么非得有这座桥?您想想 AL 和 EAX 的关系:AL 只有八位,要进 32 位的格子,上面 24 位填什么,总得有人给个说法,movz 的说法是补零。

多字节值怎么躺,也是规格的一部分。两字节搬进内存,谁躺低地址、谁躺高地址?x86 的答案叫小端:低字节躺低地址。`34 12` 那对字节,您在前置卷的 objdump 屏上见过,数在内存里倒着躺。这一层给它定个身份:它不是谁的习惯,它是指令集写明的规格,跟 movb 搬一字节一样,白纸黑字。

**您猜一猜再往下翻**:C++ 里没有 AH 这个名字,想看一个 16 位数的高半,源码该怎么落笔?写出来的这行,编成机器码又是哪条指令?这个猜想咱们揣着,走到实况里对答案。

## 宽度还能被拨:0x66 与栈的尺寸

名字把尺码写死,前缀还能再拨。上一章见过 0x66,咱们管它叫拨宽度的那一下,这回把它看全:它是操作数前缀,不改指令做什么,只改这趟搬运按哪套宽度的口径走。16 位模式里,call 原生按两字节压返回地址,0x66 打头,同一颗 e8(call 的操作码,前置卷里您见过它打头),压的就是四字节。

为什么好好的两字节不使,要拨成四?因为编 C++ 的编译器肚子里装着 32 位的世界,它编出的指令凡按四字节口径算的,头上都戴着 0x66,按 16 位口径就够用的,不戴。`.code16gcc` 是让编译器给 16 位模式生代码用的记号,它生成的代码就长这样,咱们实况里两种都有,一会儿见。手写的桩呢,想按哪个口径,笔在自己手里。

于是 push 的栈槽有了三代:16 位原生口径压两格,`.code16gcc` 拨过的压四格,64 位机器原生压八格。前置卷里您在 64 位用户态拿 gdb 量过那个 8,咱们借来当已知数。三代宽度,这一章咱们守着中间那代。

栈本身呢?它不是新添的硬件,是内存加一套大家都肯守的纪律。SS:SP 两格指着栈顶,push 按书页 171 的两步式定义走,书里写的是 IA32 的 32 位口径:`R[%esp]←R[%esp]−4; M[R[%esp]]←S`。翻成人话:栈指针往下挪四格,再把值写进新的栈顶。方向书页 172 也交代了:栈往低处长。咱们 16 位实况里,减号后面这个 4 是 0x66 拨出来的,口径拨回两格,挪的就是两格。

call 与 ret 是一对,咱们把它俩搁在一起看。call 把返回地址压下去,ret 照着栈顶弹回来走,一压一弹,两边认的宽度得是同一套。岔了,SP 挪出去的跟挪回来的就对不上,栈顶从此指着说不清的地方。

**停一停,您拿笔画一画**:一个函数里,call 是四字节口径,搭档的 ret 却按两字节弹,一进一出,SP 还回得到原点吗?栈顶下一回指着哪儿?

## Code: Cinux 实况:每一回搬运的宽度与落点

真码这回还是 r01_mbr,行号照旧按这一版的 `boot/mbr.cpp` 数。手边没有它,`git show r01_mbr:boot/mbr.cpp` 随时调出来。要在编辑器里连着上下文翻,就 `git switch --detach r01_mbr`,看完再 `git switch -` 切回来。上一章把桩走到了 call 门口,这一章从 SP 有值那儿接手,咱们眼睛只认一件事:每一回搬运,宽度写在哪儿,落在哪格。

咱们从 `mbr.cpp:31` 看起,`movw $0x7c00, %sp`,编出来三个字节 `bc 00 7c`。搬的是两字节,立即数 0x7c00 在指令自己肚子里躺成 `00 7c`——小端不光管内存里的值,连指令编码里的立即数也照此办理。

`:32`,`movb %dl, g_boot_drive`:DL 里那个盘号,一个字节,落进链接器排在 0x7d4c 的格子。搬运本身一字节。它自己编出来占几格?这事儿咱们押到章末,练一练里您猜完再对。

`:34`,章首那个问题在这儿见分晓。call 编出来六个字节 `66 e8 03 00 00 00`,落在 0x7c15。咱们断在这儿单步,实测读数是:断住时 SP 是 0x7c00,一脚跨进 MbrMain,SP 掉到 0x7bfc——一声 call,SP 当场掉四格!再看栈顶,`x/wx $sp` 读出 0x00007c1b,call 身后下一条指令的地址,四字节返回地址躺得整整齐齐。

手写的桩,这颗 call 头上也有 0x66。为什么?因为它请的客人 MbrMain 是 C++ 编的,客人一进门头一条 push 就按四字节口径压栈,call 把返回地址也压成四格,跟客人用同一套尺寸,跟机器的出身反而没关系。咱们把这 512 字节翻遍:五颗 call,颗颗带 0x66,手写的、编出来的全认四字节口径。除了 call MbrMain,另外四颗调的都是 PutString,管往调试口打字符串的那个函数。它们收尾的 retd 弹四字节,d 报的就是四字节口径,跟 movb、movl 报尺码一个逻辑,一进一出正好对上。call MbrMain 那颗没有这一半,MbrMain 在源码里带着 `[[noreturn]]` 的声明,永不返回,可它照样按四格压,编出来的世界从头到尾认一个口径。真按两字节压的 call 也存在,不带前缀就是了,咱们这儿一颗也没遇到。

跨进门就是 MbrMain 的序言,0x7c1e 起。`66 55` push ebp,SP 掉到 0x7bf8。`66 89 e5` mov ebp,esp,帧指针立起来了,把这刻的 SP 抄进 ebp,往后栈顶怎么挪,函数都拿 ebp 当不动地基,参数和局部变量全按它算偏移。书页 219 讲的栈帧,函数在栈上占下的整片地方,靠的就是这套帧指针的纪律。`66 56` push esi,SP 掉到 0x7bf4。跟着一条 `66 be 3c 7d 00 00` mov esi,0x7d3c,g_dap 的地址提前揣进 SI,回头 int 0x13 使唤。`66 53` push ebx,再掉四格。`66 0f b6 1e 4c 7d` 是 movzx,前头讲的 movz 落到真指令上,名字就带了个 x。它把 0x7d4c 那一字节装进 ebx,高位补零,咱们刚讲过的那座桥,实况里它就在这儿。`66 83 ec 0c` sub esp,0xc,把 esp 再往下拨十二格空当——MbrMain 的家什全在寄存器里,这十二格不是给局部变量的,用处待会儿见。进门这一串,习惯上叫序言。64 位那一代,函数进门干的也是这几下,栈槽宽到八格,前置卷里您跟它照过面。咱们眼前这 16 位的一版,压的是四格。严格数,压旧帧指针、立新的、存 esi 和 ebx 这几条才是正身,备参数的 mov 和 movzx,是编译器顺手插进来的活。条条带 0x66,栈槽从头到尾四格。

`:61`,C++ 里一句 `unsigned short reg_ax = 0x4200`,编出来 `66 b8 00 42 00 00`。咱们看立即数:0x4200 就躺在那儿,躺成 `00 42`。到了 AX 里,高半 AH 是 0x42,低半 AL 是 0,BIOS 的扩展读就认这个摆法,AH 装功能号 0x42,AL 装子功能号。一个 16 位的数,两个字节的去处,在名字里就分好了。

`:62` 与 `:66`,kDrive 从 0x7d4c 取回(movzx 干的),经 `66 89 da` mov edx,ebx 递进 DL,SI 里的 g_dap 地址也早备好了。然后 `cd 13`,int 0x13,控制权交给 BIOS。这一拍的来龙去脉记在上一章,咱们这边收下的是新东西:寄存器怎么排座位,C++ 里写成约束,落到机器上就是一格一格的搬运。

`:67-68`,`(reg_ax >> 8) != 0`,编出来是 `c1 e8 08` shr ax,0x8,加一条 je。轮到对答案了:C++ 里没有 AH 这个名字,reg_ax 在源码里就是一个 16 位的整体,想看高半,语言层的写法只能是移位,右挪八位,高半掉进低半。这一编法里,读高半惊动的就是整个 AX。更划算的是,这记移位顺手把标志位也立好了,结果为零,ZF 就置 1,后面的 je 白捡一记比较。您留意,shift 在这儿不带 0x66:它按 16 位口径干活,16 位模式里这口径是原生的,不用拨。

`:44-45`,报错的路上还有更细的一刀,咱们看它怎么把一个状态字节印成两个十六进制位。`66 c1 e8 04` shr eax,0x4 挪出高半位,`66 83 e0 0f` and eax,0xf 取出低半位,拿结果去查 0x7cf8 的“0123456789ABCDEF”表,查到的字符装进 AL,`e6 e9` 一声,从 0xE9 端口送出去。查表的 `67 8a 80 …` 打头的 67,是 0x66 的表亲:66 拨数据宽度,67 拨地址口径,这里它把寻址拨成 32 位。一个字节切成两位,一位一位印。

再看一处配对。0x7cc1 的 PutString,咱们请它出来走两步:`67 66 8b 55 08` mov edx,[ebp+0x8],按帧指针加八读栈上的参数,书页 221 说的参数落点就是它。参数躺在离 ebp 固定偏移的地方,这是帧指针立的纪律,槽宽几格它都守,四字节槽定的只是那个数,加八,不是加四。`67 8a 02` 一字节取字符,`66 42` inc edx,循环到字符为零。收尾 `66 5d` pop ebp、`66 c3` retd,前缀 0x66 照带,弹四字节。call 压四格进,retd 弹四格出,SP 回到进门时的旧值,两头对上了。上文“拿笔画一画”那道题,机器在这儿给的是正解的样子。还有个小尾巴,压参数的四格谁清?PutString 的 retd 只管弹返回地址,参数是调用方自己收的,0x7c37 把字符串地址压进去,call 回来,0x7c4e 一条 add esp,0x10,十六格一口气收回,进门拨的十二格空当,加参数四格。后面几颗进 PutString 的 call,进出的路子大都是这一套。兜底的那颗换了手法:它住在 returned_from_stage2 里,兜的是 stage2 万一返回的意外,参数不 push,拿一条 mov 直接写进现成的格子,call 回来照样一条 add 收十六格。

收尾看 g_dap。`:6-13` 那个结构体,链接后躺在 0x7d3c。断在 0x7c15 时咱们 dump 十六个字节,读数摆开是:`10 00 04 00 00 7e 00 00 01 00 00 00 00 00 00 00`。照着字段切:size 一字节 0x10,正好十六,reserved 一字节零,count 两字节 `04 00` 读回 4,四个扇区,offset 两字节 `00 7e` 读回 0x7e00,stage2 的落点,segment 两字节零,lba 八字节,`01` 起头。0x7e00 在内存里躺成 `00 7e`,低字节在低地址——小端在这十六个字节里演了个全套。BIOS 拿着 SI 里的地址,按同一套规格把每个字段捡回去,一格都不会捡错。

`:73` 的 ljmp 把机器交给 stage2,上一章看着它走的,这儿不重走。从 SP 有值到交棒,咱们一路数下来的是尺码。盘号,一字节。返回地址,四字节。0x4200 一次装进 AX。g_dap 里的 0x7e00,躺成 `00 7e`。每回搬运的宽度与落点,咱们都亲眼看着它落了地。

## 对照:同一件事,别的机器怎么做

xv6 那头,自家书页 25 与 28 记着开场:_entry 进门头一件事是立栈,sp 装上 stack0+4096,书里明说 RISC-V 的栈也往下长,立完才 call 进 C 的 start()。咱们 x86 这边,桩里 `:30` 到 `:31` 干的是同一件事:设好 SS,写好 SP,然后才 call 进 MbrMain。两家指令集长得毫不相干,立好栈才进 C 这一步,两边各自走到了一起。C 的函数一进门就要压序言,栈不在,序言压给谁。

再往代际看。书页 270 说过,x86-64 把家当一路加宽,AL、AX、EAX、RAX 是同一份东西的四个辈分。push 的栈槽跟着年代换尺寸,三代各压几格,咱们前头刚数过。守着 16 位这一代,咱们过得挺踏实。

Linux 内核那块还欠着。栈怎么立、对齐怎么讲究,这些得咱们逐字核过文献才敢写,眼下这块空着,核完再补。

C++ 标准里也住着同款的两个世界,整型宽度是语言层的规格,unsigned char 承诺一个字节,操作数宽度是机器层的规格,ISA 说了算。两层各自承诺,对不对得上,得有人把关。同一版代码里 `boot/layout.hpp` 顶上那句 `static_assert(sizeof(unsigned short) == 2)` 干的就是这个活:两层要是岔了,编译期就报出来,咱们不用等机器跑起来再奇怪。

您想核原文:xv6 书第 2 章开头几页,是 _entry 立栈的全文。CS:APP 第 3 章 §3.4 从书页 168 起,是操作数与 mov 的定义地段,§3.7 讲过程与栈帧,§3.13.2 交代 64 位的四种宽度。

## 这一章留下了什么

数一数到手的东西。立即数里躺着的 `00 42`,一声 call 掉进 0x7bfc 的四个字节,g_dap 里躺成 `00 7e` 的 0x7e00,这几样现在都眼熟了。名字那头,AX 切得出 AH、AL,SP 没学这门手艺,mov 拿后缀报尺码,movz 给窄往宽搭桥。栈呢,是内存加纪律,SS:SP 指着,往低处长,call 压几格、ret 就得弹几格,0x66 把口径拨过一代,栈槽就跟着换尺寸。下一章咱们往机器最开头的那个瞬间走:上电那一刻,这批家当是谁给的、按什么顺序给的。

| 术语 | 一句话口径 |
|---|---|
| 字节寄存器 | 头四个通用寄存器低两字节切出的 8 位格子,AH、AL 一类,SI、DI、BP、SP 切不出 |
| 操作数宽度 | 一趟搬运按几字节算:写在指令名字里,或由前缀拨 |
| 小端 | 多字节值的躺法:低字节躺低地址,ISA 规格的一部分 |
| 栈(SS:SP) | 内存加一套纪律:SS:SP 指着栈顶,往低处长,push 挪 SP 再写入 |
| 操作数前缀 | 0x66:不改指令做什么,改这趟搬运的宽度口径 |
| 序言 | 函数进门那几条:压旧帧指针、立新的、存要保的寄存器,有栈上局部变量的再腾地,帧指针是它立的 ebp |

continue 敲下去之后,终端里会涌进 SeaBIOS 和 iPXE 自家的几行吆喝,Press Ctrl-B、Booting from Hard Disk 之类,那是固件出场的动静,不是咱们的字节,别被带跑。跑完 GDB 自己退,QEMU 裹在 timeout 里,到点自己收走,不想等就把后台任务收掉。最后 `git switch -` 切回您来的地方,新克隆的仓回的是 main。

**题三,对着屏幕读。** 把题一的 gdb 命令里 continue 的后面添上 `-ex 'x/16xb 0x7d3c'`,g_dap 的十六个字节就躺在屏上。您对着字节把字段捡一遍:count 是几?offset 躺成什么样?0x7e00 为什么长那个样?

### 参考答案

题一:断住时 SP 是 0x7c00,si 一脚,PC 落进 0x7c1e,SP 掉到 0x7bfc,整整四格,`x/wx $sp` 读出 0x00007c1b,四字节的返回地址。实测那回屏上滚过不少,要紧的几行给您留在下面:

```text
Breakpoint 1, 0x00007c15 in ?? ()
sp             0x7c00              0x7c00
0x00007c1e in ?? ()
sp             0x7bfc              0x7bfc
0x7bfc:	0x00007c1b
```

题二:`88 16 4c 7d`,四格,您猜中了吗?搬运一字节,可 16 位的直接地址吃掉三格,88 是操作码,`16 4c 7d` 是目的地 0x7d4c 的写法。指令自己的长度,跟它搬运的宽度,是两码事。

题三:十六个字节是 `10 00 04 00 00 7e 00 00 01 00 00 00 00 00 00 00`。咱们照着字段读:size 0x10,reserved 0,count 读回 4,offset 读回 0x7e00,segment 0,lba 从 1 起头。0x7e00 长那个样,是因为 x86 的多字节值低字节躺低地址,内存里没有 0x7e00 这个数,只有字节,数是咱们按规格读出来的。
