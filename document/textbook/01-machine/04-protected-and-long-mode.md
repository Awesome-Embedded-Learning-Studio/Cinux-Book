# 04 · 保护模式与长模式:户口的就地迁移

咱们上一章收尾时,把一桩事留在了那儿:实模式这 1MB、16 位口径的世界怎么走出去。这一章咱们办它两回。头一回推开 32 位的门,咱们刚站稳,第二回又立在 64 位的门口。两个门把手的住处您已经见过:一个在 CR0 的最低位,1.3《上电》的全家福里 cr0 是 0x10,咱们当时看见只有 ET 一位立着,门还关得严严实实的。另一个在 CR0 的最高位,咱们还得等这一章走到一半才轮到它出场。

量法回到头两章的老路数:规格有处可查,真码咱们自己冻住机器抄。规格的那一头,《计算机怎么工作》里的《保护模式与长模式预览》整篇都替咱们备好了。选择子右移三位、乘八、查表的那套换算,您在那边亲手走过,描述符的八个字节怎么摆、A 位什么时候被写回,那边也各有整屏的证据。咱们这一层不陪它重学,只盯一件那边没法替咱们盯的事:换世界换到一半的那一瞬,机器长什么样。

## 门推开的那一瞬,机器换掉的到底是什么

> **门推开的那一瞬,机器换掉的到底是什么?**
>
> 您听着像搬家:新机器、新内存、新寄存器。咱们把机器两次冻在换到一半的那一拍,读数会告诉您相反的事——寄存器还是那一批,内存还是原来的那一片,连地址都还是那些数。真正被换掉的,是每一格地址按什么规则解释。这一章就把这套就地换户口的全过程,一拍一拍走给您看。

户口就地迁移,这话咱们把它落准。实模式里的地址,咱们拿 CS 的值乘十六加偏移折出来。咱们进了保护模式,同一只 CS 里装的数换了身份:它变成一个编号,咱们再拿它去 GDT 里查表,查出基址再算——查表的路子您在前置卷玩熟了,这儿只借现成的换法。要紧的是再退一步看:两次算地址,用的都是同一只寄存器、同一片内存。房子其实没换,换的是登记簿上的算法,人还住在原地。

那 CS 里记的旧东西什么时候清?这里藏着本章最要紧的一个机构,咱们把它看清楚:段寄存器分两半,可见的半截装选择子,隐藏的半截缓存着一份描述符,算地址用的是缓存里的一份。往 CS 里装新值的那一刻,CPU 才会替咱们去查表、把新描述符换进缓存,别的时候,其实谁也不碰它。于是模式开关那一拍就尴尬了:CR0 一写,新规则就全本生效了,可 CS 里缓存的内容还是实模式留下的旧条目,取指还是照它算的。您翻遍全书,由咱们在指令里指定新段值、一步写齐 CS 与 PC 的只此一种:远跳。换 CS 的还有中断,可换上去的是向量表里排好的值,不由咱们指定,咱们不在这儿展开。1.1《一条指令的一生》里咱们看它,它是 PC 的第二种走法。这一章咱们再看它,它就是刷新 CS 缓存的手。咱们两次换世界都得靠它收尾。

前置卷在教学的裸扇区上拍过这两拍:一拍置位,门开了,CS 里装的还是旧缓存,咱们再走一拍远跳,缓存才换成新的。这一章咱们在真码里把这两拍再拍一遍,头一遍拍完了,后面还有一模一样的第二遍。

## 32 位只是中转,64 位才是目的地

咱们头一回换世界,换掉的是段的那套旧算法。可咱们不在 32 位世界安家,boot 的目标从来是 64 位:第二次换世界,连算地址的路都要换成页表。这一换的气派比头一换大,咱们得自带三样东西。

咱们带的头一样是桥。咱们一开分页,机器眼里的地址就得过一道页表翻译,桥没铺的话,门后等着咱们的就是断头路。咱们铺三张表,打头的一张是页表根 PML4,跟着的一张是 PDPT,再跟着的一张是 PD,把 0 到 8MB 恒等映射:虚拟地址是几号,翻译完落到的物理地址还是几号,桥面是平的,过桥的人察觉不出脚下换了路。为什么只铺 8MB?boot 这一小段代码用多大铺多大,真正的页表体系是第 3 部内存那边的正戏,咱们这儿不铺高速公路。

咱们带的第二样是门闩。长模式的使能位不住 CR0、CR4 这些老地方,它住在一柜子按编号寻址的抽屉里,这些抽屉的学名是型号特定寄存器,咱们平时叫它 MSR。装门闩的抽屉编号 0xC0000080,咱们叫它 EFER,伺候它的是 rdmsr 与 wrmsr 一对指令。咱们代码里的使能常量 kEferLme 是 0x100。这个数咱们有段旧事:抽屉里还住着一位邻居 kEferSvme,它的值是 0x1000,跟咱们的活八竿子打不着,门牌偏偏跟咱们只差一个零。笔者当年头一回做这段引导,就是在这儿拨错了邻居:PG 一开,机器连遗言都没给咱们留,直接就复位了,咱们碰上的是一场三重故障。那一晚笔者在正文里从头记到尾,咱们这儿只留这道疤。

第三样是推门的手劲。咱们把 CR0.PG 那一拍拨下去,门后必须已经是铺好的路:页表根指错、表没对齐,机器当场就复位了,一个字都不给您留。前置卷把跑不起来的三个症状摆齐过,咱们不重叙,只要认下这一拍的脾气:它不容错,错了没有第二次机会。

咱们两次换世界的路数是相同的,添的家当却不同:备好表,拨好该拨的位,末了拿远跳收这一遍的尾,头一遍咱们只拨 PE 一个位,第二遍咱们五步拨开三处,PAE、LME、PG 的住处分别是 CR4、EFER、CR0。PAE 管的是页表格式的开关,不拨开的话,长模式要用的表不作数,门闩 LME 还得专门住进 MSR 的抽屉。咱们这就进真码,每遍替您挑四个停点,咱们一共四次冻住机器,每停都停在一条要紧指令落定的那一拍上。

## Code: Cinux 实况:第一场,PE 一拍

咱们的真码分两场。头一场的实况锚是 r04_protected_mode,主角有两个:咱们让 `boot/pm/pm_switch.cpp` 管换世界,`boot/pm/pm.cpp` 管落地后的安顿,下文引的行号各数各的。您要亲手翻,咱们拿 `git switch --detach r04_protected_mode` 切过去,看完咱们再拿 `git switch -` 切回来。第二场咱们换到 r05_long_mode,主角换成了 `boot/lm/lm_switch.cpp`,切法也是同款的。克隆在手的读者,切回来落回的还是 main。

咱们把断点下在 EnterProtectedMode 门口的 0x84d9,机器一停咱们就抄家底。CR0 咱们抄下来是 0x10,门是关着的,正是 1.3 全家福里 cr0 的后续:从 0x7c00 一路走到这儿,咱们谁也没动过它,所以它始终是 0x10。咱们读出的 CS 是 0,缓存里揣着的是 00009b00,实模式的 16 位代码段。咱们还没走 lgdt,GDT 的读数也就是 00000000 00000000 的一张空表。EFLAGS 咱们抄下来是 0x46,IF 躺在 0 上——stage2 进门的桩早把中断关过一回,不欠这一拍的债。串口那边咱们也看过了,stage2 前情的那几行都打过了:开地址线、探内存地图、挑显卡模式那几趟,咱们听到的末一句是 `[stage2] leaving real mode`,告别的话说在前头。

咱们接下来看的六行,是 `pm_switch.cpp:5` 到 `:10` 的四步:cli 关中断,咱们用 lgdt 把 kGdtr 递给 CPU,mov 加 orb 只把 CR0 的最低位置一再写回,末了 `ljmp $0x08, $PmEntry`。为什么 cli 必须打头阵、为什么碰控制寄存器只敢动一位,正文里笔者写得很细,咱们只拍动作。lgdt 这一句您留意一下:它是全章唯一一句 lgdt,第二场咱们要拿它对答案。

**咱们停一停,您猜一猜**:cr0 写回之后、远跳还没走,这一刻 CS 的可见半截装的是什么?隐藏的半截里,揣的又是哪个世界的描述符?

咱们把断点挪到 0x84e7。mov 写回 cr0 刚落地、ljmp 还没执行,咱们把读数摆开:

```text
CS =0000 00000000 0000ffff 00009b00 DPL=0 CS16 [-RA]
GDT=     00008fc4 00000017
CR0=00000011 CR2=00000000 CR3=00000000 CR4=00000000
```

咱们读到的 CR0 是 0x11,PE 立起来了,机器已经在保护模式里给咱们办差。可咱们读出的 CS 还是 0,缓存里躺着的还是 00009b00,实模式留下的 16 位描述符,咱们看它原封没动——新规则全本生效,登记的本子还没换。您猜的答案就在这儿:选择子是原封不动的,缓存也是原封不动的,变的只有 CR0 一格。前置卷的两拍论,咱们在真码里一字不差地对上了。

远跳一落地,咱们把断点挪进 PmEntry 的 0x8e4a。CS 变成了 0008,缓存换成了 00cf9a00、基址 0、限长 ffffffff,描出来的是整整齐齐的 32 位代码段。这一跳干了两件事:1.1 看过的那件,把 PC 写到新地址。这件新的,咱们看它把 0x08 装进 CS,CPU 顺手替咱们查表,GDT 第 1 项的八个字节进了隐藏半截。其余的五个段寄存器还是 0,换净的活,咱们留到下面再办。

咱们读 `pm.cpp:6` 到 `:12`:mov 把 0x10 装进 AX,五条 mov 分头送进的是 DS、ES、FS、GS、SS,咱们再给 ESP 装上 0x90000。咱们断在 `:12` 之后读一遍:DS、ES、SS 全是 0x10,ESP 装上了 0x90000,串口紧跟着给咱们打出 `[pm] 32-bit world alive`。到这儿 32 位世界的户口迁完,咱们再回头看一眼表本身:

```text
kGdtr  @0x8fbc: 17 00 c4 8f 00 00            (limit 0x17 = 3*8-1)
kBootGdt@0x8fc4: 00000000 00000000           null
                  00cf9a000000ffff           code32
                  00cf93000000ffff           data32
```

咱们看 kGdtr 的六个字节,limit 0x17 的来历是三项乘八减一,咱们数出来表里正好三项:空项、32 位代码、32 位数据。可有个数对不上:源码 gdt.hpp 里数据项的权限字节写的是 0x92,咱们屏上读到的是 0x93。差的正是 A 位——五段装载那一拍,CPU 把它写回了内存。代码项在咱们眼前还是一动没动的 0x9a。这桩案子咱们在前置卷里早见过,还专门把话收窄过:写回的,必是装载过的。反方向咱们就不保证了,装载了未必写回,代码项就是眼前的反例。这个方向您揣着,第二场咱们还会遇上它的表亲。

## Code: Cinux 实况:第二场,PG 一拍

第二场的实况锚是 r05_long_mode。咱们这一版从干净克隆构建会栽跟头:构建系统找 boot/lm.bin,产出的却叫 lm_blob.bin,所以名字对不上,镜像也就出不来了,咱们要等到下一版 r06_jump_into_kernel 才见它修好。咱们的读数,是把 build/boot/lm_blob.bin 复制成 build/boot/lm.bin 之后构建出来再抄的,咱们在这儿交代清楚。您跟读到这儿不用动手,这一场咱们当观察场看。

断点咱们下在 EnterLongMode 门口的 0x8e7f。咱们把家底抄开:CR0 是 0x11,32 位世界还在给咱们办差,CR3、CR4、EFER 咱们读出来全是 0,新东西咱们一样没动。咱们读出的 CS 是 0008,数据段是清一色的 0010,缓存揣的是 00cf9300,全是上一场换净的家当。咱们读到的 ESP 是 0x8fffc,比第一场立下的 0x90000 低四格,call 压下去的返回地址正躺在栈顶,1.2《字节寄存器与栈》里咱们量过它。可 GDT 那行读数有话要跟咱们说:

```text
GDT=     000090e0 00000027
```

表怎么已经是五项的了?limit 0x27,还是五项乘八减一的老换算。lgdt 没有第二句——您回头翻遍 r05 的源码也找不到:这一场的引导把实模式的来路重走了一遍,执行的还是 pm_switch 里那句 lgdt,咱们认得它,只是它手里的 kBootGdt 已经是五项的版本。源码里 gdt.hpp 长了两个描述符,L=1 的 64 位代码段、配套的 data64,kGdtr 的 limit 是 `sizeof(kBootGdt) - 1` 算出来的,表长它自己就跟着长了。表从三项到五项的变化,是源码长的,指令咱们一条没添。

咱们把 `lm_switch.cpp:7` 到 `:19` 数下来,一共是五步的活。头一步的 mov 把页表根 0x1000 装进 CR3。咱们给 PAE 置一,走的是读改写 CR4 的路子。ECX 装的是抽屉号 0xC0000080,咱们连着走 rdmsr、置 0x100、wrmsr,门闩也就拨上了。咱们再读改写 CR0,把最高位的 PG 置一。末了 `ljmp $0x18, $0x9300`。这一串咱们不一口气讲完,半道上有两处值得咱们停下来看。

wrmsr 落地,咱们断在 0x8e9e:CR3 是 0x1000,CR4 换上了 0x20,EFER 里躺着的是 0x100,kEferLme 立起来了,门闩也就到位了。咱们往下只差两步。

**咱们停一停,您再猜一回**:EFER 眼下是 0x100。咱们等下一拍 PG 立起来,它的读数会变成 0x500。多出来的 0x400,是咱们代码里哪一拍写上去的?

咱们断在 0x8ea9,PG 落地、ljmp 未走:

```text
CS =0008 00000000 ffffffff 00cf9a00 DPL=0 CS32 [-R-]
CR0=80000011 CR2=00000000 CR3=0000000000001000 CR4=00000020
EFER=0000000000000500
```

咱们的答案:哪一拍都不是。lm_switch 咱们从头到尾数出来十三句,写它的句子一句也没有,它是硬件在 PG 立起那一拍自己点亮的。GDB 给咱们报 `efer 0x500 [ LMA LME ]`,名字是它自家标签表里的,咱们只认两个实测数和源码里的 kEferLme,手册的背书咱们不替它做。CS 一行同样有话跟咱们讲:还是 0008,缓存还是 32 位世界换上的内容。跟第一场 0x84e7 那一瞬同一副长相:机器已经进了新世界办差,CS 揣着的还是上一个世界的描述符。头一回咱们看,旧描述符是 16 位的。这一回咱们看,旧的是 32 位的。

页表也值得咱们在 0x8ea9 这一停对一遍:内存读出来 PML4[0] 是 0x2003、PDPT[0] 是 0x3003、PD 四项是 0x83、0x200083、0x400083、0x600083,跟源码里 MakeTableEntry、MakeLargePageEntry 写进去的一字不差,咱们铺的就是 0 到 8MB 的恒等映射。等远跳落地、断进 0x9300,咱们再读一遍,读到的是 0x2023、0x3023、0x00a3。每项都多了 0x20,PD 后面三项咱们看还是老样子。多出来的正是 A 位:取指一穿表,CPU 就往它走过的表项上落一笔标记,跟 GDT 数据项 0x92 变 0x93 是咱们见过的同一种动作。咱们在 0x8ea9 那一停还没走过表,读数自然还是源码里写好的值。PD[1] 往后盖的是 2MB 开外的地界,您看机器从头到尾没踏进去,所以标记也就没落上去。CPU 落标记只落在真正用过的格子上。

远跳落地,咱们断在 0x9300,64 位世界的门口。咱们读到的 CS 是 0018,缓存里揣的是 00af9a00,查的正是表里 L=1 的一项。RIP 咱们读出是 0x9300,RSP 还是老的 0x8fffc,数据段也还是 0010 的老样子。咱们看表里第五项 data64 此刻还是 0x008f92,五段装载的活儿还没轮到,所以 A 位自然还没写回,这脾气您在第一场领教过了。往后 68 个字节是一小段自己过的日子:开头的 mov 把 0x20 装进 AX,咱们把五段换净,mov 再把 ESP 拨回了 0x90000,栈又回到第一场立下的原点。打印循环替咱们把 24 个字节从 0xe9 端口送出去,末了的 hlt 收尾。这段剥成裸字节的 blob 为什么自己一条链、不跟大部队链接,是正文里的另一道题,咱们路过不停。

咱们把串口收官的三行字摆在屏上:

```text
[stage2] leaving real mode
[pm] 32-bit world alive
[lm] 64-bit world alive
```

咱们读出的是一行一个世界。第三行是 64 位世界跟咱们打的第一声招呼。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,压根没有这两扇门的影子。书页 25 与 28 记的开场您在 1.1 见过:固件交棒那一刻,机器已经待在 64 位里了,加载器把内核放进 0x80000000 就直接跳了进去。x86 是背着几十年兼容债过来的:复位从 16 位开场,咱们看它一路自己往上爬。换世界的这两扇门,是 x86 自己的家史,咱们核过的对照里,xv6 那颗 RISC-V 一出生就在对岸了。

咱们也把不做的摆明白。第二次换世界必须自带的分页,咱们只铺三张表,做的是 0 到 8MB 的恒等映射,桥面够 boot 这一小段走的。往后的四级翻译、缺页、TLB 那一整套,是第 3 部的正戏,咱们在这儿不提前铺。

C++ 在这一章留了成对的一句话。咱们在 gdt.hpp 里用 constexpr 工厂造描述符,static_assert 替咱们把八个字节在编译期管死,权限字节错一位就编不过。咱们到 gdt.cpp 里,看到的表本身还带着 const。可咱们一跑起来,CPU 照样往咱们这页内存上写,0x92 变成了 0x93,就是它干的。const 管得住咱们的笔,管不住 CPU 的笔。页表那头同款同病:page_entry.hpp 里 `static_assert(MakeTableEntry(0x2000, kWritable).raw == 0x2003)` 管的是咱们写进去的值,运行期 CPU 照样往值上添了 0x20,屏上的 0x2023 就是证词。

您要核原文,去处咱们攒了三处。《计算机怎么工作》的《保护模式与长模式预览》,本章规格那一头的家:查表换算、两拍论、A 位、长模式里基址不算数,那边都有整屏的证据。xv6 书第 2 章的开头,还是 1.1 立过的口径。换世界这件事的来龙去脉,cli 为什么打头,EFER 邻居位的那一晚,三张表怎么填,68 字节为什么自己一条链,在正文里咱们各给了一个专节。Linux 内核怎么进的 64 位,咱们手头没有核过的文献,所以继续空着,核完了再补。

## 这一章留下了什么

攥在手里的都是实物。咱们亲手写的,只有源码里那几句:kBootGdt 长了两个描述符,kGdtr 里 limit 就跟着从 0x17 长到了 0x27。咱们两次远跳,0x8e4a 与 0x9300 各收了一回尾,收的都是同一个毛病:CS 里没换的旧缓存。EFER 咱们只拨到 0x100,后面读数里的 0x500,是硬件自己添的。A 位其实也一样,咱们一笔都没写,GDT 数据项与页表头三项上的笔迹,全是 CPU 走到哪儿就落到哪儿的。咱们读出的三行字一行一个世界,栈转了一圈回到 0x90000,户口迁了两回,人和房子都是没挪窝的。

您单看第三行字,连收尾的换行算上 24 个字节,是咱们从 0xe9 端口一个一个送出去的。门外的设备怎么接住它们,咱们留到下一章开讲。

| 术语 | 一句话口径 |
|---|---|
| 保护模式 | CR0.PE 立起后的 32 位世界:选择子查 GDT 算地址,段寄存器揣着缓存描述符 |
| 长模式 | EFER 使能位加 CR0.PG 一起推开的 64 位世界:算地址改走页表,段基址退出计算 |
| 描述符 | GDT 里八字节一项的记录:基址、限长、权限,选择子按它折算地址 |
| 选择子 | 段寄存器可见半截里的编号:右移三位得索引,拿去 GDT 里查项 |
| 恒等映射 | 虚拟地址与物理地址同号的铺法:boot 过桥用,桥面是平的 |
| MSR | 型号特定寄存器,按编号寻址的一柜子抽屉,rdmsr 与 wrmsr 伺候,EFER 住在 0xC0000080 |

## 练一练

两场换世界您都看过了,轮到您上手。咱们头一道动手只锚第一场:第二场那一版构建带着病,您当观察场就好,这正是咱们的安排。

**题一:咱们动手。**咱们把 r04 那一场跑起来,两次冻住机器:一回冻在 PE 立起、远跳未走的那一瞬,另一回咱们冻在五段换净之后。下面这几条咱们今天刚在本地一条一条跑过,您接着走:

```bash

cmake -B build && cmake --build build --target boot_image

  -nographic -display none -no-reboot -S -gdb tcp:127.0.0.1:1244 &
```

咱们拿头两条把版本切过去、把镜像编出来。末一条咱们让 QEMU 蹲进后台,机器的头一条指令还没执行,您手里的 gdb 这就带着两个断点登场:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1244' \
    -ex 'break *0x84e7' \
    -ex 'break *0x8e5d' \
    -ex 'continue' \
    -ex 'info registers cr0 cs' \
    -ex 'x/3gx 0x8fc4' \
    -ex 'continue' \
    -ex 'info registers cs ds ss esp' \
    -ex 'x/3gx 0x8fc4' \

```

您把 continue 落下去,SeaBIOS 和 iPXE 那几位又要出来给咱们刷一气屏,Press Ctrl-B 之类的吆喝,您权当没看见,咱们的头一个断点在 0x84e7 等着。gdb 跑完了自己就退。QEMU 有咱们设的 timeout 看着,两分钟到点就散场了,您嫌久就亲手把后台任务收掉。版本咱们也送回去:git switch - 一敲,您从哪儿来回哪儿去,新克隆的仓落回 main。

**题二:咱们猜一猜。**咱们从 r04 看到 r05,同一张 GDT 从三项长到了五项。您猜:单看第二场那一次引导,从咱们的头一条指令到 64 位落地,lgdt 执行了几回?猜个数,回咱们本章的前文里对。

**题三:咱们对着屏幕读。**咱们本章前文里的页表读数出现过两回:0x8ea9 那一停,咱们读到的数是 0x2003、0x3003、0x83 起头。0x9300 落地后咱们再读,读到的就是 0x2023、0x3023、0x00a3。您对着两屏读:多出来的 0x20 是谁写上去的?PD 后面三项两屏一个样,为什么它们没份?

### 参考答案

题一:咱们跑出来的要紧几行长这样:

```text
Breakpoint 1, 0x00000000000084e7 in ?? ()
cr0            0x11                [ ET PE ]
cs             0x0                 0
0x8fc4:	0x0000000000000000	0x00cf9a000000ffff
0x8fd4:	0x00cf92000000ffff

Breakpoint 2, 0x0000000000008e5d in ?? ()
cs             0x8                 8
ds             0x10                16
ss             0x10                16
esp            0x90000             589824
0x8fc4:	0x0000000000000000	0x00cf9a000000ffff
0x8fd4:	0x00cf93000000ffff
```

头一停咱们看到:PE 已立,cs 咱们读出来还是 0,旧缓存那一瞬您亲眼看到了。第二停咱们接着读:cs 是 8,ds、ss 到了 0x10,esp 到了 0x90000。咱们再看表,数据项从 0x92 变成了 0x93。两停之间隔着的是远跳和五段装载,A 位就是在装载那一拍被 CPU 记上的。

题二咱们答:一回。lgdt 咱们全工程只在 pm_switch 里写过。r05 的引导重走实模式来路,执行的还是同一句,只是它手里的表已经是五项版,limit 咱们交给 `sizeof(kBootGdt) - 1` 自己算,表长它自己就跟着长了。指令咱们一条没添,咱们改长的只是源码。

题三咱们答:A 位,CPU 走表那一拍写回的。前一停咱们的 ljmp 未落,没被走过的表里,咱们读到的自然还是源码里写好的值。后一停止指已经穿表了,前三级的头一项各落了一笔。PD 后面三项盖的是 2MB 到 8MB 的地界,咱们没见机器踏进去过,所以标记自然落不上去。这脾气咱们在 GDT 里见过:data64 没装载,它就不写回了。
