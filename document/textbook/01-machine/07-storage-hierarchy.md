# 07 · 存储层次:图只有一层,塔分好几层

上一章末行念完,有一桩事挂在咱们手上:机器会疼、也会听了,家当却还摊在同一片内存上,内存这座宅子一层一层各有各的快慢,下一章进去认门。这一章就进去。进去头一件事,是把那句“同一片内存”认清:那是内核眼里的样子。内核拿到手的是一张平面图,固件递来的 e820 清单画的就是它,图上的内存平平整整,一段挨一段。可机器真身是一座塔:寄存器一层,缓存一层,内存一层,盘再一层,一层比一层慢,一层比一层大。本章干的事,就是把图和塔对起来:图上划的是塔里哪一层,其余几层又在哪儿,认完这门,您再看那行 free 的日志,读出来的就不是一串数了。

量法也得跟着塔分两截。上半截,寄存器到缓存,各层快多少,那是有数的,可几纳秒、哪一级、哪家型号,咱们书架上没有核过的本子,一个都引不得,这一截本章只报量级,层与层差出百倍上下,话到这儿为止。下半截,内存这一层,是自家的屏拍得到的:一份固件递来的清单,一行日志,再添一本从机器肚子里冻出来的位图,读数全是现抄的。出处口径还是前几章立下的三条:前置卷管机理,正文管手续,读数出自自家的屏,本章把它按塔分成两截,上半截讲常识,下半截点读数,口气不一样,您读的时候分得出来。

## 图是一层的,塔不是

> **内核拿到的内存图,跟真实的存储是不是一回事?**
>
> 不是一回事,差得还不少。图上那几行,划的只是塔里“内存”这一层的地界,塔还有别的楼层,图上一个字都没提。可这话说回来,内核往后也只住得进图里那层,图没画错,它本来就只管一层。这一章把塔立起来,再拿图去对,对完您就清楚,32350 页 free,数出来的是塔的哪一角。

## 塔的剖面:下一层,慢一截,大一圈

塔分四层,咱们从顶上一层一层数下去。头一层是寄存器,CPU 的贴身家当,1.2《字节寄存器与栈》量过尺码的那批:机器一拍之内就在它们身上花数,快到不计,格子却少得可怜,用字节当尺子就够量完。第二层是缓存。缓存 1.1《一条指令的一生》点过名:指令集不认它,程序看不见它,摊得着的只有快慢。它干的活,是把内存里的热字抄一份放在 CPU 手边,靠的是程序的一个脾气,行话叫局部性:刚用过的数,多半转眼还用,用了一格,挨着的几格也快轮到。有这个脾气撑着,热字放在手边,十回有八九回省得往下一层跑,缓存才立得住。

第三层是内存,塔的正厅:e820 清单划的就是它的地界,本章全部读数都落在它身上,尺寸按 MiB、GiB 算。最底下是盘,咱们内核的镜像就住在盘上,stage2 把它搬进内存的那两声 kernel image ok、kernel ferried,1.6《DMA 与中断》的日志里都在,容量按 GiB、TiB 算。四层数完,规律也就一句:每往下一层,慢差出百倍上下,大也差出百倍上下。这个倍数咱们不引书,可它也用不着本子:寄存器按字节算,盘按上千 GiB 算,两头搁在一起,量级自己会说话。

剖面画到这儿,有一件本章拍不成的事,得跟您交代:上半截没有屏。眼前这部机器跑在 QEMU 的 TCG 上,1.6《DMA 与中断》认过的翻译引擎,它不演缓存。TCG 把指令一块一块翻译着跑,替的是译码的结果,不是内存的副本,1.1 数家当的时候,翻译块和缓存就是分开点的两样。所以缓存这一层,模拟器里没有现场,快慢也量不出:程序看不见的东西,自家的屏一样看不见。上半截本章只讲规格常识,一个读数都没有,这句话搁在这儿,您回头翻屏的时候,就知道该翻哪儿,不该翻哪儿。

## 把平面图对回塔上

塔立好了,回头拿图来认。1.5《与设备打交道》里,咱们把七行清单从固件手里接过来,验签,量斤两,关心的是怎么问、怎么信。同一份清单,今天换一个问法:它划的是塔里哪一层的地界?七行里 type=1 的就两段。头一段 639KiB,趴在 1MiB 门槛底下,另一段从 1MiB 起,长 126.875 MiB。这两段,就是塔里内存层的地界,图上画的是它,也画到它为止。其余五行,行行标着 type=2,保留:EBDA 那一小截、固件落脚的角落、可用段头顶上的 128KiB、4GiB 天顶的一角、天边 0xFD00000000 起的一大片,五行全在里面。还有 1.5 点过名的 320KiB 空当,显存与固件的地界,清单上谁的名下都没写。图不画它,塔里它照样在,图和塔差的正是这些:图只管内存层的地界,楼上的楼下的一概不管。

内存层的地界到了咱们手里,还得过一道手续才好用。办手续的叫 PMM,物理内存的管家,接手的头一件事是把地界切成格子:一格 4KiB,行话叫一页,page.hpp 里 kSize 一个常量写着,往上谁都认它。为什么要切?整片地界没法一处处点清,切成页,一页一页才数得清。天花板也定下了:PMM 管到 16GiB 为止,再高的址不归它。

然后轮到名册本体,就是那本一页记一位的册子,咱们把它的个头从头算一遍。管 16GiB,按 4KiB 一格切,是 4194304 格,一格记一位,亮的占着,灭的空着,4194304 位,合 512KiB。这个比值值得单独念一遍:16GiB 的地界,512KiB 的名册,1 比 32768,摊到名册头上的,三万分之一。这本名册有个讲究,库存归主人自带:位图只管位,存身的词数组是人家递进来的,它自己从不伸手讨地方——内核还是个婴儿,上哪儿给它请第二个分配器去。词,就是一个 64 位的格子,待会儿翻位图,咱们就照词数。

**停一停,这道换算您心里过一遍**:名册上一位管一页,一页 4KiB,一位管的是多少个字节?

答数是 4096。您看,一位顶一整页,64 位合成一个词,一个词管 64 页,256KiB 的地界。名册管得这么宽,靠的是位只有亮灭两样,机器翻它,一眼一个准。内存层一格一格的地界,往后还要被页表再翻译一道:虚拟址怎么穿到物理址,TLB 和缺页为什么生出来,那是第 3 部的正戏,本章把物理的地界铺平,那儿才有得翻。

## Code: Cinux 实况:三万两千多页,一位一页的名册

实况锚是 r07_serial_pmm,`git switch --detach r07_serial_pmm` 切过去,看完 `git switch -` 切回来,新克隆的仓回 main。门面上交代一句版本的新旧:这一版比上一章手里那版早,串口的嗓子倒是这一版刚换上的,tag 名里的 serial,记的就是这桩事。可门房还没搬家,心跳还没上岗,IDT 还没铺,上一章那些铃线上的家当,这一版一样都没有。日志因此比上一章短,末行的 free 也多出 3 页:32350 对 32347,差在内核个头上,多一件家当多占几页,差的构成咱们不复算,数认到差值为止。串口的嗓子怎么接进内核的,正文《换嗓子,开机》那篇有全本,本章只管收字。

打镜像这一步省不得。切过站,build 里躺着的还是上一站的产物,您拿它开机,屏是旧的,数也是旧的,所以咱们头一条命令就是把镜像重新打一遍:

```bash
cmake --build build --target boot_image
timeout 90 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -display none -no-reboot -serial file:build/console.log \
```


二十二行,行行都在前几章照过面:七行清单,1.5 从固件手里接的正是它,验签的场子还在那边。两回换世界的报平安,1.4《保护模式与长模式》逐拍拍过。stage2 与 kernel 的几声平安,上一章刚照过面。末行 pmm 算半个旧识,1.6 里它报过一回 32347,照个面就走,这一章把它接过来细读:`[kern] pmm: 32350 pages free (probe 100000 ok)`,数从哪儿数出来,咱们陪您读到底。

写这行字的手续在 kernel/mm/pmm.cpp 的 init 里,咱们分三拍看。头一拍,全掩:set_all 把 4194304 位全部点亮,整片地界起手全当占满,一页不发。第二拍,按 e820 开格:七行清单挨个过一遍,type 不是 1 的跳过,type=1 的还要夹两道,底边抬到 1MiB(kLowMemoryTop)之上,顶边压到 16GiB(kPmmMaxPhys)之下。头一段 639KiB 整段趴在门槛底下,抬完是空的,跳过,一页不进名册。第二段整段在门里,页边又齐,一页没削,clear_range 把 32480 位全部拉灭,managed_pages_ 记下 32480。末一拍,自家闭格:内核本体躺在 0x200000,占地 0x810C0,init 拿 Span 按页取整,set_range 点亮 130 位。130 从哪儿来?0x810C0 折成字节是 528576,按 4096 一页取整,正好 130 页。这 130 页里住的不光是代码,还有名册自己:65536 个词、512KiB 的位图本体睡在内核的 .bss 里,姓内核名下。名册管着地界,自己住的几页,名册上也点的是亮,一页空位都不占。

末行括号里那句 probe 100000 ok,咱们得单独认一认,它是分配器上岗办的头一单生意。kernel.cpp 里就两行,allocate_page() 分一页出来,free_page() 原样还回去,然后连 free 数带分到的址,一行打印。分到的址是 0x100000。allocate_run 拿着“要一页”的名头去名册上找空位,find_clear_run 从头扫,头 256 位全亮着,那是门槛底下的 1MiB,全掩留下的底色,头一个灭位排在第 256 位,折成址,恰好 0x100000,地界的头一页。所以括号里这个数,别读成探针扎在哪儿,它就是分到的那页的址:分得到,还得掉,free 数走一圈回到 32350,这枚探针量的就是这件本事。

分页的手续里还有一个顶。allocate_pages(order) 一次拿的页数是 2 的 order 次幂,order 只收 0 到 9,顶上这一阶拿 512 页,2MiB,正好一个大页的尺寸,这个顶是 pmm_config.hpp 里 kMaxOrder 拍下的,值是 9。再大的数目,一回办不了,分几回办。顶拦在哪儿,练一练里请您亲手试一回。

**32350 页空位,乘回字节是多少?**末行的数就摆在这儿。您拿 1.5 里 #03 那段的 126.875 MiB 一比,差出去的部分,落在了谁家?

答数:您乘出来的应当是 132505600 字节,32350 乘 4096,折成 MiB 是 126.3671875。拿 126.875 减它,剩 0.5078125 MiB,合 520KiB,页数正是 130。free 数的是空位,清单报的是整片地界,差出去的整段都点在内核名下,一页没丢。

日志对完,再把机器冻一把,名册翻开看一眼真的。GDB 从 1230 端口进,断点下在 free_page_count 门口,0xffffffff80200b76,打印末行日志那一下,请的就是它,断在这儿,三拍都拍完了,probe 也还了。nm 量过,Pmm::init 住在 0xffffffff80200a58,allocate_run 在 0xffffffff80200b88,g_pmm 这本名册的家在 0xffffffff80200ea0。g_pmm 头三个词是位图的头面,words_ 指针、capacity、count_set,底下 65536 个词是位图本体,末了一个词 managed_pages_,排在 0xffffffff80280eb8。咱们一气读下来:

```text
Breakpoint 1, 0xffffffff80200b76 in ?? ()
0xffffffff80200ea8:	0x0000000000400000
0xffffffff80200eb0:	0x00000000003f81a2
0xffffffff80280eb8:	0x0000000000007ee0
```

头一个 capacity,0x400000,4194304 位,16GiB 除以 4KiB 的商,名册的容量。第二个 count_set,0x3f81a2,4161954 位亮着。末一个 managed_pages_,0x7ee0,32480,跟 init 记下的地对上。三个数凑到一起,咱们当场算:4194304 减 4161954,得 32350,日志里那句 free,源头在这儿,名册容量减去亮着的位,剩下的灭位就是空页,机器自己数的,跟打印的分毫不差。32480 减 32350,130,自家地界,也合上。

名册本体也值得念几眼。位图从 words_ 起头,排在 0xffffffff80200eb8,咱们把头 12 个词拖出来:

```text
0xffffffff80200eb8:	0xffffffffffffffff	0xffffffffffffffff
0xffffffff80200ec8:	0xffffffffffffffff	0xffffffffffffffff
0xffffffff80200ed8:	0x0000000000000000	0x0000000000000000
0xffffffff80200ee8:	0x0000000000000000	0x0000000000000000
0xffffffff80200ef8:	0xffffffffffffffff	0xffffffffffffffff
```

一个词 64 位,管 64 页。头四个词全亮:第 0 到 255 位,门槛底下的 1MiB,全掩的底色,没人动过。接下去四个词全灭:第 256 到 511 位,折成址是 1MiB 到 2MiB,空着,probe 分走的头一页就在这儿。再往后两个词全亮:第 512 位起,折成址是 0x200000,内核的座位,跟日志里 kernel at 200000 对上。第 11 个词亮了两格就收,0x3,130 页到头,余下的位又灭回去。地界另一头还压着一块好看的,咱们把地界末尾所在的那个词也读回来,0xffffffff80201eb0 处,读回 0xffffffff00000000,前半截灭,后半截亮:32704 到 32735 位还在地界里,空着,32736 往上出了地界,全掩的底色又接上了。整本名册念下来就是一幅画,两头亮,当中灭,灭里再亮一小段,内核坐在那儿。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,咱们核过的还是书页 25 与 28:加载器把内核复制进 0x80000000,跳进 _entry。物理内存它怎么管、立不立一本一位一页的名册,书页 25 与 28 一概没提。那两页里的 xv6,出门家当拢共一个栈,内存对它是一整块生地,连用都还没开始用,名册这路东西,在它的开场里连个影子都没有。往后长没长出来,后头的章节才说得上,那里头的数,本章一个不引。

Linux 那头,留白之前替它说句公道话:它的物理内存管家脚下是真硬件,内存分坨,大小页并存,塔的上半截各家 CPU 长得还不一样。给它写读数,就得写明哪台机器的数——写读数就得认机器,机器认不准,数就交不了卷。这一问咱们答不上:手里讲它的书,一页都还没翻到那里,翻到了,书上那部机器跟咱们这部 TCG 也不是同一部。

塔是咱们自己立起来的,立到哪儿、不立到哪儿,也得跟您交代。上半截不配:TCG 不演,配也无从配起,内核眼里的世界就当它是平的,快慢的便宜一点没占,亏也没吃。内存不分坨:NUMA——内存分成几处、离谁近离谁远各不相同的那套格局——不认,这一层当它匀质一块,真硬件上谁离谁近,内核一概不知。大页不做,页就是 4KiB,page.hpp 一处说了算,真到了要大页的日子,这一套 4KiB 地界得整段重划。分配只一条路:名册从头找空位,找到就占,find_clear_run 整词全亮的整词跳过,词里混着空位的才进去一位一位数,地界越大扫得越久,9 阶又封了顶,大块的家当得多跑几趟。

C++ 在这一章留了一句话,咱们看名册的个头是怎么定下来的。pmm_config.hpp 里,kPmmTotalPages 写作 kPmmMaxPhys / cinux::arch::page::kSize:名册管多少页,是天花板除以页大小算出来的,页大小又是 page.hpp 里的一处架构事实,谁也不硬填一个数。底下 kPmmBitmapWords 接着算,Bitmap::words_for(kPmmTotalPages),65536 个词,名册占多大,也自己算。真换一部 32GiB 的机器,改一个常数,4194304 变 8388608,词数翻倍,名册自己长大,人一个数都不用动,一位管一页的分寸,编译期就定完了。

您要核原文,路牌插在下面三处。CS:APP 第 6 章整章讲的就是这座塔,层次怎么排、局部性怎么撑起缓存,都在那儿,咱们只核到章号,一页都没引,数您自己去书里对。正文《内核接管》那卷,《一页一 bit 的名册》有这本位图名册的全本叙事,《换嗓子,开机》管串口上嗓。前置卷《设备怎么碰》的后半留过一根线头:设备寄存器为什么不能让缓存随随便便吞掉,当时说那是教科书这一层的事。线头递到本章手里了,咱们能接的也只有一句:那桩细目叫缓存一致性,连着内存屏障,留到第 4 部讲内存序的时候结。

## 这一章留下了什么

走完这一章,手里的东西各自带数。一张换过视角的 e820,type=1 的两段,是塔里内存层的地界,其余楼层图上一概不画。一本位图名册,一位管一页,65536 个词管 16GiB,两头亮、当中灭、灭里再亮一小段,内核坐在亮的那一小段里。一行日志,32350,名册容量减亮位,机器自己数出来的。塔的上半截,本章只有常识,没有屏,TCG 不演它。下半截,格格都点过数。图还是原来的图,可您如今知道它管到哪儿为止。内存层往上的翻译,页表、TLB、缺页,第 3 部见。至于内核本体那 130 页里头装着什么,ELF 的头和裸镜像差在哪儿,下一章进去看它的骨头。

| 术语 | 一句话口径 |
|---|---|
| 存储层次 | 塔:寄存器、缓存、内存、盘,一层比一层慢,一层比一层大,程序看不见却躲不开 |
| 缓存 | 塔里指令集不认的层:把热字抄在 CPU 手边,程序只摊得着快慢,TCG 不演它 |
| 局部性 | 程序的脾气:刚用过的转眼还用,用了一格,挨着的几格也快轮到 |
| 页 | PMM 分地的格子:4KiB 一格,page.hpp 的 kSize 说了算 |
| 位图 | 一位管一页的名册:65536 个词管 16GiB,亮是占着,灭是空着 |
| PMM | 物理内存管家:接 e820 的地界,切页、立名册、发页收页 |

## 练一练

名册是机器立起来的,翻名册的手得是您自己的。头一道把名册从机器里翻出来,断点、命令、读数都在下面。第二道的顶,allocate_pages 自己招了半截,剩下半截请您猜。第三道回日志,给二十二行按来路分家,再追一问 639KiB 的下落。

**题一,动手。** 把 r07 那场跑起来,断在 free_page_count 门口,亲眼看名册的三个数和头 12 个词。断点等的是打印末行日志的那一跳,机器一起跑就停得准。您从切版走到收尾,次序照下面走:

```bash
git switch --detach r07_serial_pmm
cmake -B build && cmake --build build --target boot_image
timeout 90 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -display none -no-reboot -S -gdb tcp:127.0.0.1:1230 \
  -serial file:build/console.log \
  -debugcon file:build/debugcon.log &
```

`-S` 让 QEMU 把机器停在头一条指令之前,那时名册还没开张,谁也读不成数。断点咱们已经替您下好,就在后头的命令里:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1230' \
    -ex 'break *0xffffffff80200b76' \
    -ex 'continue' \
    -ex 'x/1gx 0xffffffff80200ea8' \
    -ex 'x/1gx 0xffffffff80200eb0' \
    -ex 'x/1gx 0xffffffff80280eb8' \
    -ex 'x/12gx 0xffffffff80200eb8' \
    -ex 'x/1gx 0xffffffff80201eb0' \
    -ex 'detach'
```

读数怎么念,本章前文演过一遍,您照着念就行:三个数各是什么,头 12 个词哪儿亮哪儿灭,地界末尾所在的那个词一分为二,分在哪儿。detach 之后机器接着跑到 hlt 待命,build/console.log 里躺着整本日志,题三还用它。末了 `git switch -` 一敲,回到您出发的那一版,仓要是新克隆出来的,回去站着的还是 main。

**题二,猜想。** allocate_pages(10) 这一句递进去,拿回来的会是什么?真要一次拿 600 页,这套接口该怎么办?您猜一个,回 pmm.cpp 的 allocate_pages 头两行和参考答案里对。

**题三,读屏。** 题一跑剩的日志在 build/console.log 里,二十二行。您按来路给它们分家:各出自哪一章?末行 pmm 上一章照过面,这一章轮到它当主角,添了什么要读的?分完再答一问:头一段能用的 639KiB,固件明明标了 type=1,为什么 PMM 一页都不收?

### 参考答案

题一:您读到的三个数,应当是 capacity 0x400000,count_set 0x3f81a2,managed_pages_ 0x7ee0。头 12 个词,亮四词,灭四词,再亮两词,第 11 个词亮两格读回 0x3,第 12 个词全灭,跟本章前文那屏一模一样。地界末尾所在的那个词读回 0xffffffff00000000,前半灭在地界里,后半亮在地界外。

题二:零址,空手。您把 order 报成 10,allocate_pages 头两行就把零址递回来,机器不炸,话也不多说。您真要 600 页,得分几趟办:512 加 64 加 16 加 8,四趟 allocate_pages,四个址,凑齐 600。位图找空位找的是整段的空档,阶数把趟数卡在这儿,这是分地的方便,也是分地的死板。

题三:您把二十二行分下来,来路都在前几章:七行清单出自 1.5,两回换世界的报平安出自 1.4,stage2 与 kernel 的平安、末行 pmm 都在 1.6 照过面。pmm 那行,1.6 只当旧识照个面,数了 32347 就走,这一章它当主角,free 怎么数出来、probe 分到哪页、130 页差在哪儿,全是本章的活。639KiB 那段,init 的夹取把它整段抬空了:底边要抬到 1MiB 之上,它整个趴在门槛底下,抬完的底边跑到了顶边上头,区间空了,跳过,一页不进名册。固件标它的 type=1 不假,收不收,是名册自己的章程。
