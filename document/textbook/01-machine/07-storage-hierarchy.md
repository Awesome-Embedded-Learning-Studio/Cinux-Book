# 07 · 存储层次:图只有一层,塔分好几层

上一章的末行咱们念完,有一桩事挂在咱们手上:机器会疼、也会听了,咱们的家当却还摊在同一片内存上,内存这座宅子一层一层各有各的快慢,所以下一章要进去认门。这一章咱们就进去。进去的头一件事,咱们把那句“同一片内存”认清:那是内核眼里的样子。内核拿到手的是一张平面图,固件递来的 e820 清单画的就是它,图上的内存平平整整,排成了一段挨一段的样子。可机器的真身是一座塔:打头的是寄存器,跟着的是缓存,内存是当中的一层,垫底的是盘,越往下的层越慢,越往下的层也越大。本章咱们干的事,就是把图和塔对起来:图上划的是塔里哪一层,其余的几层又住在哪儿,这门咱们认完,您再看那行 free 的日志,读出来的就不是一串数了。

咱们的量法也得跟着塔分成两截。上半截量的是寄存器到缓存,各层的快慢,那是有数的,可几纳秒、哪一级、哪家型号的准数,咱们书架上没有核过的本子,所以一个都引不得,这一截本章报的只是量级,层与层差出的是百倍上下,咱们的话到这儿为止。下半截讲的是内存这一层,是自家的屏拍得到的:一份固件递来的清单,一行现成的日志,再添一本从机器肚子里冻出来的位图,读数全是现抄的。出处口径还是前几章立下的三条:前置卷管机理,正文管的是手续,读数出自自家的屏,本章把它按塔分成了两截,上半截讲的是常识,下半截点的是读数,两截的口气不一样,您读的时候分得出来。

## 图是一层的,塔不是

> **内核拿到的内存图,跟真实的存储是不是一回事?**
>
> 咱们把话说直:不是一回事,差的还不少。图上的那几行,划的只是塔里“内存”这一层的地界,塔还有别的楼层,图上是一个字都没写的。可咱们把话说回来:内核往后住得进的,也只是图里的一层,图是没画错的,它管的本来就只有一层。咱们这一章把塔立起来再拿图去对,对完您就清楚,32350 页 free 的那行,数出来的是塔的哪一角。

## 塔的剖面:下一层,慢一截,大一圈

塔分的是四层,咱们从顶上一层一层数下去。打头的一层是寄存器,CPU 的贴身家当,1.2《字节寄存器与栈》量过尺码的那批:机器一拍之内就在它们身上花数,快得咱们都计不过来,格子的数量却少得可怜,所以用字节当尺子就够量完。第二层讲的是缓存。缓存 1.1《一条指令的一生》点过名:指令集不认它,程序是看不见它的,摊得着的只有快慢。它干的活,是把内存里的热字抄一份放在 CPU 手边,靠的是程序的一个脾气,行话叫局部性:刚用过的数多半转眼还用,用了一格,挨着的几格也快轮到。有这个脾气给咱们撑着,咱们把热字放在手边,省得往下一层跑的,十回里占了八九回,缓存也就是这么立住的。

第三层轮到的是内存,塔的正厅:e820 清单划的就是它的地界,本章全部的读数都落在它身上,尺寸按 MiB、GiB 的尺子算。垫底的那一层是盘,咱们内核的镜像就住在盘上,stage2 把它搬进内存的那两声 kernel image ok、kernel ferried,1.6《DMA 与中断》的日志里都在,容量按 GiB、TiB 的尺子算。四层咱们数完,剩下的规律只有一句:每往下一层,慢的一头差出百倍上下,大的一头也差出百倍上下。这个倍数咱们不引书,可它也用不着咱们的本子:寄存器按字节算,盘按上千 GiB 的量级算,咱们把两头搁在一起,会说话的是量级自己。

剖面咱们画到这儿,有一件本章拍不成的事,得跟您交代:上半截没有屏。眼前这部机器跑在 QEMU 的 TCG 上,1.6《DMA 与中断》认过的翻译引擎,它是不演缓存的。TCG 把指令一块一块地翻译着跑,替的是译码的结果,不是内存的副本,1.1 数家当的时候,翻译块和缓存就是分开点的两样。所以缓存这一层,咱们在模拟器里找不到现场,快慢也量不出:程序看不见的东西,自家的屏一样看不见。上半截本章讲的只有规格常识,读数是一个都没有的,这句话咱们搁在这儿,您回头翻屏的时候,就知道该翻的是哪儿,不该翻的又是哪儿。

## 把平面图对回塔上

塔立好了,咱们回头拿图来认。1.5《与设备打交道》的那一回里,咱们把七行清单从固件手里接过来,验的是签,量的是斤两,关心的是怎么问、怎么信。拿的还是同一份清单,今天换一个问法:它划的是塔里哪一层的地界?七行里 type=1 的就两段。头一段是趴在 1MiB 门槛底下的 639KiB,另一段是从 1MiB 起的 126.875 MiB。塔里内存层的地界,就是这两段:图上画的是它,画的也就到它为止。其余的五行,行行标着的都是 type=2,保留:EBDA 那一小截、固件落脚的角落、可用段头顶上的 128KiB、4GiB 天顶的一角、天边 0xFD00000000 起的一大片,五行的下落全在里面。还有 1.5 点过名的 320KiB 空当,显存与固件的地界,清单上谁的名下都没写。图是不画它的,它在塔里是照样在的,图和塔差的正是这些:图只管内存层的地界,楼上的楼下的一概不管。

内存层的地界到了咱们手里还得过一道手续才好用。办手续的叫 PMM,物理内存的管家,接手的头一件事是把地界切成格子:一格 4KiB,行话叫的就是一页,写它的是 page.hpp 里的 kSize 常量,往上的谁都认它。为什么要切?整片地界没法一处处点清,咱们把它切成页,切成的一页一页才数得清。天花板也定下了:PMM 管到 16GiB 为止,再高的址不归它。

接下来轮到的是名册本体,就是那本一页记一位的册子,咱们把它的个头从头算一遍。它管的地界是 16GiB,咱们按 4KiB 一格切,切出来的是 4194304 格,一格记下的是一位,亮的占着,灭的空着,名册记的是 4194304 位,折合的尺寸就是 512KiB。这个比值值得单独念一遍:16GiB 的地界,512KiB 的名册,得出的比例是 1 比 32768,摊到名册头上的是三万分之一。这本名册是有讲究的,库存是归主人自带的:位图只管位,存身的词数组是人家递进来的,它自己从不伸手讨地方——内核还是个婴儿,咱们上哪儿给它请第二个分配器去。咱们说的词,就是一个 64 位的格子,翻位图是待会儿的事,咱们到时候就照词数。

**咱们停一停,这道换算您心里过一遍**:名册上一位管一页,一页的个头是 4KiB,一位管的是多少个字节?

您算出来的答数是 4096。您看,一位顶的是一整页,64 位合成的是一个词,一个词管的是 64 页,256KiB 的地界。名册管得这么宽,靠的是位只有亮灭两样:机器翻它,您看一眼就是一个准。内存层一格一格的地界,往后还要被页表再翻译一道:虚拟址怎么穿到物理址,TLB 和缺页为什么生出来,那是第 3 部的正戏,本章把物理的地界铺平,咱们到那儿才有得翻。

## Code: Cinux 实况:三万两千多页,一位一页的名册

实况锚的名字是 r07_serial_pmm,咱们拿 `git switch --detach r07_serial_pmm` 切过去,看完了再拿 `git switch -` 切回来,新克隆的仓回 main。门面上交代一句版本的新旧:这一版比上一章手里那版早,串口的嗓子倒是这一版刚换上的,tag 名里的 serial,记的就是这桩事。可门房是还没搬家的,心跳是还没上岗的,IDT 是还没铺的,上一章那些铃线上的家当,这一版是一样都没有的。所以日志比上一章短,末行的 free 也多出 3 页:32350 对 32347,差的落点在内核个头上,多占的几页,配的是多添的家当,咱们把数认到差值为止,差的构成不复算。串口的嗓子怎么接进内核的,咱们把全本放在正文《换嗓子,开机》的那一篇里,本章管的只是收字。

打镜像的这一步省不得。咱们切过站,build 里躺着的还是上一站的产物,您拿它开机,屏是旧的,数也是旧的,所以咱们头一条命令就是把镜像重新打一遍:

咱们抄来的二十二行,行行都是在前几章照过面的:七行清单,1.5 从固件手里接的正是它,验签的场子还在那边。两回换世界的报平安,咱们在 1.4《保护模式与长模式》里逐拍拍过。stage2 与 kernel 的几声平安,上一章咱们刚照过面。末行的 pmm 算半个旧识,1.6 里它报过的就是 32347,照了个面就走,这一章咱们把它接过来细读:`[kern] pmm: 32350 pages free (probe 100000 ok)`,数是从哪儿数出来的,咱们陪您读到底。

写这行字的手续在 kernel/mm/pmm.cpp 的 init 里,咱们分三拍看。头的一拍是全掩:set_all 把 4194304 位全部点亮,整片地界起手全当占满,所以一页不发。第二拍咱们按 e820 开格:七行清单挨个过一遍,type 不是 1 的跳过,type=1 的还要夹两道,咱们把底边抬到 1MiB(kLowMemoryTop)之上,把顶边也压到了 16GiB(kPmmMaxPhys)之下。头一段的 639KiB 整段趴在门槛底下,抬完了是空的,所以跳过,进名册的一页都没有。第二段是整段落在门里的,页边又是齐的,挨削的一页都没有,咱们请 clear_range 把 32480 位全部拉灭,managed_pages_ 记下的是 32480。末了一拍是自家闭格:内核本体躺在 0x200000,占的地界是 0x810C0,init 拿 Span 办的是按页取整,set_range 点亮的是 130 位。130 从哪儿来?0x810C0 折成的字节是 528576,咱们按 4096 一页取整,得出来的正好是 130 页。这 130 页里住的不光是代码,还有名册自己:65536 个词、512KiB 的位图本体睡在内核的 .bss 里,姓的是内核的名。名册管着地界,自己住的几页,名册上也点的是亮,占的一页空位都没有。

末行括号里的那句 probe 100000 ok,咱们得单独认一认,它是分配器上岗办的头一单生意。咱们到 kernel.cpp 里看,写它的就两行:allocate_page() 分一页出来,free_page() 把它原样还了回去,然后连 free 数带分到的址,打出来的是一行。分到的址是 0x100000。allocate_run 拿的就是“要一页”的名头去名册上找空位,从头扫的是 find_clear_run,头 256 位是全亮着的,那是门槛底下的 1MiB,全掩留下的底色,排在第 256 位的是头一个灭位,折成的址恰好 0x100000,地界的头一页。所以括号里这个数,您别把它读成探针扎在哪儿,它就是分到的那页的址:分得到的页咱们还得掉回去,free 数走一圈回到的是 32350,这枚探针量的就是这件本事。

分页的手续里还有一个顶。allocate_pages(order) 一次拿的页数是 2 的 order 次幂,order 收的只是 0 到 9,顶上这一阶拿的是 512 页,折成 2MiB 的个头,正好一个大页的尺寸,这个顶是 pmm_config.hpp 里 kMaxOrder 拍下的,值写的是 9。再大的数目,一回办不了,咱们分几回办。顶是拦在哪儿的,练一练里请您亲手试一回。

**32350 页的空位,乘回字节是多少?**末行的数就摆在这儿。您拿 1.5 里 #03 那段的 126.875 MiB 一比,差出去的部分,落在了谁家?

答数:您乘出来的应当是 132505600 字节,就是 32350 乘 4096 的积,折成的 MiB 数是 126.3671875。咱们拿 126.875 减它,剩下的是 0.5078125 MiB,折合的是 520KiB,折出来的页数正是 130。free 数的是空位,清单报的是整片地界,差出去的整段都点在内核名下,丢的一页都没有。

日志咱们对完了再把机器冻一把,名册翻开看一眼真的。咱们领着 GDB 从 1230 端口进,断点下在 free_page_count 的门口:0xffffffff80200b76,打印末行日志的那一下,请的就是它,断在了这儿,三拍都拍完了,probe 也还了。咱们拿 nm 量过,Pmm::init 的家在 0xffffffff80200a58,allocate_run 的位置在 0xffffffff80200b88,g_pmm 这本名册的家在 0xffffffff80200ea0。g_pmm 头三个词是位图的头面:words_ 指针、capacity、count_set,底下的 65536 个词是位图本体,末了一个词 managed_pages_,位置落在了 0xffffffff80280eb8。咱们一气读下来:

咱们头一个念 capacity:0x400000,折合的是 4194304 位,正是 16GiB 除以 4KiB 的商,名册的容量。第二个咱们念 count_set:0x3f81a2,亮着的是 4161954 位。末了咱们念 managed_pages_:0x7ee0,折算的数是 32480,跟 init 记下的地对上。凑到一起的三个数,咱们当场算:4194304 减 4161954,得的是 32350,日志里那句 free 的源头就在这儿,名册容量减去亮着的位,剩下的灭位就是空页,机器自己数的,跟打印的分毫不差。咱们再算 32480 减 32350,得的是 130,自家地界的数,也就合上了。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,咱们核过的还是书页 25 与 28:加载器把内核复制进 0x80000000,跳进的是 _entry。物理内存它怎么管、立不立一本一位一页的名册,书页 25 与 28 是一概没提的。那两页里的 xv6,出门的家当拢共一个栈,内存对它是一整块连用都还没开始的生地,名册的这路东西,在它的开场里连个影子都没有。它往后出现不出现的事,后头的章节才说得上,那里头的数,本章是一个不引的。

咱们再看 Linux 那头,留白之前替它说句公道话:它的物理内存管家脚下是真硬件,内存是分坨的,大小页是并存的,塔的上半截各家 CPU 长得还不一样。咱们给它写读数,就得写明哪台机器的数——写读数就得认机器,机器认不准的话,数就交不了卷。这一问咱们答不上:手里讲它的书,到那里的一页都还没翻到,翻到了,书上那部机器跟咱们这部 TCG 也不是同一部。

塔是咱们自己立起来的,立到哪儿、不立到哪儿的分寸,也得跟您交代。上半截是不配的:TCG 不演,配的路子也无从配起,内核眼里的世界就当它是平的,快慢的便宜一点没占,亏咱们也一点没吃。内存不分坨:NUMA——内存分成几处、离谁近离谁远各不相同的那套格局——不认,这一层就当它是匀质的一块,真硬件上谁离谁近的差别,内核是一概不知的。大页是不做的,页定的就是 4KiB,page.hpp 一处说了算,真到了要大页的日子,这一套 4KiB 地界得整段重划。分配走的只是一条路:名册从头找空位,找到就占了,find_clear_run 整词全亮的整词跳过,词里混着空位的才进去一位一位数,地界越大扫得越久,9 阶又封了顶,大块的家当得多跑几趟。

C++ 在这一章留了一句话,咱们看名册的个头是怎么定下来的。pmm_config.hpp 里的 kPmmTotalPages 写作 kPmmMaxPhys / cinux::arch::page::kSize:名册管多少页,是天花板除以页大小算出来的,页大小又是 page.hpp 里的一处架构事实,没有一个数是人硬填的。底下的 kPmmBitmapWords 接着算,调的是 Bitmap::words_for(kPmmTotalPages),算出来的是 65536 个词,名册占的个头也自己算。真换一部 32GiB 的机器,改的只是一个常数,4194304 变成了 8388608,词数跟着翻了倍,名册自己就长大了,人是一个数都不用动的,一位管一页的分寸,编译期就定完了。

您要核原文,路牌咱们插在下面三处。CS:APP 第 6 章整章讲的就是这座塔,层次怎么排、局部性怎么撑起缓存,都摆在那儿了,咱们只核到章号,引的一页都没有,数您自己去书里对。咱们再看正文《内核接管》那一卷,《一页一 bit 的名册》有这本位图名册的全本叙事,串口的上嗓,咱们交给《换嗓子,开机》的那一篇去管。前置卷《设备怎么碰》的后半留过一根线头:设备寄存器为什么不能让缓存随随便便吞掉,当时说那是教科书这一层的事。线头递到本章手里了,咱们能接的也只有一句:那桩细目叫缓存一致性,它跟内存屏障是连着的,留到第 4 部讲内存序的时候结。

## 这一章留下了什么

咱们走完这一章,手里的东西各自带数。一张换过视角的 e820,type=1 的两段,是塔里内存层的地界,其余的楼层图上一概不画。一本位图的名册,一位管的是一页,65536 个词管的是 16GiB,两头亮、当中灭、灭里再亮的一小段,内核坐在亮的那一小段里。一行的日志,数出的是 32350,名册容量减去亮位的那一下,机器自己数出来的。塔的上半截,本章有的只是常识,屏是没有的,TCG 是不演它的。下半截的格格都点过数。图还是原来的图,可您如今知道它管到哪儿为止。内存层往上的翻译,说的是页表、TLB、缺页,咱们第 3 部见。至于内核本体那 130 页里头装着什么,ELF 的头和裸镜像差在哪儿,下一章进去看它的骨头。

| 术语 | 一句话口径 |
|---|---|
| 存储层次 | 塔:寄存器、缓存、内存、盘,一层比一层慢,一层比一层大,程序看不见却躲不开 |
| 缓存 | 塔里指令集不认的层:把热字抄在 CPU 手边,程序只摊得着快慢,TCG 不演它 |
| 局部性 | 程序的脾气:刚用过的转眼还用,用了一格,挨着的几格也快轮到 |
| 页 | PMM 分地的格子:4KiB 一格,page.hpp 的 kSize 说了算 |
| 位图 | 一位管一页的名册:65536 个词管 16GiB,亮是占着,灭是空着 |
| PMM | 物理内存管家:接 e820 的地界,切页、立名册、发页收页 |

## 练一练

名册是机器立起来的,翻名册的手得是您自己的。头的一道,请您把名册从机器里翻出来,断点、命令、读数都在下面给您列好了。第二道的顶,allocate_pages 自己招了半截,剩下半截请您猜。第三道咱们回日志,二十二行按各自的来路回家,再追一问 639KiB 的下落。

**题一:请您动手。** 您把 r07 那场跑起来,断在 free_page_count 的门口,亲眼看名册的三个数和头 12 个词。断点等的是打印末行日志的那一跳,机器跑起来的时候,停下的位置是准的。您从切版走到收尾,次序照着下面的走:

```bash
git switch --detach r07_serial_pmm

```

咱们拿 `-S` 让 QEMU 把机器停在头一条指令之前,那时的名册还没开张,读得成数的人一个没有。断点咱们已经替您下好,就在后头的命令里:

```bash
gdb -q -nx -batch \
```

读数怎么念,本章的前文演过一遍,您照着念就行:三个数各是什么,头 12 个词的哪儿亮哪儿灭,地界末尾所在的那个词一分为二,分在了哪儿。detach 之后机器接着跑到的是 hlt 待命,整本的日志躺在 build/console.log 里,题三用的还是它。末了 `git switch -` 一敲,回到您出发的那一版,仓要是新克隆出来的,回去站着的还是 main。

**题三:请您读屏。** 题一跑剩的日志躺在 build/console.log 里,数的是二十二行。您按来路给它们分家:各出自哪一章?末行 pmm 上一章照过面,这一章它当的是主角,添了什么要读的?分完再答一问:头一段能用的 639KiB,固件明明标了 type=1,为什么 PMM 一页都不收?

### 参考答案

题一:您读到的三个数,应当是 capacity 的 0x400000,count_set 的 0x3f81a2,managed_pages_ 的 0x7ee0。头 12 个词:该亮的是四词,该灭的是四词,再亮的是两词,第 11 个词亮两格读回的是 0x3,第 12 个词是全灭的,跟本章前文的那屏是一模一样的。地界末尾所在的那个词读回 0xffffffff00000000,前半灭在地界里,后半亮在地界外。

题二的答数:零址,回的是空手。您把 order 报成 10,allocate_pages 的头两行就把零址递回来,机器是不炸的,话也是不多说的。您真要 600 页,咱们得分几趟办:512 加 64 加 16 加 8,办的是四趟 allocate_pages,拿回的是四个址,凑齐的才是 600。位图找空位找的是整段的空档,阶数把趟数卡在了这儿,这是分地的方便,也是分地的死板。

题三:您把二十二行分下来,来路都在前几章的正文里:七行清单出自 1.5,两回换世界的报平安出自 1.4,stage2 与 kernel 的平安、末行 pmm 都在 1.6 照过面。pmm 的那一行,1.6 那头只当旧识照了个面,数了 32347 就走,这一章它当的是主角,free 怎么数出来、probe 分到哪页、130 页差在哪儿,全是本章的活。639KiB 的那段,init 的夹取把它整段抬空了:底边要抬到 1MiB 之上,它整个趴在门槛的底下,抬完的底边跑到了顶边上头,区间空了,所以跳过,进名册的一页都没有。固件标它的 type=1 不假,收不收的话,得看名册自己的章程。
