# 06 · DMA 与中断:门房搬家,心跳上岗,引擎没开工

上一章许下的日子,这一章来还:设备自己开口叫人、不劳咱们一步一步搬,两桩都认。开口叫人的这桩,今天从头到尾走一遍,铃怎么进内核的门,内核怎么应,应完怎么回礼。不劳而搬的那桩只走到边界,引擎确实在座,咱们到今天还没请它搬过一次,这半桩的底细,本章如实交代。

真码这场,实况锚是 r09_intr_with_pic_pit,`git switch --detach r09_intr_with_pic_pit` 切过去,看完 `git switch -` 切回来,新克隆的仓回 main。起机器这件事,打这一版起有两样新气象,交代在门面上。头一桩是字换了门:前五章一路的读数,印字的门都是 0xE9 那扇调试口。打这一版起,日志全搬去真串口 0x3F8——1.5《与设备打交道》留过一句“正文后面的站才走到它跟前”,在今天的屏上兑现了。debugcon 那扇门还挂着,落下来的是 0 字节,一个字都没走它。第二桩是家当住得散:搬门房的住 pic.cpp,敲心跳的住 pit.cpp,应门的住 irq.cpp,记数的住 tick.cpp,外加把活儿串起来的 kernel.cpp。这一章报名字,把住处一并报上,您顺着文件找函数,一条道走到底。

中断这个名字,1.1《一条指令的一生》拍过:PC 的第三种走法,被中断拐走,顺着表进别人的代码,办完事回来。今天补的是这道手续的全本:线那头谁在摇铃,铃怎么送到 CPU 手里,表上查到谁,应门用几步,应完那一礼怎么还。规格那一头还是老难处,in 与 out 的条文书咱们一直没置办,本章的数,出处就只有自家的屏。

## 铃响到应完,中间隔着哪几站

> **设备把铃摇响,到内核把这一下应完、礼数送回去,中间隔着哪几站?**
>
> 换咱们来抢答,八成也是这句:CPU 跳过去跑一段,跑完跳回来,一站的事。真把机器冻在铃进门的那一拍,站数就数出来了:门房得搬过家,门牌表得挂好,该开的线得放开,CPU 的总闸得拉开,进门之后还得还礼。这一章把这些站一座一座走完,每一座都停在真码上,机器该冻就冻,读数当场抄。

## 应门的家当:一张表、两片门房、一只心跳

接铃的家当有三样。头一样是表。正文《会疼:自己的表,有名有姓的疼》那一卷把 IDT,中断描述符表,铺满了 256 扇门,一门 16 字节,整张 4KiB 住进 .bss。CPU 的向量号拢共 256 个,0 到 31 是架构异常的地界,32 往上留给外线。咱们自己的 IRQ 家族,门牌就从 32 号起编,irq_stubs.cpp 里 kFirstIrqVector 写的就是这个 32,16 条线,占 32 到 47。表怎么铺、门的十六个字节怎么摆,正文那卷有整节,本章只借门的数目和待会儿屏上的 limit 一行,别的都留在那边。

第二样是接线员,行话叫 PIC,8259 这对芯片。主片带 IRQ0 到 IRQ7 八条线,从片带 IRQ8 到 IRQ15 八条,主片的 2 号线让给级联,从片那八条都打这儿过,合起来 16 条。设备要开口,在自己那片门房挂上号,门房替它去按 CPU 的铃。门房跟 CPU 说话,走的还是 1.5 认下的端口手续:主片命令口 0x20、数据口 0x21,从片 0xA0、0xA1,报门牌,写字节。铃到 CPU 的走法,前置卷《设备怎么碰》演过整场:敲门的是 8254 定时器,转达的是 8259,CPU 只是照着表跳。机理那边有整节,咱们不重讲。

第三样是心跳。8254 定时器,行话叫 PIT,吊在 IRQ0 上,是这一章唯一开口的设备。它的脾气是匀速:进口一个 1193182 赫兹的时钟,出口方波,快慢全由一个除数说了算。咱们要每秒一百拍,命令口 0x43 写 0x36 挑方波,除数按 pit.cpp 里的算法算:1193182 除以 100,除不尽,商 11931,余数扔掉。11931 写成十六进制是 0x2E9B,进 0x40 数据口分两口,低字节 0x9B 在前,高字节 0x2E 在后,这个次序是 8254 的手续,pit.cpp 里的 kWrites 表一行一行排着。除数砍掉了零头,心跳就快那么一丝:1193182 除以 11931,约莫 100.0069 赫兹。配的是 100,实际微快,一天下来多出五百九十几拍。这笔数待会儿实况里对量级,快慢的方向,题二请您笔算。

还有一件,得单独交底,就是章名里另一个词。上一章许的愿有两桩,叫人的这桩今天走全程,搬运的那桩走到边界。引擎是真的:前置卷里 in 一次 0x08,8237 的状态口答 04,它在座。PIIX3 那块总线主控的窗口,0xc040 起,monitor 的 info pci 报过门牌。可再往下,前置卷那边如实记下的就三笔,到今天还是三笔:8237 的通道地址和计数没设过,PIIX3 的 PRDT 没写过,真的块设备没挂过一块。搬运的事,本章不发明现场,只有这几笔如实的交代。OSTEP 那本书讲 DMA 的口径,前置卷转述过:OS 把搬什么、搬多少、搬到哪儿交代给引擎,自己走开办别的事,引擎搬完抬手敲一次中断。您留意后半句——引擎报信,走的也是铃线:今天这套表、门房、应门的手续铺好了,往后引擎真开工,一样得走铃线。

## 接手三步:搬家、开一线、拉总闸

门房上任,头一件事是搬家。PIC 出厂的座位是旧的:主片把 IRQ0 到 IRQ7 报在 0x08 到 0x0F,那片地界在新世界里另有住户,撞车的来历,正文《会听:验自己的伤,听世界的话》那一卷的《十六线搬家》一节交代得很细,咱们只看搬家的手续。手续是四道初始化命令字,行文里叫 ICW,外加一道掩码。ICW1 进命令口,0x11,起手开工。ICW2 进数据口,报新门牌的起点,主片 0x20,从片 0x28,IRQ0 从此挂在 32 号向量上,IRQ8 挂在 40 号上。ICW3 报级联的接法,主片说“从片吊在我 2 号线上”,写 0x04,从片说“我就是吊在 2 号线上的那个”,写 0x02。ICW4 收尾,0x01,x86 的口径。末了一道不是命令字:0xFF 全掩,16 条线一齐捂上。五格一排,pic.cpp 里主片、从片各有一张 PortWrite 表,搬家的每一步都是往端口写一个字节,1.5 那套门牌手续,在这儿办成了整桌。

全捂之后,咱们只放开一条。irq.cpp 里的 Irq::enable_line 把 0 号线交出去,pic.cpp 的 unmask 读回主片数据口眼下的掩码,把 0 号对应的位松开,再写回去,两口气办完。要放的是从片名下的线,还得顺手把主片 2 号的位一起松,级联的门不开,从片喊破嗓子,话也到不了 CPU。今天只开 0 号,用不上这道搭手,可代码里这一步是现成的,哪条线开哪道门,手续都一样。

末一步在 kernel.cpp:41,一句 sti。门房这头齐了,还差 CPU 自己的总闸:打从进保护模式那一卷起,IF 就一直躺着,1.4《保护模式与长模式》的读数里它没立起来过。sti 一拉,铃才真正进得来。进门之后还有半桩事,应完得回礼,这一礼,行话叫 EOI。前置卷拿 A/B 实验演过它的分量:处理程序末尾少了往 0x20 端口写的那一下,8259 就认定上一趟没办完,第二声死活不来,计数器停在 1。真码里,这一礼长这样:irq.cpp 的 dispatch 里,handler 跑完,ack_ 无条件跟上一句。Pic::ack 往命令口写 pic.cpp 里的应答常量 kAcknowledge,值是 0x20。从片名下的线,从片答一句、主片再答一句,主片的应答哪一声都少不了。A/B 的机理咱们留给前置卷,本章拍的就是这几行真码。

## Code: Cinux 实况:一声铃,从进门到回礼

实况锚 r09_intr_with_pic_pit,一场四停。这一场有两样不同,记在头里。一样是家当的归属:表换成了内核自家的,GDB 断点直接下在 0xffffffff802 开头的高位地址上,稳稳当当。另一样是日志:QEMU 挂 `-serial file:build/console.log`,0x3F8 收的字全落进这个文件。`-debugcon file:build/debugcon.log` 也挂着,好让您亲眼看它交白卷。GDB 这回挂 1247 号口。

咱们把 kernel.cpp 里管铃的五行摆开。:37 Pic::remap,搬家。:38 Tick::init,把 PIT 按每秒 100 拍摇起来,顺带把计数器归零。:39 InstallIrqStubs,十六个桩进表。:40 enable_line,放开 0 号线。:41 sti。:42 打印报平安。为什么是这个次序、次序乱了会怎样,正文《开闸》一节逐条给过理由,咱们只认一个现成的日子:铃是 :38 那一拍就上岗的,比 sti 早了整整三步。

**闸还没拉,您说铃响没响?**:38 到 :41 这三步里,PIT 已经按一百拍的节奏在摇,可总闸关着,铃全憋在门外。憋着不等于没响,这一问的实证,机器自己记下了流水,待会儿 -d int 那一屏替它开口。

咱们把断点下在 Pic::remap 门口,0xffffffff80202830,机器一停,抄一眼现场:

```text
Breakpoint 1, 0xffffffff80202830 in ?? ()
=> 0xffffffff80202830:	push   %rbx
$1 = 0x6
```

$1 那行是 eflags,0x6——IF 是第 9 位,0x200,没立,总闸关着,这是搬家那一拍该有的样子。趁机器冻着,拿模拟器自己的 monitor 问一句 info registers,前置卷里您把 stop 和 info registers 递进去过,同一口问法。这一问吐出来是一大屏,咱们只抄跟表和模式相干的四行,次序照机器吐的摆:

```text
GDT=     ffffffff802037e0 00000017
IDT=     ffffffff80283840 00000fff
CR0=80000013 CR2=0000000000000000 CR3=0000000000001000 CR4=00000620
EFER=0000000000000500
```

GDT 那行,limit 0x17,三项乘八减一,内核自家的三槽表,正文那卷立的门户,在这儿就位。IDT 那行,limit 0xfff:256 扇门乘 16 字节减 1,正文铺满的整张表,就站在这一行读数里。CR0 最高位立着,长模式在办差,1.4 里您见过它。EFER 是 0x500,咱们当年只拨到 0x100,多出的 0x400 是硬件自己点的灯,1.4 里对过它的来历。

咱们把断点挪到 `irq_entry<32>`,0xffffffff80202930,32 号向量的桩,第一声铃的进门处。continue 落下去:

```text
Breakpoint 2, 0xffffffff80202930 in ?? ()
=> 0xffffffff80202930:	push   %r11
0xffffffff80284860:	0x0000000000000000
```

0xffffffff80284860 是计数器 ticks_ 的家:nm 量过,Tick::local_tick 住在 0xffffffff80284850,ticks_ 在它上头 0x10。读数是 0。铃都进门了,数还是 0,您别急着喊记错:tick.hpp 里那个内联的 Tick::on_interrupt 坐在 0 号线的椅子上,得等 dispatch 把它请出来,计数才往前挪。桩这一头分文未动,所以这个 0 说的是,打开机到现在,应完的铃,一声都还没有。

这一声铃进门走的是什么路?桩不长,咱们整段请出来:

```text
80202930:	41 53                	push   %r11
80202932:	41 52                	push   %r10
80202934:	41 51                	push   %r9
80202936:	41 50                	push   %r8
80202938:	57                   	push   %rdi
80202939:	56                   	push   %rsi
8020293a:	51                   	push   %rcx
8020293b:	52                   	push   %rdx
8020293c:	50                   	push   %rax
8020293d:	fc                   	cld
8020293e:	e8 5d 08 00 00       	call   802031a0 <cinux::interrupt::Irq::self()>
80202943:	31 f6                	xor    %esi,%esi
80202945:	48 89 c7             	mov    %rax,%rdi
80202948:	e8 93 08 00 00       	call   802031e0 <cinux::interrupt::Irq::dispatch(cinux::interrupt::IrqLine)>
8020294d:	58                   	pop    %rax
8020294e:	5a                   	pop    %rdx
	……
8020295a:	48 cf                	iretq
```

中间省了七个 pop,原样是一路 pop 排到 r11。九个 push 把被断下的现场一件不落请上栈,cld 清方向,call 进 dispatch,线号 0 由 xor %esi,%esi 递进去。dispatch 里椅子上有人的请出来跑,跑完 ack 必到。收尾把现场一件件请下来,iretq 原样奉还。一来一回,礼数齐全,咱们从头到尾看了一遍。

计数行军。再放一声,再断,读数 0x1:第二声进门,读到的还是上一声的数。把这一停搁下 200 回(`ignore 2 200`),再 continue,停下来的读数是 0xca,十进制 202。您对一下:上一停站在第 2 声门口,跳过 200 声,这一停站在第 203 声门口,数出来 202——正好差一拍。

**数跟停点对不齐,差的那一拍去哪儿了?** 没丢,它在办手续。铃进门那一刻,它自己的那一记还没落。这一记要等 dispatch 走到中段,才轮得到 Tick::on_interrupt 来记。所以停点站在第几声,数就是第几声减一。这句话您拿题一的命令亲手对一遍,比咱们在这儿念十遍都管用。

末了,咱们看机器自己记下的流水。这一回不挂 GDB,给 QEMU 添 `-d int -D build/int.log`,它把每一次中断投递记成一小节:一行摘要,前后跟着二十来行寄存器细目。跑八秒收工:

```bash
timeout 8 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -display none -no-reboot -serial file:build/console.log \
  -debugcon file:build/debugcon.log \
  -d int -D build/int.log
```

日志的头几行轮不到铃:固件进场那阵,模拟器把 SMM(固件自家的一种管理模式)的进出现场记了几笔,头一声铃要翻到四百多行才露面。咱们拿 v= 一筛,头两行就是机器有生以来的头两声铃,凑近看看:

```text
     0: v=20 e=0000 i=0 cpl=0 IP=0008:ffffffff8020036e pc=ffffffff8020036e SP=0010:000000000008fee0 env->regs[R_EAX]=00000000000000fe
     1: v=20 e=0000 i=0 cpl=0 IP=0008:ffffffff802003d1 pc=ffffffff802003d1 SP=0010:000000000008fee0 env->regs[R_EAX]=000000000000000a
```

v=20,十六进制的 20,正是 32 号门牌里 0 号线那扇,心跳进的门。cpl=0,内核态。IP 在 0xffffffff802 开头的高位半区,内核自家的地界。`grep -c 'v=20 ' build/int.log`,咱们这趟数出 792,八秒墙钟 792 发,一秒九十九下上下。机器跑在 TCG 上。TCG 是 QEMU 把指令一块一块翻译着跑的引擎,1.1 说的翻译块就是它的活。墙钟,咱们拿它指机器外头真流逝的时间,它说多少是多少,您跑出来的数不会跟这一趟一样,量级对上就算数。整本日志再筛一遍 v= 的花样,拢共只有 20 一种:16 条线开着 1 条,名不虚传。

方才那一问的答案,也在这两行里,咱们一条一条对。序号 0 那声,IP 是 0xffffffff8020036e。把报平安附近的反汇编摆开,sti 躺在 0xffffffff80200368,它的下一条把 0x64(正好是 100)备进 edx,给报平安那行字当参数。头一声铃进门的时候,报平安的话还在备料!闸是 :41 拉开的,铃是 :38 上岗的,总闸一开,门外欠下的头一声立刻补上。补得这么急,是 QEMU 里 PIT 的脾气,换真 8254,头一拍得等满一个周期才来,机器到机器不一样。等 `[kern] irq on, tick 100Hz` 走到串口,计数已经是 1,报的这句 100Hz,本身就是心跳敲起来之后的产物。序号 1 那声,IP 是 0xffffffff802003d1,那儿是睡区:0x3d0 一条 hlt,0x3d1 一条 jmp 跳回 hlt。打这往后,每一声铃把机器从 hlt 里叫醒,应完,跳回 hlt 接着睡——机器合着眼,耳朵开着,世界一响它就应。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,1.1 起咱们翻的就是书页 25 与 28:加载器把内核复制进 0x80000000,跳进 _entry。设备怎么开口、谁替内核接铃,那几页没有座席。书里另有章节讲它,笔者没读到,就不从这里引数了。

Linux 那头,铃响之后接电话的是谁、16 条线上的话怎么分流到各家驱动,这一问本章答不了。它的应门要养一整个调度与分流的班子,咱们手里讲这套班子的书,一页都还没轮到。答不出来,就把问题原样递到您手上,书读到的那天,再回来交卷。

自家的取舍,咱们也报一遍。听得见的铃只有一种,8254 的心跳。放开的线只有 0 号,一条不多。应门要走的程序就一层,表上 32 号那扇,椅子上一把。其余 15 条线全捂着,谁想说话,都得等哪一章放开它的线。眼下的世界清静,铃不打架,可真到了两台设备同时开口的那天,一条线一把椅子还够不够使,得另掂量。级联的细目、铃响谁让谁、几颗核各听各的铃,那是 8259 的接班人 APIC 的地界,日子到了它自会出场,眼下还不归这一章张罗。

C++ 在这一章的话,咱们看构建选项把它写成了什么样。pic.cpp、irq.cpp、tick.cpp、irq_stubs.cpp 四户的文件头都自报家门,说自己是 no-SSE 岛的住户,SSE 就是伺候 xmm 向量寄存器的指令集。构建脚本里,连 isr.cpp、exception.cpp 一共六个文件,被单独按 `-mgeneral-regs-only` 编——整条 iret 回去的路上,向量寄存器不许碰。铃一响,被打断的代码里躺着的 xmm 家当,桩不碰,dispatch 不碰,handler 也不碰,iretq 一收,原样奉还。另一半写在 irq.cpp 的 dispatch 里:handler 之后,ack 无条件跟上一句,每响必应,礼数不挑线。

本章的出处,一并报齐。前置卷《设备怎么碰》的后半,“谁主动”一节有 EOI 那场 A/B 的原始屏,DMA 一节停在看见引擎的那一步。正文两卷,《会疼:自己的表,有名有姓的疼》管 IDT 铺满 256 门的家底,《会听:验自己的伤,听世界的话》管搬家、心跳、开闸的全本手续,本章借的都是现成家当。三条来路至此报完:前置卷两节管机理,正文两卷管手续,剩下的读数,没出过咱们自己的屏。

## 这一章留下了什么

这一章走完,咱们把到手的东西挨个报名。一张五格一行的搬家表,门房从旧座位 0x08 搬进了 0x20 和 0x28。一枚 11931,心跳敲在每秒一百拍上下,实际微快。一只从 0 走到 202 的计数器,数永远比停点慢一拍,慢得明明白白。792 发心跳,每一发走的是同一条道,一声没落。至于引擎,它还坐在门口,没开工,本章也没替它发明现场。

机器到这儿会疼、也会听了,可它眼里的家当还摊在同一片内存上。内存这座宅子其实一层一层各有各的快慢,咱们下一章进去认门。

| 术语 | 一句话口径 |
|---|---|
| 中断 | 设备开口叫人:CPU 停下手里的,照表进处理程序,办完回来 |
| PIC | 两片 8259 门房:16 条线收铃、转达,应完等一句 EOI |
| IDT | 中断描述符表:256 扇门,铃响照它查人,本章只挂屏 |
| PIT | 8254 定时器:1193182 赫兹进,除数分频,吊在 IRQ0 上摇心跳 |
| EOI | 应答回礼:往命令口写 0x20,告诉 8259 这一趟办完了,漏了第二声不来 |
| tick | 心跳计数:Tick::on_interrupt 每声加一,坐在 IRQ0 的椅子上 |

## 练一练

您动手把计数器追一回,笔算一道除法,末了读机器自己记下的流水。

**题一,动手。** 把 r09 那场跑起来,您亲手把计数器从 0 追到两百开外。这一场的镜像要现打,命令第二行干的就是这件事,省了它,要么机器起不来,要么起来的不是这一章的机器:

```bash
git switch --detach r09_intr_with_pic_pit
cmake -B build && cmake --build build --target boot_image
timeout 90 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -display none -no-reboot -S -gdb tcp:127.0.0.1:1247 \
  -serial file:build/console.log \
  -debugcon file:build/debugcon.log &
```

`-S` 让机器停在头一条指令之前:铃还没上岗,闸还锁着,计数器睡在零里,读数全在后面的代码里等着。您把两枚断点下好,放它跑起来:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1247' \
    -ex 'break *0xffffffff80202830' \
    -ex 'continue' \
    -ex 'break *0xffffffff80202930' \
    -ex 'delete 1' \
    -ex 'continue' \
    -ex 'x/1gx 0xffffffff80284860' \
    -ex 'ignore 2 200' \
    -ex 'continue' \
    -ex 'x/1gx 0xffffffff80284860' \
    -ex 'detach'
```

头一枚断点把您送到门房搬家那拍,第二枚守在 32 号桩上,continue 一路放铃进门。detach 之后没人看它了,铃照样一声一声地应,build/console.log 报完平安就再没新字——数都记在机器肚子里,您想看,题三教您开它的流水。QEMU 挂着九十秒的 timeout,到点自己收摊。收尾 `git switch -` 一敲送您回去,从干净克隆跟来的朋友,落回的还是 main。

**题二,猜想。** pit.cpp 里那道除法,1193182 除以 100,商 11931 余 82,余数扔掉。您猜:这一截断,机器实际的心跳是快了还是慢了?一天下来,计数凭空多出几拍?笔算完,回参考答案里对咱们的算式。

**题三,读屏。** 题一跑剩的 QEMU 要是还挂着,您把后台任务收掉再跑这一场——两台机器抢一份镜像,后一台起不来:

```bash
timeout 8 qemu-system-x86_64 -drive format=raw,file=build/boot/cinux.img \
  -display none -no-reboot -serial file:build/console.log \
  -debugcon file:build/debugcon.log \
  -d int -D build/int.log
```

八秒后 timeout 收场,build/ 里躺下三份日志,debugcon.log 一份还是空的。您数一数:int.log 里 v=20 的行有多少?整本日志筛得出第二种向量吗?序号 0 那行的 IP 落在哪个址,回本章前文里给它对号。

### 参考答案

题一:头一停,读数 0x0——第一声铃进门,数还没记。`ignore 2 200` 之后再停,读数 0xc9,十进制 201:上一停站在第 1 声门口,跳过 200 声,这一停站在第 202 声门口,数出来 201,差的正是正在办手续的那一拍。您要是把它停在第 2 声再跳 200,读到的会是 0xca——停点挪一拍,数跟着挪一拍,差的永远是一。

题二:快了。实际心率是 1193182 除以 11931,约 100.0069 赫兹,每秒快 82/11931 拍。咱们按一天八万六千四百秒折算,82 乘 86400 再除以 11931,合计快 593.8 拍,四舍五入 594。计数跟着快,数没坏,快有快的来历:除数砍掉的那个零头,一天合五百九十多拍,都记在它名下。要分毫不差,得挑除得尽的配速,或者另想补法,本章不折腾。

题三:v=20 的行,咱们这趟数出 792,您的数随墙钟走,几百的量级就是对的。第二种向量筛不出来,整本日志只有 20 一种:16 条线开着 1 条,铃世界里只有心跳一个声音。序号 0 的 IP 是 0xffffffff8020036e,sti 的下一条备参的半道上——总闸一开,欠下的头一声立刻进门。
