# 03 · 上电:家当是一场接力

前两章咱们花家当花得顺手:AX 里装数,栈上压地址,仿佛它们生来就揣在机器身上。真要一格一格往上追,每一格都有来处。上一章收尾把话放在了这儿:上电那一刻,这批家当是谁给的、按什么顺序给的。这一章就追这趟来路。

量法换了一半。前两章书给规格、真码对数,这一章的规格只划大框:手册和约定讲清的是“哪些事有承诺”,至于交棒那一刻每一格具体是什么值,书上没有,得咱们自己把机器冻在那一拍去抄。咱们把断点下在 0x7c00,抄一份寄存器的全家福,再取三笔内存读数,回头一层一层对。实况还是 r01_mbr 那一版,行号照旧按它的 `boot/mbr.cpp` 数。

## 交棒那一刻,BIOS 担保了什么

> **机器交到咱们桩的手里那一刻,BIOS 真正担保过的,到底有哪几样?**
>
> 直觉多半以为,交棒是一场严肃的交接,全家福上每一格都有人签字。等读数摆开,您会看见担保单短得可怜:拢共三样。单子外的格子不是空的,里头有数、有零、有固件踩过的脚印,可那些全是白送的,白送的就能变。桩进门那几条自清自立的指令,防的就是这个。

## 规格、约定,还有顺手留的

追来路得从最头上追。复位那一刻机器长什么样,前置卷里讲计算机怎么工作的那一卷,您在开篇《上电与取指》里整篇走过:CS 的选择子是 f000,隐藏基址却是 ffff0000,头一条指令从物理地址 FFFFFF0 取,这几笔是 Intel 手册写明的,搁在哪台照章办事的机器上都该对得上。固件的映像在低端另藏一份,那就属于模拟器自己的做法了。咱们不重叙,要借的是那边立下的一条纪律:哪些数是手册定的,哪些只是 QEMU 配 SeaBIOS 自己的做法,得分清。这一章把它接着用,还得往下再分一层:手册写明的之下,还有约定俗成的,和谁也没承诺过的。

从 FFFFFF0 到 0x7c00,中间隔着固件跑的一大段:自检、找盘、把咱们的扇区读进内存。前置卷那屏复位读数站在这一段的头里,咱们这一章的全家福站在尾上,一早一晚两屏,把 BIOS 干的活夹在中间。它个头大、经手多,咱们管它叫胖中介:进门时家当是手册定的,出门时它只在三样东西上肯签字。

于是家当分了三层。头一层是手册写明的,叫规格:复位态那几笔,写进手册,四海皆准。约定俗成算第二层:0x7c00 这个交棒点、盘号装进 DL、扇区末尾的 `55 aa` 签名,没有谁逐条立法,可写引导代码的都认它,照着做就对得上。最底下那层是顺手留的:交棒时 EAX 里躺着什么、SP 指着谁,固件退场时是什么样就什么样,没人担保,换一家固件就换一副长相。分层的用处待会儿就见:读全家福的时候,每一格都得问一句,你是哪层的。

## 0x7c00 与 55 aa:交棒的约定

交棒点为什么落在 0x7c00?咱们能负责任说的只有机制,手头没有书证的来历,一句史话不写。约定是这样:引导扇区定成一个扇区 512 字节,交棒点就定在 0x7c00,底下留出一大片给固件自己的数据和栈。BIOS 把头一个扇区读进 0x7c00,验末尾两字节,对了才把机器交过来。那两字节排在第 510、511 的位置,0x7c00 加 510 落在 0x7dfe,咱们实测读出来正是 `55 aa`。验对这两字节,交棒就成了,可验的只是末尾一处:签名后头要是还拖着字节,BIOS 一概不操心。1.1《一条指令的一生》里笔者摔的那一跤,摔的正是没把这两件事分开。

固件的灶台就在交棒点底下。这话不是猜的:实测交棒那一刻 SP 是 0x6f18,离 0x7c00 三 KB 出头,SP 眼皮底下的四格里还躺着 `57 d5 00 f0`,字节里透着 f000 那个固件段的模样,固件自己的栈刚在这儿歇过脚,退场时没收拾。咱们不解读那几个字节是什么,只记一件事:这片地在约定里归固件,桩不碰。

## Code: Cinux 实况:断在 0x7c00 的全家福

咱们把断点下在 `*0x7c00`,机器冻住那一刻,咱们的头一个字节还没被执行,全家福上是纯纯的交棒现场。桩这十行,:25 到 :34,1.1 一拍一拍数过它干什么,1.2《字节寄存器与栈》量过每一趟搬运多宽,这一章换个问法,只问每一样家当的来路,拍数与宽度都不重数。

**停一停,您合眼猜一猜**:断在 0x7c00 这一刻,EAX 里是什么?SP 指着谁,眼皮底下又躺着什么?猜定了往下翻,拿读数对。

咱们把全家福抄来。屏上另有几行与本章的家当不相干,基地址那几行、cr2 往后的控制行、浮点状态,连同 xmm 那几排,一并略去:

```text
eax            0xaa55              43605
ecx            0x0                 0
edx            0x80                128
ebx            0x0                 0
esp            0x6f18              0x6f18
ebp            0x0                 0x0
esi            0x0                 0
edi            0x0                 0
eip            0x7c00              0x7c00
eflags         0x202               [ IOPL=0 IF ]
cs             0x0                 0
ss             0x0                 0
ds             0x0                 0
es             0x0                 0
fs             0x0                 0
gs             0x0                 0
cr0            0x10                [ ET ]
```

咱们再取三笔内存读数,一并摆开:

```text
0x7c00:	0xea	0x05	0x7c	0x00
0x7dfe:	0x55	0xaa
0x6f18:	0x57	0xd5	0x00	0xf0
```

担保单这就点名。头一样,CS:IP 折出来落在 0x7c00。屏上 cs 是 0、eip 是 0x7c00,可担保的是折算的结果,不是两半各自的身份:1.1 的题二里您见过另一家折法,07C0:0000,折出来落在同一格。第二样,DL 揣着盘号,约定罩住的也就是“盘号装在 DL”这件事,屏上 edx 整格是 0x80,低字节就是它。0x80 指哪块盘,咱们拿实证说话。1.2 拍过的链在这儿用上了,kDrive 从 g_boot_drive 取回来递进 DL,int 0x13 拿这个号读回的,正是启动用的这块盘,至于编号本身有没有成文章法,手头的文献里查不着,咱们不替它立法。第三样,内存里那 512 字节:0x7c00 起头四个字节 `ea 05 7c 00` 是咱们自己的远跳,0x7dfe 处躺着的 `55 aa`,就是 BIOS 验的那两字节。三样之外,单子上再没有别的了。

单子外的格子,一格格看过去也值。EAX 是 0xaa55,这数瞧着眼熟,倒着念正好是签名那对字节,可咱们偏不去解读:它不在担保单上,只是固件收工时顺手留的。EBX、ECX、EBP、ESI、EDI 全是 0,六个段寄存器也全是 0,连担保单上的 cs 也在内,值干净,“是 0”这件事却同样没人签字。EFLAGS 是 0x202,中断开着,DF 躺在 0 上。cr0 是 0x10,只有 ET 一位立着:保护模式那扇门,还关着。

:25 头一条就是远跳,把 CS、IP 一次写成自己点名的数。CS 虽是担保单上的头一样,担保的内容也只是“此刻指着咱们”这一下,远跳一出手,段值变成咱们写的 0,往后按选择子乘十六的寻常算术走,不再依赖固件留下什么。:27 到 :30,一条 xor 把 AX 归零,三条 mov 分头送进 DS、ES、SS。为什么下手这么狠,正文里记着当年的教训,咱们一句带过:没担保的格子一律当它黑着,自己写过的才算数。

:31 一条 movw,SP 从固件歇脚的 0x6f18 换成咱们立的 0x7c00,栈从这一拍起姓咱们的姓:往后 push 有地方压,call 的返回地址有处躺。底下固件的旧字节一个没动,也不必动,那片地本就归它。

:32 把 DL 存进 g_boot_drive,这一拍值得咱们专门问一句为什么。DL 是担保单上唯一一件“带进未来”的家当:往后读 stage2 还得请 BIOS 出手,请它就得报盘号,可寄存器这东西随时会被任何一段代码覆写。内存格子才留得住东西,g_boot_drive 链接后排进 0x7d4c,从这一拍起,盘号有了自己的户口。

:33 是 cld,把方向标志 DF 清零,往后串指令往哪边走,听咱们的。DF 不在担保单上,照理说这一拍是纯保险。有意思的是实测:EFLAGS 是 0x202,DF 本来就躺在 0 上,cld 这一拍什么也没改。咱们照实说:它不是纠正,是保险,不能赌每一台机器、每一份固件都这么贴心,一格没担保的标志,自己立一遍才睡得着。

:34,call MbrMain,咱们看着接力交出去。清过的、立过的、存下的,从这一拍起全是有主的家当,机器后头念的每一格值,来路都说得清。

## 对照:同一件事,别的机器怎么做

RISC-V 那边的 xv6,上电的家当单子短得多。没有 BIOS 这样的胖中介:上电后机器跑只读存储器里的加载器,它把内核复制进 0x80000000,直接跳到 _entry,书页 25 与 28 记的就是这场开场。寄存器里几乎没有一样算担保的输入,_entry 一进门就给自己立栈,栈的每一样都得自己挣。咱们这边三样硬货好歹是签字画押的,那边连签字的人都省了。

BIOS 这一棒,咱们的态度是当黑盒使:进门时它家当几何是手册定的,出门只数三样硬货,门里它怎么自检、怎么枚举设备,不在这套教程的目标里,咱们要的三样,黑盒外面都数得着。

Linux 从固件手里怎么接家当,这一块还是不敢落笔:相关文献咱们没逐字核过,没核过的内容写进书就是编。哪天核完,补上。

C++ 在这章也给咱们留了一句。`boot/mbr.cpp` 里 g_boot_drive 的定义带着 `= 0` 的初值,那是 C++ 语言层发的家当,静态初始化,编译器担保。到了运行时,:32 拿 DL 把它覆写一遍,那才是 BIOS 发的。同一个词“初始化”,在两层各发生一次,谁也不替谁担保,语言层给的 0,从没承诺过等于真盘号。

您要核原文,去处有两处:《计算机怎么工作》的开篇《上电与取指》,复位态和那套分清哪些是手册定的、哪些是模拟器做法的纪律,全篇都在。xv6 书第 2 章开头,是那边开场的原话。这一章没添没核过的新文献。

## 这一章留下了什么

接力看完了,攥在手里的是几样实物。DL 里的 0x80,担保单上唯一带进未来的家当。0x7dfe 的 `55 aa`,两个字节的签名,验过才交棒。SP 从 0x6f18 到 0x7c00,固件歇过脚的地方换成了咱们立的栈。还有 g_boot_drive,源码里一个 `= 0`,运行时一条 movb,两层各发了一回家当。手册、固件、桩,三家挨个发完,机器才算真正到了咱们手里。还剩一扇关着的门:实模式这 1MB、16 位口径的世界怎么走出去,下一章开它。

| 术语 | 一句话口径 |
|---|---|
| 复位向量 | 复位后处理器取头一条指令的物理地址,手册写明在 FFFFFF0 |
| 规格 | 手册白纸黑字写明的承诺,搁在哪家照章办事的机器上都对得上 |
| 约定俗成 | 没有谁逐条立法、写引导代码的都认的做法:0x7c00 交棒、DL 装盘号、`55 aa` 签名 |
| 交棒点 | BIOS 把可引导扇区读进内存、跳进去的地址,约定在 0x7c00 |
| `55 aa` | 引导扇区第 510、511 字节的签名,BIOS 验过才肯交棒 |
| cld | 清方向标志的指令,桩里用它给串指令的方向上保险 |

## 练一练

来路听咱们讲了一遍,您亲手对一遍才算数。动手抄一回全家福,再闭眼猜一格,末了读固件踩下的脚印。

**题一,动手。** 把 r01_mbr 跑起来,断点下在 0x7c00,亲手抄一份全家福,再看看签名。从切版本到把 QEMU 挂上,咱们照下面这个顺序来:

```bash
git switch --detach r01_mbr
cmake -B build && cmake --build build --target boot_image
timeout 120 qemu-system-i386 -drive format=raw,file=build/boot/cinux.img \
  -nographic -display none -no-reboot -S -gdb tcp:127.0.0.1:1240 &
```

QEMU 起来就停在复位那一步,后台里静着,等断点去 0x7c00 叫醒它。屏上滚过 Press Ctrl-B 一类的吆喝不用分神,固件那几位,上一章您已经跟它们打过照面。回到同一个终端,这回轮到 gdb:

```bash
gdb -q -nx -batch \
    -ex 'target remote 127.0.0.1:1240' \
    -ex 'break *0x7c00' \
    -ex 'continue' \
    -ex 'info registers' \
    -ex 'x/2xb 0x7dfe' \
    -ex 'detach'
```

**题二,猜想。** 交棒那一刻 EAX 里躺着 0xaa55,桩对它读都没读,进门一条 xor 就把 AX 归了零。您猜:换一份固件,交棒那一刻 EAX 还会是 0xaa55 吗?EAX 里的家当,该记在三层里的哪一层?

**题三,对着屏幕读。** 题一的命令里给 gdb 再添一条 `-ex 'x/4xb 0x6f18'`,SP 眼皮底下的旧字节就出来了。您对着读:这几个字节是谁放的?换一台机器、换一份固件,还是这几个字节吗?SP 后来被桩写成了什么,这几格又动了没有?

### 参考答案

题一:屏上滚出来的,正文里点过名的几样都在:eax 0xaa55、edx 0x80、esp 0x6f18、cs 0、eip 0x7c00、eflags 0x202,一格不差,0x7dfe 处两字节 `55 aa`。您抄下的每一格,回头都能对上三层里的一层。

题二:不是。0xaa55 只是 SeaBIOS 收工时的样子,换一份固件没准就换数,记在顺手留的那一层。分界的判法也直白:换成别家也认的,才配叫约定,而咱们亲眼见过的,只有眼前这套环境交出这个数。

题三:您读到的几个字节是固件栈上的旧货,`57 d5 00 f0`,透着 f000 那个固件段的模样,不担保,换了固件就换字节。SP 随后被桩写成 0x7c00,桩里没有一条指令碰那片地:固件的灶台,它不收拾,也不再住。往后 BIOS 被请回来办事,那片地怎么用,是它的事。
