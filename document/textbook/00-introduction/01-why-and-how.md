# 01 · 为什么亲手做一个操作系统,这本书怎么读

咱们从您天天在用的机器说起。您敲一行命令,敲的字当场就上了屏,机器的应答也紧跟着回来。您写个小程序,它跑起来的那一刻,就有了自己的内存、自己的输入输出,崩了还有人替它收尸。

这些事顺理成章惯了,倒叫人懒得追问一句:凭什么?这本书押的就是这句凭什么。咱们把它当一门手艺,从上电的那一刻起,咱们亲手再走一遍。

这一篇是全书的导言,管的是两件事:一件是它为什么值得您做,另一件是这本书的读法。下文光报部号和章名的,都是教科书层的章,这一层的章分五部,咱们这就把两件事一样一样摆开。

> **现成的操作系统满地都是,您电脑里就跑着一套,为什么还要亲手做一个?**
>
> 您读成品,答案立刻就在您手上:中断怎么工作的,页表怎么摆的,几百页的书讲得明明白白,记了就能用。而这些机制当初为什么非来不可,成品自己讲不出来了,它们出生时面对的难处,早叫几十年的修补填平了。您亲手搓一遍,难处在前、机制在后的次序,就整个倒了个个儿:每个部件您都亲眼看着,它是给哪桩案子逼出来的。

## 为什么要亲手做一个

成品内核这样的功课,书架上多的是。Linux 的源码公开,xv6 连代码带讲解一并装订成了书,可它们有个共同的脾气:机制是现成的,来路要您自己考古。一个机制为什么长成今天这个样子,答案埋在了历年的修补里,书追认的,只能是末了那版的样子。

咱们这部书走的正是这个次序,每一件家当都从它的难处讲起。头一个例子出在设备的身上:设备的活干到哪一步了,是它自己开口叫人的事,不劳咱们一步一步搬,所以有了铃,有了应门的一整套家当(教科书层第 1 部《DMA 与中断》一章)。

第二个例子咱们到信号那儿找。系统调用进门存的帧原本是十二槽,而信号要接手的是整套执行现场,十二槽是装不下的,补了四格才装齐(第 4 部《信号》一章)。

第三个例子咱们到终端那儿找。零到二号的三个文件描述符,从前坐的是三张特权假座,摊在系统调用里成了九处特判,close 零号跟没关是一样的,shell 一搬家的时候,它拉起来的孩子,咱们叫它子进程,就死在路上了。后来的修法,是把特权尽数撤干净的,头三号与三号往上的 fd,走的是完全相同的路(第 5 部《终端与伪终端》一章)。

机制是不空降的,每一件都带着自己的案底,咱们一件一件来。

## 错也是正课

错在这部书里算正课的一部分,往后您会连着碰上三个案子。您在第 1 部第一章《一条指令的一生》里会遇上一只框,名叫笔者摔过的一跤:有个公共模块被整个链进了引导镜像,512 字节是装不下的,镜像胀了出去,机器照样起跑了,一头扎进没加载过的内存,念的是上一任住户留下的随机字节。事后拿 objdump 量出镜像的真身,咱们才对上了案发现场。

这样的跤不止一跤,咱们再看一桩,第 4 部的开篇押的是一回纯重构:一行逻辑也没有改,长凳(您写码跑测试的电脑上直跑的测试台)那头全部通过了,机器上的测试却接连退出了。当年断定的是中断应答丢了、时钟停摆,深挖翻了案,病根改判在等待循环的身上:单例收进公共底座之后,取它的门改成了头文件里的内联,等待循环里那记跨单元的调用没了影,编译器把没人写时钟计数的循环整段当成了死代码删掉。中断链上的异常只是症状,真删码的是编译器。

判读翻了案也不遮着:第 5 部的终端一章,头一号嫌疑人押过之后深挖翻了案,当年的原话就登在章里。您跟着读下来的,除了末了那版代码,还有它是怎么被逼出来的、错了往哪儿查。

## 一套书,三层分工

这部书分了三层,导航上各有各的入口。前置卷管家什:书房怎么收拾,工具链怎么装,汇编怎么读怎么写,裸地上的 C++ 还剩什么,机器上电之后大致走的是哪几步,OS 的全景长什么样,Unix 的使用侧怎么走,七卷给您备齐。

前置卷不要求您一次读完:书房与工具链两卷您读到位,您进正文的第一个卷就顺了,其余的几卷,您缺哪块就回头翻哪块。

轮到咱们讲正文,它走的是主线叙事,照着真实的开发史一行一行地搓:引导怎么写,内存怎么管,进程怎么轮,文件怎么落。每一版的来路都记在卷里,定了什么、错在哪、怎么改,您随时翻得到。

教科书层就是您眼下这一层,讲的是模型与对照:机器那边承认的是什么,咱们这边怎么兑现,别的系统是怎么做的,代价上的差别也摆给您看。这一层讲到的机制,来由常是向正文借的,卷名给您写在书名号里,您顺着卷名回得去。三层为什么各自单立?备家什的、搓系统的、往深处看的,各有各的节奏,写坏了各赔各的代价,分开来各走各的,谁也不拖谁的后腿。

您要看的机制是同一个,咱们从三处各看一眼:手法归前置卷、来路归正文、模型与对照归这一层,分工上文都交代过了。

拿缺页来当例子的话,三处各看一眼是什么样:前置卷给您手法,单步、冻拍、翻日志都是它的家什,您带着手法进场。缺页当年是怎么立起来的,正文《懒到家:从登记册到补页》那一卷讲的正是它的来路。把它从头走到尾的实况,摆在这层《缺页与按需分页》的那一章里。末了把机器的许诺与兑现摆成模型,再请您看 xv6 与 Linux 同台。

| 层 | 管什么 | 您怎么用它 |
| --- | --- | --- |
| 前置卷 | 备家什:书房、工具链、汇编、裸地上的 C++、计算机怎么工作、OS 全景、Unix 使用侧 | 缺了哪块,您回头翻哪块 |
| 正文 | 照着真实的开发史一行一行地搓的主线,机制的来路都在卷里 | 顺着走,它是全书的骨架 |
| 教科书层 | 模型与对照:机器承认什么、咱们怎么兑现、别的系统怎么做 | 正文讲完一个机制,您来这儿看它的深浅 |

**咱们写到这儿停一停**:您上一次纳闷机器底下到底干了什么,是为了什么事?终端怎么把您的键交给 shell,还是一个程序崩了谁来收尸?那件事多半就是后头五部里的一处正题。

## 一章长什么样

这一层的章,骨架大体是通用的,咱们带着您走一遍。章首立的是一道难题,用的是粗体引块,问句里是带着人称的,这样的难题,一章里立一道也就够了。第 1 部第一章立的是:

> **咱们凭什么敢把“一条指令做完,才轮到下一条”当成真的?**

概念与机制是顺着难题往下铺的,半路会停下来问您一声,请您掂量掂量再往下走,答案多半是冷的,猜错了才记得牢。笔者摔过的跤,摔得有教训的,咱们单独开一只框,框里给您备好案发现场、判读、翻案,连学费一起交给您。

概念讲完了不算完,章里还设了一节 Code: Cinux 实况,拉着您进真实代码走一遍。走查是默认的样子:一句读码指令,加一段按执行顺序的叙述,行号的给法是文件名加冒号加行号。大段贴码的章很少,往后碰上用不着一块码的章,咱们就整章不贴。

排在实况后头的,是对照的一节:人家是怎么做的,咱们又为什么不做,两边的代价,您比着看。书里别处有的,指给您延伸。这套骨架对多数前部的章都成立,后半部的章有把实况与对照并进正文的,名目章里给您交代,您照着办就行。

章末的两节,本章留下了什么,收一段短的,末了附一张术语表。练一练给您备两三道,参考答案是跟在题后的。

还有一样记法是贯穿在章与章之间的:押票。上一章末尾押下的话,下一章开了卷就来兑,收卷的时候再清一遍,押为的是让您猜在前头、看在后头,猜错的地方记得牢,您跟着兑上两回,这套记法就熟了。

## 量法三条:码,屏,书

这一层的章,开讲实况之前咱们常报一句量法。咱们报的量法有三条:码、屏、书,每章的新家当都从里头取证据。码上长什么样,屏上怎么现形,书里人家怎么讲,三处都对上了,您才算真见过它。三条怎么取,口径是全层统一的,咱们在这里一并交代,后面的章就不逐条重立了。

### 码

**打头的是码。**概念讲完了,得进代码里验:每一章报的是自己数行号的实况锚,把您带到仓库的一个具体版本,本章的行号全按它数。走查的样子前头说过了,给您读码的指令,再给您按顺序的叙述。真要逐行精讲的,明说它讲的是节选,缩略掉的行写明缩了哪儿,免得您把它当成全本。

### 屏

**跟在后面的是屏。**读数出在自家的机器上:QEMU 起机的时候抄面板,GDB 把机器冻在您要看的那一拍,抄寄存器的读数。

长凳您往后常见:它跑测试的时候,抄的是案名。长凳这个叫法是正文叫开的,它是宿主上直跑的测试台,不着机器的边,宿主说的就是您写码跑测试用的电脑。

没有的屏不造:某一场戏当年只有串口上的话、没留下能誊的屏面,咱们引旧话、标出处。整章没有新屏的,开篇交代的就是零屏。屏面按代码推演的,咱们如实标注。

### 书

**收尾的是书。**咱们有几本常引的书。规格的一本,行话叫 CS:APP 的《深入理解计算机系统》,咱们引的是第二版。教学内核的一本是 xv6 的书,书名原文 `xv6: a simple, Unix-like teaching operating system` 咱们照录,MIT 那边 PDOS 组出的,页码按它的 riscv-rev5 版来记。用户面章程的一本,行话 TLPI 的《Linux/UNIX 系统编程手册》。快慢取舍的一本,行话 OSTEP 的《操作系统导论》,第 5 部块设备那章引过它讲设备的第 36 章。往后随章还有请场的,像第 5 部讲进程语义那章请的《Unix 环境高级编程》,名目咱们不在这里封死。

引文咱们逐字核过,整句给您摘出,页号给您写明,书里跨行断开的词拼回整词,您拿原句就能核。而没核过的书,咱们明说没核过:第 1 部第一章的对照节有一处 Linux 的落点,咱们到今天还让它空着,当年的原话是“咱们还没逐字核过文献,这块留白”。底下的章程是同一条:没核过的数不往书里写,核完了再补。

## 行号为什么锚在快照上

这部书有个别的书少见的难处:它引的代码是活的。您翻开正文,书每往前走一步的工夫,仓库就又多出了一截,函数挪了窝,行号全变了。行号要是按今天的主干数,过俩月就作废了一片,您对着一页书,在仓库里找不到那一行了。

所以这一层立了实况锚。锚是咱们打了名的快照,记着仓库在某个时刻的样子,名字里带着它管的那段事。每章开讲实况之前报出自家的锚,本章的行号全按它数,个别章一个章里换了锚的,章里当场给您交代。锚不动的话,书上的行号就不会老。

有的章还会在锚名后头带一个克隆的口径,章里自己会向您交代,您照着章里的办就行。

您那头的走法,写全的章在实况节开头交代,不重印的章给您指去前一章,照着那章的办就行,这里把通式给您摆一回。书里的代码住在 Cinux-Book 仓里,地址给您放在这儿:[github.com/Awesome-Embedded-Learning-Studio/Cinux-Book](https://github.com/Awesome-Embedded-Learning-Studio/Cinux-Book),您新克隆一个下来,下文的命令就能照着敲。切到锚的版本,您用 `git switch --detach` 加锚名。要切回您来的地方,您用 `git switch -`,它的脾气下头马上给您说。只看一个文件的时候,您用 `git show` 加锚名、冒号、文件路径,单文件就调到了眼前:

```
git switch --detach r01_mbr
git show r01_mbr:boot/mbr.cpp
git switch -
```

这些命令都是咱们实测过的,您照敲就行。`git switch -` 这一招有它的脾气:您上一步待在分支上的时候,它领您回那根分支,新克隆的仓里您从 main 切去锚、看完一敲,人就回到 main 了。可您连环切锚的时候,上一步待的是锚、是个提交,再敲它就给您报错,报的话是它要分支、拿的是提交。这会儿回家的路有两条:报分支的名,您敲 `git switch main`,或者您接着带 --detach 切下一个锚,末了您再照上头的法子回。新克隆的仓,落回的是 main,这也是各章实况节写明的。

锚在一层之内是允许换的,咱们管这个叫锅:几章共一个锚的,咱们叫它同锅,行号是能直接对着看的。各锚各的,咱们叫它不同锅,两边就不混着舀了。第 5 部的地界里,《文件与目录》《文件系统实现》《块设备与驱动》《终端与伪终端》四章数的是同一口锅,夹在里头的《崩溃一致性与日志》换了另一口。您也别跨章抄行号:每章只认自己报的锚,两章的数字对不上,是正常的事。

锚之外还有一条演进的口径。机制后来又长了,新章按当下的正身说话,当年的旧面貌进演进叙事,出处给您报卷名。正文没记、码里看出来的,咱们明说是码里看出来的,不往正文的嘴里放话。这样的交底每章都有,词句是不一样的,口径是一条:东西是谁的,就说是谁的。

## 题目怎么用,答案怎么读

每章的末尾都有练一练等着您,题给您备两三道,题名报的是题型。动手的,把命令给您,全是实测过的,您照敲。猜想的,押的是您抢在机器前头开口,猜的是机器会怎样,答对了答案里有读数,答错了读数更多。还有读屏的,机器跑起来的样子摆在题面里,您照着说门道。

咱们只有一句口径:您猜在前、机器在后的次序,末了对答案。第 1 部第一章收卷时留过一句劝的话,意思是光读不跑的话,这一章咱们就白走了一半。猜想题的价值就在猜错的那一下:错了,您才知道自己哪层模型跟机器差着半拍。对了,答案里的读数替您再核一遍。

参考答案是跟在题后的,您自己答完再翻。

判卷的标准卷没有,咱们给的是自己走一遍的实录:命令、读数、屏上几行、翻过的车,都在里头了。您拿它对数,交差的事它替不了。

## 从哪儿读起,往后怎么长

进门的路,咱们给您摆三条,条条是通的。

**您从头走起。**前置卷的书房与工具链两卷您读到位,您进正文,从开卷的第一个卷起一路往下走。教科书层您配着读,正文讲完了一个机制,您来这一层看它的深浅。这样走是最省力的,也是笔者心里的默认顺序。

**您缺哪就补哪。**您从正文半路进来,卡在了汇编、链接、调试这些家什上,回前置卷对应的卷。这一层讲到您没见过的机制,回正文对应的卷。卷名是互报的,路是通的。

**您只找深读。**您已经读过别的内核书,是专来这儿看深水区的,目录里怎么挑都行,您自己排个次序,每章开卷是自足的,难题是它自己立的,锚是它自己报的。想找点读的,第 1 部第一章是全书起步的地方。

路给您摆了三条,您挑哪条都行:这一层的章是开卷自足的,您从哪条路进来,都接得上正文的话。

五部的地界,咱们挨个报门:

- 第 1 部 机器:从一条指令的一生起,讲字节与栈、上电、模式切换、设备、中断、存储层次的事,收在内核镜像的两本护照上(同一颗内核的两种写法)
- 第 2 部 总论:内核态与用户态、中断与异常、系统调用、进程与上下文,末了是文件系统的脸(一套统一接口)
- 第 3 部 内存:地址空间、分页与 TLB、缺页与按需分页、物理内存、内核地址布局,末了是 Page Cache 与写回
- 第 4 部 并发:竞态与临界区、锁的实现、死锁与锁序、条件等待、信号的事,末了是内存序
- 第 5 部 持久化与使用侧:文件与目录、ext2、崩溃一致性、块设备、终端与伪终端,末了是进程语义的全景

这一层是没有长完的。第 5 部欠的是 VFS 与 socket 两样。再往后的日子,目录跟着正文的进度接着长。这层不抢正文的节奏:正文推进到哪儿、咱们攒下的东西够写成一章了,咱们才在这边动笔写成一章。

您过些日子再来,目录多半又长了几行。

## 这一章留下了什么

## 练一练

咱们出的三道题,都出在这部书自己的身上:您对一回锚、核一回书、找一处交底。

- **题一,对锚。**请您翻到第 1 部第一章,把它报的实况锚找出来,您拿 `git switch --detach` 切过去,在它引的头一个文件里,把一处行号当场就给对上了。末了再答两问:要切回您来的地方,敲哪一条?要是您在一个新克隆的仓里动手,切回来落的是哪儿?

- **题二,核书。**这一层的书证都写了页号。请您亲手挑任何一章引过的一句原文,您翻到那一页,一字一字地对一遍。对上了,这门书的量法您亲手验过一回。对不上的话,该记下哪三样?

- **题三,找交底。**交底是各章都有的,请您挑一处交底的原句,没有的屏不造的、没核的书不引的都算数,一字不改地抄下来。末了再答一问:这类句子在各章的词面不一样,底下的章程是同一条,您说是哪一条?

### 参考答案

题一:咱们对。锚名在章内实况一节的开头,第 1 部第一章报的是 r01_mbr,您拿 `git switch --detach r01_mbr` 切过去,它引的头一个文件是 `boot/mbr.cpp`,章里给的行号是文件名加冒号加行号,您在文件里一找就到。回来的时候敲 `git switch -`,切回您来的地方。新克隆的仓,落回的是 main,这也是那一章实况节写明的。

题二:这道题没有统一的读数,验的就是手艺本身。对上了,您核过的那句原句就是凭据。对不上的时候,您记下三样:章名、页号,还有书上的原句。三样都到手了,这桩书证该怎么处置,就按本章量法里说的口径办:谁核过的谁说话,没核过的空着。

题三:现成的在第 1 部第一章的对照节里,一处 Linux 的落点,当年的原话是“咱们还没逐字核过文献,这块留白”。底下同一条章程:引文咱们逐字核过才进书,没核过的明说没核过、空着,转述是冒充不了原文的。
