# 03 · 标号、跳转与 16 位初见,跳去哪里,以及十六位的一副面孔

读法那一篇的验收里,咱们把一段 `Sum` 读到了底,末尾留下两张没讲过的脸。`jne 20 <_Z3SumPKii+0x20>` 里,`jne` 说的是“不等就跳”,属于带条件的跳转,条件成立才动身。`jmp 2b <_Z3SumPKii+0x2b>` 里,`jmp` 什么条件都不看,一路跳过去就是了。

读法那一篇把它们标成了没读过的脸,这一篇就轮到它们了。咱们把标号、跳转,还有十六位那副截然不同的长相,一样样摆回机器码里看。

## 标号与伪指令都是写给汇编器看的行

以 `.` 开头的行跟机器码不沾边,它们是写给汇编器看的吩咐,咱们行话里管它叫伪指令。

标号是另一种小机关,`名字:` 记录的是“下一个字节的地址”,占用的字节数是零。咱们拿 `.global` 做个最见效的实验,把下面这几行写进 `lbl.s`:

```asm
.text
.global visible
visible:
    inc %eax
hidden:
    inc %ebx
```

```bash
as lbl.s -o lbl.o
nm lbl.o
```

```text
0000000000000002 t hidden
0000000000000000 T visible
```

您看 `nm` 交回来的两行,那是专门用来查符号的:大写 `T` 给了 `visible`,小写 `t` 归了 `hidden`。大写表示链接器也找得到,小写表示只有本文件找得到,`.global` 干的就是这件事,把名字递出门去。

这两行还有一处对得上:两条 `inc` 各占两个字节,`visible` 落在 0,`hidden` 落在 2,标号本身一格都没吃。`.text` 这个抽屉装的是代码,`.data` 装的是数据,`.section` 就是用来点抽屉名的(写 `.data` 就切去数据抽屉,再写 `.text` 就切回来)。咱们拿 `objdump -h` 把 `lbl.o` 的抽屉列表列出来:

```bash
objdump -h lbl.o
```

```text
Idx Name          Size      VMA               LMA               File off  Algn
  0 .text         00000004  0000000000000000  0000000000000000  00000040  2**0
                  CONTENTS, ALLOC, LOAD, READONLY, CODE
  1 .data         00000000  0000000000000000  0000000000000000  00000044  2**0
                  CONTENTS, ALLOC, LOAD, DATA
  2 .bss          00000000  0000000000000000  0000000000000000  00000044  2**0
                  ALLOC
  3 .note.gnu.property 00000030  0000000000000000  0000000000000000  00000048  2**3
                  CONTENTS, ALLOC, LOAD, READONLY, DATA
```

表里的四行咱们一行不落:`.text` 住代码,`.data` 住数据,空着的 `.bss` 交给以后,末尾那行 `.note.gnu.property` 是编译器捎带来的。贴全了,您自己就能数清 `objdump -h` 认得的这几格。

您要是看见 `objdump -d` 只吐了个文件头,那就是文件里根本没有代码,没有 `.text` 就没有可反汇编的,东西多半住进了 `.data`。

数字标号走的是另一条路,`0:` 和 `1:` 允许咱们在一个文件里反复定义,它们本来就是给一次性的跳转准备的。回引的时候,`0b` 说的是“往回找最近的 `0:`”,`0f` 说的是“往前找最近的 `0:`”,字母管方向,数字管名字。这一篇里咱们让 `f` 那一半真跑起来,`b` 那一半是它照镜子的写法,报错桩里还会再见它一次。

## 近处的 `jmp` 和 `call` 把距离装进字节

近处的 `jmp` 和 `call` 装进字节的是距离,说的就是“往下一条指令之后再数多少格”。其中 `call` 跟 `jmp` 不一样,它是“叫一个子过程,回来接着走”的跳,动了身还要记着回程。咱们把三种近形态写进 `jmp.s`,让它们出场:

```asm
.text
top:
    inc %eax
    jmp top
    call top
    jmp 1f
    inc %eax
1:  ret
```

```bash
as jmp.s -o jmp.o
objdump -d jmp.o
```

```text
0000000000000000 <top>:
   0:	ff c0                	inc    %eax
   2:	eb fc                	jmp    0 <top>
   4:	e8 f7 ff ff ff       	call   0 <top>
   9:	eb 02                	jmp    d <top+0xd>
   b:	ff c0                	inc    %eax
   d:	c3                   	ret
```

您把 `fc` 当普通数字读,算出来的是 252,可 `jmp top` 要跳回去的地方,离它不过几个字节。

`fc` 只占一个字节,机器按无符号读它,读出来是 252,按带符号读它,读出来是 -4。基准落在指令结束的地方,也就是下一条指令的地址:编码是 `eb fc`,两个字节,下一条指令的地址在偏移 4,目标是偏移 0 的 `top`,拿目标减去下一条指令的地址,`0 − 4 = -4`,这就是位移。反过来验一遍,下一条指令的地址加上位移,`4 + (-4) = 0`,正好落回 `top`。两式您拿着输出都能复算。也就是说 `jmp` 存的是“离这里多远”,没有人真去记那个地址长什么样。

`e8 f7 ff ff ff` 编的是 `call`,咱们看这串字节,里面有四个在装 32 位的位移,`call` 和 `jmp` 都按这一套算。它俩的差别不在这几个字节上,在于 `call` 顺手把回家的地址记在了栈上,那口栈是下一篇专门要看的东西,`jmp` 跳过去就不管回程了。

往前找的 `jmp 1f` 编出 `eb 02`,正跨过挡路的 `inc %eax`。目标在哪儿,`objdump` 也用尖括号在原行末尾标了出来,您顺着那个 `d <top+0xd>` 就能一路对到偏移 `d` 上的 `ret`。

条件跳转是一整家人,行话里咱们统称它们 `jxx`:`jne` 是不等就跳,`je` 是相等就跳,`jle` 是不大于就跳。名字后面的 `e` 是 equal,`ne` 是 not equal,`le` 是 less or equal,一家人共用同一套后缀。它们的正身在验收那段 `Sum` 里就露过面,`jne 20` 没到头就往回跳。

## 远形态的 `ljmp` 把两个立即数一起装走

远形态的 `ljmp` 咱们留到最后一件讲,它要的是段和偏移两个立即数(段是 16 位时代寻址的另一半,细节留到正文讲实模式的那一篇再还)。咱们把它写进 `far.s` 看看:

```asm
.code16
begin:
    ljmp $0x0000, $begin
```

```bash
as far.s -o far.o
objdump -d -M i8086 far.o
```

```text
0000000000000000 <begin>:
   0:	ea 00 00 00 00       	ljmp   $0x0,$0x0
```

咱们再换一组能分辨出谁是谁的取值,写进 `far2.s` 来看,书写的次序是段在前、偏移在后:

```asm
.code16
begin:
    ljmp $0x4321, $0x0007
```

```bash
as far2.s -o far2.o
objdump -d -M i8086 far2.o
```

```text
0000000000000000 <begin>:
   0:	ea 07 00 21 43       	ljmp   $0x4321,$0x7
```

源码写着 `$0x4321, $0x0007`,反汇编回来的那一行还是 `$0x4321,$0x7`,`objdump` 跟书写一样,都是段在前、偏移在后,它没有翻次序。真正调了个个儿的是字节内部:`ea` 之后是 `07 00`,也就是偏移 16 位,再往后才是 `21 43`,段 16 位。上一组输出里两个数都是 0,本来分辨不出谁是谁,咱们看它只看形状。

递上去的 `-M i8086` 是给 `objdump` 换的一副眼睛,让它按 16 位读,它才肯把这串字节念成一条完整的指令。它跟后头那个递给 `gcc` 的 `-m16` 不是一码事:`-M i8086` 只管读的工具,`-m16` 管的是让编译器生成 16 位的码,两件工具上的两个选项,咱们分头认。眼下对这个远形态咱们只求认得脸。

## 64 位默认与 `.code16` 编出的两种尺码

这几条伪指令里,`.code16` 最值得咱们当场验,它跟汇编器说的是“接下来的指令按 16 位编”。同一行 `mov %ax, %bx`,咱们写两份,一份让汇编器按默认的 64 位编,存成 `plain.s`:

```asm
.text
mov %ax, %bx
```

另一份把 `.code16` 顶在头上,咱们存成 `sixteen.s`:

```asm
.code16
mov %ax, %bx
```

```bash
as plain.s -o plain.o
as sixteen.s -o sixteen.o
objdump -d plain.o
objdump -d -M i8086 sixteen.o
```

下面两小块,是上面两条 `objdump` 各自的产出,咱们并排摆着对照:

```text
0000000000000000 <.text>:
   0:	66 89 c3             	mov    %ax,%bx
```

```text
0000000000000000 <.text>:
   0:	89 c3                	mov    %ax,%bx
```

咱们对比着看:64 位默认下 `mov %ax, %bx` 编出的是 `66 89 c3`,带上 `.code16` 就缩成了 `89 c3`,`66` 前缀省下了。16 位那边的编码本来就正常,是咱们的眼睛需要多一副 `-M i8086`,`objdump` 才读得对。

清零在 16 位的底下有两种写法,咱们写进 `zero.s`,各编一条:

```asm
.code16
xor %ax, %ax
mov $0, %ax
```

```bash
as zero.s -o zero.o
objdump -d -M i8086 zero.o
```

```text
0000000000000000 <.text>:
   0:	31 c0                	xor    %ax,%ax
   2:	b8 00 00             	mov    $0x0,%ax
```

省出一个字节的是 `xor`,它也成了老手们的心头好,读法那一篇里那段 `_start`,清零用的多是这一招。咱们自己也能让 GCC 说起 16 位的话。写一个最小的 C 函数存成 `m16.c`:

```c
int f(void){return 1;}
```

咱们把 `-m16` 递给它,它吐出来的汇编里就有一行 `.code16gcc`。

```bash
gcc -m16 -S m16.c -o m16.s
head -5 m16.s
```

```text
	.file	"m16.c"
	.code16gcc
	.text
	.globl	f
	.type	f, @function
```

下面还有 `f:`、函数序言的两条真指令 `pushl %ebp` 与 `movl %esp, %ebp`,以及一串随 GCC 版本变动的 `.cfi_*`,咱们就不贴了。

`-m16` 吐出来的头几行里,`.code16gcc` 排在第二行。它跟 `.code16` 是同一类吩咐,都是叫汇编器按 16 位编,寻址方面的默认写法另有差别,那一步咱们暂时用不到,也就不往深处追了。

## 同一串字节的两副眼睛,一场骗局和一桩报错

16 位的码,默认 64 位的眼睛读起来会出岔子,咱们挨个看。骗得最安静的是头一种,同一串 `89 c3`,按 64 位读回来是这样:

```bash
objdump -d sixteen.o
```

```text
0000000000000000 <.text>:
   0:	89 c3                	mov    %eax,%ebx
```

它看着有模有样,却是一条完全不同的指令:`mov %ax,%bx` 被念成了 `mov %eax,%ebx`,一个字母的差别,搬的东西从 16 位宽成了 32 位。您要是没留神,就这么照着读下去了。

另一种岔子报得就难看了。前面 `far.s` 编出来的码,开头的 `ea` 在 64 位里根本不成指令,`objdump` 直接给您打出了 `(bad)`:

```bash
objdump -d far.o
```

```text
0000000000000000 <begin>:
   0:	ea                   	(bad)
   1:	00 00                	add    %al,(%rax)
	...
```

两份读错的根子是同一个:同一串字节换副眼睛就换个意思。读别人的 16 位码之前,咱们手里这副眼睛是哪一位的,值得弄清楚,`-M i8086` 一递,两份就都正常了。

往回找的 `b` 也有桩当场碰得上的报错。您要是把 `.text` 摆在头一行、`jmp 1b` 摆在第二行,存进 `t2.s`,而它要找的 `1:` 并不存在,`as` 就回您:

```bash
as t2.s -o t2.o
```

```text
t2.s: Assembler messages:
t2.s:2: Error: backward ref to unknown label "1:"
```

它连产物都不肯出。您在前头补一个 `1:`,`jmp 1b` 就找得到它了。或者把方向改成 `f`,再把 `1:` 补到后头去,让它往前找。

## 16 位这一刻,到此为止

16 位是 x86 从 16 位起步的那个年代留下的尺码,寄存器窄、地址分两半,后来才一路长到 32 位、64 位。咱们这一卷的主线是 64 位,见它一面,是为了日后翻那些老书和老引导码的时候,认得出这副面孔。

`.code32` 和 `.code64` 两条伪指令,还有保护模式那一整套系统指令,用场都在保护模式的那边。机器怎么从实模式切进保护模式,咱们留给讲计算机怎么工作的那一卷。至于 `call` 记在栈上那个回家的地址,就得看下一篇了。
