# 02 · 实模式与段寻址:两个 16 位数,凑出一个 20 位地址

跟着上一篇那次 `ljmpw` 落下来,咱们这回停在实模式里看清楚。复位那一刻的 `CS` 长什么样,上一篇已经摊开过了:它拆成两半,选择子和隐藏基址。咱们这会儿要记的是那两半的关系,因为在复位那一刻,基址这一半还不按老算术来。

一次远跳罢了。咱们跳过去之后,让模拟器再报一次 `CS`:

> CS =f000 000f0000 0000ffff 00009b00

基址从 `FFFF0000` 换成了 `0x000F0000`,而 `0xf000 × 16` 正好就是这个数,选择子 `f000` 一动没动。上一篇那次跳之前,这同一条乘法管不着它。往后咱们要用的,就是跳完之后这个按老算术算出来的基址。

## 两个 16 位数,凑出一个 20 位地址

这一段别扭算术为什么存在,得从位数说起。实模式里咱们手上的寄存器是 16 位的,一个数最大 65535,也就是 64KB 见方的一块。8086 的地址线却有 20 根,能摸到 1MB。16 位的寄存器够不到 20 位的地址,设计者的办法是把地址写成两半,段和偏移,各自装进一个 16 位寄存器,合起来算物理地址。公式是一句乘法加一句加法。

咱们拿 BIOS 交棒那个地址真的排一遍,两半各来一次。头一家,段 `0000`、偏移 `7C00`:`0x0000` 乘 16 还是 0,加上 `0x7C00`,得到 `0x07C00`。再看另一家,段 `07C0`、偏移 `0000`:`0x07C0` 乘 16,十六进制里乘 16 就是往左挪一位、低位补零,于是拿到 `0x7C00`,加 0 还是 `0x07C00`。两家的写法完全不同,落点却是同一间房子、同一个门牌。

同一间房子往往不止两个门牌。咱们再挑一个地址,`0x07D00`,把它的算式一位一位摊开:

```text
0x0000*16 + 0x7D00 = 0x0000 + 0x7D00 = 0x07D00
0x06C0*16 + 0x1100 = 0x6C00 + 0x1100 = 0x07D00
0x07C0*16 + 0x0100 = 0x7C00 + 0x0100 = 0x07D00
```

段加 1,偏移就减 16,算式里的两半换了个写法,落点却原地不动。于是任何落在某个段 64KB 窗口里的物理地址,平均都凑得出四千种左右的写法。咱们挑两个地址,把算式一行一行列出来,您拿纸笔照着表里的排法各算一次:左半乘 16,右半相加,每一行的和都该落回那一行顶上写着的老地方(这一段是照算式排的版,不是模拟器的哪一屏输出):

```text
物理地址 0x07C00
    0000:7C00    0*16 + 7C00 = 0000 + 7C00 = 07C00
    0001:7BF0    1*16 + 7BF0 = 0010 + 7BF0 = 07C00
    0002:7BE0    2*16 + 7BE0 = 0020 + 7BE0 = 07C00
    0003:7BD0    3*16 + 7BD0 = 0030 + 7BD0 = 07C00
物理地址 0x07D00
    0000:7D00    0*16 + 7D00 = 0000 + 7D00 = 07D00
    0001:7CF0    1*16 + 7CF0 = 0010 + 7CF0 = 07D00
    0002:7CE0    2*16 + 7CE0 = 0020 + 7CE0 = 07D00
    0003:7CD0    3*16 + 7CD0 = 0030 + 7CD0 = 07D00
```

咱们想让段再往上走也行,不过得留个心眼:偏移那一半是个 16 位的数,减到 `0x0000` 就到头了,再往下减就会在 16 位里回绕成 `0xFFF0`,算式也就对不上了。所以一个物理地址能凑出的写法是有限的,能凑多少,看的是它离地址 0 有多远,顶到四千。

再往下有两条推论,咱们得拿到手上。一件:一段最多管 64KB。咱们把段定住、让偏移随便跑,可偏移是个 16 位的数,顶到 `0xFFFF` 就到头了,想摸更远的地方只能换段。段与段之间还咬着:段 `1000` 从 `0x10000` 起到 `0x1FFFF`(含),段 `1010` 从 `0x10100` 起到 `0x200FF`(含),中间 `0x10100` 到 `0x1FFFF` 这一段两家都管得着。

另一件:20 根线封了顶。咱们把段和偏移都顶到 `0xFFFF`,算下来是:

```text
段顶 0xFFFF、偏移顶 0xFFFF:0xFFFF0 + 0xFFFF = 0x10FFEF
超出 1MB 的部分:0x10FFEF - 0x100000 + 1 = 65520 字节(= 0xFFF0 = 64KB 差 16 字节)
第 21 根地址线(A20)一关,0x10FFEF 就绕回 0x0FFEF
```

多出来的是 65520 字节,离 64KB 只差 16 字节。这么一小截后来有个名字叫 HMA,咱们想拿到它,得让 A20 这根线点头。

## 机器上撞一次:三个门牌,一个字节

算术的底细铺完了,该让机器自己回答。咱们搓一枚 512 字节的扇区,在文件偏移 `0x100` 的位置埋一个字节 `0x5A`,那个位置折成物理地址是 `0x7D00`。三次调用都进同一个子程序,三次之间变的只有 `DS:SI`。下面这几行是 `objdump -D -b binary -m i8086 -Mintel` 反汇编出来的,而且只留了指令那一列,地址列和字节列都没抄进来,不是源码里写的原样:

```asm
    mov ax,0x7c0
    mov ds,ax
    mov si,0x100
    call 0x36
    mov ax,0x0
    mov ds,ax
    mov si,0x7d00
    call 0x36
    mov ax,0x6c0
    mov ds,ax
    mov si,0x1100
    call 0x36
```

镜像搓好之后,咱们拿 `xxd -s 0xfc -l 8 segment.bin` 核一下,它真的躺在文件里:

```text
000000fc: 0000 0000 5a00 0000                      ....Z...
```

咱们把它跑起来,模拟器往调试口上打了三个字节:

```text
$ qemu-system-i386 -drive format=raw,file=segment.bin,if=floppy -boot a -display none -debugcon stdio -no-reboot
5a 5a 5a 
```

`07C0:0100`、`0000:7D00`、`06C0:1100`,三次读回来的都是同一个 `0x5A`。咱们只换了段寄存器和偏移,取数的动作从头到尾一模一样。这也就解释了咱们的引导代码为什么能有那么多种段:偏移写法,它们指的本来就是同一个位置。

## 20 根线:地址够不到,就绕回来

8086 身上只有 A0 到 A19 这 20 根地址线,超过 1MB 的那截地址没有对应的地方可去,只能绕回 0。IBM 的 AT 为了兼容当年故意用回卷取数的程序,给第 21 根线单独装了个门,复位时把它拉低。“A20 默认关着”这句话说的是复位默认态。咱们自己写的镜像在模拟器里把它读一遍,看到的会是另一个样子:`0x92` 端口读回来是 `02`,monitor 在复位那一刻就报 `A20=1`。到引导扇区开始跑的时候,固件早就把这根线打开了,这两句咱们必须分开写,免得您照着书去机器上查,当场对不上。

门装在那儿,咱们可以亲手关一次看结果。下面七个读数是同一趟运行里打出来的,第一个就是端口 `0x92` 的原值:

```text
$ qemu-system-i386 -drive format=raw,file=a20.bin,if=floppy -boot a -display none -debugcon stdio -no-reboot
02 00 00 00 53 00 53
```

咱们按打出它们的顺序读一遍。头一个读数是端口 `0x92` 的原值。下面一个,A20 开着的时候读 `FFFF:0010`,也就是物理地址 `0x100000`,读回来是 `00`。再下面一个,把 `0x92` 的 bit0 清掉再读,还是 `00`。跟着把端口还原,又回到 `00`。再改清 bit1,读回来的字节变了。然后把端口还原一次。最后一个,直接读 `0000:0000`,也就是物理地址 `0x00000`。

第五格那个 `53` 和第七格一模一样。地址 `0x100000` 并没有够不到,它是被拉回了 `0x000000`,咱们读到的就是那个位置上原本躺着的字节。清掉 bit0 那一次,读数一动没动,清掉 bit1 它才变。两个数摆在一起,门控位是哪一位就不用猜了。第四格和第六格的还原是这次实验的自证:变的确实是 `0x92` 的 bit1,不是别的东西顺手改了内存。

咱们认定门控位的时候,看的是屏上打出来的七个读数:管着这根线的是 `0x92` 的 bit1,bit0 是另一个用途,叫 fast reset,碰它之前最好确认它是 0。这与 OSDev 的 Fast A20 写法(`or al, 2`)对得上,而网上常见的说法“bit0 管 A20”站不住。

## 低 1MB 的地板

咱们从 0 看到 `0xFFFFF`,整段地址并不是一片空地,上面排着一屋子老住户。最底下 1KB 是中断向量表,`int` 指令一来,CPU 就按中断号翻到表里对应的一格,读到地址、跳过去。往上一小块是 BDA,BIOS 自己的记事本。再往上到 `0x9FFFF` 是常规内存,咱们的引导扇区会被塞进 `0x7C00` 起的 512 字节里。`0xA0000` 起是显存,再往上留给各种 ROM。哪一段归谁,各地固件会挪动位置,不归 x86 定。

这些住户不是咱们从某张图上背下来的,是机器自己写在内存里的。咱们到 `0x0000:0013*4` 这个位置读四个字节,也就是从 `0x004C` 起,那是段 `0000`、偏移 `004C` 算出来的物理 `0x4C`:

```text
$ qemu-system-i386 -drive format=raw,file=ivt.bin,if=floppy -boot a -display none -debugcon stdio -no-reboot
e3fe:f000 027f 9fc0 4227 03
```

这屏咱们印了五格,挨着读下来是:第一格就是 `int 0x13` 占用的向量的偏移 `e3fe` 和它的段 `f000`,两者合起来四个字节。后面四格是 BIOS 记在 BDA 里的别的事,跟咱们眼下要看的东西无关。排法要留意一下,一格里面挨着下来的是偏移和段,跟咱们写 `段:偏移` 的顺序正好倒过来。咱们把它们按老算术折一遍:`0xF000*16 + 0xE3FE = 0xFE3FE`,这个落点在低 1MB 最顶上那 64KB 里,是 BIOS ROM 那一带。BIOS 的代码住在那儿,而咱们就是从 `0x004C` 起的四个字节里读出它的。

咱们再看看 ROM 从哪儿起、到哪儿止,固件之间会挪。顺手问一句 monitor,在它的控制台上敲一句 `info mtree -f`,它会把模拟出来的主板怎么切地址空间摊开给您:

```text
  0000000000000000-000000000009ffff (prio 0, ram): pc.ram
  00000000000a0000-00000000000bffff (prio 1, i/o): vga-lowmem
  00000000000c0000-00000000000dffff (prio 1, rom): pc.rom
  00000000000e0000-00000000000fffff (prio 0, rom): pc.bios @0000000000020000
  0000000000100000-0000000007ffffff (prio 0, ram): pc.ram @0000000000100000
  00000000fec00000-00000000fec00fff (prio 0, i/o): ioapic
  00000000fed00000-00000000fed003ff (prio 0, i/o): hpet
  00000000fee00000-00000000feefffff (prio 4096, i/o): apic-msi
  00000000fffc0000-00000000ffffffff (prio 0, rom): pc.bios
```

咱们看 RAM 在哪儿收住,`0x9FFFF` 到头,`0x100000` 往上又是 RAM。第四行说的是:同一份固件被映在两个地方,低端 `0xE0000` 到 `0xFFFFF` 有它。末行再报一次高端:`0xFFFC0000` 到 `0xFFFFFFFF` 还有它。所以 `0xFFFF0` 与 `0xFFFFFFF0` 会读出同一串字节(前面那一篇就拿 `xp` 读过这串字节),复位向量蹲在 4GB 顶端这件事才不至于像是笔误。咱们读到的这一屏,说的是模拟出来的机器怎么切地址空间,不是 x86 的规范条文。

## CS 的两半

六个段寄存器各有各的差事。`CS` 装代码段,取指令跟着它走。`DS` 装数据段,咱们读写内存默认找它。`SS` 配上 `SP` 组成栈。`ES` 给串操作和 BIOS 服务当帮手。剩下 `FS`、`GS` 是 386 加进来的两个空位,实模式里咱们用不上。这一层讲到各自管住一段就够,保护模式怎么用它们,后面另开一篇。

复位时 `SS`、`DS`、`ES`、`FS`、`GS` 的选择子和基址都是 0,只有 `CS` 例外:它的基址在那一刻还不按选择子乘 16 算,而是 `FFFF0000`。上一篇读到的就是它。它为什么这么怪,以及手册写明的那句“复位之后 `CS` 第一次装进新值时就回到寻常规则”,上一篇都交代过了。往后它就归老算术管,咱们前面读到的 `CS =f000 000f0000` 就是个例子。

能改 `CS` 的只有段间转移那一类指令,远跳、远调用都算,一次中断也能把它换掉。`DS` 不一样,您写一句 `mov` 它就换了。想直接写 `CS`,拦您的是 CPU,不是汇编器。咱们另搓一枚扇区,跟前面埋 `0x5A` 那枚不是同一枚。这一枚动手之前打一个 `A`,接着两条指令把 `ax` 清零、再把它送进 `cs`,然后打 `B`、`C`。`as` 把它照单收下,反汇编出来是:

```text
   f:	b0 41                	mov    al,0x41
  11:	e8 12 00             	call   0x26
  14:	b8 00 00             	mov    ax,0x0
  17:	8e c8                	mov    cs,ax
  19:	b0 42                	mov    al,0x42
  1b:	e8 08 00             	call   0x26
```

编过、链接过、镜像也搓出来了,可咱们把它在模拟器里跑起来,调试口上只落下来一个 `A`:

```text
$ qemu-system-i386 -drive format=raw,file=cs_trap.bin,if=floppy -boot a -display none -debugcon stdio -d int -D qemu-int.log -no-reboot
终端上落下来的字符:[Aqemu-system-i386: terminating on signal]
```

`B` 和 `C` 再也没出来,机器执行到 `8e c8` 这行编码的时候就抛了异常。更麻烦的是这个异常被反复投递,模拟器陷在里面出不来,`-d int` 的日志能涨到几百 MB。您真要复现,记得给模拟器带上 `timeout`。要在日志里数它被投递了多少次,就把 `-d int` 接成文件再拿 `grep -c` 数,别让它直接灌满终端。读 `CS` 是合法的,`mov %cs, %ax` 编成 `8c c8`,一点问题都没有,不许的是往它里面写。

## 双视角锚点:地址到底在哪

同一件事,咱们让两个人分头来看。

咱们来看应用程序员这一边。他盯着自己的程序看,`&x` 打出来是一个数。这个数单调地指向那个对象,他这辈子都不会遇上同一个地址有两种写法。低端那一截地址空间他也不去想,进程看到的地址跟物理低端本来就不是一回事。地址在他眼里就是一个数,越平越好。

轮到内核作者,这套算术得您自己扛。您拿起 `0x7D00`,它其实是一对数的运算结果,而且这一对不唯一。您写引导代码的时候得同时管段寄存器此刻指着哪、偏移是多少,也得知道低端那 1MB 里挤着中断向量表、BIOS 的记事本、显存和各种 ROM,自己那 512 字节只是借住在 `0x7C00`。地址在您手里是一套得自己算的算术,算错了没有第二个人替您兜着。

咱们还得提醒一句:这回读到的行为分两类。前面已经交代过,复位基址与第一条指令的落点是 Intel 手册写明的,换到真正的 x86 硬件上也该照样出现。另一类是模拟出来的机器自己的做法:把固件在低端再映一份、用 `0000:7C00` 交棒,还有 `0x92` 的哪一位管 A20 这一类硬件细节,换固件、换机型都可能不一样。手册里的复位态是一回事,模拟器怎么兑现是另一回事,咱们别把它们混成一句。
