# 05 · 编辑器最小生存:开、写、存、走,外加被拦下的那一下

您手上有一份要改的东西,它这会儿就摊在屏幕上了。那是您前些天存下的一份配置,里面有个数字写错了位置,您想把它挪回来。前几天您还敲顺过一条长命令,今天记不全了,您想把它存成一份文件,下回您直接喊它出来。咱们把这两样都 `cat` 出来看过,一行一行摊在屏幕上了,可 `cat` 的活儿只是把内容往外读,咱们没法靠它写回去一个字节。

咱们其实有别的办法能往文件里塞东西。重定向干的就是这件事:`>` 的用处是把一整份内容覆盖过去,`>>` 的用处是往尾巴上追加一行。可那是整个换掉的一套路子,您想改的是中间某一个字,这就是重定向干不了的活。咱们真想动它,总得请一个能在终端里写字的家伙。

上一篇临走的时候留下一句,说轮到编辑器了,咱们这篇要认的就是两样:终端里的 `vim`,和装在 Windows 那一侧的 VSCode。咱们从 `vim` 开始,多数的 Linux 上都带着它,您多半不用另外去装。它的活不多,您要办的就四步:开、写、存、走。您把这四步走完,脚下就会多出一个自己造出来的文件,里面躺着您亲手敲进去的字。中间还会多出您没料到的一下:您改完东西想走的时候,它会把您拦下来问一句。那一下咱们留到后头细看。

## 它为什么这么“怪”:您敲的字,它当命令听

刚进去的那一下,您多半会以为它坏了。咱们敲下 `vim demo.txt`,屏幕上跳出来的是一张几乎空着的脸,上面一大片都是空的,左边一列 `~` 从顶上排到了底(这个波浪号跟您家目录那个不是一回事,它只是占着还没有内容的行)。咱们试着把 `hello` 敲进去,屏幕却不肯把咱们敲的字好好排出来,字迹落到了没指望的地方,光标自己也乱跳了起来。咱们敲下去的那些字母,一个都没排成您想要的那一行。

咱们手边那本讲命令行的书里讲过这件事,是把它跟怎么退出并排放在一处的,说这是学 vim 第二重要的一件事,它是个靠模式说话的编辑器。您一进去,站在的就是命令模式,您敲的几乎每一个键都是一条命令。您拿它当记事本使,它就真把您敲的每个字母都当命令执行了一遍,屏幕当然会乱。要写字的时候,咱们得敲一个 `i`,敲完人就进了插入模式。写完了以后,咱们按一下 `Esc`,就把话交还给命令模式了。

按书里的说法,进了插入模式以后,屏幕底部会为您亮出一行 `-- INSERT --`。那行提示干的是告示牌的活:这会儿您敲进去的字算内容,就算不上命令了。您哪天看见它不在,您手里又敲不出字来,那多半就是人已经回到了命令模式。

vi 是 1976 年出生的,那会儿的终端常常连方向键都没有,所以键位被安排成让熟练的人手不离键盘也能挪动光标。您今天觉得别扭的那几个字母,就是那时候留下来的。您要是问名字,咱们敲 `vi` 还是敲 `vim`,打开的通常是同一个东西:多数发行版并不带真正的老 vi,它把 `vi` 这个名字指到了 vim 身上。光标您就拿键盘上的方向键用,咱们这儿不折腾。`h`、`j`、`k`、`l` 那一套是老终端没有方向键时的替身,咱们这一篇用不着它们,您想试随时可以试。

## 开、写、存、走:四步走完一圈

打开和新建干的是同一件事,您只要在命令后面跟一个名字就成。咱们拿 `demo.txt` 走这一趟。下面引文里的每一句回话,都是笔者自己机器上留下的。数字跟着里头的内容走,您那儿跟这儿对不上是很正常的。

```bash
vim demo.txt
```

屏幕上立刻回您一行:

```text
"demo.txt" [New File]
```

您看见这行小字头一次跳出来,是要愣一下的。它怎么知道这文件本来不在?方括号里那句 `[New File]` 说的就是这件事:这个名字底下本来是空的,是您刚才那一下把它编出来的。咱们再认一下左边那列 `~`,它占着的位置,都是还没有内容的行。

> 这是 vim 的习惯:说存盘、说读档的时候,它都会把文件名带上了,您同时开着好几份文件的时候,一眼就认得出这话是说谁的。

接下来轮到写字了。咱们敲一个 `i` 进插入模式。您把 `hello vim` 敲进去,写完了按一下 `Esc`。顶容易忘的就是这一下,忘了的人常常接着往下敲,敲出来的东西就全成了命令。

存盘也是一句话的事:咱们在命令模式敲一个冒号,后面跟的是 `w`,敲完回车它就开始写盘了。您这一下存的是整个文件,它会把写进去多少如实报给您:

```text
"demo.txt" [New File] 1 line, 10 bytes written
```

它报给您一行、10 个字节,就是 `hello vim` 那 9 个字符加上尾巴的那个换行。您什么也没写就存,它也一样放您过去,报给您的一句是 `"demo.txt" [New File] 0 lines, 0 bytes written`。

> 存盘这句确认是跟着版本走的。书里那版 vim(8.0.707)报的是 `1L, 46C written`,数的是行数和字符数。笔者自己机器上跑的是 vim 9.2,报的就是您上面看到的 `1 line, 10 bytes written` 那一行。您机器上是哪一版,以它当场念的为准。

只存不走走的是同一条路:您敲 `:w` 再回车,它给您的还是 `:wq` 时那一行,只是您人还留在文件里。

```text
"demo.txt" [New File] 1 line, 10 bytes written
```

您一敲 `:wq`,它就会把您上面看到的那行又报一遍。有写盘动作的时候它就会出声,裸敲 `:q`、什么也没改的时候,它就一声不吭了。

写完了,走的时候咱们敲 `:wq` 再回车。`w` 帮您存,`q` 帮您走,一条命令就办了两件事,您又回到了那个熟悉的提示符前面。什么也没改的时候,您裸敲一个 `:q`,它也放您走。改过了东西还想裸敲 `:q`,那就等着后头那一段了。回头您再打开它,方括号没了,它换了一副口气:

```text
"demo.txt" 1 line, 10 bytes
```

这回它报的是“本来就有,这么大”。您把它跟 `[New File]` 摆在一起看最清楚:一个说这名字底下本来是空的,一个是报它本来就有、里面是这么多。

咱们从 vim 里退了出来,眼前又是那个熟悉的提示符了,活儿却真的留下了。想确认的时候,您敲一句 `ls` 看一眼,名单里多的就是 `demo.txt`。

> 万一您不知道自己这会儿在哪儿、敲什么都乱,您就连按两下 `Esc`。书里给的救命键就是这两下 `Esc`:迷路了,您按两下,人就能找回来了。

## 改完想走,它拦了您一下

现在咱们故意犯一次错。咱们打开 `demo.txt` 往里头敲进一行字,存盘的念头还没转完,人就想走了。咱们敲下 `:q`,敲完了回车,它偏偏没走,屏幕底下给您留下了一行:

```text
E37: No write since last change (add ! to override)
```

这一行跳出来的时候,人是会冒火的:“我就是要走,你拦我干什么?” 您把火按下去再看,它其实把修法直接写在脸上了:`add ! to override` 说的是加一个 `!`。前面那个 `E37` 是 vim 给报错编的号,后面那半句的意思,说的是上次改动之后没有写过盘。

咱们说“我要走”的那一刻,它挡了一下,问的是同一件事:刚改的那点东西,您确定不要了?它给咱们兜着的是安全网,不是来报故障的。

而且它不会自己收场。您敲完了键,它就停在那儿等着您,不会替您退出,得您自己动手。

咱们要是舍不得刚改的那点东西,出口也是留着的:您敲 `:w` 把它存住,您人还留在文件里,您接着敲 `:q`,这回它放咱们走了。

两个相反的走法到这儿就分清了。`:wq` 是存完了再走,`:q!` 是我确定不要了。您敲下 `:q!`,它一声不响把您放回 shell,也就是咱们认过的那个 bash,黑框里一直听您说话的程序。它照办了,这一回的改动也就真的没了。咱们改一行配置、扫一眼写错的地方,存了就走,`vim` 干的正是这个活。咱们改了东西还没写盘、人就想往外走的时候,它才拦咱们一下。

## 正经干活的那条道:把 VSCode 接到 Linux 这一侧

上面那一套够您顺手改东西了。您真正坐下来干活的时候,还有另外的一条路:VSCode,一个装在 Windows 那一侧的图形编辑器。它和 vim 是各管一头的,vim 是住在 Linux 里的,它却装在了 Windows 那一侧。VSCode Remote 的用处,就是把 VSCode 的窗口接到 Linux 这一侧的目录上来,让 VSCode 里那些干活的插件跑在 Linux 这一侧。这一整段照的是官方那篇教程,它的名字是 Remote development in WSL。

笔者翻这篇教程的时候,它开头摆的就是一个难题:人是在 Linux 这一侧干活的,手上要么是终端里的 vim,要么从 Windows 那一侧绕过去,顺着 `\\wsl$` 那个挂载点编辑您的文件(Windows 的资源管理器里能直接翻 Linux 的文件,走的就是这么一条口子)。文档嘴里的“远端”,说的就是 Linux 这一侧。

它把从 Windows 那一侧绕过去的走法讲得很直:Python 的运行时(跑 Python 程序要用的那一套东西)、装 Python 包的 `pip`,这些东西都是装在 Linux 里的,您人坐在 Windows 那一侧编辑它们,跑也跑不起来了,调也调不动了。您真想让它跑得动,那就得在 Windows 上再搭一套一样的家伙,那您这套隔离出来的 Linux 环境就白搭了。

笔者在文档里看到的前提,是您机器上得装好 VSCode。它的全名是 Visual Studio Code。

咱们跟着文档往下走。咱们头一件事是在 VSCode 里装上 WSL 扩展(它就是 VSCode 里的一个插件),这一篇说的 VSCode Remote,走的就是这个扩展铺出来的路。装好了之后,您会在状态栏最左边看到一个 Remote 项,那就是这个扩展留下的,点它能调出这个扩展带来的命令,那个项也会告诉您,您手上的 VSCode 这会儿跑在哪一侧。

文档里最要紧的一步在这儿:在 Linux 这一侧的终端里,咱们站在要干活的目录下敲一句

```bash
code .
```

咱们照文档的说法试一下。那个点的用处是把您当前所在的目录在 VSCode 里打开。命令要是不灵的时候,咱们也有一条排障可看:多半是终端没有重开过的缘故,或者装 VSCode 的时候没把它加进 `PATH`。`PATH` 就是 shell 找命令时翻的那串目录。

照文档的说法,刚连上的那一下,屏幕上会为您多出正在安装 VS Code Server 的一行字。那是您 Windows 那一侧的 VSCode,往 Linux 这一侧装上了一个不大的服务端。笔者自己机器上就留着那一步的痕迹:`code` 这个命令住的地方是 `~/.vscode-server/bin/` 底下,那是一个已经装好的 Linux 侧服务端留下来的东西。

您在 VSCode 里装的那些扩展,也装到了这个服务端上,跑也是在 Linux 这一侧跑的。于是您点开扩展干活的时候,它用的是 Linux 里的工具和运行时,不是 Windows 那一侧的。您收工的时候,照文档的说法,您点一下 File 菜单里的 Close Remote Connection,VSCode 就回到了 Windows 那一侧。

界面上的按钮长什么样、该点哪儿,咱们这一篇不搬,文档里的步骤写得很细,您真装的时候照着点就行。

这是两条谁也不挡谁的路。咱们在终端里跑 vim 的那一套,装了 WSL 扩展以后照样是能用的,顺手改一个东西的时候,它还是最快的。VSCode 接过来的那一摊,是正经干一整天活的那套家伙。

## 字不听使唤,人找不着北

敲出来的字全乱套,多半是您人还在命令模式里。这时候您按一下 `i`,字就回到该去的地方了。

人走丢了、敲什么都不对劲的时候,您连按两下 `Esc`,咱们把话交还给命令模式,再看屏幕上剩下了什么。

## 还有一整层键盘没用上:挪光标、删改、查找和一份 .vimrc

这一篇只给了您会活的那几下,方向键之外的东西还多着呢。书里给挪光标列出来的,是一整张表:`h`、`j`、`k`、`l` 能让您一格一格挪,`0` 到的是行首,`^` 到的是头一个非空白字符,`$` 到的是行尾,`w` 让您一个个词往前跳,`G` 带您直奔末行。书里还留了一条规律,不少命令的前头能带数字,`5j` 就是往下挪五行的意思。这些咱们这一篇都不动,方向键按得手酸的时候,您随时可以拿它们换换手。

插入的入口也不止 `i` 一个:`a` 让您在光标后面接着写,`A` 跳到了行尾再写,`o` 和 `O` 帮您在下一行、上一行开个新行。删改那一摊的东西更厚:`x` 删掉一个字符,`d` 配上一个动作就成了 `dd` 这样的整行删除。删掉的东西一并进了粘贴缓冲,`p` 让您把它贴回来,`P` 让您贴在前面,`y` 帮您复制。轮到 `u` 的时候咱们得多说一句:老 vi 只让您撤一次,vim 能让您一级一级撤回去,书里为这件事专门留了话。它是新手少有的后悔药。

接着轮到的是查找和替换:`f` 让您在行内找字符,`/` 让您在满文件里找词,替换的写法是在冒号后面写一条命令,那就是书里说的 ex,您能划出范围来,还能一处一处问您要不要换。多文件编辑靠的是 `:bn` 和 `:bp`,一个带您翻到下一份文件,一个带您翻回上一份。`.vimrc` 是装您自己习惯的配置文件,书里提过的就是它。`vimtutor` 咱们没在书上找到出处,咱们也没验证过,咱们只把名字摆在这儿,不给您打包票。`Ctrl+Z` 的用处是把 vim 挂到后台,您别把它当退出,进程还在的,您记下这个名字就够了。

vi 的模式不止这些。咱们按 `v` 就进了可视模式,选中了一段文字再动手,别的模式咱们这一篇不铺开,您哪天真用上了再说。

> `:help` 是它肚子里自带的一本说明书,您敲一下它就翻给您看,里头写的是英文,您哪天想认某个键,那儿是最好的去处。

笔者在文档里读到几处好认的:VSCode 里起的那个集成终端,就是 Linux 这一侧的 shell。咱们打开一份文件,悬停上去看到的是 Linux 路径,状态栏上写的是 `WSL: Ubuntu`。这些凑到一起的时候,咱们就知道自己人还在 Linux 这一侧。

这些咱们这一篇都不碰。眼下您手里这一套,改一份配置、补一行脚本已经够了。

这间书房到这儿就算置办齐了。咱们把门带上,该进正文了。
