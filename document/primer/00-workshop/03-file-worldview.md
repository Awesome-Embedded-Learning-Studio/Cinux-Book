# 03 · 文件的世界观:点开头的住户、九个字母,和删得掉删不掉

上一回咱们练手的时候,在您的家目录里留下一间 playground,嘱咐过您留着它。这一篇的活全在那间屋里干,您敲一句 `cd playground` 就进去了。那间屋要是被清掉了,您敲一句 `mkdir -p playground` 也就回来了,那个 `-p` 管两件事:路径里缺的层它一并建出来,您哪天发现目录已经在,它也不报错了。您上次是在自己家目录里看见过一串点开头的名字,还问过它们为什么藏。咱们把这笔疑问答完,再认一件更古怪的事:咱们说话用的这块终端,在 Linux 的眼里也是一份文件。

## 藏与不藏,不在文件身上

咱们回到屋里,给 `note.txt` 造个家:敲一句 `touch note.txt` 就有了。下面这六行的,咱们一行一行看仔细。

```bash
touch note.txt
touch .secret
ls -a
printf '%s\n' *
ls -l .secret note.txt
ls -ld playground
```

```text
.
..
.secret
note.txt
note.txt
-rw-r--r-- 1 tom tom 0 Sep 29 18:42 .secret
-rw-r--r-- 1 tom tom 0 Sep 29 18:42 note.txt
drwxr-xr-x 2 tom tom 4096 Sep 29 19:25 playground
```

`ls -a` 交出来的名单里,`.secret` 和 `note.txt` 都排在里面了,前面还多出 `.` 和 `..` 两个地址。`ls -a` 是您上次学过的写法,这回您再补上 `ls -A`,您看它跟 `-a` 只差一点:`.` 和 `..` 不再列出来。紧接着 `printf '%s\n' *` 只列了 `note.txt` 一行,`*` 代表的是“随便什么名字”,它却把 `.secret` 让了过去。`ls -l` 报出来的那两行才是关键:`.secret` 和 `note.txt` 的属性一字不差,咱们看首字母都是 `-`,九位也都排着 `rw-r--r--` 的。咱们在它们身上实在找不出标记,能说明谁藏谁不藏的。这里有个反直觉的地方:其实它根本不在文件身上,是 `ls` 的默认行为,加上 `*` 的匹配规则,一路让着点开头的名字。您哪天让它列全,它就列全了,`ls -A` 报出来的名单里 `.secret` 当场回来。

## 首字母这四种,外加一个 `0`

咱们看名字之前,得会看它写出来的长格式,头一屏里 `ls -l .secret note.txt` 那两行就是了。值得单独看的是最前面一格 `-rw-r--r--`,这一篇剩下的内容基本都围着它转。往下排的几格依次是硬链接数、属主、属组、字节大小和最后修改时间。这里给您提个醒:这些格子里除了名字,别的值都跟着您手上的机器走。其实日期各人不尽相同,因为各自造出来的时辰不一样。属主属组写的是您用户名的名字,大小看的是内容。您手上机器出来的多半对不上,那是正常的,咱们要认下来的只是结构。

属性第一位才值得咱们单独看。`-` 说的是普通文件,您的笔记、脚本、照片全都算。目录的记号是 `d`,`ls -ld playground` 报出来的那一行就是它。剩下的这几种字母,咱们从系统里现抓来认:

咱们拿 `ls -l` 去看 `/dev/null` 和 `/proc/uptime`,让它们自己说话吧:

```bash
ls -l /dev/null /proc/uptime
```

```text
crw-rw-rw- 1 nobody nobody 1, 3 Sep 28 17:42 /dev/null
-r--r--r-- 1 nobody nobody 0 Sep 29 19:25 /proc/uptime
```

两位的首字母一个是 `c`,一个是 `-` 的。前者管的是字符设备,后者就是普通文件了。属主属组两列咱们不用看,各家机器上都不同的。第五格按文件不同而不同:普通文件上写的是大小,设备文件上写的才是设备号。咱们只需看 `/dev/null` 那一行,第五格写着这个设备的主次设备号,各机不变的。`cat /dev/null` 是一声不吭的,往里写一行字的 `echo "this line goes nowhere" > /dev/null` 也消失得干干净净,咱们连一条输出都等不到。

轮到 `/proc/uptime` 就不同了,它把自己装成一份普通文件的样子,首字母也是 `-` 的。咱们拿 `file` 去问它,它判的是 `empty`,可同一个 `cat` 吐出来的却是两个活数字:

```text
$ file /proc/uptime
/proc/uptime: empty
$ cat /proc/uptime
80819.23 1591417.07
$ cat /proc/uptime
80819.23 1591417.13
```

咱们读的同一个文件,后一个数字当场就变了。大小一格写出来的是 `0`,那个 `0` 是真的,吐出来的内容也是真的:这两样读数背后没有一份躺在硬盘上的文件,是内核现算给咱们的。`/proc` 底下藏着的这些东西,就是内核给咱们留的一排窥孔,您每开一次口,它都现算一遍给您。

### 您敲字用的那块终端,也是一份文件

咱们说话用的这块终端,在系统里究竟是个什么东西?您拿 `ls -l` 去看程序的标准输入。`/proc/self/fd/0` 这一串看着是长的,咱分成几段看:进程自己(`self`)的文件描述符表(`fd`)里的 0 号,而 0 号就是标准输入。

```bash
ls -l /proc/self/fd/0
```

```text
lrwx------ 1 tom tom 64 Sep 29 18:42 /proc/self/fd/0 -> /dev/pts/0
```

箭头那头指着的是 `/dev/pts/0`,它就是您眼前的这块终端,您的编号多半不是 0,照着咱们这个数抄没用。那我直接往终端身上写一行字,行不行?行,您敲一句 `echo 喂 > /dev/tty`,它会当场把那行字吐回来给您,这结果得由您亲手敲,笔者没法替您贴。看见那行字回来了,您就明白了,“终端是文件”这话并不是谁编出来骗人的。咱们这一趟看过的东西,一份普通笔记、一间目录、一条符号链接、一个字符设备、一份没大小的内核读数,它们全都有名字了,也全都按文件的方式使唤着。Unix 那边后来爱用一句短话把它总结掉了,说的就是“everything is a file”。

## 九个字母的权力

咱们看完了类型,剩下的九位才是这一篇里的重头,它们管着一件很朴素的事:谁能对这东西做点什么。咱们手里拿到的 `-rw-r--r--`,上面一共分了三段。头一段 `u` 说的是属主,也就是您自己。中段 `g` 说的是跟您同组的那些人,末段 `o` 说的是除您俩之外的全体。每一段里的 `r`、`w`、`x` 管的就是读、写、执行。照这么读下来,您本人能读能写,同组的只能读,剩下的也只能读,咱们这些人谁都没拿到执行权。把它换成八进制写出来的 `644`,过一会儿咱们还要用到它。

同样是 `r`、`w`、`x` 的,对着目录的时候,意思就整个换了一套。这是本篇里咱们最该看明白的一处:

| 位 | 对一份文件 | 对一间目录 |
|---|---|---|
| `r` | 打开它、读里面 | 列得出屋里有哪些名字(还得同时有 `x`) |
| `w` | 写它、清空它,但不许改名、不许删除 | 在屋里创建、删除、改名(还得同时有 `x`) |
| `x` | 当程序跑起来 | 进得去,也就是 `cd` |

中间那行您得看仔细:一份文件自己的 `w`,管得着您往它里面写,可管不着您把它从屋里的名单上划掉。文件的删除和改名,这两件事都归所在那间屋的 `w` 管,这一点违反了大多数人的直觉,咱们过一会儿拿实验确认。您再敲一个 `umask`,笔者那边的机器报的是 `0022`,新文件落生时那些位就是它替您削掉的:掩码里是 1 的位,从文件的属性里被削掉,`0022` 削的是同组与其他的写位,所以新文件落生成 `644`。

## 动手改权限

改权限的家伙是 `chmod`,它最顺手的写法,您直接递给它一个八进制数就行。您常用的数就五个,`u` 管一位、`g` 管一位、`o` 管一位——`7` 给的是 `rwx`,`6` 给的是 `rw-`,`5` 给的是 `r-x`,`4` 给的是 `r--`,`0` 就什么都没有。您拿刚才的笔记来走一趟:

```text
$ chmod 600 note.txt
$ ls -l note.txt
-rw------- 1 tom tom 0 Sep 29 18:42 note.txt
$ chmod 000 note.txt
$ ls -l note.txt
---------- 1 tom tom 0 Sep 29 18:42 note.txt
$ cat note.txt
cat: note.txt: Permission denied
```

`600` 打完这一下了,除了您本人,谁也别想碰它了。接着敲的那一下是 `000`,九个位一个都不剩了,您自己还读得出来吗?读不出来。您是这个文件的属主,是它的写入者、创建者,只要您不是 root(系统里的超级用户),它照样把您拦在外面。权限拦人的时候不认交情,内核比的是进程的 uid、gid(您的用户编号与组编号)和文件上的属主、属组,而不是谁跟谁熟。您要是把自己的文件关得太死,只要您还是它的属主,就能用 `chmod` 改回来了,您再补上 `644` 一份的,门就开了。

脚本那一路还得补一个 `x` 上去了。符号写法里的 `+x` 就是给三段加上执行位。咱们现场造一份小脚本:`printf '#!/bin/sh\necho hi from a script\n' > hi.sh` 写进去。咱们写进去的就是一行 shebang 加上一行 `echo`,您一量正好 32 字节。您敲一句 `chmod +x hi.sh`,那行 `-rwxr-xr-x 1 tom tom 32 Sep 29 18:42 hi.sh` 就亮出来了。符号写法里其实还藏着一整套花活,咱们这一篇不铺开,您眼下把 `+x` 认下就够。

## 删得掉删不掉,看的是那间屋

咱们前面讲过“删除不归文件自己的位管”,这里咱们拿实验把它验一遍。您造一间屋出来,咱们往里面放上小东西,再把它设成谁都只能读的:

```text
$ mkdir cage
$ printf 'prey\n' > cage/prey.txt
$ chmod 444 cage/prey.txt
$ ls -l cage/prey.txt
-r--r--r-- 1 tom tom 5 Sep 29 18:42 cage/prey.txt
```

它的九位里连一个 `w` 都没有,连您本人也写不进去,那么把它删掉呢?

```text
$ rm -f cage/prey.txt
$ ls cage
```

咱们敲的 `ls cage` 那一下,屏幕上什么都没有,它就是把这个文件给删掉了。这一拍您得停一下:文件自己是 `-r--r--r--`,连属主也写不进去了,可它照样一路通行了,咱们一句抱怨都听不到,拦人的那道关压根不在文件身上。这里还得交代一句:这回咱们带了 `-f`,图的是利索。您要是不带它去删一份写保护的文件,`rm` 会问您一句,问的原话是:`rm: remove write-protected regular file 'cage/prey.txt'?`,问完就停在那儿等着您回话。标准输入不是终端的时候,或者您给了 `-f`,它都不问了。咱们刚才删的那一次,满足的只有 `-f`,而标准输入不是终端并不成立。

文件那头咱们读完,接下来咱们就换一头,该把屋锁上了。您把东西放回原处,这回咱们动的是那间屋:

```text
$ printf 'prey\n' > cage/prey.txt
$ chmod 555 cage
$ rm cage/prey.txt
rm: cannot remove 'cage/prey.txt': Permission denied
```

您看,这回它就删不动了。咱们用的还是这 `rm`,变的只是那间屋肯不肯让咱们动手。所以删除干的到底是什么事,您可以往这个方向想:`rm` 移走的从来都不是箱子,它移走的是目录名单上的一行登记:那东西还在不在、箱子归谁管、文件自己愿不愿意,它一概都不问了。它只看登记所在那间屋的 `w` 位开着没有,开着就动手了。您还记得删除命令有多绝情吗,那绝情有一半就是打这儿来的,它压根没打算替您保管箱子,只替您把名字划掉。咱们顺手敲一句 `chmod 755 cage`,这间屋就还回原样了。下一节咱们现造一间屋、把它整个锁上,那时候正好接着用它了。

## 同一个 Permission denied,分清门还是屋

排障的时候,咱们只盯一种最常遇到的失权。`Permission denied` 您刚才已经遇到过两次了。改权限时的 `cat` 那次是门,文件自己的位不肯开。紧接着来的那次 `rm cage/prey.txt`,拦住您的换成了屋的 `w` 位,`cage` 的 `555` 把它挡下了。这回咱们把整间屋的位全关掉,您再挨个敲三条命令看看:

```text
$ mkdir locked
$ printf 'treasure\n' > locked/inside.txt
$ chmod 000 locked
$ cat locked/inside.txt
cat: locked/inside.txt: Permission denied
$ ls locked
ls: cannot open directory 'locked': Permission denied
$ cd locked
bash: cd: locked: Permission denied
```

咱们发三条命令出去,回来的判决都叫 `Permission denied`,变的是说话人。头一句里 `cat` 走到路径中间就被拦下了,其实它连是哪一级都没点出来,倒是第二句里 `ls` 才明确告诉您,打不开的就是那间屋,`cannot open directory` 就是它给的。第三句是最短的,`bash` 只说 `cd` 也进不去了,通常就意味着屋的 `x` 被摘掉了。您下次再看到 `Permission denied`,多读半句就知道自己失的是哪种权:文件读不了,看它自己的位。咱们名单列不出来、路也切不进去,那就得去看那间屋的位了。要看目录自己的属性,您拿 `ls -ld locked` 去看,那个 `-d` 说的是看目录本身,不列里面的东西,回来的正是 `d--------- 2 tom tom 4096 Sep 29 18:40 locked` 这一行。

## 留在后面的几件活

符号链接和硬链接是两份名单之间的亲戚,咱们这一篇只让 `l` 露了个脸,怎么创建、有什么区别,咱们留到后面找机会再讲。改属主、改属组的两条命令要动用户身份,`sudo` 那边的东西也不轻,咱们等装东西那篇一起请。`ls -l` 里偶尔其实还会冒出一两个 `s` 或者 `t`,它们管的是另一套权限,咱们这一篇不展开。块设备的首字母是 `b`,它管的是按块读写的设备,硬盘就是现成的一位。这一篇里咱们没见着它,是笔者在这机器上找过,没取到样例的,往后遇上了再认。`file` 那一句咱们只用过一次,看的是文件里装的是什么,而不是名字,那一次的用武之地就是 `/proc/uptime`。

咱们这一趟走下来,九个字母怎么读,咱们对着 `644` 和讲目录权限的表走完了,点开头的住户怎么藏,咱们也在 `ls` 和 `*` 上验过了。您要是哪天想再试试删除的狠劲,找一份不心疼的笔记,拿 `chmod 444` 和一间 `555` 的屋分别删一次,两边的差别您当场就看得见。您再回头看一眼自己那间 playground,里头有您亲手造的 `note.txt` 和 `.secret`,往后都得您亲手照看。咱们下一篇,去给这间书房添几件趁手的家伙,把装东西的家伙请进门。
